Off-by-One — Pre-Solve Lab

Converts idle GPU time into pre-verified answers for AI coding agents. Agents submit problems they expect to hit; the lab solves them during idle cycles so the next agent skips debugging entirely.

1. Executive Summary

Off-by-One is a pre-solve lab — a system that turns idle compute cycles into a cache of verified solutions for common AI coding agent errors. Instead of every agent debugging the same class of problem from scratch, one agent's solved problem becomes the next agent's instant answer.

The name's triple meaning:
① The most iconic programmer error class (off-by-one)
② The value proposition — answers exist one step ahead of errors, not after
③ A nod to Stack Overflow's legacy — the next generation of developer knowledge sharing

2. The Core Loop

1. SUBMIT ──→ Agent pushes problem via Muster (API / MCP / CLI) │ ▼ 2. QUEUE ──→ Ranked by recurrence likelihood + severity │ ▼ 3. SANDBOX ──→ Bubblewrap (bwrap) isolates the problem │ Unprivileged, no dockerd, ~10ms startup ▼ 4. SOLVE ──→ Pi Agent reproduces and fixes (DeepSeek V4 Flash) │ ▼ 5. VALIDATE──→ 2-3 adversarial validators attack the solution │ Survivors get verified stamp + signatures.json ▼ 6. CACHE ──→ Answer enters graph DB with evidence + signatures │ ▼ 7. DISCOVER──→ Any agent queries graph → gets answer + related + │ version warnings + prerequisites ▼ ✅ Problem solved before it's encountered again

4. Dual Interface Design

Off-by-One serves two audiences through two interfaces, backed by the same engine:

AI Interface — Muster MCP

  • Audience: AI coding agents (Coding Hermes, OpenCode, Claude Code)
  • Protocol: MCP tools auto-generated from OpenAPI spec
  • Tools: submit_problem, discover_solution, list_problems, get_queue_status
  • Workflow: Agent hits error → submits → continues working → later discovers pre-verified answer

Human Interface — Web UI

  • Audience: Developers, operators, maintainers
  • Protocol: HTTP/WebSocket, browser-rendered
  • Views: Search, Submit, Explore (taxonomy), Export, Import, AI Agent Chat
  • Workflow: Browse taxonomy → search solutions → submit problems → export/import → chat with AI
AI Agent → Muster MCP ──→ Off-by-One API ──┐
                              ├── SQLite Graph
Human    → Web UI    ──→ Off-by-One API ──┘
         → Web UI    ──→ WebSocket → Pi Agent Chat

5. Sandbox Architecture

Problems are solved inside Bubblewrap (bwrap) — unprivileged Linux containerization with zero Docker overhead. No daemon, no root, no image registry. ~10ms startup per solve.

PropertyDockerBubblewrap
Daemon requireddockerdNone
Root requiredYes (daemon)No (user namespaces)
Image overheadLayers + registryNone (bind mounts)
Startup time~1–5s~10ms
Filesystem isolationOverlayFSBind mounts + tmpfs
Network isolationFull namespaceShared net (for API access)

Lifecycle

  1. Create: bwrap container with bind-mounted workspace
  2. Setup: Copy problem files + Pi Agent into sandbox
  3. Solve: Pi Agent runs, produces solution + evidence
  4. Extract: Copy results out of workspace
  5. Destroy: Kill bwrap, clean workspace
  6. Timeout: 5-minute wall clock — stuck agent = killed
Idle gating: The cron loop checks loadavg < 1.0 before dequeuing. On a loaded system (loadavg 50+), the solver won't activate — this is intentional. It only consumes truly idle CPU time.

6. Graph Discovery Engine

Answers are stored in a problem-class tree with lateral graph edges. Discovery uses recursive CTE + BFS traversal — returning the neighborhood, not just the match.

Data Model

TablePurpose
problem_classesTaxonomy root nodes (e.g., "Docker volume permissions")
answer_nodesVersion-branched solutions (self-referential parent_id for version tree)
problem_edgesLateral connections: same_root_cause, prerequisite, superseded_by, generalizes

Discovery Ranking

  1. Exact match (same version) — score 1.0
  2. Parent version (go-1.25 for go-1.26 query) — score 0.8
  3. Same problem class, different environment — score 0.6
  4. Related via lateral edge — score = edge weight
  5. Semantic similarity (OpenRouter embeddings) — score 0.3–0.7
When an agent queries Off-by-One, it gets:
① The exact answer for its problem class + environment + version
② Related answers via lateral edges (same root cause, different environment)
③ Version warnings ("Python 3.14 changes this — you're on 3.12")
④ Prerequisites ("before fixing this, the Docker volume must be mounted correctly")

7. Git Export / Import Model

Verified answers can be shared between instances via git — the same model as code sharing, applied to agent knowledge.

Export

  • Select verified answers → export to git repo
  • Files follow S3-key depth path: pre-solve-answers/{class}/{env}/{version}/
  • Each answer: solution.md + evidence.md + signatures.json
  • Committed as git subtree, pushed to remote

Import

  • Pull from trusted git repos → parse directory tree
  • Diff against local graph: new, updated, conflict
  • Select → merge into local SQLite graph

CI Prompt Injection Filter

Before answers are merged into a shared community repo, CI runs a 3-stage filter:

  1. Static pattern matching — known injection vectors
  2. LLM semantic analysis — embedded instructions in markdown?
  3. Sandbox execution — run code in isolation, check behavior

Answers that pass all three stages get ci-passed stamp. Consumers trust answers that survived CI, not answers that claim to be safe.
