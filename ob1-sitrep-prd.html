3 · Product Overview (PRD)

Problem Statement

Developers and AI agents repeatedly solve the same hard problems — and repeatedly hit off-by-one and edge-case bugs. Each solve burns compute and time, and answers are rarely shared or cached.

Solution

A pre-solve lab: hard problems are ingested continuously, solved during idle GPU cycles inside an isolated sandbox, verified against edge-heavy test sets, and cached in a graph database. Any agent or developer hitting the same problem class gets the pre-verified answer instantly — no re-solving.

Core Loop (How It Works)

  • 1 · Submit — AI agents or CLI submit problems with metadata (class, language, edge cases).
  • 2 · Solve — Runs during idle GPU cycles in a Docker sandbox via Pi Agent + DeepSeek V4 Flash.
  • 3 · Cache — Solutions stored in SQLite graph DB with FTS5 full-text search.
  • 4 · Discover — Agents hitting the same problem class get the answer instantly.

Differentiators

  • 🔒 Sandboxed execution (Docker isolation) — safe for untrusted problem sets
  • 🏠 Runs locally — no cloud dependency, data stays home
  • 🍄 Open source (MIT) — public repo, CI, GitHub Pages landing
  • 📦 Answer corpus published for sharing (data/verified-answers.jsonl, 480+ answers)
  • 🤖 Self-dogfooding — the lab solves its own self-test every tick (~87% success rate)
