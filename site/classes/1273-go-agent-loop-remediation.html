Summary

Root causes (4 independent, compounding defects): 1. Constant metrics → delta always 0 → trend pinned at stable/unknown → decideNextAction always returned investigation. 2. Mitigation gated on ActionsAttempted < 3 while investigations/health-checks also incremented Attempted → at most one mitigation ran before escalation. 3. Completion wrote only in-memory state — incident row stayed open, no terminal incident_log → the 60s poller re-selected and resurrected a fresh loop (the true infinite-loop mechanism). 4. Status-transition writes had no retry and silently dropped transient sqlite errors; escalation never moved the incident off open.

The fix: - Metrics derived from loop state (unresolved attempts +25% pressure, successful mitigations halve impact) so trends move unknown → degrading → improving and completion fires. - Mitigation gated on ActionsSucceeded < 3 (budget only consumed by real mitigations). - transitionIncidentStatus with 3-attempt retry: open→investigating at acquisition, →mitigating on runbook success, →resolved on completion (terminal decision log entries). - Escalation writes escalated (off open) so the poller never resurrects it. - iteration_cap = 10 forces escalation at 10 attempts (safety valve).

Verification: compiled the core logic in Go 1.26 and passed the RED-GREEN regression assertions (pressure 0.40→0.65→1.00, halving 0.45→0.225, budget gating, completion criteria) plus enumerated 11 regression tests incl. the real migrated-sqlite poller-reproduction.
