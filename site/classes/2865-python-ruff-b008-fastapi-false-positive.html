Answer

I diagnosed and verified this against real Ruff builds (0.0.292 → 0.15.22). The solution is written to:

~/&lt;project&gt;-core-ruff-B008-solution.md

Key findings

Root cause: B008 (function-call-in-default-argument) is a genuine false positive for FastAPI's Depends()/Query()/Path() injection DSL. But the reason the project's existing pyproject.toml ignore didn't work is Ruff's rule-selection precedence: an explicit CLI selector (--select B008 / --extend-select B008) becomes the highest-priority basis for the rule set, and no config-level ignore or extend-ignore can remove a CLI-selected rule.

I empirically disproved a claim in the brief: [tool.ruff.lint].ignore = ["B008"] is also overridden by ruff check --select B008, exactly like extend-ignore. Both keys behave identically here.

Config ruff check . ruff check --select B008 .
ignore = ["B008"] ✅ ❌ still fires
extend-ignore = ["B008"] ✅ ❌ still fires
per-file-ignores ✅ ✅
flake8-bugbear.extend-immutable-calls ✅ ✅
--select B008 --ignore B008 ✅ ✅

The fixes

A. Requested config change (sufficient when selection comes from config):

[tool.ruff.lint]
ignore = ["B008"]

B. Drop-in that also survives an explicit CLI --select B008 — either:

[tool.ruff.lint.per-file-ignores]
"**/*.py" = ["B008"]

or the canonical, narrower FastAPI fix:

[tool.ruff.lint.flake8-bugbear]
extend-immutable-calls = ["fastapi.Depends", "fastapi.Query", "fastapi.Path", "fastapi.Header", "fastapi.Cookie", "fastapi.Body", "fastapi.Form", "fastapi.File", "fastapi.Security"]

C. CLI-only: ruff check --select B008 --ignore B008 .

The doc includes a full self-contained reproduction, expected outputs, a tooling grep to find any place re-adding B008 on the CLI, and references. My recommendation is to apply fix A and the extend-immutable-calls allow-list (B2), which is the semantically correct FastAPI suppression and is immune to CLI precedence.
