Fixing intermittent 409 CONFLICT namespace-teardown errors in the auger pytest suite

Problem class: duckbrain-native-sync-lock-409-teardown-contention Repo: coding-hermes/auger @ 1792b7ef3727196e1dd4a94044d022ba59d7c1ab Verdict: Environmental contention, not a code/test regression. The suite is green in substance; the failure is a teardown-time artifact of DuckBrain's per-namespace native sync lock being held by a sibling process.

1. Root-cause analysis

1.1 The causal chain

sibling lane (other pytest / gitreins judge / foreman git push)
        │  holds DuckBrain native sync lock for namespace N
        ▼
auger suite teardown: DELETE /api/namespaces/N
        │  native sync lock is per-namespace and serializes git push/commit
        ▼
DELETE returns 409 {"error": "Push in flight for 'N' (native sync lock held by pid OTHER)",
                    "code": "CONFLICT"}
        │  teardown_namespace retries 600s with 5s→30s backoff, then gives up
        ▼
3 × teardown ERROR (conftest.py finalizer)
   + 1 × FAILED leak audit (test_no_test_namespace_survives_the_suite)

1.2 Why it always looks the same

  • The native sync lock serializes git push/commit per namespace.
  • On the shared substrate (<ip-address>:3000) several lanes use the same namespace pool, so a sibling can legitimately hold the lock for minutes.
  • Teardown is the only phase that both (a) blocks on the lock and (b) fails loudly when the lock outlasts its retry budget. Therefore contention always surfaces as teardown errors + a leak-audit failure, never as a functional-assertion failure.
  • The leak audit is behaving correctly: it faithfully reports namespaces that teardown could not remove. It is a symptom, not the bug.
  • The lock-holder pid in the error is never the suite's own process — this is the single most reliable discriminator from a real regression.
  • Wall time is the secondary victim: the same suite measured 59–60 min at loadavg 20–30 vs. the gate's default 1200 s pytest budget (REVIEW-AUGER-005 records ~19.5 min on a quiet box). The timeout and the 409 share the same root cause (host/lock contention), not the test logic.

1.3 Attribution rules (do not get this wrong)

Observation Means
lock-holder pid ≠ own pid cross-process contention, not a deadlock in the suite
only teardown ×N errors + leak audit ×1 failed green in substance
any functional assertion failure that is the real problem — investigate separately
re-run of the exact affected tests passes in seconds after lock clears confirms environmental cause

Do not re-dispatch a worker, "fix" test logic, weaken the leak audit, or report the run as a regression.

2. Immediate response — correct triage and cleanup

The API DELETE is irreversible (row and directory). The only safe cleanup is by exact namespace id printed in the failure message.

2.1 Extract the exact leaked ids

From the pytest output, collect only the ids named in teardown failures. The suite emits the id in the message:

teardown of auger-pytest-3f9c1a was incomplete after 600s
DELETE /api/namespaces/auger-pytest-3f9c1a returned 409: ...

# Capture the run log first, then pull EXACT ids (no prefix expansion):
grep -oE 'auger-pytest-[0-9a-f]+' /tmp/auger-gate.log | sort -u > /tmp/auger-leaked-ids.txt
cat /tmp/auger-leaked-ids.txt        # eyeball: expect ~3 lines, all from THIS run

⚠️ Never do delete_namespace(prefix="auger-pytest-"). On a shared substrate that prefix is the entire historical litter backlog (~15k rows / 620 dirs), it deletes namespaces a concurrent suite is using live, and it runs until your own command timeout kills it with no audit trail. See §5.

2.2 Confirm the lock has cleared, then delete by exact id

A robust, idempotent, audit-logging script (preferred — uses the project's client if tests/_client.py exposes one):

#!/usr/bin/env python3
# tools/cleanup_exact_namespaces.py
"""Delete ONLY the exact namespaces given on the CLI/in a manifest.

Refuses to run without explicit ids. Never matches by prefix.
Idempotent: 404/410 == already gone. 409 is retried with backoff.
"""
import argparse, json, os, sys, time
import requests  # or: from tests._client import DuckBrainClient

def main() -> int:
    ap = argparse.ArgumentParser()
    ap.add_argument("ids", nargs="*")
    ap.add_argument("--ids-file", help="newline-separated exact namespace ids")
    ap.add_argument("--manifest", help="JSON list of {namespace: ...} leak records")
    ap.add_argument("--url", default=os.environ.get("DUCKBRAIN_URL", "http://<ip-address>:3000"))
    ap.add_argument("--api-key", default=os.environ.get("DUCKBRAIN_API_KEY"))
    ap.add_argument("--budget", type=float, default=600.0)
    ap.add_argument("--sleep", type=float, default=10.0)
    args = ap.parse_args()

    ids = set(args.ids)
    if args.ids_file:
        ids.update(l.strip() for l in open(args.ids_file) if l.strip())
    if args.manifest:
        ids.update(r["namespace"] for r in json.load(open(args.manifest)))
    if not ids:
        print("refusing to run: no explicit namespace ids supplied", file=sys.stderr)
        return 2

    headers = {"X-API-Key": args.api_key or "", "Content-Type": "application/json"}
    audit, deadline, failed = [], time.monotonic() + args.budget, []
    for ns in sorted(ids):
        while True:
            r = requests.delete(f"{args.url}/api/namespaces/{ns}", headers=headers, timeout=30)
            if r.status_code in (200, 202, 204, 404, 410):
                audit.append({"namespace": ns, "result": r.status_code})
                break
            if r.status_code == 409 and time.monotonic() < deadline:
                time.sleep(args.sleep)   # lock still held by a sibling
                continue
            failed.append({"namespace": ns, "result": r.status_code, "body": r.text[:400]})
            break

    print(json.dumps({"deleted": audit, "failed": failed}, indent=2))
    with open("/tmp/auger-exact-delete-audit.jsonl", "a") as fh:
        for rec in audit + failed:
            fh.write(json.dumps(rec) + "\n")
    return 1 if failed else 0

if __name__ == "__main__":
    raise SystemExit(main())

3. Durable fix (prevent recurrence)

Apply these in order. (1) is the real cure; the rest reduce blast radius and cost.

3.1 Give the suite its own scratch substrate (primary fix)

Stop sharing <ip-address>:3000 with sibling lanes. Point the suite at a private daemon via DUCKBRAIN_CONFIG_PATH and a second port, both under a session-scoped temp dir.

# tests/ or gate.sh: create an isolated substrate for this leg only
export AUGER_SUBSTRATE_DIR="$(mktemp -d -t auger-substrate-XXXXXX)"
export DUCKBRAIN_CONFIG_PATH="$AUGER_SUBSTRATE_DIR/duckbrain.yaml"
export DUCKBRAIN_PORT="${DUCKBRAIN_PORT:-31337}"
export DUCKBRAIN_URL="http://<ip-address>:$DUCKBRAIN_PORT"
# start the daemon with that config (project-specific invocation; keep it local)
duckbrain serve --config "$DUCKBRAIN_CONFIG_PATH" --port "$DUCKBRAIN_PORT" &
AUGER_SUBSTRATE_PID=$!
trap 'kill "$AUGER_SUBSTRATE_PID" 2>/dev/null; rm -rf "$AUGER_SUBSTRATE_DIR"' EXIT

If a real daemon cannot be spun up in CI, at minimum set DUCKBRAIN_URL to a scratch port that only this leg owns. The contract is: one lock namespace pool per concurrent leg.

3.2 Serialize substrate use across concurrent legs

When a shared daemon is unavoidable, take an inter-process mutex around the blocking phases:

# gate.sh wrapper — only one leg touches the shared substrate at a time
AUGER_LOCK="${AUGER_SUBSTRATE_LOCK:-/tmp/auger-substrate.lock}"
exec 9>"$AUGER_LOCK"
flock 9                       # blocks until the other leg releases
trap 'flock -u 9' EXIT
pytest tests/test_auger.py ...

Keep the lock scoped as tightly as possible (ideally around the substrate-touching tests, not the whole suite) so wall time doesn't serialize unnecessarily on quiet boxes.

3.3 Raise the gate's pytest budget via an env knob

Do not edit config or hardcode a larger timeout. Add an env-overridable budget and record a timeout honestly as a timeout, not as a failure:

# gate.sh
: "${AUGER_GATE_PYTEST_BUDGET:=1200}"   # seconds
echo "[gate] pytest budget = ${AUGER_GATE_PYTEST_BUDGET}s"
timeout --foreground --signal=INT "${AUGER_GATE_PYTEST_BUDGET}" \
  pytest tests/test_auger.py 2>&1 | tee /tmp/auger-gate.log
rc=${PIPESTATUS[0]}
if [ "$rc" -eq 124 ]; then
  echo "[gate] TIMEOUT after ${AUGER_GATE_PYTEST_BUDGET}s (environmental; record as timeout, not regression)" >&2
  exit 124
fi
exit "$rc"

On the contended host, run with AUGER_GATE_PYTEST_BUDGET=3600 (or higher) and record the actual wall time in the review row.

3.4 Make teardown idempotent + loudly record leaks

Hardening for tests/conftest.py (adapt names to the existing client):

# tests/conftest.py — teardown hardening
import json, os, time
from pathlib import Path
import pytest
import requests

DUCKBRAIN_URL = os.environ.get("DUCKBRAIN_URL", "http://<ip-address>:3000")
DUCKBRAIN_API_KEY = os.environ.get("DUCKBRAIN_API_KEY", "")
LEAK_MANIFEST = Path(os.environ.get("AUGER_LEAK_MANIFEST", "/tmp/auger-leaked-namespaces.json"))

def _headers():
    return {"X-API-Key": DUCKBRAIN_API_KEY, "Content-Type": "application/json"}

def delete_namespace(ns: str) -> bool:
    """Idempotent single-namespace delete. Returns True when gone."""
    r = requests.delete(f"{DUCKBRAIN_URL}/api/namespaces/{ns}",
                        headers=_headers(), timeout=30)
    if r.status_code in (200, 202, 204, 404, 410):
        return True          # already gone is success
    if r.status_code == 409:
        return False         # native sync lock held by a sibling — retry
    r.raise_for_status()     # anything else is a real failure

def _record_leak(ns: str, last_error: str) -> None:
    try:
        data = json.loads(LEAK_MANIFEST.read_text()) if LEAK_MANIFEST.exists() else []
    except json.JSONDecodeError:
        data = []
    data.append({"namespace": ns, "last_error": last_error, "at": time.time()})
    LEAK_MANIFEST.write_text(json.dumps(data, indent=2))

def teardown_namespace(ns: str, budget_s: float = 600.0,
                       backoff: float = 5.0, max_backoff: float = 30.0) -> None:
    """Delete one namespace; never give up silently."""
    deadline, delay, last = time.monotonic() + budget_s, backoff, ""
    while time.monotonic() < deadline:
        try:
            if delete_namespace(ns):
                return
        except requests.RequestException as e:
            last = str(e)
        time.sleep(min(delay, max(0.0, deadline - time.monotonic())))
        delay = min(delay * 1.5, max_backoff)
    _record_leak(ns, last or "409 CONFLICT: native sync lock held by sibling")
    pytest.fail(f"teardown of {ns} was incomplete after {budget_s:.0f}s "
                f"(see {LEAK_MANIFEST}; delete that EXACT id later, never by prefix)")

The leak audit should read LEAK_MANIFEST and fail with the exact ids, so a residual namespace is visible and auditable instead of silently retained.

5. Anti-patterns — do not repeat

  1. Prefix/bulk delete. delete_namespace(prefix="auger-pytest-") on a shared substrate is the whole historical backlog (~15k rows / 620 dirs). It deletes live namespaces owned by concurrent suites, runs until your command timeout kills it, and leaves an unmeasurable count with no audit trail. DELETE is irreversible (row + directory).
  2. Rule: pass only the exact namespace id from the failure message. A backlog cleanup is its own tracked work item, never a foreman tick's cleanup step.
  3. Re-dispatching a worker or "fixing" test logic. There is no logic bug here; the leak audit and teardown finalizer are working as designed.
  4. Reporting the run as a regression. It is green in substance. Report the environmental contention and the long wall time, and record the gate timeout honestly.
  5. Silencing the leak audit. Do not make it pass on residual namespaces; make residuals loud and auditable.

6. One-line runbook

Bottom line: the fix is to stop sharing DuckBrain's per-namespace sync lock across lanes (dedicated scratch substrate and/or serialization), raise the gate budget via AUGER_GATE_PYTEST_BUDGET, make teardown idempotent and loud, and clean up by exact id only. The 409 teardown/leak-audit signature is contention, not a code regression.
