DPhyp Join Enumeration under a Hash-Table Memory Budget — Diagnosis and Verified Solution

Root-cause analysis

Building this correctly exposes six failure modes. Two were real bugs hit while developing; the rest are the algorithmic traps.

  1. A budget makes the DP bi-criteria. Keeping only the cheapest plan per connected subset is wrong: a subset's cheapest plan may have a huge build-side hash table, while a costlier plan with a small one is needed for the root to fit. Fix: retain the Pareto front over (cost, peak) per subset; q dominates p iff q.Cost ≤ p.Cost && q.Peak ≤ p.Peak.

  2. Peak memory is the max over live branches. Summing hash tables makes every bushy plan look infeasible; counting only the current join undercounts nested tables. The table is live during build and probe, and the children never run together: peak(node) = hash(build) + max(peak(build), peak(probe)) hash(build) = card(build) * rowBytes This also makes pruning children with peak > budget safe.

  3. Neighbourhood-pruning bookkeeping. The recursion must carry the new frontier N(S') \ N where N is the immediate parent call's candidate set (not the original N(S)), and the complement recursion must also remove the csg (&^ Csg). Getting either wrong drops valid csg–cmp pairs or explodes the state space.

  4. Enumeration is structural; replan must not repeat it. Cardinalities affect only costs. On a >10× miss, apply the correction factor to all supersets of the bad operator and rebuild only those Pareto fronts by increasing popcount, reusing every cached csg–cmp pair.

  5. Determinism. Go map iteration is randomized. The certificate is accumulated in insertion-ordered slices and subsets are visited in a fixed order (popcount, then bitmask).

  6. Two concrete bugs found:

  7. (a) Oracle too permissive. The first exhaustive oracle accepted any partition with a crossing edge, even with a disconnected side, giving a false DPhyp missed pair {2,4}|{1,6}. A legal bushy child must be connected: g.conn[a] && g.conn[b].
  8. (b) Duplicate encoding/json tags silently dropped the certificate. CSGCmpPairs int json:"csgCmpPairs" and Pairs []string json:"csgCmpPairs" collide, and Go drops all fields sharing a name with no error. Fixed with distinct tags (csgCmpPairCount vs csgCmpPairs).

Exact fix

Cardinality estimate (telescopes to a function of the subset, since every induced edge is applied at exactly one join):

card(S) = PROD_{i∈S} Base[i] * PROD_{edges (u,v) inside S} Sel[u][v]

Core enumeration with neighbourhood pruning:

func (e *Enumerator) enumCsgRec(s, n uint) {
    for x := n; x != 0; x = (x - 1) & n {
        sp := s | x
        if !e.g.conn[sp] { continue }
        e.emitCsg(sp)
        e.enumCsgRec(sp, e.g.nbr[sp]&^n)   // new frontier only
    }
}
func (e *Enumerator) enumCmpRec(csg, cmp, n uint) {
    for x := n; x != 0; x = (x - 1) & n {
        cmpp := cmp | x
        if !e.g.conn[cmpp] { e.recordPruned(csg, cmpp); continue }
        if cmpp&csg != 0 { continue }
        e.recordPair(csg, cmpp)
        e.enumCmpRec(csg, cmpp, e.g.nbr[cmpp]&^(n|csg))
    }
}

Pareto join (both orientations, budget-safe):

bc, pc := e.g.card[b.Mask], e.g.card[p.Mask]
cost := b.Cost + p.Cost + bc*e.g.q.BuildCost + pc*e.g.q.ProbeCost
hash := bc * e.g.q.RowBytes
peak := hash + math.Max(b.Peak, p.Peak)
if peak > e.budget { return }
e.fronts[u] = addPlan(e.fronts[u], &Plan{Cost: cost, Peak: peak, ...})

Incremental replan (no enumeration restart):

for s := 0; s < e.size; s++ {
    if uint(s)&bad == bad { e.g.card[s] *= factor }   // propagate 12x
}
for _, u := range e.order {                            // popcount order
    if u&bad != bad { continue }                       // reuse untouched fronts
    e.fronts[u] = nil
    if u&(u-1) == 0 { /* reset base */ } else { e.processMask(u) }
}
