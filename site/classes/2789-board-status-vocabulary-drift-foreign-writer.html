Fixing status: "closed" drift from a foreign board writer (DF-BOARDCTL-41)

Tool: github.com/coding-hermes/boardctl (Go 1.26). Live board: a sibling repo's .coding-hermes/board/tasks.jsonl (the "other repo" / <project> lane). Landing commit of the fix: af36041becebc0094f3943cdb13d708fb4af2432.

1. Symptom

boardctl validate on the live sibling board fails with an off-vocabulary status that the board CLI itself will never write:

[error] tasks.jsonl line N (task DF-WARPFS-...): status "closed" not in
  vocabulary {blocked,complete,failed,in_progress,pending,review}
  (accepted read aliases: completed->complete, done->complete, ...)
RESULT: FAIL

normalize-board refuses every closed row instead of converting it:

line N  DF-WARPFS-...: REFUSED status — status "closed" is not in the
        vocabulary or the alias table — needs an explicit decision

Because the refusal is correct for an ambiguous value, the repair is blocked: the board stays validate-red after every mechanical repair and the drift regrows each time the foreign writer runs.

2. Root-cause analysis

2.1 The tool cannot have emitted closed — the write path bypasses the alias table

boardctl has two vocabularies:

  • StatusVocabulary (internal/board/read.go) — the canonical, writable set: pending, in_progress, review, blocked, complete, failed.
  • StatusAliases (internal/board/read.go) — the read-only alias table used by ResolveStatus (completed→complete, done→complete, todo/open/reopen/reopened→pending, …).

Every write surface checks StatusVocabulary directly, never ResolveStatus:

// internal/board/write.go:339  (create)
if status == "completed" { /* singular-'complete' refusal */ }
if !StatusVocabulary[status] {
    return "", fmt.Errorf("status %q not in write vocabulary {%s}", status, vocabList())
}

// internal/board/write.go:896  (update)
if !StatusVocabulary[s] {
    return nil, fmt.Errorf("status %q not in write vocabulary {%s}", s, vocabList())
}

So create --status closed and update <id> --status closed both refuse (exit 1) no matter what the alias table says. The tool can never have written the value — the writer is a third party.

2.2 The writer is a scripted full-file rewrite, not an appender

Find the introducing commit by searching the board file history for the literal string (this is history on the sibling repo, where the board lives):

git -C /path/to/other-repo log -S'"status":"closed"' --oneline \
    -- .coding-hermes/board/tasks.jsonl
# -> ffcd7f29 ...
git -C /path/to/other-repo show --stat ffcd7f29

The introducing diff is a 764-line full-file rewrite of tasks.jsonl (commit ffcd7f29, writer = the sibling repo's foreman/appender path), not a one-line append. That shape — an entire-file re-serialization by an agent — is the signature of a third-party writer that does not call the boardctl write API and therefore never consults StatusVocabulary.

2.3 The live value is unambiguous: 100% terminal evidence

Count live occurrences and inspect every row:

grep -c '"status":"closed"' .coding-hermes/board/tasks.jsonl      # 4 at fix time
grep -n '"status":"closed"' .coding-hermes/board/tasks.jsonl

Every closed row carries terminal-success evidence (commit_hash present, judge verdict / worker_status, completed_at populated). None is a parked or failed task. The value therefore unambiguously means complete in this fleet, which means it belongs in the read-alias table (closed → complete) and not in the writable vocabulary.

2.4 Why it was rejected before

closed was deliberately absent from StatusAliases (the "ambiguous bucket": retired, closed, wip, junk), so ResolveStatus returned ok=false, validate raised an error, and normalize/normalize-board refused the row. The policy was right for unknown values; the evidence for closed says it is a known value.

3. The exact fix

3.1 Functional change — one line, read side only

internal/board/read.go, in StatusAliases:

var StatusAliases = map[string]string{
    "completed":   "complete",
    "done":        "complete",
    "closed":      "complete",   // <-- ADD (DF-BOARDCTL-41)
    "todo":        "pending",
    "open":        "pending",
    "in-progress": "in_progress",
    "inprogress":  "in_progress",
    "in_progress": "in_progress",
    "reopen":      "pending",
    "reopened":    "pending",
}

That is the entire functional fix. StatusVocabulary is deliberately not touched. Because every read/normalize surface resolves through the single ResolveStatus chokepoint, adding the alias automatically makes validate, normalize (update --normalize), normalize-board, sweep-status, iddupe and the evidence gate treat closed as complete.

Keep the doc comment / README in sync (the upstream change also updated the StatusAliases comment and the README "status vocabulary and read aliases" section to move closed out of the ambiguous bucket and record the evidence basis).

Write-rejection (must still refuse closed, proving the write path ignores the alias table) — internal/board/review_status_vocab_test.go:

func TestWriteRejectsOffVocabularyStatus(t *testing.T) {
    for _, st := range []string{"duplicate", "parked", "resolved", "retired", "closed", "done", "open", "completed", "todo"} {
        // create path: rejected, nothing appended, no event fired.
        b := newTestBoard(t)
        tasksBefore := boardLineCount(t, b.tasksPath)
        eventsBefore := boardLineCount(t, b.eventsPath)
        if _, err := b.Create(TaskRowSpec{ID: "NEW-1", Title: "n", Status: st}); err == nil {
            t.Errorf("create --status %q accepted", st)
        } else if !strings.Contains(err.Error(), "not in write vocabulary") && !strings.Contains(err.Error(), "is not allowed") {
            t.Errorf("create --status %q error should refuse the spelling, got: %v", st, err)
        }
        if n := boardLineCount(t, b.tasksPath); n != tasksBefore {
            t.Errorf("tasks.jsonl grew on rejected create --status %q", st)
        }
        if n := boardLineCount(t, b.eventsPath); n != eventsBefore {
            t.Errorf("events.jsonl grew on rejected create --status %q", st)
        }

        // update path: rejected, the target row untouched
        b2 := newTestBoard(t)
        before, _ := ReadJSONLLines(b2.tasksPath)
        s := st
        if _, err := b2.UpdateTask("EXIST-1", UpdateSpec{Status: &s}); err == nil {
            t.Errorf("update --status %q accepted", st)
        }
        after, _ := ReadJSONLLines(b2.tasksPath)
        if len(before) != len(after) {
            t.Fatalf("line count changed on rejected update --status %q", st)
        }
        for i := range before {
            if string(before[i]) != string(after[i]) {
                t.Errorf("rejected update --status %q rewrote line %d", st, i+1)
            }
        }
    }
}

func TestNormalizeBoardClosedAliasConverts(t *testing.T) {
    dir := t.TempDir()
    writeBoardFiles(t, dir, map[string]string{
        "tasks.jsonl": `{"id":"DF41-CLOSED","title":"terminal success","status":"closed","priority":"P2"}` + "\n" +
            `{"id":"DF41-WIP","title":"ambiguous junk","status":"wip","priority":"P3"}` + "\n",
        "events.jsonl": `{"id":1,"timestamp":"2026-09-04 00:00:00","event_type":"audit","task_id":null,"actor":"foreman","detail":null,"tick_number":1}` + "\n",
        "board.jsonl":  `{"project":"df41","namespace":"df41","version":1,"ticks_total":1,"ticks_idle":0,"last_commit":null}` + "\n",
    })
    b, _ := Resolve(dir)
    before, _ := os.ReadFile(b.tasksPath)

    // dry-run: closed -> complete classified; wip still refused; no write
    dry, err := b.NormalizeBoard(false)
    if err != nil { t.Fatalf("NormalizeBoard(dry-run): %v", err) }
    var closedChange, wipRefusal bool
    for _, c := range dry.Changes {
        if c.ID == "DF41-CLOSED" && c.Kind == "status" && c.From == "closed" && c.To == "complete" {
            closedChange = true
        }
    }
    for _, r := range dry.Refusals {
        if r.ID == "DF41-WIP" && r.Kind == "status" { wipRefusal = true }
    }
    if !closedChange { t.Fatalf("dry-run did not classify closed->complete: %+v", dry.Changes) }
    if !wipRefusal { t.Fatalf("dry-run did not refuse wip: %+v", dry.Refusals) }
    mid, _ := os.ReadFile(b.tasksPath)
    if string(before) != string(mid) { t.Fatalf("dry-run rewrote tasks.jsonl") }

    // apply: closed becomes complete; wip stays byte-identical
    if _, err := b.NormalizeBoard(true); err != nil { t.Fatalf("NormalizeBoard(apply): %v", err) }
    after, _ := os.ReadFile(b.tasksPath)
    if !strings.Contains(string(after), `{"id":"DF41-CLOSED","title":"terminal success","status":"complete"`) {
        t.Fatalf("closed row not converted: %s", after)
    }
    if !strings.Contains(string(after), `{"id":"DF41-WIP","title":"ambiguous junk","status":"wip"`) {
        t.Fatalf("wip row was mutated by apply: %s", after)
    }
}

validate semantics for the duplicate marker (internal/board/validate.go): a plain duplicate id is an error; a later duplicate line carrying a non-empty superseded_by is a warning ("later line closed as superseded"). So the marker is what turns the last remaining error into a warning.

4.3 Acceptance criteria check

  • (a) mapping decided: closed → complete, read alias only — done.
  • (b) writer lane: the sibling repo's foreman full-file rewrite (ffcd7f29) is the emitter; boardctl writes can never emit closed.
  • (c) normalize-board/repair passes and validate reaches RESULT: OK.
  • (d) a subsequent sibling tick that still emits closed will regrow the drift — see below.

5. Regrowth surface and prevention

A tool-side read-alias fix is a mitigation on the read path only. It turns the symptom from a hard error into a warning and lets the mechanical repair converge, but it cannot stop a third-party full-file rewriter from writing closed again on the next tick. The real fix has to land where the bytes are produced:

  1. Fix the writer. The sibling repo's foreman/appender must emit the canonical complete (it must not re-serialize an agent's closed spelling). Note the writer lane in that repo's commit.
  2. Gate the commit. Install boardctl's pre-commit hook in the sibling repo so an off-vocabulary or alias status cannot be committed: bash boardctl install -C /path/to/other-repo # enforce (default) boardctl install -C /path/to/other-repo --fleet ... # fleet rollout The hook runs boardctl validate --fail-on dangling-dep, so a rewritten board carrying closed/unknown statuses is rejected before it lands.
  3. Monitor the drift. Keep validate's alias warning visible; run the off-vocabulary census (sweep-status, normalize-board dry-run) after each foreign tick. Since closed is now a warning, wip/retired/junk still fail loudly, so genuinely ambiguous values are not masked.
  4. Document the read/write split. closed is accepted on read and normalized on repair, but is still rejected by create/update/import — keep the write-rejection test in the suite so a future change cannot quietly promote an alias into the writable vocabulary.
