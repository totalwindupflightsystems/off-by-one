MOB-026 — Every speaking activity completable by text

Problem class: eduos-exec-tick-voice-text-fallback-shared-decision-module Outcome: a pure decision module that composes MOB-008 connectivity + MOB-010 capability + MOB-019 route verdicts (with spec-077 queuedOffline semantics), one shared student-facing TextFallbackPanel, and additive BETA-071 delegation. Verification: 32/32 vitest tests pass + tsc typecheck clean. Airplane-mode device E2E is explicitly deferred (not claimed).

1. Root-cause analysis

Speaking activities treated voice as the primary path and each screen classified availability on its own. That produced three classes of defect:

  1. Re-implemented classification. Screens re-derived "can I use voice?" from raw connectivity/capability checks, so the same device state yielded different results across activities.
  2. Hard gating on non-fatal states. Offline, unknown connectivity, missing mic, and (critically) the MOB-019 queued_offline verdict were all treated as blocking errors. A queued voice attempt under spec-077 is a resumable, successful state — not a failure — but it blocked completion.
  3. No shared surface. Fallback UI was duplicated or absent, so there was no single place to guarantee text completion is always offered.

The plan that worked was not to add another classifier but to compose the existing verdicts and fail open to text: the only state that selects voice is the one where every upstream signal is explicitly green. Everything else — including every unknown — selects text.

Invariant (specs/104 AC4): canCompleteWithText is always true.

2.3 Pure decision module — decision.ts

export function decideTextFallback(input: FallbackInput = {}): TextFallbackDecision {
  const connectivity = input.connectivity ?? { status: "unknown" };
  const capability = input.capability ?? { microphone: "unknown", speechToText: "unknown" };
  const route = input.route ?? { verdict: "unknown" };

  const queuedOffline =
    route.verdict === "queued_offline" || connectivity.queuedOffline === true;

  const reason = resolveReason(connectivity, capability, route.verdict, queuedOffline);
  const mode = reason === "voice-available" ? "voice" : "text";

  return {
    mode, canCompleteWithText: true, queuedOffline, reason,
    isFallback: mode === "text" && reason !== "route-prefers-text",
  };
}

function resolveReason(connectivity, capability, verdict, queuedOffline): FallbackReason {
  if (queuedOffline) return "spec077-queued-offline";   // spec-077 first
  if (verdict === "denied") return "route-denied";      // MOB-019
  if (verdict === "text") return "route-prefers-text";
  if (connectivity.status === "offline") return "connectivity-offline";
  if (connectivity.status === "unknown") return "connectivity-unknown";
  if (capability.microphone === "unavailable" ||
      capability.speechToText === "unavailable") return "capability-unavailable";
  if (capability.microphone === "unknown" ||
      capability.speechToText === "unknown") return "capability-unknown";
  if (verdict !== "voice") return "fail-open-unknown";
  return "voice-available";
}

Precedence: spec-077 queued-offline > MOB-019 verdicts > MOB-008 connectivity > MOB-010 capability > fail-open. voice is selected only when all signals are explicitly green.

2.4 Shared surface view model + additive BETA-071 delegation

buildTextFallbackViewModel(decision, activity) maps each FallbackReason to student copy, offline notice, retry-voice gating, and canSubmitText (trim + minLength). TextFallbackPanel.tsx is a thin renderer over it, so behavior is DOM-free testable and it is the only text-fallback UI.

export function bindConversationFallback(input, activity) {
  const decision = decideTextFallback(input);
  const panel = decision.mode === "text"
    ? buildTextFallbackViewModel(decision, activity) : null;
  return { panel, voiceInputEnabled: decision.mode === "voice", decision };
}
export function isCompletableByText(decision) { return decision.canCompleteWithText; }

The existing conversation flow keeps owning turns/scoring/navigation and only renders panel when non-null — purely additive.
