Fix: libpam auth/account + faillock lockout auditor

Root-cause analysis

A naive PAM replay auditor fails in four main places:

  1. Control parsing — Unknown control words are treated as required, and bracketed controls are treated as strings instead of per-return-code actions. This breaks [success=N ...], [new_authtok_reqd=N ...], [default=die], and [default=ignore].
  2. Dispatch semantics — libpam does not stop at the first failed required module. A sufficient success only terminates immediately if there was no earlier non-ignored failure. Jumps skip the next N modules of the same management type. The implementation follows libpam/pam_dispatch.c (impression, status, ok, done, bad, die, reset, jump).
  3. faillock boundary arithmetic — Real pam_faillock uses:
  4. locked while latest_failure + unlock_time >= now
  5. records counted while latest_failure - failure_time < fail_interval
  6. records expired when now - failure_time >= fail_interval

authfail returns PAM_IGNORE when it successfully records a failure, but PAM_AUTH_ERR when already locked. Root is skipped unless even_deny_root is set. 4. Delay accounting — libpam keeps the largest requested delay and applies it only when the final result is failure. pam_faillock requests 2000000 microseconds unless nodelay is set. A purely additive model overcounts.

The auditor also flags: - a sufficient module before a later requisite/default=die check - event-log gaps >= fail_interval that reset the failure counter for free - unknown control words without silently promoting them to required

Event format:

TIMESTAMP USER RESULT [key=value ...]

Examples:

0 alice failure
1 alice failure
2 alice failure
3 alice success
13 alice success
2024-01-01T00:00:00Z root failure uid=0

Output columns:

timestamp user decision status module line delay_us cumulative_delay_us

decision is success or failure. delay_us is the applied delay for that attempt; cumulative_delay_us is the running total. Use --delay-mode sum to sum every delay request instead of using libpam’s max-request rule.

Key corrected dispatch logic:

case $action in
    ok|done)
        if ((impression == 0)); then
            take_ok=1
        elif ((impression == 1)) && [[ $status == success ]]; then
            take_ok=1
        fi
        if ((take_ok)) && [[ $retval != ignore ]]; then
            impression=1
            status=$retval
        fi
        if ((impression == 1)) && [[ $action == done ]]; then
            decision_made=1
        fi
        ;;
    bad|die)
        if ((impression != -1)); then
            impression=-1
            [[ $retval == ignore ]] && status=perm_denied || status=$retval
        fi
        [[ $action == die ]] && decision_made=1
        ;;
esac

Key corrected faillock boundary logic:

# still locked at the exact unlock_time boundary
if ((latest + unlock_time < now)); then
    unlocked=1
else
    locked=1
fi

# count only failures inside fail_interval
if ((latest - failure_time < fail_interval)); then
    ((failures++))
fi

# expire old tally records
if ((now - failure_time >= fail_interval)); then
    discard_record
fi
