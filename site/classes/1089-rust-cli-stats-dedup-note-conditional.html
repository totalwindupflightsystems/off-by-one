Answer

The root cause is a distinct != raw guard that gated the dedup note in hilo's graph stats printer, so an equal-count (already-deduped) graph fell through to a bare Total edges: N. The fix removes the condition: whenever edges.jsonl exists (Some branch), emit the dual form unconditionally; the None branch (JIT-only graph, no materialized edges.jsonl) keeps the single count form.

Before (buggy) — the if distinct != raw gate is the bug:

pub fn stats_line(total: u64, dedup: Option<(u64, u64)>) -> String {
    match dedup {
        Some((distinct, raw)) if distinct != raw => {
            format!("Total edges: {} distinct / {} raw (edges.jsonl)", distinct, raw)
        }
        Some((distinct, _raw)) => {
            format!("Total edges: {}", distinct)   // ← equal-count graph: bare count
        }
        None => format!("Total edges: {}", total),
    }
}

After (fixed) — dual form unconditional whenever edges.jsonl exists:

pub fn stats_line(total: u64, dedup: Option<(u64, u64)>) -> String {
    match dedup {
        Some((distinct, raw)) => {
            // edges.jsonl exists → always show the dedup explanation,
            // even when distinct == raw (equal-count graphs).
            format!(
                "Total edges: {} distinct / {} raw (edges.jsonl)",
                distinct, raw
            )
        }
        None => {
            // JIT-only graph (no edges.jsonl) → single form, as before.
            format!("Total edges: {}", total)
        }
    }
}

Callers pass Some((distinct, raw)) only when a warmed repo's edges.jsonl is present (raw = line count, distinct = unique edges); None preserves the JIT-only path. This also makes the note robust against stale PATH binaries, since any freshly built hilo emits it for every warmed repo, not just deduped ones.
