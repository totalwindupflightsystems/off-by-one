Fixing docs-stage-status-drift (stale PRD stage table + README headline)

Summary

A merged PRD artifact (docs/PRD.md) and the README headline claimed pipeline stages were not built (tatara_nodes, tatara_build, tatara_test, tatara_publish, tatara_report) while the corresponding modules had long been landed. The fix is not to hand-edit the merged artifact. You verify each cell against module provenance, edit the PRD source fragment (docs/prd/C1-*.md), regenerate with scripts/merge-prd.py, prove idempotency with a second run, and preserve any defect note that is still true (the DuckBrain compound-filter claim defect).

Root cause analysis

Symptom. The stage-status table and README headline are stale: they report not built for stages whose modules already exist.

Cause. Status is hand-maintained prose while the truth lives in module provenance. Nothing couples "stage module landed" to "status cell says not built", so the prose rots silently after each landing.

Why it survives review. (1) Reviewers trust the row text instead of checking git log/module existence. (2) Patching the stale cell directly in the generated docs/PRD.md is overwritten or creates source/artifact divergence — the source of truth is docs/prd/C1-*.md.

Key insight. Status is derivable. Validate each row against git log --oneline -1 -- scripts/tatara_<stage>.py, never against the previous row text.

The fix (portable procedure)

Step 0 — Establish provenance (do not trust the row text)

for s in nodes build test publish report duckbrain; do
  printf '%-8s ' "$s"
  git log --oneline -1 -- "scripts/tatara_${s}.py"
done

grep -c '| not built' docs/PRD.md || true   # grep exits 1 when count is 0

Step 1 — Find the source of truth

  • Source fragments: docs/prd/C1-*.md (the only files you edit)
  • Merged artifact: docs/PRD.md — header says DO NOT EDIT; regenerate only
  • Generator: scripts/merge-prd.py

Step 2 — Edit the source fragment, preserving still-true facts

-| duckbrain | not built | Known defect: compound-filter claim is not implemented |
+| duckbrain | built     | Known defect: compound-filter claim is not implemented |

Status and defect are orthogonal facts: update the status, keep the note.

Step 3 — Regenerate and prove idempotency

python3 scripts/merge-prd.py
h1=$(sha256sum docs/PRD.md | awk '{print $1}')
python3 scripts/merge-prd.py
h2=$(sha256sum docs/PRD.md | awk '{print $1}')
[ "$h1" = "$h2" ] && echo "IDEMPOTENT" || echo "NOT IDEMPOTENT"

A second run must produce zero bytes of change.

Step 4 — Fix the README headline

-Implementation status: nodes, build, test, publish and report are **not built**.
+Implementation status: nodes, build, test, publish and report are **built**.

Step 5 — Verify

grep -c '| not built' docs/PRD.md || true                        # expect 0
grep -c 'compound-filter claim is not implemented' docs/PRD.md    # expect 1
git diff --stat                                                   # only intended files
git --no-pager diff                                               # only intended cells

Regression guard

scripts/check-status-drift.sh fails when a landed module is still marked not built. Verified:

# after reintroducing one stale cell:
DRIFT: nodes module exists but PRD says 'not built'
guard-exit=1

Pitfalls

  • Never edit docs/PRD.md — it is generated; edit docs/prd/C1-*.md then regenerate.
  • grep -c exits 1 at zero matches — use || true under set -e.
  • Don't delete true defect notes along with the stale status.
  • Prove idempotency by hash comparison; don't assume determinism.
  • Keep the diff minimal — git diff --stat must list only source, regenerated artifact, and README.
