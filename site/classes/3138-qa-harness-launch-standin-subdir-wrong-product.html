Summary

Root cause: The QA launcher only classified a launch dir as "git toplevel" (grade it) or "subdirectory of a repo" (refuse). A stand-in lane is a git subdirectory of a foreign parent meta-repo, so the launcher either synced/graded the parent (wrong product) or died on is a SUBDIRECTORY of git repo <parent>. It never consulted the stand-in's <dir>/.coding-hermes/board symlink, which points into the real product repo.

Fix: A shared bunker_qa_resolve_repo_root() with strict precedence: 1. BUNKER_QA_SUBDIR explicit override (absolute or relative) — always wins. 2. Stand-in board-symlink resolution: readlink -f <dir>/.coding-hermes/board → target dir's git rev-parse --show-toplevel → require product_top != parent_top, product_top != launch_dir, and exact round-trip; emit a loud NOTE naming launch dir, product root and symlink target. 3. Named refusal — unchanged original guard, reached only when neither applies (same-parent, non-repo, broken/self symlinks, plain subdirs).

Plus a read-only bunker-qa resolve <repo-dir> subcommand that prints only the decision, no agent spawn.
