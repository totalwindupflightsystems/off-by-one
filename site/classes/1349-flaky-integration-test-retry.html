Summary

Root cause: Retry logic was gated entirely on output_schema, and that gate wrapped a single detector. So the aggregator's validation-failure envelope {"passed": false, "errors": [...]} arriving on a non-schema deliberation was never retried, flowed into the HTML check, and raised AssertionError: No html tag or doctype found ….

Fix: Split the detector in tests/integration/test_collaborative_evals.py: - _is_validation_failure_object(text) — matches {passed: false, errors: [...]} → retry unconditionally (never a legitimate answer). - _is_degraded_schema_answer(text) — the no-JSON-no-HTML heuristic; stays gated on has_output_schema so prose answers (math proofs) don't burn all retries. - _should_retry(text, has_output_schema) composes the two, keeping behavior consistent everywhere.

Verification: Includes targeted pytest -k collaborative_static_website, a self-test snippet asserting both detector paths, and a note that a separately-flaking sibling SSE test gets its own row while this issue stays closed.

One caveat: this sandbox doesn't have the chimera checkout, so I couldn't diff the actual file — the two new functions plus the gating change are complete, and the doc flags the two placeholders (_retry_payload(...) and the has_output_schema flag name) to match your exact utility signatures.
