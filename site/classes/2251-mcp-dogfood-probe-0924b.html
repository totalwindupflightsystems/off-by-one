Solution: mcp-dogfood-probe-0924b — empty MCP tools/call probe

Summary

The probe payload carries no diagnostic content: error_message, stack_trace, version and context are all empty, and the only human-readable text is "second probe via MCP tools/call". There is therefore no failing program, stack frame, or error string to reproduce. This is a synthetic health probe emitted through an MCP tools/call, not a bug report.

A diagnostic sweep of the sandbox found exactly one concrete environment anomaly, and it is the only actionable defect:

~/.local/bin/go and ~/.local/bin/gofmt are stale, broken symlinks pointing at /home/kara/sdk/go1.26.5/{go,gofmt}. That directory does not exist. The real toolchain is the system Go 1.26.0 at /usr/lib/go-1.26 (/usr/bin/go).

The anomaly is masked in normal use because Bash/exec.LookPath skip broken symlinks and fall through to /usr/bin/go, but any code/tooling that invokes the resolved ~/.local/bin/go path directly fails with No such file or directory (exit 127).

Root-cause analysis

  1. Input side (the reported "problem"). /workspace/problem.json contains: json { "problem_class": "mcp-dogfood-probe-0924b", "environment": "linux", "language": "go", "version": "", "description": "second probe via MCP tools/call", "error_message": "", "stack_trace": "", "context": {} } All failure-bearing fields are empty. There is no state that can be evaluated as "broken", so the probe is a negative control / liveness check, not a defect.

  2. Toolchain side (the only real anomaly). PATH order inside the sandbox is: /tmp/pi-agent-1000/bin:/home/kara/.local/bin:/usr/local/bin:/usr/bin:/bin /home/kara/.local/bin precedes /usr/bin and contains: go -> /home/kara/sdk/go1.26.5/bin/go (target missing) gofmt -> /home/kara/sdk/go1.26.5/bin/gofmt (target missing) /home/kara/sdk does not exist. The intended SDK (Go 1.26.5 at a user-local prefix) was never installed or was removed, leaving dangling links. The system toolchain is Go 1.26.0 at /usr/lib/go-1.26.

  3. Why the difference normally does not surface. A PATH search (command -v, type -a, exec.LookPath, Bash lookup) treats a dangling symlink as non-existent and continues to /usr/bin/go, so go version, go build, go test, go vet, gofmt all work. The failure only appears when the dangling path is used literally: $ /home/kara/.local/bin/go version /bin/bash: line 1: /home/kara/.local/bin/go: No such file or directory (exit 127) That is the classic "works for me, fails in the harness/Makefile" trap for a dogfood/probe tool that resolves the binary path once and reuses it.

  4. Scope note. /home/kara/.local/bin is mounted read-only inside the bwrap sandbox (... /home/kara/.local/bin type ext4 (ro,...)), so the repair must be made on the host (or by removing the shadowing directory from the probe's PATH).

Exact fix

On the host (outside the bwrap sandbox, where ~/.local/bin is writable), repoint the two dangling links at the installed system Go, or delete them so the system Go is used unambiguously.

Option A — repoint (preserves the ~/.local/bin/go entry):

# Verify current damage
ls -l ~/.local/bin/go ~/.local/bin/gofmt
readlink -f ~/.local/bin/go || echo "dangling"

# Repoint to the system toolchain actually present (Go 1.26.0, /usr/lib/go-1.26)
ln -sfn /usr/bin/go    ~/.local/bin/go
ln -sfn /usr/bin/gofmt ~/.local/bin/gofmt

# Re-check
ls -l ~/.local/bin/go ~/.local/bin/gofmt
/home/kara/.local/bin/go version

Option B — remove the shadowing links:

rm -f ~/.local/bin/go ~/.local/bin/gofmt
# PATH then resolves /usr/bin/go and /usr/bin/gofmt directly.

If the probe genuinely needs Go 1.26.5 (the version the links expected), install the missing SDK instead of downgrading the links:

# Either provide the expected SDK tree ... so /home/kara/sdk/go1.26.5/bin/go exists
# ... or let the Go toolchain self-provision when go.mod demands it:
#   GOTOOLCHAIN=auto  (default) automatically downloads go1.26.5 on demand.

For a probe/make target that must be robust in this sandbox, resolve the binary at run time instead of hardcoding the home path:

GO="$(command -v go)"        # skips the dangling symlink, returns /usr/bin/go
"$GO" version
