Answer 1

Solution written to ~/websocket-topic-subscription-fix.md.

The repository wasn't present in this environment, so I reconstructed the exact defect from your description into a runnable project at /tmp/ws-bug, reproduced it with real ws sockets, fixed it, and verified.

Root cause (two compounding bugs)

EventBus is keyed by event type (game:state, player:joined, …) but handleJoinGame subscribed using the game id as the type:

eventBus.on(`game:${gameId}`, ...)   // key "game:g1" — never an event.type → never fires

Even if it had fired, the callback did broadcastToGame(..., { excludeClientId: client.id }), which skips the joiner — so a lone spectator always gets nothing. The returned unsubscribe was also discarded, leaking listeners across leave/disconnect/re-join.

The fix

const handleJoinGame = (client: Client, gameId: string): void => {
  client.unsubscribeGame?.();          // re-join safety: no stacked listeners
  client.unsubscribeGame = undefined;
  client.rooms.add(gameId);

  // EventBus is event-TYPE keyed; wildcard + explicit gameId filter.
  client.unsubscribeGame = eventBus.subscribeAll((event: GameEvent) => {
    if (event.gameId !== gameId) return;
    broadcastToGame(gameId, event);    // spectator semantics: NO excludeClientId
  });
};

Plus: store the teardown on the client, and call client.unsubscribeGame?.() in handleLeaveGame and the socket close handler. EventBus.subscribeAll (returns an unsubscribe) is included in the doc if the bus lacks it.

Verification (real sockets, Vitest)

cd /tmp/ws-bug
npm install
npx tsc --noEmit          # TSC OK
npx vitest run --reporter=verbose

✓ lone joiner > FIXED: the only client receives its own game event
✓ lone joiner > BUGGY: the topic never fires, so the lone joiner gets nothing
✓ lone joiner > BUGGY: a direct game-topic publish still skips the joiner (excludeClientId)
✓ two clients > FIXED: both receive
✓ gameId filter > FIXED: other game's events not delivered
✓ leave/re-join > FIXED: leave stops delivery
✓ leave/re-join > FIXED: re-join resubscribes exactly once (no duplicates)
✓ leave/re-join > FIXED: disconnect unsubscribes and keeps server healthy
