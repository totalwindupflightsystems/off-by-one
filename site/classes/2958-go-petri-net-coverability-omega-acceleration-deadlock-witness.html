Petri-Net Coverability with ω-Acceleration and Deadlock Witnesses: Diagnosis and Fix

1. Executive summary

The specification asks for a Go engine that reads a Petri net as JSON, decides each query as coverable / uncoverable / unbounded using a Karp–Miller tree with ω acceleration, emits a concrete cycle for unbounded answers, reports accelerated-node count, and finds the shortest lexicographically tie-broken firing sequence to a deadlock with a canonical marking hash.

It contains one critical, non-obvious defect: a Karp–Miller tree with ω acceleration is unsound for nets with inhibitor arcs, because inhibitor arcs destroy the monotonicity the whole Karp–Miller argument rests on. A literal implementation returns wrong answers on valid inputs. The fix:

  1. represent ω as a proper extended natural (not an integer sentinel),
  2. only accelerate along a cycle whose inhibitor guards are preserved, and only prune by a dominator that agrees on every inhibitor place's zero status,
  3. prove uncoverability on inhibitor nets only by exhausting the explicit finite reachable state space, returning unknown instead of lying.

For inhibitor-free nets the engine degenerates to textbook Karp–Miller and is complete.

2. Root-cause analysis

Semantics. t enabled at M iff M(p) ≥ in(p) for every input and M(q) == 0 for every inhibitor q; firing yields M − in + out. Empty in/out is a self-loop.

2.1 Critical: ω-acceleration is unsound with inhibitor arcs

Karp–Miller acceleration folds a growing token count into abstract ω. Its correctness relies on monotonicity: if M ≤ N and a transition fires at M, it also fires at N. Inhibitor arcs invert this — more tokens can disable a zero-test. So acceleration can erase the exact finite value needed to pass a zero-test, and dominance pruning can discard the only state that can fire a guarded transition.

Concrete counterexample:

places: p1, p2
t1: in {p1:1} out {p1:2}                (p1 += 1)
t2: in {p1:2} out {}                    (p1 -= 2)
t3: in {}     out {p2:1} inhibit [p1]   (needs p1 = 0)
initial: p1 = 1
query:   p2 ≥ 1

Real execution: p1=1 --t1--> 2 --t2--> 0 --t3--> p2=1. Textbook Karp–Miller accelerates p1=2 to ω, loses the value 2, never enables t3, and reports uncoverable — a false negative. (The symmetric false positive also exists: accelerating a place that a guard disables once positive.)

Why the spec's escape hatch fails. Finkelstein generalized acceleration only strengthens how much is accelerated at once; it does not restore monotonicity. The real distinction is monotone nets vs. zero-tests, not plain ω vs. generalized ω.

2.2 ω must be an extended natural

Encoding ω as a large int or -1 breaks the ancestor-coverage test (a ≤ m') or arithmetic, so acceleration never fires and the tree fails to close. Use an explicit ℕ ∪ {ω} total order with saturated arithmetic (ω ± k = ω, ω > every natural, ω = ω).

2.3 "Canonical under place permutation" hash

A hash invariant under arbitrary place re-identification would merge {p1:1,p2:0} with {p1:0,p2:1} — wrong. What is needed is a key independent of input array order: sort place names once, fix that index order, and key by it.

2.4 Accelerated-node count is not a termination proof

The count is a diagnostic. Inhibitor-free termination follows from the classic Karp–Miller measure (ω is monotone along a branch, finite parts drawn from a finite set). On inhibitor nets the sound tree may not terminate, so a node budget is used and unknown is returned.

2.5 Deadlock BFS on unbounded nets

Shortest-deadlock is only guaranteed finite on bounded nets. The engine uses a bounded BFS, exact when the reachable state space is finite, and flags search_truncated so it never silently lies.

3. The fix (exact code)

The complete runnable source is main.go (embedded in SOLUTION.md). The critical pieces:

Extended naturals — the correct ω order:

const omega = -1

func extLeq(a, b int) bool {          // a <= b in N ∪ {ω}
    if a == omega { return b == omega }
    if b == omega { return true }
    return a <= b
}
func vecLeq(a, b []int) bool {
    for i := range a {
        if !extLeq(a[i], b[i]) { return false }
    }
    return true
}
// fire(): if out[i] != omega { out[i] -= c } ... ; saturating, so omega stays omega.

Sound acceleration — guard places of the cycle must not change:

func (e *Engine) cycleGuards(a, n *KMNode, t *Transition) map[int]bool {
    guard := map[int]bool{}
    for _, p := range t.Inhibit { guard[e.index[p]] = true }
    for x := n; x != a; x = x.parent {
        for _, p := range e.trans[x.via].Inhibit { guard[e.index[p]] = true }
    }
    return guard
}
func (e *Engine) accelSound(a, m []int, guard map[int]bool) bool {
    if !e.hasInhibitors { return true }
    for q := range guard {
        if a[q] != omega && m[q] != omega && m[q] != a[q] { return false }
    }
    return true
}

Sound dominance pruning — dominator must preserve zero/non-zero on inhibitors:

func (e *Engine) prunableByAny(nodes []*KMNode, m []int) bool {
    for _, n := range nodes {
        if !vecLeq(m, n.marking) { continue }
        if e.hasInhibitors {
            safe := true
            for _, q := range e.inhPlaces {
                if m[q] == 0 && n.marking[q] != 0 { safe = false; break }
            }
            if !safe { continue }
        }
        return true
    }
    return false
}

Generalized (all-places-at-once) acceleration in buildKM:

for a := n; a != nil; a = a.parent {
    if !vecLeq(a.marking, m) || !e.accelSound(a.marking, m, e.cycleGuards(a, n, t)) {
        continue
    }
    prefix := pathFromRoot(a, e)
    var path []string
    for x := n; x != a; x = x.parent { path = append(path, e.trans[x.via].Name) }
    reverse(path)
    cycle := append(append([]string{}, path...), t.Name)
    for p := range m {
        if a.marking[p] != omega && m[p] != omega && m[p] > a.marking[p] {
            m[p] = omega; acc = true
            cycles[p] = AccWitness{Prefix: prefix, Cycle: cycle}
        }
    }
}

Decision procedure (evalQuery): ω-only cover ⇒ unbounded + replayable cycle; finite tree node or explicit BFS state ⇒ coverable; no cover + (inhibitor-free complete tree) or BFS-exhausted ⇒ uncoverable; else unknown.

Deadlock BFS (runBFS): canonical sorted-place keys, FIFO BFS with transitions visited in name order — the first deadlock found is the lexicographically smallest shortest witness; returns exhausted to prove finite state spaces.

Output: adds unknown because the three spec values are insufficient on inhibitor nets; every other value is exact.
