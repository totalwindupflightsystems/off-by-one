Citing gitreins verdict evidence by both ID namespaces

Problem class: gitreins-verdict-evidence-cited-by-two-id-namespaces Case: EduOS QA-EDUOS-6 (t629) Status: diagnosed, fix specified, recipe verified in a self-contained reproduction

1. Symptom

Completion notes and test-state.toml entries recorded the gitreins judge result using the verdict commit id (e.g. b334dee1, a commit on the gitreins branch with message verdict: <TASK> - PASS). But the evidence lives under the run-dir id (6fd74599):

.gitreins/history/<date>/6fd74599/
├── summary.md
└── verdict.json

grep -r b334dee1 .gitreins/history/ matches nothing — the commit id is a git object name, the run dir is named after the run id. Resolving this cost four probes (dir list, content grep, git cat-file, git log gitreins). Both ids are real and consistent: the verdict commit diffs exactly the run-dir files, and verdict.json carries task_id + passed: true. The failure is a citation conflation of two namespaces.

2. Root cause

Namespace What it is Discoverable via Greps for it
run id (6fd74599) Directory name of one judge run .gitreins/history/<date>/<run-id>/ grep/find under history
verdict commit id (b334dee1) Git commit on gitreins packaging that run dir git log gitreins / git show git, never a history grep

The author cited the SHA most prominent in git log as if it were the run handle; an auditor following the documented lookup path cannot find it. The convention that works (docs-only fix, commit 5869de2a) is to cite both ids in one phrase.

3. Exact fix

3.1 Canonical citation format

Document in AGENTS.md/CONTRIBUTING.md:

Always cite both id namespaces in one phrase: judge run <run-id> (verdict commit <commit-id>). <run-id> is the newest run dir under .gitreins/history/<date>/ containing the task in verdict.json; <commit-id> is the gitreins-branch commit packaging exactly that run dir. Never cite the commit alone, never treat the run id as a git ref.

Example test-state.toml block:

[tasks."QA-EDUOS-6"]
status = "done"
evidence = "judge run 6fd74599 (verdict commit b334dee1)"

3.2 Helper scripts/gitreins-evidence-ids.sh

#!/usr/bin/env sh
# usage: gitreins-evidence-ids.sh <TASK_ID>
set -eu
TASK=${1:?usage: gitreins-evidence-ids.sh <TASK_ID>}

VJSON=$(grep -rl "\"task_id\"[[:space:]]*:[[:space:]]*\"$TASK\"" \
          .gitreins/history/*/*/verdict.json 2>/dev/null \
        | xargs -r ls -1dt 2>/dev/null | head -n1)
[ -n "${VJSON:-}" ] || { echo "no judge run found for task $TASK" >&2; exit 1; }
RUNDIR=$(dirname "$VJSON"); RUN_ID=$(basename "$RUNDIR"); DATE=$(basename "$(dirname "$RUNDIR")")

CMT=$(git log gitreins --format=%h -- ".gitreins/history/$DATE/$RUN_ID" | head -n1)
[ -n "${CMT:-}" ] || { echo "no verdict commit packages run $RUN_ID" >&2; exit 1; }

printf 'judge run %s (verdict commit %s)\n' "$RUN_ID" "$CMT"

Newest-mtime variant for step 1: DATE=$(date +%F); RUNDIR=$(ls -1dt .gitreins/history/"$DATE"/*/ | head -n1); RUN_ID=$(basename "$RUNDIR").

3.3 Optional CI lint

Fail if a verdict-commit SHA is cited without an accompanying run id:

#!/usr/bin/env sh
set -eu; fail=0
for f in "$@"; do
  if grep -nE 'verdict commit [0-9a-f]{7,40}' "$f" >/dev/null 2>&1; then
    grep -nE 'judge run [0-9a-f]{6,}( .verdict commit [0-9a-f]{7,40}.)?' "$f" >/dev/null 2>&1 \
      || { echo "$f: verdict commit cited without run id" >&2; fail=1; }
  fi
done
exit "$fail"

4. Verification

Auditor recipe for judge run 6fd74599 (verdict commit b334dee1):

cat .gitreins/history/<date>/6fd74599/verdict.json   # task_id + passed
git show --stat b334dee1                             # only the run-dir files
grep -rl 6fd74599 .gitreins/history/                 # run id hits
grep -rq b334dee1 .gitreins/history/ && echo unexpected || echo "absent: expected"

The commit diff is exactly the target run dir, the run id greps under history, the commit id does not — confirming the two-namespace model and that the helper binds them correctly. (The demo built verdict: QA-EDUOS-6 - PASS as a clean commit containing only summary.md + verdict.json; git show --stat confirms it.)

5. One-line summary

The citation was wrong, not the evidence: a git commit id was used where the history tree is keyed by a run-dir id. Fix: always cite judge run <run-id> (verdict commit <commit-id>), derive the run id from .gitreins/history/<date>/ and the commit id from git log gitreins -- <run-dir>, verify with cat .../verdict.json + git show --stat <commit-id>.
