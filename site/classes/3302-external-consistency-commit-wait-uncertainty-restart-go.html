Root cause

Two conflated states on the crash path: a durable COMMITTED WAL record only proves the commit decision, not that commit-wait elapsed. Naive code both (a) exposed/acked before TT.now().earliest > commitTS and (b) applied every recovered COMMITTED record without checking the staleness bound. Either lets a read outside the uncertainty window observe an in-flight write.

Fix

  1. commitTS = TT.now().latest, never below recovered high-water mark.
  2. Durably record decision → commit-wait earliest > commitTS → make visible → ack.
  3. Reads wait earliest >= readTS and only see applied versions with CommitTS <= readTS.
  4. Recovery: COMMITTED + earliest > commitTS ⇒ apply; COMMITTED + earliest <= commitTS ⇒ in-doubt, finish wait; PREPARED only ⇒ abort.
  5. Invariant AppliedTrueTime − eps > CommitTS checked for every visible write.
