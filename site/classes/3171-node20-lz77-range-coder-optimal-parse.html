Diagnosis

The workspace was empty, so this was a from-scratch build. Two bugs are the crux — both corrupt output only once the range coder spans more than a few dozen bytes:

  1. Range-coder carry bug. LZMA's ShiftLow ends with Low = (UInt32)Low << 8. The natural JS translation (low >>> 0) * 256 keeps bits 32–39, so the next carry is 0–255 instead of 0/1. Symptom: 1–36 byte inputs round-tripped; a 5000-byte input failed with distance 40 exceeds output position 36. Fix: this.low = (this.low << 8) >>> 0.
  2. Reverse bit-tree decode bug. LZMA reverse trees emit bits LSB-first; the decoded value is sym |= bit << i. Returning the tree-path index m - 2^n yields the bit-reversed value (2-bit 1 → 2; distance 9 → 10). Fix: accumulate sym while walking the tree.

Plus the structural issue: greedy longest-match is not optimal, and untyped decoding can hang or return short output.

Solution (lzrc/src/lzrc.js, dependency-free)

  • MatchFinder — hash chains returning a Pareto frontier of matches; lazyParse (greedy + one-step lookahead) and optimalParse (forward DP).
  • RangeEncoder/RangeDecoder — 11-bit adaptive probs, shift 5.
  • LZMA-style decomposition — previous-byte literal trees, position-state isMatch, 9-bit length tree, 6-bit slot tree + direct bits + 4-bit reverse align tree.
  • Price table — PROB_PRICE0/1, fixed-point 1/16 bit; the DP precomputes length/slot prices and prices each length once from the closest distance. A cheap lazy pass warms prices; the real bitstream uses a fresh model, so prices guide the parse only.
  • Container — "LZR1", version, model params, size, data CRC32, payload, stream CRC32. decompress checks the stream CRC first, restricts the decoder to the payload slice, and uses a bounded loop.
  • Model.serialize/deserialize — deterministic replay.
  • Typed errors — TRUNCATED, BAD_MAGIC, BAD_VERSION, STREAM_CHECKSUM, DATA_CHECKSUM, INVALID_DISTANCE, INVALID_LENGTH, OVERRUN, UNEXPECTED_EOF.
