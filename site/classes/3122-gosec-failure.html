Answer

Fix: gosec CI re-flags rules already dispositioned in .golangci.yml

Root cause

The standalone securego/gosec action does not read .golangci.yml. That file is a golangci-lint configuration, so the repo’s linters.settings.gosec.excludes policy only applies to the golangci-lint lane.

The failing workflow used:

uses: securego/gosec@master
with:
  args: ./...

That means:

  1. No exclusions were passed to standalone gosec, so it re-reported all 102 already-dispositioned findings (G104, G118, G115, G705, etc.).
  2. @master is a moving dev build, so CI behavior can drift independently of the repo’s pinned tooling.
  3. The two AWS SNS SHA-1 sites were suppressed with //nolint:gosec, which only golangci-lint understands. Standalone gosec ignores it and still reports G401/G505.

The fix is to mirror the repo policy into the standalone invocation, pin the action, and use #nosec for the two protocol-required SHA-1 sites so the suppression works in both lanes.

Fix

1. Add a policy extractor

Create .github/scripts/gosec-excludes.awk:

# Extract linters.settings.gosec.excludes from .golangci.yml as a comma-separated list.
function trim(s) { sub(/^[[:space:]]+/, "", s); sub(/[[:space:]]+$/, "", s); return s }
function unquote(s) { gsub(/^["'\'']|["'\'']$/, "", s); return s }
BEGIN { in_gosec=0; in_excludes=0; gosec_indent=-1; excludes_indent=-1; out="" }
{
  line=$0
  sub(/[[:space:]]*#.*$/, "", line)
  if (line ~ /^[[:space:]]*$/) next
  match(line, /^[[:space:]]*/)
  indent=RLENGTH
  content=substr(line, indent+1)

  if (content ~ /^gosec:[[:space:]]*$/) {
    in_gosec=1; gosec_indent=indent; in_excludes=0; next
  }
  if (in_gosec && indent <= gosec_indent) {
    in_gosec=0; in_excludes=0
  }
  if (in_gosec && content ~ /^excludes:[[:space:]]*\[/) {
    item=content
    sub(/^excludes:[[:space:]]*\[/, "", item)
    sub(/\][[:space:]]*$/, "", item)
    n=split(item, arr, ",")
    for (i=1; i<=n; i++) {
      v=trim(arr[i]); v=unquote(v)
      if (v != "") out = (out == "" ? v : out "," v)
    }
    next
  }
  if (in_gosec && content ~ /^excludes:[[:space:]]*$/) {
    in_excludes=1; excludes_indent=indent; next
  }
  if (in_excludes) {
    if (indent <= excludes_indent) { in_excludes=0; next }
    if (content ~ /^-/) {
      item=content
      sub(/^-[[:space:]]*/, "", item)
      item=trim(item); item=unquote(item)
      if (item != "") out = (out == "" ? item : out "," item)
      next
    }
  }
}
END { print out }

This reads the exact list from .golangci.yml, so the standalone lane cannot drift from the repo policy.

2. Pin the action and pass the extracted excludes

Replace the gosec workflow with:

name: gosec

on:
  push:
  pull_request:

permissions:
  contents: read
  security-events: write

jobs:
  gosec:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Read gosec exclusions from repo policy
        id: gosec-policy
        shell: bash
        run: |
          set -euo pipefail
          excludes="$(awk -f .github/scripts/gosec-excludes.awk .golangci.yml)"
          if [ -z "$excludes" ]; then
            echo "::error file=.golangci.yml::No linters.settings.gosec.excludes list found"
            exit 1
          fi
          echo "excludes=$excludes" >> "$GITHUB_OUTPUT"

      - name: Run gosec
        uses: securego/gosec@v2.30.0
        with:
          args: "-exclude=${{ steps.gosec-policy.outputs.excludes }} ./..."

The key changes are:

-      - uses: securego/gosec@master
+      - name: Read gosec exclusions from repo policy
+        id: gosec-policy
+        shell: bash
+        run: |
+          set -euo pipefail
+          excludes="$(awk -f .github/scripts/gosec-excludes.awk .golangci.yml)"
+          test -n "$excludes"
+          echo "excludes=$excludes" >> "$GITHUB_OUTPUT"
+
+      - uses: securego/gosec@v2.30.0
         with:
-          args: ./...
+          args: "-exclude=${{ steps.gosec-policy.outputs.excludes }} ./..."

If you prefer a static list, run:

awk -f .github/scripts/gosec-excludes.awk .golangci.yml

Then paste the full comma-separated output into args: "-exclude=... ./...". Do not hand-copy only the rules from the error message; use the full policy list.

3. Replace the two SHA-1 //nolint:gosec directives

Find the sites:

rg -n 'crypto/sha1|sha1\.New|//nolint:gosec' --glob '*.go'

Replace the golangci-only directives with gosec-native #nosec annotations that include the rule ID and a justification.

Before:

import "crypto/sha1" //nolint:gosec

// ...

h := sha1.New() //nolint:gosec

After:

import "crypto/sha1" // #nosec G505 -- SHA-1 is required by the AWS SNS signature protocol.

// ...

// #nosec G401 -- SHA-1 is required by the AWS SNS signature protocol.
h := sha1.New()

If the import is in a block, this form also works:

import (
    // #nosec G505 -- SHA-1 is required by the AWS SNS signature protocol.
    "crypto/sha1"
)

Important:

  • Remove the old //nolint:gosec; do not leave both. Once gosec self-suppresses via #nosec, the old //nolint can become an unused directive and trigger nolintlint.
  • Do not add G401/G505 to the exclude list. They must remain active globally; only these two protocol-required sites are suppressed.
  • The -- reason form satisfies gosec’s -nosec-require-justification and -nosec-require-rules checks if those are enabled.

Verification

Run the same policy extraction and gosec version locally:

#!/usr/bin/env bash
set -euo pipefail

# 1. Action must be pinned, not @master.
grep -q 'securego/gosec@v2.30.0' .github/workflows/gosec.yml
if grep -q 'securego/gosec@master' .github/workflows/gosec.yml; then
  echo "gosec action is still on @master" >&2
  exit 1
fi

# 2. Extract the exact repo policy list.
policy="$(awk -f .github/scripts/gosec-excludes.awk .golangci.yml)"
test -n "$policy"
echo "policy excludes: $policy"

# 3. Run the same gosec version and args locally.
gobin="$(mktemp -d)"
GOBIN="$gobin" go install github.com/securego/gosec/v2/cmd/gosec@v2.30.0
"$gobin/gosec" -exclude="$policy" ./...
echo "gosec exit: $?"

# 4. Both lanes must pass.
golangci-lint run ./...

Expected result:

policy excludes: G104,G115,G118,G705,...
...
Summary:
  Gosec  : 2.30.0
  Files  : ...
  Lines  : ...
  Nosec  : 2
  Issues : 0
gosec exit: 0

golangci-lint run ./... must also exit 0, with no nolintlint unused-directive errors.

I verified the suppression mechanics with gosec v2.30.0 locally: without the annotations, G401 and G505 are reported and gosec exits 1; with #nosec G401 -- ... and #nosec G505 -- ..., the summary shows Nosec: 2, Issues: 0, and exit 0.
