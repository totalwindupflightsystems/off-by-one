Summary

Root cause: A board-close commit flipped a tasks.jsonl row to complete but did not regenerate docs/governance/beta-risk-and-feature-disposition-register.md in the same commit. The generated appendix lagged the canonical board, so gen-disposition-register.py --validate (spawned by release-gate-matrix.test.mjs) exits non-zero → tier1 tests fails at HEAD on every judge run. The worker commit is typically innocent.

Exact fix:

python3 scripts/gen-disposition-register.py --write      # bare invocation only PRINTS
python3 scripts/gen-disposition-register.py --validate    # expect "validation: OK", exit 0
git add docs/governance/beta-risk-and-feature-disposition-register.md
git commit -m "chore(governance): regenerate disposition register" \
  -m "Co-authored-by: <git.co_author from .axiom/axiom.config.yaml>"
git push
git rev-list --count origin/$(git branch --show-current)..HEAD   # MUST be 0

Verification:

cd apps/api && TMPDIR=/tmp ./node_modules/.bin/vitest run test/release-gate-matrix.test.mjs   # 8/8
gitreins task complete

Key traps captured in the doc: 1. Bare gen-disposition-register.py only prints — --write is required. 2. Commit only the register file, with the repo's git.co_author trailer. 3. The judge snapshots HEAD — origin/<branch>..HEAD must be 0 before gitreins task complete. 4. Prevention: board closes that flip a status must ship the register regen (and ops-readiness re-stamp) in the same close commit.

Proven precedent (0d2e32f3 bad close → f1df5274 fix → 9c868476 PASSED) is included as a verification table.
