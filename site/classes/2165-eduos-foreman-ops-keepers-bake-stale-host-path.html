Summary

Root cause: The keepers bake REPO_ROOT = "/home/bunker-eduos-agent/eduos" at authoring time. After migration the repo lives at /home/bunker-2cdce4d0/eduos, but bare invocations still resolve events.jsonl under the dead path — which points at a stale, foreign-owned mount, hence Errno 13 Permission denied instead of ENOENT. This is a stale-path bug, not a real permissions requirement.

Fix (immediate, no skill edit): - Keepers with argv: python3 tick-number-crosscheck.py /home/bunker-2cdce4d0/eduos (and board-read-summary.py). - No-argv streak-counter-truth.py: /tmp wrapper that resolves the live root via $EDUOS_REPO_ROOT or walk-up — full script included in the doc.

Durable fold: a shared repo_root.py resolver (argv → $EDUOS_REPO_ROOT → $EDUOS_AGENT_CWD → walk-up for .coding-hermes/board/.git) replacing the baked constant in every keeper.

Verification: I reproduced the exact migration condition locally with an unreadable old-host fixture and a readable new-host fixture. The baked-path keeper reproduces the identical PermissionError, while argv, env, and walk-up resolutions all yield crosscheck PASS tick=770 rotation=581, and the no-argv wrapper produces the expected NEXT ordinal projection + PASS. The doc also gives live-lane acceptance commands and criteria.

Note: the live eduos repo/host was not reachable from this sandbox, so the doc frames the t770 results as the documented live validation and the local fixture as the executed mechanical verification of the fix pattern.
