Answer

Both failures are test bugs with an environment-dependent signature, not code bugs. Rule: when a test is red locally but green on CI, reproduce it at a clean HEAD worktree (stash/checkout the change under review) before blaming the code.

Bug 1 — hardcoded main vs environment-dependent git default branch. The test helper ran git init with no branch pin. GitHub Actions sets init.defaultBranch=main (CI: green); bare hosts default to master (local: every main pathspec fails — a go-git "pathspec did not match" panic, or fatal: Needed a single revision from the CLI). Fix: pin the branch explicitly, and commit so the ref actually exists (an unborn branch has no ref to resolve):

// git_test.go — the FIXED helper
func initGitRepo(t *testing.T, dir string) {
    t.Helper()
    runGit(t, dir, nil, "init", "-q", "-b", "main") // pin branch: -b beats init.defaultBranch
    commitEmpty(t, dir) // materialize the ref so "main" resolves
}

func commitEmpty(t *testing.T, dir string) {
    t.Helper()
    env := []string{
        "GIT_AUTHOR_NAME=idet", "GIT_AUTHOR_EMAIL=idet@test",
        "GIT_COMMITTER_NAME=idet", "GIT_COMMITTER_EMAIL=idet@test",
    }
    runGit(t, dir, env, "commit", "--allow-empty", "-q", "-m", "init")
}

Bug 2 — negative allocGrowth wrapping in the int64 → uint64 cast. The measured window contains a GC reclaim, so int64(after.HeapAlloc)-int64(before.HeapAlloc) is negative; uint64(negative) wraps to 2^64-1 ≈ 16.0 EiB, tripping any budget check. Fix: clamp to 0 before the unsigned comparison:

// alloc.go — the FIXED production function
func AllocGrowthClamped(before, after uint64) uint64 {
    growth := int64(after) - int64(before)
    if growth < 0 {
        return 0 // GC reclaimed memory inside the window — no allocation growth
    }
    return uint64(growth)
}

The buggy assertion that got replaced: if uint64(growth) > 1<<30 { t.Fatalf(...) } → if AllocGrowthClamped(before, after) > 1<<30 { ... }.

Evidence & signatures

Built `/tmp/idet` (Go 1.26, git 2.53 — host defaults to `master`: confirmed via `git symbolic-ref --short HEAD` after bare `git init`). The original bugs are preserved behind a `//go:build buggy_demo` tag; the fixes are the default build. All with `-count=1`.

The alloc wrap is exact: real forced-reclaim delta was **-67,108,752 bytes** (64 MiB + overhead); `uint64(-67108752)` = 18446744073642442752. `uint64(-1)` = `math.MaxUint64` = 16 EiB, asserted in `TestUnsignedWrapIsTheBug`.

**Clean-HEAD verification (the "don't blame the change" step):** committed the buggy state, ran the tagged suite at that clean HEAD → both failures reproduce. Committed the fix → default suite green:

```

```

**Edge cases tested:** clamp of 0 / −1 / one-byte reclaim; growth within and over budget (0-budget boundary); worst realistic positive (`MaxInt64−1`); `-b main` beating a hostile `init.defaultBranch=master` config; unborn-branch trap (commit needed before `rev-parse --verify main`); `symbolic-ref` HEAD == `main`; `gofmt`, `go vet`, and `go test -race ./...` all clean. Note `-b` requires git ≥ 2.28 (2020); for older git, fall back to `git init` + `git branch -m master main`.
