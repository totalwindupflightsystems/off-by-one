Diagnosis

The environment is the Helix / coding-hermes platform (boardctl for the JSONL foreman board, helix for the 12-step audit chain with GitReins as Step 6). There is no source checkout present, so the deliverable is the verification runbook itself — grounded in the actual tooling on the box (I validated boardctl behavior against a scratch board).

Root cause: DOGFOOD-26 is a stale bookkeeping row, not an open defect. 1. The perf regression was fixed under a sibling task id SCHED-GAP-1730. 2. DOGFOOD-26 never got commit_hash, detail.evidence[], or a superseded_by marker. 3. boardctl's freshness check (internal/freshness.isAncestor) can't reconcile a row with no commit claim, so it stays pending and keeps looking dispatchable. 4. Dispatching would create duplicate work and a redundant GitReins evaluation.

Correct action: verification-only close — no code change.

Key commands (in the runbook)

  • Find the fix: rg the tree + git log --all --grep=DOGFOOD-26 --grep=SCHED-GAP-1730 -i
  • Prove landed: git merge-base --is-ancestor "$FIX_SHA" origin/main + git branch -r --contains
  • Read GitReins verdict: locate the evidence bundle bound to $FIX_SHA, then helix audit validate --evidence-file … / helix audit trace … --json (Step 6 = GitReins Verdict, JSON key gitreins_verdict)
  • Re-verify at HEAD: go build ./..., focused go test/go vet on the fix's packages, dashboard bench
  • Close with witness: bash boardctl -C "$REPO" update DOGFOOD-26 --status complete \ --commit-hash "$FIX_SHA" --evidence-run-id "$GITREINS_RUN_ID" \ --worker-status complete --guard PASS --ci GREEN \ --summary "Duplicate of SCHED-GAP-1730; verification-only." \ --note "Witness $FIX_SHA; no worker; no new GitReins task." boardctl -C "$REPO" event --type audit --task-id DOGFOOD-26 --actor foreman --detail-text "…" boardctl -C "$REPO" validate

The runbook also documents an important gotcha: do not use boardctl sweep-status --decide's duplicate path — it only works for an earlier same-id twin, and DOGFOOD-26 has none.
