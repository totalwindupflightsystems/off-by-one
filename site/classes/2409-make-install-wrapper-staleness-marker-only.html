Fix: make install leaves a stale vendored wrapper (marker-only guard)

Problem class: make-install-wrapper-staleness-marker-only Repo: totalwindupflightsystems/totalstack Files involved: Makefile (L64–68), scripts/awslocal (source), .venv/bin/awslocal (installed copy)

Symptom

Documented behavior works via the repo source but not via the venv-installed copy:

bash scripts/awslocal s3 mb s3://x      # warns + succeeds
.venv/bin/awslocal s3 mb s3://x          # InvalidLocationConstraint, zero warnings

Root cause

The install guard only checks for the presence of a marker string:

# Makefile L64-68 (before)
.venv/bin/awslocal: scripts/awslocal
    @mkdir -p $(@D)
    grep -q "ambient region" $@ || cp $< $@

grep -q answers "does the installed file mention this feature at all?", not "is it the same as the source?". Once any revision containing the marker is installed, the copy is skipped forever — reinstalling/git pull never fixes it. Diagnostic signature: marker count differs between source and installed copy (e.g. 0 vs 4).

Exact fix

Make the copy condition content-based — copy when the marker is missing or the files differ byte-for-byte:

# Makefile L64-68 (after)
.venv/bin/awslocal: scripts/awslocal
    @mkdir -p $(@D)
    @if ! grep -q "ambient region" $@ 2>/dev/null || ! cmp -s $< $@; then \
        echo "  INSTALL $@"; \
        cp $< $@; \
    fi

Recommended robust form (guarantees every make install re-checks, avoiding the file-target mtime escape hatch):

.PHONY: install install-awslocal

install: install-awslocal

install-awslocal:
    @mkdir -p .venv/bin
    @if ! grep -q "ambient region" .venv/bin/awslocal 2>/dev/null \
        || ! cmp -s scripts/awslocal .venv/bin/awslocal; then \
        echo "  INSTALL .venv/bin/awslocal"; \
        cp scripts/awslocal .venv/bin/awslocal; \
    fi

Immediate remediation if you can't edit the Makefile yet:

cp scripts/awslocal .venv/bin/awslocal && chmod +x .venv/bin/awslocal

Verification

# 1. Show staleness signature
echo "source: $(grep -c 'ambient region' scripts/awslocal)"
echo "installed: $(grep -c 'ambient region' .venv/bin/awslocal)"
cmp -s scripts/awslocal .venv/bin/awslocal && echo IDENTICAL || echo DIFFERENT

# 2. Apply and reinstall
make install

# 3. Confirm identical
cmp -s scripts/awslocal .venv/bin/awslocal && echo IDENTICAL || echo DIFFERENT

# 4. Confirm venv CLI now matches source (with ambient region in ~/.aws/config)
.venv/bin/awslocal s3 mb s3://x   # must warn + succeed

Local simulation of the guard confirmed:

before:  source=4  installed=1  DIFFERENT
make install -> INSTALL .venv/bin/awslocal
after:   IDENTICAL
marker present but content differs -> refreshed OK
second run -> no copy (idempotent)

Why correct: cmp -s detects any byte drift regardless of mtime or marker presence; the grep is retained only as a fallback for a missing file; the phony step closes the mtime loophole; and the check stays idempotent so identical files aren't recopied.
