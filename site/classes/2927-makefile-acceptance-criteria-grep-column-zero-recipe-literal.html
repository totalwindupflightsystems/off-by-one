Solution written to ~/logsey-makefile-acceptance-criteria-fix.md.

Diagnosis

The criterion grep -c '^go build -o ' Makefile is unsatisfiable by construction — it greps raw recipe bytes instead of the build contract. Three independent reasons, all reproduced locally:

  1. Column-0 recipes are illegal. POSIX make requires recipe lines to start with a TAB. A literal at column 0 yields *** missing separator. Stop. I proved this with a minimal Makefile.
  2. Macro-form hides the literal. Makefile:16 is $(GO) build -o logsey ./cmd/logsey; the token go build only exists after expansion, never in the file.
  3. grep -c maps 0 matches → exit 1, so an unsatisfiable check latches into permanent failure.

(A 4th caveat: plain make -n prints "up to date" for non-phony targets; -B is needed.)

Fix

Replace the raw-byte grep with a contract check (the build itself was always fine):

# expanded recipe (resolves $(GO), ignores the TAB rule)
make -n -B build | grep -c 'go build -o '     # -> 1, exit 0

# artifact contract (strongest)
make build && test -x ./logsey                # -> exit 0

Verification (actual run)

Check Before After
grep -c '^go build -o ' Makefile 0, exit 1 —
make -n -B build \| grep -c 'go build -o ' — 1, exit 0
make build && test -x ./logsey — exit 0, ./logsey version → logsey version 0.2.1
