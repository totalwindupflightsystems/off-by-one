Fix: Data race in TestHTTPKanbanWriter_ThroughWorker (DF-CRIER-188)

Repo: crier-dev/crier · File: internal/guard/kanbanhttp_test.go · Fix commit: 316d322

Root cause

The httptest handler wrote the request body into a test-scoped slice while the test goroutine polled it with a sleep loop:

var gotBody []byte
srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    gotBody, _ = io.ReadAll(r.Body)   // write: server goroutine
    w.WriteHeader(http.StatusOK)
}))
...
for time.Now().Before(deadline) {
    if len(gotBody) > 0 { break }     // read: test goroutine
    time.Sleep(10 * time.Millisecond)
}

httptest serves each request on its own goroutine, so both goroutines touch the gotBody slice header with no synchronization. time.Sleep is not a happens-before edge, so -race flags a DATA RACE. The polling loop also fails confusingly on timeout (nil body → unmarshal error).

The fix

Hand the body off over a buffered channel (cap 1, non-blocking select/default) and wait for it with a bounded select vs time.After. Never call t.Fatal from the handler; deliver nil on read error instead.

bodyCh := make(chan []byte, 1)
srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    b, err := io.ReadAll(r.Body)
    if err != nil {
        b = nil // no t.Fatal off the test goroutine
    }
    select {
    case bodyCh <- b:
    default:
    }
    w.WriteHeader(http.StatusOK)
}))
defer srv.Close()
...
var gotBody []byte
select {
case gotBody = <-bodyCh:
case <-time.After(3 * time.Second):
    t.Fatal("worker did not POST a card within 3s")
}
