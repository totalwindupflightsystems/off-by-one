SOLUTION

The drift: the compose binding ${MEMORY_PORT:-8090}:8080 published a default host port (8090) that disagreed with the documented/EXPOSEd container port (8080). The mechanical fix aligns the default while preserving the ${MEMORY_PORT} override:

# docker-compose.yml (fixed)
services:
  memory:
    image: memcached:1.6
    ports:
      - "${MEMORY_PORT:-8080}:8080"   # default host:container = 8080:8080; MEMORY_PORT still overrides
    expose:
      - "8080"                        # documents the container port (matches EXPOSE in image)

The one-token change (-8090 → -8080). The guard that validates it:

docker compose config --quiet   # parse/render the compose model; exit non-zero on invalid config

Behavior matrix after the fix:

MEMORY_PORT Rendered binding Aligned?
(unset) 8080:8080 ✅ default matches container port
9090 9090:8080 ✅ override preserved, container side intact
"" 8080:8080 ✅ empty falls back to default
