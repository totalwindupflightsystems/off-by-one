Answer

Diagnosed and solved. The full write-up is at ~/dirty-checkout-stale-duplicates-solution.md (593 lines, self-contained with both scripts inline). I also built and ran a reproduction to verify every claim.

Root cause

The prior tick treated dirtiness as unpublished work. But the dirty checkout was a stale materialization of an already-published closeout commit:

  • local main was behind origin/main (not diverged),
  • board.jsonl / events.jsonl working bytes were already in origin/main's tree,
  • the untracked wave manifest was byte-identical to its tracked blob in that commit,
  • the only other untracked files were zero-byte tooling locks.

Since local main was behind, the changes looked like "work that would be lost," so the safe-seeming action was pending-external-handoff. The missing step was subsumption checking against origin/main.

Fix (proof-gated, two phases)

  1. Prove — git log origin/main, then git show <sha>:<path> + cmp for every dirty path (including the untracked manifest vs its tracked blob), and confirm the locks are 0 bytes.
  2. Fold only on proof — git checkout -- board.jsonl events.jsonl; rm -f <manifest>; git merge --ff-only "$CLOSEOUT"; leave the 0-byte locks untracked; record a fold_disposition audit event.

I included two scripts: prove-subsumption.sh (verdicts IDENTICAL / DRAFT_TIMESTAMP / LOCK / UNIQUE, exit 3 on any unique content) and fold-subsumed-closeout.sh (runs the proof, refuses unless SUBSUMED, then folds and records the disposition).

Verification results

Scenario Dirty content Verdict Exit
A all identical SUBSUMED 0
B events.jsonl tail has earlier draft ts SUBSUMED (DRAFT_TIMESTAMP) 0
C manifest has a unique extra task UNIQUE_CONTENT — refused, tree untouched 3

After the fold: local main == origin/main, manifest restored as tracked, .foreman.lock/.boardctl.lock still present and untracked, disposition written to .git/closeout-fold-dispositions.jsonl. The h3 lane unblocks without a second handoff block.
