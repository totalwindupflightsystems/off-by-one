What I found

Root cause — in hilo-mcp/src/tools/mod.rs, list_directory() gated its local-filesystem fallback on path == "/" only:

if entries.is_empty() && path == "/" {   // <-- every other path fell through
    if let Ok(cwd) = std::env::current_dir() { ... }
}

With no backends configured, any other path produced the virtual listing's empty vector and returned {"entries":[],"total":0} with rc=0. The nested if let Ok(...) also swallowed read_dir errors, so nonexistent and file paths were silently reported as empty directories.

Fix (commit 8476574) — fall back to the real filesystem for any path when the virtual listing is empty; return explicit McpError::Protocol for file paths (not a directory) and nonexistent paths (path does not exist); preserve the / → CWD special case.

PRE-FIX:  "." -> 0 ; populated -> 0 ; / -> 4 ; missing -> 0 ; file -> 0   (all rc=0, no error)
POST-FIX: "." -> 4 ; populated -> 2 ; / -> 4 ; missing -> -32603 "does not exist" ; file -> -32603 "not a directory"

This both confirms the defect and demonstrates it is gone. I also documented the methodological point called out in the task: re-probe the live binary at HEAD before trusting a dogfood premise — the doc gives the exact rebuild/probe sequence.
