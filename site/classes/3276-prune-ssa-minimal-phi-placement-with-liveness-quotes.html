Diagnosis (root cause)

Pruned SSA is a mutual recursion: phi placement depends on liveness, but liveness depends on the phi set (a phi is a def at its owner and a use on every predecessor edge).

The common implementation resolves it in the wrong direction — start from the full Cytron DF+ phi set and delete phis not live-out. That's a greatest-fixpoint computation, so a cycle of phis whose only "uses" are each other becomes self-justifying and can never be deleted. Concretely: v defined at blocks 0 and 1, join at 3 with a back edge 3→1, v never really used. DF+ gives phis at b1 and b3; each keeps the other live-out, so the naive pruner keeps 2. The true minimum is 0.

Second failure: after deleting a dead phi you must re-derive liveness from real uses, or you leave dead arguments alive or violate SSA dominance.

The fix

Compute the least fixpoint by iterating from ∅: recompute liveness with the current phi set and add phi(v,X) whenever X ∈ DF+(defs(v)) and v ∈ LiveIn(X). The operator is monotone, so iteration from ∅ converges to the unique minimum; nothing enters unless transitively justified by a real use, making dead-phi cycles impossible. Dominator-tree renaming emits the per-edge argument, using undef when no definition reaches — i.e. the argument is dead at that predecessor. Cooper–Harvey–Kennedy dominators + Cytron DF handle irreducible CFGs.
