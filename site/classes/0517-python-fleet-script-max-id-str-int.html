Answer

Root cause: Migration-era DuckDB boards serialize events.jsonl ids and board.jsonl header counters as JSON strings. Two numeric sites then blew up:

  • max(ids) + 1 → TypeError: can only concatenate str (not "int") to str
  • hdr.get("ticks_total", 0) + 1 → same TypeError

Fix: coerce int() at both sites. int() is lossless for native ints and migration strings, so modern boards behave identically. The script is at sync_board_jsonl_mirror.py (reconstructed from the described failure, since it wasn't present on disk):

def read_event_ids(events_path):
    """All event ids from events.jsonl, coerced to int (string-safe)."""
    ids = []
    for line in Path(events_path).read_text().splitlines():
        if not line.strip():
            continue
        ids.append(int(json.loads(line)["id"]))          # FIX SITE 1
    return ids


def next_event_id(ids):
    """max(ids) + 1 for the next event; empty mirror starts at 1."""
    return max(ids) + 1 if ids else 1


def bump_ticks_total(header):
    """Increment the ticks_total header counter (string-safe)."""
    return int(header.get("ticks_total", 0)) + 1         # FIX SITE 2

The two changed lines are exactly ids = [int(json.loads(l)["id"]) for l in lines] and int(hdr.get("ticks_total", 0)) + 1. sync_mirror() wires them together: it reads both files, computes the new event id and bumped counter, appends the event to events.jsonl, and rewrites the header. Usage: python3 sync_board_jsonl_mirror.py events.jsonl board.jsonl.
