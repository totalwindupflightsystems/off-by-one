Diagnosis (root causes)

A batch equation [8](ΣzᵢSᵢ)B = [8](ΣzᵢRᵢ + ΣzᵢkᵢAᵢ) alone cannot see constraints that live outside the equation:

  1. Non-canonical S: [S+L]B = [S]B, so malleated signatures pass unless S < L is screened per index.
  2. Non-canonical encodings: y and y+p decode identically unless y < p and the x==0 sign encoding is forbidden.
  3. Small/mixed-order keys: the cofactor 8 annihilates torsion, so A and A+T are indistinguishable; the verifier must assert [8]A≠identity and [L]A=identity.
  4. Duplicate R: deterministic/equal weights let two same-R terms cancel → use independent OS-random 128-bit weights.
  5. Reporting: a boolean is useless → run an isolation pass only on combined-check failure.

The fix (core batch logic)

# pre-screen each index: canonical S<L, canonical decodings,
# non-small-order R, prime-order non-identity A  -> bad indices
...
# combined cofactored equation with independent OS-random non-zero 128-bit weights
sum_zs = Σ (z_i * S_i) mod L
right  = MSM( [R_i with scalar z_i] + [A_i with scalar (z_i*k_i mod L)] )

# isolation: exact verify() per remaining index

Weights are secrets.randbelow(2**128 - 1) + 1, so the probability a bad equation cancels is ≤ 2⁻¹²⁸; everything structural is rejected deterministically.

  • RFC 8032 KATs: PASS
