Answer

Root cause: a spec-dir reorg dropped the speclang-slash- prefix, so 137 src/ symlinks of the form ../speclang-slash-<rest>.spec.dir/src/<file> went dead. The dual-view design (src/ symlinks exposing canonical spec-dir sources under a second import view) needed repair — but only by name-mapping classification, never blind relinking.

1. Find the dead links (the find quirk). find src/ -type l ! -exec test -e {} \; prints nothing: once -exec appears in the expression, find's implicit -print is suppressed. Either add explicit -print, or use -xtype l:

# quirk: prints NOTHING (no implicit print after -exec)
find src/ -type l ! -exec test -e {} \;
# fix A: explicit -print (authoritative: follows the full chain)
find src/ -type l ! -exec test -e {} \; -print
# fix B: -xtype l (verified against GNU findutils 4.10: matches the same dead set)
find src/ -xtype l -print

2. Classify by name-mapping before acting — speclang-slash- → specs/ on the target string (preserves ../ relative structure). Live mapped targets that are non-TS or spec files are removed, not relinked: they sit outside the compile surface and duplicate views already linked elsewhere.

3. Repair script (core loop, -print0 for name safety; targets are relative to the link's directory, not cwd):

while IFS= read -r -d '' link; do
  target="$(readlink -- "$link")"
  [[ "$target" == *"speclang-slash-"* ]] || { rm -f -- "$link"; continue; }   # unmappable
  new_target="${target/speclang-slash-/specs/}"                                # drop prefix
  link_dir="$(dirname -- "$link")"
  [[ -e "$link_dir/$new_target" ]] || { rm -f -- "$link"; continue; }          # no mapped target
  leaf="$(basename -- "$new_target")"
  if [[ "$leaf" == *.ts && "$leaf" != *.spec.ts && "$leaf" != *.test.ts ]]; then
    ln -sfn -- "$new_target" "$link"    # RELINK: TS, in compile surface
  else
    rm -f -- "$link"                    # REMOVE: non-TS / spec file / fixture
  fi
done < <(find src/ -type l ! -exec test -e {} \; -print0)

4. Compiler backstop — relinks that tsc rejects (spec-tree files importing test-runtime types like vitest) are outside the compile surface too; remove and re-run until tsc --noEmit is clean, then run the full suite. Link counts alone prove nothing; only tsc --noEmit + the suite do.
