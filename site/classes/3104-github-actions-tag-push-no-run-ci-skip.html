Tag-push CI evidence when the target commit contains a GitHub Actions skip marker

Summary

A tag push is a push event. GitHub suppresses push and pull_request workflow runs when the pushed commit's message contains one of the skip markers:

[skip ci], [ci skip], [no ci], [skip actions], [actions skip]

There is no tag-push override. If a tag points at a skip-marked commit and the workflow has no alternative trigger, GET /repos/{owner}/{repo}/actions/runs?head_sha=<sha> will stay at total_count: 0 forever. The tag still lands; GitHub is not down. The correct response is to stop polling, prove the impossibility, and use one of the workarounds below.

In the reported case, c4043b0c (skip-free) produced run 40202677040, while fdcec4c (subject ends with [ci skip]) produced zero runs. That is the expected signature of this problem, not a CI outage.

Root cause analysis

  1. GitHub evaluates skip markers before workflow trigger matching for push and pull_request events.
  2. A tag push is a push event. on.push.tags: ['v*'] does not bypass the marker filter.
  3. The marker is read from the commit message of the pushed commit (subject or body), not from the annotated tag message. A skip-free tag annotation does not override a skip-marked commit.
  4. No run means no re-run. GitHub's "Re-run jobs" requires an existing run.
  5. Other events only help if the workflow declares them:
  6. workflow_dispatch can run on a tag ref.
  7. repository_dispatch can target a ref.
  8. schedule runs on the default branch, not an arbitrary tag SHA.
  9. pull_request events also die on the HEAD commit marker.
  10. Therefore, if the target commit has a marker and none of those alternative triggers exist, zero runs is the correct, expected result. The impossibility proof is the coverage finding.

Step 0 — Diagnose before designing any tag-push CI strategy

0.1 Check the target commit message

REPO=owner/repo
TAG=v1.0.0
SHA=$(git rev-parse "$TAG^{commit}")

git log -1 --format='%H%n%s%n%b' "$SHA"

SKIP_RE='\[(skip[[:space:]-]?ci|ci[[:space:]-]?skip|no[[:space:]-]?ci|skip[[:space:]-]?actions|actions[[:space:]-]?skip)\]'
if git log -1 --format=%B "$SHA" | grep -Eiq "$SKIP_RE"; then
  echo "SKIP_MARKER_PRESENT"
else
  echo "NO_SKIP_MARKER"
fi

The regex is case-insensitive and also catches hyphenated variants. The official markers use spaces.

0.2 Inventory triggers at the target SHA

git ls-tree -r --name-only "$SHA" .github/workflows \
  | grep -E '\.ya?ml$' \
  | while read -r f; do
      echo "--- $f"
      git show "$SHA:$f" \
        | awk '/^on:/{inon=1;print;next} inon && /^[^[:space:]#]/{inon=0} inon{print}' \
        | head -60
    done

Look for workflow_dispatch, repository_dispatch, schedule, release, or create. If only push/pull_request exist, no other GitHub event can cover this SHA.

0.3 Query runs and checks

gh api "repos/$REPO/actions/runs?head_sha=$SHA&per_page=100" \
  --jq '{total_count, runs: [.workflow_runs[] | {id,name,event,head_branch,status,conclusion,html_url}]}'

gh api "repos/$REPO/commits/$SHA/check-runs" \
  --jq '{total_count, check_runs: [.check_runs[] | {name,status,conclusion}]}'

0.4 Decision table

Target commit Alternative trigger at SHA Existing run Action
Skip marker present None No Use Fix A, B, or C below. Do not keep polling.
Skip marker present workflow_dispatch or repository_dispatch No Dispatch the workflow at the tag ref.
Skip marker present schedule only No Schedule runs the default branch, not the tag. Use Fix A/B/C.
No skip marker Any No Normal tag push should run. Investigate tag filter, workflow path, permissions, or Actions being disabled.
No skip marker Any Yes Re-run the existing run.

0.5 One-shot doctor

Save the ci-tag-doctor.sh script from the appendix and run:

REPO=owner/repo ./ci-tag-doctor.sh v1.0.0

It prints the commit subject, marker status, workflow on: blocks, Actions runs, check runs, and a diagnosis.

Exact fix

Fix A — Preferred for new tags: tag a tree-identical, skip-free commit

Create a new commit with the same tree as the target but a skip-free message, then tag that commit. The workflow runs on the new commit; cite tree equivalence to the original.

Save ci-tag-fix.sh from the appendix, then:

# From a checkout that contains the target commit:
./ci-tag-fix.sh v1.0.0 v1.0.0-tree

# Or create and push in one shot:
PUSH=1 ./ci-tag-fix.sh v1.0.0 v1.0.0-tree origin

The script:

  • resolves the target commit and its tree;
  • refuses if the target has no marker (it tells you to tag directly);
  • preserves all parents, including merge commits;
  • creates a new commit with the same tree and a skip-free message;
  • verifies tree equality and marker absence before tagging;
  • creates an annotated tag;
  • optionally pushes it.

Choose a new tag name that matches the workflow's tag filter. For example, v1.0.0-tree matches v*. If the original tag already exists, do not force-move a release tag unless you explicitly accept rewriting it; use a new tag or Fix C. If signed commits/tags are required, add -S to git commit-tree and use git tag -s.

Fix B — Exact-SHA local evidence: run the workflow with act

This runs the exact workflow at the exact SHA locally. It is real evidence, but it is not a GitHub Actions run.

git fetch origin
git checkout --detach "$SHA"

TAG=v1.0.0
jq -n \
  --arg ref "refs/tags/$TAG" \
  --arg sha "$SHA" \
  --arg repo "$REPO" \
  --arg msg "$(git log -1 --format=%B "$SHA")" \
  '{ref:$ref,before:"0000000000000000000000000000000000000000",after:$sha,head_commit:{id:$sha,message:$msg},repository:{full_name:$repo}}' \
  > /tmp/tag-event.json

act -l -e /tmp/tag-event.json

act push \
  -W .github/workflows/release.yml \
  -e /tmp/tag-event.json \
  -P ubuntu-latest="${ACT_IMAGE:-catthehacker/ubuntu:act-latest}" \
  --container-architecture linux/amd64

If the repository ships an act-parity container image, set ACT_IMAGE to it. Add secrets with -s NAME=value or --secret-file. Use act -l to confirm the tag-push event is recognized before running.

Fix C — Existing tag already points at a skip-marked commit: publish the impossibility proof

You cannot retroactively create a GitHub Actions run for that SHA through the tag push. Generate a report that proves why, and attach it to the release/issue.

Save ci-tag-proof.sh from the appendix, then:

REPO=owner/repo ./ci-tag-proof.sh v1.0.0

Or generate the report inline:

Fix D — If the workflow already declares workflow_dispatch

workflow_dispatch is not a push event, so the skip marker does not suppress it. If the workflow declares it, dispatch at the tag ref:

gh workflow run release.yml --ref "$TAG"
gh run list --workflow release.yml --limit 5

If the workflow does not declare workflow_dispatch, add it on the default branch as a future escape hatch. Do not rely on schedule to cover a specific tag SHA.

Prevention

  • Never cut release tags from [ci skip] bookkeeping/log commits. This is the primary fix.
  • Add a pre-tag/pre-push guard. A workflow on tag push cannot enforce this because the tag push itself is skipped. Use a client-side guard, a GitHub ruleset with required checks (if available), or a GitHub App/webhook.
#!/usr/bin/env bash
set -euo pipefail
SKIP_RE='\[(skip[[:space:]-]?ci|ci[[:space:]-]?skip|no[[:space:]-]?ci|skip[[:space:]-]?actions|actions[[:space:]-]?skip)\]'
for ref in "$@"; do
  sha=$(git rev-parse "$ref^{commit}")
  if git log -1 --format=%B "$sha" | grep -Eiq "$SKIP_RE"; then
    echo "REFUSING to tag/push $ref: commit $sha has a CI skip marker" >&2
    exit 1
  fi
done
  • Use skip markers only on commits that will never be tagged or released, and keep release branches free of them.
  • Add workflow_dispatch to release workflows as a manual escape hatch:
on:
  push:
    tags: ['v*']
  workflow_dispatch:
  • Do not rely on schedule to cover a specific tag SHA; schedule runs on the default branch.

Controlled comparison (proves the marker is the cause)

Push one probe tag at a skip-free commit and one at the skip-marked commit, then compare:

CLEAN_SHA=<skip-free-sha>
SKIP_SHA=<skip-marked-sha>

git tag -a v0.0.0-probe-clean "$CLEAN_SHA" -m "probe"
git tag -a v0.0.0-probe-skip  "$SKIP_SHA"  -m "probe"
git push origin v0.0.0-probe-clean v0.0.0-probe-skip

for sha in "$CLEAN_SHA" "$SKIP_SHA"; do
  echo "$sha: $(gh api "repos/$REPO/actions/runs?head_sha=$sha&per_page=1" --jq .total_count)"
done

Expected: the skip-free SHA has at least one run; the skip-marked SHA has zero. This is the controlled comparison that isolates the commit-message marker as the cause.

Appendix — scripts

ci-tag-doctor.sh

#!/usr/bin/env bash
set -euo pipefail

SKIP_RE='\[(skip[[:space:]-]?ci|ci[[:space:]-]?skip|no[[:space:]-]?ci|skip[[:space:]-]?actions|actions[[:space:]-]?skip)\]'
REF=${1:-HEAD}
REPO=${REPO:-}
if [ -z "$REPO" ] && command -v gh >/dev/null 2>&1; then
  REPO=$(gh repo view --json nameWithOwner -q .nameWithOwner 2>/dev/null || true)
fi
TARGET=$(git rev-parse --verify "$REF^{commit}")
SUBJECT=$(git log -1 --format=%s "$TARGET")
BODY=$(git log -1 --format=%B "$TARGET")
if printf '%s\n' "$BODY" | grep -Eiq "$SKIP_RE"; then SKIP=yes; else SKIP=no; fi

printf 'repo: %s\n' "${REPO:-<unknown>}"
printf 'ref: %s\n' "$REF"
printf 'sha: %s\n' "$TARGET"
printf 'subject: %s\n' "$SUBJECT"
printf 'skip_marker: %s\n' "$SKIP"
printf '\nworkflow files at %s:\n' "$TARGET"
mapfile -t WF < <(git ls-tree -r --name-only "$TARGET" .github/workflows 2>/dev/null | grep -E '\.ya?ml$' || true)
if [ ${#WF[@]} -eq 0 ]; then
  echo '  (none)'
else
  for f in "${WF[@]}"; do
    echo "--- $f"
    git show "$TARGET:$f" | awk '
      /^on:/ {inon=1; print; next}
      inon && /^[^[:space:]#]/ {inon=0}
      inon {print}
    ' | head -60
  done
fi

printf '\nGitHub Actions runs for head_sha=%s:\n' "$TARGET"
if [ -n "$REPO" ] && command -v gh >/dev/null 2>&1; then
  gh api "repos/$REPO/actions/runs?head_sha=$TARGET&per_page=100" \
    --jq '{total_count, runs: [.workflow_runs[] | {id, name, event, head_branch, status, conclusion, html_url}]}' \
    2>/dev/null || echo '  (gh query failed; check auth/network)'
  printf '\nCheck runs for %s:\n' "$TARGET"
  gh api "repos/$REPO/commits/$TARGET/check-runs" \
    --jq '{total_count, check_runs: [.check_runs[] | {name, status, conclusion}]}' \
    2>/dev/null || echo '  (gh query failed; check auth/network)'
else
  echo '  (skipped: no repo or gh)'
fi

if [ "$SKIP" = yes ]; then
  cat <<'EOF'

DIAGNOSIS: The target commit message contains a GitHub Actions skip marker.
GitHub evaluates this marker for push events, including tag pushes. No run will
be created for this SHA by an on.push.tags workflow, and there is no tag-push
override. Re-run is impossible without an existing run. Use one of:
  A) tag a tree-identical, skip-free commit (ci-tag-fix.sh)
  B) run the workflow locally with act at this exact SHA
  C) if the release tag already points here, publish the impossibility proof
EOF
fi

ci-tag-fix.sh

#!/usr/bin/env bash
set -euo pipefail

SKIP_RE='\[(skip[[:space:]-]?ci|ci[[:space:]-]?skip|no[[:space:]-]?ci|skip[[:space:]-]?actions|actions[[:space:]-]?skip)\]'

if [ $# -lt 2 ]; then
  echo "usage: $0 <target-sha-or-tag> <new-tag> [remote]" >&2
  echo "  PUSH=1 $0 <target-sha-or-tag> <new-tag> [remote]   # also push the new tag" >&2
  exit 2
fi

TARGET_REF=$1
NEW_TAG=$2
REMOTE=${3:-origin}
PUSH=${PUSH:-0}

TARGET=$(git rev-parse --verify "$TARGET_REF^{commit}")
TREE=$(git rev-parse "$TARGET^{tree}")
BODY=$(git log -1 --format=%B "$TARGET")

if ! printf '%s\n' "$BODY" | grep -Eiq "$SKIP_RE"; then
  echo "target has no skip marker; tag it directly:"
  echo "  git tag -a '$NEW_TAG' '$TARGET' -m 'Release $NEW_TAG'"
  echo "  git push '$REMOTE' 'refs/tags/$NEW_TAG'"
  exit 0
fi

if git rev-parse -q --verify "refs/tags/$NEW_TAG" >/dev/null; then
  echo "ERROR: tag '$NEW_TAG' already exists; choose a new tag name" >&2
  exit 1
fi

mapfile -t PARENTS < <(git rev-list --parents -n 1 "$TARGET" | awk '{for(i=2;i<=NF;i++) print $i}')
PARENT_ARGS=()
for p in "${PARENTS[@]}"; do
  [ -n "$p" ] && PARENT_ARGS+=(-p "$p")
done

MSG="ci: trigger workflow for $TARGET (tree-identical; no skip marker)"
NEW_SHA=$(GIT_AUTHOR_NAME="${GIT_AUTHOR_NAME:-CI Bot}" \
          GIT_AUTHOR_EMAIL="${GIT_AUTHOR_EMAIL:-<email>}" \
          GIT_COMMITTER_NAME="${GIT_COMMITTER_NAME:-CI Bot}" \
          GIT_COMMITTER_EMAIL="${GIT_COMMITTER_EMAIL:-<email>}" \
          git commit-tree "$TREE" ${PARENT_ARGS[@]+"${PARENT_ARGS[@]}"} -m "$MSG")

NEW_BODY=$(git log -1 --format=%B "$NEW_SHA")
if printf '%s\n' "$NEW_BODY" | grep -Eiq "$SKIP_RE"; then
  echo "ERROR: generated commit still has a skip marker" >&2
  exit 1
fi
NEW_TREE=$(git rev-parse "$NEW_SHA^{tree}")
if [ "$NEW_TREE" != "$TREE" ]; then
  echo "ERROR: tree mismatch: $NEW_TREE != $TREE" >&2
  exit 1
fi

git tag -a "$NEW_TAG" "$NEW_SHA" -m "Release $NEW_TAG (tree-identical to $TARGET)"
printf 'target_sha=%s\nnew_sha=%s\ntree=%s\nnew_tag=%s\n' "$TARGET" "$NEW_SHA" "$TREE" "$NEW_TAG"

if [ "$PUSH" = 1 ]; then
  git push "$REMOTE" "refs/tags/$NEW_TAG"
fi

ci-tag-proof.sh

#!/usr/bin/env bash
set -euo pipefail

SKIP_RE='\[(skip[[:space:]-]?ci|ci[[:space:]-]?skip|no[[:space:]-]?ci|skip[[:space:]-]?actions|actions[[:space:]-]?skip)\]'
REPO=${REPO:-}
REF=${1:?usage: REPO=owner/repo $0 <tag-or-sha> [tag-name]}
TAG=${2:-$REF}
TARGET=$(git rev-parse --verify "$REF^{commit}")
OUT=${OUT:-ci-coverage-finding-${TAG//\//_}.md}

{
  echo "# CI coverage finding: ${REPO:-<repo>} $TAG"
  echo
  echo "- Tag: \`$TAG\`"
  echo "- Commit: \`$TARGET\`"
  echo "- Subject: $(git log -1 --format=%s "$TARGET")"
  if git log -1 --format=%B "$TARGET" | grep -Eiq "$SKIP_RE"; then
    echo "- Skip marker: **present**"
  else
    echo "- Skip marker: absent"
  fi
  echo
  echo '## Commit message'
  echo '```'
  git log -1 --format='%H%n%an <%ae>%n%ad%n%n%B' "$TARGET"
  echo '```'
  echo
  echo '## Workflow triggers at this SHA'
  echo '```'
  mapfile -t WF < <(git ls-tree -r --name-only "$TARGET" .github/workflows 2>/dev/null | grep -E '\.ya?ml$' || true)
  if [ ${#WF[@]} -eq 0 ]; then
    echo '(no workflow files)'
  else
    for f in "${WF[@]}"; do
      echo "--- $f"
      git show "$TARGET:$f" | awk '/^on:/{inon=1;print;next} inon && /^[^[:space:]#]/{inon=0} inon{print}' | head -60
    done
  fi
  echo '```'
  echo
  echo '## GitHub Actions runs for this SHA'
  echo '```json'
  if [ -n "$REPO" ] && command -v gh >/dev/null 2>&1; then
    gh api "repos/$REPO/actions/runs?head_sha=$TARGET&per_page=100" --jq '{total_count, runs: [.workflow_runs[] | {id,name,event,head_branch,status,conclusion,html_url}]}' 2>/dev/null || echo '{"error":"gh query failed"}'
  else
    echo '{"error":"REPO not set or gh unavailable"}'
  fi
  echo '```'
  echo
  echo '## Check runs for this SHA'
  echo '```json'
  if [ -n "$REPO" ] && command -v gh >/dev/null 2>&1; then
    gh api "repos/$REPO/commits/$TARGET/check-runs" --jq '{total_count, check_runs: [.check_runs[] | {name,status,conclusion}]}' 2>/dev/null || echo '{"error":"gh query failed"}'
  else
    echo '{"error":"REPO not set or gh unavailable"}'
  fi
  echo '```'
  echo
  echo '## Conclusion'
  echo
  echo 'The tag landed, but GitHub Actions cannot create a run for this SHA because the commit message contains a GitHub Actions skip marker and no alternative trigger exists. This is an impossibility proof, not a CI failure.'
} > "$OUT"

echo "wrote $OUT"
