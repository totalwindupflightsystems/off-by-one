Diagnosis

The task is minimum-cost fault-tolerant temporal connectivity. The trap is that naive approaches (rebuild max-flow per timestamp × upgrade all bridges, or one global min-cut) are wrong:

  • Feasibility of a given upgrade set U is a polynomial per-boundary max-flow check: capacity K+1 on upgraded edges, 1 on naturally-alive edges. U is feasible iff every boundary's max-flow > K.
  • But choosing U is NP-hard (contains min-cost 2-edge-connected augmentation). The exact structure is a minimum-weight hitting set over all "small" temporal s-t cuts: for every partition S and boundary τ with at most K naturally-alive forward edges, any feasible U must upgrade at least one forward edge of S (including edges dead at τ — upgrading resurrects them).

The fix (SOLUTION.md)

  1. Cutting-plane loop: master = exact min-cost hitting set; separation = one max-flow per boundary with K+1/1/0 capacities, returning a violated partition and its full forward frontier. Terminates with the globally optimal upgrade set.
  2. Exact hitting-set branch-and-bound with a disjoint-cut lower bound (the exponential work stays in the small master, not in per-timestamp flows).
  3. Independent verifier that re-proves (K+1)-robustness by max-flow, validates every emitted cut, and re-solves the hitting set to certify optimality via OPT ≤ cost(U) = H(F) ≤ OPT.
  4. Explicit handling of half-open lifetimes (a ≤ τ < b), simultaneous expirations, shared upgrades, dead-edge repairs, and infeasibility (ErrInfeasible).

Verification

  • go test -count=1 ./... — all targeted edge-case tests pass.
  • 10,000 randomized instances (2–4 vertices, up to 7 edges, K∈{0,1,2}, multi-interval lifetimes) matched an exact 2^m brute force and passed the independent verifier, including infeasible cases.
  • End-to-end CLI: go run . solve examples/two_cuts.json cert.json → go run . verify ... prints VALID: optimal certificate verified.
