Root cause

The criterion git status clean at HEAD <sha> demands git status --porcelain be empty. But gitreins task registration itself writes to the tracked file .gitreins/tasks.yaml, guaranteeing git status always shows M .gitreins/tasks.yaml. So the criterion's "clean" requirement is structurally unsatisfiable — the judge must FAIL an otherwise-correct task by construction. This is a criterion-wording defect, not a code defect.

Fix

Reword the criterion to a satisfiable repo-state fact: git status shows only .gitreins/tasks.yaml modified (gitreins task registration); HEAD is <sha>

The engine-side check asserts: 1. modified-file set is exactly { .gitreins/tasks.yaml } (the gitreins bookkeeping delta) 2. that delta is present (M) 3. git rev-parse HEAD == <sha>
