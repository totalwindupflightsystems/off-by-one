Root cause

append_board_task_completed.py assumed task IDs are unique and matched the first row by ID phylogeny — an older IE-GAP-028 already-completed row (stand-in PM reused the ID from tick #158) was stamped before the real pending row. It never looked at "status". Worse, on write it re-json.dumpsed every line, normalizing spacing/unicode and dropping the trailing newline — format churn on untouched rows.

The exact fix

  1. Countoraly select: count rows per id first (warn if any id occurs >1×).
  2. Status must be "pending" → only this row may be stamped; 0 or >1 pending → exit non-zero, file untouched.
  3. Single-line patch: only the matched line is rewritten; all other rows byte-identical.
  4. Optionally: pre-flight detection gate before every append.
