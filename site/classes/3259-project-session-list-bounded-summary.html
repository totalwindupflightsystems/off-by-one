Done. I diagnosed the problem against the real repo, implemented and verified the fix, and wrote the self-contained solution document.

Root cause

GET /sessions (HandleListSessions, internal/session/http.go) was O(sessions × transcript depth): it listed session ids and then called Load() per id, rebuilding the entire State (transcript, threads, members, context shares, and one chat_deliveries query per message) only to emit a message count, thread count, participant count and a 120-char preview. On the shipped 20×20 fixture that was 561 SQL statements/request (400 delivery lookups) and 10.7–16.8 ms p50. The prior PERF-002 prototype was scratch-only, so origin/main had no SessionListReader/SessionSummaries.

Fix (applied in /workspace/&lt;project&gt;, patch applies cleanly to pristine origin/main)

  • New internal/session/summary.go: optional SessionListReader interface + (*SQLStore).SessionSummaries(ctx, now) — two statements (one aggregate over chat_sessions/chat_transcript/chat_threads, one membership read with ActiveAt evaluated in Go).
  • internal/session/http.go: a handler branch that takes the bounded path only when the concrete store implements the interface, plus listSessionsBounded and viewOfSummary that mirror the existing filters, realm wall, sort and viewOf field-for-field.
  • internal/session/summary_test.go: equivalence, filter, realm, JSONL-fallback and digest tests.
  • docs/performance.md: before/after, command, fixture, fallbacks.

Verification

  • Byte-identical: TestSessionListSummaryShippedFixtureDigest reproduces the finding's recorded digest exactly — sha256 19c7ad65…f3d6e (5936 bytes, 20×20). A control wrapper that hides the interface proves every filter and the realm wall produce byte-identical bodies.
  • Same-window latency (both arms, 20×20, loadavg 3.2): shipped 10.65 ms p50 → bounded 0.69 ms p50 (~15×), p99 1.1 ms; CR_SESSION_ASSERT_P99=1 BenchmarkSessionList → verdict=PASS.
  • go build ./..., go vet ./..., go test ./internal/session/... -count=1 all pass.
  • Confirmed the patch applies cleanly to a pristine origin/main worktree and the tests pass there.
