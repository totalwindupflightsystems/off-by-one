Fix: discovery_misses stops moving after seam merge (go-parallel-wave-integration-arm-missing)

Class: go-parallel-wave-integration-arm-missing Environment: docker/go/go1.26 Symptom: Integrated test asserts discovery_misses == 1, observes 0.

1. Root cause

Two parallel waves edited the same handler on disjoint-looking lines:

Wave Change
A Extracted class resolution into a new resolveClass method and routed unknown classes through a new if errors.Is(err, ErrNotFound) arm.
B Added a RecordDiscovery(false) counter call wired only to the old 404 arm (empty-class validation).

Both unit suites were green in isolation because each exercised its own arm: A's suite went through resolveClass and only checked the returned ErrNotFound; B's suite hit the legacy empty-class arm and saw the counter move.

After the serial merge, Discover reaches worker A's resolveClass arm first. That arm returns ErrNotFound without touching the counter, so B's wiring is dead code on the real request path:

Discover(class)
  ├─ class == ""            → old 404 arm → RecordDiscovery(false) ✅
  └─ resolveClass(class)
        └─ ErrNotFound      → NEW arm     → (no observer call)  ❌  <- counter never moves

The bug is that the merge produced a third program neither wave tested: the union of A's routing and B's observable contract.

Consumer-visible semantics outrank the internal call graph. A 404 not_found produced by discover is a discovery miss, regardless of which internal method constructed the error.

2. Exact fix

Add the observer call to the new resolveClass ErrNotFound arm:

// discovery/handler.go
ep, err := h.resolveClass(class)
if errors.Is(err, ErrNotFound) {
    if h.Observer != nil {
        h.Observer.RecordDiscovery(false) // <- the missing wiring
    }
    return "", err
}
if err != nil {
    return "", err
}

One-line diff:

    ep, err := h.resolveClass(class)
    if errors.Is(err, ErrNotFound) {
+       if h.Observer != nil {
+           h.Observer.RecordDiscovery(false)
+       }
        return "", err
    }

Durable alternative: record the outcome once at the Discover boundary from the final error (a shared finish(err) helper), so future arms cannot silently drop the call.

4. Wave doctrine addition

Same-HANDLER rows are a seam collision even when file lists look disjoint. Two waves touching different lines of the same function/method share a merge seam; file-level "no overlap" checks are insufficient.

Merge order must re-run the sibling row tests on the merged tree. Never rely on each suite having passed in isolation.

Merge checklist

  1. Detect shared handlers (git merge-base + per-function ownership), not just shared files.
  2. After serial merge, run the union of both waves' tests on the merged tree.
  3. For any moved/renamed path (e.g., 404 handling extracted into resolveClass), assert behavior at the consumer boundary (Discover), not only the new internal method.
  4. Prefer a single centralized outcome hook so parallel arms cannot drop cross-cutting calls (counters, metrics, tracing).
