Root cause

Three conflations in the board-loading path:

  1. Absent vs. partial — resolution only checked "are both files present?", so a directory with exactly one of the pair (tasks.jsonl OR events.jsonl) was reported as absent, discarding the detected path and the missing half.
  2. Lost line context — parser errors surfaced as bare unexpected end of JSON input with no file:line.
  3. Pretty-JSON misdiagnosis / false positives — a multi-line valid JSON document fails JSONL parsing on line 1 with an EOF-class error. It must be diagnosed as "valid JSON, not line-loadable JSONL", but only when the whole file is genuinely valid — otherwise truncated/corrupt JSON gets wrongly labeled.

The fix (core logic)

Shared exit class, distinct diagnostics — BoardNotFoundError carries Partial, Dir, Present, Missing; both cases return exit code 2.

type BoardNotFoundError struct {
    Dir     string
    Present string
    Missing string
    Partial bool
}

First partial candidate tracked while ascending, but a complete board always wins:

switch len(present) {
case len(requiredFiles):
    return dir, nil          // complete board wins
case 1:
    if partial == nil {      // first (deepest) partial candidate
        partial = &BoardNotFoundError{Dir: dir, Present: present[0],
            Missing: missingPair(present[0]), Partial: true}
    }
}

Exact 1-based line context via LineError{File, Line, Err}.

Guarded pretty-JSON detection — the only discriminator is whole-file validity:

if err := json.Unmarshal([]byte(trimmed), &raw); err != nil {
    le := &LineError{File: path, Line: i + 1, Err: err}
    if isEOFClass(err) && wholeFileIsValidJSON(data) {
        le.WholeFileJSON = true    // -> "valid JSON document, but not line-loadable JSONL ... jq -c"
    }
    return nil, le                 // corrupt/truncated keeps plain file:line error
}

func wholeFileIsValidJSON(data []byte) bool {
    trimmed := strings.TrimSpace(string(data))
    if trimmed == "" { return false }
    return json.Valid([]byte(trimmed))   // false-label guard
}

The key invariant: only a successful json.Valid over the entire trimmed file can upgrade an EOF-class failure to the pretty-JSON diagnosis — truncation, corruption, or trailing garbage always keep the plain parse error.
