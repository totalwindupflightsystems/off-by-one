Solution: stale-pending-row-premise-verification

Close the pending row verification-only after a live HEAD re-probe — do not dispatch a worker

Problem class: a pending board row describes a defect that a sibling commit already fixed. Case at hand: the row quotes arm --check-kind delete-the-world emitting the inverse-leg error. At HEAD the same command still exits non-zero, but the failure text now names the check leg (check kind "...": unknown) because an unrelated DF-29-R2 commit made the message slot-aware. Outcome: the row's premise is stale. Resolve it as verification-only, cite the fixing SHA plus the live probe, dispatch no worker, and record any cosmetic residual as a note.

1. Root-cause analysis

1.1 Why the premise went stale

A board row is a claim about a defect at a point in time. Dispatch logic implicitly assumes the predicate still holds at HEAD. Between filing and dispatch, sibling commits land on the same code path. When one of them changes the behaviour the row describes:

  • the row is no longer a description of a live defect, and
  • dispatching a worker wastes a worktree/session on a defect that does not exist, and risks a "fix" that re-introduces the old wrong behaviour or a no-op commit.

This is the failure mode of assuming "the command still errors ⇒ the defect still exists." Exit code is not a premise check. The probe must read the failure text the row actually wrote.

1.2 The specific mechanism

The defect was not "the tool rejects a bogus kind" — rejecting a bogus kind is correct. The defect was misattribution of the failing slot:

  • The unknown-kind error was hard-coded to name the inverse leg, so --check-kind <bogus> blamed the inverse/matcher slot.
  • Commit DF-29-R2 made the message slot-aware: it interpolates which slot is unknown. The same validation now reports the leg that was actually requested.

So at HEAD:

Probe Old (row's premise) New (HEAD) Correct?
arm --check-kind delete-the-world inverse ... : unknown (wrong slot) check kind "delete-the-world": unknown ✅ names the check leg
arm --<inverse-flag> delete-the-world inverse ... : unknown inverse ... : unknown (names itself) ✅ names the inverse leg

The first row still fails, and that is expected. What changed is the slot named. That is the fix.

1.3 The trap

A blanket message change (always printing check) would also make the first probe "look fixed". That is why the resolution must probe both slots: the other slot has to keep naming itself. Only then is the change proven to be slot-aware rather than a global string swap.

2. Exact fix (commands)

This is a process fix, not a source change. The source fix already exists in the sibling commit DF-29-R2; do not re-implement it. The concrete actions are: re-probe at HEAD, prove the fix landed, and close the row without dispatch.

Set up once:

REPO=/path/to/repo
ROW=<row-id>                    # e.g. DF-<n> from `boardctl show`
FIX_SHA=<df29-r2-commit-sha>    # filled in at step 4
ARM=arm                         # or an absolute path
BOGUS=delete-the-world

Step 1 — Pin HEAD and fetch the integration branch

cd "$REPO"
git fetch origin
HEAD_SHA=$(git rev-parse HEAD)
echo "HEAD=${HEAD_SHA:0:12}"

Step 2 — Recover the row's own reproduction verbatim

Do not paraphrase. Read the exact command and the exact expected/observed text the row recorded:

boardctl -C "$REPO" show "$ROW" --events

Extract the reproduction command (arm --check-kind delete-the-world) and the leg the row says was wrongly named.

Step 3 — Run that exact command at HEAD and read the text

"$ARM" --check-kind "$BOGUS"; echo "check   exit=$?"

Expected at HEAD:

check kind "delete-the-world": unknown
check   exit=<non-zero>

The row's stated defect (inverse leg named) is gone. The non-zero exit is correct behaviour.

Step 4 — Probe both slots (prove slot-awareness, not a blanket change)

Identify the inverse-slot flag from the row or "$ARM" --help, then:

"$ARM" --check-kind   "$BOGUS"; echo "check   exit=$?"
"$ARM" --inverse-kind "$BOGUS"; echo "inverse exit=$?"   # <-- use the real inverse-slot flag

Pass condition:

  • check probe message names the check leg and does not contain inverse;
  • inverse probe message names the inverse leg.

If both probes print the same slot name, the fix is not verified (blanket change / regression) — stop and open a row instead of closing.

Step 5 — Identify the fixing commit and confirm it landed on origin/main

Find the commit that made the message slot-aware, then verify ancestry:

# locate the fixing commit (either form)
git log --oneline -S 'check kind' -- <path/to/error-message/source>
git log --oneline --grep='DF-29-R2'
FIX_SHA=$(git rev-parse <sha>)          # pin the full SHA

# hard gate: the fix must be on the integration branch
if git merge-base --is-ancestor "$FIX_SHA" origin/main; then
  echo "ANCESTOR: $FIX_SHA is on origin/main"
else
  echo "NOT-ANCESTOR: do NOT close; the fix has not landed"
  exit 1
fi

The illustrative shape of what DF-29-R2 did (for reference only — already committed):

// before (stale premise): the inverse leg is hard-coded
return fmt.Errorf("inverse check kind %q: unknown", kind)

// after (DF-29-R2): slot-aware; slot is "check" or "inverse"
return fmt.Errorf("%s kind %q: %w", slot, kind, ErrUnknownKind)

Step 6 — Close the row verification-only, no worker

Record the evidence, cite the SHA, and explicitly mark that no worker ran. The exact worker_status token may be constrained by the board's vocabulary; use the canonical "verified/verification-only" token your board accepts (check with boardctl validate / boardctl sweep-status).

boardctl -C "$REPO" event \
  --type task_verified --task-id "$ROW" --actor foreman \
  --detail-text "Premise stale at HEAD $(git rev-parse --short HEAD). Fixed by $FIX_SHA (DF-29-R2): check-kind errors are slot-aware. Live probe: 'arm --check-kind delete-the-world' -> 'check kind \"delete-the-world\": unknown'. Both slots self-identify. No worker dispatched."

boardctl -C "$REPO" update "$ROW" \
  --status complete \
  --worker-status verification-only \
  --commit-hash "$FIX_SHA" \
  --summary "Stale premise; defect already fixed by $FIX_SHA. Closed verification-only, no worker dispatched." \
  --note "Repro at HEAD: arm --check-kind delete-the-world -> check kind \"delete-the-world\": unknown (check leg named)." \
  --note "Symmetry probe: inverse-slot command still names the inverse leg." \
  --note "Cosmetic residual: <optional formatting nit, see §4>."

boardctl -C "$REPO" validate --strict-keys

No worktree, no branch, no task_dispatched event, no worker session. The only new event is the verification artifact.

3. Verification

3.1 Reproduction of the fix (live at HEAD)

cd "$REPO"
git fetch origin

"$ARM" --check-kind   delete-the-world; echo "exit=$?"
"$ARM" --inverse-kind delete-the-world; echo "exit=$?"   # real inverse flag

git merge-base --is-ancestor "$FIX_SHA" origin/main && echo "FIX-ON-MAIN"

Expected:

Assertion Expected Meaning
check probe exit non-zero bogus kind still rejected (correct)
check probe text contains check kind "delete-the-world": unknown check leg named
check probe text does not contain inverse old defect gone
inverse probe text contains inverse (names itself) slot-aware, not blanket
merge-base --is-ancestor exit 0 / FIX-ON-MAIN fix is on origin/main
row status complete, worker status verification-only closed without dispatch
boardctl show "$ROW" fix_commit_hash == $FIX_SHA, worker_dispatched absent cited SHA, no worker

3.2 Reusable probe script

Save as verify-slot-aware.sh, set INVERSE_FLAG to the board's real inverse-slot flag, then run from the repo:

#!/usr/bin/env bash
set -uo pipefail
ARM=${ARM:-arm}
BOGUS=${BOGUS:-delete-the-world}
INVERSE_FLAG=${INVERSE_FLAG:?set INVERSE_FLAG to the inverse-slot flag}

out_check=$("$ARM" --check-kind "$BOGUS" 2>&1); rc_check=$?
out_inv=$("$ARM" "$INVERSE_FLAG" "$BOGUS" 2>&1); rc_inv=$?

printf 'check   (rc=%s): %s\n' "$rc_check" "$out_check"
printf 'inverse (rc=%s): %s\n' "$rc_inv"  "$out_inv"

[ "$rc_check" -ne 0 ] || { echo "FAIL: check leg did not reject bogus kind"; exit 1; }
[ "$rc_inv"   -ne 0 ] || { echo "FAIL: inverse leg did not reject bogus kind"; exit 1; }
grep -qi 'check kind' <<<"$out_check" || { echo "FAIL: check leg did not name the CHECK slot"; exit 1; }
grep -qi 'inverse'    <<<"$out_inv"   || { echo "FAIL: inverse leg did not name the INVERSE slot"; exit 1; }
if grep -qi 'inverse' <<<"$out_check"; then
  echo "FAIL: check leg still names the INVERSE slot (stale premise)"; exit 1
fi
echo "PASS: check-kind error is slot-aware"

3.3 Triage rule (generalise the class)

Observation at HEAD Verdict Action
Row's command no longer errors at all Premise stale (fully fixed) Close verification-only, cite SHA, no worker
Row's command errors, but text changed to the correct value Premise stale (fixed) Close verification-only, cite SHA, no worker
Row's command reproduces the same wrong text Live defect Dispatch worker
Both slots now name the same slot Regression introduced, not a fix Open a row; do not close as fixed
Fix SHA not an ancestor of origin/main Fix not landed Do not close; dispatch/escalate

4. Residuals and follow-through

  • Cosmetic residual. If the new message is slightly ugly (e.g. quoting/formatting such as check kind "delete-the-world": unknown vs a preferred unknown check kind: delete-the-world), record it as a --note on the closed row. Do not file a fresh row: the defect (wrong slot) is fixed, and a formatting nit is not the row's premise. The note keeps the evidence for a future cleanup without re-opening the class.
  • Post-close check. Re-read the row and confirm fix_commit_hash, task_verified event, and the absence of any task_dispatched/worktree/branch fields. If any dispatch artifact exists, the process was violated — correct it before moving on.
  • Never trust exit code alone. The whole class exists because "still errors" was mistaken for "still broken." Always read the text the row wrote.

One-line summary

Re-run the row's exact repro at HEAD; if the failure text now names the correct slot and the sibling commit is an ancestor of origin/main and both slots self-identify, close the row verification-only citing the SHA + probe, dispatch no worker, and log cosmetic residuals as notes.
