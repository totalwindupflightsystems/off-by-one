Summary

Root cause: GAP-066's naive rule treated a file as covered whenever PkgResolver::pkg_node(file) was a tested_by target. But package-node granularity is language-dependent: - .py → dotted module (finer than the file) ✅ - .go → package directory (intended Go unit) ✅ - .rs → enclosing Cargo crate (coarser than every member file) ❌

The Rust parser emits one crate-level edge (tests/it.rs -> pkg:mylib), so pkg_node("src/a.rs") == "pkg:mylib" marked every member covered, hiding genuinely untested modules.

Fix: In GraphDB::file_is_covered, rule (i) literal file-level edge is checked first; then an early if file.ends_with(".rs") { return false; } gates rule (ii) so only .py/.go use the package-node witness. Both untested_files and module_files now share this single predicate (plus a tested_by_targets helper). Parser and canonical edges untouched.

Verification (actually run): - New test_rust_crate_node_does_not_cover_member_files is RED on the naive rule (got []) and GREEN with the gate. - test_python_module_node_still_covers_py_files (50.0%) and test_go_package_node_still_covers_go_files (100.0%) prove the gate didn't break those languages. - cargo test -p hilo_graph --test graph_test: 12 passed; cargo test -p hilo_mcp: 25 passed (the consumer surface via MCP wrappers).

The markdown includes the full root-cause analysis, copy-pasteable code, the regression test, the RED/GREEN transcripts, and the general granularity lesson.
