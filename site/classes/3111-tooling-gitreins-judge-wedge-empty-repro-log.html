Runbook: Recovering a gitreins judge Wedge (dead evaluator + never-filling repro log)

Problem class: tooling-gitreins-judge-wedge-empty-repro-log Symptom: gitreins judge --run-job <job-hex> stays alive forever after its task already flipped to complete in tasks.yaml. The judge's only child is a respawning /bin/sh -c 'sleep 29; wc -l /tmp/fulltest.log; tail -5 /tmp/fulltest.log; pgrep -f "go test"' polling a 0-byte /tmp/fulltest.log, while no go test process exists anywhere. The job record is stuck at status=running, finished_at=null, and the judge is orphaned to systemd --user. It burns evaluator cost and blocks the ownership gate of every later tick.

Replace the placeholders below: $TASK (task id), $JOB (the full job hex), $REPO (checkout root that contains tasks.yaml).

1. Root-cause analysis

The wedge is not a crash — it is a liveness/termination bug where the judge's wait loop has no terminal condition that can ever become true once the evaluator dies.

  1. Judge lifetime is decoupled from task state. The judge is spawned to run an evaluation job. It does not subscribe to tasks.yaml; when the task flips complete out-of-band (the code was already merged), nothing tells the running judge to stop. It keeps evaluating a job whose subject no longer exists.

  2. The wait loop is driven only by the repro log, which never fills. The judge decides "keep waiting" vs. "finish" by observing /tmp/fulltest.log (wc -l, tail -5). The evaluator process died (evaluator log went silent minutes in, right after context-compaction warnings), so the log stays at 0 bytes. An empty file matches neither the success pattern nor the failure pattern, so the state machine can never transition — it just re-polls.

  3. The liveness probe is non-authoritative. pgrep -f "go test" returning nothing is a perfectly valid terminal signal ("there is no work left to wait on"), but the loop treats it only as informational and re-arms sleep 29. There is no "no producer + no output ⇒ abort" rule and no overall deadline.

  4. The poll is respawned, so a naive PID check is unreliable. Each iteration forks a new /bin/sh; the parent judge PID is stable, but any single child PID is transient. Killing one child does nothing — you must terminate the judge tree / process group, or the loop re-forks.

  5. Orphaning defeats reaping. When the launching session/tmux ends, the judge reparents to systemd --user. There is no PR_SET_PDEATHSIG, no cgroup/KillMode=control-group, and no supervisor to reap it. The stale job record stays running with finished_at=null forever.

  6. The ownership gate is process-based, not lease-based. The next tick sees "a judge process still exists" and yields ownership to it. Because the process never exits, every subsequent tick is blocked — the blast radius grows over time.

  7. Abbreviated job ids are unusable for recovery. gitreins judge --status <short-id> answers Job not found; the reaper requires the full job hex. Operators who copy a short id conclude the record is already gone and then fail to reap it.

Correct invariant: a judge job must reach a terminal record under strictly bounded time regardless of the evaluator: (a) an overall job deadline, (b) a "no producer, no new bytes" abort rule, and (c) guaranteed death of the whole tree when the parent goes away. Recovery today is a manual equivalent of these.

2. Recovery procedure (exact commands — run in order)

All commands are copy-paste safe. The golden rule from the incident: capture evidence before stopping anything, and never re-run task complete.

Step 0 — Set up and capture evidence (do this BEFORE any kill / --status)

set -uo pipefail

TASK="${TASK:?export TASK=<task-id>}"
JOB="${JOB:?export JOB=<FULL-job-hex>}"     # FULL id: see step 0e
REPO="${REPO:?export REPO=/path/to/checkout}"

TS="$(date -u +%Y%m%dT%H%M%SZ)"
R="$HOME/gitreins-receipts/judge-wedge-$TASK-$TS"
mkdir -p "$R"
echo "evidence dir: $R"

(a) Find the judge and capture its full tree.

pgrep -af 'gitreins judge' | tee "$R/judge-procs.txt"
JUDGE_PID="$(pgrep -f "gitreins judge --run-job $JOB" | head -1)"
if [ -z "${JUDGE_PID:-}" ]; then
  echo "WARN: no --run-job $JOB process; showing all judge procs" | tee -a "$R/judge-procs.txt"
  JUDGE_PID="$(pgrep -f 'gitreins judge' | head -1)"
fi
echo "JUDGE_PID=$JUDGE_PID" | tee "$R/pid.txt"

ps -o pid,ppid,pgid,sid,lstart,etime,stat,wchan:24,args -p "$JUDGE_PID" \
   2>/dev/null | tee "$R/ps-self.txt"
pgrep -P "$JUDGE_PID" -a | tee "$R/children.txt" || true
ps -eo pid,ppid,pgid,args --forest > "$R/ps-forest.txt" 2>/dev/null || true
readlink -f "/proc/$JUDGE_PID/cwd" | tee "$R/cwd.txt"

(b) Capture the full job hex and the stale status.

# Discover the full job id if you only have a short one:
gitreins judge --list 2>/dev/null | tee "$R/job-list.txt"
gitreins judge --status "$JOB" | tee "$R/status-before.txt"

(c) Capture the tasks.yaml diff and the task's recorded state.

git -C "$REPO" diff -- tasks.yaml | tee "$R/tasks.yaml.diff"
grep -n "$TASK" "$REPO/tasks.yaml" | tee "$R/task-line.txt" || true
git -C "$REPO" rev-parse HEAD | tee "$R/head-before.txt"

(d) Capture the existing (quick-tier) verdict, if any.

gitreins judge --verdict "$TASK" 2>/dev/null | tee "$R/verdict-before.txt" \
  || echo "no verdict yet" | tee "$R/verdict-before.txt"

(e) Capture the repro/evaluator evidence — this is the smoking gun.

{
  echo "### /tmp/fulltest.log"
  ls -la /tmp/fulltest.log 2>&1
  wc -c /tmp/fulltest.log 2>&1
  echo "### go test processes"
  pgrep -af 'go test' || echo "none"
  echo "### poll children"
  pgrep -af 'sleep 29|fulltest.log' || echo "none"
} | tee "$R/repro-evidence.txt"

Expected: /tmp/fulltest.log size 0, go test → none, but the sleep 29 … pgrep poll is present. That triple is the signature of this wedge.

Step 1 — SIGTERM the orphan judge tree (it exits on TERM)

Terminate the process group, not a single transient child, so the respawning poll cannot re-fork.

PGID="$(ps -o pgid= -p "$JUDGE_PID" | tr -d ' ')"

# TERM the whole group; falls back to the leader if PGID is 0/unavailable.
if [ -n "${PGID:-}" ] && [ "$PGID" -gt 1 ] 2>/dev/null; then
  kill -TERM "-$PGID" 2>/dev/null || kill -TERM "$JUDGE_PID" 2>/dev/null
else
  kill -TERM "$JUDGE_PID" 2>/dev/null
fi

# Wait up to 20s for a clean TERM exit.
for i in $(seq 1 20); do
  kill -0 "$JUDGE_PID" 2>/dev/null || { echo "judge exited after ${i}s"; break; }
  sleep 1
done

# Escalate only if it ignored TERM.
if kill -0 "$JUDGE_PID" 2>/dev/null; then
  echo "escalating to KILL"
  [ -n "${PGID:-}" ] && kill -KILL "-$PGID" 2>/dev/null
  kill -KILL "$JUDGE_PID" 2>/dev/null
  sleep 1
fi

pgrep -af 'gitreins judge' | tee "$R/judge-procs-after.txt" || echo "no judge procs remain"

Step 2 — Reap the stale record with the FULL job hex

gitreins judge --status "$JOB" | tee "$R/status-reap.txt"

This is the step that marks the record terminal (error/orphan) and sets finished_at. A truncated id returns Job not found, so always pass the full hex captured in 0(b).

Confirm the record is terminal:

gitreins judge --status "$JOB" | grep -Eq 'status=(error|orphan|failed|done)' \
  && echo "OK: record terminal" \
  || echo "STILL STALE: inspect status-reap.txt"

Step 3 — Re-dispatch the judge asynchronously

gitreins judge "$TASK" --async | tee "$R/redispatch.txt"

Do not run gitreins task complete — the task is already complete; re-completing corrupts state.

Step 4 — Bind the existing quick-tier verdict to the merged commit (first-pass evidence)

If Step 0(d) produced a verdict (commonly PASS DEGRADED with "No Go files staged" because the code was already merged), attach it to the merged commit as first-pass evidence and let the async re-run supersede it.

MERGED_SHA="$(git -C "$REPO" rev-parse HEAD)"
echo "MERGED_SHA=$MERGED_SHA" | tee "$R/merged-sha.txt"

# Primary: use gitreins' binding verb if available in your version.
gitreins verdict bind \
  --task "$TASK" --commit "$MERGED_SHA" --tier quick \
  --verdict "PASS_DEGRADED" \
  --note "No Go files staged; code already merged; bound as first-pass evidence" \
  2>&1 | tee "$R/verdict-bind.txt" \
  || echo "verdict bind unavailable; recording portable evidence in receipt" \
       | tee -a "$R/verdict-bind.txt"

If verdict bind is not a verb in your build, record the same fact in the receipt (Step 5) and in the task's evidence notes — the re-run verdict is authoritative and supersedes.

Step 5 — Record the receipt OUTSIDE the checkout

Never write evidence into $REPO (it would dirty the tree and re-trigger tooling).

cat > "$R/RECEIPT.md" <<EOF
# Judge-wedge recovery receipt

- task:        $TASK
- full job:    $JOB
- judge pid:   $JUDGE_PID (pgid ${PGID:-?})
- cwd:         $(cat "$R/cwd.txt" 2>/dev/null)
- head:        $MERGED_SHA
- repro log:   /tmp/fulltest.log size=$(wc -c < /tmp/fulltest.log 2>/dev/null || echo n/a)
- go test:     $(pgrep -af 'go test' || echo none)
- prior verdict: $(head -c 200 "$R/verdict-before.txt" 2>/dev/null)
- actions: evidence -> SIGTERM group -> judge --status (full hex) -> judge --async -> bind quick verdict
- NOT done: task complete (already complete)
EOF
cat "$R/RECEIPT.md"

3. Permanent fix (prevent recurrence)

The manual procedure above is a patch. Apply these in the judge implementation / supervisor so the wedge cannot recur.

(1) Overall job deadline. If a job runs longer than --job-timeout (e.g. 30–45 min), write status=error reason=timeout and exit non-zero.

(2) "No producer, no progress" abort. Track (mtime,size) of the repro log. If it is unchanged for N consecutive polls and pgrep -f "go test" is empty, terminate with status=error reason=no-progress. A 0-byte log with no producer is terminal, not "wait".

(3) Die with the parent. Launch the job in its own process group/cgroup and set KillMode=control-group (systemd) or prctl(PR_SET_PDEATHSIG, SIGTERM) so orphans cannot survive the launching session.

(4) Lease-based ownership gate. Gate on a heartbeat timestamp in the job record, not on pgrep. A record with a stale heartbeat is reclaimable; a live-but-stuck process cannot block future ticks.

(5) Full-id or unambiguous status. Make judge --status expand unique abbreviated ids, or fail with Ambiguous/Too short instead of Job not found, so recovery never stalls on id handling.

(6) Watchdog sweep. On every tick, before acquiring ownership, sweep for status=running records whose heartbeat is stale and whose process tree is gone, and reap them automatically.

4. Verification

Run these after recovery; all must hold.

  1. No wedged judge remains. bash pgrep -af 'gitreins judge' || echo "PASS: no judge processes" pgrep -af 'sleep 29' || echo "PASS: no respawning poll"

  2. Old job is terminal, not running. bash gitreins judge --status "$JOB" | tee /dev/stderr \ | grep -Eq 'status=(error|orphan|failed|done)' \ && echo "PASS: old job terminal" || echo "FAIL: still running" gitreins judge --status "$JOB" | grep -Eq 'finished_at=[^n]' \ && echo "PASS: finished_at set" || echo "FAIL: finished_at null"

  3. New async job is alive and making progress. bash gitreins judge --list | grep "$TASK" # after a few minutes, the evaluator log must be growing: stat -c '%s %y' /tmp/fulltest.log pgrep -af 'go test' && echo "PASS: producer running"

  4. Ownership gate is free for the next tick. bash gitreins judge --list --status running # must not show the old wedged job; only the newly dispatched one

  5. No forbidden actions taken. bash git -C "$REPO" status --porcelain # no tasks.yaml churn from recovery # receipt exists outside the checkout: ls -l "$HOME/gitreins-receipts/judge-wedge-$TASK-"*/RECEIPT.md

  6. Cost is bounded. The wedged judge is gone and the re-run has a deadline, so evaluator spend stops when the run completes or times out.

Rollback / abort: if Step 2 cannot mark the record terminal after the tree is dead, do not re-dispatch; escalate with $R/status-before.txt + $R/ps-forest.txt (full job hex included) and leave the dead tree stopped. Never restore the wedged process.

Key takeaway: the recovery that unblocks the system is SIGTERM the whole process group, then gitreins judge --status <FULL-job-hex> to reap the stale record, then gitreins judge <task> --async. The two forbidden moves are re-running task complete and leaving the wedged judge alive.
