Fix Dashboard Control Commands Targeting the Wrong Session (DF-AIPP-11)

Root cause

FastAPI binds a plain scalar parameter to the query string, not the JSON body:

@app.post("/api/control/pause")
async def pause(session_id: str = Query("default")):
    ...

The dashboard was sending:

POST /api/control/pause
Content-Type: application/json

{"session_id": "sess-42"}

FastAPI ignored session_id in the JSON body because the handler did not declare a Body(...) parameter or a Pydantic request model. It found no session_id in the query string and silently used the default, "default". Every control request therefore returned 200 OK while acting on the wrong session.

The same mismatch existed on all four control endpoints (pause, resume, stop, restart). The default value hid the error; without it, FastAPI would have returned 422 Unprocessable Entity for the mismatched request.

Exact fix

1. Send session_id on the query string in the dashboard

Find the shared dashboard control helper, or the four individual fetch calls, and change the transport so session_id is only in the URL query string. Keep any other command fields in the JSON body.

// dashboard/static/app.js
const CONTROL_ACTIONS = ["pause", "resume", "stop", "restart"];

async function sendControl(action, sessionId, body = {}) {
  if (!CONTROL_ACTIONS.includes(action)) {
    throw new Error(`Unknown control action: ${action}`);
  }
  if (!sessionId) {
    throw new Error("Cannot send a control command without session_id");
  }

  // Defensive: remove session_id if an old caller still puts it in the body.
  const { session_id: _ignored, ...jsonBody } = body;

  const params = new URLSearchParams({ session_id: sessionId });
  const response = await fetch(
    `/api/control/${action}?${params.toString()}`,
    {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(jsonBody),
    },
  );

  if (!response.ok) {
    throw new Error(
      `${action} failed (${response.status}): ${await response.text()}`,
    );
  }
  return response.json();
}

Replace all four button handlers with calls through this helper:

document.querySelector("#pause").addEventListener("click", () => {
  sendControl("pause", currentSessionId()).catch(showError);
});

document.querySelector("#resume").addEventListener("click", () => {
  sendControl("resume", currentSessionId()).catch(showError);
});

document.querySelector("#stop").addEventListener("click", () => {
  sendControl("stop", currentSessionId()).catch(showError);
});

document.querySelector("#restart").addEventListener("click", () => {
  sendControl("restart", currentSessionId()).catch(showError);
});

If the four endpoints are not under /api/control/{action}, keep the same change: put ?session_id=${encodeURIComponent(sessionId)} on the endpoint URL and remove session_id from JSON.stringify(...).

2. Make the FastAPI side fail closed

Keep session_id as a required query parameter instead of silently falling back to "default". This turns any future client regression into a visible 422 rather than a control command against the wrong session.

from fastapi import Query
from typing import Annotated

@app.post("/api/control/pause")
async def pause(session_id: Annotated[str, Query(min_length=1)]):
    ...

@app.post("/api/control/resume")
async def resume(session_id: Annotated[str, Query(min_length=1)]):
    ...

@app.post("/api/control/stop")
async def stop(session_id: Annotated[str, Query(min_length=1)]):
    ...

@app.post("/api/control/restart")
async def restart(session_id: Annotated[str, Query(min_length=1)]):
    ...

Do not switch the handler to Body(...) unless the client is also changed to send JSON. Mixing the two is exactly what caused this bug.

3. Add the regression test

Add a test that pins both the HTTP transport and which session the handler receives. Adjust the two imports/names marked below to the project's actual app and control service.

# tests/test_dashboard_control_transport.py
import pytest
from fastapi.testclient import TestClient

from app.main import app  # adjust to the project's FastAPI app

CONTROL_ACTIONS = ("pause", "resume", "stop", "restart")


class TestControlTransportQueryParam:
    @pytest.mark.parametrize("action", CONTROL_ACTIONS)
    def test_session_id_is_carried_in_query_and_reaches_handler(
        self, action, monkeypatch
    ):
        calls = []

        # Patch the single service function that all four routes call.
        # Adjust module/function names to the project's implementation.
        from app import control_service
        monkeypatch.setattr(
            control_service,
            "apply_control",
            lambda action_, session_id: (
                calls.append((action_, session_id)) or {"ok": True}
            ),
            raising=True,
        )

        response = TestClient(app).post(
            f"/api/control/{action}",
            params={"session_id": "sess-42"},
            json={},  # deliberately no session_id in the JSON body
        )

        assert response.status_code == 200, response.text
        assert response.request.url.params["session_id"] == "sess-42"
        assert "session_id" not in response.request.content.decode()
        assert calls == [(action, "sess-42")]

The key assertions are:

  • session_id appears in the request URL query string.
  • session_id is absent from the JSON body.
  • The handler/service receives the selected session ID, not "default".

To pin the browser-side transport itself, also export sendControl from the dashboard module and add a small unit test with the project's JS test runner:

// dashboard/static/control.test.js
import { describe, expect, it, vi } from "vitest";
import { sendControl } from "./app.js";

describe("dashboard control transport", () => {
  it("puts session_id on the query string, not in the JSON body", async () => {
    global.fetch = vi.fn(async () => ({
      ok: true,
      json: async () => ({}),
    }));

    await sendControl("pause", "sess-42", {
      reason: "manual",
      session_id: "stale-value",
    });

    const [url, init] = global.fetch.mock.calls[0];
    const parsed = new URL(url, "http://localhost");
    expect(parsed.pathname).toBe("/api/control/pause");
    expect(parsed.searchParams.get("session_id")).toBe("sess-42");
    expect(JSON.parse(init.body)).toEqual({ reason: "manual" });
  });
});
