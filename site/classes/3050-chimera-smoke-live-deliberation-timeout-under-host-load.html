Smoke-live deliberation TimeoutError under host load — not a regression

Problem class: chimera-smoke-live-deliberation-timeout-under-host-load Verdict: The service and deliberation path are healthy. scripts/smoke_live.py failed because its fixed per-request timeout is shorter than a healthy /v1/deliberate call takes on a loaded host. Do not touch provider/auth/format code, and do not conflate this with deployment staleness.

Root-cause analysis

urllib.request.urlopen(...) raised TimeoutError: [Errno 110] / socket readinto timed out while waiting for the /v1/deliberate response body. The raw socket.timeout propagates out of urlopen, so it looks like a provider/service fault — but it is a client-side read timeout: the client gave up before the server answered.

Why this happens under load:

  1. smoke_live.py uses a single fixed timeout= (typically 15–60 s) for the deliberation request.
  2. Deliberation is a multi-model fan-out + aggregation; on an idle box it's a few seconds, but under heavy concurrent load (loadavg 13–23 on 16 cores) it stretches to ~18–27 s.
  3. When latency crosses the fixed budget, the socket read times out, urlopen raises, the smoke aborts rc=1.
  4. Nothing changed between the failing and passing runs except host load (9bdb753 → 06639fa, same code). That is the signature of a budget-vs-latency race, not a code regression.

The TimeoutError means "server did not answer inside my budget", not "server is broken". Prove the endpoint answers with a real budget.

Discrimination procedure (before debugging code)

1. Service up with expected commit?

curl -s -m 10 http://localhost:8765/health

Observed: {"status":"alive","uptime_models":43,"commit":"06639fa","version":"0.2.8"} — process is serving.

/v1/health may also show "status":"degraded" with unhealthy_providers:["cliproxy"] (missing credentials) and slow_providers:["router9"]. That is pre-existing and unrelated — google, hermes, deepseek, openrouter, zai, anthropic are healthy and deliberate fine. A cliproxy credential issue cannot cause a socket read timeout.

2. Direct /v1/deliberate with a real budget

cat >/tmp/delib.json <<'EOF'
{"prompt":"Reply with the single word: pong","formation":"auto"}
EOF
curl -s -m 300 -o /tmp/delib_out.json -w 'HTTP=%{http_code} time_total=%{time_total}\n' \
  -H 'Content-Type: application/json' --data @/tmp/delib.json \
  http://localhost:8765/v1/deliberate

Observed: HTTP=200 time_total=14.825631, request_id=4d21cfd7cbd34e6b, answer='pong', worker_failures=None.

3. Reproduce failure by shrinking only the client budget

for t in 5 10 300; do
  curl -s -m $t -o /dev/null \
    -w "timeout=${t}s HTTP=%{http_code} time=%{time_total}\n" \
    -H 'Content-Type: application/json' --data @/tmp/delib.json \
    http://localhost:8765/v1/deliberate || echo "curl rc=$? (timed out)"
done

Observed:

timeout=5s   HTTP=000 time=5.002809    curl rc=28 (timed out)
timeout=10s  HTTP=000 time=10.002077   curl rc=28 (timed out)
timeout=300s HTTP=200 time=7.850687    answer='pong'

Identical request, healthy server; only the client timeout changes the outcome.

4. Re-run later / when load drops → rc=0 unchanged.

Only if step 2 also fails is there a real fault: check /v1/health details.providers and journalctl -u chimera. Not the case here.

Exact fix

A. Immediate (no code change)

Re-run when load drops, or set a larger budget if supported:

uptime
python scripts/smoke_live.py; echo "rc=$?"

B. Durable fix — make the timeout explicit, configurable, classified

grep -n "urlopen\|timeout=" scripts/smoke_live.py

Patch (scripts/smoke_live.py) — three essential changes:

import os, socket, json, urllib.request

DELIBERATE_TIMEOUT_S = float(os.environ.get("SMOKE_DELIBERATE_TIMEOUT", "300"))

def post_json(url: str, payload: dict) -> dict:
    req = urllib.request.Request(
        url, data=json.dumps(payload).encode(),
        headers={"Content-Type": "application/json"}, method="POST",
    )
    try:
        with urllib.request.urlopen(req, timeout=DELIBERATE_TIMEOUT_S) as resp:
            return json.load(resp)
    except (socket.timeout, TimeoutError) as exc:
        load = os.getloadavg()[0]
        raise SystemExit(
            "SMOKE TIMEOUT (classified: budget-vs-host-load, not a regression): "
            f"/v1/deliberate exceeded {DELIBERATE_TIMEOUT_S:.0f}s (loadavg={load:.1f}). "
            "Confirm with: curl -s -m 300 -H 'Content-Type: application/json' "
            "-d '{\"prompt\":\"Reply with the single word: pong\"}' "
            "http://localhost:8765/v1/deliberate ; then re-run when load drops "
            "or raise SMOKE_DELIBERATE_TIMEOUT."
        ) from exc
    # Do NOT swallow non-timeout errors; genuine HTTP/provider faults must fail loudly.

Optional bounded retry for bursty load:

import time
for attempt in range(2):
    try:
        body = post_json(url, payload); break
    except SystemExit:
        if attempt == 1: raise
        time.sleep(5.0)

Do not: restart providers, rotate credentials, or edit provider/aggregation logic — the path already returned 200 with a merged result.
