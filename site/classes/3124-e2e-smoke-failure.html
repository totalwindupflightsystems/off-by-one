Fix: derive e2e smoke schema expectations from migrations

Root cause

scripts/e2e-smoke.sh hard-coded the old schema shape:

EXPECTED_MIGS=27
EXPECTED_TABLES=44

Migrations 028–031 added four *.up.sql files and a net two tables, so the database now has 31 applied migrations, 46 user tables, and 31 schema_migrations rows. The binary and migrations were correct; the smoke script compared current results against stale constants.

The test should derive expectations from the migration directory rather than duplicating schema history as literals.

Exact fix

In scripts/e2e-smoke.sh, replace the hard-coded EXPECTED_MIGS / EXPECTED_TABLES assignments and any remaining literal 27 / 44 checks with:

# --- derive schema expectations from migrations (source of truth) ---
SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
REPO_ROOT="$(cd -- "$SCRIPT_DIR/.." && pwd)"
MIGRATIONS_DIR="${MIGRATIONS_DIR:-$REPO_ROOT/migrations/sqlite}"

mapfile -t MIGRATION_FILES < <(
  find "$MIGRATIONS_DIR" -maxdepth 1 -type f -name '*.up.sql' -print | LC_ALL=C sort
)

if ((${#MIGRATION_FILES[@]} == 0)); then
  echo "e2e-smoke: no *.up.sql files found under $MIGRATIONS_DIR" >&2
  exit 1
fi

EXPECTED_MIGS=${#MIGRATION_FILES[@]}

# Final tables = every CREATE TABLE, minus every DROP TABLE, plus the
# migrator-owned schema_migrations table. A rebuild migration
# (create temp + drop old + rename) contributes +1 -1 = 0 net.
CREATE_TABLE_COUNT="$(
  grep -Eih '^[[:space:]]*CREATE[[:space:]]+TABLE([[:space:]]|$)' \
    "${MIGRATION_FILES[@]}" | wc -l
)"
DROP_TABLE_COUNT="$(
  grep -Eih '^[[:space:]]*DROP[[:space:]]+TABLE([[:space:]]|$)' \
    "${MIGRATION_FILES[@]}" | wc -l
)"
EXPECTED_TABLES=$(( CREATE_TABLE_COUNT - DROP_TABLE_COUNT + 1 ))

# Backward-compatible name used by the schema_migrations check.
EXPECTED_SCHEMA_MIGRATIONS="$EXPECTED_MIGS"

Then ensure the checks use:

  • EXPECTED_MIGS for applied migration count
  • EXPECTED_TABLES for PRAGMA table count
  • EXPECTED_SCHEMA_MIGRATIONS or EXPECTED_MIGS for schema_migrations rows

Remove the old literal display text such as migrate up 27/27.

For this repository, this derives:

EXPECTED_MIGS=31
EXPECTED_TABLES=46
EXPECTED_SCHEMA_MIGRATIONS=31

Verification

Check shell syntax and run the suite:

bash -n scripts/e2e-smoke.sh
bash scripts/e2e-smoke.sh

Expected:

ALL LEGS PASS 18/18

Independently print the derived values:

cd /path/to/Helios
MIGS=$(find migrations/sqlite -maxdepth 1 -name '*.up.sql' | wc -l)
CREATES=$(grep -Eih '^[[:space:]]*CREATE[[:space:]]+TABLE([[:space:]]|$)' migrations/sqlite/*.up.sql | wc -l)
DROPS=$(grep -Eih '^[[:space:]]*DROP[[:space:]]+TABLE([[:space:]]|$)' migrations/sqlite/*.up.sql | wc -l)
printf 'migs=%s creates=%s drops=%s tables=%s\n' \
  "$MIGS" "$CREATES" "$DROPS" "$((CREATES - DROPS + 1))"

Expected:

migs=31 ... tables=46

The exact create/drop split depends on rebuild migrations; the invariant is:

tables == creates - drops + 1

A synthetic 31-migration test covering a normal create, a rebuild (create new + drop old + rename), a permanent drop, and additional creates was validated against a real SQLite database:

EXPECTED_MIGS=31 ACTUAL_MIGS=31
creates=30 drops=2 EXPECTED_TABLES=29 ACTUAL_TABLES=29
SYNTHETIC CHECK PASS

The create-minus-drop formula remains correct as migrations grow, including rebuild-style migrations.
