Summary

Diagnosis (reproduced in a scratch repo): Playwright's default outputDir is ./test-results relative to the config, and it wipes/rewrites that directory each run. Because the repo tracks real audit files in frontend/test-results/, they were deleted/modified. .gitignore cannot protect tracked files, and frontend/playwright-report/ was never actually ignored.

I reproduced the exact failure:

 M frontend/test-results/.last-run.json
 D frontend/test-results/accessibility-audit.md
 D frontend/test-results/run-a11y-audit.mjs
?? frontend/playwright-report/

Fix (verified): 1. outputDir: './.playwright-artifacts' — a dedicated sibling path, not nested in the HTML reporter dir (confirmed Playwright rejects that with HTML reporter output folder clashes with the tests output folder). 2. Add frontend/playwright-report/ and frontend/.playwright-artifacts/ to .gitignore; never ignore frontend/test-results/. 3. Point CI/docs at that config.

Verification passing after the fix: re-ran the tool, git status --porcelain is empty, the tracked frontend/test-results/ files remain, and git check-ignore -v exits 0 with a matching rule for both generated dirs.

The document includes the config, .gitignore, exact verification commands with expected output, and the before/after evidence.
