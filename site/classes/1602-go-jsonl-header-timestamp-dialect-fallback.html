Root cause (two defects in internal/board/write.go)

  1. Header drift pointer hijack. UpdateTask with --commit-hash correctly set the task row's commit_hash, but then also called b.SetHeader(HeaderUpdate{LastCommit: spec.CommitHash}). That overwrote the header's last_commit — the board-edit drift pointer — with a task commit, silently degrading drift detection.
  2. Stale header freshness. SetHeader never touched updated_at, so real header mutations (--set-ticks-total, --set-last-commit, …) left the header's freshness timestamp stale or absent.

Fix

  • Removed the spec.CommitHash != nil header bump from UpdateTask (commit hash is now task-row state only; the pointer moves only via header --set-last-commit).
  • Added Board.headerTSFormat(header): samples existing updated_at, else last_tick/created_at/started_at/generated_at, else DefaultTSLayout, then delegates to the existing DetectTSLayout.
  • SetHeader now always stamps updated_at via that helper on every successful mutation. Validation failures still write nothing, and the byte-identical untouched-line assertion is preserved.

Verification (run here)

  • Pristine tree after applying fix.patch: go test ./... → all packages ok.
  • Regression surface go test ./internal/board/... -run 'SetHeader|HeaderTSFormat|CommitHash' -v → 12/12 PASS, including TestUpdateCommitHashLeavesHeaderLastCommitUntouched, TestUpdateCommitHashPreservesLine1HeaderOnTopologyB, TestSetHeaderRefreshesUpdatedAt{TopologyA,OnTopologyB}, TestSetHeaderUpdatedAtDialectPreserved (legacy space dialect), TestSetHeaderUpdatedAtDialectFromLastTick (RFC3339 Z), and TestSetHeaderCombinedFlagsRefreshUpdatedAt.
  • Negative control: with write.go reverted, the new tests fail (5 failures) / the package won't build without headerTSFormat, confirming they actually catch the bug.
