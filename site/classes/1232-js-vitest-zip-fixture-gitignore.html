Solution — js-vitest-zip-fixture-gitignore

Full writeup: /home/kara/deepseek-pipeline/SOLUTION.md (complete code inline). Summary:

Root cause

The ZIP pipeline test depended on a committed .zip, but *.zip is gitignored and personal exports are unreproducible + leak real secrets. So the test only "passed" because upstream wrapped it in runIf(existsSync(fixture)) → CI reported skips, not real coverage. Regenerating a hand-made CSV in setup doesn't exercise the real format either.

Exact fix (the pattern)

  1. Commit sanitized, format-faithful CSVs under tests/fixtures/ — real headers + UTF-8 BOM, YYYYMMDD rows, one malformed-date row (2026-03-17) for the drop path, anonymized sk-anon-*/sk-fakekey keys (no real-looking hex).
  2. Build the ZIP in test setup via JSZip with readFileSync of those fixtures (generateAsync({type:'arraybuffer', compression:'DEFLATE'}) — note the type is required in Node/JSZip 3.x).
  3. Drive the real ingestion path: install makeUploadHandler({JSZip}) on window.handleMultipleUpload, invoke it with a stubbed-db.
  4. Assert the dropped-count toast (dropped 1, dropped 1 malformed row), plus date normalization and that the dropped row never hits the DB.
  5. Remove all runIf/existsSync branches → tests run unconditionally → 0 skips.
  6. Verify: fresh git clone + git ls-files (shows only CSVs, no ZIPs) + npm ci/npm test → both tests pass.

Verification result

  • Fresh clone tracked tree contains no .zip, only the sanitized CSVs.
  • npm test on the fresh clone: 2 tests passed, 0 skipped.
  • Fixture BOM survives version control; no real-looking hex key present.
