Tempo Compose/Config Drift: Sync from the Live Host Before Committing

Root cause

The repository was treated as the source of truth while the running host was the real source of truth.

The failure chain is:

  1. Tempo was changed on the live host: image tag, ports, command, mounts, or tempo.yml contents.
  2. Those changes were never copied back into Git.
  3. Compose/config edits and documentation were made from the stale repository copy.
  4. The README “shape” diagram and architecture.md data flow therefore described the old deployment, even if the new files were syntactically valid.
  5. No verification compared the committed files to the live container/configuration before commit.

A Compose project can also use multiple files and env_file entries. Copying only the repository’s docker-compose.yml — or assuming Tempo’s config is always at /etc/tempo.yml — is unreliable. The live container’s Compose labels, command line, and mounts must be inspected.

Exact fix

Run the discovery/sync steps on the Docker host that runs Tempo. If the Git checkout is elsewhere, sync the resulting files back to the checkout, review them, and commit there.

1. Discover the actual live Tempo deployment

SERVICE=tempo
COMPOSE_PROJECT=monitoring

CID="$(docker ps -q \
  --filter "label=com.docker.compose.project=$COMPOSE_PROJECT" \
  --filter "label=com.docker.compose.service=$SERVICE" | head -n1)"
test -n "$CID" || { echo "Tempo container not found"; exit 1; }

docker inspect "$CID" --format '
project={{index .Config.Labels "com.docker.compose.project"}}
compose_files={{index .Config.Labels "com.docker.compose.project.config_files"}}
workdir={{index .Config.Labels "com.docker.compose.project.working_dir"}}
image={{.Config.Image}}
entrypoint={{json .Config.Entrypoint}}
cmd={{json .Config.Cmd}}
'

docker inspect "$CID" --format '{{json .Mounts}}' | jq .

The key values are:

  • com.docker.compose.project.config_files — the actual compose file(s).
  • com.docker.compose.project.working_dir — the host project directory.
  • Config.Cmd / Config.Entrypoint — contains the real -config.file=... path.
  • Mounts — maps the container config path to the host file, if bind-mounted.

2. Copy the exact live files into the repository

Save this as sync-live-tempo.sh and run it with the environment variables below.

#!/usr/bin/env bash
set -euo pipefail

SERVICE="${SERVICE:-tempo}"
COMPOSE_PROJECT="${COMPOSE_PROJECT:-monitoring}"
REPO="${REPO:-$PWD}"

die() { printf 'ERROR: %s\n' "$*" >&2; exit 1; }

command -v docker >/dev/null || die "docker not found"
command -v git >/dev/null || die "git not found"
[[ -d "$REPO/.git" ]] || die "$REPO is not a git worktree"
REPO="$(git -C "$REPO" rev-parse --show-toplevel)"

CID="$(docker ps -q \
  --filter "label=com.docker.compose.project=$COMPOSE_PROJECT" \
  --filter "label=com.docker.compose.service=$SERVICE" | head -n1)"
if [[ -z "$CID" ]]; then
  CID="$(docker ps -aq \
    --filter "label=com.docker.compose.project=$COMPOSE_PROJECT" \
    --filter "label=com.docker.compose.service=$SERVICE" | head -n1)"
fi
[[ -n "$CID" ]] || die "No $SERVICE container found in project $COMPOSE_PROJECT"

label() {
  docker inspect -f "{{index .Config.Labels \"$1\"}}" "$CID"
}

COMPOSE_FILES="$(label com.docker.compose.project.config_files)"
WORKDIR="$(label com.docker.compose.project.working_dir)"
[[ -n "$COMPOSE_FILES" && "$COMPOSE_FILES" != "<no value>" ]] \
  || die "Container has no compose config_files label"

IFS=',' read -r -a FILES <<< "$COMPOSE_FILES"

# Pick the compose file that defines the Tempo service.
MAIN_COMPOSE=""
for f in "${FILES[@]}"; do
  [[ "$f" = /* ]] || f="$WORKDIR/$f"
  if [[ -f "$f" ]] && grep -Eq "^[[:space:]]*${SERVICE}:" "$f"; then
    MAIN_COMPOSE="$f"
    break
  fi
done
if [[ -z "$MAIN_COMPOSE" ]]; then
  MAIN_COMPOSE="${FILES[0]}"
  [[ "$MAIN_COMPOSE" = /* ]] || MAIN_COMPOSE="$WORKDIR/$MAIN_COMPOSE"
fi
[[ -f "$MAIN_COMPOSE" ]] || die "Live compose file not found: $MAIN_COMPOSE"

# Find the real Tempo config path in entrypoint/cmd.
ARGS=()
while IFS= read -r line; do ARGS+=("$line"); done < <(
  docker inspect -f \
    '{{range .Config.Entrypoint}}{{println .}}{{end}}{{range .Config.Cmd}}{{println .}}{{end}}' \
    "$CID"
)
CFG_PATH=""
for i in "${!ARGS[@]}"; do
  case "${ARGS[$i]}" in
    -config.file|--config.file) CFG_PATH="${ARGS[$((i+1))]:-}";;
    -config.file=*|--config.file=*) CFG_PATH="${ARGS[$i]#*=}";;
  esac
done
[[ -n "$CFG_PATH" ]] || CFG_PATH="/etc/tempo.yml"

# Resolve a bind-mounted config; otherwise read it from the container.
CFG_SRC="$(docker inspect -f \
  "{{range .Mounts}}{{if eq .Destination \"$CFG_PATH\"}}{{.Source}}{{end}}{{end}}" \
  "$CID")"

TMP="$(mktemp -d)"
trap 'rm -rf "$TMP"' EXIT

cp -a "$MAIN_COMPOSE" "$TMP/docker-compose.live.yml"
if [[ -n "$CFG_SRC" && -f "$CFG_SRC" ]]; then
  cp -a "$CFG_SRC" "$TMP/tempo.live.yml"
else
  docker cp "$CID:$CFG_PATH" "$TMP/tempo.live.yml" >/dev/null
fi

printf 'live compose : %s\n' "$MAIN_COMPOSE"
printf 'live tempo   : %s%s\n' "$CFG_PATH" "${CFG_SRC:+ (host bind: $CFG_SRC)}"
printf 'compose files: %s\n\n' "$COMPOSE_FILES"

# Show the drift before replacing the repository files.
diff -u "$REPO/docker-compose.yml" "$TMP/docker-compose.live.yml" || true
diff -u "$REPO/tempo.yml" "$TMP/tempo.live.yml" || true

cp "$TMP/docker-compose.live.yml" "$REPO/docker-compose.yml"
cp "$TMP/tempo.live.yml" "$REPO/tempo.yml"

printf '\nUpdated %s and %s\n' \
  "$REPO/docker-compose.yml" "$REPO/tempo.yml"
printf 'Review with: git -C %q diff\n' "$REPO"

Run it:

SERVICE=tempo COMPOSE_PROJECT=monitoring REPO=/path/to/repo \
  ./sync-live-tempo.sh

Do not blindly accept the diff if the repository intentionally contains extra services. In that case, merge only the Tempo service block and any referenced top-level volumes/networks, then re-run the verification below.

3. Keep the config filename consistent with the Compose mount

The script writes the committed config as tempo.yml. Make sure the synchronized Compose file references that same file. If the live deployment used a different host filename, normalize the host side of the mount, for example:

# Live might mount:
#   /opt/monitoring/tempo.yaml:/etc/tempo/tempo.yaml:ro
# Repository should resolve portably:
volumes:
  - ./tempo.yml:/etc/tempo/tempo.yaml:ro

The container-side target (/etc/tempo/tempo.yaml) must remain exactly what Tempo’s -config.file points to. Only the host side should be made repository-relative.

If the live Compose file uses env_file or secret files, sync their non-secret structure or provide documented placeholders. Never commit secret values.

4. Rebuild documentation from the live facts

Extract the actual Tempo service definition:

WORKDIR="$(docker inspect -f \
  '{{index .Config.Labels "com.docker.compose.project.working_dir"}}' "$CID")"
MAIN_COMPOSE="$(docker inspect -f \
  '{{index .Config.Labels "com.docker.compose.project.config_files"}}' "$CID" | cut -d, -f1)"

( cd "$WORKDIR" && docker compose -f "$MAIN_COMPOSE" config --format json ) \
  | jq '.services.tempo |
        {image, command, ports, volumes, environment, depends_on, networks}'

Extract the Tempo runtime settings:

python3 - tempo.yml <<'PY'
import sys, yaml
c = yaml.safe_load(open(sys.argv[1]))

def get(*keys):
    cur = c
    for key in keys:
        cur = cur.get(key, {}) if isinstance(cur, dict) else {}
    return cur or "not set"

print("http port   :", get("server", "http_listen_port"))
print("otlp grpc   :", get("distributor", "receivers", "otlp", "protocols", "grpc", "endpoint"))
print("otlp http   :", get("distributor", "receivers", "otlp", "protocols", "http", "endpoint"))
print("trace backend:", get("storage", "trace", "backend"))
PY

Update the README diagram using only components that actually exist. For a direct OTLP-to-Tempo deployment:

flowchart LR
    App[Applications / OTel SDKs]
    Tempo[Tempo]
    Store[(Trace storage)]
    Grafana[Grafana]

    App -->|OTLP gRPC :4317| Tempo
    App -->|OTLP HTTP :4318| Tempo
    Tempo -->|write blocks| Store
    Grafana -->|query :3200| Tempo
    Tempo -->|read blocks| Store

If an OpenTelemetry Collector exists in the live topology, insert it between the applications and Tempo. Do not add it just because it is common.

Update architecture.md with the same live values:

Ingest path
1. Applications/OTel SDKs send OTLP to Tempo on <actual endpoint/port>.
2. Tempo's distributor receives and validates spans.
3. Ingesters write trace blocks to <actual storage backend>.

Query path
1. Grafana queries the Tempo HTTP API on <actual port>.
2. Tempo's query components read blocks from <actual storage backend>.
3. Results are returned to Grafana.

Replace every angle-bracket value with the output from the extraction commands. Do not copy ports or backends from an older README.

5. Validate and commit

cd /path/to/repo

docker compose -f docker-compose.yml config -q

# Validate Tempo config with the same image version as the live container.
IMAGE="$(docker inspect -f '{{.Config.Image}}' "$CID")"
docker run --rm --entrypoint=/tempo \
  -v "$PWD/tempo.yml:/etc/tempo.yml:ro" \
  "$IMAGE" -config.file=/etc/tempo.yml -config.verify

git diff --check
git add docker-compose.yml tempo.yml README.md architecture.md
git diff --cached
git commit -m "monitoring: sync Tempo compose/config and docs from live host"

Verification

Run these checks after syncing and before pushing.

1. The committed Tempo config is byte-identical to the live file

docker cp "$CID:$CFG_PATH" /tmp/tempo.live.check
cmp /tmp/tempo.live.check tempo.yml && echo "tempo.yml matches live"

2. The committed Compose service matches the live service

docker compose -f docker-compose.yml config --format json \
  | jq -S '.services.tempo' > /tmp/repo-tempo.json

( cd "$WORKDIR" && docker compose -f "$MAIN_COMPOSE" config --format json ) \
  | jq -S '.services.tempo' > /tmp/live-tempo.json

diff -u /tmp/live-tempo.json /tmp/repo-tempo.json

Expected: no output. The only acceptable difference is a deliberately normalized host-side config path such as ./tempo.yml instead of /opt/monitoring/tempo.yml.

3. The repository Compose file is valid

docker compose -f docker-compose.yml config -q && echo "compose valid"

4. Tempo accepts the committed config

docker run --rm --entrypoint=/tempo \
  -v "$PWD/tempo.yml:/etc/tempo.yml:ro" \
  "$(docker inspect -f '{{.Config.Image}}' "$CID")" \
  -config.file=/etc/tempo.yml -config.verify && echo "tempo config valid"

5. Documentation contains the live version and endpoints

Check the image tag, Tempo HTTP port, and OTLP ports against README.md and architecture.md:

grep -RnsF -- "grafana/tempo:" README.md architecture.md
grep -RnsE -- '4317|4318|3200' README.md architecture.md

Every value shown in the docs must appear in either the live Compose definition or tempo.yml; no stale image tag, port, or storage backend should remain.

6. The running service is healthy and Git is clean

curl -fsS "http://<ip-address>:3200/ready" && echo
git status --porcelain

Expected: Tempo reports ready, and git status shows no uncommitted changes after the commit.
