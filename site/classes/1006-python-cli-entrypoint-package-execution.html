Answer

SOLUTION

Root cause. python -m src.ptp_cli failed because src/ptp_cli was a package (had src/ptp_cli/__init__.py), and a package is not directly executable: Python raises ModuleNotFoundError: No module named 'src.ptp_cli.__main__'; 'src.ptp_cli' is a package and cannot be directly executed. The old entry logic lived in a module-level if __name__ == "__main__": block inside src/ptp_cli.py, which is only reachable when the file is run as a script.

Fix. Make the package runnable by adding __main__.py that mirrors the module's original main block, keep a cheap __init__.py, and gate the two debug scripts (debug_screen, memory_reader) behind argparse so --help short-circuits before PyBoy is ever imported/booted.

1. Package entrypoint — src/ptp_cli/__main__.py

# src/ptp_cli/__main__.py
"""Entry point so `python -m src.ptp_cli` == `python src/ptp_cli.py`.

Mirrors the original module-level `if __name__ == "__main__":` block
byte-for-byte so both invocation styles behave identically.
"""
import sys

from src.ptp_cli.cli import build_parser, run

if __name__ == "__main__":
    sys.exit(run(build_parser().parse_args()))

2. Cheap package init — src/ptp_cli/__init__.py

# src/ptp_cli/__init__.py
"""ptp_cli package.

Must stay import-cheap: no PyBoy import at package import time.
Heavy dependencies load lazily inside run()/main().
"""

__version__ = "1.0.0"
__all__ = ["main"]

Also ensure src/__init__.py exists (empty) so -m src.ptp_cli resolves the src namespace.

3. CLI keeps its single source of truth — src/ptp_cli/cli.py

# src/ptp_cli/cli.py  (light imports only)
import argparse
import sys


def build_parser():
    p = argparse.ArgumentParser(prog="python -m src.ptp_cli")
    p.add_argument("--rom", required=False, help="Game Boy ROM path")
    p.add_argument("--frames", type=int, default=0, help="frames to emulate")
    return p


def run(args):
    if args.rom is None or args.frames <= 0:
        # --help already exited 0 in argparse; this handles no-op invocations
        # without ever importing PyBoy.
        print("Nothing to run. Pass --rom <file> --frames N.", file=sys.stderr)
        return 0
    from pyboy import PyBoy  # lazy: boot only on an explicit action

    with PyBoy(args.rom) as boy:
        for _ in range(args.frames):
            boy.tick()
    return 0


def main(argv=None):
    return run(build_parser().parse_args(argv))

4. Gated debug scripts — src/ptp_cli/debug_screen.py and src/ptp_cli/memory_reader.py

Same pattern in both; debug_screen shown:

# src/ptp_cli/debug_screen.py
import argparse


def build_parser():
    p = argparse.ArgumentParser(
        prog="python -m src.ptp_cli.debug_screen",
        description="Dump PPU screen state (requires PyBoy only when acting)",
    )
    p.add_argument("--rom", help="Game Boy ROM path")
    p.add_argument("--dump-frames", type=int, default=0, help="dump N frames")
    return p


def _run(argv=None):
    args = build_parser().parse_args(argv)
    if not args.rom or args.dump_frames <= 0:
        print("Nothing to do: pass --rom <file> --dump-frames N.", flush=True)
        return 0
    from pyboy import PyBoy  # lazy import — --help / no-op never boots PyBoy

    with PyBoy(args.rom) as boy:
        for i in range(args.dump_frames):
            boy.tick()
            print(f"frame {i}: {boy.screen.screen_buffer()[:16]}")
    return 0


main = _run  # module-level placeholder keeps unittest.mock.patch() working

if __name__ == "__main__":
    import sys

    sys.exit(main())

memory_reader.py is identical in shape (argparse gate → --read / --range action → lazy from pyboy import PyBoy → module-level main = _run).

Why the placeholder matters. Tests do @patch("src.ptp_cli.debug_screen.main"). Because main is bound at module level in a dependency-light module, the test imports the module instantly and the patch intercepts before any PyBoy import. Patching a function defined only inside another function (or patching pyboy after it was already imported at module scope) would either miss the call or force a slow PyBoy boot in every test.
