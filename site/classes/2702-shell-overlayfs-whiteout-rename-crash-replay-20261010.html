OverlayFS Whiteout/Rename Crash-Replay Checker

Problem class: shell-overlayfs-whiteout-rename-crash-replay-20261010 Environment / language: bash / shell

1. Symptom

A layered (OverlayFS-style) filesystem survives a power loss and returns with a namespace that looks plausible but is wrong:

  • a path that was renamed away reappears with its lower-layer contents ("lower-layer resurrection");
  • a copy-up changes the inode number of a file or directory;
  • recovery blindly replays the whole journal even though only a prefix of a transaction persisted;
  • or recovery refuses to start and cannot say which operations conflict.

The bug is not one corrupt byte; it is a missing durability constraint between operations that are individually valid.

2. Root-cause analysis

Operation Crash hazard
COPYUP Creates an upper copy. If it allocates a new inode instead of preserving the lower inode, inode identity is lost.
RENAME Moves an upper entry. If the old path is not left covered by a whiteout (file) or an opaque directory, the lower entry becomes visible again. A lower directory move is the dangerous case: children reappear too.
UNLINK / RMDIR Must leave a whiteout when the path exists in the lower layer, otherwise the lower entry resurrects.
OPAQUE Masks lower children of an upper directory; it only has meaning when an upper directory exists at that path.

The durability rule is the hard part: after a crash the persistent state is a prefix of the journal (torn tail). A correct checker must reconstruct the upper state for every prefix, decide whether the recovered metadata equals some prefix, verify inode identity and no-resurrection, and otherwise report a minimal conflicting set rather than failing opaquely.

Naive checkers fail either by validating ops one-at-a-time (missing the missing whiteout after a rename) or by computing the merged view per path without ancestor masking (showing /srv/x even though /srv is a whiteout).

3. The fix

overlayfs_replay.sh — dependency-free bash 4+.

Input format

[lower]
L file /etc/conf 10
L dir  /srv 20
L file /srv/x 21

[journal]
COPYUP /etc/conf 10
RENAME /etc/conf /etc/conf.new
UNLINK /etc/conf
FSYNC
COMMIT

[snapshot]
U file     /etc/conf.new 10
U whiteout /etc/conf

Ops: CREATE p ino, MKDIR p ino, COPYUP p ino, UNLINK p, RMDIR p, RENAME src dst, OPAQUE dir, REDIRECT dir t, FSYNC, COMMIT. Snapshot rows: U file p ino, U dir p ino [opaque] [redirect=t], U whiteout p.

Algorithm

  1. Parse into a flat op list; collect a universe of paths.
  2. Enumerate prefixes 0..N, capturing per-path tokens (NONE/W/F:ino/D:ino[:O][:R=t]).
  3. Reachability: snapshot legal iff some prefix tokenises identically.
  4. Minimal conflict: deletion-based MUS shrink → irreducible conflicting paths, plus every state each path can legally take.
  5. Replay + merged view with ancestor-aware masking (whiteout/opaque ancestors hide lower descendants).
  6. Safety: copy-up preserves inode; fresh create over a live lower inode preserves it or is preceded by whiteout/move; every rename source with lower content ends whiteout/opaque.

Exit codes

Code Meaning
0 REPLAY OK
3 CONFLICT (no prefix matches; core printed)
4 UNSAFE (prefix matches but identity/resurrection invariant broken)
2 parse/usage error
