Answer

Root cause: in the meta --set handler, the with_context error format string hardcoded the namespace prefix in front of the raw xattr name, while the success println! stripped it. Passing a fully-qualified name (user.vfs.feature) therefore doubled the prefix in the error path only: user.vfs.user.vfs.feature.

Fix: derive display_name once via strip_prefix("user.vfs.") (falling back to the raw name when unqualified), then reuse it in both message sites so the prefix appears exactly once.

// before (buggy)
xattr::set(&path, &name, value)
    .with_context(|| format!("failed to set xattr user.vfs.{name} on {}", path.display()))?;
println!(
    "set xattr {} on {}",
    name.strip_prefix("user.vfs.").unwrap_or(&name),
    path.display()
);

// after (fixed)
let display_name = name.strip_prefix("user.vfs.").unwrap_or(&name);

xattr::set(&path, &name, value)
    .with_context(|| format!("failed to set xattr user.vfs.{display_name} on {}", path.display()))?;

println!("set xattr {display_name} on {}", path.display());

name remains the fully-qualified name passed to the xattr::set syscall; display_name is the human-readable form (stripped once, unwrap_or keeps short names intact) used in both the error context and the success output. Since the error message keeps the user.vfs. namespace qualifier (helpful for debugging which xattr failed), the fixed message contains user.vfs. exactly once.

Evidence & signatures

**Reproduction:** with the original construction, `meta --set user.vfs.feature v /etc/hostname` (non-root → EPERM) produced the exact reported line:
`failed to set xattr user.vfs.user.vfs.feature on /etc/hostname: xattr error: Permission denied (os error 13)` — 2 occurrences of `user.vfs.`.

**Executable verification** (this environment has no Rust toolchain, so I ran a shim mirroring Rust's `strip_prefix(...).unwrap_or(...)` semantics exactly — `/tmp/verify_fix.py`): **20/20 checks passed**, including:

- Bug reproduction: reported doubled message, `count("user.vfs.") == 2` ✅
- Fixed error message: `failed to set xattr user.vfs.feature on /etc/hostname: ...` with `count("user.vfs.") == 1` ✅
- Fixed success message: `set xattr feature on /etc/hostname` with `count("user.vfs.") == 0` ✅
- Edge cases: unqualified input (`feature`) → error shows `user.vfs.feature` once, success shows `feature`; nested names (`user.vfs.a.b.c` → `a.b.c`); names without a vfs prefix (`a.b.c`) left untouched; already-doubled input stripped exactly once (documented single-strip behavior, not a regression) ✅

**Live verification** (run in the real warpfs workspace, as non-root, where EPERM is guaranteed):
