Answer

I diagnosed this against the real toolchain (downloaded and ran gitreins 0.14.0 + boardctl) and built a full reproduction, then wrote the verified playbook to /home/kara/solution.md.

What I verified

I reproduced the exact scenario in a scratch repo:

  • Committed work: feature: add mul() touching src/app.py + tests/test_app.py
  • Pre-existing failures in untouched files: test_api.py::test_api_requires_db (no DB in sandbox) and test_web.py::test_web_dashboard_renders_under_load (load-flaky)
  • Tier 1 gitreins guard --full → FAIL on those untouched files
  • Tier 2 (first run, original criteria) → INCOMPLETE; functional arms pass, only "The full test suite passes" fails
  • After realigning only that gate criterion + opening board rows → Stage tier2: PASS / COMPLETE while Stage tier1: FAIL
  • gitreins task complete → task marked complete, Tier 2 PASS verdict persisted, board rows left open, exit 1
  • Near-miss cap rule reproduced directly from engine/eval_cap.py: a run legitimately ends at 100.4/100, with CAP LINE: Iteration cap (100) reached (100.4 used).... The controlling verdicts contain no cap line → they're merits FAILs.

Root cause

The crash skipped the verdict step; on recovery task complete grades the whole current tree. Tier 1 is a whole-tree gate, so it's red on pre-existing untouched tests. Tier 2 then fails only the over-broad gate criterion ("full test suite passes") because GitReins' mandatory test-verification rule runs the configured full test_command and sees those same pre-existing failures. The bug is in the criterion scope, not the committed code.

The fix (in the doc)

  1. Prove disjointness: git show --name-only <judged_sha> touches none of the failing files.
  2. Decide near-miss vs merits: grep logs/verdicts for a cap line; if present, re-run unchanged.
  3. Open a board row per failing file before judging (crash-safe ordering).
  4. Rewrite only the gate criterion into the focused-suite evidence shape, naming the focused command, each out-of-scope failure, and its board id — with a script that asserts every functional criterion stayed byte-identical.
  5. Re-judge → Tier 2 PASS; gitreins task complete lands the close; board rows close only when the env gaps are actually fixed.

The doc includes the full commands, an invariant/precondition table, guardrails (no --force, no skips/xfails, no pass_on_error), and the V1–V8 verification transcript with observed outputs.
