Answer

Root cause. scripts/check_style.sh runs the repo's vendored scripts/cpplint --verbose=2 --root=src --extensions=h,hpp,cc,tcc over every *.h/*.hpp/*.cc/*.tcc under src/ (via parallel xargs), under set -eu -o pipefail. Any cpplint error therefore makes the pipeline fail and the script exit non-zero. Five fork-era files carried 7 pre-existing violations in three classes; the fix removes all 7 so the full-tree run exits 0.

Fix 1 — namespace using-directive → per-symbol using-declarations (build/namespaces)

using namespace ql; drags every ql symbol into scope. House style (already used elsewhere) is one using ql::symbol; per needed symbol:

// before: src/rdb_protocol/ql_bridge.cc
#include "rdb_protocol/datum.hpp"

using namespace ql;                      // cpplint: build/namespaces [5]

datum_t get_datum(env_t *env, ...) { ... }

// after
#include "rdb_protocol/datum.hpp"

using ql::datum_t;                       // per-symbol using-declaration (house: using ql::datum_t;)

datum_t get_datum(env_t *env, ...) { ... }

Only symbols actually referenced get a using-declaration; unused ones are dropped.

Fix 2 — explicit on single-arg ctor (runtime/explicit)

downsample_root_t(size_t factor) is callable with one argument and would permit implicit downsample_root_t x = 1024; conversions. Mark it explicit:

// before: src/rdb_protocol/downsample.hpp
struct downsample_root_t {
    downsample_root_t(size_t factor);    // cpplint: runtime/explicit [5]
    size_t factor_;
};

// after
struct downsample_root_t {
    explicit downsample_root_t(size_t factor);
    size_t factor_;
};

Fix 3 — %lu/static_cast<unsigned long> → %" PRIu64/static_cast<uint64_t> (runtime/int)

unsigned long trips runtime/int ("Use int16/int64/etc, rather than the C type long"), and %lu is a portability trap on LLP64 (Windows). Replace with the house pattern, which is verbatim at src/rdb_protocol/changefeed.cc:120:

// changefeed.cc:120 — house reference
std::string print(uint64_t i) {
    return strprintf("%" PRIu64, i);
}

// before: src/rdb_protocol/downsample.cc
#include <cstdio>
...
std::fprintf(stderr, "rows=%lu\n", static_cast<unsigned long>(n_rows));

// after
#include <inttypes.h>                    // PRIu64 (house pattern)
#include <cstdio>
...
std::fprintf(stderr, "rows=%" PRIu64 "\n", static_cast<uint64_t>(n_rows));

"%" PRIu64 string-concatenates to the correct 64-bit conversion specifier on every platform, and static_cast<uint64_t> both satisfies runtime/int and type-matches the format.
