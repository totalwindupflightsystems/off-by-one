Fixing shim-single-method-registration-flips-sibling-drift-class

Root cause

The drift checker compares declared OpenAPI operations with what the live router serves:

  • NOT-SERVED — no route exists for the path.
  • METHOD-MISSING — the path is registered, but that HTTP method is not handled.

Registering only one method of a multi-operation path makes the router own the entire path. For example, if only POST /widgets/{id} is registered, then GET /widgets/{id} and DELETE /widgets/{id} reach a method guard and return 405. Their drift class therefore flips from NOT-SERVED to the forbidden METHOD-MISSING.

TestNotImplementedTableMatchesDeclaredSurfaceArtifact forbids METHOD-MISSING, but it reads a generated artifact. The package-local suite stays green against the stale artifact; only the full suite fails after regeneration.

A second mux.HandleFunc on the same path-only pattern cannot fix this because Go's ServeMux panics on duplicate patterns. The path must be registered once, with one dispatcher for all declared methods.

Fix

1. Serve every declared method from one dispatcher

Replace single-method registration with one path registration and a method table:

// One registration per pattern. Never call HandleFunc twice with the same pattern.
func (s *Server) registerWidgetItem(mux *http.ServeMux) {
    registerOperations(mux, "/v1/widgets/{id}", map[string]http.HandlerFunc{
        http.MethodGet:    s.listWidget,   // declared: list
        http.MethodDelete: s.removeWidget, // declared: remove (previously missing)
    })
}

func registerOperations(mux *http.ServeMux, pattern string, ops map[string]http.HandlerFunc) {
    methods := make([]string, 0, len(ops))
    for method := range ops {
        methods = append(methods, method)
    }
    sort.Strings(methods)
    allow := strings.Join(methods, ", ")

    mux.HandleFunc(pattern, func(w http.ResponseWriter, r *http.Request) {
        handler, ok := ops[r.Method]
        if !ok {
            w.Header().Set("Allow", allow)
            http.Error(w, http.StatusText(http.StatusMethodNotAllowed), http.StatusMethodNotAllowed)
            return
        }
        handler(w, r)
    })
}

If the path declares more methods, add them to the same map. If a declared method is currently a shim, register the shim there so it is still considered served rather than METHOD-MISSING.

2. Rewrite the earlier method-guard test

The old test asserted that sibling declared methods were rejected. That is now wrong because those methods are served. Keep only the undeclared-method guard.

Before, conceptually:

for _, method := range []string{http.MethodGet, http.MethodDelete, http.MethodPut} {
    // expect 405
}

After:

func TestWidgetItemRejectsUndeclaredMethod(t *testing.T) {
    // Pick a method that is not declared anywhere on this path item.
    // Do not use GET/DELETE here: they are now valid operations.
    req := httptest.NewRequest(http.MethodPatch, "/v1/widgets/42", nil)
    rr := httptest.NewRecorder()

    newTestMux(t).ServeHTTP(rr, req)

    if rr.Code != http.StatusMethodNotAllowed {
        t.Fatalf("PATCH: got %d, want %d", rr.Code, http.StatusMethodNotAllowed)
    }
    if got, want := rr.Header().Get("Allow"), "DELETE, GET"; got != want {
        t.Fatalf("Allow = %q, want %q", got, want)
    }
}

Use a different method if the OpenAPI document declares PATCH. The test should assert only the undeclared-method 405, not rejection of declared operations.

3. Regenerate the artifact only after the code change

Locate the generator if it is not already known:

rg -n 'NotImplementedTableMatchesDeclaredSurfaceArtifact|METHOD-MISSING|NOT-SERVED' --glob '*.go'
rg -n 'go:generate' --glob '*.go'
rg -n 'declared.?surface|not.?implemented|artifact' Makefile* .github 2>/dev/null

Then run the repository's artifact generator. Common forms are:

go generate ./...
# or, if the repository exposes a make target:
make generate
# or the explicit generator found above, for example:
go run ./cmd/<artifact-generator> -write

Do not regenerate against the old single-method registration.

4. Format and verify

gofmt -w .
go test -short ./...
go test ./...

The full repository run is essential because the package-local suite can pass against a stale artifact.

Verification

The mechanism is reproducible with Go's net/http:

  1. A path with only POST registered returns 405 for GET and DELETE — the METHOD-MISSING signal.
  2. Registering both GET and DELETE in one dispatcher makes those operations succeed and leaves only an undeclared method returning 405.
  3. A second HandleFunc on the same path-only pattern panics with a duplicate-pattern panic.

For the affected repository:

# Artifact test must pass after regeneration.
go test -short -run TestNotImplementedTableMatchesDeclaredSurfaceArtifact ./... -v

# Full suite catches the live-vs-artifact mismatch.
go test -short ./...

Expected result for the reported tick:

  • Previously METHOD-MISSING sibling operations become COVERED.
  • METHOD-MISSING entries for that path are eliminated.
  • Covered operations go from 114 to 118; drift goes from 54 to 50.
  • The rewritten method-guard test still returns 405 for the undeclared method with an accurate Allow header.
