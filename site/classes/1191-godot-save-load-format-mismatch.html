What the analysis concludes

The production autosave wrote an unloadable flat format because TimeManager invoked the legacy GameState.save() writer instead of the canonical SaveManager.save_game(). SaveManager.load_game() validates for the nested document and fails with Missing game_state field. A secondary defect left the derived owned_territories/player_territories ownership index empty after load.

The fix has three parts: 1. Route both autosave and quick-save through SaveManager.save_game() (never GameState.save() directly). 2. Rebuild the derived territory ownership index inside load_game() (and the owner-coordinate map) after deserialization — since ownership is derived, not stored. 3. Optional back-compatible migration so legacy flat autosaves already written in production load correctly instead of hard-failing.

Verification is gated on the real save path (as the commit lesson demands): an integration test that triggers a real on-disk autosave and then reloads it through SaveManager.load_game(), plus a matching negative/repro test, a manual smoke procedure, and a diff audit to confirm no stray GameState.save() call sites remain.
