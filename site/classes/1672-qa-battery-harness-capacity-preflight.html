Fix: bunker-qa.sh capacity preflight (qa-battery-harness-capacity-preflight)

File: ~/.hermes/scripts/bunker-qa.sh · Judge: d954d2e6 · Landed: 2026-09-15

Root-cause analysis

run_battery calls spawn_agent and retries up to 3× on failure. Bunkerd owns a finite, deterministic port-range pool (port_range_start=30000, port_range_end=30999, port_range_per_agent=100, max_agents=20). Once every range is leased, allocation fails with the same "no free port ranges" error on every attempt, so the 3× retry adds no resilience — it only burns the tick timeout, emits N duplicate FAIL rows for one deterministic condition, and makes a full pool look like a flaky harness. The harness never asked bunkerd for capacity before spawning; bunker status already reports Agents:N/MAX.

Exact fix

1. Add the preflight helper (top of bunker-qa.sh)

# ---------------------------------------------------------------------------
# Capacity preflight (qa-battery-harness-capacity-preflight, judge d954d2e6)
# Bunkerd's port-range pool is finite/deterministic. Once Agents == MAX every
# spawn fails identically, so retrying is pointless. Fail fast instead.
# ---------------------------------------------------------------------------
BUNKER_QA_SKIP_PREFLIGHT="${BUNKER_QA_SKIP_PREFLIGHT:-0}"

# Adapter: replace with the script's existing evidence writer.
# Signature: <STATUS> <check> <detail>.
_qa_evidence() {
  printf '%s\t%s\t%s\n' "$1" "$2" "$3" >>"${QA_EVIDENCE_FILE:-/dev/stdout}"
}

# 0 = room to spawn. 1 = capacity unknown (warn + proceed, non-fatal).
# Exits 2 when the pool is exhausted (no spawn attempted).
preflight_bunker_capacity() {
  if [[ "$BUNKER_QA_SKIP_PREFLIGHT" == "1" ]]; then
    return 0
  fi

  local status used max
  if ! status="$(bunker status 2>/dev/null)"; then
    printf 'WARN: PREFLIGHT: cannot query bunker status; proceeding with spawn\n' >&2
    return 1
  fi

  # Accept "Agents: 3/20", "Agents:3/20", tabs, etc.
  if [[ "$status" =~ Agents:[[:space:]]*([0-9]+)[[:space:]]*/[[:space:]]*([0-9]+) ]]; then
    used="${BASH_REMATCH[1]}"
    max="${BASH_REMATCH[2]}"
  else
    printf 'WARN: PREFLIGHT: bunker status has no "Agents:N/MAX" capacity field; proceeding with spawn\n' >&2
    return 1
  fi

  if (( used >= max )); then
    _qa_evidence "FAIL" "preflight" "bunker capacity exhausted (Agents:${used}/${max})"
    printf 'PREFLIGHT FAIL: bunker capacity exhausted (Agents:%s/%s), no spawn attempted\n' "$used" "$max" >&2
    exit 2
  fi

  return 0
}

2. Call it at the top of spawn_agent

spawn_agent() {
  # unknown capacity (return 1) is advisory only; never abort on it
  preflight_bunker_capacity || true

  # ... existing spawn/retry body unchanged ...
}

exit 2 propagates out of run_battery's retry loop, so exactly one attempt is observed and no spawn is issued. Keep it on the main shell path (not inside $(...)/a pipeline), or only the subshell exits.

3. Bypass

BUNKER_QA_SKIP_PREFLIGHT=1 ./bunker-qa.sh run_battery ...

Edge cases

  • Regex tolerates whitespace around : and / (Agents: 3/20 and Agents:3/20).
  • Uses >=: at Agents:20/20 the next allocation is the one that would fail, so it's blocked before it's attempted.
  • Unknown/absent field or a failed bunker status is non-fatal (return 1 + warn), preserving compatibility with bunkerd versions that don't expose the field.
  • Preflight runs per spawn (not once in run_battery) so mid-run pool exhaustion is caught at the point of use.
