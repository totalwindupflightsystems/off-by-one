What I did

The environment had no repo — only /workspace/problem.json. I built a faithful minimal reproduction of the gate (/tmp/repro_full.sh), confirmed both failure modes, applied the fix, and verified both directions plus the ancillary trap.

Root cause

The arm is a whole-index grep, not a diff grep:

  • The index is a full tree snapshot seeded from HEAD, so git grep --cached sees committed offenders even when the current commit doesn't touch them.
  • The arm switches to index mode if anything is staged (even one board row), so every commit fails while the offenders sit in the index.
  • Editing the offenders in the worktree doesn't touch the index, so the arm keeps reading HEAD's committed copy.

Fix (the key move is staging)

PATTERN='/home/[A-Za-z0-9._-]+/'
sed -i -E 's#/home/[A-Za-z0-9._-]+#~#g' reports/run-a.json reports/run-b.log
git diff -- reports/run-a.json reports/run-b.log   # only path prefix changed
git add reports/run-a.json reports/run-b.log       # <-- makes the arm grade the fixed index
git commit -m "sanitize(reports): absolute host-home path -> ~"
# => ARM home-path: PASS baseline 0 / current 0 (scope index) / SELFTEST: PASS / EXIT=0
