What I did

Diagnosed (A) the tier-2 hang and (B) the boardctl evidence-id refusals, then reproduced the boardctl format rules against the installed boardctl v0.4.0 binary in a scratch git repo.

Key findings (empirically verified)

Attempt Result
--evidence-artifact w/o fingerprint --evidence-artifact requires --evidence-fingerprint
--evidence-fingerprint sha256:<64hex> must be exactly 64 hexadecimal characters
--evidence-run-id 2026-11-15/15dc1bed must name a directory under .gitreins/history/
--evidence-run-id 15dc1bed (bare leaf dir exists) accepted
bare 64-hex digest + bare run-id + artifact accepted, recorded as detail.evidence[].run_id + tree_fp

I also confirmed via the binary's disassembly that boardctl normalizes the run-id with filepath.Base(id) (so any / is rejected) and that the "is not an existing directory" refusal is the existence probe against .gitreins/history/<date>/<run>/.

Root causes

  • A: tier-2 runs inline with no timeout/cancellation and writes usage.jsonl/verdict.json only on success → non-resumable; async only moves the same unbounded call to a worker whose heartbeat is liveness-only. Kill via the pid in the job JSON.
  • B: boardctl wants the storage identifiers — bare leaf run-dir name and bare 64-hex digest — not a date/run display path, tick id, or sha256:-prefixed hash. The artifact⇒fingerprint⇒run-id chain is coupled.
  • Also documented the gate scope: nothing guardable staged trap: the tier-1 PASS skips build/lint/test on a clean tree.

The doc includes the exact kill/judge/hash/update runbook plus a verification section with the reproduced transcripts and post-close-out checks.
