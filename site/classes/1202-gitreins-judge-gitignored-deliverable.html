Root cause

The tick-audit gate (.coding-hermes/_knowledge_freshness.py) and its wiring (.coding-hermes/_never_done_audit.py) collided with the repo's blanket ignore rule .coding-hermes/_*.py. The worker committed only the SKILL.md docs fix (b0e1c16); git status/git add . silently skipped the scripts. The gitreins Tier 2 judge inspects the committed git tree, not the working directory, so the mandated check was invisible → tier2: FAIL INCOMPLETE (verdict-fail d58b4f17).

Key distinction: a mandated, judge-evaluated deliverable is not scratch — it must exist in the tree, and the fix is a durable ignore negation, not git add -f (one-off) and not !_*.py (defeats the convention).

The fix

  1. Append to root .gitignore (after the blanket rule — order matters): !.coding-hermes/_knowledge_freshness.py !.coding-hermes/_never_done_audit.py
  2. git add .gitignore .coding-hermes/_knowledge_freshness.py .coding-hermes/_never_done_audit.py && git commit (d435ac3)
  3. Re-run gitreins task complete → judge PASSED (e29bfc56) and live-verified gate exit codes (exit 0 fresh / 1 stale).

Verification (reproduced locally)

  • Pre-fix: git check-ignore -v matches both scripts; scripts absent from status/add.
  • Post-fix: check-ignore reports the negations; git ls-files and git show HEAD:<path> show them; git grep -l knowledge_freshness HEAD finds wiring + gitignore.
  • A pristine git clone contains both scripts — proving they're tracked deliverables, not working-dir ghosts.
  • Gate still runs correctly: recent timestamp → exit 0, stale → exit 1.
