The full document:

Fix: CI cold pnpm run build fails with Cannot find module '@mafia/shared/types'

Symptom

  • CI runs pnpm run build (root script → turbo run build) on a cold checkout and fails with: @mafia/consumer:build: src/index.ts(1,26): error TS2307: Cannot find module '@mafia/shared/types' or its corresponding type declarations.
  • The same build passes locally because packages/shared/dist already exists and/or the turbo cache is warm.

Root cause

The consuming package compiles against a sibling workspace package's build output via TypeScript paths, but does not declare that package as a dependency:

// packages/consumer/tsconfig.json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@mafia/shared/types": ["../shared/dist/types"],
      "@mafia/shared":       ["../shared/dist/index"]
    }
  }
}

// packages/consumer/package.json  (BUG)
{
  "name": "@mafia/consumer",
  "scripts": { "build": "tsc -p tsconfig.json" }
  // ❌ no "@mafia/shared" dependency
}

Turbo builds its task graph from the package dependency graph (package.json), not from tsconfig.json paths. With no dependency, turbo schedules @mafia/shared#build and @mafia/consumer#build in parallel. On a cold machine packages/shared/dist doesn't exist yet, so the consumer's tsc resolves the alias to a nonexistent .d.ts → TS2307. Locally stale dist/ or a warm turbo cache masks the race. Turbo's ^build only enforces ordering when the dependency is declared.

The fix

Declare the workspace package in the consuming package's package.json (workspace:*, mirroring sibling packages), then run pnpm install and commit both files:

// packages/consumer/package.json  (FIXED)
{
  "name": "@mafia/consumer",
  "scripts": { "build": "tsc -p tsconfig.json" },
  "dependencies": {
    "@mafia/shared": "workspace:*"
  }
}

# from the repo root
pnpm install          # updates pnpm-lock.yaml (adds the workspace link)
git add packages/consumer/package.json pnpm-lock.yaml

The lockfile gains:

  packages/consumer:
    dependencies:
      '@mafia/shared':
        specifier: workspace:*
        version: link:../shared

Finding every affected package:

rg -n '"@[^"]+":\s*\[\s*"\.\./[^/]+/dist' --glob 'tsconfig*.json' packages
for f in packages/*/package.json; do echo "== $f"; rg -n 'workspace:' "$f" || echo "   (no workspace deps)"; done

Verification (from repo root)

  1. Turbo knows the edge bash pnpm exec turbo run build --dry=json | node -e ' const g = JSON.parse(require("fs").readFileSync(0, "utf8")); for (const t of g.tasks) console.log(t.taskId, "deps=" + JSON.stringify(t.dependencies)); ' Before: both deps=[] → After: @mafia/consumer#build deps=["@mafia/shared#build"]

  2. Cold forced build bash rm -rf packages/*/dist packages/*/.turbo .turbo node_modules/.cache/turbo pnpm exec turbo run build --force; echo "exit=$?" # exit=0

  3. Exact CI command, fully cold bash rm -rf packages/*/dist packages/*/.turbo .turbo node_modules/.cache/turbo pnpm run build; echo "exit=$?" # exit=0

Pitfalls

  • Warm turbo cache / lingering dist/ masks the bug. Always delete packages/*/dist, .turbo/packages/*/.turbo, node_modules/.cache/turbo. --force bypasses cache but does not remove stale dist/.
  • tsconfig paths do not create turbo edges — only declared package.json dependencies do.
  • Commit the lockfile, or pnpm install --frozen-lockfile in CI fails before the build.
  • CI remote cache can hide the problem on re-runs; prove with a cold cache.
  • Longer term, TypeScript project references (composite/references) encode the type ordering too, but the turbo edge still requires the package dependency.
