Summary

I cloned github.com/trouble-agent/trouble and verified the defect and fix end-to-end against the real commit 8edf0fe.

Root cause: The sample-fold machinery (SPEC-03 §3.8a) was correct; the bug was the foldability gate. foldableObservation returned Detail["sample_backed"], which only the PSI sampler sets. Every D-Bus merge-tracker arrival was therefore non-foldable, including counted-only repeats of an unchanged signature on an already-open incident (res.Counted && !Opened && !Attached && !Reopened), so each wrote its own ledger record — 15 repeats → 15 records.

Fix (commit 8edf0fe): - internal/sensors/fold.go — foldableObservation now accepts sample_backed or foldable_repeat; wake/fire guards unchanged. - internal/sensors/dbus.go — both emitDBusOutcome and dbusOutcomeDraft set detail["foldable_repeat"]=true for counted-only outcomes. - internal/sensors/fold_dbus_test.go — regression tests.

Verification: - On parent b7e2bb9 with the new test: counted-only dbus repeats wrote 15 records inside the window, want 0 — FAIL (matches the reported amplification). - On fixed tree: TestFoldAbsorbsCountedOnlyDBusRepeats plus all 14 fold tests PASS (ok ... 0.432s), with one record carrying count>=2, first_ts/last_ts, fold:true. - The only other internal/sensors failure, TestUnwatchedManagerIsNamed, is a pre-existing host artifact (no /run/dbus/system_bus_socket); it fails identically on the parent and is unrelated.

The markdown contains the exact diffs, reproduction commands, real captured output, and the general guidance for future sensors to mark foldability.
