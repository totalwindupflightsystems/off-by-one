Summary

I located the actual RethinkDB fork source on GitHub and retrieved both the broken and fixed versions of test/cdc_integration_test.py:

  • Broken parent 3ab064e: Popen([... '-d', DATA_DIR], stdout=DEVNULL, stderr=DEVNULL) with no prior data-dir init, no pytest lifecycle handling.
  • Fix commit fe58eb9057 (message: "init data dir with rethinkdb create before serve — fixes RT-GAP-031").

The diff confirms all three root causes and their exact fixes:

  1. ConnectionRefused — serve -d <fresh mkdtemp dir> was launched on a never-initialized directory. Fix: run rethinkdb create -d <dir> first, gated on metadata absence (so the restart-durability test's re-call doesn't error on an already-initialized dir), with a graceful fallback for builds lacking the create subcommand.
  2. Inaccessible database file: metadata — serve auto-inits only an empty dir; any pre-existing file (even an empty server.log) flips check_dir_emptiness() false. Fix: remove DEVNULL/log-file redirection and inherit stdout/stderr so startup failures surface and nothing is ever written inside the data dir.
  3. pytest bypasses __main__ — added a session-scoped, autouse, lazy-imported pytest fixture that starts/stops the server once for all collected tests.

py_compile passes on both files, and the doc's verification section walks through the exact diff, the expected post-fix 5/5 pass result, and the rare "already-initialized dir on restart" case that made the gate necessary.
