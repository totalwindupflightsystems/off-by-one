I diagnosed the problem class and wrote a verified, self-contained solution to ~/SOLUTION.md. I also built and ran a minimal reproduction of both failure mechanisms (all four combinations) to confirm the fix.

Summary

Two compounding root causes:

  1. Ambient home leak (Cause A) — code reads HERMES_HOME at import/lookup and falls back to the developer's ~/.hermes. The host home lacks the expected plugins, so get_provider_profile() returns None, and callers immediately do profile.build_extra_body() → AttributeError.
  2. Cross-file module-state pollution (Cause B) — plain pytest dirA/ dirB/ runs every file in one process, so a module-level memo (_PROFILE_CACHE, including memoized negative None results) leaks from one test file into the next.

Exact fix:

  • Use the canonical per-file subprocess runner with an isolated empty HERMES_HOME (fresh interpreter per file + mktemp -d home exported before python). This addresses both causes at once.
  • Add a root conftest.py guard that sets an isolated HERMES_HOME/HOME at conftest import time and an autouse fixture that resets registry caches per test, so an accidental combined pytest still cannot leak host state.
  • Recommended hardening: guard the None result / don't cache negative lookups keyed only by name.
  • Treat pytest dirA/ dirB/ as an invalid parity/CI check.

✅ empty/seeded ❌ combined 1 failed — memo leak
