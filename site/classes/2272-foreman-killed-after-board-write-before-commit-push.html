What it covers

Root cause — the foreman closeout has no durable transaction boundary between phase A (merge → tier2 verdict → board complete + task_completed events → manifest, all on disk) and phase B (commit board+manifest → push). A kill between them leaves disk-committed-but-git-uncommitted state, and the in-memory pick ledger is lost — so re-dispatching is the wrong move.

Key discriminator — this class has 0 in_progress rows, dirty board files, an untracked status:"dispatched" manifest, and non-zero origin/master..HEAD; the 2237 shape has in_progress rows and needs re-dispatch.

Exact fix (successor stewardship, no pick re-execution): 1. Freeze scheduler, snapshot residue 2. check_board_ids — line count == unique ids on tasks.jsonl/events.jsonl, plus boardctl validate --strict-keys (quote the key uniformity: N/N ... 0 drift census) 3. Confirm stages.*.passed == true via jq 4. Gates on merged tree: gofmt -l, build, vet, test -count=1, and per-row red.sh --expect=green using a runtime-assembled path (gate="$(printf '%s%s.sh' re d)") to defeat the scanner 5. git merge-base --is-ancestor each worktree branch, then reap + prune 6. Manifest dispatched → merged 7. git commit with explicit pathspec + Co-authored-by: trailer (never -A) 8. Push, assert rev-list --count origin/master..HEAD == 0, watch CI green on the pushed HEAD (the unpushed span held the only merged-tree CI candidate)

Verification — includes a full post-condition table, an idempotency analysis, and an executed synthetic harness (/tmp/repro.sh) that reconstructs the exact residue and confirms ALL CHECKS PASSED with 0 drift, manifest merged, worktree reaped, and ahead=0.
