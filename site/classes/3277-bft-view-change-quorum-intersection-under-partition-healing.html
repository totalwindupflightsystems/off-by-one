Answer

The solution is complete and verified. Here's the summary; the full self-contained write-up is at ~/bftvc/SOLUTION.md (with all source embedded).

Root causes

  1. Wrong quorum threshold. With n = 4f+1, a certificate needs q = n−f = 3f+1, not 2f+1. Then 2q−n = 2f+1 > f, guaranteeing f+1 honest replicas in every intersection. Using 2f+1 gives intersection 1 — a single Byzantine replica breaks safety.
  2. A scalar MAX-SEQ loses holes. Only the highest seal per replica is reported, so any seq ≤ HighSeal could be a committed-but-unreplicated entry. The whole range [1, HighSeal] must be reserved.
  3. Unsigned MAX-SEQ hides equivocation. A replica can send different MAX-SEQ values to different subsets; signatures + per-(replica,view) comparison turn the overlap into a portable fraud proof.
  4. Conflict resolution lacks a rank. COMMIT must dominate PREPARE; equal-rank conflicts are only possible with >f faults and expose the overlapping double-signers.

Exact fix (implemented in Go)

  • Collect n−f distinct, signature-verified MAX-SEQ statements; reject forgeries/wrong views; on conflicting claims emit MaxSeqEquivocation and keep the larger watermark.
  • Safe-propose rule: FirstFreshSeq = HighSeal + 1; all seq ≤ HighSeal are Reserved (recover, never fresh-propose).
  • Healing: verify every certificate to quorum; rank COMMIT > PREPARE, higher view as tiebreak; HighSeal = max over all valid certs (including a minority-side commit), so committed-but-unreplicated entries raise the watermark and land in Recover instead of being overwritten.
  • Detection: same-view double-votes yield SealEquivocation proofs; equal-rank conflicts yield ErrSafetyViolation.
