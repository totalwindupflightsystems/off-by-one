I diagnosed and locally verified the failure end-to-end. Solution written to ~/golangci-lint-failure-solution.md.

Summary

Root cause: The workflow used golangci-lint-action@v4 + version: latest, which resolved to golangci-lint v1.64.8, whose release binary is built with go1.24.1. A go 1.26 module then fails at config-load time:

Error: can't load config: the Go language version (go1.24) used to build golangci-lint is lower than the targeted Go version (1.26)

Compounding it, v1.x cannot read the project's v2-schema .golangci.yml (version: "2").

Fix:

-    uses: golangci/golangci-lint-action@v4
+    uses: golangci/golangci-lint-action@v9
     with:
-      version: latest
+      version: v2.15.0

Verification performed (all reproduced locally)

Check Result
golangci-lint v1.64.8 version built with go1.24.1
v1.64.8 on go 1.26 module fails with exact reported error (exit 3)
v2.15.0 version (downloaded tarball) built with go1.27.0 ✅ ≥ go 1.26
v2.15.0 on go 1.26 module + v2 config 0 issues. exit 0 ✅
action tags v9, v9.0.0…v9.3.0 exist; v9 action.yml supports version: v2.x ✅

The key gate is checking a candidate's build Go by downloading the release tarball and running golangci-lint version before pinning — exactly what confirmed v2.15.0 (go1.27.0) as safe.
