Answer

I diagnosed and verified the problem end-to-end. The full solution is written to /workspace/SOLUTION.md, with a runnable reproduction at /workspace/repro (pnpm workspace + turbo + vitest).

Root cause (confirmed empirically)

_project.yaml is a frontmatter file = two YAML documents. The two readers handle that differently:

Loader Call Result
Graph-DB YAML.parseDocument(raw).toJS() silently returns only doc #1 → id/name kept, branch/description/metadata dropped, no error
Service YAML.parse(raw) throws MULTIPLE_DOCS → wrapped as StorageError, project rejected

I reproduced the exact symptom before fixing: graph-DB assertion expected undefined to be 'main', service StorageError: Failed to load project, container logs Failed to auto-load project proj-regress1. Second bug: turbo runs scripts with cwd=packages/backend, so relative PROJECTS_PATH resolved to .../packages/backend/packages/backend/projects (nonexistent) instead of using TURBO_INVOCATION_DIR.

Fix

One shared splitter used by both loaders:

const FRONTMATTER_RE = /^\uFEFF?---\r?\n([\s\S]*?)\r?\n---(?:\r?\n|$)([\s\S]*)$/;

export function parseProjectManifest(raw: string, sourcePath?: string): ProjectManifest {
  const match = raw.match(FRONTMATTER_RE);
  let front: unknown;
  let body: Dict | undefined;
  if (match) { front = parseYaml(match[1]); body = tryParseMapping(match[2]); }
  else { front = parseYaml(raw); }
  if (!isPlainMapping(front)) throw new Error(/* not a mapping */);
  const merged = body ? Object.assign({}, front, body) : { ...front };
  if (typeof merged.id !== 'string') throw new Error(/* missing id */);
  return merged as ProjectManifest;
}

export function resolveProjectsRoot(env = process.env): string {
  const configured = env.PROJECTS_PATH ?? 'packages/backend/projects';
  if (isAbsolute(configured)) return configured;
  return resolve(env.TURBO_INVOCATION_DIR ?? process.cwd(), configured);
}

tryParseMapping wraps body parsing in try/catch and only merges when the body is a mapping, so prose bodies are tolerated. Both loadProjectFromGraphDatabase and loadProjectForService now just call parseProjectManifest(readFileSync(filePath,'utf8'), filePath).

Verification (all green)

  • Regression test seeds a frontmatter manifest, asserts Auto-loaded project: proj-regress1, no failure log, and asserts the body fields (branch/description/metadata) in list() — before fix: 3 failed | 8 passed; after: 11 passed.
  • Turbo path check: PROJECTS_PATH=packages/backend/projects turbo run check:root → cwd=/workspace/repro/packages/backend, TURBO_INVOCATION_DIR=/workspace/repro, resolved root correct, loaded projects=1.
  • Live HTTP check: server booted via turbo logs Auto-loaded project: proj-abcd1234; GET /api/projects → 200 with branch=main, description=..., metadata={"owner":"team-x",...}.

The write-up also lists the grep command to catch any remaining whole-file YAML reader and the pitfall checklist (must assert a body field, must patch both loaders, TURBO_INVOCATION_DIR not cwd).
