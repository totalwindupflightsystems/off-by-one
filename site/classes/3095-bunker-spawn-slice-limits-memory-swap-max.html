Answer

I diagnosed the issue and produced a verified solution. Here's a summary.

Diagnosis

The failure is host-side cgroup containment, not a client or CLI problem:

  1. bunkerd applies resource limits to the agent's user slice (user-<uid>.slice). The shipped standard/hardened tiers arm swap-bar containment (MemorySwapMax=0 → cgroup memory.swap.max).
  2. After writing the drop-in and systemctl daemon-reload, it runs a landing check that reads /sys/fs/cgroup/user.slice/user-<uid>.slice/memory.swap.max and requires exactly 0. If not, spawn fails at slice-limits and rolls back.
  3. On the broken host, nothing sets the bar:
  4. the deployed bunkerd 0.1.4 binary contains zero occurrences of MemorySwapMax (I verified with strings; all 9 /etc/systemd/system/user-*.slice.d/50-bunker.conf files are missing it), and
  5. the global template /etc/systemd/system/user-.slice.d/ only sets TasksMax, so user-<uid>.slice inherits memory.swap.max = max.

So the check wants 0, the cgroup says max, and every standard/hardened spawn fails deterministically.

Fix (in the doc)

  • Immediate host-side: a persistent [Slice] MemorySwapMax=0 drop-in at /etc/systemd/system/user-.slice.d/50-bunker-swap.conf (per-UID slices inherit the user-.slice template — confirmed via systemctl cat user-1000.slice), plus systemctl set-property --runtime for live agent slices and daemon-reload.
  • Durable: deploy a bunkerd that emits MemorySwapMax=0 in sliceContainmentKnobs and applies the drop-in before verifying (current main, INT-CI-37), with the 2s convergence budget.
  • Do not "fix" it with memory_swap_max_bytes: -1 or --preset open (weakens a real containment).

Verification performed

  • Ran the project's hermetic tests against cloned github.com/deployBunker/bunker (main, e8ffd59):
  • TestGAP118_TierTableMatchesMatrix → standard/hardened emit MemorySwapMax=0, open emits nothing.
  • TestINTCI37_SliceDropInBeforeLandingCheck → fixture starts at memory.swap.max=max, reproduces the exact fingerprint under the broken verify-before-apply order, passes with the fixed order.
  • TestINTCI37_LandingCheckBoundedConvergence, TestGAP118_SwapBarNeverOnOpen → PASS.
  • Documented on-host checks (systemctl show ... -p MemorySwapMax, live cgroup read), a probe-spawn procedure, and rollback/breadcrumb checks.
