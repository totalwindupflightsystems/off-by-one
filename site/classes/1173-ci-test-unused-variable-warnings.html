Key contents:

  1. Root cause — The CI RUSTFLAGS=-D warnings makes -D warningband unused-variables into a hard error. A new lib test declared let main = write_rust_crate(...) and never used the binding. Locally (no -D warnings) this is only a warning, so local cargo test passes; CI rejects it at compile time (exit 101).
  2. Exact fix — In hilo-graph/src/parser.rs (~line 1659), rename the binding to _main (or consume it): rust let _main = write_rust_crate(locx);
  3. Verification — Reproduce locally first, compile-only: bash RUSTFLAGS='-D warnings' cargo test --workspace --no-run This must go from a compile error to passing before you push; the CI run on the pushed commit is the final gate. The doc also includes a tiny standalone rustc repro of the same mechanism and a full-suite check command.

To apply and fully verify it, run it against the checked-out hilo 0.3.0 tree where the workflow and parser.rs live.
