Fix: Fail-loud root Vitest guard for a pnpm monorepo

Summary

A bare vitest run from the repository root collects unrelated suites: React/TSX unit tests from every package and Playwright *.spec.ts end-to-end specs. The supported test entry point is pnpm test, which runs each package's own Vitest config sequentially.

The fix is a dependency-free root vitest.config.ts that refuses the bare root invocation with a banner and exit code 1, while remaining harmless when Vitest walks up from a config-less package such as crm. This is intentionally the fail-loud option, not a root Vitest workspace/project.

Root cause

  • The root had no vitest.config.*, so Vitest 4.1.10 used its default include glob (**/*.{test,spec}.?(c|m)[jt]s?(x)) relative to the repository root. That glob matched package TSX tests plus Playwright specs, which do not run under Vitest (e.g. they import @playwright/test).
  • The correct behaviour is not a root test project. The monorepo's supported runner (pnpm test) executes package configs sequentially, and packages that have no config of their own (e.g. crm) must collect nothing.
  • Critical pitfall: Vitest resolves config by walking up the directory tree. From packages/crm, Vitest 4.1.10 finds and loads the root vitest.config.ts. Therefore an unconditional process.exit(1) in that file breaks crm (and any other config-less package). The refusal must be gated on process.cwd() actually matching the root config's directory; for any other cwd the config must export an empty test config (include: []).

Exact fix

1. Add vitest.config.ts at the repository root

The file uses only Node built-ins (no vitest, vite, or other dependency), because the workspace root may not have Vitest installed. It compares the realpath of the cwd against the realpath of the directory containing the config so pnpm symlinks do not defeat the gate.

// vitest.config.ts (repository root)
// ---------------------------------------------------------------------------
// Root Vitest guard config (dependency-free).
//
// Supported entry point:  pnpm test
//   -> runs every package's own Vitest config sequentially.
//
// Unsupported entry point: bare `vitest` from the repository root.
//   -> Vitest's default include glob would scan the whole monorepo and
//      miscollect React/TSX unit suites and Playwright `*.spec.ts` suites.
//
// This file makes the unsupported entry point fail loudly. It deliberately
// does NOT define a root test project/workspace.
//
// IMPORTANT (Vitest 4.1.10): a config-less package (for example `crm`)
// inherits this file by walking UP the directory tree. The refusal is
// therefore gated on the process cwd matching this config's directory. When
// loaded from a package cwd we export an empty test config instead, so the
// supported per-package runs are unaffected and can never inherit a
// monorepo-wide glob.
// ---------------------------------------------------------------------------

import { realpathSync } from 'node:fs'
import { dirname } from 'node:path'
import { fileURLToPath } from 'node:url'

const CONFIG_DIR = realpathSync(dirname(fileURLToPath(import.meta.url)))
const CWD = realpathSync(process.cwd())

if (CWD === CONFIG_DIR) {
  process.stderr.write(
    [
      '',
      '[vitest] Refusing to run from the repository root.',
      '',
      '  Bare `vitest` is not a supported entry point in this monorepo: its',
      '  default glob collects unrelated TSX and Playwright suites.',
      '',
      '  Run the supported runner instead:',
      '',
      '      pnpm test',
      '',
      '  It executes each package config sequentially.',
      '',
    ].join('\n'),
  )
  process.exit(1)
}

// Reached only when Vitest walks UP from a package directory (e.g. crm).
// Never contribute a workspace-wide test glob from here.
export default {
  test: {
    include: [],
  },
}

No other source changes are required. Do not add a root test script that calls vitest, and do not turn this into a root workspace — pnpm test already drives the package configs sequentially.

If the root package.json is CommonJS (no "type": "module"), Vite may log a warning about ESM syntax loaded as CJS. It is harmless, or you can silence it by renaming the file to vitest.config.mts or adding "type": "module" to the root package.json. The config content is identical.

Verification

All commands are run from the repository root unless noted. Check the real subprocess exit code (echo $?), not just the visible output.

1. Bare root invocation is refused (exit 1)

pnpm exec vitest run
echo "exit=$?"

# Expected: the banner is printed to stderr, no test files are collected,
# and exit=1.

Verified locally:

[vitest] Refusing to run from the repository root.
ROOT_BARE_EXIT=1

2. Config-less package does not inherit the refusal

crm has no vitest.config.*, so Vitest 4.1.10 walks up to the root config. With the cwd gate in place this must not print the refusal banner and must contribute an empty include set.

cd packages/crm
pnpm exec vitest run --passWithNoTests
echo "exit=$?"
cd ../..

# Expected: no "[vitest] Refusing..." banner, "No test files found",
# and exit=0.

Verified locally:

CRM_EXIT=0
No test files found, exiting with code 0

Regression check for the pitfall: temporarily replace the gate with a bare process.exit(1) and rerun step 2. It now fails (exit=1) with the banner, proving the process.cwd() gate is what keeps config-less packages working. Restore the gated version afterwards. Verified locally (CRM_WITH_UNCONDITIONAL_EXIT=1).

3. Supported runner is green

pnpm test
echo "exit=$?"

# Expected: sequential package configs run, "Test Files ... passed",
# "Tests  649 passed (649)" across the 9 packages, and exit=0.

4. Build and lint are unaffected

pnpm build
echo "build=$?"
pnpm lint
echo "lint=$?"

# Expected: build=0 and lint=0.

Minimal local reproduction used to validate this fix

A 3-package pnpm workspace (one package with its own config, a config-less crm package, and Playwright-looking *.spec.ts under e2e/) reproduces the behaviour exactly with vitest@4.1.10:

  • before the fix: bare root vitest run collected all three files and failed with Cannot find package '@playwright/test' (exit 1);
  • after the fix: bare root vitest run prints the banner and exits 1 without collecting anything;
  • cd packages/crm && vitest run --passWithNoTests prints no banner and exits 0;
  • the package with its own config still passes through the supported runner.

Why not a root workspace?

A root Vitest workspace/project would run something from the root, which is exactly the ambiguity that caused the bug. Package ownership of test configs is the contract here, so the root must refuse rather than aggregate. The guard keeps the failure explicit and the package runs untouched.
