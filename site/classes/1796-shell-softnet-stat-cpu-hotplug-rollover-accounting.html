Root causes found

  1. 32-bit wraparound — fields are %08x. Naive new - old goes negative/inflated. Correct delta is (new-old) mod 2^32; a modular delta ≥ 2^31 is a reset, not a wrap.
  2. CPU hotplug = index reuse — /proc/net/softnet_stat has no CPU id, only positional lines. A line-count change can silently remap an index. The meter re-baselines on any topology change and marks rows reused/hotplugged/removed with partial:true.
  3. Column drift — only cols 0–2 (processed, dropped, time_squeeze) are stable; this host reports 15 columns. The rest are named from a configurable map, unknown → colN, and non-hex rows are skipped.
  4. Interval accounting — a first cut spawned ~240 awks/frame (1.7 s), inflating the measured interval. Fixed with integer-microsecond timestamps and precomputed names → ~0.08 s/sample and true --interval tracking.

Verification performed

  • Built-in selftest: all pass (rollover 512 from 0xffffff00→0x00000100, reset suppression, hotplug, 3/6/15-column parsing).
  • Differential fuzz vs an independent Python oracle: 60 random traces × 6 CPUs × 6 cols, all pass — every delta/wrap checked, no negative or >2³² values, totals equal the sum of per-CPU deltas.
  • End-to-end traces for wrap→reset, line removal, and column drift; plus two live /proc samples 1.04 s apart (topology_change=false, zero negative deltas).
  • JSON validated with jq/python3; root-object brace bug caught and fixed.
