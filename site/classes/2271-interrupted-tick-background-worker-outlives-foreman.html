What the diagnosis says

The "ghost commit" was not a concurrent writer. The dead foreman dispatched a detached hermes chat -q … -Q run worker via terminal background=true. The gateway drain_timeout tore down the foreman but never reaped the detached child, which survived ~80 minutes, self-gated, and committed — landing the commit during the successor tick.

The four probes that prove authorship

  1. /tmp/*_worker*.log mtime == commit minute (/tmp/pulse005_worker.log).
  2. Worker's final report line carries its session_id (20260924_143551_bbc0dd).
  3. state.db messages for that session shows edit/commit activity ending at the commit time.
  4. ~2-min-earlier api_server sessions belong to other projects (per first user message), ruling out a parallel pulse tick.

If all four hold and no live competitor exists → ADOPT; otherwise freeze and escalate (never rebase/force).

The exact fix / stewardship contract

  1. Freeze evidence before any mutation.
  2. Enumerate surviving workers (live ps, /tmp log mtimes, state.db).
  3. Adjudicate ADOPT/COLLISION/INCONCLUSIVE.
  4. Adopt + independently re-verify: go build, go vet, gofmt -l, go test ./... -count=1, -race, gitleaks 0 leaks.
  5. Bookkeep: gitreins task complete … --tier1 real --tier2 COMPLETE --passed true.
  6. Surgical board closure (two-file, byte-exact dumper probes + single trailing-newline terminator check).
  7. Push + rev-list parity 0 + CI green.

  • bash -n triage-surviving-worker.sh → SYNTAX OK.
  • Smoke-tested the nearest-worker-log awk selector and the trailing-newline probe (single \n accepted; \n\n and missing \n rejected).

Preventive fix for the class: stop using background=true for tick dispatch; signal the worker's process group on drain; persist a tick journal (session_id/pgid/task/base commit); stamp commits with a Session: trailer; make /tmp log mtimes + state.db a quiescence gate; default to adopt-or-escalate, never overwrite.
