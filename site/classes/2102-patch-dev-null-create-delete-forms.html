Fixing toolsd patch for /dev/null create/delete unified-diff forms

Root cause

FilePatch had no operation discriminator and only one path. Every section went to applyEdit, which assumes both sides exist. /dev/null create/delete hunks have a zero-count side (@@ -0,0 +N,M @@ / @@ -N,M +0,0 @@), so the edit engine could not locate a region and refused the patch.

Exact fix

  1. Classify at +++: old == /dev/null → OpCreate; new == /dev/null → OpDelete; else OpEdit. Path is always the file side, never /dev/null.
  2. Dispatch in Apply before the edit machinery:
switch p.Op {
case OpCreate: return applyCreate(p)
case OpDelete: return applyDelete(p, base)
case OpEdit:   return applyEdit(p, base)
}
  1. Create builds content from + lines; a parser-recorded MarkerAfterLastPlus flag (a \ No newline at end of file after the last +) removes the trailing newline.
  2. Delete reconstructs context/removals, requires an exact byte match, and returns []byte{}.
  3. Parser count rule (context+removals == OldCount, context+additions == NewCount) already makes a removal-in-create / addition-in-delete unparseable; applyCreate/applyDelete re-check so hand-built FilePatch values are refused at Apply.
  4. Atomicity: CLI refuses create-onto-existing; new multifile Transaction.StageRemove runs removals after writes, snapshots every touched path for byte-identical rollback, and fsyncs removal dirs too.

Key branch:

func applyDelete(p FilePatch, base []byte) ([]byte, error) {
    var b strings.Builder
    for _, h := range p.Hunks {
        if h.NewCount != 0 {
            return nil, fmt.Errorf("delete %s: hunk claims new-side content", p.Path)
        }
        for _, l := range h.Lines {
            if l.Kind == LineAdd {
                return nil, fmt.Errorf("delete %s: addition in delete patch", p.Path)
            }
            b.WriteString(l.Text); b.WriteByte('\n')
        }
    }
    if !equalBytes([]byte(b.String()), base) {
        return nil, fmt.Errorf("delete %s: context/removals do not match", p.Path)
    }
    return []byte{}, nil
}
