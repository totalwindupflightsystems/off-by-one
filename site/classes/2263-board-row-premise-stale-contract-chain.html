Root cause (short)

  1. Board rows are historical snapshots; their implicit premise ("feature absent") is never re-checked against the moving tree.
  2. Dispatch goes row → worker with no premise-verification gate.
  3. Discovery's not_found (the cfg-admission / unparam-cascade cases) failed open instead of blocking.
  4. No standard, auditable closure path for already-delivered rows.

Fix (short)

Gate every row before dispatch: - delivered (0) → close verified-no-op / GAP-054; commit_hash = HEAD, code_commit = null, in-repo-fact criteria. - not_delivered (1) → dispatch. - not_found (3) → block and route to premise repair (fixes the observed leak). - regressed (4) → regression triage (built then removed ≠ never built).

Verification performed

All four states reproduced and confirmed on a throwaway git repo:

Case Status Exit

new symbol, path valid not_delivered 1
src/unparam/ absent not_found 3
removed after being added regressed 4

Closure emitted "class":"GAP-054", "code_commit":null, "commit_hash":"<HEAD>"; the closure script refuses non-delivered inputs. Both scripts pass bash -n.
