Root cause

  1. set -e treats rsync's exit 24 ("vanished source files" — benign, normal on busy trees) as fatal → rotation aborted.
  2. --delete ran against the live snapshot tree; a retry after an interrupted run deleted the only intact copy.
  3. Rotate step was unsynchronized → concurrent runs interleaved.

The fix (three structural guarantees)

  • Exit-code classification: rsync ... || rc=$? (the OR-list is what set -e can't kill before inspection). 0 and 24 → proceed; 11/12/23/25 and everything else → fatal, nothing published, previous snapshot kept. Real errors are never masked.
  • Stage → verify → atomic publish: transfer (with --delete) only ever targets .staging; publish happens only after a successful transfer via one atomic mv (rename) + one atomic symlink swap of latest. The previous snapshot is used purely read-only as --link-dest (cheap hardlinks). Any failure discards staging via an EXIT trap.
  • flock mutex with timeout (flock -w $LOCK_TIMEOUT on fd 9) held for the whole run, so transfer and rotate can never interleave; a blocked invocation times out and exits 1.

Verification (56/56 pass, real toolchain)

  • Raw reproduction confirmed real rsync exits 24 with "file has vanished" messages when files are deleted mid-transfer.
  • T1 exit-code matrix: 0/24 publish; 23/11/12/1 exit with that code, no publish, previous snapshot byte-identical. T2 SIGKILL mid-transfer: previous snapshot intact, stale staging discarded on rerun. T3 two concurrent runs: serialized, lock-ordering verified. T4 lock timeout: exits 1, publishes nothing. T5 real rsync + 3 files deleted mid-run: exit 24 tolerated, every surviving file byte-identical in the new snapshot. T6 delete isolation: deleted source file absent from new snapshot while the old snapshot retains it.

The tests also caught and the fix addresses two latent bugs: same-second snapshot-name collisions (would nest a snapshot inside the previous one via mv semantics — now guarded with -NN suffixes) and retention pruning that kept the oldest N instead of the newest (now sort -zr); plus --max-delete as the tripwire against a momentarily empty source becoming a mass deletion.
