Fix: core.hooksPath at user scope poisons temp-repo git commits in Go tests

Class: global-hookspath-poisons-temp-repo-test-commits Affected file: src/typescript/dagger_qa_board_append_test.go (the three TestQaBoardAppend* cases that shell out to git)

Symptom

Full-package go test fails with:

--- FAIL: TestQaBoardAppendClobberGuardRefusesEmptyRowsAndSkipsCommit
    git [commit -m baseline]: exit status 1: gate: GitReins NOT RUN — .gitreins/config.yaml
    is absent; board validation remains mandatory
    gate: board arm UNAVAILABLE — /var/tmp/hermes-go-tmp/<TestName><rand>/001/scripts/check-board.sh
    is missing; EVERY commit requires board validation

Two sibling tests fail identically. The three pass standalone and with GIT_CONFIG_GLOBAL=/dev/null, but fail in the full-package run.

Root cause

The host sets a user-level core.hooksPath:

$ git config --global --get core.hooksPath
~/.hermes/hooks

Git resolves hooks from exactly one directory: core.hooksPath if set, else .git/hooks. The tests create a throwaway repo under t.TempDir() and run git commit with the inherited environment, so git runs the host's foreign pre-commit gate against the scratch repo. That gate demands a repo-local contract (.gitreins/config.yaml + scripts/check-board.sh) a temp repo can't satisfy, so it exits 1.

This is not env inheritance leaking GIT_INDEX_FILE/GIT_DIR (a separate class) — git was simply pointed at the wrong hooks dir by user config.

Why it looks intermittent

The hook's failure depends on its own preconditions: (a) standalone passes, (b) with GIT_CONFIG_GLOBAL=/dev/null passes, (c) full-package fails. The discriminator is which hook git found, not timing. Do not call it a flake.

Minimal reproduction (verified)

git config --global core.hooksPath /tmp/host-hooks
cat > /tmp/host-hooks/pre-commit <<'EOF'
#!/bin/sh
if [ ! -f .gitreins/config.yaml ] || [ ! -f scripts/check-board.sh ]; then
  echo "gate: GitReins NOT RUN — .gitreins/config.yaml is absent; board validation remains mandatory" >&2
  echo "gate: board arm UNAVAILABLE — $(pwd)/scripts/check-board.sh is missing; EVERY commit requires board validation" >&2
  exit 1
fi
EOF
chmod +x /tmp/host-hooks/pre-commit

T=$(mktemp -d); (cd "$T" && git init -q && git commit --allow-empty -m x); echo "exit=$?"
T=$(mktemp -d); (cd "$T" && git init -q && \
  GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null git commit --allow-empty -m x); echo "exit=$?"

Observed: first prints the exact gate text and exits 1; second exits 0.

The fix

Centralize a hermetic git helper in src/typescript/dagger_qa_board_append_test.go and route every git call through it.

Primary fix (recommended)

import (
    "os"
    "os/exec"
    "strings"
    "testing"
)

// hermeticGitEnv strips all user/system git config so a scratch repo can never
// inherit the operator's core.hooksPath (or GIT_CONFIG_COUNT-injected config).
func hermeticGitEnv() []string {
    drop := func(key string) bool {
        return key == "GIT_CONFIG_GLOBAL" ||
            key == "GIT_CONFIG_SYSTEM" ||
            key == "GIT_CONFIG_COUNT" ||
            strings.HasPrefix(key, "GIT_CONFIG_KEY_") ||
            strings.HasPrefix(key, "GIT_CONFIG_VALUE_")
    }
    env := []string{
        "GIT_CONFIG_GLOBAL=/dev/null",
        "GIT_CONFIG_SYSTEM=/dev/null",
        "GIT_CONFIG_NOSYSTEM=1",
        "GIT_CONFIG_COUNT=0",
    }
    for _, kv := range os.Environ() {
        key := kv
        if i := strings.IndexByte(kv, '='); i >= 0 {
            key = kv[:i]
        }
        if drop(key) {
            continue
        }
        env = append(env, kv)
    }
    return env
}

// runGit runs git inside dir with host git config stripped. Identity is passed
// explicitly because removing global config also removes the operator's user.name/email.
func runGit(t *testing.T, dir string, args ...string) string {
    t.Helper()
    full := append([]string{
        "-c", "user.name=Hermes Test",
        "-c", "user.email=<email>",
        "-c", "commit.gpgsign=false",
    }, args...)
    cmd := exec.Command("git", full...)
    cmd.Dir = dir
    cmd.Env = hermeticGitEnv()
    out, err := cmd.CombinedOutput()
    if err != nil {
        t.Fatalf("git %v: %v: %s", args, err, out)
    }
    return strings.TrimSpace(string(out))
}

Route all three TestQaBoardAppend* cases through this helper (git init, add, commit, rev-parse, ...). The essential part for commit is GIT_CONFIG_GLOBAL=/dev/null + GIT_CONFIG_SYSTEM=/dev/null; the -c user.name/-c user.email pair replaces the identity that /dev/null hides.

Gotcha (verified): GIT_CONFIG_GLOBAL=/dev/null alone gives fatal: unable to auto-detect email address unless identity is passed via -c user.name/-c user.email or set locally.

Alternative fix (smallest diff)

Keep the operator's identity, disable hooks only:

full := append([]string{"-c", "core.hooksPath="}, args...)
cmd := exec.Command("git", full...)
cmd.Dir = dir // keep inherited env

An empty core.hooksPath disables hook lookup entirely.

Also valid

Write the scratch repo's own hooks dir into local config at init time:

runGit(t, dir, "init", "-q")
runGit(t, dir, "config", "core.hooksPath", filepath.Join(dir, ".git", "hooks"))

Do NOT

  • Disable/rename the host hook — it is correct for real repos; the test must stop inheriting it.
  • Repoint user-level core.hooksPath as a workaround.
  • Dismiss the failure as a flake because -run passes.

Verification

Reproduced with a faithful Go harness (hostile user config + foreign gate):

Harness / condition Result
Pre-fix (inherits config) FAIL — prints scripts/check-board.sh is missing
Fixed (/dev/null + identity, hostile config) ok
Fixed, config neutral ok
Alt (-c core.hooksPath=, hostile config) ok

Apply to the real repo:

go test ./src/typescript -run TestQaBoardAppend                    # pre-fix fails
GIT_CONFIG_GLOBAL=/dev/null go test ./src/typescript -run TestQaBoardAppend
go test ./src/typescript -run TestQaBoardAppend
go test ./src/typescript                                           # full package

Post-fix all exit 0 and no scripts/check-board.sh is missing text appears.

Scope note

The error names a path inside the temp dir, so it reads like a missing-fixture bug in the repo under test. Any CI/local run on a box setting core.hooksPath can trip this, in any language whose tests shell out to git. Durable rule: tests that create throwaway git repos must sanitize git config and supply their own commit identity when they do.
