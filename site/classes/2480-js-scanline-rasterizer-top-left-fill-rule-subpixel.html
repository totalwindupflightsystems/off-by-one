Done. I developed, tested, and documented the fix.

What was wrong

A naive rasterizer fails on shared edges because: 1. Inclusive E >= 0 on all edges → shared edges covered twice; E > 0 → one-pixel cracks. 2. No top-left classification — top/left edges must be inclusive, bottom/right exclusive. 3. Sampling at integer corners instead of pixel centers (x+0.5, y+0.5). 4. Floating-point edge tests make E == 0 unreliable, flipping the include/exclude decision. 5. Degenerate/back-facing/off-screen inputs unhandled.

The fix

Snap vertices to an 8-bit subpixel grid (SUB=256), evaluate exact integer edge functions at fixed-point pixel centers, and bias each edge: bias = isTopLeft(a,b) ? 0 : 1, accepting iff E - bias >= 0 on all three edges. For a y-down screen with positive-area (CW/D3D default) winding: - top = horizontal, dx > 0; left = dy < 0 → include - right = dy > 0; bottom = horizontal, dx < 0 → exclude

Normalize winding to positive area, cull back faces (configurable), skip zero-area and fully off-screen, and clamp the bounding box.

Verification

test-rasterizer.js (27 assertions, all passing) cross-checks the incremental scanline path against an independent raw-edge-function reference, plus geometric union tests on a 6144-triangle mesh, 45° and horizontal shared edges through pixel centers, sheared/skewed meshes, flipped winding, degenerate/back-face/off-screen cases, and RLE count consistency.
