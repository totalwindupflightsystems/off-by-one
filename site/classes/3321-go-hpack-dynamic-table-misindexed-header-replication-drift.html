Fixing HPACK dynamic-table drift between proxy replicas

Problem class: go-hpack-dynamic-table-misindexed-header-replication-drift Environment: Go 1.26 (go1.26.8), linux/amd64 Artifact: github.com/example/hpackdrift

1. Symptom

An HTTP/2 proxy decodes the client's header block once per backend replica and forwards the decoded headers. Both decoders start from the same state and see the same bytes, so their dynamic tables must stay bit-identical. Two defects break that:

  • a never-indexed literal is inserted into one decoder's dynamic table, shifting every dynamic index by one so later indexed references resolve to a different header; and
  • after SETTINGS_HEADER_TABLE_SIZE shrinks mid-stream, a dynamic table size update changes the maximum but does not evict entries that no longer fit, so an indexed lookup returns a header that RFC 7541 says must already be gone (or the correct decoder rejects an index the buggy one still resolves).

2. HPACK rules violated

First byte Representation Prefix Dynamic-table effect
1xxxxxxx Indexed Header Field 7-bit none
01xxxxxx Literal with Incremental Indexing 6-bit adds the field
0000xxxx Literal without Indexing 4-bit none
0001xxxx Literal Never Indexed 4-bit none (mark sensitive)
001xxxxx Dynamic Table Size Update 5-bit changes max, evicts

RFC 7541: §6.2.3 never-indexed must not enter the table; §4.3 a maximum-size change evicts entries; §4.2 a shrink forces a size update at the start of the next block. Dynamic indices are positional (static 1..61, newest dynamic = 62), so a spurious insertion mis-indexes everything after it.

3. Root cause

Both are one-line mistakes in the state machine.

Bug 1 — never-indexed dispatched as incremental indexing (parseOne):

case b&0xF0 == 0x10:
    // BUG: same 4-bit prefix (byte-aligned!) but wrong indexing mode.
    return d.parseFieldLiteral(buf, out, 4, indexedTrue)   // adds + drops Sensitive
    // correct: parseFieldLiteral(buf, out, 4, indexedNever)

Because the 4-bit prefix is preserved, the field decodes correctly once, but it.indexed() makes parseFieldLiteral call d.add(hf). The next Indexed 62 therefore resolves to the sensitive field instead of the real entry.

Bug 2 — size change updates the max without evicting (setMaxSize):

func (d *Decoder) setMaxSize(v uint32) {
    d.maxSize = v
    return          // BUG (VariantNaive): no eviction
    d.evict()       // correct
}

add() also evicts, so the tables re-converge after the next insertion; the divergence window is between the size update and that insertion — exactly where an indexed reference can sit.

4. Crafted reproduction

Stream A (never-indexed):

block 0: 40 03 78 2d 61 02 76 31                  Incr. new name x-a=v1
block 1: 1f 08 0d 42 65 61 72 65 72 20 73 65 63 72 65 74
                                                  Never Indexed name 23 = authorization, "Bearer secret"
block 2: be                                       Indexed 62

Reference → x-a=v1; naive → authorization=Bearer secret.

Stream B (shrink):

block 0-2: x-a/x-b/x-c = v1/v2/v3                  table size 111
block 3: 3f 21                                     Size Update to 64
block 4: bf                                        Indexed 63

Reference evicts x-a,x-b (only x-c left) → error on index 63; naive keeps stale x-b=v2.

Observed with go run ./cmd/repro: replicas DIVERGE on both streams.

5. The fix

    case b&0xF0 == 0x10:
-       if d.variant == VariantNaive {
-           return d.parseFieldLiteral(buf, out, 4, indexedTrue)
-       }
        return d.parseFieldLiteral(buf, out, 4, indexedNever)
@@
 func (d *Decoder) setMaxSize(v uint32) {
    d.maxSize = v
-   if d.variant == VariantNaive {
-       return
-   }
    d.evict()
 }

Resulting correct code:

case b&0xF0 == 0x10:
    // RFC 7541 6.2.3: never indexed. 4-bit prefix, NOT added, marked sensitive.
    return d.parseFieldLiteral(buf, out, 4, indexedNever)

func (d *Decoder) setMaxSize(v uint32) {
    d.maxSize = v
    d.evict() // RFC 7541 4.3
}
func (d *Decoder) evict() {
    n := 0
    for d.size > d.maxSize && n < len(d.entries) {
        d.size -= d.entries[n].size
        n++
    }
    if n > 0 {
        d.entries = append(d.entries[:0], d.entries[n:]...)
    }
}

Production uses NewDecoder (always corrected); NewNaiveDecoder exists only for regression tests.

Layout: decoder.go, decoder_test.go, fuzz_test.go, cmd/repro/main.go, and internal/refhpack/ = upstream golang.org/x/net/http2/hpack (BSD-3) plus a Snapshot() method exposing the dynamic table.

  • Regression tests reproduce both crafted streams and assert naive ≠ reference, fixed == reference.
  • Differential fuzz drives the reference encoder with a seeded RNG (random sensitive fields, size updates), groups output into blocks, and after every block compares emitted fields in order, the Sensitive flag, error presence, and the full dynamic-table snapshot (MaxSize, Size, every entry). Fixed matched on all 2000 seeds; naive diverged on 1998 — this is true state-machine equivalence, not just output equivalence.
  • FuzzDecoderEquivalence ran ~2.4M arbitrary-byte executions with no mismatch.

The oracle is independent (upstream x/net hpack, the implementation net/http uses); only the Huffman primitive is shared, which is irrelevant to the table bug.
