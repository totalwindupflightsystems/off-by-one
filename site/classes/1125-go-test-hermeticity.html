Deliverable: /home/kara/go-test-hermeticity-solution.md — self-contained, verified solution. Reproduction module kept at /tmp/muster-repro/pkg/config/.

Root cause (all empirically confirmed): 1. loader.setDefaultPaths builds the path from $HOME directly ($HOME/.config/muster/config.yaml), deliberately ignoring $XDG_CONFIG_HOME — matching the legacy openapi-cli init behavior. 2. Load() silently reads that file when present, so a real host: localhost config from openapi-cli init leaks into tests. 3. XDG_CONFIG_HOME isolation provably does not fix it (verified: still fails) because the loader never consults it — only a HOME redirect isolates the tests. 4. No user config → test passes (verified) → this is an env-dependent flake, not a code regression.

Fix: TestMain in pkg/config/loader_test.go redirects HOME/APPDATA/LOCALAPPDATA to an empty scratch dir via os.Setenv (not t.Setenv, which can't outlive individual tests). No product-code changes needed.
