Summary

Root cause: The judge's tier1 stage runs bare pytest -x --tb=short with the ambient PATH, which on this multi-project host resolved to /home/kara/ai_plays_poke/.venv/bin/pytest. That's not just another pytest — it's another Python interpreter whose site-packages contains an editable-install .pth (__editable__.ai_plays_poke-0.1.0.pth) that injects ai_plays_poke/src into sys.path. The target repo's own src/ lives only in its venv, so from dashboard import server resolves to the foreign dashboard (which lacks server) → collection-time ImportError, aborted by -x right after "test session starts". tier2 passes because it reads the tree, not sys.path.

Fix: PATH="$PWD/.venv/bin:$PATH" gitreins judge <task-id> — flips tier1 to PASS (1120 passed / 95 skipped) and Overall to PASS; re-judging idempotently overwrites the FAIL verdict dir.

Verification performed here: - Built a minimal two-project lab repro (foreign src-layout project with editable venv + target project whose dashboard exports the module under test) — exact signature reproduced: - broken (foreign venv on PATH): ImportError: cannot import name 'Server' from 'dashboard' (/tmp/lab/ai_plays_poke/src/dashboard/__init__.py), 0 items / 1 error - fixed (PATH="$PWD/.venv/bin:$PATH"): 1 passed - Confirmed the mechanics: foreign interpreter's sys.path contains its own src/ via the .pth; pytest's prepend mode doesn't help (basedir tests/unit lacks the package; repo root isn't added since it's a src layout) - Confirmed the shadowing is generic (same-named top-level config package also hijacked) and that python -m pytest under the wrong interpreter fails identically - Re-ran the doc's embedded repro script verbatim (extracted from the markdown) — it reproduces both outcomes exactly as documented

Key takeaway in the doc: run which pytest before ever concluding a real test failure on a shared host.
