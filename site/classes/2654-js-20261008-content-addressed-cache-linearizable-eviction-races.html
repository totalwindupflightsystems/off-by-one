The full self-contained markdown (root-cause analysis, on-disk protocol, byte-exact code, tests, and verified output) is at ~/SOLUTION.md (copy at ~/cac/SOLUTION.md), with the runnable implementation in ~/cac/{cache.js,test.js,crash-child.js}.

Root-cause analysis

The failures are five missing guarantees, not one bug:

  1. Duplicate/partial blobs — writing directly to the final path is non-atomic. Fix: temp → fsync → atomic link(2), which fails EEXIST, so identical concurrent uploads converge on one inode.
  2. Eviction deletes a referenced blob — check-then-unlink TOCTOU. A manifest can acquire a reference between the refs==0 check and the unlink.
  3. Crash between commit and metadata update — refcounts living only in a WAL either leak or, worse, replay a release and delete a live blob.
  4. Global serialization — one lock keyed on the cache instead of on the data.
  5. Crash mid-commit/mid-evict — no defined linearization point, so recovery guesses.

Exact fix (protocol)

  • Two-phase reservation: a committing manifest durably reserves every newly referenced blob before the atomic rename that publishes it. Eviction succeeds only when refs == 0 && reserved == 0, under the same per-shard lock → the published manifest's reference set is undeletable from the instant it is visible.
  • Manifests are the durable source of truth. Recovery recomputes refs from manifests; the per-shard WAL only records reservations (multi-process correctness) and evict intents (so an interrupted unlink is completed).
  • Journal framing: <crc32>\t<json>\n; replay stops at the first bad/short record and truncates the torn tail.
  • Sharding without global locks: shard = parseInt(hash[0:8],16) % S, one mutex + journal per shard, plus a per-manifest-name mutex. Reservations hold exactly one shard lock at a time and release before the next → no deadlock, no global serialization.

Linearization points: commit = rename; eviction = unlink (WAL evict written before it).
