Diagnosis summary

Root cause: go-duckdb is CGO-only. Conn is defined in connection.go, which has import "C", so the file is excluded when CGO_ENABLED=0. But transaction.go has no build constraint and references *Conn (line 6), producing the misleading undefined: Conn. The real trigger is that Go silently defaults CGO_ENABLED=0 when no C compiler (gcc/cc) is found.

Verified on this box: - go env CGO_ENABLED = 1 normally; with a PATH lacking gcc/cc it returns 0 (silent disable confirmed). - CGO_ENABLED=0 go build ./... → transaction.go:6:5: undefined: Conn (rc=1, ~2.8s) — reproduced the exact error. - CGO_ENABLED=1 go build ./... → rc=0 (~15s), producing a working binary. - Forcing CGO_ENABLED=1 without a compiler gives the honest error: cgo: C compiler "...gcc" not found.

Fix (Option A, recommended): install a C toolchain on the build host (sudo apt-get install -y build-essential) and pin CGO_ENABLED=1 in CI so the failure is loud. Option B: if the host must stay compiler-free, drop the cgo-only dependency (DuckDB has no pure-Go driver) — use modernc.org/sqlite, shell out to the duckdb CLI, or gate the DuckDB import behind //go:build cgo.
