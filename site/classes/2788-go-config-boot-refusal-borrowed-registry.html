Answer

Fix: Refuse boot when a daemon would borrow another daemon's registry

Summary

A scratch bunkerd started with a private --config set its own agent.base_data_dir but left agent.registry.path unset. Config defaulting then resolved the registry to the compiled default /var/lib/bunkerd/agents.jsonl, so the scratch daemon opened and replayed the production registry (11497 events, 5 live agents) and began reconciling/destroying agents it did not own (one foreign agent restored, a live one killed mid-archive within ~60 s).

The fix is a read-only config predicate (DF-BUNKER-102) wired at both boot call sites, mirroring the existing DF-BUNKER-95 foreign-instance gate. It is not built on the registry cross-process flock, because lockCrossProcess is held only for the duration of a write and therefore proves nothing about a live owner.

Root cause

The two boot gates are mirror images:

tree (agent.base_data_dir) registry (agent.registry.path)
DF-BUNKER-95 (existing) DEFAULT elsewhere → inherits foreign identity
DF-BUNKER-102 (this bug) custom resolves into DEFAULT → replays foreign registry

config.Load/Validate applies RegistryConfig.Defaults, and the compiled default is:

DefaultAgentBaseDataDir = "/var/lib/bunkerd"
DefaultRegistryPath     = "/var/lib/bunkerd/agents.jsonl"

So an unset agent.registry.path with a custom base_data_dir silently resolves to the default tree's registry. The predicate must refuse boot only on positive evidence that the default tree already belongs to a running daemon (its registry file and its instance identity file both present); missing/unreadable evidence fails open.

Exact fix

1. Add the predicate and error type to internal/config/config.go

Insert immediately after pathWithinDir (and after statePathExists, which already exists and returns false on any os.Stat error):

// BorrowedRegistryCollisionError reports the DF-BUNKER-102 boot refusal: this
// daemon was given its OWN agent.base_data_dir, but its durable registry still
// resolves into the DEFAULT tree — i.e. the daemon would open another daemon's
// registry as its own while keeping a private identity.
type BorrowedRegistryCollisionError struct {
    BorrowedRegistryPath string
    OwningBaseDataDir    string
    InstancePath         string
    OwnBaseDataDir       string
}

// Error names the borrowed registry, the tree that owns it and the fix. Kept
// free of the "refusing to start: " prefix so both call sites (cmd/bunkerd and
// server.Run) can add it once, exactly like the DF-BUNKER-95 gate's error.
func (e *BorrowedRegistryCollisionError) Error() string {
    return fmt.Sprintf(
        "agent.registry.path resolves to %s inside the default tree at %s (instance=%s), but this daemon's agent.base_data_dir is %s: "+
            "the daemon would replay ANOTHER daemon's registry and reconcile its live agents as its own — restoring or destroying agents it does not own. "+
            "Fix: set agent.registry.path to a path inside your own agent.base_data_dir (e.g. %s)",
        e.BorrowedRegistryPath, e.OwningBaseDataDir, e.InstancePath, e.OwnBaseDataDir,
        filepath.Join(e.OwnBaseDataDir, filepath.Base(DefaultRegistryPath)))
}

// DetectBorrowedRegistryCollision reports, as a non-nil error, the boot-time
// collision where this config has its OWN agent.base_data_dir but its durable
// registry still resolves into the DEFAULT tree (DF-BUNKER-102); nil means
// "safe to continue". READ-ONLY probe: no directory is created and no file
// content is read, so it is safe to call before EnsureJWTSecret.
func (c *Config) DetectBorrowedRegistryCollision() error {
    return detectBorrowedRegistryCollision(DefaultAgentBaseDataDir, c)
}

// detectBorrowedRegistryCollision is the gate behind
// DetectBorrowedRegistryCollision. defaultBaseDataDir is a parameter so the
// refusal is provable against a scratch tree, not the host's real
// /var/lib/bunkerd. A collision requires ALL of:
//
//  1. agent.base_data_dir is set and is NOT the default dir (normalised).
//  2. the resolved registry path (falling back to DefaultRegistryPath when
//     config.Load has not applied the default — the incident shape) is INSIDE
//     the default dir.
//  3. the default dir already holds the owning daemon's registry file AND its
//     instance identity file. A partial tree fails OPEN.
//
// Residual (stated, not hidden): the registry cross-process lock is held only
// for a write, so it proves nothing about a live owner and is deliberately not
// used as evidence; the instance identity file is the ownership signal.
func detectBorrowedRegistryCollision(defaultBaseDataDir string, c *Config) error {
    base := strings.TrimSpace(c.Agent.BaseDataDir)
    if base == "" {
        return nil
    }
    defaultDir := filepath.Clean(defaultBaseDataDir)
    if filepath.Clean(base) == defaultDir {
        // The default tree IS this daemon's tree: the DF-BUNKER-95 gate owns
        // every shape with base_data_dir at the default.
        return nil
    }

    registryPath := resolveOwnRegistryPath(c)
    if !pathWithinDir(defaultDir, registryPath) {
        return nil
    }

    collision := BorrowedRegistryCollisionError{
        BorrowedRegistryPath: filepath.Clean(registryPath),
        OwningBaseDataDir:    defaultDir,
        InstancePath:         filepath.Join(defaultDir, InstanceIdentityFileName),
        OwnBaseDataDir:       filepath.Clean(base),
    }
    // Refuse only on POSITIVE evidence: an unreadable path (EACCES for a
    // non-root daemon) is "not proven", never a borrowed registry.
    if !statePathExists(filepath.Join(defaultDir, filepath.Base(DefaultRegistryPath))) ||
        !statePathExists(collision.InstancePath) {
        return nil
    }
    return &collision
}

// resolveOwnRegistryPath returns the registry path this daemon will open as its
// own: the configured path, or the documented default when config.Load has not
// applied RegistryConfig.Defaults. The fallback is the incident mechanism:
// unset agent.registry.path with a CUSTOM base resolves into the DEFAULT tree,
// and the constants make that containment structural.
func resolveOwnRegistryPath(c *Config) string {
    if p := strings.TrimSpace(c.Agent.Registry.Path); p != "" {
        return p
    }
    return DefaultRegistryPath
}

Key correctness points:

  • pathWithinDir normalises both sides, so dir/./agents.jsonl and trailing slashes are contained as expected.
  • statePathExists already fails open (os.Stat error ⇒ false), so permission errors never cause a refusal.
  • Requiring both DefaultRegistryPath basename and InstanceIdentityFileName avoids refusing a legitimate first boot against an empty/default tree.
  • The base == defaultDir early return keeps the two gates disjoint (95 owns default-tree shapes; 102 owns custom-tree/borrowed-registry shapes).

2. Wire it at both boot call sites, beside the existing gate

cmd/bunkerd/main.go (immediately after the DetectForeignInstanceCollision block):

    // DF-BUNKER-102: the mirror shape — the config gave this daemon its OWN
    // agent.base_data_dir, but agent.registry.path (or its unset default)
    // still resolves into the DEFAULT tree, so boot would replay ANOTHER
    // daemon's registry and reconcile its live agents as this daemon's own.
    // Same read-only, before-EnsureJWTSecret position as the gate above.
    if err := cfg.DetectBorrowedRegistryCollision(); err != nil {
        return fmt.Errorf("refusing to start: %w", err)
    }

internal/server/server.go in (*BunkerdServer).Run (immediately after the DetectForeignInstanceCollision block):

    // DF-BUNKER-102: the mirror shape — this daemon HAS its own
    // base_data_dir, but its registry still resolves into the DEFAULT tree,
    // so boot would replay ANOTHER daemon's registry and reconcile its live
    // agents as this daemon's own. Same read-only, before-anything-opens
    // position as the gate above.
    if err := s.cfg.DetectBorrowedRegistryCollision(); err != nil {
        return fmt.Errorf("refusing to start: %w", err)
    }

The gate error text deliberately omits "refusing to start: "; each call site adds it exactly once via fmt.Errorf("refusing to start: %w", err).

Test design (why the incident shape is pinned structurally)

The hermetic tests take the default dir as a parameter and pass a scratch t.TempDir(); they seed an "owning tree" with both <default>/agents.jsonl and <default>/instance to model an occupied production tree. A temp-dir test cannot seed the real /var/lib/bunkerd, so the exact incident shape (unset agent.registry.path) is pinned structurally:

  • TestDetectBorrowedRegistryCollisionDefaultsAndDelegation asserts DefaultRegistryPath == DefaultAgentBaseDataDir + "/agents.jsonl" and that the exported method delegates to detectBorrowedRegistryCollision(DefaultAgentBaseDataDir, c).
  • TestDetectBorrowedRegistryCollisionUnsetRegistryFallsBackToDefault builds a config with a custom base and an empty registry path, then proves resolveOwnRegistryPath returns DefaultRegistryPath and the gate refuses when the default tree is fully occupied.
  • The equivalent explicit-path refusal case (cfg.Agent.Registry.Path = filepath.Join(defaultDir, filepath.Base(DefaultRegistryPath))) is covered directly, so both the bug's unset-default mechanism and the explicit misconfiguration are gated.
  • Fail-open cases: missing default dir, registry-only tree, instance-only tree, unreadable default dir, empty base_data_dir, registry inside the custom base, registry elsewhere, and default-base production restart.

The flock (internal/registry.lockCrossProcess) is intentionally never consulted: it is held only for a write, so it proves nothing about a live owner.
