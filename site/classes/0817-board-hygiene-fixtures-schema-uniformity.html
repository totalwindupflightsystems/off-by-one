Answer

Root cause: one row of fixtures.jsonl was written with the 31-key task schema (status, priority, assignee, pending, …) instead of the 5-key fixture schema (id/title/description/active/created_at). Parsers that iterate the registry and dispatch on key sets hit the outlier.

Fix: a normalizer (board/normalize.py) that rewrites every non-conforming row into the fixture schema, mapping task-schema pending semantics to active: false — and deliberately not promoting the row to tasks.jsonl (its id stays in the fixture registry; promotion would change registry membership and break id references). Unknown schemas now raise instead of silently passing.

# board/normalize.py (core of the fix)
def normalize_row(row: dict) -> dict:
    keys = set(row)
    if keys == FIXTURE_KEYS:                      # 5-key: pass through
        return dict(row)
    if keys == TASK_KEYS:                         # 31-key outlier: normalize
        return {
            "id": row["id"],
            "title": row["title"],
            "description": row.get("description", ""),
            "active": not bool(row.get("pending", False)),   # pending -> active:false
            "created_at": row["created_at"],
        }
    raise ValueError(f"row {row.get('id')!r}: unrecognized {len(keys)}-key schema")

def normalize_file(path: Path) -> tuple[int, int]:
    out = [normalize_row(json.loads(line)) for line in path.read_text().splitlines() if line.strip()]
    path.write_text("\n".join(json.dumps(r, sort_keys=True) for r in out) + "\n")
    return len(out), ...

Result for the outlier row T-003:

{"id": "T-003", "title": "Wire kanban columns", "description": "Draft column layout for the kanban view", "active": false, "created_at": "2026-08-02T10:00:00Z"}

(31 keys → 5 keys; pending: true → active: false; id/title/description/created_at carried over.)

A validator (board/validate.py) enforces the PASS criterion — every row's key set must equal the 5 fixture keys, and no fixture id may leak into tasks.jsonl.
