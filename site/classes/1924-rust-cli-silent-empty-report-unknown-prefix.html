Fix: hilo graph module <prefix> must not silently succeed on an unknown prefix

Problem class: rust-cli-silent-empty-report-unknown-prefix Repo: /home/kara/warpfs (rust workspace, clap CLI + DuckDB graph store) Crate affected: hilo-graph (binary hilo)

1. Root cause

hilo graph module <prefix> had exactly one success shape for "nothing to show": print Files: 0 / Edges: 0 / Tests: 0.0% and exit 0. It could not distinguish (1) a real module directory with no warmed graph coverage from (2) a prefix that was never a directory and is not named in the graph (e.g. no/such/dir).

Two things combined:

  • The command resolved/opened DuckDB first. With no graph (fresh, unwarmed tree), the early-return printed the generic empty/"No graph data" output instead of consulting the filesystem.
  • On the graph-present path, an empty stats row was treated as a normal empty module. The query cannot tell a typo from a coverless directory by itself, and nothing else checked the filesystem.

Sibling graph related <path> / graph impact <path> already fail with exit 1 ... not in the graph ..., so graph module was inconsistent with its own family.

Fix: classify the positional against the filesystem first (before DuckDB) with a pure helper, and apply it on both the no-graph path and the empty-stats path. The tolerant case — directory deleted after a warm, graph still names files under the prefix — has non-empty stats and never reaches the classifier.

2. Exact fix

2.1 Locate the handler

No flag changes; the prefix stays the clap positional:

The code below is drop-in for the file implementing the handler (commonly hilo-graph/src/cli/graph.rs or hilo-graph/src/main.rs). It assumes prefix: &str and stats fields files: u64, edges: u64, tests: f64 (rename to match).

2.2 Pure classifier + messages (no DuckDB)

use std::path::Path;

/// The result of asking the filesystem whether an empty `graph module`
/// prefix is a typo or a real-but-uncovered directory.
///
/// Deliberately two-state: the tolerant case (directory deleted after a warm,
/// graph still names files under the prefix) never reaches this function
/// because its stats are non-empty and are reported normally.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum EmptyModule {
    /// No such path on disk and nothing in the graph under this prefix.
    UnknownPrefix,
    /// The path exists on disk but nothing in the graph covers it.
    UncoveredDirectory,
}

/// Pure, filesystem-only classification of a `graph module` prefix.
///
/// Called *before* graph-db resolution so a fresh/unwarmed tree can answer a
/// typo in the user's own terms rather than with "No graph data".
fn classify_empty_module(dir_exists: bool) -> EmptyModule {
    if dir_exists {
        EmptyModule::UncoveredDirectory
    } else {
        EmptyModule::UnknownPrefix
    }
}

fn unknown_prefix_error(prefix: &str) -> anyhow::Error {
    anyhow::anyhow!(
        "'{prefix}' is not in the graph (no such directory and no matching module prefix)"
    )
}

fn uncovered_directory_notice(prefix: &str) -> String {
    format!(
        "No files in the graph under '{prefix}' - the directory exists but no warmed \
         graph entry covers it. Run `hilo graph warm`."
    )
}

2.3 Wire into the handler at both exit points

fn run_graph_module(prefix: &str) -> anyhow::Result<()> {
    // 1. Filesystem probe FIRST, before any DuckDB resolution.
    let dir_exists = Path::new(prefix).exists();

    // 2. No-graph path: a fresh tree answers a typo with the prefix error.
    let Some(store) = GraphStore::open_default()? else {
        return match classify_empty_module(dir_exists) {
            EmptyModule::UnknownPrefix => Err(unknown_prefix_error(prefix)),
            EmptyModule::UncoveredDirectory => {
                // Unconditional, state-independent line; exit 0.
                println!("{}", uncovered_directory_notice(prefix));
                Ok(())
            }
        };
    };

    // 3. Empty-stats path: same classification, same outcomes.
    let stats = store.module_stats(prefix)?;
    if stats.files == 0 && stats.edges == 0 && stats.tests == 0.0 {
        return match classify_empty_module(dir_exists) {
            EmptyModule::UnknownPrefix => Err(unknown_prefix_error(prefix)),
            EmptyModule::UncoveredDirectory => {
                println!("{}", uncovered_directory_notice(prefix));
                Ok(())
            }
        };
    }

    // 4. Tolerant case: report normally, exit 0.
    print_module_report(prefix, &stats);
    Ok(())
}

GraphStore::open_default, store.module_stats, and print_module_report are placeholders for the repo's existing symbols. Keep the notice unconditional (no verbose/TTY/empty-graph gate) and change neither the flag set nor --help.

3. Tests

3.1 Unit tests (same module as the helper)

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn classify_empty_module_unknown_prefix() {
        assert_eq!(classify_empty_module(false), EmptyModule::UnknownPrefix);
    }

    #[test]
    fn classify_empty_module_uncovered_directory() {
        assert_eq!(classify_empty_module(true), EmptyModule::UncoveredDirectory);
    }

    #[test]
    fn messages_are_prefixed_and_non_empty() {
        let err = unknown_prefix_error("no/such/dir").to_string();
        assert!(err.contains("'no/such/dir' is not in the graph"));

        let notice = uncovered_directory_notice("hilo-graph/src");
        assert!(notice.contains("No files in the graph under 'hilo-graph/src'"));
        assert!(notice.contains("hilo graph warm"));
    }
}

3.2 Integration test (built binary in a temp dir)

Under the package owning the binary (adjust CARGO_BIN_EXE_hilo if needed), e.g. hilo-graph/tests/graph_module.rs:

use std::process::Command;

#[test]
fn graph_module_unknown_prefix_fails_loudly_in_fresh_tree() {
    let tmp = tempfile::tempdir().expect("tempdir");
    let exe = env!("CARGO_BIN_EXE_hilo");

    let out = Command::new(exe)
        .current_dir(tmp.path()) // fresh dir: no .vfs anywhere above
        .args(["graph", "module", "no/such/dir"])
        .output()
        .expect("run hilo");

    assert_eq!(out.status.code(), Some(1), "must exit 1");
    let stderr = String::from_utf8_lossy(&out.stderr);
    assert!(
        stderr.contains("'no/such/dir' is not in the graph"),
        "stderr was: {stderr}"
    );
}

#[test]
fn graph_module_real_uncovered_directory_exits_zero_with_notice() {
    let tmp = tempfile::tempdir().expect("tempdir");
    std::fs::create_dir_all(tmp.path().join("real/dir")).unwrap();
    let exe = env!("CARGO_BIN_EXE_hilo");

    let out = Command::new(exe)
        .current_dir(tmp.path())
        .args(["graph", "module", "real/dir"])
        .output()
        .expect("run hilo");

    assert_eq!(out.status.code(), Some(0), "must exit 0");
    let stdout = String::from_utf8_lossy(&out.stdout);
    assert!(
        stdout.contains("No files in the graph under 'real/dir'"),
        "stdout was: {stdout}"
    );
    assert!(stdout.contains("hilo graph warm"));
}

The tolerant path (delete a directory that still has graph entries) reports normally because non-empty stats bypass the classifier.

5. Pitfall for the foreman

Do not put RUSTFLAGS="-D warnings" cargo check in a local gate brief on this host — it changes the dependency fingerprint and recompiles libduckdb-sys C++ from source (~26 min). Use the repo's ./scripts/rust-lint.sh (clippy -D warnings) plus CI for that leg.
