Answer

File: /tmp/git-rename-branch.sh — a comprehensive script demonstrating all 5 Git branch rename scenarios with full edge-case handling.

1) Rename current branch

git branch -m <new-name>
# or via the script:
./git-rename-branch.sh --current <new-name>

2) Rename any branch (not checked out)

git branch -m <old-name> <new-name>
# or:
./git-rename-branch.sh <old-name> <new-name>

The script auto-detects if old-name == current branch and uses the single-arg form.

3) Rename + push + set upstream + delete old remote

# Manual:
git branch -m <new-name>
git push -u origin <new-name>
git push origin --delete <old-name>

# Script (one command):
./git-rename-branch.sh --push <old> <new> [remote]

4) Delete stale remote branch after local rename

git push origin --delete <old-name>
git remote prune origin           # clean up local tracking refs

# Script:
./git-rename-branch.sh --delete-remote <old> [remote]

5) Master → Main migration (industry-wide)

# Full sequence:
git branch -m master main
git push -u origin main
git push origin --delete master
# Then in GitHub/GitLab: Settings → Branches → change default to "main"
git remote prune origin

# Script (one command):
./git-rename-branch.sh --master-to-main [remote]

The script also handles git check-ref-format validation, detached HEAD detection, same-name no-ops, non-existent branches, and already-on-main scenarios.

Edge cases verified:
- **Bare remote refuses to delete HEAD branch**: handled with `receive.denyDeleteCurrent` config note in script output
- **Branch name validation**: uses `git check-ref-format` — catches `..`, spaces, `~^:?*[\`, leading `.`, trailing `.lock`, `@{`
- **Tracking branch format**: upstream stored as `origin/branch` not `refs/remotes/origin/branch`
- **Remote doesn't exist**: skipped gracefully
- **Already on target name**: early return with no-op
