Fixing the GitReins tier2 wall-clock false-fail (gap094_resident_reconcile.rs:179)

Class: gitreins-tier2-judge-false-fail-load-sensitive-timing-test Repo: gethilo/hilo · Commit under judgment: fed7ae22b40f587f9bad4d46aa973309719d467b Verdict artifact: 30800c72 · Observed: passed=false, tier2 summary INCOMPLETE Failing signal: the cold tool call exceeded the bounded wall clock: 11.145689799s > 8s (gap094_resident_reconcile.rs:179) from cargo test -p hilo-cli EXIT=101 Decisive evidence: same test PASSES on the quiet merged tree (15.77s < 16s on the same host, later) Required code change: none — this is an adjudication (verdict-stamping) fix.

1. Summary

The tier2 judge returned INCOMPLETE/FAIL on work that was functionally complete. The judge's own narrative verified every functional criterion (change present, committed unit tests passing, live behavior proven). The only red item was one wall-clock assertion in a test file the diff never touched. The judge runs the whole suite inside its own tier1 lane; that lane ran concurrently with a parallel wave build on the same 16-core host, so the timing assertion absorbed host load. This is a green-under-quiet / red-under-load flake inside the judge lane, not a defect in the work.

Correct action: stamp the verdict verified with the false-fail reason and grep evidence — not re-dispatch, not re-judge into the same contention.

2. Root-cause analysis

  1. Grading target too wide. gitreins task complete lets tier2 run the entire cargo test -p hilo-cli, so one timing-sensitive integration test gates a verdict whose functional claims it doesn't represent.
  2. Wall-clock assertions are non-hermetic. A "cold tool call < 8s" bound is a function of CPU/IO availability. Under a parallel wave build the same path took 11.145689799s; on the quiet tree 15.77s against 16s.
  3. Judge lane has no exclusivity. Nothing serializes judge tier1 against build lanes. Judge-side analogue of class 2290 (guard-side shared-DB flake). Key difference: this is a Rust repo, no shared DB — the shared resource is CPU/wall-clock.
  4. No "degraded" verdict bucket. A lone timing failure in an otherwise fully verified narrative collapses to INCOMPLETE = false merits FAIL.
  5. Two different budgets. Failure was >8s; quiet rerun passed 15.77s < 16s. Confirm you re-run the exact named assertion, not a similarly named sibling.

  1. Serialize judge tier1 vs build lanes via host-wide flock /var/lock/gitreins-heavy.lock.

  4. Budget: foremen avoid overlapping heavy builds; record uptime/active jobs in the ledger.
