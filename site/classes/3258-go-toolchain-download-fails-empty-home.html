Answer

Solution written to /workspace/solution.md. I reproduced the failure and verified the fix end-to-end on this host.

What's going on

The probe runs env -i HOME=/tmp/probe-home go run ./cmd/guardd — i.e. it compiles inside the empty‑HOME sandbox. Because the module pins go 1.26.9 while the installed toolchain is go1.26.8 and GOTOOLCHAIN=auto, the go command treats the toolchain as a downloadable module. env -i resets GOPATH/GOMODCACHE to /tmp/probe-home/go/pkg/mod (empty), so Go tries to download go1.26.9 again. When egress is blocked it fails before the program ever runs and emits no program output. The tick then mistook the toolchain error for product behaviour.

Reproduced failure (GOPROXY=off):

go: downloading go1.26.9 (linux/amd64)
go: download go1.26.9 for linux/amd64: toolchain not available
exit=1

The fix (verified)

  1. Build once in the real environment: make build → go build -o bin/guardd ./cmd/guardd.
  2. Pipe input into the artifact under empty HOME: printf 'hello\n' | timeout 120 env -i HOME=/tmp/probe-home PATH=/usr/bin:/bin ./bin/guardd {"status":"ok","input":"hello"} # exit 0 Confirmed it runs even with PATH=/nonexistent and a dead proxy → the binary needs no Go/cache/network.
  3. A guard script (probe-guardd.sh) that classifies evidence:
  4. exit 0 + JSON stdout → valid (PASS/FAIL allowed)
  5. non-zero exit, empty stdout, non-JSON, timeout, or missing binary → INVALID_EVIDENCE (exit 2, loud), never PASS/FAIL.

Verified guard behavior:

BIN=/bin/true  → INVALID_EVIDENCE reason=no-program-output        (exit 2)
BIN=/bin/false → INVALID_EVIDENCE reason=probe-nonzero-exit:rc=1  (exit 2)

/workspace/solution.md contains the full root-cause analysis, Makefile, guard script, exact before/after commands, verification transcript, the tick classification policy, and the read‑only‑module‑cache cleanup note.
