Answer

I diagnosed and fixed the issue end-to-end in a GitReins source checkout, verified with tests, and wrote the full write-up to:

~/gitreins-guard-test-timeout-ignores-config.md

Root cause

The go_tests lane does honor guards.test_timeout — but only if the judge is given the repo config. On the task complete path it never is:

  1. gitreins/cli.py :: cmd_task_complete builds Judge(llm, workdir, scan_root=scan_root) without guard_config.
  2. engine/judge.py collapses it: self.guard_config = guard_config or {} (None → {}).
  3. engine/guard_manager.py only loads .gitreins/config.yaml when the argument is literally None, so with {} it skips _load_guard_config and keeps the default test_timeout = 180.

Result: configured 1200 is ignored; the green ~201 s suite trips the hardcoded 180 s cap, and the verdict lands pass_class=tier1-only / overall FAIL.

Reproduced directly:

config=None -> 1200
config={}   -> 180
Judge(...)  -> 180   # before fix

Fix (3 changes)

  • gitreins/cli.py — cmd_task_complete now does config = load_config(workdir) and calls Judge(llm, workdir, guard_config=config, scan_root=scan_root), matching cmd_judge.
  • engine/judge.py — stop coercing None to {}: self.guard_config = guard_config, so GuardManager's disk-load fallback fires for every caller (also fixes the MCP server).
  • engine/guards.py — the timeout failure now prints the effective timeout and measured wall clock: Tests timed out after 180s (guards.test_timeout); measured wall clock 0.0s. ...

Plus a regression test test_task_complete_threads_guard_config_into_judge and an updated FakeJudge signature.

Verification (all run and green)

  • Repro now yields Judge(no guard_config) -> 1200.
  • check_go_tests timeout message contains both fields.
  • pytest tests/test_cli.py::TestTaskCompleteScanScopeAndLease tests/test_guard_go_lanes.py tests/test_guard_manager.py tests/test_judge.py → 380 passed.
  • ruff check + ruff format --check clean.

The markdown also includes the interim pipx unblock (raise the installed fallback 180 → 1200, keeping hook_timeout above test_timeout), the exact one-shot git apply patch, and the end-to-end bunker verification steps (gitreins task complete → go_tests PASS, pass_class != tier1-only).
