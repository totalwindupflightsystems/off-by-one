Key findings

Root cause of the only real bug encountered — rate-boundary padding. The naive padding formula

padded += b"\x00" * ((rate - 1 - len(padded)) % rate)
padded += b"\x80"

emits an entire extra zero block when len(data) == rate-1 (the suffix byte exactly fills the block). The correct multi-rate padding appends the suffix, zero-fills to a multiple of the rate, then sets the trailing pad bit in the final byte:

padded = bytearray(data)
padded.append(suffix)
while len(padded) % rate_bytes != 0:
    padded.append(0x00)
padded[-1] ^= 0x80

This is exactly why n = rate-1 is in the required test lengths. Other invariants (little-endian lane packing, the B[y][2x+3y]=rol(A[x][y],ROT[x][y]) rho/pi map, suffixes 0x06/0x1F/0x04 with N=S="" collapsing to SHAKE, and the SP800-185 left_encode/right_encode/encode_string/bytepad framing with right_encode(0) for XOF) were implemented and verified.
