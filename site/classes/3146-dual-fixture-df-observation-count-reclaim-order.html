Solution written to ~/SOLUTION.md and verified against the real repo.

Root cause

scripts/disk-policy.py ran the under-lock recovery probe against the target path ($HOME) instead of the reclaim namespace directory ($HOME/.node/disposable-cache-v1). The frozen contract uses two df stubs:

  • fixture (a) (DF_BEFORE/DF_AFTER) logs only exact -Pk -- $HOME calls and exit 18s silently otherwise;
  • fixture (b) (DF_SEQUENCE) logs every call and asserts no extra reading.

A target-path probe therefore adds a visible extra observation to fixture (a) tests, producing exactly the reported diffs:

['1048576','1048576','1048576'] != ['1048576','1048576']
['1048576','1048576','5242880'] != ['1048576','5242880']
['1048576','1048576','bad']     != ['1048576','bad']

The only ordering that satisfies both fixtures is: target admission → lock → namespace-dir recovery probe → delete if needed → target final admission.

A secondary bug: available_kib() used require(result.returncode == 0, ...), making a failed df raise ValueError and become indistinguishable from malformed output. Switching to result.check_returncode() is what lets a failed probe mean "no recovery info → delete", while malformed successful output means "refuse without deleting".

The fix

Canonical upstream commit 20aeb9e (parent c078906). Deciding change in reclaim():

try:
    # probe the reclaim namespace, never the target path
    recovered = available_kib(os.path.join(home, ".node", "disposable-cache-v1"))
except subprocess.CalledProcessError:
    recovered = None          # df failed -> no recovery info -> delete
if recovered is not None and enough(recovered):
    print("  ..    capacity recovered under reclaim lock")
    return 0

plus def reclaim(home) → def reclaim(home, enough), reclaim(path) → reclaim(path, enough), result.returncode == 0 → result.check_returncode(), and the prerequisite --reclaim-disposable wiring in lib.sh, project-node.sh, node-create.sh (same commit).
