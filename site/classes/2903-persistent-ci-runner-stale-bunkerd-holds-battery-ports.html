The full write-up follows.

Persistent CI runner: stale bunkerd holds the battery ports (:28081/:29091)

Problem class: persistent-ci-runner-stale-bunkerd-holds-battery-ports Repository: deployBunker/bunker Defect: INT-CI-077 — fixed in 894f8aeb (impl) / f5ee50a2 (trace) Witness: GitHub run 39544219096, job 119038796197 (regression), head 85c802e6 Sibling defect: INT-CI-042 (stale deterministic spawn keyfile), fixed in 9ae65606 — same "killed daemon leaves residue on the persistent runner" family.

1. Symptom

On the persistent self-hosted runner, a battery run dies before a single test cell executes:

bunkerd: server error: listen tcp :28081: bind: address already in use
Process completed with exit code 42.

The other four jobs of the run (build-and-test, root-suite, unit-tests, gitreins-guard) are green. The regression job's transcript shows exit code 42 with no cell output — the failure carries no test verdict, so it reads as a code failure when it is actually runner hygiene. The only real evidence (bind: address already in use) is buried in the daemon log on the runner (/var/log/bunkerd-battery.log, /var/log/bunkerd-regression.log).

A previous job's bunkerd — started in the background, then orphaned when its job was killed/cancelled on the shared persistent host — was still LISTENing on the fixed CI ports.

2. Root-cause analysis

Three facts combine:

  1. Persistent runner, reused host. Unlike an ephemeral runner, the same machine runs job after job. A background bunkerd (... bunkerd -c "$CONFIG" ... &) survives job teardown whenever the harness's own cleanup does not run (e.g. the job process is killed/cancelled, so the EXIT trap never fires; SIGKILL cannot be trapped).

  2. Fixed, hard-coded ports. CI pins them per job in .github/workflows/ci.yml:

Job Env Ports
regression (regression-tests.sh) BUNKERD_COEXIST=1 gRPC :29090, REST :28080
E2E battery (e2e-full-battery.sh) BUNKERD_COEXIST=1 gRPC :29091, REST :28081

A leaked daemon from the previous run therefore collides with the next run deterministically.

  1. The bind loss is not a harness-level event. The new daemon is started in the background and fails asynchronously inside its own log. regression-tests.sh had no startup readiness check at all: it proceeded straight into section 3, where every cell found "connection refused" — an unattributable cascade. e2e-full-battery.sh did have an INT-CI-028 startup probe, but it only tailed the shared daemon log generically and still exited 42 before any cell.

Net effect: the harness treats "the port my daemon needs is occupied" as an internal code failure instead of a pre-condition violation, and the caller learns nothing actionable.

Desired invariant

Before a harness starts its own daemon, verify the exact requested ports are free. If not, emit one cell that names the port, the owning stale pid, the reclaim action, and the production-daemon warning — and abort with the harness's documented preflight code. Detect only; never kill and never sleep the bind failure away.

Reclamation between jobs was considered and rejected: the runner also hosts a systemd-managed production bunkerd (INT-CI-012). A harness that auto-kills port owners could kill the live service, which is exactly the bug that host_state_sweep_allowed / BUNKERD_COEXIST were introduced to prevent. The safe, deterministic choice is detection + operator guidance.

3. The fix

A detection-only shell helper port_preflight <grpc_addr> <rest_addr>, defined and invoked in both battery entrypoints before the daemon starts.

3.1 The helper (identical in both scripts)

# port_preflight <grpc_addr> <rest_addr> — INT-CI-077: refuse the run BEFORE
# the scratch daemon loses a bind fight it can only report in its own log.
# Detection ONLY: this never kills anything — the production-daemon safety
# rules expressed by host_state_sweep_allowed / BUNKERD_COEXIST are untouched
# — the ONE refusal cell names the exact port, the owning stale pid, and the
# reclaim action, and leaves the kill to the operator.
port_preflight() {
    local PORT SNAP LINE OWNER_PID
    SNAP="$(ss -tlnp 2>/dev/null || true)"
    for PORT in "${1#:}" "${2#:}"; do
        # INT-CI-020 shape: match the LISTEN line by ":<port>" followed by
        # whitespace/end — no grep -q, no head (SIGPIPE kills the writer and
        # pipefail fails the pipeline even on a match).
        LINE="$(printf '%s\n' "$SNAP" | grep -E "^LISTEN .*:${PORT}([[:space:]]|$)" || true)"
        LINE="${LINE%%$'\n'*}"
        [ -n "$LINE" ] || continue
        OWNER_PID=""
        case "$LINE" in
            # First pid=<n> in the users:(...) field; absent when this user
            # may not see socket owners (non-root ss -tlnp).
            *pid=*) OWNER_PID="${LINE#*pid=}"; OWNER_PID="${OWNER_PID%%[^0-9]*}" ;;
        esac
        if [ -n "$OWNER_PID" ]; then
            echo "  ✗ FATAL: requested port :$PORT is already LISTENing — a stale daemon from a previous job still holds it (the new bunkerd would die with 'address already in use'; CI run 39544219096). Owner pid $OWNER_PID — reclaim: kill $OWNER_PID (verify first with 'systemctl is-active bunkerd': NEVER kill the systemd-managed production daemon)." >&2
        else
            echo "  ✗ FATAL: requested port :$PORT is already LISTENing — a stale daemon from a previous job still holds it (the new bunkerd would die with 'address already in use'; CI run 39544219096). Owner pid not visible to this user — identify it with: ss -tlnp | grep :$PORT ; then kill <pid> (verify first with 'systemctl is-active bunkerd': NEVER kill the systemd-managed production daemon)." >&2
        fi
        return 1
    done
    return 0
}

Design notes:

  • Reads ss -tlnp; matches the LISTEN line by :<port> followed by whitespace/end-of-line. This avoids the classic false positive :2909 matching :29091, and avoids grep -q/head under pipefail (SIGPIPE would fail the pipeline even on a match — INT-CI-020).
  • Extracts the first visible pid=N from the users:(("bunkerd",pid=N,fd=..)) field. When the pid is not visible (non-root ss), it still refuses and tells the operator how to find it — it never invents a pid.
  • The one refusal cell names: exact port, owner pid, reclaim action (kill <pid>), the historical signature (address already in use, run 39544219096), and the systemctl is-active bunkerd warning so the systemd-managed production daemon is never the kill target.
  • Detection only — no kill/pkill, no sleep, no retry.

3.2 Wiring — regression-tests.sh (exit 2)

Defined next to kill_stray_bunkerd. Invoked in section 2 (Server startup), unconditionally, before bunkerd -c "$REGRESSION_CONFIG":

# INT-CI-077: the exact ports this run requested must be FREE before the
# scratch daemon is started — a stale listener from a previous job is ONE
# actionable refusal naming the owning pid (exit 2 = preflight refusal,
# nothing mutated), not 22 unattributable cascade reds. Detection only: no
# kill, no retry, no sleep; the operator reclaims. The systemd-managed
# production daemon (INT-CI-012) is never this suite's to stop — if it is
# the owner, the refusal says so and the RUN PORTS must move instead.
if ! port_preflight "$BUNKERD_GRPC_ADDR" "$BUNKERD_REST_ADDR"; then
    echo "FATAL: port preflight refused the run — free the ports above (or point BUNKERD_GRPC_ADDR/BUNKERD_REST_ADDR at free ones) and re-run." >&2
    exit 2
fi

Default ports here are :29090/:28080; CI overrides to the same. exit 2 is the suite's documented preflight-refusal code and mutates nothing.

6. Operator reclaim runbook

When the preflight refuses, it prints exactly what to do. The safe sequence:

# 1. Is the owner the systemd-managed production daemon?
systemctl is-active bunkerd

# 2a. If ACTIVE: do NOT kill it. Move this run to free ports instead:
BUNKERD_GRPC_ADDR=:29092 BUNKERD_REST_ADDR=:28082 bash e2e-full-battery.sh

# 2b. If INACTIVE: the listener is an orphan from a previous job. Confirm it:
ss -tlnp | grep -E ':(28081|29091)\b'
ps -o pid,ppid,etime,cmd -p <pid>          # should be a bunkerd, long started, PPID 1

# 3. Reclaim it (operator action, outside the harness):
kill <pid>          # escalate to kill -9 only if it ignores SIGTERM

# 4. Re-run the battery.

The harness deliberately does not perform step 3 — automation that kills port owners is what would take down the production service (INT-CI-012).

8. Notes / non-goals

  • Detection, not reclamation. The helper intentionally contains no kill/pkill/sleep. The kill guidance is printed text the operator executes.
  • The systemd-managed production daemon is never a target. If port_preflight finds the production service holding a run port, the fix is to move the run's ports, not to stop the service.
  • Non-root ss. When socket owners are not visible, the refusal still fires and tells the operator to identify the pid with ss -tlnp | grep :<port>; it never fabricates a pid.
  • INT-CI-042 sibling. The same leaked-daemon residue also left stale /tmp/bunker-key-<id> pairs that broke spawn at keygen; that half was fixed in 9ae65606 (pre-clear the deterministic spawn keyfile pair before keygen). Together they close the "killed job leaves residue" class on the persistent runner.
  • Residual CI leg. The committing tick recorded that a post-fix main run reaching VERIFY-PASS with no cell skipped had not yet been observed when the row closed (runs 39579771167 / 39580390737 were still queued). The discriminating behaviour is already proven hermetically here: on a dirty runner the run now stops with an explicit port+pid refusal cell instead of an unattributable exit 42.
