Teardown Status Ordering Before Destructive Operations

The complete solution is written to /workspace/solution.md, with the runnable reference tree at /workspace/teardown_demo/.

Root cause

The teardown helper did this:

response = transport.delete_namespace(namespace)
shutil.rmtree(directory)          # unconditional
status = response.status_code     # inspected too late

On HTTP 409, the substrate lock means the registry row still exists. Destroying the local directory first leaves the registry pointing at a namespace that no longer exists — the orphaned mapping from the earlier closed row.

The old tests only checked final state, so they could not distinguish “directory removed after success” from “directory removed before status inspection.”

Exact fix

The ordering contract is:

DELETE(namespace)
  |
  +-- 200/404 --> rmtree(namespace_dir) --> success
  |
  +-- 409/429 and no retry used yet
  |       --> bounded backoff --> re-enter DELETE once
  |
  +-- any other status, or retry exhausted
          --> raise TeardownError; DO NOT rmtree

Core diff:

 response = transport.delete_namespace(namespace)
-if directory.exists():
-    shutil.rmtree(directory)
-status = int(response.status_code)
-if status == 200:
-    return TeardownResult(...)
-if status == 409:
-    continue
+status = int(getattr(response, "status_code", response))
+
+# CRITICAL: inspect status before any filesystem mutation.
+if status in (200, 404):
+    if directory.exists():
+        shutil.rmtree(directory)
+    return TeardownResult(
+        namespace=namespace,
+        status_code=status,
+        attempts=attempts,
+        directory_removed=True,
+    )
+
+if status in (409, 429) and attempts <= 1:
+    sleep(min(backoff_seconds * (2 ** (attempts - 1)), 2.0))
+    continue
+
+raise TeardownError(namespace, status, attempts)

The directory survives the 409 and is removed only after the retry returns 200.

Second-order lesson

The AC named two leftovers that were already reaped, while the prefix-blind class had grown from 32 to 41. The AC should be re-measured at HEAD and restated, not dropped.

Restate the AC to the live class, broaden the sweep gate to derive candidates from the union of registry rows and local directories, and verify the restated class reaches zero — not just the original two names.
