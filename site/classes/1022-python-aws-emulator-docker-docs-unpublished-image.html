Answer

The totalwindupflightsystems/totalstack fork is a LocalStack fork that ships an in-repo Dockerfile but no published Docker Hub image. Its docs and compose files still pinned the upstream localstack/localstack / localstack/localstack-pro images (and the fork name totalwindupflightsystems/totalstack doesn't exist on Docker Hub either — docker pull 404s). Fixed in 4 files:

1. docker-compose.yml — replaced the upstream image pin with a build from the in-repo Dockerfile:

services:
  localstack:
    container_name: "${LOCALSTACK_DOCKER_NAME:-localstack-main}"
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "127.0.0.1:4566:4566"            # LocalStack Gateway
      ...

2. docker-compose-pro.yml — same repoint for the Pro variant (was image: localstack/localstack-pro):

  localstack:
    container_name: "${LOCALSTACK_DOCKER_NAME:-localstack-main}"
    build:
      context: .
      dockerfile: Dockerfile

3. DOCKER.md - Removed the decorative badge: <img alt="Docker Pulls" src="https://img.shields.io/docker/pulls/localstack/localstack"> - Docker CLI example now builds from the repo before running (no pull):

$ docker build -t totalstack .
$ docker run --rm -it -p 4566:4566 -p 4510-4559:4510-4559 totalstack
  • Compose example now uses build: {context: ., dockerfile: Dockerfile} instead of image: localstack/localstack, and the note about "pulls the current nightly build… set the localstack image tag" was replaced with a note that the image is built from the current checkout (docker compose up --build to rebuild).
  • Dropped the entire dead "## Base Image Tags" section (semantics for latest/stable/<major>/<minor>/<patch> tags that the fork never pushes).

4. README.md — install is now checkout-based instead of pip install localstack (and upstream brew/binary CLI downloads, which also target upstream images):

git clone https://github.com/totalwindupflightsystems/totalstack.git
cd totalstack
make install-test

equivalent to:

pip install -r requirements-test.txt
pip install -e .

(make install-test in the Makefile runs pip install -r requirements-test.txt + pip install -e ".[test]" inside a fresh .venv.)
