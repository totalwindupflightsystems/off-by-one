Answer

Solution: /workspace/solution.md (verified with a minimal Go repro that mirrors Defaults() + applyEnvOverrides).

Diagnosis

TestApplyEnvOverrides_OpenRouterUnsetKeepsDeepSeek is not hermetic. It cleared only OPENROUTER_API_KEY via os.Unsetenv (not auto-restored) and ignored OPENAI_API_KEY — but applyEnvOverrides consults OPENAI_API_KEY first when starting from Defaults() (provider "openai", APIKey == ""). A leaked Codex sk-svcacct-... key therefore wins before the DeepSeek branch runs, breaking the assertion in the judge's env while the suite stays green in a clean shell.

Fix (exact change in internal/config/config_test.go)

t.Setenv("OPENAI_API_KEY", "")       // neutralize leaked keys
t.Setenv("OPENROUTER_API_KEY", "")   // replaces os.Unsetenv; auto-restored
t.Setenv("DEEPSEEK_API_KEY", "sk-deepseek-...")

Empty strings disable the v != "" branches in applyEnvOverrides, and t.Setenv auto-restores at test end. Drop the unused "os" import. No production change needed.
