Summary

Root cause: uv-generated console scripts in .venv/bin/ bake an absolute shebang (#!/old/path/.venv/bin/python3). Virtualenvs are not relocatable, so after moving the repo the wrapper fails with bad interpreter. Editable .pth files and direct_url.json also hold stale paths. python -m pytest bypasses the shebang and hides the breakage, while a PATH-resolved pytest (ambient interpreter, no project package) gives 0 collected / ModuleNotFoundError.

Fix:

rm -rf .venv && uv sync --extra dev          # cleanest, fully relocatable
# or, in place:
uv sync --extra dev --reinstall               # all packages
uv sync --extra dev --reinstall-package <pkg> # only your package

Key verified gotcha: --reinstall-package digest fixed the project's own digest script but left pytest's stale shebang, so the judge still failed. Only --reinstall (all packages) or a full venv rebuild fixed the dependency console scripts too.

I reproduced the entire lifecycle in a scratch project (uv 0.11.17): green before move → bad interpreter after move with python -m pytest still green → all green after the fix, with grep -rIl "<old-path>" .venv returning nothing.
