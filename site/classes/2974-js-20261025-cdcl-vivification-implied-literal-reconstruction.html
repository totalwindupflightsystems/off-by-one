CDCL SAT Solver with RUP-Checkable Clause Vivification

Environment: Node 20+ (verified on Node 22.23.2) · plain CommonJS, no dependencies. Deliverable: ~/solution/ — modular sources plus cdcl-vivify.js (single-file bundle) and SOLUTION.md (full write-up with the bundle embedded).

TL;DR

The soundness hinge is trail reconstruction:

To drop literal l from clause C, test RUP(C \ {l}): assume ¬(C \ {l}), let C propagate l, and require unit propagation to hit a conflict. Never assume ¬C.

A naive vivifier assumes ¬C, sees the conflict caused by C itself, removes l, and emits a non-RUP/non-RAT derivation that an independent checker rejects. The implementation below passes an independent RUP checker on pigeonhole and parity instances, with and without vivification, and the differential harness prints the exact counterexample.

1. Root-cause analysis

2.1 Soundness condition for removing one literal

For C = D ∨ l in formula F, replacing C by D is sound iff F ⊨ D, i.e. F ∧ ¬D is UNSAT. Since C is present, F ∧ ¬D forces l true (all of D false), and the step is RUP-checkable when F ∧ ¬D ⊢_UP ⊥. So the algorithm must assume ¬(C\{l}) — not ¬l, not ¬C — let C propagate l, then find a conflict, then emit D (add) before deleting C.

2.2 Why naive strengthening is unsound (circular reasoning)

Naive code sets all of C false (¬C). Unit propagation immediately conflicts because C itself is falsified, and it removes a literal. The conflict is circular. Concrete witness from the harness on php(5,4):

clause C             : [1,2,3,4]
naive removes        : 1
naive candidate C\l  : [2,3,4]
naive conflict trail : [-1,-2,-3,-4]        <-- all of C set false
independent checker  : REJECTED              <-- [2,3,4] is not RUP
correct test         : assume ~(C\l) = [-2,-3,-4]; C propagates 1; no conflict
                       => sound algorithm keeps 1

A valid step instead shows the removed literal propagated (not assumed), e.g.:

clause before       : [9,6,-3,5,10]
remove literal      : 9
clause after        : [6,-3,5,10]
reconstructed trail : [-6,3,-5,-10,9, ... ]   <-- 9 propagated here
falsified clause    : [-18,-14]

2.3 A second trap found during development

The restart check ran even when propagate() had just returned a fresh conflict. After backtrack(0) the stale conflict index was still set, and the next loop iteration interpreted a deep conflict as a level-0 conflict — emitting an empty clause that unit propagation could not reproduce. The independent checker caught it. Fix:

// buggy
if (conflictsSinceRestart >= restartInterval) { ... backtrack(0) ... }
// fixed
if (confl < 0 && conflictsSinceRestart >= restartInterval) { ... backtrack(0) ... }

2. Exact fix

2.1 Trail-reconstructing RUP and vivification (src/solver.js)

rupTrace(lits) {
  if (this.decisionLevel !== 0) this.backtrack(0);
  this.rupCalls++;
  const startTrail = this.trail.length;
  let conflict = false, conflictClause = null;

  for (const l of lits) {                       // assume ~(candidate clause)
    const val = this.value(l);
    if (val > 0) { conflict = true; break; }    // root-true => immediate conflict
    if (val < 0) continue;                      // already false
    this.newDecisionLevel();
    if (!this.enqueue(-l, -1)) { conflict = true; break; }
  }
  if (!conflict) {
    const ci = this.propagate();                // C propagates the removed literal
    if (ci >= 0) { conflict = true; conflictClause = this.clauses[ci].lits.slice(); }
  }
  const trail = this.trail.slice(startTrail);   // the reconstruction
  this.backtrack(0);
  return { rup: conflict, trail, conflict: conflictClause };
}

vivifyClause(idx) {
  const c = this.clauses[idx];
  if (c.deleted || c.lits.length < 2) return false;
  let changed = false, i = 0;
  while (i < c.lits.length && c.lits.length > 0) {
    const oldLits = c.lits.slice();
    const cand = oldLits.slice(0, i).concat(oldLits.slice(i + 1));
    const trace = this.rupTrace(cand);
    if (!trace.rup) { i++; continue; }          // not implied -> keep literal
    this.vivifyLog.push({ clause: oldLits, removed: oldLits[i], strengthened: cand,
                          conflictClause: trace.conflict, trail: trace.trail });
    this.proofAdd(cand);                        // RUP addition (C still present)
    this.proofDel(oldLits);                     // then delete the old clause
    this.replaceClause(idx, cand);
    changed = true; i = 0;
    if (cand.length === 0 || this.unsat) break;
  }
  return changed;
}

2.2 Independent RUP checker (src/drat.js, shares no solver code)

verifyRUP(lits) {
  this.assign.fill(0); this.trail.length = 0; this.qhead = 0;
  let conflict = false;
  for (const ui of this.units) {                 // active unit clauses are true
    const c = this.clauses[ui];
    if (!c.active) continue;
    if (!this.enqueue(c.lits[0])) { conflict = true; break; }
  }
  if (!conflict) {
    for (const l of lits)                        // assume the clause's negation
      if (!this.enqueue(-l)) { conflict = true; break; }
  }
  if (!conflict) conflict = this.propagate() >= 0;
  if (!conflict) { this.failed = { clause: lits.slice(), trail: this.trail.slice() }; return false; }
  return true;
}

addProofClause(lits) {
  const norm = normalizeClause(lits);
  if (norm.taut) return true;
  if (!this.verifyRUP(norm.lits)) return false;  // reject non-RUP additions
  this.addActiveClause(norm.lits);               // install only after verification
  return true;
}

4. Guarantees established

  • Every installed clause is checked before use — learned clauses are 1UIP/RUP; vivified clauses satisfy RUP(C\{l}) with the old C still present.
  • Every proof step is independently re-propagated by verify.js from the original CNF; no solver state is imported. Tampering with one literal of one learned clause is detected (test.js).
  • The pruned database remains refutation-complete on pigeonhole and Tseitin: vivified proofs reach and verify the empty clause while the active database shrinks (e.g. php(8,7): 16 474 → 13 405 literals; tseitin(13): 3 183 → 2 451).
  • Naive strengthening is demonstrably non-RAT, with the clause, circular trail, checker rejection, and the correct RUP(C\{l}) test printed side by side.
