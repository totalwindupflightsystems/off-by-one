Linearizable Lease Renewal Under Bounded Clock Skew and Reordering

Root-cause analysis

The unsafe design is a lease whose expiry is decided by a node’s local clock:

// unsafe
if node.localNow().Before(lease.Expires) {
    serveWrite()
}

With clocks that can differ by up to δ = 500ms, this breaks in two directions:

  1. Slow node, stale leader. Node A is 500ms behind. The real lease deadline has passed, but A.localNow() < lease.Expires, so A still believes the lease is valid. If A was the old leader and was partitioned during a failover, it may accept writes after a new leader has already granted the same key to another owner.
  2. Fast node, false expiry. Node B is 500ms ahead. The real lease is still valid, but B.localNow() > lease.Expires, so B may try to reassign the key too early.

Message reordering adds a second failure mode: an old lease-renewal or old write request can arrive after a newer election or a newer lease grant.

The fix must make every safety decision from a quorum of clocks, and must fence old operations by a monotonically increasing (term, leaseID) pair.

The runnable reference implementation is in:

  • ~/leasekv/leasekv.go
  • ~/leasekv/leasekv_test.go

Protocol and invariants

Assume each node’s clock C_i satisfies

|C_i - realTime| <= δ,  δ = 500ms

and choose lease duration D > 2δ.

For any quorum Q of clock samples, define:

lo = max(C_i for i in Q) - δ      // guaranteed lower bound on real time
hi = min(C_i for i in Q) + δ      // guaranteed upper bound on real time

Because each |C_i - realTime| <= δ:

lo <= realTime <= hi

The safety invariants are:

  1. Granting a conflicting lease requires lo > oldLease.Expires. Then real time when the new lease is committed is strictly after the old deadline.

  2. Serving a write under a lease requires hi <= lease.Expires. Then real time when the write is validated is before the deadline.

  3. Every lease grant and write is committed to a majority and carries a monotonic (Term, LeaseID). A node accepts a command only if its current term is not greater and the command’s lease ID is not older.

  4. A leader must see a majority with no higher term. Any higher term forces step-down before the decision.

  5. A local clock is never used to declare a lease expired. The only local-clock method in the code, BelievesLeaseValid, exists to demonstrate the bug in tests.

Exact fix — safety-critical code

1. Real-time bounds from a quorum

// bounds returns a guaranteed lower and upper bound for real time from a
// quorum of clocks. For every clock C_i, |C_i - now| <= skew, so
//
//  max(C_i) - skew <= now <= min(C_i) + skew.
func (c *Cluster) bounds(ps []probeResult) (lo, hi time.Time) {
    lo = ps[0].now
    hi = ps[0].now
    for _, p := range ps[1:] {
        if p.now.Before(lo) {
            lo = p.now
        }
        if p.now.After(hi) {
            hi = p.now
        }
    }
    return hi.Add(-c.skew), lo.Add(c.skew)
}

2. Quorum read must detect higher terms

// collect reads clock and lease state from the reachable nodes. At least a
// majority must answer. Responses are sorted in reverse ID order to model
// arbitrary network reordering; the order does not matter because the leader
// processes every response before deciding. A leader that sees any higher
// term must step down before it makes a decision.
func (c *Cluster) collect(leader *Node, key string) ([]probeResult, uint64, error) {
    leader.mu.Lock()
    baseTerm := leader.term
    leader.mu.Unlock()
    if !c.isReachable(leader.id) {
        return nil, baseTerm, ErrNoQuorum
    }

    ps := make([]probeResult, 0, len(c.nodes))
    for _, n := range c.nodes {
        if !c.isReachable(n.id) {
            continue
        }
        ps = append(ps, n.probe(key))
    }
    sort.Slice(ps, func(i, j int) bool { return ps[i].id > ps[j].id })

    var maxTerm = baseTerm
    for _, p := range ps {
        if p.term > maxTerm {
            maxTerm = p.term
        }
    }
    if maxTerm > baseTerm {
        leader.mu.Lock()
        if leader.term < maxTerm {
            leader.term = maxTerm
        }
        leader.mu.Unlock()
        return nil, maxTerm, ErrNotLeader
    }
    if len(ps) < c.Majority() {
        return nil, baseTerm, ErrNoQuorum
    }
    return ps, baseTerm, nil
}

3. Renewal: conflict only after quorum-proven expiry

func (c *Cluster) Renew(leaderID int, owner, key string, dur time.Duration) (Lease, error) {
    leader := c.nodes[leaderID]
    ps, term, err := c.collect(leader, key)
    if err != nil {
        return Lease{}, err
    }
    lo, _ := c.bounds(ps)
    cur, found := latestLease(ps, key)

    if found && cur.Owner != owner {
        // Strictly greater: at equality the deadline itself is still not
        // provably in the past.
        if !lo.After(cur.Expires) {
            return Lease{}, fmt.Errorf("%w: quorum lower bound %s <= expires %s",
                ErrLeaseBusy, lo.Format(time.RFC3339Nano), cur.Expires.Format(time.RFC3339Nano))
        }
    }
    if dur <= 0 {
        dur = c.leaseFor
    }
    expires := lo.Add(dur)
    if found && cur.Owner == owner && cur.Expires.After(expires) {
        // Never shorten an already committed lease on renewal.
        expires = cur.Expires
    }

    l := Lease{
        Key:     key,
        Owner:   owner,
        ID:      c.leaseSeq.Add(1),
        Term:    term,
        Expires: expires,
    }
    if err := c.replicateLease(l); err != nil {
        return Lease{}, err
    }
    return l, nil
}

4. Write: quorum upper bound plus (term, leaseID) fencing

func (c *Cluster) Put(leaderID int, owner, key, value string, leaseID uint64) error {
    leader := c.nodes[leaderID]
    ps, term, err := c.collect(leader, key)
    if err != nil {
        return err
    }
    _, hi := c.bounds(ps)
    cur, found := latestLease(ps, key)
    if !found || cur.Owner != owner || cur.ID != leaseID || cur.Term != term {
        return ErrLeaseInvalid
    }
    if hi.After(cur.Expires) {
        return ErrLeaseExpired
    }
    return c.replicatePut(term, key, value, owner, leaseID)
}

The fencing check on every replica is:

func (n *Node) preparePut(term uint64, key, owner string, leaseID uint64) (bool, uint64) {
    n.mu.Lock()
    defer n.mu.Unlock()
    if term > n.term {
        n.term = term
        n.votedFor = -1
    }
    if term < n.term {
        return false, n.term
    }
    cur, ok := n.leases[key]
    if !ok || cur.Term != term || cur.ID != leaseID || cur.Owner != owner {
        return false, n.term
    }
    return true, n.term
}

The commit path applies the same check before touching the KV state. This is what makes a delayed old write impossible to commit after a newer lease exists.

5. Election fences old leaders

func (c *Cluster) Elect(id int) error {
    if !c.isReachable(id) {
        return ErrNoQuorum
    }
    var maxTerm uint64
    for _, n := range c.nodes {
        if !c.isReachable(n.id) {
            continue
        }
        n.mu.Lock()
        if n.term > maxTerm {
            maxTerm = n.term
        }
        n.mu.Unlock()
    }
    newTerm := maxTerm + 1

    cand := c.nodes[id]
    cand.mu.Lock()
    cand.term = newTerm
    cand.votedFor = id
    cand.mu.Unlock()

    votes := 1
    for _, n := range c.nodes {
        if votes >= c.Majority() {
            break
        }
        if n.id == id || !c.isReachable(n.id) {
            continue
        }
        n.mu.Lock()
        if n.term < newTerm {
            n.term = newTerm
            n.votedFor = id
            votes++
        }
        n.mu.Unlock()
    }
    if votes < c.Majority() {
        return ErrNoQuorum
    }
    return nil
}

Safety proof with happens-before

Let G(L) be the commit point of a lease grant, i.e. the moment a majority has accepted and applied L. Let W(L) be the commit point of a write under L.

Claim 1: A conflicting lease is never granted before the old lease deadline in real time.

For conflicting owners, Renew requires lo > L_old.Expires from a quorum of clocks. Since lo <= realTime at the moment of the quorum read, and the lease grant is committed after that read,

realTime(G(L_new)) >= quorum read time >= lo > L_old.Expires

So G(L_new) happens after the old deadline.

Claim 2: A delayed old write cannot commit after a new conflicting lease.

Suppose W(L_old) attempts to commit after G(L_new). The write quorum Q_w and the lease quorum Q_new are both majorities, so

Q_w ∩ Q_new != ∅

At any node x in the intersection, L_new has been applied by the time G(L_new) completes. The write validation at x checks

cur.Term == term && cur.ID == leaseID

L_new has either a higher term or a higher lease ID than L_old, so x rejects the old write. Therefore W(L_old) cannot obtain a write quorum after G(L_new).

If instead W(L_old) did obtain a quorum before G(L_new), then its commit point is ordered before the new lease grant. Thus every W(L_old) is either rejected or linearized before G(L_new). There is no overlap between conflicting lease validity windows.

Claim 3: A stale leader cannot make progress even if its local clock says the lease is live.

Any leader operation requires a majority at the leader’s term. A successful election has already updated a majority to a higher term. Any two majorities intersect, so the stale leader’s quorum contains a node with a higher term. collect sees that higher term and returns ErrNotLeader; preparePut on that node also rejects the old term. The local clock belief is irrelevant.

Claim 4: Lease expiry is only detectable via a quorum read.

lo and hi are functions of quorum clock samples. Neither Renew nor Put calls LocalNow() for a decision. If a node is isolated, it cannot form a majority and cannot safely declare anything about expiry; it returns ErrNoQuorum.

These claims give linearizability: all writes are committed in (term, leaseID) order; conflicting leases are separated by a real-time deadline proven by a quorum; stale leaders and delayed messages are fenced by term and lease ID.

The three tests cover the required failure modes:

  1. TestStaleLeaderCannotWriteAfterFailover
    The old leader’s clock is -500ms. After the old lease deadline, it still believes the lease is valid. A new leader has already granted the key to another owner. The stale write fails with ErrNotLeader, and the old lease fails through the new leader with ErrLeaseInvalid.

  2. TestLeaseExpiryRequiresQuorumNotLocalClock
    The new leader’s clock is +500ms and says the old lease has expired. The quorum lower bound still has not passed the deadline, so a conflicting renewal is refused with ErrLeaseBusy until real time advances further.

  3. TestRenewalExtendsOnlyAndConflictsWaitForExpiry
    Same-owner renewal never shortens an existing lease. Conflicting owners wait until the renewed deadline plus clock uncertainty has passed.

Production integration notes

This repository is an executable reference model of the safety-critical protocol. In production, replace the in-memory prepare/commit transport with a real replicated log such as etcd/raft, hashicorp/raft, or a linearizable consensus service.

Keep these rules:

  • Store lease grants as committed log entries, not leader-local state.
  • Carry (Term, LeaseID) in every write and fence on both.
  • Never trust a single node’s clock to declare lease expiry.
  • Require a majority quorum read for the lo/hi bounds.
  • Monitor actual clock skew; if |C_i - realTime| > δ, stop granting new leases until clocks recover.
  • Choose D > 2δ; here D = 8s with δ = 500ms.
  • Renew well before Expires - δ with a retry loop so clients never rely on a nearly expired lease.
  • A stale leader that cannot reach a majority must stop serving immediately; safe failure is better than a stale write.
