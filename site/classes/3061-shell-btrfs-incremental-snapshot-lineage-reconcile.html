Btrfs Incremental-Snapshot Lineage Reconciliation

Problem class: shell-btrfs-incremental-snapshot-lineage-reconcile · Environment: bash · Version: 5

A read-only reconciler that consumes out-of-order Btrfs subvolume / send-receive inventory records from many hosts and produces a deterministic repair plan naming the unique safe incremental-send base for every target. It never mutates state.

1. Root-cause analysis

The naive approach — trust the inventory as an ordered list and match snapshots by path — fails for five independent reasons:

  1. Records arrive out of order and duplicated. Indexing by arrival position or last-write-wins is non-deterministic and can pair a target with a base that a later record disproves. Records must be folded by identity.
  2. Subvolume paths are not identities. Snapshots get renamed and names get reused across hosts/deletions; path matching silently glues unrelated lineages. The Btrfs UUID is the identity; path is only a label.
  3. Ancestry spans hosts through received_uuid. A btrfs receive subvolume gets a new UUID but records received_uuid = <sent UUID>. A correct search must follow both parent_uuid and received_uuid, resolved to content identity.
  4. Interrupted transfers / partial records. Missing generation/cgen, dangling parent/origin UUIDs, and truncated lines must be classified — treating them as "no ancestor" silently forces a full send or trusts an unverifiable base.
  5. Ambiguity and stale generations must be rejected, not guessed. Disagreeing parent/origin records or two equally-near branches ⇒ no unique base; a base not strictly older than the target ⇒ stale generation.

Fix in one sentence: fold every record by UUID (detecting conflicts), collapse received_uuid chains into a content identity, BFS up the content ancestry, and accept a base only when the nearest local read-only ancestor is unique and strictly older — otherwise emit ambiguous, stale, invalid, or full.

2. The exact fix — reconcile.sh

Full script is in /workspace/reconcile.sh. Key logic:

  • Parse each JSONL line with jq (-re so @tsv emits real tabs); malformed lines are recorded and skipped, never fatal.
  • Fold records per UUID: first sorted value wins, and disagreeing parent_uuid / received_uuid / host set conflict flags; generations take the max; validate gen >= cgen and reject self-parents.
  • Resolve content: resolve(x) follows received_uuid chains to a stable content id.
  • BFS ancestry: from the target, traverse both parent_uuid and received_uuid edges; at each depth look for local read-only candidates whose content id matches. The first depth with candidates is the nearest; >1 distinct matched content ⇒ ambiguous; any candidate with gen >= target.gen is excluded and, if it is the only option, reported stale.
  • Deterministic output: all arrays are explicitly sorted (TSV by uuid,path; plan by host,path,uuid) before awk/jq, so output is byte-identical across runs.

Output contract (.targets[]): incremental (unique base), full, ambiguous, stale, invalid, not-readonly; .diagnostics[] lists parent-conflict, received-conflict, stale-generation, partial-record, cycle, malformed-line, etc. .mutation is always false.

chmod +x reconcile.sh
./reconcile.sh inventory.jsonl > plan.json    # or: cat inventory.jsonl | ./reconcile.sh
