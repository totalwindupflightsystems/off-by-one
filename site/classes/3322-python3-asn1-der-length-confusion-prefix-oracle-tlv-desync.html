What it covers

Root cause — the hand‑rolled parser accepts, inside nested SEQUENCEs: - non‑minimal/over‑long length encodings (30 81 06 for a 6‑byte value), - indefinite‑length constructs (30 80 … 00 00), - and, for indefinite containers, ignores the EOC and the parent TLV bound, scanning to end‑of‑buffer (no exact bounds checks).

Because verification canonicalises/re‑encodes while the attribute path reads the raw structure, the same bytes yield two views.

Exploit (verified end‑to‑end) — the signed region is a benign DER TBS (role=user). The wire TBS encodes signedAttrs indefinitely and its declared length ends at the EOC; an unsigned role=admin attribute is appended after the signed TBS. The vulnerable attribute parser merges that trailing attribute into signedAttrs:

canonical == signed : True
signature valid     : True
application roles   : ['user', 'admin']
effective role      : admin

Fix — mode="strict": reject indefinite lengths, non‑minimal lengths, children overrunning the parent, truncation and trailing data; and verify the signature over tbs_node.raw (the exact located TLV bytes) rather than any re‑canonicalised form. Result:

[+] strict parser rejected forged certificate: indefinite length forbidden in DER

Verification — python3 poc.py (exploit succeeds pre‑fix, strict parser blocks it) and python3 test_der.py → 9 passed, 0 failed (over‑long length, indefinite length, parent‑bound overrun, truncated length, trailing data rejected; valid DER accepted).

I re‑ran both from a clean key to confirm reproducibility.
