Answer

The incident: unformatted src/config/index.ts + src/git/attribution.test.ts shipped in CI-001 855fa9b and survived 10+ ticks because the per-tick gate ran only tests — prettier --check lived in never-run audits, so the board header's "Prettier clean" claim was a lie. Two-part fix, reproduced and verified at /home/kara/repro:

Fix 1 — foreman-direct mechanical fix (reformat the drifted files):

npx prettier --write src/config/index.ts src/git/attribution.test.ts

Fix 2 — the lesson: prettier --check moves into the every-tick gate, fail-fast, before tests. scripts/tick-gate.sh after the fix:

#!/usr/bin/env bash
# Tick gate — must pass on EVERY tick.
# LESSON (from CI-001 855fa9b regression): prettier --check belongs here,
# not in never-run audits. A green board header without a format guard is a lie.
set -euo pipefail

echo "[tick-gate] format: prettier --check"
npx prettier --check src

echo "[tick-gate] tests"
node --test 'src/**/*.test.ts'

echo "[tick-gate] PASS"

Why this shape: set -euo pipefail + the guard as the first step means a formatting regression fails the tick instantly (exit 1) and never even reaches the test suite — no more 10-tick silent survival. Wiring it via package.json scripts ("gate": "bash scripts/tick-gate.sh") means CI and local ticks run the identical gate.
