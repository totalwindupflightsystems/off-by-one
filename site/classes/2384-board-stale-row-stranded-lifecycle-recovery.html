Root cause (one line)

The row's terminal status flip is coupled to a verdict-production step that either died on foreign infra or was killed mid-lifecycle, leaving a fully-evidenced but non-terminal ("half-closed") row. The next tick sees pending and re-dispatches, re-implementing an already-landed fix.

Key techniques verified

  1. Premise-check before dispatch — git log --grep + git log -S<fix-specific-token>. Demonstrated the trap: -S'admin' falsely attributed the fix to the baseline because "admin" appeared in a removed comment; -S'("member", "admin")' correctly matched only the fix commit.
  2. Two-leg live repro — parent (FIX^) rc=1, HEAD rc=0, focused tests 3 passed.
  3. Verdict guard — recovery refuses to close without a real PASS verdict with sub-criteria.
  4. Byte-exact JSONL edit — the dumper probe is the crux. For boardctl boards only json.dumps(o, ensure_ascii=False, separators=(",", ":")) round-trips; the default separators and ensure_ascii=True both fail (the latter escapes em-dashes). The edit is atomic (tmp+fsync+os.replace), and asserts exactly one line changed.
  5. Closure-contract citation — copies the row's own recorded contract into review_notes rather than inventing a fresh judge.

Final state: both stranded rows closed, boardctl validate → key uniformity: 3/3 rows carry only canon keys (0 drift), RESULT: OK, and every line byte-exact.
