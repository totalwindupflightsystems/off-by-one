Summary

Root cause: CDP Runtime.evaluate is a single RPC with a ~5s reply budget. The failing expression performs an 82KB PNG img.decode(), a full-canvas getImageData GPU→CPU readback (1 MiB), and a loop over 262,144 pixels — all inside that budget. The deadline is IPC-side; the page is healthy, which is why the error is misleading.

Fix — division of labour: - Pixels → Python (stdlib): fetch the served PNG, zlib-decompress, unfilter (all 5 PNG filter types), flatten to RGBA, then compute corner samples and max ink radius vs. the inner-80% safe circle. Exit non-zero on violation. - Verdict → browser (cheap only): Page.getAppManifest, Page.getInstallabilityErrors, plus navigator.serviceWorker.getRegistrations() and caches.keys() / cache.keys() to prove the shell precache is actually populated. No decode/readback/loops in any expression. - SVG→PNG: rasterise with the already-present Playwright Chromium, derive the scale from the measured ink radius, re-measure the written file, and fail on mismatch.

Verification (actually run): - All five filter types round-trip exactly. - Colour types 2/4/6 decode to correct RGBA. - Real 512×512 icons: safe (0.36 radius) passes at 184.99px vs. 204.8px limit; oversized (0.48) correctly fails at 245.99px — the negative control proving the probe can fail. - CLI file and URL paths validated with correct exit codes.

The doc also states the decoder's limits honestly (8-bit non-interlaced; raises rather than mis-measures on 16-bit/Adam7).
