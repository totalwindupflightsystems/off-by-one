Answer

Solution: move the synthetic sk- fixture, then squash the unpushed history

Root cause

engine/push_secrets.py does not scan the final tree. scan_push_range() runs:

git log --no-ext-diff --diff-merges=first-parent -p --format= <remote_sha>..<local_sha>

and checks every added line in the outgoing history. If the first scan misses, it removes quote-concatenation glue and scans again:

_CONCAT_GLUE = re.compile(r"""["']\s*\+\s*["']""")
glued = _CONCAT_GLUE.sub("", content)
label = _first_match(glued)

The relevant rules are:

# push-check: needs at least 20 characters after "sk-"
re.compile(r"\bsk-[A-Za-z0-9_-]{20,}"), "API key"

# redactor: needs at least 12 characters after "sk-"
re.compile(r"\b(?:sk|ghp|glpat)-[A-Za-z0-9_-]{12,}\b")

The failing fixture built a split token whose reassembled body was at least 20 characters, so _CONCAT_GLUE rejoined it and push-check reported exactly:

PUSH REFUSED: API key found in outgoing commit history.

A follow-up commit deleting or shortening the fixture does not help while the earlier bad commit remains in remote_sha..local_sha, because the earlier added line is still scanned.

Do not weaken _SECRET_PATTERNS, add an allowlist, or add a gitleaks suppression. Move the fixture and rewrite the unpushed history.

Exact fixture fix

Use a synthetic token with 12–19 characters after sk-. A 15-character body satisfies the redactor’s {12,} rule while staying below push-check’s {20,} rule.

In tests/test_spec_alignment.py, inside test_secret_bearing_checker_output_is_redacted, use:

"secret = 'sk-' + 'live-1234567890'\n"

The joined token is:

sk-live-1234567890

That is sk- plus 15 characters after the prefix:

  • redactor {12,} → fires, producing [REDACTED]
  • push-check {20,} → does not fire

The string concatenation may remain: it no longer reassembles into a token long enough to match the push scanner.

Rewrite the unpushed commits

Only do this if the affected commits have never been pushed. First confirm the base and that the rewrite is a fast-forward:

cd /path/to/gitreins
git fetch origin

BASE=$(git rev-parse origin/main)
# In the recorded incident the base was 55168c4b.

git merge-base --is-ancestor "$BASE" HEAD
git log --oneline "$BASE"..HEAD

Apply the fixture change, then stage it. Staging before the soft reset ensures the shortened token is in the squashed index even if the fixture edit was not yet committed:

git add tests/test_spec_alignment.py

git reset --soft "$BASE"
git add tests/test_spec_alignment.py

# Sanity check: only intended files should be staged.
git diff --cached --stat "$BASE"

Commit the whole outgoing change as one clean commit:

cat >/tmp/gitreins-gr154-msg.txt <<'EOF'
feat: opt-in Auger spec-alignment guard (GR-154)

Fixture: use a 15-character body after the sk- prefix so the redactor's
sk-[A-Za-z0-9_-]{12,} rule still fires while push-check's
sk-[A-Za-z0-9_-]{20,} rule stays clean.

The scanner audits added lines across the entire outgoing range, so the
pre-fix commits are squashed here; nothing in this range was pushed.
EOF

git commit -F /tmp/gitreins-gr154-msg.txt

This leaves a single commit directly on top of the remote base. The pre-fix line never appears in any added-line diff of the outgoing range.

Verification

NEW=$(git rev-parse HEAD)

# Exactly one outgoing commit, directly on the remote base.
git rev-list --count "$BASE".."$NEW"          # 1
git log --oneline "$BASE".."$NEW"

# Fixture tests still prove redaction.
python -m pytest -q tests/test_spec_alignment.py
# 7 passed

# The authoritative pre-push check.
gitreins push-check "$NEW" "$BASE"
# PUSH SECRET CHECK: clean

If the installed gitreins binary is unavailable, run the source CLI:

python -m gitreins push-check "$NEW" "$BASE"

Then push normally — no force is needed because the rewritten commit is still a fast-forward of the remote base:

git push origin HEAD:main

For the recorded fix, the outgoing range was 55168c4b..8fa5a67d:

python -m pytest -q -o addopts='' tests/test_spec_alignment.py
# 7 passed

python -m gitreins push-check 8fa5a67 55168c4b
# PUSH SECRET CHECK: clean

The later exact-head CI run 41236012894 succeeded, and the push fast-forwarded to <organization>/gitreins main.

Recurrence rule

For synthetic credential-shaped fixtures:

  • Keep the body after sk- in the safe window 12–19 characters when testing redaction.
  • Do not rely on splitting a long token across + concatenation; push-check explicitly rejoins that pattern.
  • Remember that removing a fixture in a later commit does not clear the scanner while the earlier commit is still in the pushed range. Squash unpushed history instead.
  • If the offending commit is already published, do not rewrite silently; treat it as a history/incident problem and coordinate.
