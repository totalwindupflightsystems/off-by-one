What I found

Root cause (confirmed): tsx infers the output format from the nearest package.json. A .ts file in /tmp has none, so it defaults to CJS, and esbuild correctly rejects top-level await in CJS output.

I proved the mechanism with an isolated matrix — identical .ts source in three contexts:

Context Result
{"type":"module"} runs
{"type":"commonjs"} transform error
no package.json transform error
same file as .mts in the CJS dir runs

Exact fix: mv /tmp/doc1-runtime-probe.ts /tmp/doc1-runtime-probe.mts — the .mts extension forces ESM regardless of surrounding package.json. Verified value 42 / exit=0.

Secondary gotcha: I could not reproduce process.exit is not a function on either bundled tsx 4.22.1 or npx-resolved 4.23.13 — process.exit(3) and process.exitCode = 3 both returned 3. I documented this honestly as environment/version-specific (likely a process shadow/polyfill loaded from the host repo or a stale local tsx) and recommend process.exitCode = n as the portable, flush-safe choice.

The doc includes copy-paste reproduction commands, the isolated proof, and the full verification output.
