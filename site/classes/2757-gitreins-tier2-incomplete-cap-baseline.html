Treating a cap-class GitReins Tier 2 INCOMPLETE on a merged baseline

Task: DF-HERMES-DAGGER-19 (fix SHA already an ancestor of master). Situation: async GitReins re-judge under a raised max_time=120m cap returned Tier 2 INCOMPLETE a second time (2h wall clock, cut during the guard leg). The partial verdict nevertheless confirmed implementation present, 5 tests PASS at HEAD, and RED-proof vs the parent commit.

1. Decision

Question Answer
Is INCOMPLETE a failure? No. It is a first-class, structurally valid non-verdict.
Revert / unmerge the fix? No. The fix commit is an ancestor of master; the baseline is authoritative.
Move the task back to in_progress / reopen? No.
Claim a fresh Tier 2 PASS? No. INCOMPLETE is explicitly not a clean verdict.
Carry the merged baseline forward? Yes.
guard_result? PASS (kept), grounded in the corroborated partial.
Block delivery? No for a cap-class INCOMPLETE; escalate only content-class.
Next action Record cause=cap; resume only the unfinished guard leg with a per-leg budget.

One-line rule: a cap-class INCOMPLETE on an already-merged tree is a non-destructive baseline carry-forward, not a failure and not a pass.

Anti-patterns

  • INCOMPLETE → FAIL (destructive revert of an audited merge).
  • Re-running the entire Tier 2 with a bigger cap (cuts again; see §2).
  • INCOMPLETE → PASS (over-claims a clean verdict).
  • Leaving the merged task blocked/in_progress (churn).

2. Root-cause analysis

  1. The cap is global and the run is not resumable. max_time applies to the whole Tier 2 run; the guard leg is the expensive tail. 120m == 2h, so it is cut exactly at the cap; each retry re-derives earlier legs from zero, so raising the cap only moves the cut point → INCOMPLETE again.
  2. INCOMPLETE is valid but not clean. Helix audit step 6 is "GitReins Verdict — Tier 1 guard results + Tier 2 verdict (COMPLETE/INCOMPLETE)"; validateGitReinsVerdict accepts exactly those two strings. The CLI warns review incomplete; do not treat as a clean verdict. It is absence of a verdict, never a negative one.
  3. The baseline is already fixed in history. git merge-base --is-ancestor <fix> master is true; a judge-side operational failure cannot retroactively invalidate a landed, previously-verified merge.
  4. The guard leg's substance was captured before the cut. Missing piece is bookkeeping completeness, not correctness data.

Root cause = (a) non-resumable, globally-capped judge harness + (b) no typed cause and no explicit foreman rule for cause=cap on merged trees.

3. Exact fix

3.1 Typed cause + resumability (pkg/audit/chain_validators.go)

The real struct (from DWARF, size 80) is Tier1Passed bool, Tier1Checks []string, Tier2Verdict string, Tier2Findings []string, VerdictTime time.Time. Add:

type GitReinsVerdictEvidence struct {
    Tier1Passed   bool
    Tier1Checks   []string
    Tier2Verdict  string      // "COMPLETE" | "INCOMPLETE"
    Tier2Findings []string
    VerdictTime   time.Time

    // NEW
    Cause     IncompleteCause `json:"cause,omitempty"`     // cap | eval_timeout | evidence | invalid_guard
    Resumable bool            `json:"resumable,omitempty"`
    NextLeg   string          `json:"next_leg,omitempty"` // e.g. "guard"
}

type IncompleteCause string

const (
    CauseNone         IncompleteCause = ""
    CauseCap          IncompleteCause = "cap"
    CauseEvalTimeout  IncompleteCause = "eval_timeout"  // integration.ErrGitReinsEvalTimeout
    CauseEvidence     IncompleteCause = "evidence"
    CauseInvalidGuard IncompleteCause = "invalid_guard"
)

Keep INCOMPLETE accepted, but force a cause:

// inside validateGitReinsVerdict
if ev.Tier2Verdict == "INCOMPLETE" && ev.Cause == CauseNone {
    errs = append(errs, "incomplete tier2 verdict has no cause")
}

3.2 Map the client error (pkg/integration/gitreins_client.go)

func incompleteCause(err error) audit.IncompleteCause {
    switch {
    case errors.Is(err, ErrGitReinsEvalTimeout):
        return audit.CauseEvalTimeout // cap/deadline class
    case errors.Is(err, ErrGitReinsInvalidGuard):
        return audit.CauseInvalidGuard
    default:
        return audit.CauseEvidence
    }
}

func capIncomplete(done *audit.GitReinsVerdictEvidence, next string) audit.GitReinsVerdictEvidence {
    return audit.GitReinsVerdictEvidence{
        Tier1Passed:   done.Tier1Passed, // guard facts survive the cut
        Tier1Checks:   done.Tier1Checks,
        Tier2Verdict:  "INCOMPLETE",
        Tier2Findings: done.Tier2Findings,
        VerdictTime:   time.Now().UTC(),
        Cause:         audit.CauseEvalTimeout,
        Resumable:     true,
        NextLeg:       next,
    }
}

Budget fix: make max_time per leg (guard leg gets its own budget) and return NextLeg="guard" on a cut; retries run only the missing leg.

3.3 Foreman policy (Go)

type Action string

const (
    ActionPass      Action = "pass"
    ActionCarryFwd  Action = "carry-forward-baseline"
    ActionResumeLeg Action = "resume-unfinished-leg"
    ActionEscalate  Action = "escalate-human"
)

type Disposition struct {
    Action Action
    Revert bool
    Reopen bool
    Block  bool
    Reason string
}

// Invariant: INCOMPLETE is never FAIL and never a clean PASS.
func Classify(v GitReinsVerdictEvidence, merged bool) Disposition {
    switch v.Tier2Verdict {
    case "COMPLETE":
        return Disposition{Action: ActionPass, Reason: "complete tier2 verdict"}
    case "INCOMPLETE":
        capClass := v.Cause == CauseCap || v.Cause == CauseEvalTimeout
        switch {
        case merged && capClass:
            return Disposition{Action: ActionCarryFwd,
                Reason: "cap-class INCOMPLETE on merged baseline: retain prior verdict; no revert/reopen; schedule resumable guard-leg rerun"}
        case merged:
            return Disposition{Action: ActionEscalate,
                Reason: "non-cap INCOMPLETE on merged baseline: baseline stands; escalate evidence gap"}
        default:
            return Disposition{Action: ActionResumeLeg,
                Reason: "INCOMPLETE before merge: no verdict; resume unfinished leg, do not fail"}
        }
    default:
        return Disposition{Action: ActionEscalate, Block: true,
            Reason: "structurally invalid tier2 verdict"}
    }
}
