TR-340 — Stop the router's own gate verdicts from opening provider circuits

Problem class: python-circuit-breaker-failure-classification Primary file: scripts/router_server.py Shared taxonomy: scripts/router_circuit.py (FAILURE_CLASS_MAP) Regression test: tests/test_proxy_circuit_hygiene.py (TR-182) Related: TR-172 (placeholder-identity guard), TR-340 (this bug)

1. Symptom

Over a 17-minute window the router proxy opened:

  • 22 (provider, model) pair breakers across 12 unrelated providers, and
  • 5 provider-wide breakers,

…while the independent health probe simultaneously reported 22/28 providers OK. A breaker system that trips healthy providers is by definition consuming a non-failure signal as a failure.

Representative breaker record at unmodified HEAD:

provider=deepseek model=deepseek-chat        class=api_down cooldown=1800 reason="registry-missing"
provider=deepseek model=deepseek-reasoner    class=api_down cooldown=1800 reason="registry-missing"
provider=deepseek model=deepseek-v4.1-flash  class=api_down cooldown=1800 reason="registry-missing"

The reason is not an upstream error. It is the router's own gate verdict — the message the router emits when it refuses/cannot open a hop:

  • 503 no open hop for this request
  • no-hops
  • unservable-rating
  • registry-missing

2. Root-cause analysis

Two independent defects compounded.

2.1 The failed-hop call site passes router prose as if it were an upstream error

When the hop ladder exhausts, the failed-hop path forwards the raw gate verdict as the reason into the circuit-recording path (_proxy_record). That prose describes a routing decision, not a provider failure. The pair on which the ladder happened to be standing is irrelevant to the verdict and may be perfectly healthy.

2.2 _circuit_class() had a hard api_down fallback and only substring heuristics

At HEAD (schematically):

def _circuit_class(reason):
    r = (reason or "").lower()
    if "timeout" in r:
        return "overload"
    if "429" in r:
        return "quota_window"
    return "api_down"          # <-- HARD fallback, 1800s cooldown

Any text that is not literally a timeout/429 becomes the hardest class. registry-missing, no-hops, etc. therefore fell straight through to api_down, giving a 30-minute cooldown on an innocent pair.

The shared taxonomy in scripts/router_circuit.py already maps positive failure kinds (e.g. 5xx-overloaded) to classes, but _circuit_class never consulted it, so even genuine taxonomy kinds were mis-bucketed as api_down.

2.3 The existing TR-172 guard did not cover this

_proxy_record already had a placeholder-identity guard:

if provider == "none" or model == "none":
    return

That protects the synthetic none identity only. The gate verdicts were being recorded against real pairs, which the guard never touched.

2.4 Why it spread so fast

Every ladder attempt re-reported the same router-level gate state, but each attempt stood on a different pair, so each hop minted a new pair breaker. A single unservable registry therefore fanned out into 22 pairs / 12 providers / 5 provider-wide breakers in 17 minutes, independent of provider health.

2.5 What must not change (the TR-182 trap)

tests/test_proxy_circuit_hygiene.py pins the unknown-text default:

assert _circuit_class("connection refused") == "api_down"
assert _circuit_class("upstream down")     == "api_down"
assert _circuit_class("")                  == "api_down"

So the api_down default must stay hard. Only positively identified router-generated shapes may be dropped, and only taxonomy kinds already in FAILURE_CLASS_MAP may be reclassified.

3. Exact fix

All changes are in scripts/router_server.py; scripts/router_circuit.py is not modified. router_server already imports router_circuit.

3.1 Add the router-generated predicate

# scripts/router_server.py

# TR-340: the router emits its own "gate verdicts" when the ladder cannot
# open a hop.  They are ROUTING DECISIONS, not upstream API failures, and must
# never open a breaker on a real (provider, model) pair.
_ROUTER_GATE_MARKERS = (
    "no open hop for this request",
    "no open hop",
    "no-hops",
    "unservable-rating",
    "registry-missing",
)


def _is_router_generated(reason):
    """True iff *reason* is one of the router's own gate verdicts."""
    if not reason:
        return False
    r = reason.lower()
    return any(marker in r for marker in _ROUTER_GATE_MARKERS)

3.2 Consult the shared taxonomy first in _circuit_class()

def _circuit_class(reason):
    # (1) A taxonomy KIND (e.g. "5xx-overloaded") is authoritative: let the
    #     shared table classify it instead of falling through to api_down.
    if reason in router_circuit.FAILURE_CLASS_MAP:
        return router_circuit.FAILURE_CLASS_MAP[reason]

    # (2) Upstream prose heuristics (unchanged).
    r = (reason or "").lower()
    if "timeout" in r:
        return "overload"
    if "429" in r:
        return "quota_window"

    # (3) Unknown text keeps the HARD default.  Do NOT soften this:
    #     tests/test_proxy_circuit_hygiene.py (TR-182) pins it.
    return "api_down"

reason in router_circuit.FAILURE_CLASS_MAP is an exact key test, so prose such as "connection refused"/"upstream down"/"" still reaches step (3) and returns api_down.

3.3 Drop router-generated reasons before any record-failure call

In the _proxy_record circuit block, add the guard immediately after the existing TR-172 identity guard and before classification or any record-failure invocation:

def _proxy_record(self, provider, model, reason, ...):
    # TR-172: synthetic placeholder identity from health probes.
    if provider == "none" or model == "none":
        return

    # TR-340: the router's own gate verdicts are decisions, not upstream
    # failures.  The TR-172 guard only covered the placeholder "none"
    # identity, so REAL pairs were left unprotected.  Bail out BEFORE any
    # classification / record-failure call.
    if _is_router_generated(reason):
        return

    klass = _circuit_class(reason)
    # ... existing cooldown lookup ...
    # record-failure --provider <provider> --model <model> \
    #                --class <klass> --reason <reason> --cooldown <cooldown>

python3 -m pytest -q tests/ -k "circuit or proxy"

Expected: (1) green; (2) green; (3) shows both _is_router_generated (called before _circuit_class/record-failure) and the FAILURE_CLASS_MAP lookup in _circuit_class.

4.4 Acceptance criteria

  • A router gate verdict (no open hop…, no-hops, unservable-rating, registry-missing) recorded against a real pair opens 0 pair breakers and 0 provider-wide breakers.
  • A genuine upstream failure (connection refused, upstream down, empty/unknown prose) still classifies as api_down and opens the breaker with the existing cooldown.
  • A failure kind present in router_circuit.FAILURE_CLASS_MAP (e.g. 5xx-overloaded) is classified by that table.
  • No change to FAILURE_CLASS_MAP or to cooldowns.

5. Notes / rollout

  • The predicate is intentionally positive-match only. New gate vocabulary must be added to _ROUTER_GATE_MARKERS; the default path is never widened.
  • Keep the early return in _proxy_record before both _circuit_class and the record-failure call. Doing the check only in the class function would still let gate text be recorded (as whatever class) and would not protect real pairs.
  • If a future caller wants to record a router-side condition deliberately, it should do so against the synthetic none identity (already denied by TR-172) rather than a real (provider, model) pair.
