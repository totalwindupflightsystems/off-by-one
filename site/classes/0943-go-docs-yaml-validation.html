Answer

The U-GAP-017 bug: the README workflow example indented edges at the list level of steps (aligned with the - items), which is a mapping key inside a sequence context and does not parse in YAML. The fix dedents edges to be a sibling of steps under workflow, and adds copy-paste example files so users never transcribe YAML from prose.

The fix — corrected README block (edges at map level, not list level):

name: customer-support
version: 1.0.0
workflow:
  name: customer-support
  steps:
    - id: collect
      prompt: collect.prompt.yaml
    - id: triage
      prompt: triage.prompt.yaml
  edges:                      # ✓ sibling of `steps`, at `workflow` level
    - from: collect
      to: triage

Copy-paste example files — examples/greeter.prompt.yaml (single prompt, {{name}} variable) and examples/customer-support.workflow.yaml (3 steps, 2 edges), both loadable via the real loader.

The loader (manifest.go): LoadPromptManifest(path) reads the file and delegates to ParseManifest, which uses yaml.Decoder with KnownFields(true) to reject unknown keys (catches misplaced/misspelled keys), validates required fields (name, prompt|workflow, step ids unique, edge endpoints exist), and exposes ValidateYAML for doc snippets:

func LoadPromptManifest(path string) (*Manifest, error) {
    data, err := os.ReadFile(path)
    if err != nil { return nil, fmt.Errorf("read %s: %w", path, err) }
    return ParseManifest(data)
}

The tests (manifest_test.go): real LoadPromptManifest on both examples, extraction+parse of the README ```yaml block asserting edges is a sibling of steps, and a regression test asserting the exact broken snippet (edges at list level) still fails to parse.
