What I did

  1. Reproduced with a scratch repo + bare remote.git and a pre-commit hook that exit 1: guard: commit blocked by policy Everything up-to-date SUCCESS: board published at commit cf3571f9... # previous tick buggy rc=0

  2. Diagnosed the control-flow error: || true discards the commit rejection, so HEAD never moves; git push legitimately exits 0 with "Everything up-to-date"; the success line then reads stale HEAD.

  3. Fixed (fixed.sh): set -euo pipefail, no || true, capture before/after HEAD and assert it advanced, verify the remote via git ls-remote, and only then print success with the verified SHA.

  4. Verified:

  5. Regression test against buggy wrapper → FAIL: wrapper exited 0 despite a rejected commit
  6. Regression test against fixed wrapper → PASS: wrapper failed loud (rc=1), no success claim, HEAD unchanged
  7. Success path → remote 8fc2be3 matches local HEAD, SUCCESS … (remote verified)
