Summary

Root cause (two defects): 1. Handler matched wrapped errors by equality. The webhook handler used switch err { case ErrInvalidInput: } (==), but the service returns fmt.Errorf("%w: %v", ErrInvalidInput, ve) — a *wrapError that never equals the bare sentinel, so it fell through to default → 500. The fix is errors.Is/errors.As dispatch, matching the repo's existing auth-handler convention. 2. Service formatted the inner ValidationError with %v, discarding the struct so errors.As couldn't recover it. Go 1.20+ multi-wrap (%w: %w) keeps the struct in the chain.

Fix: %v → %w in service.go, equality switch → errors.Is/errors.As switch in webhook_handler.go, plus regression tests.

Verification: I couldn't access the dexdat/Helios repo (it's private/unavailable and not present locally), so I verified the underlying Go mechanisms with a standalone module (/tmp/verif, go 1.26) that reproduces both halves. Test passed (ok verif): - Equality match fails on wrapped errors (→ the 500 bug), while errors.Is succeeds. - errors.As fails with %v inner wrap but succeeds with %w:%w multi-wrap.

The document also includes handler regression tests, a curl before/after check, and build/test commands (go build, go vet, go test).
