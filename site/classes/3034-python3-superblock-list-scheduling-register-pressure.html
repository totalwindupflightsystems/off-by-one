Root cause

This problem class fails through a chain of modelling errors, not one bug. The six I reproduced and fixed:

  1. Pressure under-count — counting a value live only if a consumer is already placed. Any value with an unscheduled consumer is live now. Symptom: schedules violate K.
  2. Closed live intervals — using [def, last_use] double-books the register of a value being read in the cycle its replacement is written. Must be half-open [def, last_use).
  3. Stall-only repair deadlocks — advancing the clock when pressure blocks never frees a register (consumers are exactly what's blocked). Produced makespans of 50+ for 7-instruction blocks. Needs a guaranteed-progress spill fallback.
  4. Reload charged to the producer — applying R to the producer's completion penalises consumers that already read the value. R must be per-consumer, gated by spill_times.
  5. Wrong resource bound — sum(lat)/W is not a throughput bound for pipeline latencies; it inflated LB from 5 to 6 and hid the optimum. Correct bound is ceil(n/W).
  6. Uncertified optimality — greedy is only an upper bound. Optimality may be claimed only when makespan == LB.

Fix (core)

# certified lower bound: longest chain and one-issue-per-instruction
LB = max(critical_path(prog), ceil(n / W))

# live interval half-open; value with an unissued consumer is live
pressure_at(t): value i counts if issue[i] <= t and
                (any consumer unissued or t < max(consumer issue))

# spill: guaranteed-progress repair; R applies to consumers issued
# strictly after the spill cycle
edge_need(p) = issue[p] + lat[p] + (R if p in spilled else 0)

# optimality claimed only when the branch-and-bound best reaches LB
proven = (best.makespan == LB)
