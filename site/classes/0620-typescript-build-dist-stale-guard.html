typescript-build-dist-stale-guard

Answer

Root cause: dist/ was committed and served via npx serve dist, but the redesign merged only into src/ — nobody rebuilt/committed dist/, so users got a build that was 2 days behind source. Fix: rebuild, commit dist/, and add a guard that makes staleness fail loudly, plus ignore tooling caches so they never pollute status.

1. Rebuild and commit dist (the immediate fix):

cd /home/kara/game
npm run build                  # tsc -> dist/
git add dist/
git commit -m "build: rebuild dist to ship neon redesign (was 2 days stale)"

2. Add the verify:dist guard — npm run build && test -z git status dist/ (spec form) implemented as proper POSIX: rebuild, then assert git sees zero changes under dist/:

// package.json
"scripts": {
  "build": "tsc -p tsconfig.json",
  "verify:dist": "npm run build && test -z \"$(git status --porcelain dist/)\" && echo 'OK: dist/ is in sync with source'",
  "serve": "npx serve dist"
}

Cross-platform note: test -z is POSIX; on Windows cmd this needs a Node shim (node -e "process.exit(require('child_process').execSync('git status --porcelain dist/').toString().trim()?1:0)"). CI runs the shell form.

3. Ignore tooling caches — inline # comments are not supported in .gitignore (they silently corrupt the pattern — I hit this live), so comments go on their own lines:

# --- Tooling caches (never commit these) ---
# .vfs: VS Code Remote / Virtual File System cache
.vfs/
.cache/
.DS_Store

# --- Dependencies ---
node_modules/
