Watchdog kill logic (the RSS_KB/1024 for MB and 2.5GB contract):

with open(f"/proc/{pid}/status") as f:
    if line.startswith("VmRSS:"):
        rss_kb = int(line.split()[1])          # kB
rss_mb = rss_kb / 1024.0
f.write(f"{time.time():.3f} {rss_kb} {rss_mb:.1f}\n")
if rss_mb > kill_mb:
    os.kill(pid, signal.SIGKILL); return 42    # watchdog killed it

Real bugs found & fixed during verification (the "fix"): 1. Memlog gate false positive — the log stores MB rounded to 1 decimal (16.7), so |16.7109 − 16.7| = 0.0109 > 0.01 tolerance flagged valid lines; tolerance widened to 0.06. 2. Re-run idempotency — metrics.jsonl/stdout.log were opened append-mode and board.jsonl preserved stale events, doubling rows on re-run; orchestrator now owns fresh-run cleanup (truncate metrics, delete board/frames/logs pre-launch). 3. Live-gate startup race — fast runs finished before live gates sampled files, and a stale board.jsonl could short-circuit the grace poll; added a startup grace (wait for first board event or runner exit) + orchestrator-owned dir cleanup → stable 3/3 re-runs.
