What I diagnosed

This is a from-scratch codec (no broken starter existed), so the "root cause" is the family of failure modes this problem class encodes. Four of them bite independently and all present the same way — tiny inputs work, real inputs desync:

  1. Interleaved lane cursors. 8 rANS states share one lane byte stream, so they must share one forward read pointer. My first implementation gave each state its own cursor; it passed for n < 32 and first diverged at input index 37 on random data.
  2. Adaptive prefix model vs. reverse rANS. rANS encodes back-to-front, but an order-0 adaptive table for symbol i must depend on data[0:i]. A reverse encoder only knows the suffix, so it needs a forward model pre-pass recording table transitions.
  3. Cumulative drift. Flooring frequencies and clamping rare symbols to 1 doesn't sum to 4096; incremental cum patching drifts by one and decodes wrong only on stale symbols. Fixed with a deterministic largest-remainder normaliser + build_cum recomputed from the normalised frequencies.
  4. CRC as an afterthought. The trailer must be verified before unpacking a single state, and every renorm read must still be bounds-checked so truncation can't become IndexError or garbage.

The fix (in rans4x8.py)

  • 4 lanes × 8 states = 32 states; 12-bit precision (M=4096); byte renorm; 64-bit states (L=2**31, range [2**31,2**39)).
  • AdaptiveModel with in-band rescale when any count reaches 2**16 ((c+1)>>1), mirrored exactly by the decoder.
  • Stream header carries n, 4 lane lengths, and 32 uint64 states; CRC32 over everything precedes decoding.
  • Bounds-checked LaneDecoder.get, deterministic build_freq/build_cum.
