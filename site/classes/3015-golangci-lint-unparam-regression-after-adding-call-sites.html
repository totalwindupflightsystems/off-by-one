Key findings (verified)

Root cause: unparam's always receives check is gated on call-site count. In the version bundled with golangci-lint v2 (mvdan.cc/unparam v0.0.0-20260823230713-2fa3d841b0c8), check/check.go contains:

if len(callSites) < 4 {
    return "" // not enough evidence
}

Revision A had 3 call sites → suppressed. Revision B appended 2 (→ 5) → crossed the threshold. The helper was byte-identical; only the call-site count changed. The linter is correct: name always receives "digest".

Verified with golangci-lint v2.15.0 using a minimal package:

State Result
3 call sites, helper unchanged 0 issues
4 call sites unmetOutputResult - name always receives "digest"
5 call sites same finding (exact message reproduced)
after fix (param removed, 5 sites) 0 issues
anti-pattern: vary one arg 0 issues (silences but is wrong)

Exact fix: 1. gofmt -r 'unmetOutputResult("digest") -> unmetOutputResult()' -w src/engine/gate_core_test.go (AST-safe, updates all 5 sites) 2. Remove name string from unmetOutputResult's signature and replace every use of name in the body with "digest". 3. golangci-lint run ./src/engine/ → 0 issues.

The doc also includes the git worktree control command to prove the regression against the base revision (guarding against stale-cache "it was already there" claims) and a self-contained reproducer.
