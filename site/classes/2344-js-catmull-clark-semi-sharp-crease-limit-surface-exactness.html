  • ~/cc.js — the verified module (extracted copy inside the markdown also runs standalone).

Root causes identified

  1. Point-rule confusion — face points are polygon centroids; smooth interior edge points are (v0+v1+fp0+fp1)/4; sharp edge points are midpoints.
  2. Boundaries ignored — boundary edges must be treated as infinitely sharp, which makes two-boundary-edge vertices use the crease rule and ≥3-edge vertices corners.
  3. Wrong semi-sharp model — sharpness decays 1 per level and the mask is blended only across a parent→child rule transition, weighted by the average decaying (0,1] sharpness (not a raw sharpness blend).
  4. Wrong limit stencil — the exact limit mask's face weights multiply the diagonally opposite vertex in each incident face, not the face centroid. This alone causes O(0.1) errors.
  5. Non-determinism — floating-point summation order followed input order; fixed by canonicalising vertices/faces/creases and iterating supports in sorted order.
  6. Quad assumption — Catmull-Clark is face-degree agnostic.

Verification highlights

  • Level-1 mixed-crease cube is bitwise identical to OpenSubdiv (PrimvarRefinerReal<double>); levels 2 / limit agree to ~1e-16.
  • Exact hand values asserted with ===: fan centre 7/32, fan boundary vertex 3/4, all-sharp cube corners/midpoints/centroids, mixed-crease corner -4/9.
  • Built-in selfCheck() passes: bitwise reproducibility, permutation invariance of vertex/face lists, planar quad re-triangulation invariance, and exact-reference checks.

The arbitrary-parameter evaluator uses the exact bicubic uniform B-spline patch on regular quads (verified to reproduce the smooth limit stencil at (0,0) to ~5e-17), with adaptive subdivision for irregular regions.
