Key conclusions captured in the doc

  1. Root cause is runtime state: the LM Studio catalog drifted (the configured embedding model is no longer resident; the only two resident models are state:not-loaded), and provider=auto probes lmstudio→ollama→openai and falls through → embedding.healthy=false.
  2. Fix requires no config change/restart: POST any /v1/embeddings request to trigger LM Studio's JIT loader, which serves via fallback within ~60s and flips /health to healthy.
  3. Co-finding: this degraded health was not the cause of the accompanying POST 500s — those were a separate missing-Content-Type client bug. Red /health + 500s ≠ embeddings problem; check the daemon journal first.
