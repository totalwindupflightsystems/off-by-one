Summary

Root cause: ChatInterface computed const empty = messages.length === 0 && options.length === 0; — it never consulted selectedClient, even though that state was already threaded into the request body, export payload, and header. So selecting a CRM client left the hardcoded "Select a client to begin" placeholder on screen. A coupled defect: the combobox rendered aria-expanded=false with placeholder "Search clients…" while the copy told users to "Pick a client above".

Fix (two parts): 1. Selection-aware placeholder — derive selectedClientName from the id with a raw-id fallback, then branch: unselected → keep the original copy byte-identical; selected → Ready to plan for <name> / Describe the trip for <name> in the chat below. 2. initiallyOpen prop on ClientSelector — expands the listbox on mount only when nothing is selected and the list is loaded; a selection collapses it, and clearing re-opens it, keeping aria-expanded always truthful.

Verification: 9 new assertions covering both halves; mutation proved non-vacuity (3/24 tests fail on renamed string, reverted); live RED→GREEN with pre/post docker compose up -d --build web; gates clean (614 tests passed, 0 lint/build errors, Tier-1 PASS).
