Fixing SSA Phi-Coalescing Register Allocation, Loop-Weighted Spill Costs, and the Second Pass

Problem class: ssa-phi-coalescing-register-allocation-spill-cost-second-pass Environment: Python 3.12+ (stdlib only) Artifacts: regalloc.py (allocator), test_regalloc.py (verification harness), SOLUTION.md (this document)

1. Symptom

A register allocator built on this pipeline misbehaves in a characteristic way:

  • Phi coalescing does nothing. Even d = phi(pred: v) pairs that obviously can share a register are reported as not coalesced, so every loop-carried value keeps a copy.
  • Register pressure explodes and spills never settle. The first pass forces spills, the reload temporaries spill again, and the second pass does not converge.
  • Wrong things get spilled. Hot loop values are chosen over cold straight-line values because the spill cost ignores loop nesting.
  • Spilled live-in parameters reload garbage, because there is no defining instruction to attach a store to.

The root cause is a single liveness bug (item 1). The rest are independent correctness/quality defects that must also be fixed.

2. Root-cause analysis

2.1 The coalescing killer: phi results leak into the predecessor's live-out

A phi result is defined at block entry. If block-level use/def is computed only from the non-phi instructions — or if def is reset at block start — then a use of the phi result later in the same block (e.g. cond = lt i, n after i = phi(...)) is classified as upward-exposed. That puts the phi result into the block's live_in, which propagates to every predecessor's live_out.

The interference pass then walks each predecessor backwards from live_out, sees the phi result live, and adds an edge between it and its own operand (i ⇄ i0, i ⇄ i_next). Since interference forbids coalescing, no phi copy is ever removed. The system degenerates to "allocate every SSA name to a distinct register" — maximum pressure and maximum spills.

Correct transfer function (phi results counted as defs):

live_in[b]  = use[b]  ∪ (live_out[b] − def[b] − phi_def[b])
live_out[b] = ⋃_{s ∈ succ(b)} ( live_in[s] ∪ phi_operands(s, b) )

where def[b] is seeded with phi_def[b] before scanning the block's non-phi instructions.

Diagnostic that proves it:

adj = build_interference(f, *liveness(f)[3:5])
assert "i0" not in adj["i"]     # holds only after the fix

2.2 Spilled live-in values are never initialized

Spill rewriting attaches a store after each definition. Values that are live-in (parameters / undefined inputs such as n, one) have no definition, so their slot is never written and every reload returns garbage. Every spilled value with no definition site must get a store at function entry.

2.3 The spill cost ignores loop depth and use counts

Static use counts spill loop-carried values. Each use/def must be weighted by loop nesting depth, then normalized by degree, so cold values spill first:

cost[v]    = Σ_{uses/defs of v} 10 ** loop_depth[block]
benefit(v) = cost[v] / max(1, degree(v))      # spill the minimum

2.4 The "second pass" must be a complete re-analysis

Inserting loads/stores produces a new function with new temporaries. Liveness, interference, coalescing and coloring must all be recomputed on it. The original spilled name collapses to a short def → store range, and each reload temp is live only from its load to its use, so pressure drops and a fixed point (no spills left, or budget exhausted) is reached.

The harness proves four things end to end:

  1. Liveness is phi-aware — the phi result is neither live-in to its own block nor live-out of its predecessor, while its operand is; therefore the phi dest does not interfere with its operand and does interfere with sibling phi dests.
  2. Coloring is valid — verify_allocation recomputes the interference graph for the final, spill-rewritten IR and rejects any interfering pair that shares a color, any out-of-range color, and any operand/definition left uncolored.
  3. Spill rewriting preserves semantics — a small IR interpreter runs the original and the allocated function on the same inputs; results match for K = 2, 3, 4 on a loop and a diamond phi. This is what catches the missing entry store for spilled parameters.
  4. The second pass works and the budget is reported — the pass history shows forced spills in pass 1 and zero spills at the fixed point; res["budget_met"] compares final slot count against the requested budget (e.g. K=2, budget=3 → met=False; K=2, budget=100 → met=True).
