Summary

Diagnosis. boardctl (at github.com/coding-hermes/boardctl) auto-detects two topologies — A (header in board.jsonl) and B (header is line 1 of tasks.jsonl, no board.jsonl). Reads worked on B, but every mutating path treated B as read-only: hard gates in Create/UpdateTask/AppendEvent/SetHeader, plus a stale migration message in the header subcommand, plus validate/doctor downgrading B's header-counter checks to "not checked" warns (and counting the header as a task row). The missing abstraction: "which file carries the header" (A → board.jsonl, B → tasks.jsonl); HeaderRow() returned nil on B and SetHeader/validateHeader dereferenced an empty path.

Fix. Added headerPathFor() + skipTaskLine() (+ rowIsHeaderShape()) in board.go; removed the 4 write gates in write.go (SetHeader now rewrites only line 1 of tasks.jsonl on B with a whole-file byte-identical untouched-line assert before the atomic rewrite); added topology-aware TaskRows() used by list/show/stats/doctor; routed validateHeader/doctorHeaderVsEvents through headerPathFor() in both topologies (with the "extra lines past header" shape check kept topology-A-only); fixed header subcommand wording; init still refuses B but with writable-era wording (fresh boards only, migration optional); README/comments updated.

Verification (all run live, Go 1.26): - Pre-fix source + BT-010 tests: go test fails (b.TaskRows undefined; 4 CLI tests fail). The installed buggy binary: create/header exit 1 with the stale message; validate shows header counters not checked (exit 0 even for junk). - Fixed tree: go test -count=1 ./... → ok both packages, 71 test functions pass (16 new topology-B/BT-010 tests), go vet clean. - Fixed binary full workflow on one shared topology-B board: create → header read/set → event → update --commit-hash → validate/doctor all exit 0; header counters are really checked (ticks_total -5 fails validate, tick drift fails doctor); tasks.jsonl final state shows only line 1 rewritten by header/commit-hash updates — all other lines byte-identical.
