The repo for GAP-003 was not checked out in this environment, so this is the complete fix keyed to the spec's file map. Core mechanics were verified live (see EVIDENCE).

1. internal/cli/serve.go — route table

// BEFORE (drift)
mux.HandleFunc("POST /rooms", rooms.HandlePostRooms)
mux.HandleFunc("GET /rooms", rooms.ListRooms)
mux.HandleFunc("GET /rooms/{roomId}", rooms.GetRoom)

// AFTER (contract)
mux.HandleFunc("POST /spaces", spaces.HandlePostSpaces)
mux.HandleFunc("GET /spaces", spaces.ListSpaces)
mux.HandleFunc("GET /spaces/{spaceFileId}", spaces.GetSpace)

2. cmd/demo/main.go — route table — same three lines as above. Both binaries (CLI serve + demo) must change in lockstep, or one binary still 404s.

3. git mv rooms.go spaces.go + handler renames

git mv internal/api/rooms.go internal/api/spaces.go

// internal/api/spaces.go
package spaces

func HandlePostSpaces(w http.ResponseWriter, r *http.Request) { /* body: room_file_count field UNCHANGED */ }

func ListSpaces(w http.ResponseWriter, r *http.Request) { /* unchanged body */ }

func GetSpace(w http.ResponseWriter, r *http.Request) {
    // CRITICAL: PathValue key must equal the pattern literal "spaceFileId".
    // Go 1.22 mux matches keys by name; "roomId" would return "" for every request.
    id := r.PathValue("spaceFileId") // was r.PathValue("roomId") — this was the id-404 bug
    if id == "" {
        http.Error(w, "space not found", http.StatusNotFound)
        return
    }
    // ...
}

4. Frontend fetch URLs (e.g. frontend/src/api.js)

// BEFORE → AFTER

fetch(`/rooms`, {method: 'POST'})   →  fetch(`/spaces`, {method: 'POST'})
fetch(`/rooms`)                     →  fetch(`/spaces`)

5. Tests — update all request paths in _test.go/integration tests: /rooms → /spaces, /rooms/{id} → /spaces/{id}, and assert PathValue("spaceFileId") is populated (a test asserting non-empty id catches the key-mismatch class).

6. Docs - docs/integration-guide.md: implementation note "the server exposes /spaces; the {spaceFileId} path parameter is read via r.PathValue("spaceFileId")". - docs/frontend-design.md: API-path table rows /rooms → /spaces (all three: POST /spaces, GET /spaces, GET /spaces/{spaceFileId}).

Deliberately untouched: JSON payload field room_file_count (kept as-is — separate drift, out of scope).

With pattern `GET /spaces/{spaceFileId}`: `r.PathValue("spaceFileId")` → `"xyz"`, but `r.PathValue("spaceId")` → `""`. Since `GetSpace` 404s on empty id, any key ≠ `spaceFileId` makes every id-based request 404 — exactly the described bug.

**Edge cases tested:**
- Key mismatch returns `""` (not panic/error) → safe empty-check 404, verified above.
- Both route tables must be updated: fixing only one binary leaves the other serving 404 (the fix includes both `internal/cli/serve.go` and `cmd/demo/main.go`).
- `POST /spaces` vs `GET /spaces` method discrimination works with `http.Method`-prefixed patterns (verified: both return 200 for their respective methods).
- JSON payload fields left unchanged — no payload-contract churn from this rename.
