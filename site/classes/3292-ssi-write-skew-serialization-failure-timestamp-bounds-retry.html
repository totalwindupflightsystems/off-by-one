SSI write-skew serialization failure: timestamp bounds and retry

Problem class: ssi-write-skew-serialization-failure-timestamp-bounds-retry Environment: Go 1.26 (single node) Deliverable: a self-contained, verified implementation of a transactional key/value store with Serializable Snapshot Isolation (SSI), a bounded timestamp oracle, and a retry policy that guarantees forward progress on the classic doctor-on-call write-skew workload.

1. Symptom

A transactional KV store gives snapshot reads and correct read-your-writes, yet a concurrent, write-skew-prone workload silently violates an invariant even though every transaction "committed successfully". The canonical case is doctor on call:

T1: check that some other doctor is on call  ->  take Alice off call
T2: check that some other doctor is on call  ->  take Bob off call

Under plain snapshot isolation both transactions read the pre-state, both see another doctor on call, both succeed, and the system ends with zero doctors on call. Snapshot isolation is not serializable.

When SSI is bolted on naively, a second failure mode appears: commits start failing with serialization errors, but under contention the system either (a) still lets write skew through, or (b) livelocks because every retry takes a snapshot that is still behind the conflicting commit, so the same pair always re-conflicts.

2. Root-cause analysis

The failure has four independent root causes. Each maps to a specific line of defence in the implementation.

RC1 — Snapshot isolation cannot prevent write skew

Snapshot isolation only detects write–write conflicts (first committer wins). Write skew creates a cycle using read–write anti-dependencies only:

  • A ->rw B means A read a version that B overwrote.
  • Doctor-on-call produces A ->rw B and B ->rw A with no shared key.

No ww check can see this. SSI must materialise rw-antidependencies and reject a commit when it would close a dangerous structure

T1 ->rw T2 ->rw T3      (two consecutive rw edges)

The safe rule of Cahill et al. (2008), also used by PostgreSQL, is: abort the pivot T2 when T3 has already committed (T3 is the first committer). This breaks exactly the cycles that could otherwise form while letting the first committer make progress.

RC2 — The rw-edge set must be complete in both directions and both commit orders

This is the subtle bug that makes naive SSI both unsound and inert.

2a. Missing edge when a reader's snapshot predates a commit but the read happens after it. If writer W commits the successor version before reader R performs its read, then at W's commit time R was not yet registered as a reader, so W cannot create the edge R ->rw W. The edge is nevertheless real: R read the version W superseded. A correct implementation must, at read time, add R ->rw W for the first version newer than R's snapshot. Without this, dangerous structures are missed and the store is not serializable.

2b. Wrong ordering inside commit. The pivot's incoming edges T1 ->rw T2 are exactly the edges created by T2's own writes (T2 commits and discovers readers of those keys). If the dangerous-structure test runs before those edges are recorded, the pivot sees inFrom == empty and the check is a no-op — write skew passes. The commit must therefore:

  1. allocate commitTS,
  2. run ww validation,
  3. record the readers' ->rw edges into the pivot,
  4. then run the dangerous-structure test,
  5. apply the write set.

RC3 — Timestamp bounds

The conflict window is the half-open interval (startTS, commitTS]:

  • a writer that committed at ts <= startTS is already in the snapshot — no conflict;
  • a writer that committed at startTS < ts <= commitTS is a conflict.

Getting the bounds wrong produces either spurious aborts (closed lower bound) or missed conflicts (closed-but-too-wide or open upper bound). Two invariants are non-negotiable:

  • Allocate() must be strictly monotonic: ts = max(now, last+1). A coarse or backwards-stepping wall clock otherwise hands out duplicate timestamps and destroys the window.
  • commitTS > startTS always. If a commit timestamp can equal or precede its snapshot, read-your-writes and ordering break.

Clock uncertainty (maxOffset) is modelled with a TrueTime-style commit-wait: a commit is not externally visible until the physical clock passes commitTS + maxOffset. This guarantees no future timestamp can be below an already-issued one.

RC4 — Retry must guarantee forward progress

Retrying with the same snapshot, or without jitter, makes symmetric transactions re-conflict forever (livelock). The fix is to retry with a brand-new snapshot timestamp and a jittered exponential backoff. Progress is structural: in every dangerous structure only the pivot aborts, so the first committer's writes persist; the retry takes a later snapshot and observes them.

3. The fix

The complete, verified implementation is below. It is a single Go package (ssikv). Highlights:

  • TSO.Allocate — strict monotonicity + maxOffset commit-wait.
  • version{ts, value, deleted, writer} — MVCC versions remember their writer.
  • Txn.Get calls recordReadConflict to close the RC2a hole.
  • Txn.Commit orders: ww check, record incoming rw edges, dangerous structure test, apply, commit-wait.
  • Store.Run — fresh transaction + jittered exponential backoff.

// Package ssikv implements a single-node transactional key/value store with
// Serializable Snapshot Isolation (SSI).
//
// Design summary
//
//   - A monotonic timestamp oracle (TSO) hands out strictly increasing
//     timestamps and models a bounded clock-uncertainty window (TrueTime
//     style epsilon).  Snapshot reads use a start timestamp; committing
//     writers use a commit timestamp and commit-wait so that timestamps are
//     externally consistent.
//
//   - Storage is multi-version: every committed write appends a version
//     tagged with its commit timestamp, so a reader can reconstruct any
//     snapshot by scanning versions <= startTS.
//
//   - Snapshot isolation alone permits write skew.  We additionally track
//     rw-antidependencies: an edge T1 ->rw T2 exists when T1 read a version
//     that T2 later overwrote.  A commit is rejected when the pivot of a
//     dangerous structure T1 ->rw T2 ->rw T3 has an already-committed
//     successor T3 (T3 is the first committer).  This is the SSI safety rule
//     of Cahill et al. (2008), as implemented by PostgreSQL.
//
//   - Commit validation uses the half-open interval (startTS, commitTS]:
//     a write by another transaction committed strictly after our snapshot
//     and at or before our commit timestamp conflicts.
//
//   - Run() supplies a jittered, exponentially backed-off retry loop so that
//     write-skew-prone workloads (doctor-on-call) make forward progress:
//     only the pivot aborts, the first committer always wins, and retries
//     observe the new state.
package ssikv

import (
    "errors"
    "math/rand"
    "sort"
    "sync"
    "time"
)

// ---------------------------------------------------------------------------
// Errors
// ---------------------------------------------------------------------------

var (
    // ErrSerialization is returned when a commit would create a dangerous
    // structure in the rw-antidependency graph.  The transaction must be
    // retried from a fresh snapshot.
    ErrSerialization = errors.New("ssikv: serialization failure (dangerous structure)")

    // ErrWriteConflict is returned when a concurrent transaction already
    // committed a write to one of our keys after our snapshot was taken
    // (first-committer-wins).  Retryable.
    ErrWriteConflict = errors.New("ssikv: write-write conflict")

    // ErrAborted is returned for any operation on a finished transaction.
    ErrAborted = errors.New("ssikv: transaction already finished")

    // ErrNotFound is a non-retryable "key absent in this snapshot".
    ErrNotFound = errors.New("ssikv: key not found")
)

// Retryable reports whether err may be resolved by retrying the transaction
// from a fresh snapshot.
func Retryable(err error) bool {
    return errors.Is(err, ErrSerialization) || errors.Is(err, ErrWriteConflict)
}

// ---------------------------------------------------------------------------
// Timestamp oracle
// ---------------------------------------------------------------------------

// TSO allocates strictly monotonically increasing timestamps.  maxOffset is
// the clock-uncertainty bound: the maximum amount by which the physical clock
// of any node could differ from ours.  CommitWait blocks for that bound so a
// commit cannot be observed with a timestamp that "moves backwards" from the
// point of view of a future reader.
type TSO struct {
    mu        sync.Mutex
    last      int64
    maxOffset int64 // nanoseconds
    now       func() time.Time
}

// NewTSO returns a TSO with the supplied clock-uncertainty bound.
func NewTSO(maxOffset time.Duration) *TSO {
    return &TSO{
        maxOffset: int64(maxOffset),
        now:       time.Now,
    }
}

// Allocate returns a timestamp strictly greater than every timestamp returned
// before.  It is never less than the current physical time, so timestamps are
// monotonically non-decreasing with respect to wall-clock time even if the
// wall clock steps backwards.
func (o *TSO) Allocate() int64 {
    o.mu.Lock()
    defer o.mu.Unlock()
    ts := o.now().UnixNano()
    // Timestamp bounds: enforce strict monotonicity.  Without the +1 below a
    // coarse or regressing clock can hand out duplicate timestamps, which
    // breaks the (startTS, commitTS] conflict window.
    if ts <= o.last {
        ts = o.last + 1
    }
    o.last = ts
    return ts
}

// Last returns the most recently allocated timestamp.
func (o *TSO) Last() int64 {
    o.mu.Lock()
    defer o.mu.Unlock()
    return o.last
}

// CommitWait blocks until the physical clock has advanced past ts+maxOffset.
// After it returns, no future Allocate can produce a value <= ts, which makes
// commit timestamps externally consistent.
func (o *TSO) CommitWait(ts int64) {
    deadline := time.Unix(0, ts+o.maxOffset)
    for {
        d := time.Until(deadline)
        if d <= 0 {
            return
        }
        time.Sleep(d)
    }
}

// ---------------------------------------------------------------------------
// MVCC storage
// ---------------------------------------------------------------------------

type version struct {
    ts      int64
    value   []byte
    deleted bool
    // writer is the id of the transaction that produced this version.  It is
    // needed to record rw-edges when a reader with an old snapshot reads a
    // value that a transaction which has already committed overwrote.
    writer uint64
}

type entry struct {
    versions []version // ascending by ts
}

// lookup returns the version visible at snapshot ts, or false if the key did
// not exist (or was deleted) at that snapshot.
func (e *entry) lookup(ts int64) (version, bool) {
    // Greatest index with versions[i].ts <= ts.
    i := sort.Search(len(e.versions), func(i int) bool { return e.versions[i].ts > ts }) - 1
    if i < 0 {
        return version{}, false
    }
    v := e.versions[i]
    if v.deleted {
        return version{}, false
    }
    return v, true
}

func (e *entry) latestTS() int64 {
    if len(e.versions) == 0 {
        return 0
    }
    return e.versions[len(e.versions)-1].ts
}

// ---------------------------------------------------------------------------
// Store
// ---------------------------------------------------------------------------

// Store is a single-node SSI key/value store.  A single mutex guards all
// mutable state; transactions interleave between calls, not inside them.
type Store struct {
    mu     sync.Mutex
    tso    *TSO
    data   map[string]*entry
    next   uint64
    active map[uint64]*Txn
    // committedTx holds committed transactions so rw-edges can be resolved to
    // a commit order during dangerous-structure detection.
    committedTx map[uint64]*Txn
    // readers maps a key to the transactions that read it.  Readers are kept
    // after commit so that a later writer can still record the rw-edge.
    readers map[string]map[uint64]*Txn

    // counters for observability / tests
    aborts int
}

// New returns an empty store with the given clock-uncertainty bound.
func New(maxOffset time.Duration) *Store {
    return &Store{
        tso:         NewTSO(maxOffset),
        data:        make(map[string]*entry),
        active:      make(map[uint64]*Txn),
        committedTx: make(map[uint64]*Txn),
        readers:     make(map[string]map[uint64]*Txn),
    }
}

// Aborts returns the number of transactions aborted by SSI/ww validation.
func (s *Store) Aborts() int {
    s.mu.Lock()
    defer s.mu.Unlock()
    return s.aborts
}

// Begin starts a transaction and pins its snapshot at a fresh timestamp.
func (s *Store) Begin() *Txn {
    s.mu.Lock()
    defer s.mu.Unlock()
    s.next++
    t := &Txn{
        id:        s.next,
        startTS:   s.tso.Allocate(),
        store:     s,
        writeSet:  make(map[string][]byte),
        deleteSet: make(map[string]bool),
        readSet:   make(map[string]int64),
        inFrom:    make(map[uint64]struct{}),
        outTo:     make(map[uint64]struct{}),
    }
    s.active[t.id] = t
    return t
}

func (s *Store) registerReader(key string, t *Txn) {
    set := s.readers[key]
    if set == nil {
        set = make(map[uint64]*Txn)
        s.readers[key] = set
    }
    set[t.id] = t
}

// writtenKeys returns the union of the write and delete sets.
func (t *Txn) writtenKeys() []string {
    keys := make([]string, 0, len(t.writeSet)+len(t.deleteSet))
    for k := range t.writeSet {
        keys = append(keys, k)
    }
    for k := range t.deleteSet {
        keys = append(keys, k)
    }
    sort.Strings(keys)
    return keys
}

func (t *Txn) abortLocked() {
    t.state = aborted
    delete(t.store.active, t.id)
    t.store.aborts++
    // Remove this transaction from the reader registry so it can no longer
    // generate rw-edges, and drop its edges.
    for key := range t.readSet {
        if set := t.store.readers[key]; set != nil {
            delete(set, t.id)
        }
    }
    // Remove dangling edges in both directions so a later pivot does not
    // inspect an aborted neighbour.
    lookup := func(id uint64) *Txn {
        if x := t.store.active[id]; x != nil {
            return x
        }
        return t.store.committedTx[id]
    }
    for id := range t.inFrom {
        if x := lookup(id); x != nil {
            delete(x.outTo, t.id)
        }
    }
    for id := range t.outTo {
        if x := lookup(id); x != nil {
            delete(x.inFrom, t.id)
        }
    }
    t.inFrom = map[uint64]struct{}{}
    t.outTo = map[uint64]struct{}{}
}

// ---------------------------------------------------------------------------
// Transaction
// ---------------------------------------------------------------------------

type txnState int

const (
    active txnState = iota
    committed
    aborted
)

// Txn is a single transaction.  It is not safe for concurrent use by multiple
// goroutines; create one transaction per goroutine.
type Txn struct {
    id      uint64
    startTS int64
    store   *Store

    writeSet  map[string][]byte
    deleteSet map[string]bool
    // readSet maps key -> the version timestamp observed (0 means "absent").
    readSet map[string]int64

    // rw-antidependency edges, as transaction ids:
    //   inFrom[X] : X ->rw this
    //   outTo[Y]  : this ->rw Y
    inFrom map[uint64]struct{}
    outTo  map[uint64]struct{}

    state    txnState
    commitTS int64
}

// StartTS returns the snapshot timestamp of the transaction.
func (t *Txn) StartTS() int64 { return t.startTS }

// CommitTS returns the commit timestamp once the transaction has committed.
func (t *Txn) CommitTS() int64 { return t.commitTS }

// Get reads key at the transaction's snapshot (or its own buffered write).
// It returns ErrNotFound if the key is absent in this snapshot.
func (t *Txn) Get(key string) ([]byte, error) {
    s := t.store
    s.mu.Lock()
    defer s.mu.Unlock()
    if t.state != active {
        return nil, ErrAborted
    }
    // Read-your-own-writes takes precedence over the snapshot.
    if v, ok := t.writeSet[key]; ok {
        return append([]byte(nil), v...), nil
    }
    if t.deleteSet[key] {
        return nil, ErrNotFound
    }
    if e := s.data[key]; e != nil {
        if v, ok := e.lookup(t.startTS); ok {
            t.readSet[key] = v.ts
            s.registerReader(key, t)
            t.recordReadConflict(e)
            return append([]byte(nil), v.value...), nil
        }
        t.recordReadConflict(e)
    }
    // Record a read of an absent key: a later write to it is still an
    // rw-conflict (phantom-style write skew).
    t.readSet[key] = 0
    s.registerReader(key, t)
    return nil, ErrNotFound
}

// Put buffers a write.  It becomes visible to other transactions only on
// commit.
func (t *Txn) Put(key string, value []byte) error {
    s := t.store
    s.mu.Lock()
    defer s.mu.Unlock()
    if t.state != active {
        return ErrAborted
    }
    t.writeSet[key] = append([]byte(nil), value...)
    delete(t.deleteSet, key)
    return nil
}

// Delete buffers a deletion of key.
func (t *Txn) Delete(key string) error {
    s := t.store
    s.mu.Lock()
    defer s.mu.Unlock()
    if t.state != active {
        return ErrAborted
    }
    delete(t.writeSet, key)
    t.deleteSet[key] = true
    return nil
}

// Rollback abandons the transaction.
func (t *Txn) Rollback() {
    s := t.store
    s.mu.Lock()
    defer s.mu.Unlock()
    if t.state == active {
        t.abortLocked()
    }
}

// recordReadConflict records an rw-edge to the writer of the first version
// newer than the reader's snapshot.  This closes the soundness hole where a
// transaction takes its snapshot before a commit but performs the read after
// that commit: the writer is already committed and therefore cannot discover
// the reader when it processes its own reader set.  Looking at it from the
// reader side restores the missing edge.  Caller holds s.mu.
func (t *Txn) recordReadConflict(e *entry) {
    i := sort.Search(len(e.versions), func(i int) bool { return e.versions[i].ts > t.startTS })
    if i >= len(e.versions) {
        return
    }
    v := &e.versions[i]
    if v.writer == 0 || v.writer == t.id {
        return
    }
    w := t.store.committedTx[v.writer]
    if w == nil {
        return
    }
    t.outTo[w.id] = struct{}{}
    w.inFrom[t.id] = struct{}{}
}

// isDangerousPivot reports whether committing this transaction would close an
// SSI dangerous structure T1 ->rw pivot ->rw T3 where T3 has already committed
// (T3 is the first committer).  Caller holds s.mu.
func (t *Txn) isDangerousPivot() bool {
    if len(t.inFrom) == 0 {
        return false
    }
    for id := range t.outTo {
        y := t.store.active[id]
        if y == nil {
            // Not active; look it up among committed writers.
            y = t.store.committedTx[id]
        }
        if y != nil && y.state == committed {
            return true
        }
    }
    return false
}

// Commit validates and atomically applies the transaction.
//
// The conflict window is the half-open interval (startTS, commitTS]:  any
// other write committed strictly after our snapshot but at or before our
// commit timestamp is a conflict.  Using a closed lower bound would
// spuriously abort on our own snapshot version; using a closed upper bound
// would miss a writer that committed at exactly commitTS.
func (t *Txn) Commit() error {
    s := t.store
    s.mu.Lock()
    defer s.mu.Unlock()
    if t.state != active {
        return ErrAborted
    }

    commitTS := s.tso.Allocate()
    if commitTS <= t.startTS {
        // Timestamp bounds invariant: a commit must be strictly newer than
        // its snapshot, otherwise read-your-writes and ordering break.
        t.abortLocked()
        return ErrSerialization
    }

    // 1. Snapshot-isolation write-write validation (first committer wins).
    for _, key := range t.writtenKeys() {
        if e := s.data[key]; e != nil {
            if latest := e.latestTS(); latest > t.startTS {
                t.abortLocked()
                return ErrWriteConflict
            }
        }
    }

    // 2. Record rw-edges from every reader of a key we write to us.  A reader
    // whose observed version is older than commitTS did not see our write, so
    // reader ->rw us.  These are the pivot's incoming edges, so they MUST be
    // established before the dangerous-structure test below.
    for _, key := range t.writtenKeys() {
        for id, r := range s.readers[key] {
            if id == t.id || r.state == aborted {
                continue
            }
            if obs, ok := r.readSet[key]; ok && obs < commitTS {
                r.outTo[t.id] = struct{}{}
                t.inFrom[id] = struct{}{}
            }
        }
    }

    // 3. SSI dangerous-structure detection: reject the commit if this
    // transaction is the pivot T2 of T1 ->rw T2 ->rw T3 and T3 has already
    // committed (T3 is the first committer).
    if t.isDangerousPivot() {
        t.abortLocked()
        return ErrSerialization
    }

    // 4. Apply the write set atomically at commitTS.
    for _, key := range t.writtenKeys() {
        e := s.data[key]
        if e == nil {
            e = &entry{}
            s.data[key] = e
        }
        if v, ok := t.writeSet[key]; ok {
            e.versions = append(e.versions, version{ts: commitTS, value: v, writer: t.id})
        } else {
            e.versions = append(e.versions, version{ts: commitTS, deleted: true, writer: t.id})
        }
    }

    t.commitTS = commitTS
    t.state = committed
    delete(s.active, t.id)
    s.committedTx[t.id] = t

    // TrueTime-style commit-wait: make the commit externally visible only
    // once its timestamp is safely in the past of every clock.
    s.tso.CommitWait(commitTS)
    return nil
}

// ---------------------------------------------------------------------------
// Retry helper
// ---------------------------------------------------------------------------

// Run executes fn in a transaction, committing on success.  On a retryable
// SSI/ww abort it starts a completely fresh transaction (new snapshot
// timestamp) after a jittered exponential backoff.  Forward progress is
// guaranteed for finite workloads: in every dangerous structure only the
// pivot aborts, so the first committer's writes persist and each retry
// observes strictly more committed state.
func (s *Store) Run(fn func(t *Txn) error) error {
    backoff := 200 * time.Microsecond
    const maxBackoff = 50 * time.Millisecond
    for {
        t := s.Begin()
        err := fn(t)
        if err == nil {
            err = t.Commit()
        } else {
            t.Rollback()
        }
        if err == nil {
            return nil
        }
        if !Retryable(err) {
            return err
        }
        // Jitter breaks lock-step retries from symmetric transactions.
        // The global math/rand source is safe for concurrent use and is
        // auto-seeded in modern Go.
        jitter := time.Duration(rand.Int63n(int64(backoff) + 1))
        time.Sleep(backoff/2 + jitter/2)
        if backoff < maxBackoff {
            backoff *= 2
        }
    }
}

Applying it

s := ssikv.New(1 * time.Millisecond) // maxOffset = clock-uncertainty bound

err := s.Run(func(tx *ssikv.Txn) error {
    // 1) read whatever you need at the snapshot
    if _, err := tx.Get("oncall/alice"); err != nil {
        return err
    }
    // 2) validate the invariant, then write
    return tx.Delete("oncall/alice")
})
if err != nil {
    log.Fatal(err)
}

Run returns only non-retryable errors; ErrSerialization and ErrWriteConflict are retried automatically with a fresh snapshot.

func TestTSOMonotonicConcurrent(t *testing.T) {
    o := NewTSO(0)
    const goroutines, per = 32, 200
    var wg sync.WaitGroup
    results := make([][]int64, goroutines)
    for g := 0; g < goroutines; g++ {
        wg.Add(1)
        go func(g int) {
            defer wg.Done()
            rs := make([]int64, per)
            for i := 0; i < per; i++ {
                rs[i] = o.Allocate()
            }
            results[g] = rs
        }(g)
    }
    wg.Wait()

    seen := make(map[int64]bool)
    for _, rs := range results {
        for i, ts := range rs {
            if seen[ts] {
                t.Fatalf("duplicate timestamp %d", ts)
            }
            seen[ts] = true
            if i > 0 && rs[i] <= rs[i-1] {
                t.Fatalf("non-monotonic within goroutine: %d then %d", rs[i-1], rs[i])
            }
        }
    }
}

// TestDoctorOnCallDeterministic forces the classic write-skew interleaving:
// two transactions each verify that another doctor is on call, then remove
// themselves.  Snapshot isolation alone would leave zero doctors on call.
// SSI must abort exactly the second committer.
func TestDoctorOnCallDeterministic(t *testing.T) {
    s := New(0)
    seed(t, s, map[string]string{"alice": "on", "bob": "on"})

    a := s.Begin()
    if _, err := a.Get("bob"); err != nil { // guard: another doctor present
        t.Fatal(err)
    }
    if _, err := a.Get("alice"); err != nil {
        t.Fatal(err)
    }
    if err := a.Delete("alice"); err != nil {
        t.Fatal(err)
    }

    b := s.Begin()
    if _, err := b.Get("alice"); err != nil {
        t.Fatal(err)
    }
    if _, err := b.Get("bob"); err != nil {
        t.Fatal(err)
    }
    if err := b.Delete("bob"); err != nil {
        t.Fatal(err)
    }

    if err := a.Commit(); err != nil {
        t.Fatalf("first committer must succeed: %v", err)
    }
    err := b.Commit()
    if !errors.Is(err, ErrSerialization) {
        t.Fatalf("pivot commit err = %v, want ErrSerialization", err)
    }

    // Retry b with a fresh snapshot: the other doctor is gone, so it is a
    // no-op and the invariant is preserved.
    err = s.Run(func(tx *Txn) error {
        self, other := "bob", "alice"
        if _, err := tx.Get(other); errors.Is(err, ErrNotFound) {
            return nil // nobody else on call: do not leave the desk
        } else if err != nil {
            return err
        }
        if _, err := tx.Get(self); errors.Is(err, ErrNotFound) {
            return nil
        } else if err != nil {
            return err
        }
        return tx.Delete(self)
    })
    if err != nil {
        t.Fatalf("retry: %v", err)
    }

    if present(t, s, "alice") {
        t.Fatalf("alice should have been removed")
    }
    if !present(t, s, "bob") {
        t.Fatalf("bob must remain on call (invariant)")
    }
    if s.Aborts() != 1 {
        t.Fatalf("aborts = %d, want exactly 1", s.Aborts())
    }
}

// TestDoctorOnCallConcurrent stresses the workload with many symmetric
// transactions.  It verifies the invariant (at least one doctor stays on
// call) and that every transaction eventually terminates (no livelock).
func TestDoctorOnCallConcurrent(t *testing.T) {
    s := New(0)
    keys := []string{"alice", "bob", "carol", "dave", "erin"}
    all := map[string]string{}
    for _, k := range keys {
        all[k] = "on"
    }
    seed(t, s, all)

    const rounds = 8
    var wg sync.WaitGroup
    var done int64
    errCh := make(chan error, len(keys)*rounds)

    for r := 0; r < rounds; r++ {
        for _, key := range keys {
            key := key
            wg.Add(1)
            go func() {
                defer wg.Done()
                err := s.Run(func(tx *Txn) error {
                    n := 0
                    selfOn := false
                    for _, k := range keys {
                        _, err := tx.Get(k)
                        switch {
                        case err == nil:
                            n++
                            if k == key {
                                selfOn = true
                            }
                        case errors.Is(err, ErrNotFound):
                        default:
                            return err
                        }
                    }
                    if !selfOn || n < 2 {
                        return nil // never drop below one on-call doctor
                    }
                    return tx.Delete(key)
                })
                if err != nil {
                    errCh <- err
                    return
                }
                atomic.AddInt64(&done, 1)
            }()
        }
    }

    waitTimeout(t, &wg, 30*time.Second, errCh)

    n := 0
    for _, k := range keys {
        if present(t, s, k) {
            n++
        }
    }
    if n != 1 {
        t.Fatalf("invariant violated: %d doctors on call, want 1", n)
    }
    if got := atomic.LoadInt64(&done); got != int64(len(keys)*rounds) {
        t.Fatalf("completed %d/%d transactions", got, len(keys)*rounds)
    }
    close(errCh)
    for err := range errCh {
        t.Fatalf("transaction failed: %v", err)
    }
}

// TestDoctorOnCallForcedOverlap removes scheduling luck: every transaction
// reads the whole set before any of them commits, so all of them try to
// remove themselves.  SSI must abort every writer but the first committer.
func TestDoctorOnCallForcedOverlap(t *testing.T) {
    s := New(0)
    keys := []string{"a", "b", "c"}
    all := map[string]string{}
    for _, k := range keys {
        all[k] = "on"
    }
    seed(t, s, all)

    var ready sync.WaitGroup
    ready.Add(len(keys))
    release := make(chan struct{})

    var commits, aborts int32
    var wg sync.WaitGroup
    for _, self := range keys {
        self := self
        wg.Add(1)
        go func() {
            defer wg.Done()
            tx := s.Begin()
            for _, k := range keys {
                if _, err := tx.Get(k); err != nil {
                    t.Errorf("read %s: %v", k, err)
                }
            }
            if err := tx.Delete(self); err != nil {
                t.Errorf("delete %s: %v", self, err)
            }
            ready.Done()
            <-release
            switch err := tx.Commit(); {
            case err == nil:
                atomic.AddInt32(&commits, 1)
            case errors.Is(err, ErrSerialization):
                atomic.AddInt32(&aborts, 1)
            default:
                t.Errorf("commit %s: %v", self, err)
            }
        }()
    }
    waitReady(t, &ready)
    close(release)
    wg.Wait()

    if commits != 1 {
        t.Fatalf("commits = %d, want 1", commits)
    }
    if aborts != int32(len(keys)-1) {
        t.Fatalf("aborts = %d, want %d", aborts, len(keys)-1)
    }
}

// waitTimeout fails the test if wg does not complete in time, guarding
// against a retry livelock hanging the suite.
func waitTimeout(t *testing.T, wg *sync.WaitGroup, d time.Duration, errCh chan error) {
    t.Helper()
    doneCh := make(chan struct{})
    go func() {
        wg.Wait()
        close(doneCh)
    }()
    select {
    case <-doneCh:
    case <-time.After(d):
        select {
        case err := <-errCh:
            t.Fatalf("timeout after error: %v", err)
        default:
        }
        t.Fatalf("timeout: possible retry livelock")
    }
}
