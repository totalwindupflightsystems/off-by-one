Fix: qa-harness-cell-detection detail pin drifted after bunker-qa.sh rework

Problem class: pinned-harness-contract-test-detail-format-drift Repo: 9router federation fork Test: tests/federation/qa-harness-cell-detection.test.js Harness: ~/.hermes/scripts/bunker-qa.sh (edited 2026-09-24T15:03) Guard: gitreins tier-1 tests guard (verify-no-regression.mjs)

Root cause

The repo pins the exact human-readable detail string emitted by an external harness that lives outside the repo (~/.hermes/scripts/bunker-qa.sh). That harness was reworked on 2026-09-24 15:03. The rework moved the act return code out of the inline clause into a trailing parenthesised clause:

- ... FAIL act rc=1: act step failed
+ ... FAIL (act leg rc=1: act step failed)

The test's NEGATIVE CONTROL still asserted the old substring:

expect(verdict.detail).toContain("act rc=1");   // stale, no longer present

Because verdict.detail now contains act leg rc=1, the detail assertion fails while the status-level pin still passes (status === "FAIL"). The pre-commit tier-1 guard therefore blocks the first commit after the harness edit, and the red test looks like a product regression. It is not: only the rendering of the detail drifted, not the verdict semantics.

Diagnosis (reproduce before changing anything)

  1. Reproduce the single test in isolation and confirm deterministic failure:

bash npx jest tests/federation/qa-harness-cell-detection.test.js -t "NEGATIVE CONTROL" # Expected substring: "act rc=1" # Received string: "... (act leg rc=1: ...)"

  1. Stat the harness and diff it against the newest backup:

bash stat -c '%y %n' ~/.hermes/scripts/bunker-qa.sh ~/.hermes/scripts/bunker-qa.sh.bak-* diff -u ~/.hermes/scripts/bunker-qa.sh.bak-* ~/.hermes/scripts/bunker-qa.sh \ | grep -nE 'act|rc=' | head grep -nE 'act[^"]*rc=' ~/.hermes/scripts/bunker-qa.sh.bak-*

The diff shows act rc=N became (act leg rc=N: ...).

  1. Confirm the STATUS-level pin still passes (verdict semantics unchanged):

bash npx jest tests/federation/qa-harness-cell-detection.test.js -t "status" # PASS

Exact fix

Re-pin the detail assertion to the NEW format with a dated comment:

-  expect(verdict.detail).toContain("act rc=1");
+  // Re-pinned 2026-09-24: bunker-qa.sh rework (2026-09-24T15:03) moved the
+  // act return code into a trailing '(act leg rc=N: ...)' clause.
+  expect(verdict.detail).toContain("act leg rc=1");

Do NOT edit ~/.hermes/scripts/bunker-qa.sh back to the old format, and do NOT add this test to a known-fails baseline. The harness is shared external infrastructure; the repo pins the contract, so the repo moves when the contract's presentation changes.
