Gitreins: task flips complete while verdict.json is missing after a client 180s timeout

Class: gitreins-judge-client-timeout-status-landed Symptom: gitreins task complete is killed by the caller's 180s timeout after tier1/tier2 verification runs. tasks.yaml ends up with status: complete + completed_at, but no verdict.json for that task. Downstream (<project> tick 277) trusts status and propagates the completion. Observed instance: CLI-DOCS-WAVE flipped complete at 02:41:52Z despite the kill; the criteria were verified in-session (S3-git-local=0, endpoint ×8 in cli-reference, GAP-106/107 sections present).

TL;DR

Completion is a two-write, non-atomic operation: the ledger (tasks.yaml status + completed_at) and the judge verdict (verdict.json) are committed as separate, independent file writes, with the ledger write able to land first. The long-running tier1/tier2 judge runs synchronously inside the client's hard 180s deadline. When the client SIGKILLs the process between the two writes, the result is a torn record: complete without a verdict. <project> has no invariant requiring the verdict, so it accepts and propagates the torn state.

Fix in one line: persist the verdict first, atomically, then flip status with an atomic read-modify-write; make completion idempotent/resumable; and have <project> (reconcile) refuse to treat a task as complete unless its verdict is present.

Impact

  • Auditability gap: completed work has no durable judge verdict. The pass decision existed only in the killed process's memory.
  • False completions: any crash/timeout between the ledger write and the verdict write silently lands an unverified completion. If the judge routinely exceeds the client timeout, this becomes the normal path, not a rare race.
  • Compounding: because there is no reconciliation, the torn window stays torn forever; <project> keeps treating it as complete.

Evidence and timeline reconstruction

Time / step Event Durable state
t0 worker finishes task, calls gitreins task complete CLI-DOCS-WAVE ledger in_progress
t1 tier1/tier2 judge runs (passes; criteria verified in-session) no verdict written yet
t2 ledger write: status=complete, completed_at=... ledger says complete
t3 client 180s timeout fires → SIGKILL (untrappable) —
t4 verdict write never happens no verdict.json
t5 <project> tick 277 reads status=complete flips task complete, propagates

The decisive fact: the pass criteria were verified in-session, so this is a durability/ordering defect, not a verification-correctness defect.

Root cause

Primary — non-atomic completion, verdict written last

run tier1/tier2
write tasks.yaml  (status=complete, completed_at)   <-- commits first
write verdict.json                                  <-- committed second (lost on kill)

There is no transaction, no ordering guarantee, and no write-ahead marker. A kill between the writes yields complete without a verdict.

Two variants produce the same torn state: code writes the ledger status before running/persisting the verdict (optimistic mark-complete), or code writes the ledger status after the judge but before the verdict is flushed. Both are fixed by the same reordering + atomicity.

Secondary — the judge runs synchronously under a hard client deadline

task complete holds the client connection open for the entire tier1/tier2 judge. The 180s client timeout is therefore a normal termination path whenever the judge is slow. SIGKILL cannot be trapped, so no cleanup handler can save the old code.

Tertiary — no invariant enforcement downstream

<project> treats status: complete as sufficient. Nothing asserts the completion invariant, and there is no reconciler to repair a torn record. So the corruption is not just created, it is accepted.

Invariant that must hold

INV-1: tasks.yaml[t].status == "complete" ⟹ verdicts/<t>.json exists, is valid, and its commit equals tasks.yaml[t].commit.

Every ledger mutation, every <project> tick, and every CLI invocation must preserve INV-1.

Exact fix

1. Add a crash-safe completion module gitreins/completion.py

Ordering rule: verdict durable → then status flip, both via write-temp + fsync + os.replace (+ directory fsync). A crash can then leave at worst verdict-without-status, which the reconciler finalizes safely. It can never leave complete-without-verdict.

# gitreins/completion.py
"""Crash-safe, idempotent task completion.

INV-1: status == "complete"  =>  verdicts/<id>.json exists and matches the commit.

Ordering: the verdict is persisted (atomic) BEFORE the status flip (atomic).
Any crash therefore leaves at worst verdict-without-status, which reconcile()
finalizes. It can never leave complete-without-verdict.
"""
from __future__ import annotations

import errno
import fcntl
import json
import os
import signal
import tempfile
import time
from contextlib import contextmanager
from dataclasses import asdict, dataclass
from pathlib import Path
from typing import Any, Callable, Optional

import yaml


# ----------------------------- atomic primitives -----------------------------

def _fsync_dir(path: Path) -> None:
    fd = os.open(path, os.O_RDONLY | getattr(os, "O_DIRECTORY", 0))
    try:
        os.fsync(fd)
    finally:
        os.close(fd)


def atomic_write_bytes(path: Path, data: bytes) -> None:
    """Durable atomic replace: tmp file -> fsync -> os.replace -> fsync(dir)."""
    path.parent.mkdir(parents=True, exist_ok=True)
    fd, tmp = tempfile.mkstemp(dir=str(path.parent), prefix=f".{path.name}.", suffix=".tmp")
    try:
        with os.fdopen(fd, "wb") as f:
            f.write(data)
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp, path)
        _fsync_dir(path.parent)
    except BaseException:
        try:
            os.unlink(tmp)
        except FileNotFoundError:
            pass
        raise


def atomic_write_json(path: Path, obj: Any) -> None:
    atomic_write_bytes(path, (json.dumps(obj, indent=2, sort_keys=True) + "\n").encode())


def atomic_write_yaml(path: Path, obj: Any) -> None:
    atomic_write_bytes(path, yaml.safe_dump(obj, sort_keys=False).encode())


# ------------------------------- locking -------------------------------------

@contextmanager
def _flock(path: Path, timeout: float = 300.0):
    path.parent.mkdir(parents=True, exist_ok=True)
    fd = os.open(path, os.O_CREAT | os.O_RDWR, 0o644)
    deadline = time.monotonic() + timeout
    try:
        while True:
            try:
                fcntl.flock(fd, fcntl.LOCK_EX | fcntl.LOCK_NB)
                break
            except OSError as e:
                if e.errno not in (errno.EACCES, errno.EAGAIN) or time.monotonic() > deadline:
                    raise
                time.sleep(0.05)
        yield
    finally:
        try:
            fcntl.flock(fd, fcntl.LOCK_UN)
        finally:
            os.close(fd)


def task_lock(root: Path, task_id: str):
    """Serializes judge runs for one task (dedupes concurrent complete calls)."""
    return _flock(Path(root) / ".locks" / f"task-{task_id}.lock")


def ledger_lock(root: Path):
    """Serializes all read-modify-write access to tasks.yaml (CLI and &lt;project&gt;)."""
    return _flock(Path(root) / ".locks" / "tasks.yaml.lock")


# ------------------------------- ledger IO -----------------------------------

def _load_tasks(ledger: Path) -> dict:
    if not ledger.exists():
        return {}
    return yaml.safe_load(ledger.read_text()) or {}


def _save_tasks(ledger: Path, tasks: dict) -> None:
    atomic_write_yaml(ledger, tasks)


def _now_iso() -> str:
    return time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime())


# --------------------------- interruption handling ---------------------------

_interrupted = False


class Interrupted(Exception):
    """Raised at a safe checkpoint after SIGTERM/SIGINT/SIGHUP."""


def install_signal_handlers() -> None:
    """Trap the catchable signals; SIGKILL still cannot be trapped, which is
    exactly why the write ordering (verdict first) must be crash-safe."""
    global _interrupted

    def _handler(signum, frame):  # noqa: ARG001
        global _interrupted
        _interrupted = True

    for sig in (signal.SIGTERM, signal.SIGINT, signal.SIGHUP):
        try:
            signal.signal(sig, _handler)
        except (ValueError, OSError):
            pass


def interrupted() -> bool:
    return _interrupted


# ------------------------------- verdict -------------------------------------

@dataclass
class Verdict:
    task_id: str
    commit: Optional[str]
    passed: bool
    tier1: dict
    tier2: dict
    finished_at: str
    schema_version: int = 1


# ------------------------------ completion -----------------------------------

def complete_task(
    root: Path,
    task_id: str,
    run_judge: Callable[[dict], "Verdict | dict"],
    *,
    completed_at: Optional[str] = None,
) -> dict:
    """Idempotent, crash-safe completion. Returns the resulting task record.

    Phases:
      0. per-task lock (dedupe judges)
      1. read task (ledger lock, short)
      2. reuse or produce verdict, persist it durably      <-- before status
      3. flip status with an atomic read-modify-write
    """
    root = Path(root)
    ledger = root / "tasks.yaml"
    vpath = root / "verdicts" / f"{task_id}.json"

    with task_lock(root, task_id):
        # -- phase 1: read current state
        with ledger_lock(root):
            tasks = _load_tasks(ledger)
            if task_id not in tasks:
                raise KeyError(f"unknown task {task_id!r}")
            task = dict(tasks[task_id])
        commit = task.get("commit")

        # idempotent fast path
        if task.get("status") == "complete" and vpath.is_file():
            return task

        # -- phase 2: verdict must be durable BEFORE any status change
        verdict = None
        if vpath.is_file():
            verdict = json.loads(vpath.read_text())

        if not verdict or verdict.get("commit") != commit or not verdict.get("passed"):
            result = run_judge(task)                 # long-running tier1/tier2
            if _interrupted:
                raise Interrupted(task_id)           # leave state untouched
            verdict = asdict(result) if isinstance(result, Verdict) else dict(result)
            verdict.setdefault("task_id", task_id)
            verdict.setdefault("commit", commit)
            if not verdict.get("passed"):
                # Do NOT mark complete on a failed verdict.
                atomic_write_json(vpath, verdict)
                raise RuntimeError(f"judge failed for {task_id}: {verdict.get('reason', '')}")
            atomic_write_json(vpath, verdict)        # durable commit point

        # -- phase 3: commit the status flip only now
        with ledger_lock(root):
            tasks = _load_tasks(ledger)
            cur = dict(tasks.get(task_id, {}))
            if cur.get("status") == "complete" and vpath.is_file():
                return cur
            cur["id"] = cur.get("id", task_id)
            cur["status"] = "complete"
            cur["completed_at"] = completed_at or _now_iso()
            cur["commit"] = commit
            cur["verdict"] = f"verdicts/{task_id}.json"
            tasks[task_id] = cur
            _save_tasks(ledger, tasks)
            return cur


# ------------------------------ reconciler -----------------------------------

def reconcile(root: Path, *, requeue: bool = True) -> list[dict]:
    """Enforce INV-1. Call at &lt;project&gt; startup and at the top of every tick.

    * complete without verdict  -> downgrade to 'needs_verdict' (requeue judge)
    * verdict present, not complete -> finalize status (safe direction)
    Returns the list of actions taken.
    """
    root = Path(root)
    ledger = root / "tasks.yaml"
    vdir = root / "verdicts"
    actions: list[dict] = []

    with ledger_lock(root):
        tasks = _load_tasks(ledger)
        changed = False
        for tid, task in tasks.items():
            if not isinstance(task, dict):
                continue
            has_verdict = (vdir / f"{tid}.json").is_file()
            if task.get("status") == "complete" and not has_verdict:
                task["status"] = "needs_verdict" if requeue else "in_progress"
                task["reconcile_reason"] = "complete_without_verdict"
                changed = True
                actions.append({"task": tid, "action": "downgrade", "to": task["status"]})
            elif has_verdict and task.get("status") != "complete":
                v = json.loads((vdir / f"{tid}.json").read_text())
                if v.get("passed"):
                    task["status"] = "complete"
                    task["completed_at"] = task.get("completed_at") or v.get("finished_at")
                    task["verdict"] = f"verdicts/{tid}.json"
                    changed = True
                    actions.append({"task": tid, "action": "finalize"})
        if changed:
            _save_tasks(ledger, tasks)
    return actions

def run_judge(task):

3. Route every ledger mutation through the same atomic helper

Any code that writes tasks.yaml (including <project>) must:

with ledger_lock(root):
    tasks = _load_tasks(ledger)
    ...                       # mutate
    _save_tasks(ledger, tasks)   # atomic replace, not open(path, "w")

Writing with a plain open(path, "w") is not acceptable: a kill mid-write truncates/corrupts the entire ledger.

4. Guard <project>: run reconcile() every tick, before using status

# &lt;project&gt; tick
from gitreins.completion import reconcile

def tick(root):
    for action in reconcile(root):        # enforces INV-1 first
        log.warning("reconciled tasks.yaml: %s", action)
    tasks = load_tasks(root / "tasks.yaml")
    for tid, t in tasks.items():
        if t.get("status") != "complete":
            continue
        # Belt-and-braces: status is only trusted if the verdict is present.
        if not (root / "verdicts" / f"{tid}.json").is_file():
            log.error("refusing to propagate complete without verdict: %s", tid)
            continue
        propagate_complete(tid)

5. Decouple the judge from the client timeout (recommended)

  • Preferred — async: task complete enqueues a judge job and returns immediately ({"task_id": ..., "job_id": ..., "state": "judging"}, sub-second). A worker runs the judge and calls complete_task atomically. <project> treats judging as not complete.
  • If synchronous: set the judge budget well under the client timeout (e.g. --timeout 150 for a 180s client), stream heartbeats so the client can distinguish progress from a hang, and add a retry that resumes from an existing verdict (already handled by complete_task).

B. Fault-injection test (proves the torn state cannot occur)

Kill the process at each durable-write boundary and assert INV-1 after every kill, then that reconcile() restores it.

# tests/test_completion_atomicity.py
import os, subprocess, sys, textwrap
from pathlib import Path
import pytest, yaml

CHILD = textwrap.dedent(
    """
    import os, sys
    from pathlib import Path
    import gitreins.completion as c

    root, kill_at = Path(sys.argv[1]), sys.argv[2]
    calls = {"n": 0}

    def counting(orig):
        def inner(*a, **k):
            calls["n"] += 1
            if kill_at == str(calls["n"]):
                os._exit(137)          # simulate the client SIGKILL
            return orig(*a, **k)
        return inner

    c.atomic_write_json = counting(c.atomic_write_json)
    c.atomic_write_yaml = counting(c.atomic_write_yaml)

    def judge(task):
        return {"task_id": task["id"], "commit": task.get("commit"), "passed": True,
                "tier1": {"ok": True}, "tier2": {"ok": True},
                "finished_at": "2026-01-01T00:00:00Z"}

    c.complete_task(root, "T1", judge)
    """
)

@pytest.mark.parametrize("kill_at", ["1", "2", "3"])
def test_never_complete_without_verdict(tmp_path, kill_at):
    (tmp_path / "tasks.yaml").write_text(
        "T1:\n  id: T1\n  status: in_progress\n  commit: abc123\n"
    )
    r = subprocess.run(
        [sys.executable, "-c", CHILD, str(tmp_path), kill_at],
        env={**os.environ, "PYTHONPATH": os.getcwd()},
    )
    assert r.returncode in (0, 137)

    complete = (yaml.safe_load((tmp_path / "tasks.yaml").read_text()) or {})["T1"]["status"] == "complete"
    has_verdict = (tmp_path / "verdicts" / "T1.json").is_file()
    assert not (complete and not has_verdict), f"TORN state at kill point {kill_at}"

    from gitreins.completion import reconcile
    reconcile(tmp_path)
    tasks = yaml.safe_load((tmp_path / "tasks.yaml").read_text()) or {}
    assert not (tasks["T1"]["status"] == "complete" and not has_verdict)

def test_sigterm_before_verdict_leaves_status_untouched(tmp_path):
    import signal, os
    from gitreins import completion as c

    (tmp_path / "tasks.yaml").write_text("T1:\n  id: T1\n  status: in_progress\n  commit: abc\n")
    c.install_signal_handlers()

    def judge(task):
        os.kill(os.getpid(), signal.SIGTERM)   # as if the client gave up
        return {"passed": True, "commit": task["commit"]}

    with pytest.raises(c.Interrupted):
        c.complete_task(tmp_path, "T1", judge)

Why this fix is correct

Requirement Mechanism
No complete without verdict Verdict is fsynced/renamed into place before the status flip; a kill can only leave the safe verdict-without-status direction.
No corrupted ledger on kill Every ledger write is temp-file + fsync + os.replace; a kill cannot truncate tasks.yaml.
Concurrent CLI + <project> writers All ledger read-modify-writes take the same ledger_lock; per-task lock dedupes judge runs.
Retry / timeout resumability complete_task reuses an existing passing verdict (idempotent fast path) and matches it to the task commit.
Downstream cannot be fooled reconcile() runs on every tick and downgrades torn records; <project> additionally re-checks verdict presence before propagating.
Client timeout stops being routine Async judge queue (or a judge budget < client timeout with heartbeats) removes the synchronous long call.

Assumptions

  • tasks.yaml is a task-id→record mapping with a commit field, and verdicts live at verdicts/<task_id>.json.
  • The judge is implemented in Python (gitreins was installed via pipx) and exposes a run_judge(task) entry point.
  • <project> performs a periodic tick() that reads tasks.yaml and propagates completions.

If your layout differs (e.g. verdicts are embedded in a database, or tasks.yaml is generated), keep the three invariants: (1) verdict durable before status, (2) every ledger write atomic, (3) a reconciler that enforces INV-1 on every read.
