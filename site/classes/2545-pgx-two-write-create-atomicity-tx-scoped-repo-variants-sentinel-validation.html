The third test is the key one: it forces the child member insert to fail via a check constraint and asserts count(*) == 0 for the parent workspace, proving the transaction boundary genuinely rolls back rather than just relying on validate-before-write.

Root cause in one line

Two pool-backed writes ran sequentially with autocommit (workspaces.Create then members.Add), so a child FK failure left the parent committed, and the untyped error fell through the handler switch to 500. The fix validates the profile first (sentinel error), runs both writes through shared *Tx helpers on one SQL body inside a pool.Begin + deferred-rollback transaction, and maps the sentinel to 404 PROFILE_NOT_FOUND.
