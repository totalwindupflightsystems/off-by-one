gitreins Tier-2 judge evaluates the wrong repository

Problem class: gitreins-tier2-judge-evaluates-wrong-repo Environment: Hermes fleet host, repo ~/helios-work with a legacy sibling checkout ~/helios in the same home directory Language: Python (GitReins)

Summary

gitreins task complete <id> resolved the source tree to grade by directory name, not by the worktree path recorded with the task. Because the legacy checkout helios is a prefix sibling of the real tree helios-work, a name/prefix match (or a sorted glob) returned ~/helios first. The Tier-2 evaluator therefore read and graded the wrong repository, while the verdict's persisted binding fields (worktree/branch/commit) were taken from the explicit task record and correctly named ~/helios-work (master, 8536349). The result was a confident FAIL whose evidence (internal/api/router.go:54, web/src/api/client.ts:13, "no test files") is true of the legacy clone and false of the worktree that actually contains the task's diff.

Fix in one sentence: resolve the graded tree from the explicit worktree path recorded with the task, canonicalize it with Git, and refuse the verdict unless every cited path/line and every "file absent" claim verifies inside that exact tree.

Root-cause analysis

There are two independent answers to "which repo is this?"

Question Source of truth in the failing run Result
Which tree do we write the verdict for? task/worktree record (worktrees.json / task metadata) ~/helios-work ✔
Which tree do we feed the evaluator? repo name matched against directories (glob/prefix/sort) ~/helios ✘

These two paths were never cross-validated. AgenticEvaluator.read_file() resolves everything relative to self.workdir (full_path = os.path.join(self.workdir, path)), so once the wrong workdir/scan_root was passed, every tool call — read_file, search_pattern, run_command, read_diff — graded the legacy clone. GitReins never noticed, because the evaluator is internally consistent: every path it reads really is inside the tree it was given.

Why helios beats helios-work

The name resolution is prefix/basename keyed. Two common forms both fail the same way:

# prefix glob — sorted() puts "helios" before "helios-work"
sorted(glob.glob(os.path.join(home, f"{repo_name}*")))[0]        # -> $HOME/helios

# exact-basename scan of sibling checkouts, first match wins
next(p for p in os.scandir(home) if p.name.startswith(repo_name))  # -> $HOME/helios

helios sorts first and matches first. The legacy checkout is a different repository (<email>:totalwindup/helios.git) whose entire layout differs from helios-work.

Why the binding fields looked correct

The binding is stamped by engine/persist.py from the task/worktree record (resolve_worktree_identity / the recorded worktree path), not from the evaluator's workdir. So the verdict document truthfully says it graded ~/helios-work@8536349 while its body describes files only present in ~/helios. The binding is not evidence that the evidence is bound.

Why it is not global (calibration)

Only helios-df-062 failed: verdict dirs ae4893fb and d9b3ed81. In the same tick helios-df-064, helios-df-065, and helios-readme-1-3 returned PASS with evidence citing the real tree. A name collision between <name> and <name>-work only misbinds the tasks/surfaces that go through the name-keyed path; anything already passing an absolute worktree path is unaffected. It is a scope-resolution bug, not a judge bug — the judge is faithful to whatever tree it is handed.

The tell

Read the verdict body, then resolve each cited path:line against the binding worktree. If web/src/api/auth.ts (14528 bytes) is in the worktree and the verdict says "no test files" / "file absent", the verdict was bound to a different tree. See the guard in §Fix B.

The fix

Part A — bind the evaluator to the recorded worktree (structural)

Single source of truth: the worktree path recorded with the task. Never derive the graded tree from a name.

Add to engine/repo_paths.py:

def resolve_task_worktree(
    recorded_path: str,
    control_root: str | os.PathLike[str] | None = None,
) -> Path:
    """Return the explicit task worktree, validated against Git and its control root."""
    path = Path(recorded_path).expanduser().resolve(strict=False)
    if not path.is_dir():
        raise WorktreeResolutionError(f"recorded worktree is not a directory: {path}")

    top = _git_path(path, _git_value(path, "rev-parse", "--show-toplevel"))
    if top != path:
        raise WorktreeResolutionError(
            f"recorded worktree {path} resolves to {top}; refusing to grade"
        )
    if control_root is not None:
        root = Path(control_root).expanduser().resolve(strict=False)
        if _git_path(path, _git_value(path, "rev-parse", "--git-common-dir")) != _git_path(
            root, _git_value(root, "rev-parse", "--git-common-dir")
        ):
            raise WorktreeResolutionError(
                f"recorded worktree {path} is not the same repository as control root {root}"
            )
    return path

Then make cmd_task_complete pass that path as both the control root and the scan root, instead of get_workdir() + a name-resolved --scan-root:

# gitreins/cli.py :: cmd_task_complete
from engine.repo_paths import resolve_task_worktree
from engine.worktree_manager import WorktreeManager

workdir = get_workdir()                       # where the verdict is written
resolved = _require_task(tm, args.id)

# The task's own worktree (registry is keyed by task id, never by name).
manager = WorktreeManager(workdir)
record = manager.reconcile_and_persist().get(resolved.id)
if record is None:
    sys.exit(f"no recorded worktree for task {resolved.id}; run `gitreins task worktree {resolved.id}`")
scan_root = resolve_task_worktree(record.path, control_root=workdir)

judge = Judge(llm, scan_root, scan_root=scan_root)   # one tree, no name lookup
result = judge.evaluate_task(task, skip_tier2=skip_tier2)

If the wrapper/scheduler currently passes --scan-root computed from the repo name, delete that computation. Name→path lookup is the bug:

# WRONG — name keying: "helios" matches the legacy sibling first
scan_root="$(ls -d "$HOME/${repo_name}"* 2>/dev/null | head -1)"

# RIGHT — the path recorded with the task, validated by Git
scan_root="$(git -C "$recorded_worktree" rev-parse --show-toplevel)"
[ "$(realpath "$scan_root")" = "$(realpath "$recorded_worktree")" ] || {
  echo "worktree misbinding: recorded=$recorded_worktree resolved=$scan_root" >&2
  exit 3
}

Part B — reject a verdict whose evidence is not in the recorded tree (detection)

Add engine/verdict_guard.py. It validates citations and absence claims from the evaluator's own free-text evidence against the recorded worktree and the task diff. (Full runnable source: /workspace/repro_guard.py.)

_CITATION = re.compile(r"(?<![\w/.-])([A-Za-z0-9_./-]+\.[A-Za-z0-9]+):(\d+)(?:-(\d+))?")
_ABSENT = re.compile(
    r"(?:file|path)?\s*([A-Za-z0-9_./-]+\.[A-Za-z0-9]+)\s+"
    r"(?:is\s+(?:absent|missing)|does not exist|not found|is not present)",
    re.IGNORECASE,
)

def validate_evidence(worktree_root, evidence_details, diff_files):
    violations = []
    blob = "\n".join(evidence_details)
    for m in _CITATION.finditer(blob):
        rel, first, last = m.group(1), int(m.group(2)), m.group(3)
        full = os.path.realpath(os.path.join(worktree_root, rel))
        if not os.path.isfile(full):
            violations.append(Violation("cited-file-absent", f"{rel}:{first} not in {worktree_root}"))
            continue
        end = int(last) if last else first
        total = sum(1 for _ in open(full, errors="replace"))
        if end > total:
            violations.append(Violation("cited-line-out-of-range", f"{rel}:{end} > {total} lines"))
    for m in _ABSENT.finditer(blob):
        rel = m.group(1)
        if rel in diff_files and os.path.isfile(os.path.join(worktree_root, rel)):
            violations.append(Violation("false-absence", f"{rel} reported absent but diff touched it"))
    return violations

Wire it in before _persist_result, so a misbound verdict is never written as a confident FAIL:

# gitreins/cli.py :: cmd_task_complete
result = judge.evaluate_task(task, skip_tier2=skip_tier2)
from engine.verdict_guard import validate_evidence
base = record.branch_point or "HEAD"
diff_files = set(
    subprocess.run(
        ["git", "-C", scan_root, "diff", "--name-only", base, "HEAD"],
        capture_output=True, text=True,
    ).stdout.split()
)
details = [item.detail for item in (result.verdict.items if result.verdict else [])]
violations = validate_evidence(scan_root, details, diff_files)
if violations:
    print("Tier-2 verdict rejected — evidence does not resolve in the recorded worktree:",
          file=sys.stderr)
    for v in violations:
        print(f"  - {v.kind}: {v.detail}", file=sys.stderr)
    print(f"  recorded worktree: {scan_root}", file=sys.stderr)
    print("  This is an infrastructure misbinding, not a FAIL on the work.", file=sys.stderr)
    sys.exit(3)          # refuse; do NOT persist a verdict
_persist_result(workdir, task, result)

Also record every resolved tool read and audit it (cheap, exhaustive):

# in AgenticEvaluator.read_file / search / run: append the realpath to self.read_ledger

if any(not p.startswith(os.path.realpath(scan_root) + os.sep) for p in evaluator.read_ledger):
    raise RuntimeError("evaluator read outside the recorded worktree")
