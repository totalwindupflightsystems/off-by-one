What I found

Root cause: MCP schema declares source.extracted_text required + maxLength: 100000 (caller gets a hard VALIDATION_ERROR when absent), but the handler validates those constraints and then only writes metadata — it never calls CreateSourceArtifact. Validation-passing calls silently discard the payload; the defect is only visible as a missing durable post-condition.

Fix (binary): persist via the existing artifact repo, or remove the required contract. The concrete instance warrants persistence:

// BEFORE — validated, then discarded
h.Sources[sourceID] = struct{}{}
return nil

// AFTER — persist through the existing repo
if _, err := h.Repo.CreateSourceArtifact(ctx, sourceID, in.Source.ExtractedText); err != nil {
    return fmt.Errorf("persist source artifact: %w", err)
}
h.Sources[sourceID] = struct{}{}
return nil

Verification (observed behavior, not assumed call path): - Buggy baseline — TestExtractedTextIsPersisted fails with got 0 (field was discarded) while the two named-error tests pass. - After fix — all three pass: missing_required_field, max_length_exceeded, and the persisted-artifact post-condition.
