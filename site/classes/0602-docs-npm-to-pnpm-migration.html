Answer

EduOS migrated to a pnpm workspace but docs (READMEs, contributing guides, CI snippets, dev guides) still invoked npm. Fix = rewrite all npm invocations to pnpm equivalents, with exactly one intentional exception: the bootstrap step npm install -g pnpm (you need npm once to install pnpm itself).

1. Command mapping applied across docs

Before (npm) After (pnpm)
npm install pnpm install
npm install <pkg> pnpm add <pkg>
npm ci pnpm install --frozen-lockfile
npm run <script> pnpm run <script> (or bare pnpm <script>)
npm test pnpm test
npx <tool> pnpm dlx <tool> / pnpm exec <tool>
npm audit / npm outdated / npm publish pnpm audit / pnpm outdated / pnpm publish
package-lock.json refs pnpm-lock.yaml
npm install -g pnpm kept as-is (bootstrap)

2. Migration script (protect the bootstrap first, or it gets clobbered):

find docs -type f \( -name '*.md' -o -name '*.yml' -o -name '*.yaml' \) -print0 \
| xargs -0 sed -i -E \
  -e 's/npm install -g pnpm/__PNPM_BOOTSTRAP__/g' \
  -e 's/\bnpm install\b/pnpm install/g' \
  -e 's/\bnpm ci\b/pnpm install --frozen-lockfile/g' \
  -e 's/\bnpm test\b/pnpm test/g' \
  -e 's/\bnpm run\b/pnpm run/g' \
  -e 's/\bnpm audit\b/pnpm audit/g' \
  -e 's/\bnpm publish\b/pnpm publish/g' \
  -e 's/\bnpx\b/pnpm dlx/g' \
  -e 's/__PNPM_BOOTSTRAP__/npm install -g pnpm/g'

3. Guard / acceptance check (word-boundary, not literal):

# SATISFIABLE: exactly 1 whole-word 'npm' remains (the bootstrap line)
[ "$(grep -rnw 'npm' docs/ | grep -v 'npm install -g pnpm' | wc -l)" -eq 0 ] \
  && [ "$(grep -rwc 'npm' docs/ | awk -F: '{s+=$2} END{print s}')" -eq 1 ]

The pitfall: pnpm literally contains the substring npm (p+npm), so pnpm install, pnpm test, pnpm run all match a literal grep -c "npm install" / "npm test" / "npm run". A literal AC asserting "0 npm install left" is unsatisfiable — it fails on correct output. Word-boundary grep -w npm matches npm only as a standalone word and never matches inside pnpm, so it can pass iff exactly the bootstrap line remains.

Evidence & signatures

Ran a live demonstration (`/tmp/acdemo`) on a sample containing pre-migration commands:

**Before migration** — literal `grep -c "npm install"` = 3, word-boundary `grep -cw npm` = 4 (genuine npm-word lines).

**After correct migration** (`pnpm install`, `pnpm test`, `pnpm run build`, `npm install -g pnpm` kept, `npx` → `pnpm dlx`):

- **Bad literal AC:** `grep -c "npm install"` → **3** — false positives from the two `pnpm install` lines (substring `npm install`) plus bootstrap. An AC expecting 0 can never pass → confirms why word-boundary greps are mandatory.
- **Good AC:** `grep -cw npm` → **1**; `grep -nw npm` shows only line `7: npm install -g pnpm` → **PASS**.
- **Over-migration bug caught:** an earlier sed pass without the protect/restore step converted the bootstrap to `pnpm install -g pnpm` (word-boundary count dropped to 0); protect/restore fixed it.

Edge cases tested/covered:
- `npm install -g pnpm` preserved (bootstrap exception) — the only remaining `npm` word.
- `pnpm install` / `pnpm test` / `pnpm run` not flagged by `-w` (no substring false positives).
- `npx` → `pnpm dlx` (no leftover `npx`); `npm ci` → `pnpm install --frozen-lockfile` (pnpm has no `ci`).
- `package-lock.json` → `pnpm-lock.yaml` references; `npm` in prose stays untouched because the check is command-pattern based.
- Case-sensitivity: `grep -w` is case-sensitive by design so prose "NPM" isn't over-matched; CI steps reviewed separately.
