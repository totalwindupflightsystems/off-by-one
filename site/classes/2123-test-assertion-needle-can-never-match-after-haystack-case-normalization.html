Fix: TestCHT063PrivateRemoteIsStatedHonestly needle can never match a lowercased haystack

Summary

cht062_install_readme_test.go extracts the README Install section and lowercases it (strings.ToLower) before calling strings.Contains. The test needle is the mixed-case string copied verbatim from the README:

needle := "could not read Username for https://github.com: terminal prompts disabled"

strings.Contains is case-sensitive. Because the haystack is always lowercase, the U in Username can never be found, so the assertion fails on every run even though the README genuinely contains the quoted failure. The test is reporting a defect in itself, not in the documentation.

Root cause

An asymmetric normalization: the haystack passes through strings.ToLower, the needle does not. Any character whose case differs becomes a permanent mismatch.

haystack (after ToLower): ... could not read username for https://github.com: ...
needle (source case):     ... could not read Username for https://github.com: ...
                                      ^ never matches, every run

The failure text at cht062_install_readme_test.go:136 is misleading: it says the Install section "does not quote the real failure" when it does — only the case of the assertion literal is wrong.

General rule: when a haystack is normalized before Contains, the needle must pass through the identical normalization.

Exact fix

Locate the needle declaration/use in cht062_install_readme_test.go (around line 136) and lowercase the needle with the same call used on the haystack, plus a comment recording the asymmetry. Do not change the README or the needle's source casing.

Before:

needle := "could not read Username for https://github.com: terminal prompts disabled"
if !strings.Contains(haystack, needle) {
    t.Fatalf("the Install section does not quote the real failure (`%s`)", needle)
}

After:

// The Install section is lowercased before the Contains check above, so the
// needle must be lowercased with the identical normalization. strings.Contains
// is case-sensitive: do NOT "repair" this literal back to the README's
// mixed-case source form, or the assertion can never match again.
needle := strings.ToLower("could not read Username for https://github.com: terminal prompts disabled")
if !strings.Contains(haystack, needle) {
    t.Fatalf("the Install section does not quote the real failure (`%s`)", needle)
}

If the needle is a shared package-level constant, normalize at the comparison site instead to preserve source casing:

const privateRemoteFailure = "could not read Username for https://github.com: terminal prompts disabled"

// haystack is lowercased; normalize the needle identically (see above).
needle := strings.ToLower(privateRemoteFailure)
if !strings.Contains(haystack, needle) {
    t.Fatalf("the Install section does not quote the real failure (`%s`)", needle)
}

Apply with gofmt:

gofmt -w cht062_install_readme_test.go
go test ./... -run TestCHT063PrivateRemoteIsStatedHonestly -v

Harness used:

package needlerepro

import (
    "strings"
    "testing"
)

// README source content, mixed case exactly as shipped.
const readmeInstall = "`go get` may fail with:\n" +
    "could not read Username for https://github.com: terminal prompts disabled\n"

func extractInstallSection(doc string) string {
    _ = doc
    return readmeInstall
}

func TestCHT063PrivateRemoteIsStatedHonestly(t *testing.T) {
    section := extractInstallSection(readmeInstall)
    haystack := strings.ToLower(section)

    // The haystack is lowercased, so the needle must be lowercased too.
    // strings.Contains is case-sensitive; do not restore source case.
    needle := strings.ToLower("could not read Username for https://github.com: terminal prompts disabled")
    if !strings.Contains(haystack, needle) {
        t.Fatalf("the Install section does not quote the real failure (`%s`)", needle)
    }
}

Why this is the correct fix and not a test weakening

  • The README content is unchanged; the claim being tested is unchanged.
  • The assertion now fails only when the README actually stops quoting the failure, restoring its diagnostic value.
  • The comment prevents a future reader from "fixing" the needle back to source case, which would silently re-introduce the permanent failure.
