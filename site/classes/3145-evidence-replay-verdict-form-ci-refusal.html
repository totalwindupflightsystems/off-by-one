Answer

Verified end-to-end at the board level (the gitreins replay binary itself is a broken symlink in this environment, so the replay-gate portion uses the documented TR-339/TR-350 behavior plus a fresh-clone procedure). Full solution written to /workspace/SOLUTION.md.

Key diagnosis

The bug is a shape mismatch amplified by append-only binding:

  1. Two run-id shapes, one field. The replay gate's resolve_run classifies ids: digit-shaped → GitHub Actions databaseId (portable); otherwise → gitreins verdict-form, resolved from .gitreins/history/<date>/<id>/verdict.json (gitignored local state).

  2. The local CI-mode trap. TR251_CI_MODE=1 doesn't change classification. Locally, .gitreins/history/.../verdict.json exists, so the verdict-form id resolves and replay exits 0. A fresh CI clone has no history → REPLAY-FAIL. A local CI-mode replay is therefore worthless as proof.

  3. Sibling poisoning is the real trap. _row_run_ids collects every run id on the row (detail.evidence[].run_id and top-level evidence_run_id), and replay_diff extends failures unconditionally. A CI run id resolves with continue, not break, so a sibling verdict id still poisons the row.

  4. boardctl update --evidence-run-id is not a fix. I verified experimentally that it appends a new detail.evidence[] entry and never removes the old one — leaving the verdict id on the row.

  5. Both gates are misleading. board_commit_boundary_gate uses shape-agnostic _has_bound_run, and boardctl validate only checks presence of a run id — an unresolved 9c458449 passes both. Neither implies replay success.

Exact fix

  • Find/verify a completed-success Actions run for the graded commit (gh run list --commit …, then gh run view … --jq 'select(.status=="completed" and .conclusion=="success")').
  • Rewrite tasks.jsonl (atomic, idempotent script included) to evict every non-digit id from detail.evidence[].run_id and the top-level evidence_run_id, pin the verified digit CI id, and preserve the verdict id only in detail.evidence[].artifacts / foreman_note.
  • Verify from a clone without .gitreins/history under TR251_CI_MODE=1: pre-rebind REPLAY-FAIL exit 1, post-rebind OK exit 0.

The included rebind script was executed against a live boardctl-format board and confirmed to be idempotent and to leave zero gate-read verdict-form ids.
