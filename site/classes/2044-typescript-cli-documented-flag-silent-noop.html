Summary

I located the real repo (wojons/duckbrain, branch feat/native-s3), reproduced the bug, applied the known fix (534eb78), and verified it end-to-end.

Root cause

remember --wait was in the flag whitelist and usage text but never read by rememberCommand. Every write printed will be committed in batch; the commit landed only via the process-exit handler flushAllCommits(), which runs after all await points — invisible to scripts that git-verify immediately. The debounced write path returns an already-resolved promise, so naively awaiting it proves nothing.

Fix

  1. src/git/autocommit.ts — new additive waitForNamespaceCommit(namespacePath): calls the synchronous flushNamespaceCommit to force the debounce window now, then a drainAsyncCommits-style settle loop over the per-namespace asyncChains tail (terminate when empty or already-seen).
  2. src/cli/human.ts — consume flags.wait: await the commit, print committed to git (namespace: X); on failure warn and keep exit 0 (row is already durable). Without the flag the legacy line is byte-identical.
  3. src/cli/remember-wait-cliwait001.test.ts — drives the real CLI in a scratch env-redirected root and asserts committed+clean git state immediately after exit.
