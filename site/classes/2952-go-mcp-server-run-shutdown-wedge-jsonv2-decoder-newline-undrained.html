Fix: MCP stdio Run hangs after stdin close because a handler owns a blocked stdout write

Root cause

The failure is a lifecycle bug, not a semaphore bug.

Run used a single sync.WaitGroup to wait for request goroutines. Each request goroutine wrote its response inline to stdout:

// before
s.writeMu.Lock()
defer s.writeMu.Unlock()
fmt.Fprintln(s.stdout, string(b))

The test client reads exactly the JSON response value and never reads the trailing newline. Because stdout is an io.Pipe, Write is synchronous: it does not return until every byte, including the newline, has been consumed. Therefore the request goroutine remains parked in io.Pipe.Write.

On stdin EOF, Run executes:

s.wg.Wait() // server.go:164

That Wait is now waiting for a request goroutine blocked on client consumption, not on handler completion. The goroutine dump confirms this:

  • Run goroutine: sync.WaitGroup.Wait at server.go:164
  • request goroutine: io.Pipe.write, reached from fmt.Fprintln in writeResponse at server.go:307
  • not on the concurrency semaphore

Why Go 1.27 exposes it

Go 1.27 enables encoding/json v2 in the baseline. The v2 jsontext decoder performs an initial 64-byte read, while the Go 1.26 decoder uses a larger 512-byte minimum read.

The response value in the test is 64 bytes, followed by a newline. Under Go 1.27 the decoder consumes exactly the value and leaves the newline undrained. Under Go 1.26 the decoder over-reads and happens to drain the newline. The latent lifecycle coupling existed before; the newer decoder merely stops hiding it.

A toolchain floor bump is not a fix. It only changes which decoder read size masks the bug.

Exact fix

1. Add a dedicated response writer to pkg/mcp/server.go

Add fields to Server:

type Server struct {
    // ... existing fields ...

    // Existing: stdout is whatever field currently owns stdout.
    stdout io.Writer

    // Existing concurrency limit. The queue capacity must be at least this.
    sem chan struct{}

    // Existing: now covers request-handler completion only.
    wg sync.WaitGroup

    // New response pipeline.
    respCh   chan []byte
    done     chan struct{}
    stopOnce sync.Once

    // Only touched by responseWriter.
    writeErr error
}

Remove the old per-write mutex from the stdout path. The single writer now serializes all stdout writes.

2. Initialize and start the writer exactly once

Call this from the constructor or from Run before any request goroutine is started:

func (s *Server) initResponseWriter() {
    s.respCh = make(chan []byte, cap(s.sem))
    s.done = make(chan struct{})
    go s.responseWriter()
}

cap(s.sem) is the maximum concurrency, matching the required cap = maxConcurrent.

3. Replace inline stdout writes in writeResponse

Keep the existing response-marshalling and error handling, but replace the direct fmt.Fprintln/mutex block with an enqueue:

func (s *Server) writeResponse(/* existing parameters */) {
    b, err := json.Marshal(resp)
    if err != nil {
        // Keep the existing marshal-error path.
        return
    }
    b = append(b, '\n')

    s.enqueueResponse(b)
}

func (s *Server) enqueueResponse(b []byte) {
    // Once shutdown starts, do not block on a full queue.
    select {
    case <-s.done:
        return
    default:
    }

    select {
    case s.respCh <- b:
    case <-s.done:
        // Shutdown is in progress; handler must not hold Run/Shutdown open.
    }
}

The handler is now done once the bytes are queued. It never performs client-facing I/O.

4. Add the single stdout-owning writer

func (s *Server) responseWriter() {
    for {
        select {
        case b := <-s.respCh:
            s.writeStdout(b)
        case <-s.done:
            // Drain what has already been queued, then exit.
            for {
                select {
                case b := <-s.respCh:
                    s.writeStdout(b)
                default:
                    return
                }
            }
        }
    }
}

func (s *Server) writeStdout(b []byte) {
    if s.writeErr != nil {
        // A previous write failed. Keep draining the queue so handlers
        // cannot block, but do not retry a broken stdout.
        return
    }

    for len(b) > 0 {
        n, err := s.stdout.Write(b)
        if err != nil {
            s.writeErr = err
            return
        }
        if n == 0 {
            s.writeErr = io.ErrShortWrite
            return
        }
        b = b[n:]
    }
}

func (s *Server) stopResponseWriter() {
    s.stopOnce.Do(func() {
        close(s.done)
    })
}

A blocked client write now parks only this writer goroutine. Run and Shutdown must not wait for responseWriter to finish.

5. Update Run and Shutdown

At the top of Run, start the writer and arrange unconditional cleanup:

func (s *Server) Run(ctx context.Context) error {
    s.initResponseWriter()
    defer s.stopResponseWriter()

    // ... existing read/dispatch loop ...

    // Existing EOF / cancellation shutdown point:
    //
    // Signal shutdown BEFORE waiting for handlers. This unblocks any
    // handler attempting to enqueue into a full queue while the writer
    // is parked on a non-reading client.
    s.stopResponseWriter()
    s.wg.Wait()

    // Deliberately do NOT wait for responseWriter here.
    return /* existing result */
}

In Shutdown, use the same lifecycle:

func (s *Server) Shutdown(ctx context.Context) error {
    s.stopResponseWriter()
    s.wg.Wait()

    // Deliberately do NOT wait for responseWriter here.
    return /* existing result */
}

The key invariant is:

  • s.wg waits for handler completion.
  • Nothing waits for client consumption of stdout.

Regression test

Add to pkg/mcp/server_test.go. Use the same server constructor used by the surrounding tests; newTestServer below is a placeholder for that existing helper.

const runReturnBudget = 3 * time.Second

func requireRunReturned(t *testing.T, done <-chan error) error {
    t.Helper()

    select {
    case err := <-done:
        return err
    case <-time.After(runReturnBudget):
        buf := make([]byte, 1<<20)
        n := runtime.Stack(buf, true)
        t.Fatalf(
            "Run did not return after stdin close within %s\n\ngoroutine dump:\n%s",
            runReturnBudget, buf[:n],
        )
        return nil
    }
}

// readOneJSONValue reads exactly one complete JSON object/array from r.
// It stops immediately after the closing delimiter and deliberately does
// not consume any trailing newline.
func readOneJSONValue(r io.Reader) ([]byte, error) {
    one := make([]byte, 1)
    var out []byte
    depth := 0
    started := false
    inString := false
    escaped := false

    for {
        if _, err := io.ReadFull(r, one); err != nil {
            return out, err
        }
        c := one[0]

        if !started {
            switch c {
            case ' ', '\t', '\r', '\n':
                continue
            case '{', '[':
                started = true
                depth = 1
            default:
                return out, fmt.Errorf("expected JSON value, got %q", c)
            }
            out = append(out, c)
            continue
        }

        out = append(out, c)

        if inString {
            switch {
            case escaped:
                escaped = false
            case c == '\\':
                escaped = true
            case c == '"':
                inString = false
            }
            continue
        }

        switch c {
        case '"':
            inString = true
        case '{', '[':
            depth++
        case '}', ']':
            depth--
            if depth == 0 {
                return out, nil
            }
        }
    }
}

func TestServer_Run_NotHeldOpenByUndrainedNewline(t *testing.T) {
    stdinR, stdinW := io.Pipe()
    stdoutR, stdoutW := io.Pipe()

    t.Cleanup(func() {
        _ = stdinW.Close()
        _ = stdoutR.Close()
    })

    // Keep the constructor used by the existing server tests.
    srv := newTestServer(t, stdinR, stdoutW)

    runDone := make(chan error, 1)
    go func() {
        runDone <- srv.Run(context.Background())
    }()

    request := `{"jsonrpc":"2.0","id":1,"method":"ping"}` + "\n"
    if _, err := io.WriteString(stdinW, request); err != nil {
        t.Fatal(err)
    }

    value, err := readOneJSONValue(stdoutR)
    if err != nil {
        t.Fatalf("read response value: %v", err)
    }
    if !json.Valid(value) {
        t.Fatalf("invalid response JSON %q", value)
    }

    // IMPORTANT: do not read stdoutR again. The trailing '\n' is still
    // unread in the pipe, exactly the condition that wedged the old code.

    if err := stdinW.Close(); err != nil {
        t.Fatal(err)
    }

    if err := requireRunReturned(t, runDone); err != nil {
        t.Fatalf("Run returned an error: %v", err)
    }

    // Let a writer parked on the intentionally-undrained newline unwind.
    _ = stdoutR.Close()
}

This test is intentionally stronger than relying on decoder over-read behavior: it reads exactly the response value and never consumes the newline.

No test timeout or production timeout is increased. The fix removes the lifecycle coupling rather than extending the deadline.
