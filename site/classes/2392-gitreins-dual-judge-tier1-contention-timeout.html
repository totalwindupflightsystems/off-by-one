Answer 1

Solution written to ~/gitreins-dual-judge-tier1-contention-timeout.md.

I verified the diagnosis against the actual gitreins==0.15.0 wheel (installed into a throwaway venv), not just the description.

What I confirmed from source

  • Generated Tier‑1 stage is parallel (engine/pipeline.py:1366), so secrets+lint+tests run concurrently within a single judge.
  • Every Tier‑1 script step has a fixed per-step budget, default 120 s (engine/pipeline.py:586).
  • tests honors guards.test_timeout (default 120 s, pipeline.py:1277/1321); secrets and lint have no timeout key, so they inherit 120 s — no config knob.
  • Timeout ⇒ StepResult(passed=False, error="Command timed out") ⇒ stage/overall FAIL.
  • Tier 2 is a separate ai_eval stage with its own budget, so its PASS is real.
  • Verdicts are written to disk before git (engine/persist.py:148–181), so "saved but not committed" is not lost evidence.
  • Same-job_id re-runs auto-chain supersedes/superseded_by (persist.py:160–186).

The fix

# 1. NEVER run two completes concurrently — serialize/stagger
gitreins task complete MEM-API  --force --skip-tier2
gitreins task complete DF-JEV-3 --force --skip-tier2   # only after the first exits

--skip-tier2 is the Tier‑1-only switch (there is no --tier1-only); --force bypasses the dependency check so the already-complete task can be re-graded.

# 2. Durable hardening in .gitreins/config.yaml
guards:
  test_timeout: 900   # covers the tests step only
  hook_timeout: 900   # guard/hook budget (default 300)

For secrets/lint (>120 s or parallel: false) you must declare an explicit pipeline: block, copying the generated step commands (a one-liner to print them is in the doc).

# 3. Keep the false-FAIL dirs as audit trail; board note:
# tier2 PASS in 8e4cf62c + tier1 false-FAIL superseded by tier1 PASS in a4ec552f = final PASS
gitreins report -n 20

Verification evidence (actual runs)

  • Reproduced byte-for-byte: "✗ tests: Command timed out\n ✗ secrets: Command timed out", passed=false.
  • Same 3 s workload with a 30 s budget → passed=True, ✓ tests / ✓ secrets.
  • tier1_plan with test_timeout: 600 → {'secrets': 120, 'lint': 120, 'tests': 600}.
  • Two persist() calls with the same job_id → predecessor superseded_by=...bd1bcbf2, successor supersedes=...9a383a7d.
