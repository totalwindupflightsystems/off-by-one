Answer

I diagnosed the failure, implemented a fix, and verified it. The full written solution is at /workspace/solution.md. Summary:

Root cause

select_scratch_port (scripts/lib/port-guard.sh) is a probe, not a reservation — it checks ss -tlnp and hands the port to the caller without holding it. Every runner selects the port before its multi-second go build, and binds later, so the pick→bind window is seconds wide. In CI a foreign socket took :38614 after the pre-check and before the bind, so the relay died with EADDRINUSE; the "run did not start / pid mismatch / mesh not empty" checks were all downstream fallout. This is the runner-side twin of the already-fixed INT-CI-005 decoy-bind race.

Fix

  1. scripts/lib/port-guard.sh — added two shared helpers:
  2. port_is_free <port> — non-exiting occupancy probe.
  3. reselect_lost_port … — re-probes the chosen port immediately before the bind; if taken, rotates through the same candidate block via select_scratch_port (naming the thief) and updates the caller's port variable. Explicit ports still fail closed, never rotate.
  4. examples/ws-mesh-demo/run-demo.sh — remembered DEMO_PORT_EXPLICIT, and replaced the single start with a bounded reselect_lost_port + start + health rotate-and-retry loop. A real product death (port free, process dead) is still surfaced, not retried.

Verification (all passed)

  • Deterministic repro: old single-attempt start dies on the stolen port; reselect_lost_port rotates :39520 → :39521, comes up healthy, and ss confirms it owns the port.
  • Real runner end-to-end: with a slow-go shim stealing the selected port during the build, run-demo.sh logged the rotation and reached DEMO PASS (exit 0).
  • No regressions: port-guard.sh --selftest 11/11; scratch-port-rotation-selftest.py --case wiring --case ws-mesh-rotate --case ws-mesh-exhaust --case ws-mesh-explicit all pass (97/11/12/13 checks).

The writeup also gives the mechanical recipe (§2.4) for applying the same helper to the federation/gateway/llm-mesh starts. Note the degraded case and the non-ws-mesh live arms are unchanged by this patch.
