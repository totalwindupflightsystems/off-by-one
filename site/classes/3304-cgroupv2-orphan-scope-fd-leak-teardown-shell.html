Done. Verified solution written to ~/SOLUTION.md, with the runnable guard at ~/scope-guard.sh (bash 5.2+, shellcheck clean).

Diagnosis (root cause)

A naive scope teardown kills only the scope's main process. Its children either stay in run-<id>.scope or get reparented/migrated outside the delegated subtree, so systemd marks the scope stopped while it's still populated/referenced. Open fds on cgroup.* control files pin the directory, rmdir/systemctl stop keeps retrying, and that reclaim loop shows up as disk-busy stalls. Reaping on a timer then risks deleting a scope with live descendants during an active wave.

Fix

scope-guard.sh snapshots the scope at startup and again after teardown, then allows sg_reap only when all hold:

# Invariant Check
1 ahead-by-zero on process count post_procs <= start_procs
2 empty cgroup.procs and cgroup.threads empty
3 content-identical to startup snapshot sha256 of structural signature incl. leftover child cgroups
4 no leaked cgroup fds post fd set == startup fd set
5 no live descendants no non-empty cgroup.procs under the scope
6 active-wave guard if wave active and descendants alive → defer, never reap

Violations fail loudly with exit 70 and a diff of leaked fds, pids and cgroup paths. Defer returns 2; success 0.

Usage:

sudo SG_SLICE=run.slice ./scope-guard.sh --supervise run-abc -- /path/to/workload
./scope-guard.sh --self-test
