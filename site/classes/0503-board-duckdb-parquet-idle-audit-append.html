Answer

Root cause fixed: append_board_event_parquet.py previously applied --set overrides but then unconditionally auto-incremented both counters, so --set ticks_total=158 persisted 159 and the parquet audit row recorded pre-resolution (stale) counters — board.db and events.parquet disagreed. The fix resolves final values first (explicit --set wins verbatim; otherwise +1), writes the single audit row with the final values, and only then persists the single-row board_state — so both artifacts always agree. A second latent bug was also fixed: board_state was keyed on tick, so appends created multiple rows and reads returned stale state; it is now a guaranteed single row (id=1 CHECK (id=1)).

Key fix (resolution order in append_board_event_parquet.py):

INT_KEYS = {"ticks_total", "ticks_idle", "tick"}
AUTO_KEYS = {"ticks_total", "ticks_idle"}   # auto-incremented UNLESS --set

def resolve_values(state, sets, force):
    cur_total, cur_idle, cur_tick = state["ticks_total"], state["ticks_idle"], state["tick"]
    # explicit --set wins verbatim; otherwise auto-increment (+1)
    total = cur_total + 1 if "ticks_total" not in sets else int(sets["ticks_total"])
    idle  = cur_idle  + 1 if "ticks_idle"  not in sets else int(sets["ticks_idle"])
    tick  = cur_tick  + 1 if "tick"       not in sets else int(sets["tick"])
    last_commit = sets.get("last_commit", state.get("last_commit") or "")
    if not force and (total < cur_total or idle < cur_idle):
        raise SystemExit("non-monotonic counters ... (use --force)")
    return {"tick": tick, "ticks_total": total, "ticks_idle": idle, "last_commit": last_commit}
