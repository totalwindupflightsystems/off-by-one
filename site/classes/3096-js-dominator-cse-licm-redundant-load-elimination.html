Sound Redundant-Load Elimination and LICM over a Mini SSA IR

Root-cause analysis

The task is not a single mutation to repair; it is a specification whose soundness obligations are easy to violate. A naive "CSE every repeated load" pass is wrong for several independent reasons, and a naive "hoist every load out of a loop" pass is wrong for several more. Each was reproduced and fixed:

# Naive behaviour Why observably wrong
1 CSE a load across an intervening store store may alias the same base (field-insensitively): reader sees the old value
2 CSE a load across opaque(x) the call has unknown memory side effects and may throw
3 Treat a store to p.x as only killing p.x field-insensitive may-alias says it may kill p.y too
4 Use SSA-id identity as the alias test two ids can denote the same object through a phi
5 LICM hoist above a call / throwing op changes exception order and store visibility
6 LICM hoist a load whose base is loop-defined the "invariant" is reallocated each iteration
7 Split a header with several outside predecessors and just repoint edges header phis see duplicate incoming blocks, so the interpreter picks one value for all paths

Two implementation land-mines also surfaced during differential testing:

  • const.value is a literal, not an operand. The rewrite pass did inst.value = sub(inst.value) for every instruction, silently converting const 8 into const 5 when value 8 had been eliminated. Substitution is now op-aware (only store.value is an operand).
  • A self-referential phi never gets a finite points-to set. The conservative fix is to treat it as unknown (aliases everything).

Soundness invariants enforced: 1. A load is removed only if an identical load is available on every path reaching it, and no intervening store/call may alias its base. 2. May-alias is field-insensitive and based on allocation-site points-to sets (conservative through phi). 3. LICM moves a load into the preheader only when invariant, no store in the loop may alias it, the loop has no call, and the base is provably non-faulting. 4. Synthesized preheaders mirror header phis, preserving each original edge's value. 5. calls are never reordered and are barriers for both passes.

Exact fix

Five self-contained Node 20+ files. Full source is in ~/opt/:

  • ir.js — IR schema + reference interpreter (alloc/const/load/store/binop/call, jmp/br/ret, phis). opaque(x) throws on x<0 and mutates the newest object's field, so unsound eliminations become visible.
  • opt.js — Cooper-Harvey-Kennedy dominators; allocation-site points-to (union through phis); available-load must-dataflow with TOP representative; natural-loop detection; preheader synthesis with mirrored phis; conservative LICM. Returns { program, eliminated, hoisted }.
  • gen.js — structured AST → SSA generator with phi insertion at joins and an entry-defined fuel variable to guarantee loop termination.
  • harness.js — 12k-program differential test comparing outcome, final memory, and call/exception trace; validates rewritten IR well-formedness.
  • mutation.js / unit.js — mutation testing and targeted alias/barrier/preheader tests.

The key corrected substitution (the bug that first caused mismatches):

for (const inst of b.insts) {
  if (inst.base != null) inst.base = sub(inst.base);
  // const.value is a LITERAL; only store.value is an operand.
  if (inst.op === 'store' && inst.value != null) inst.value = sub(inst.value);
  if (inst.left != null) inst.left = sub(inst.left);
  if (inst.right != null) inst.right = sub(inst.right);
  if (inst.args) inst.args = patch(inst.args);
}

The key preheader fix (mirrors phis so merged edges stay distinct):

for (const hphi of header.phis) {
  const inc = outside.map((p) => {
    const pair = hphi.incomings.find(([pb]) => pb === p);
    return [p, pair ? pair[1] : 0];
  });
  const np = { id: nid++, op: 'phi', type: hphi.type, incomings: inc };
  ph.phis.push(np);
  const latch = hphi.incomings.filter(([pb]) => !outside.includes(pb));
  hphi.incomings = [[phId, np.id], ...latch];
}

Soundness argument

  • RLE: forward must-analysis. in[B] maps (baseId,field) -> representative load id, intersected over all predecessors requiring an identical representative, initialized to TOP, iterated to fixpoint. A non-TOP representative is on every path reaching the load (dominates it). Stores delete every key whose base may-alias them; calls clear the map. So the replacement executed earlier, did not fault, and sees the same value.
  • Alias: allocation-site sets unioned through phis; disjoint sets cannot alias; unknown aliases everything; distinct allocs are distinct objects.
  • LICM: hoisted loads are invariant with outside, provably non-null bases; no aliasing store anywhere in the loop; no call/throw in the loop; preheaders mirror phis. Moving to the preheader can't change memory state, raise new exceptions, or read a different value.
