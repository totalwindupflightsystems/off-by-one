Zero-Write Worker Stall (futex) — Diagnosis & Recovery Runbook

Problem class: coding-hermes-worker-alive-zero-write-futex Environment: Hermes unattended API-server foreman on Linux Scope: diagnosis only — no repository files were modified Verdict: liveness stall (deadlock-grade unsatisfiable wait), not a slow run and not a correctness failure. Because the worktree had zero writes and no commit, it is in a known base state; preserving it and requeuing is safe and idempotent.

1. Observed signature and what each signal excludes

Signal Observed Meaning / what it rules out
/proc/<pid>/wchan futex_do_wait Blocked inside a futex wait. The process is sleeping until another thread/process issues futex_wake. It is not doing I/O, not computing, not sleeping on a timer.
State S (sleeping) Interruptible sleep. Rules out D (uninterruptible I/O hang), T (job-control stop / cgroup freezer), Z (zombie awaiting reap), R (spinning).
Child processes none (/proc/<pid>/task/*/children empty, pgrep -P empty) Rules out "waiting on a slow child/subsystem". Nobody inside the worker's tree can ever perform the wake.
Worktree git status --porcelain empty, git diff empty, no untracked files, HEAD == base Rules out partial work, index corruption, and an uncommitted-but-real edit.
CPU time across samples utime/stime frozen Rules out a busy-but-silent loop.
Wall clock > 3 minutes Exceeds any bounded step budget.

Reference wchan values (verified in-sandbox) to disambiguate:

pthread condvar / mutex  -> wchan=futex_do_wait
nanosleep/usleep         -> wchan=hrtimer_nanosleep
fifo/pipe rendezvous     -> wchan=wait_for_partner   (read on an open pipe -> pipe_read)

Only futex_do_wait indicates a userspace synchronization dependency that requires an external wake.

2. Root-cause analysis

A futex wait is a symptom of waiting, not a cause. With no child process and no visible peer, the wake-up is unsatisfiable; that makes this a deadlock/liveness bug rather than a throughput problem. Ranked candidate causes in an unattended API-server foreman:

  1. Unattended deadlock on an interactive primitive (most likely). The worker's first step in the isolated worktree blocks on a sync.Cond/pthread_cond_wait/mutex/Event that is supposed to be signaled by an operator TTY, a prompt broker, or the API server callback. In unattended mode that signal never arrives. Signature: futex wait before the first write, single-threaded or all threads parked, no child.

  2. Lock/lease inversion with the foreman. The worker acquires (or waits to acquire) a per-worktree/shared-agent lock, while the foreman holds it and is itself blocked on the worker's completion. Classic circular wait; the futex is the lock.

  3. Runtime-level stall. A Go runtime semacquire / GC assist or sync.Cond that never gets signaled due to a swallowed error path (e.g., the API-server handler returned early and leaked the waiter).

  4. PID/PGID supervision gap (why it lived 3 minutes). The foreman's liveness predicate only asked "is the PID alive?". A futex-parked process is alive, so the supervisor never escalated to a bounded liveness check, never inspected wchan, and never reaped the run.

  5. Excluded: cgroup freezer (would be T), disk/network hang (would be D/pipe_read/poll), OOM kill (PID would be gone), and genuine work (CPU time and writes would advance).

Why zero writes matters: the stall happened before any side effect. There is nothing to reconcile. The correct recovery is therefore: preserve the clean worktree → terminate the exact stalled PID → verify no descendants → requeue. Salvage (stash/branch of a dirty tree) is only needed when the zero-write precondition is violated.

3. The exact fix — recovery runbook (copy/paste usable)

Run as the foreman user. Substitute WT, PID, and BASE from the run journal.

#!/usr/bin/env bash
# recover-zero-write-stall.sh -- preserve, terminate exact PID, verify, requeue
set -euo pipefail

WT="${WT:?worktree path required}"
PID="${PID:?exact worker pid required}"
BASE="${BASE:?expected base commit required}"

# ---- 0. Identity guard: never act on a recycled PID ------------------------
START=$(awk '{print $22}' /proc/$PID/stat)          # starttime (field 22)
EXE=$(readlink /proc/$PID/exe)
echo "worker pid=$PID starttime=$START exe=$EXE"

# ---- 1. Bounded liveness proof: must be sleeping-in-futex AND make no progress
stalled=1
for _ in 1 2 3; do
  read -r _ _ state _ _ _ _ _ _ _ _ _ ut st _ < /proc/$PID/stat
  wchan=$(cat /proc/$PID/wchan 2>/dev/null || echo "?")
  echo "probe: state=$state wchan=$wchan utime=$ut stime=$st"
  case "$state:$wchan" in S:futex_do_wait) : ;; *) stalled=0 ;; esac
done
[ "$stalled" = 1 ] || { echo "NOT a futex stall; escalate for inspection"; exit 2; }

# ---- 2. Descendant snapshot BEFORE killing (must be empty for zero-write) ---
children=$(cat /proc/$PID/task/*/children 2>/dev/null | tr -s ' ' '\n' | grep -E '^[0-9]+$' || true)
[ -z "$children" ] || { echo "worker has children: $children -- inspect before kill"; exit 3; }

# ---- 3. Preserve: record and verify the tree is untouched -------------------
echo "status=[$(git -C "$WT" status --porcelain)]"
echo "diff  =[$(git -C "$WT" diff --stat)]"
echo "untracked=[$(git -C "$WT" ls-files --others --exclude-standard)]"
echo "HEAD=$(git -C "$WT" rev-parse HEAD)  BASE=$BASE"
[ "$(git -C "$WT" rev-parse HEAD)" = "$BASE" ] || { echo "HEAD drifted; SALVAGE, do not requeue"; exit 4; }
[ -z "$(git -C "$WT" status --porcelain)" ] || { echo "tree DIRTY; SALVAGE, do not requeue"; exit 4; }

# ---- 4. Terminate the exact, identity-checked PID (bounded escalation) ------
[ "$(awk '{print $22}' /proc/$PID/stat)" = "$START" ] || { echo "PID reused; refusing"; exit 5; }
kill -TERM "$PID"
for _ in $(seq 1 30); do kill -0 "$PID" 2>/dev/null || break; sleep 0.1; done
if kill -0 "$PID" 2>/dev/null; then
  echo "SIGTERM timed out; escalating SIGKILL"
  kill -KILL "$PID"
  sleep 0.2
fi
kill -0 "$PID" 2>/dev/null && { echo "FAILED to reap $PID"; exit 6; }
echo "reaped pid=$PID"

# ---- 5. Verify no orphaned descendants survived the kill -------------------
pgrep -P "$PID" >/dev/null 2>&1 && { echo "orphans: $(pgrep -P "$PID")"; exit 7; } || echo "no orphans"

# ---- 6. Requeue only now: worktree is provably at BASE and clean -----------
git -C "$WT" worktree prune
# re-dispatch the task against BASE (foreman-specific enqueue command here)
echo "REQUEUE ok: $WT @ $BASE"

Salvage path (only if step 3 fails — tree dirty):

# Preserve work, never discard the worktree:
git -C "$WT" branch -f "salvage/worker-${PID}-$(date +%s)" HEAD
git -C "$WT" stash push -u -m "salvage worker $PID futex stall" || true
# Inspect the stash/branch, then requeue a fresh worktree at BASE.

Never do this: pkill -f hermes, killall, or deleting the worktree. Pattern kills hit sibling workers and other lanes; deleting loses forensic evidence and risks clobbering a peer's tree.

4. Permanent fix — foreman supervisor guard

Replace the "is the PID alive?" liveness predicate with a bounded progress predicate. Contract: the worker touches a heartbeat file at every step boundary; the supervisor kills only when all of the following hold for STALL_DEADLINE seconds:

  1. PID still exists and identity (starttime) unchanged;
  2. utime+stime did not advance;
  3. heartbeat mtime did not advance;
  4. wchan == futex_do_wait (or another explicit stall class) for the whole window.
STALL_DEADLINE=180          # matches the observed >3 min ceiling
HARD_DEADLINE=600           # absolute cap even with progress

watch_worker() {            # wrapper around the agent invocation
  local pid=$1 wt=$2 base=$3 hb=$4 t0=$(date +%s) last=-1 last_hb=0
  while kill -0 "$pid" 2>/dev/null; do
    now=$(date +%s)
    read -r _ _ state _ _ _ _ _ _ _ _ _ ut st _ < /proc/$pid/stat
    cpu=$((ut+st)); hbm=$(stat -c %Y "$hb" 2>/dev/null || echo 0)
    if [ "$cpu" = "$last" ] && [ "$hbm" = "$last_hb" ] && [ "$(cat /proc/$pid/wchan 2>/dev/null)" = futex_do_wait ]; then
      [ $((now-t0)) -ge "$STALL_DEADLINE" ] && { recover_zero_write_stall "$pid" "$wt" "$base"; return 124; }
    else
      t0=$now
    fi
    last=$cpu; last_hb=$hbm
    [ $((now - ${START_TS:-$now})) -ge "$HARD_DEADLINE" ] && { recover_zero_write_stall "$pid" "$wt" "$base"; return 124; }
    sleep 5
  done
}

Also wrap every agent launch in timeout --signal=TERM --kill-after=5s "$HARD_DEADLINE" and run it via setsid so the whole worker process group is bounded and identifiable.

Diagnostic escalation when the stall is reproducible (needs no source change): /proc/<pid>/stack (root), py-spy dump --pid <pid> (Python), kill -QUIT <pid> then read the Go goroutine dump, or gdb -p <pid> -batch -ex 'thread apply all bt'. The first frame tells you which primitive was waiting for the wake.
