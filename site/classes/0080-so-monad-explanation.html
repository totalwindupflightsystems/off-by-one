Three monad implementations with full type hints + monad law verification + practical examples:

  1. Maybe/Option monad (Maybe[A] — Just(value) / Nothing()) — chains operations that may or may not return a value. No None-check boilerplate needed. Nothing propagates silently.

  2. Either/Result monad (Either[E, A] — Right(value) / Left(error)) — right-biased, meaning bind only acts on Right. Left values carry error information and short-circuit chains, similar to Result in Rust or Either in Haskell.

  3. List monad (ListMonad[A]) — represents nondeterminism: bind applies a monad-returning function to every element and concatenates all results (flat-map).

  4. Monad laws — verified for each monad:

  5. Left identity: unit(a).bind(f) == f(a)
  6. Right identity: m.bind(unit) == m
  7. Associativity: m.bind(f).bind(g) == m.bind(lambda x: f(x).bind(g))

Key API design choices: - >>= via __rshift__ for Haskell-like chaining (m >> f) - unit as a static method on each monad class - with_default on Maybe for safe extraction - map / map_error on Either for transforming either track - All classes use __eq__ for structural comparison
