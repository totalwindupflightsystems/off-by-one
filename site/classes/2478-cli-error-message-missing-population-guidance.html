Fix: snapshot-mode CLI must explain how the state-backups directory is populated

Problem class: cli-error-message-missing-population-guidance Source: hermes-canopy DF-71 tick 2026-09-30, commit 820c4455

1. Symptom

Running a snapshot-mode subcommand (e.g. hermes restore, hermes inspect) when ~/.hermes/state-backups does not exist fails with a bare message:

error: snapshot directory does not exist

The user cannot answer: who populates it, what a valid file looks like, how to fix it now. Because restore and inspect each carried their own copy of the message, the guidance drifted.

2. Root cause

The missing-prerequisite branch was a local, per-subcommand string that stated only the condition without the remediation. No contract tied the error path to --help. Second, subtler defect: "directory missing" and "directory present but empty" were conflated, so --snapshot-dir <existing-empty> could produce the misleading "does not exist" text.

3. The fix

3.1 One shared guidance constant (rendered verbatim by every sibling, and in the help epilog):

DEFAULT_SNAPSHOT_DIR = Path.home() / ".hermes" / "state-backups"
SNAPSHOT_GLOB = "state-*.snapshot"

SNAPSHOT_DIR_GUIDANCE = (
    "This directory is populated by the scheduled 'hermes-snapshot' job "
    "(systemd timer hermes-snapshot.timer), which writes one file per run "
    "named like 'state-20260930T120000Z.snapshot'.\n"
    "\n"
    "Manual fallback:\n"
    "  mkdir -p ~/.hermes/state-backups\n"
    "  cp <your-state-file>.snapshot ~/.hermes/state-backups/state-<UTC>.snapshot\n"
    "\n"
    "One-off alternative: bypass snapshots entirely with --db <file>."
)

3.2 Separate the two failure states:

def _require_snapshot(snapshot_dir: Path) -> Path:
    if not snapshot_dir.is_dir():
        raise SystemExit(
            f"error: snapshot directory '{snapshot_dir}' does not exist.\n"
            f"{SNAPSHOT_DIR_GUIDANCE}")
    snapshots = sorted(snapshot_dir.glob(SNAPSHOT_GLOB))
    if not snapshots:
        raise SystemExit(
            f"error: no snapshots found in '{snapshot_dir}' "
            f"(expected files matching '{SNAPSHOT_GLOB}').\n"
            f"{SNAPSHOT_DIR_GUIDANCE}")
    return snapshots[-1]

3.3 Wire into --help for root parser and each subparser (epilog=SNAPSHOT_DIR_GUIDANCE, RawDescriptionHelpFormatter). For Go cobra: a package-level const SnapshotDirGuidance, referenced from RunE errors and the command Long/Example.

3.4 Pin with a substring-set test on both surfaces:

REQUIRED = ["scheduled", "hermes-snapshot", "state-20260930T120000Z",
            "mkdir -p", "cp ", "--db"]

def test_missing_dir_error_carries_full_guidance(tmp_path):
    r = run("restore", "--snapshot-dir", str(tmp_path / "absent"))
    assert r.returncode != 0
    assert not [s for s in REQUIRED if s not in r.stderr]

def test_help_carries_full_guidance():
    r = run("--help")
    assert not [s for s in REQUIRED if s not in r.stdout]

  cp <your-state-file>.snapshot ~/.hermes/state-backups/state-<UTC>.snapshot
One-off alternative: bypass snapshots entirely with --db <file>.

Falsification 2 — --snapshot-dir at an existing empty dir hits the no-snapshot error, not the missing-dir error:

$ python3 snapshot_cli.py restore --snapshot-dir ~/empty-snap
error: no snapshots found in '~/empty-snap' (expected files matching 'state-*.snapshot').

First lines differ (no snapshots found vs does not exist), proving the states are no longer conflated.
