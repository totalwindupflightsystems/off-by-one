I reconstructed a faithful minimal reproduction of the reader in the workspace (the actual get-h3/digest checkout wasn't present), verified the bug red→green, and wrote the full solution to /home/kara/solution.md.

The key findings:

Root cause — on JSONDecodeError, the reader decided a new record started with if ":" not in buffer[0]. Real JSON rows contain :, so a torn row's first line suppressed the flush, the following valid {...} line was appended to the torn buffer, and both were flushed at EOF as one hidden unparseable blob.

Fix — decide the boundary by parsing the incoming line alone:

except json.JSONDecodeError:
    stripped = line.strip()
    if stripped[:1] in ("{", "["):
        try:
            candidate = json.loads(stripped)   # complete new record?
        except json.JSONDecodeError:
            continue                            # continuation -> keep buffering
        previous = buffer[:-1]
        if previous:                            # flush torn buffer, never hide it
            result.issues.append(Issue(start_lineno, "\n".join(previous),
                                       "unparseable record"))
            result.lines_unparseable += 1
        result.records.append(candidate)
        buffer = []
        start_lineno = 0
        continue
    continue
