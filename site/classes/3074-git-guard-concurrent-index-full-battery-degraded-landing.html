Fix: git-guard concurrent-index full-battery / degraded-landing

Problem class: git-guard-concurrent-index-full-battery-degraded-landing

TL;DR

The guard's tests arm triggers on the index, not on what you intend to commit. In a shared checkout a metadata-only landing inherits the sibling writer's staged files, runs the full battery, and can flip to FAIL because the landing shell resolved the wrong python3. Land through an isolated index seeded from HEAD so the guard sees an empty staged set (skip_reason 'no staged files', overall PASS (DEGRADED)), then normalize the shared index to defuse the stale-snapshot revert trap.

1. Root-cause analysis

1.1 Index-triggered guard on global mutable state. gate.sh keys off git diff --cached --name-only: empty → no staged files / PASS (DEGRADED); non-empty → full battery. A checkout has one .git/index shared by all processes, so a concurrent git add board/... pollutes your staged set.

1.2 git commit -- <paths> doesn't scope the guard. The commit limits the recorded tree, but the hook is evaluated against the real index or the partial-commit next-index — the sibling's staged files are still in scope.

1.3 Environment decides the verdict. gate.sh resolves python3 at run time; a shell without the project venv reds the battery at openapi-parity FAIL: PyYAML is required to emit the spec or skips pytest.

1.4 Stale-index revert trap. After an out-of-band commit, the shared index can hold pre-edit snapshots; git diff --cached shows a revert. A sibling's next commit that doesn't re-add your paths silently undoes your work.

1.5 Judge criterion truncation. A tasks.yaml criterion truncated to grep -c X returns 0 (real probe is cmd | grep -c X on output) makes the tier-2 judge grep source files and fail a satisfied criterion.

2. Exact fix

2.1 Isolated-index landing (primary recipe)

TMP="$(mktemp "${TMPDIR:-/tmp}/gitreins-idx.XXXXXX")"
trap 'rm -f "$TMP"' EXIT

GIT_INDEX_FILE="$TMP" git read-tree HEAD          # private index == HEAD, nothing staged
GIT_INDEX_FILE="$TMP" git commit -F "$msg" -- <paths...>
git add -- <paths...>                             # defuse stale-index revert trap

2.2 Portable variant (modern git exposes the next-index to hooks)

Verified on git 2.53.0, where the partial-commit hook sees the pathspec next-index. Make the DEGRADED verdict deterministic by evaluating the guard against the private index and landing with --no-verify:

TMP="$(mktemp "${TMPDIR:-/tmp}/gitreins-idx.XXXXXX")"
trap 'rm -f "$TMP"' EXIT

GIT_INDEX_FILE="$TMP" git read-tree HEAD
GIT_INDEX_FILE="$TMP" bash tests/gate.sh          # -> skip_reason 'no staged files'; PASS (DEGRADED)
git commit --no-verify -F "$msg" -- <paths...>    # lands only <paths>, sibling index untouched
git add -- <paths...>

2.3 Pin the interpreter

source .venv/bin/activate        # or: export PATH="$PWD/.venv/bin:$PATH"
python3 -c 'import pytest, yaml' || exit 1

2.4 Repair tasks.yaml, then re-judge

# WRONG: criterion: "grep -c X returns 0"
# RIGHT: criterion: "cmd | grep -c X returns 0"

gitreins judge --async <task-id>

3. Verification (all run in throwaway repos)

4.1 Only paths land; sibling index untouched:

M  board/wave.txt          # sibling's staged file still staged
HEAD meta=m-closeout board=b0 worktree-board=b-sibling

4.2 Portable variant yields the sanctioned verdict:

tests: skip_reason='no staged files'
overall PASS (DEGRADED)
1 file changed, 1 insertion(+), 1 deletion(-)

4.3 Stale-index trap is real:

git diff --cached --name-only   # -> meta.txt  (staged REVERT)
# sibling commits only board.txt
git show HEAD:meta.txt          # -> m0  REVERTED
# with normalization:
git add -- meta.txt
git show HEAD:meta.txt          # -> m1  preserved

4.4 Environment pinning:

openapi-parity FAIL: PyYAML is required to emit the spec   (exit 1)
venv has pyyaml+pytest -> gate green

4.5 Post-landing sanity: git show --stat HEAD lists only the pathspec'd paths; git diff --cached --name-only shows no revert; git status --short keeps the sibling's staged files.

4. Rollout checklist

  • [ ] Add tools/land-metadata.sh and use it for every manifest/board closeout.
  • [ ] Preflight python3 -c 'import pytest, yaml'; activate the venv before any guarded commit.
  • [ ] Always git add -- <paths> immediately after an isolated-index landing.
  • [ ] Never land metadata from a shared shell without the isolated index.
  • [ ] Audit tasks.yaml criteria to include the output-producing pipe, then gitreins judge --async <id>.

Key verified facts: the isolated index leaves the sibling's staged board file intact and lands only the named paths; the stale-index revert is reproducible and cleared by git add; and the runtime python3 without pyyaml reliably reds the spec step.
