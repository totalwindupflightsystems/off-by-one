Fixing the silent exit 1 in acceptance-matrix.sh cell 2b (postgres)

Ticket: INT-CI-010 · Commit: 7677578 (board-only) · Runs: 37763860613 (x2, incl. rerun) Symptom: cell 2b (postgres) dies with status 1 ~13 s after the port-guard, and the log ends with no PASS / FAIL / SKIP and no ERROR line. Locally the same commit is green 2/2.

Verdict: a set -euo pipefail silent kill, not a test failure. The cell aborts inside bash before its reporter runs. Since the commit is board-only and only the runner is red, the correct first action is instrumentation, not a blind logic patch (as filed in INT-CI-010).

1. What the evidence already proves

Observation Conclusion
Exit status exactly 1 (not 137/143/134) Not an OOM kill or fatal signal. Bash chose to exit.
The cell's PASS/FAIL/SKIP/ERROR reporter never printed Death happened before/outside the reporting path — a set -e trip on an unguarded command.
Zero output, not even a bash error The failing command's stderr is redirected/captured (2>/dev/null, $(…)).
Same commit green locally, only runner red Environmental, not a regression. The board-only commit changed nothing.
~13 s, repeatable across original + rerun A fixed-duration window: a bounded retry/sleep loop, or Postgres' init→restart cycle.

set -e aborts on the first unguarded non-zero status. Under set -u/pipefail there is a family of commands that return non-zero without output, so a self-inflicted exit looks like an external kill.

2. Root cause

The matrix runs under set -euo pipefail with no ERR/EXIT trap. Any command after the port-guard that returns non-zero while its stderr is suppressed exits the script with 1 and prints nothing. The usual culprits, all reproduced locally (see §5):

  1. Command substitution/assignment whose command fails — out="$(tool 2>/dev/null)". The assignment trips set -e; stderr was redirected, so it's silent. Most common cause of "exit 1, no output".
  2. grep -q under pipefail — returns 1 on no match and can SIGPIPE the producer; fatal if the check was only informational.
  3. ((i++)) when i == 0 — post-increment returns the old value, status 1, set -e kills the shell (confirmed on bash 5.3).
  4. A failure inside a function/subshell with captured stderr, or wait on a failed background job.
  5. Postgres init/restart race (the ~13 s clue) — the official image starts a temporary server for initdb, stops it, then starts the real one. A nc -z//dev/tcp port-guard passes against the temporary server; the next psql/pg_isready lands in the gap. Wider on a loaded runner than a developer box.

set -u alone is not silent — bash prints …: parameter not set (verified). So a truly empty log means set -e + suppressed stderr.

3. Exact fix

Step 1 — instrument cell 2b on the runner (required first; zero behaviour change)

scripts/ci/trace-cell.sh:

# shellcheck shell=bash
# scripts/ci/trace-cell.sh — per-cell abort diagnostics for acceptance-matrix.sh
set -E                                  # ERR trap is inherited by functions and subshells
: "${CI_CELL_NAME:=cell}"               # caller sets the cell id, e.g. 2b
export PS4='+ ${CI_CELL_NAME} \t ${BASH_SOURCE##*/}:${LINENO}:${FUNCNAME[0]:-main} + '
CELL_TRACE=${CELL_TRACE:-0}             # CELL_TRACE=1 -> full `bash -x` per-line trace
_on_err() {
    local rc=$?
    printf '\n[%s] ABORT rc=%s at %s:%s in %s\n[%s] failed command: %s\n' \
        "$CI_CELL_NAME" "$rc" "${BASH_SOURCE[1]:-main}" "${BASH_LINENO[0]:-?}" \
        "${FUNCNAME[1]:-main}" "$CI_CELL_NAME" "$BASH_COMMAND" >&2
    exit "$rc"
}
trap '_on_err' ERR
if [ "$CELL_TRACE" = 1 ]; then set -x; fi

Source it right after the existing set -euo pipefail in scripts/acceptance-matrix.sh:

 set -euo pipefail
+
+# INT-CI-010: never die without naming the line. See scripts/ci/trace-cell.sh.
+CI_CELL_NAME="${CI_CELL_NAME:-matrix}"
+. "$(dirname "$0")/ci/trace-cell.sh"

The \t in PS4 timestamps every trace line — that is what pins the ~13 s window to a specific sleep/retry.

Step 2 — read the one line the trace adds, apply the matching fix

Revealed command Permanent fix
out="$(tool 2>/dev/null)" if ! out=$(tool 2>&1); then echo "[2b] FAIL tool rc=$?"; return 1; fi
printf … \| grep -q PAT (informational) … \| grep -q PAT \|\| true, or capture and test
((i++)) from 0 i=$((i+1)), or ((i++)) \|\| true
docker exec "$CID" … right after port-guard Fix the guard (see §4), not the call
wait "$pid" wait "$pid" \|\| { echo "[2b] FAIL child rc=$?"; return 1; }

Step 3 — make the class impossible (per-cell result contract)

run_cell() {                             # run_cell 2b postgres_cell_2b
    local name=$1 fn=$2 rc
    (
        set -euo pipefail
        CI_CELL_NAME=$name
        . "$(dirname "$0")/ci/trace-cell.sh"
        "$fn"
    ); rc=$?
    if [ "$rc" -eq 0 ]; then printf 'CELL %s PASS\n' "$name"
    else                     printf 'CELL %s FAIL rc=%s\n' "$name" "$rc"; FAIL=$((FAIL+1)); fi
    return 0
}

No cell can ever die without printing a result again.

4. Postgres-specific hardening (after the trace confirms it)

Make readiness stable, not merely open:

stable=0
for _ in $(seq 1 60); do
    if docker exec "$PG" pg_isready -U "$PGUSER" -d "$PGDB" >/dev/null 2>&1; then
        stable=$((stable+1))
        [ "$stable" -ge 3 ] && break
    else
        stable=0
    fi
    sleep 1
done
if [ "$stable" -lt 3 ]; then
    echo "[2b] ERROR: postgres never reached stable readiness"
    docker logs --tail=100 "$PG" >&2 || true
    exit 1
fi

Also give Postgres shared memory (--shm-size=256m) and check docker inspect -f '{{.State.OOMKilled}}'.

Board-only commit + runner-only reproduction means nothing should be patched blind.
