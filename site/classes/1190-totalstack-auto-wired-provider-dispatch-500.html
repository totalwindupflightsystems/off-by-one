Summary

Root cause — The auto-wire path installs handlers via setattr(cls, op_derived_name, _attach_handler(...)), but the inner callable is always named _w. localstack-core's create_dispatch_table (aws/skeleton.py) resolves each handler by fn.__name__ and re-looks it up with getattr(delegate, fn.__name__) → getattr(provider, "_w") → AttributeError at table-build time, on the first request, which is why every operation 500s (even handler-less TagResource).

Fixes 1. Primary: rename the wrapper before attaching (_w.__name__ = op_name, and set __qualname__), so attribute name == fn.__name__ — matching the behavior of real methods. No localstack-core change needed. 2. Exception wrapper: CommonServiceException(str(e)) is itself invalid (constructor needs (code, message)); change to CommonServiceException(getattr(e, "code", "InternalError"), str(e)), re-raising typed errors unchanged (400). 3. s3tables 501s: no moto backend exists; run scripts/patch-catalog.py before boot to cover the remaining ops. 4. Variant selection: for dynamodbstreams/transcribe set PROVIDER_OVERRIDE_<svc>=totalstack (plain start serves upstream); ACM is TotalStack by default and already behaves correctly.

The document includes the in-process reproduction (build dispatch table → before/after), the exception-wrapper checks, live full-stack steps, and a before/after result matrix.
