Answer

Handling a Pre-Existing Full-Gate Baseline Red Without Bypassing the Guard

Problem class: gitreins-guard-red-preexisting-baseline-no-verify-policy
Verified example: auger AUG-117, baseline 30f4f65, fix commits 6fe905f + 4d89882
Verdict: tier2 PASS / tier1 baseline FAIL (expected and correctly attributed)

1. Root Cause

The repository’s gitreins guard runs the full live gate:

test_command = bash tests/gate.sh
test_mode    = full

That gate includes live-substrate tests. On this tick, origin/main was already red for reasons unrelated to the candidate diff:

  • 6 propagate/ask tests failed at auger.py:817
  • Error: 422 Column 'proposed_by_model' (varchar) requires a string, got null in table 'question'
  • This is a live substrate/schema drift, owned by a different subsystem

Because the guard runs the whole gate, it cannot distinguish:

  1. failures introduced by the candidate diff, and
  2. failures already present on clean origin/main.

Hosted CI skips the live arms, so it cannot see this red either. The guard and CI therefore have complementary blind spots: the local full gate sees the live baseline red, while hosted CI cannot. Silencing or weakening either surface would hide real regressions.

The correct resolution is attribution, not bypass:

  • File the baseline as its own P1 board row.
  • Reproduce the exact failures by name on a clean origin/main worktree.
  • Only if the failure set and errors are identical may the verified diff be committed with --no-verify.
  • Record the evidence in the commit message and on the board row.
  • Keep hosted CI green as the independent amplifier.

Without the clean-tree proof, --no-verify is a bypass. With it, the red is assigned to its owner and tracked so it cannot rot.

2. Decision Rule

Use this rule before every --no-verify:

Condition Action
Failing tests also fail identically on clean origin/main File baseline row, commit with --no-verify, attach proof
Failing tests pass on clean origin/main Do not use --no-verify; fix the diff
Failure set differs between clean baseline and fix tree Treat as diff-caused; do not bypass
Baseline row missing or unreproducible Do not use --no-verify
Error text differs even if test names match Do not bypass without renewed diagnosis

In short: no board row + no clean-tree proof = no --no-verify.

3. Step-by-Step Fix

Step 1: Capture the exact failing test set by name

Run the full gate on the fix tree and preserve the log:

cd /path/to/auger
set -o pipefail
bash tests/gate.sh 2>&1 | tee /tmp/gate-red.log

Extract the failing pytest node IDs:

grep -E '^FAILED ' /tmp/gate-red.log \
  | sed -E 's/^FAILED ([^ ]+).*/\1/' \
  | sort -u > /tmp/failing-node-ids.txt

cat /tmp/failing-node-ids.txt
wc -l < /tmp/failing-node-ids.txt   # expected: 6

Expected failure signature:

422 Column 'proposed_by_model' (varchar) requires a string, got null in table 'question'
at auger.py:817

Also record the fix-tree summary, e.g.:

354 passed, 6 failed

The six node IDs in /tmp/failing-node-ids.txt are the reproduce-by-name set. Do not replace them with broad test-file names or directory-level selectors.

Step 2: File the baseline board row FIRST

Create GATE-RED-002 as a P1 baseline row before attempting the commit. Use the board CLI/API in your environment; the required payload is:

{
  "id": "GATE-RED-002",
  "priority": "P1",
  "title": "Baseline red: 6 propagate/ask tests fail on clean origin/main at auger.py:817 due to live schema drift",
  "status": "open",
  "baseline_commit": "30f4f65",
  "failing_tests": [
    "<six node IDs from /tmp/failing-node-ids.txt>"
  ],
  "error_signature": "422 Column 'proposed_by_model' (varchar) requires a string, got null in table 'question' at auger.py:817",
  "reproduce": "git worktree add /tmp/auger-baseline origin/main --detach && cd /tmp/auger-baseline && pytest <six node IDs> -q --tb=short",
  "owner_subsystem": "live substrate / schema drift",
  "guard": "investigating",
  "guard_reason": "Suspected pre-existing baseline; clean origin/main proof pending",
  "ci": "hosted CI green but skips live arms; local full gate is the only observer",
  "acceptance_criteria": [
    "All six named tests fail identically on clean origin/main 30f4f65",
    "Failure set and error signatures are byte-for-byte comparable",
    "Runtime is in the same seconds-scale range",
    "Board row remains open until clean origin/main passes all six tests",
    "Any guard exception is removed once the baseline is fixed"
  ]
}

If the board is markdown-based, the minimum row is:

| GATE-RED-002 | P1 | 6 propagate/ask tests fail on clean origin/main 30f4f65 at auger.py:817: 422 `proposed_by_model` null | Reproduce the six named node IDs in a clean `origin/main` worktree | Substrate/schema | Guard=investigating |

The row must exist before the --no-verify commit. Its acceptance criteria are reproduce-by-name: the exact six test node IDs, the exact error signature, on the pinned baseline commit.

Step 3: Prove the failure is pre-existing on clean origin/main

Create a clean worktree at the recorded baseline:

REPO=/path/to/auger
BASE=30f4f65
WT=/tmp/auger-baseline

git -C "$REPO" worktree remove --force "$WT" 2>/dev/null || true
git -C "$REPO" fetch origin --prune
git -C "$REPO" worktree add --detach "$WT" origin/main

test "$(git -C "$WT" rev-parse --short=7 HEAD)" = "$BASE"

If the HEAD assertion fails, stop. Do not commit with --no-verify until the baseline commit matches the board row.

Run only the failing tests, using the same interpreter, environment, and database configuration as tests/gate.sh:

cd "$WT"

# Activate/export exactly what the gate uses, for example:
# source .venv/bin/activate
# export DATABASE_URL=...
# export APP_ENV=...

mapfile -t NODES < /tmp/failing-node-ids.txt

start=$(date +%s)
set -o pipefail
pytest "${NODES[@]}" -q --tb=short 2>&1 | tee /tmp/baseline-proof.log
status=${PIPESTATUS[0]}
end=$(date +%s)

echo "baseline runtime: $((end - start))s"
echo "pytest exit: $status"

Expected result:

6 failed
runtime: approx. 16.91s on the verified AUG-117 run
same 422 / proposed_by_model / auger.py:817 signature

Extract and compare the failing set mechanically:

grep -E '^FAILED ' /tmp/baseline-proof.log \
  | sed -E 's/^FAILED ([^ ]+).*/\1/' \
  | sort -u > /tmp/baseline-node-ids.txt

diff -u /tmp/failing-node-ids.txt /tmp/baseline-node-ids.txt

Required outcomes:

# 1. Identical node IDs
diff -u /tmp/failing-node-ids.txt /tmp/baseline-node-ids.txt

# 2. Same error signature present in the clean run
grep -F "requires a string, got null in table 'question'" /tmp/baseline-proof.log
grep -F "auger.py:817" /tmp/baseline-proof.log

# 3. Same seconds-scale runtime
grep -F "baseline runtime:" /dev/null || true   # retain the recorded timing from the command above

Do not proceed if:

  • the clean worktree passes any of the six tests,
  • the node-ID diff is non-empty,
  • the error text differs,
  • or the runtime indicates a different execution path.

That would make the red diff-caused or otherwise unproven.

Step 4: Commit the verified diff with evidence in the message

First inspect the candidate diff to ensure it contains only intended changes:

cd "$REPO"
git status --short
git diff --stat
git diff

Then stage only the verified paths:

git add path/to/changed/file1 path/to/changed/file2

Write the commit message with the baseline evidence:

{
  echo "fix(<scope>): <verified change>"
  echo
  echo "Baseline red: GATE-RED-002 (P1)"
  echo "Baseline commit: 30f4f65 (origin/main)"
  echo
  echo "Pre-existing failing set on clean origin/main (6 tests):"
  sed 's/^/  - /' /tmp/failing-node-ids.txt
  echo
  echo "Baseline proof command:"
  echo "  git worktree add /tmp/auger-baseline origin/main --detach"
  echo "  cd /tmp/auger-baseline"
  echo "  pytest <six node IDs> -q --tb=short"
  echo
  echo "Baseline proof result:"
  echo "  6 failed, identical errors (422 Column 'proposed_by_model' requires a string, got null in table 'question' at auger.py:817), 16.91s"
  echo
  echo "Fix-tree gate result:"
  echo "  354 passed, 6 failed (same pre-existing baseline set)"
  echo
  echo "CI status:"
  echo "  Hosted CI green; live arms are skipped in CI, so local full-gate proof is authoritative for this baseline."
  echo
  echo "Guard:"
  echo "  SKIP-with-reason authorized by clean origin/main proof; not an unproven bypass."
  echo "  Baseline owner/row: GATE-RED-002."
} > /tmp/gate-red-commit-msg

git commit --no-verify -F /tmp/gate-red-commit-msg

Push normally:

git push origin HEAD

Record the resulting commit SHA. In the verified AUG-117 run these were 6fe905f and 4d89882.

Step 5: Update the board row with the proof and guard decision

After the push, update GATE-RED-002 to include:

{
  "id": "GATE-RED-002",
  "priority": "P1",
  "status": "open",
  "baseline_commit": "30f4f65",
  "failing_tests": [
    "<six exact node IDs>"
  ],
  "baseline_proof_command": "git worktree add /tmp/auger-baseline origin/main --detach && cd /tmp/auger-baseline && pytest <six node IDs> -q --tb=short",
  "baseline_proof_result": "6 failed, identical 422 proposed_by_model errors at auger.py:817, 16.91s",
  "fix_tree_result": "354 passed, 6 failed (same baseline set)",
  "commits": ["6fe905f", "4d89882"],
  "ci": "green on both commits; live arms skipped",
  "guard": "SKIP-with-reason",
  "guard_reason": "Pre-existing live-substrate baseline proven on clean origin/main; failure attributed to GATE-RED-002, not to the candidate diff",
  "owner_subsystem": "substrate/schema",
  "acceptance": "Close only after clean origin/main passes all six named tests; then remove the guard exception"
}

The board row is the durable ownership record. Hosted CI being green does not clear it, because CI cannot observe live-substrate reds.

Step 6: Clean up the proof worktree

git -C "$REPO" worktree remove "$WT"

Keep /tmp/gate-red.log, /tmp/baseline-proof.log, and the node-ID lists until the board row is closed, in case the proof needs to be replayed.

4. One-Shot Baseline Proof Script

Save as /tmp/prove-baseline.sh and run from the repository after capturing /tmp/failing-node-ids.txt:

#!/usr/bin/env bash
set -euo pipefail

REPO=${REPO:-/path/to/auger}
BASE=${BASE:-30f4f65}
WT=${WT:-/tmp/auger-baseline}
FAILED=${FAILED:-/tmp/failing-node-ids.txt}

[[ -s "$FAILED" ]] || { echo "Missing failing node IDs: $FAILED" >&2; exit 2; }

git -C "$REPO" worktree remove --force "$WT" 2>/dev/null || true
git -C "$REPO" fetch origin --prune
git -C "$REPO" worktree add --detach "$WT" origin/main

actual=$(git -C "$WT" rev-parse --short=7 HEAD)
if [[ "$actual" != "$BASE" ]]; then
  echo "Baseline mismatch: expected $BASE, got $actual" >&2
  exit 3
fi

cd "$WT"
mapfile -t NODES < "$FAILED"

start=$(date +%s)
set +e
pytest "${NODES[@]}" -q --tb=short 2>&1 | tee /tmp/baseline-proof.log
status=${PIPESTATUS[0]}
set -e
end=$(date +%s)

grep -E '^FAILED ' /tmp/baseline-proof.log \
  | sed -E 's/^FAILED ([^ ]+).*/\1/' \
  | sort -u > /tmp/baseline-node-ids.txt

echo "baseline commit: $actual"
echo "baseline runtime: $((end - start))s"
echo "pytest exit: $status"

if ! diff -u "$FAILED" /tmp/baseline-node-ids.txt; then
  echo "FAIL: clean baseline failure set differs from fix-tree failure set" >&2
  exit 4
fi

if ! grep -Fq "requires a string, got null in table 'question'" /tmp/baseline-proof.log; then
  echo "FAIL: expected schema-drift error signature not present" >&2
  exit 5
fi

if ! grep -Fq "auger.py:817" /tmp/baseline-proof.log; then
  echo "FAIL: expected auger.py:817 failure site not present" >&2
  exit 6
fi

echo "PASS: baseline failure set and signature match exactly"

A nonzero exit means the red is not proven pre-existing. In that case, do not use --no-verify.

6. Anti-Patterns

Do not:

  • commit with --no-verify before proving the red on clean origin/main;
  • skip, xfail, or delete the six failing tests to make the gate green;
  • broaden the baseline to “propagate tests are flaky” without exact node IDs;
  • use a clean-tree run at a different commit than the board row records;
  • treat green hosted CI as proof that the live baseline is fixed;
  • close GATE-RED-002 without rerunning the six named tests on clean origin/main;
  • leave the guard exception in place after the baseline owner fixes the schema drift.

The durable fix is not a weaker guard. It is a proven baseline exception with an owner, a reproduce-by-name row, and a removal condition.
