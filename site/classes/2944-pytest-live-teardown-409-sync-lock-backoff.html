pytest live-teardown 409: fleet sync lock burning the 61 s backoff ladder

TL;DR

DELETE /api/namespaces/<ns> returns HTTP 409 in two very different cases. The teardown handler treated them as one and retried a 61 s ladder (1,2,4,8,16,30) for every throwaway namespace. A full-fleet node bin/duckbrain.js s3 sync all push was walking every namespace at the same time, so every teardown exhausted the ladder and still found residue. 16 namespaces × 61 s ≈ 993 s, which is exactly the 1802 s − 810 s = 992.88 s wall growth. The API-key theory is wrong: a missing key makes these arms pytest.skip(), never error.

Durable fix = a session-start preflight that refuses to run while a fleet sync is in flight and names the pid, plus a teardown that fails fast on the lock-holding-pid 409 and keeps only a short ladder for the ordinary post-write window.

1. Root-cause analysis

1.1 The 409 is overloaded

409 body shape Meaning Correct response
Push in flight for '<ns>'. Retry after it completes. Short-lived push that started moments ago short retry, seconds
Push in flight for '<ns>' (native sync lock held by pid 2385306 (since …)). Retry after it completes. Long-running external job (s3 sync all push, deadline 3600 s) do not retry; it will outlive the whole suite

The old teardown handler collapsed both into "retry the ladder". The body already carries the discriminator — lock held by pid <N> — and the handler ignored it.

1.2 The arithmetic names the culprit

The old ladder sums to 1+2+4+8+16+30 = 61 s per exhausted namespace. Wall delta 1802 − 810 = 992 s:

python3 -c 'print(992.88/61)'   # 16.276...

≈ 16 namespaces collided. That is a global fleet walk, not a missing credential (which cannot produce 106 errors).

1.3 Why it is not the missing API key

A missing/invalid key is handled as pytest.skip(). Skips create no errors, do not inflate wall time by 61 s each, and would not reproduce only while the sync ran. The 19–25 s spot-reruns passed because no sync was in flight then.

1.4 The separate lock trap

A sibling pytest leg can hold the session-wide AUGER_TEST_LOCK flock. A second full run then prints the first progress line and produces nothing — it is blocked acquiring flock, not hung. Distinguish with fuser -v <lockfile>.

2. Triage (run in order)

# 1. Name the sync job from the pid in the 409 body
ps -o pid=,etime=,args= -p 2385306

# 2. Is a fleet sync in flight right now? (before every correctness battery)
pgrep -af 's3 sync all push'

# 3. How many namespaces collided? (wall delta / ladder)
python3 -c 'print((1802-810)/61)'

# 4. On-demand reproduction: small slice, stop after 3 failures, while sync runs
pytest tests/test_auger.py -k 'live_table or live_ns' --maxfail=3 -x -q

# 5. Silent second run = lock, not a hung test.
#    fuser writes the pid to stdout and the table to stderr -> capture both.
fuser -v "${AUGER_TEST_LOCK:-/tmp/auger_test.lock}" 2>&1

Rule: do not start a live/correctness battery while pgrep -af 's3 sync all push' prints anything.

3. Fix (all in tests/conftest.py)

3.1 Session-start preflight — fail fast, name the pid

# tests/conftest.py
import os, re, subprocess, pytest

SYNC_MARKER = "s3 sync all push"


def fleet_sync_pids(marker: str = SYNC_MARKER) -> list[tuple[int, str]]:
    """Return [(pid, cmdline), ...] for any native sync push in flight."""
    try:
        out = subprocess.run(["pgrep", "-af", marker],
                             capture_output=True, text=True, check=False).stdout
    except FileNotFoundError:
        return []
    found = []
    for line in out.splitlines():
        m = re.match(r"\s*(\d+)\s+(.*)", line)
        if m:
            found.append((int(m.group(1)), m.group(2)))
    return found


def assert_no_fleet_sync(marker: str = SYNC_MARKER) -> None:
    pids = fleet_sync_pids(marker)
    if pids:
        detail = "; ".join(f"pid {p}: {c}" for p, c in pids)
        raise RuntimeError(
            f"Refusing live battery: fleet sync in flight ({detail}). "
            f"pgrep -af '{marker}' before rerunning."
        )


def pytest_sessionstart(session):
    if os.environ.get("DUCKBRAIN_ALLOW_SYNC") == "1":
        return                       # explicit override for deliberate reproduction
    try:
        assert_no_fleet_sync()
    except RuntimeError as exc:
        pytest.exit(str(exc), returncode=4)

Converts a 16-namespace, ~993 s wasted run into an immediate, named failure.

3.2 Teardown — distinguish external lock from transient 409

# tests/conftest.py
import re, subprocess, time, requests

API = os.environ.get("DUCKBRAIN_API", "http://<ip-address>:3000")

# Ordinary post-write window only; a transient push clears in seconds.
SHORT_LADDER = (0.5, 1.0, 2.0)          # ~3.5 s total, was 61 s
LADDER_TOTAL = sum(SHORT_LADDER)
EXTERNAL_LOCK = re.compile(r"lock held by pid (\d+)")


def describe_pid(pid: int) -> str:
    """Human-readable owner of the lock, for the error message."""
    try:
        out = subprocess.run(
            ["ps", "-o", "pid=,etime=,args=", "-p", str(pid)],
            capture_output=True, text=True, check=False,
        ).stdout.strip()
    except FileNotFoundError:
        out = "(ps unavailable)"
    return f"pid {pid}: {out or 'no longer running'}"


def teardown_namespace(ns: str) -> list[str]:
    """Return [] on success, else a list of problems. Never burns the 61 s ladder."""
    deadline = time.monotonic() + LADDER_TOTAL
    attempt = 0
    while True:
        r = requests.delete(f"{API}/api/namespaces/{ns}", timeout=30)

        if r.status_code in (200, 202, 204):
            return []

        if r.status_code != 409:
            return [f"DELETE /api/namespaces/{ns} -> {r.status_code}: {r.text[:300]}"]

        body = r.text

        # External/fleet sync owns the lock: retrying cannot help within this suite.
        m = EXTERNAL_LOCK.search(body)
        if m:
            return [
                f"namespace {ns} not deletable: {body[:300]}",
                describe_pid(int(m.group(1))),
            ]

        # Anonymous 409 = ordinary in-flight push; short bounded retry.
        if time.monotonic() >= deadline:
            return [f"namespace {ns} still listed after short ladder; 409: {body[:300]}"]
        time.sleep(SHORT_LADDER[attempt % len(SHORT_LADDER)])
        attempt += 1
  • Fleet-sync 409 is reported once, immediately, with the owning pid resolved by ps.
  • Ordinary transient pushes still get a bounded retry (~3.5 s).
  • The preflight catches the fleet case before any test runs.

3.3 Session lockfile — fail fast instead of hanging silently

# tests/conftest.py
import contextlib, fcntl, os, subprocess, time


@contextlib.contextmanager
def auger_session_lock(timeout: float = 5.0):
    path = os.environ.get("AUGER_TEST_LOCK", "/tmp/auger_test.lock")
    fh = open(path, "w")
    deadline = time.monotonic() + timeout
    while True:
        try:
            fcntl.flock(fh, fcntl.LOCK_EX | fcntl.LOCK_NB)
            break
        except BlockingIOError:
            if time.monotonic() >= deadline:
                out = subprocess.run(["fuser", "-v", path],
                                     capture_output=True, text=True)
                holders = (out.stderr + out.stdout).strip()   # <-- both streams
                raise RuntimeError(
                    f"AUGER_TEST_LOCK {path} is held by another pytest leg; "
                    f"this is a lock wait, not a hung test:\n{holders}"
                )
            time.sleep(0.25)
    try:
        yield
    finally:
        fcntl.flock(fh, fcntl.LOCK_UN)
        fh.close()

3.4 Operational rules

  1. pgrep -af 's3 sync all push' before any live battery.
  2. Never run a correctness battery concurrently with a fleet sync push.
  3. Keep the short ladder for the ordinary post-write window; never restore the 61 s ladder.
  4. "Second run silent after first progress line" = lock problem: fuser -v <lock> 2>&1.

Applying to the real suite

  1. Patch tests/conftest.py with 3.1–3.3.
  2. pytest tests/ -q offline — unchanged pass.
  3. DUCKBRAIN_ALLOW_SYNC=1 pytest tests/test_auger.py -k live --maxfail=3 -q while sync runs → teardown reports the sync pid immediately; no 61 s/namespace growth.
  4. Idle: pgrep -af 's3 sync all push' empty, full run back to ~810 s baseline.
  5. Lock trap: second run exits within the timeout with the fuser table instead of hanging.

Harness gotchas confirmed

  • bash -c 'sleep 60 # marker' may exec the trailing command and discard the marker from argv; give the marker its own process argument when testing pgrep -f.
  • fuser -v writes the pid list to stdout and the verbose table to stderr; capture 2>&1 or you get a table with an empty PID column.
