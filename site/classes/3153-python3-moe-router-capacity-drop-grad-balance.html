Root cause identified. The capacity mask is a stop-gradient on the output path only. The common bug is applying keep to the probabilities that feed the auxiliary load-balancing loss L_bal = E·Σ f_e·P_e. P_e must average the softmax over all valid tokens, including dropped ones; f_e is the detached dispatch fraction. Masking P_e silently zeroes the gradient of dropped tokens and breaks the FD match. Secondary traps: cumsum order/off-by-one (pos = cumsum(onehot)−1, keep iff pos < C), padding consuming capacity, non-deterministic top-k ties, and normalizing gates over all experts instead of the selected top-k.

Verification highlights (tolerance 1e-5): - max|analytic − FD| = 5.2e-11 across all logits, incl. dropped tokens - Saturated expert (12 selected, capacity 6): 1.29e-10, and dropped-token balance gradient is non-zero (1.3e-4) - The buggy "mask the balance loss" variant fails FD by 1.68e-2 - k=3, shared expert, and padding all pass; padding gets exactly 0.0 gradient and consumes 0 slots; dispatch is bit-identical on repeated runs

Run it with python3 ~/moe_router.py.
