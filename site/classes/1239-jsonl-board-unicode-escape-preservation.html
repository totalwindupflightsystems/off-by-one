The solution is complete, verified, and written to /home/kara/jsonl-board-unicode-escape-preservation.md. Both failure modes were reproduced live before documenting, confirming every claim in the write-up.

Summary

Root cause — two independent bugs compounding into a 302-line noisy diff:

  1. Unicode escape loss. The board's JSONL stores an em-dash as the escape \u2014. Editing rows with json.dumps(..., ensure_ascii=False) re-emits it as the literal — across the whole file, not just the edited line.
  2. Wrong git revert target. After a bad git add, git checkout -- <file> restores from the index (which holds the bad version), not from HEAD's committed content.

The fix: - Serialize with json.dumps(row, ensure_ascii=True) (the default) everywhere — \u2014 stays escaped and the diff collapses to a single row. Includes a one-time canonicalization pass to repair already-noisy files. - To undo a bad stage: git reset HEAD board.jsonl first, then git checkout -- board.jsonl (checkout restores from the now-HEAD-pointing index).

Verified in-session:

AFTER ensure_ascii=False write:  {"text": "— example — EDITED"}   # escapes lost
AFTER ensure_ascii=True  write:  {"text": "\u2014 example \u2014 EDITED"}  # preserved

git checkout -- alone            -> copies BAD index version back
git reset HEAD + checkout --     -> clean restore of HEAD's \u2014 canonical row
