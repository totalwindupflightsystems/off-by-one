Fix: normalizeSpaceFormFlags pre-pass for remember value flags

Repo: duckbrain · File: src/cli/human.ts · Commit: 0873d86

Root cause

parseArgs is hand-rolled and only splits arguments on =:

function parseArgs(argv: string[]) {
  const flags: Record<string, string | boolean> = {};
  const positionals: string[] = [];
  for (const a of argv) {
    if (a.startsWith("--")) {
      const eq = a.indexOf("=");
      if (eq === -1) flags[a.slice(2)] = true;        // lone --flag => boolean true
      else flags[a.slice(2, eq)] = a.slice(eq + 1);
    } else positionals.push(a);
  }
  return { flags, positionals };
}

So --namespace myns becomes { namespace: true } and myns is pushed into positionals. There is no error:

  • Loud case: --domain concept fails enum validation because domain is true, not concept → Invalid option: expected one of "person"|....
  • Silent case: --namespace ns sets namespace to the truthy boolean "true", so the write lands in a resource literally named namespaces/true/ with no error.

recall (:366), search (:517), and forget (:629) were already fixed by wrapping their args with normalizeSpaceFormFlags (:468). rememberCommand (:195) called parseArgs bare, so remember regressed. Fixing globally is wrong: a global pre-pass would let boolean flags (e.g. --json, --force) swallow the next token.

Fix

1. Add/reuse the helper (already at human.ts:468)

/**
 * Rewrite space-form value flags (`--flag value`) into equals form
 * (`--flag=value`) so the '='-only parser sees the value.
 * Only flags listed in `valueTakingFlags` are considered; boolean
 * flags are intentionally excluded so they do not consume the next token.
 */
export function normalizeSpaceFormFlags(
  args: string[],
  valueTakingFlags: readonly string[],
): string[] {
  const out: string[] = [];
  for (let i = 0; i < args.length; i++) {
    const arg = args[i];
    const isLoneLongFlag = arg.startsWith("--") && arg.indexOf("=") === -1;
    if (isLoneLongFlag && valueTakingFlags.includes(arg)) {
      const next = args[i + 1];
      // Only absorb a real value; never a following flag.
      if (next !== undefined && !next.startsWith("-")) {
        out.push(`${arg}=${next}`);
        i++;
        continue;
      }
    }
    out.push(arg);
  }
  return out;
}

2. Define remember's value-taking subset and wrap parseArgs

At the top of rememberCommand (around human.ts:195):

const REMEMBER_FLAGS = ["--namespace", "--domain", "--content"] as const;

Then replace the bare call:

// before
const { flags, positionals } = parseArgs(args);

// after
const { flags, positionals } = parseArgs(
  normalizeSpaceFormFlags(args, REMEMBER_FLAGS),
);

Do not add boolean remember flags (e.g. --json, --force) to REMEMBER_FLAGS. Apply this per command, mirroring the existing recall/search/forget wraps; do not put it inside parseArgs, or booleans would start consuming tokens.

The negative control is the decisive check: the same command that silently created and wrote namespaces/true/ before the fix now writes namespaces/myns/ after it.

Why this is safe

  • The rewrite is per-command and only touches the declared value-taking subset, so booleans keep their current behavior and never swallow the next token.
  • Existing equals-form invocations are passed through byte-for-byte (the indexOf("=") === -1 guard).
  • A trailing flag with no value is left untouched, preserving existing validation/error behavior rather than silently inventing a value.
