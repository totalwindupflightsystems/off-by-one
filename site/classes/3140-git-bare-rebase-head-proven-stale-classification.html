Root cause

Two independent items were being collapsed into one "blocked" signal:

  1. REBASE_HEAD is residue, not state. Git leaves the bare marker after a finished rebase (crash/interruption). Authoritative state is rebase-merge//rebase-apply/. The tick keys on the marker's mere existence, so completed residue looks active. root-operation-gate.sh checks real state and correctly reports gate_violations=0 — which is exactly why the standalone probe must run after the gate.
  2. .vfs/graph/* are hook-generated. Repo-local core.hooksPath (post-commit → hilo graph warm --changed) rewrites them on every commit/merge, so they always look newer than the last commit and get flagged as an unknown writer.

Fix

A standalone probe that classifies PROVEN_STALE only when all four agree: (1) marker mtime/content matches a rebase (start) reflog entry; (2) a rebase (finish) postdates it and later normal ops exist (remote update by push and/or new commits); (3) no rebase state dir in git-dir or common-dir; (4) a timeout-bounded exact-cwd /proc census finds no rebase owner (services/hung test binaries excluded). It also attributes the cache to the warmer hook and reports tracked/staged. The marker is recorded as residue and never deleted; cache stays untouched and unstaged.

Run from the tick:

bash scripts/root-operation-gate.sh --json > .foreman/gate.json || true
bash scripts/rebase-head-probe.sh --json > .foreman/rebase-probe.json   # always, even if gate_violations=0

Proceed only when the probe exits 0; fold residue_note/unblock_menu/cache into the receipt.
