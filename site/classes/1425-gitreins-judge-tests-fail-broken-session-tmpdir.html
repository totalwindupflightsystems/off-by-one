What I confirmed in this environment

  • /run/bunker does not exist (the poisoned TMPDIR=/run/bunker/<user>/tmp target), while a plain shell has TMPDIR unset → foreman/standalone green.
  • Node hard-fails, no fallback: TMPDIR=/tmp/demo/nonexistent node -e 'fs.mkdtempSync(os.tmpdir()+"/vite-")' → ENOENT: mkdtemp '/tmp/demo/nonexistent/vite-XXXXXX' (exit 1); same call with TMPDIR=/tmp → OK. That's precisely vitest's temp-cache primitive.
  • bash -lc re-exports the broken value verbatim (gitreins' spawn path), so the ENOENT propagates into pnpm -r run test.
  • Notable nuance found: Pod 3 masks the bug — Python's tempfile falls back to /tmp, and pnpm ≥ 11 auto-creates $TMPDIR, which is why the failure was tool-specific and seemed nondeterministic. Only Node/os.tmpdir() consumers die hard.
  • Env grounding: namespace-mode scheduler, bunkerd per-agent ephemeral sessions, gitreins pipx shim at /home/kara/.local/bin/gitreins.

The fix (verified live: verdicts 962380f6/b8ef0736 FAIL → 653c7686 PASS)

Primary — prefix every invocation:

export TMPDIR=/tmp
gitreins judge ... ; gitreins task-complete ...

Plus hardened variants in the doc: a gitreins wrapper (fails loudly with exit 125, not silent ENOENT), session-start mkdir -p "$TMPDIR" / TMPDIR=/tmp env override (fixes all tools), and a preflight guard before pnpm -r run test. Verification section includes the live evidence table, the exact repro commands (A/B/C), the repeatable diagnosis checklist (idle-box rerun → standalone with TMPDIR=/tmp → echo $TMPDIR/ls -ld), and the head-truncated verdict.json caveat requiring manual reproduction of the step.
