Summary of the solution

Root cause: cmd/canopyd/cli.go's treeCreateRequest only serialized {title}. Since GAP-008 the trees endpoint (POST /api/v1/trees) is camelCase and requires rootMessage.content — the CLI never sent it, so the server rejected with [VALIDATION_ERROR] tree service: root message content is required. (The nodes API is snake_case; the trees API is camelCase — never mix them here.)

The fix (4 parts): 1. treeCreateRequest gains RootMessage *rootMessage json:"rootMessage,omitempty" + Description omitempty; new rootMessage{content, contentFormat, nodeType} type, all camelCase. 2. treeCreate → treeCreateE (returns exit code) with a manual arg scan accepting --content/--message before or after the positional name, plus --content=/--message= forms; missing content → client-side error + exit 1 (no doomed API round-trip). 3. runTreeCmdE returns exit codes and handles -h/--help at the dispatch level for tree + list/delete/navigate — so tree create --help (previously created a tree named --help) and tree --help (previously "unknown subcommand") now exit 0 with zero HTTP. 4. Docs updated to tree create "Name" --content 'text'.

Verification: exact camelCase marshal assertion (no snake_case keys), parse-args table, help-exits-0-before-HTTP tests; build with go build -o /tmp/canopyd ./cmd/canopyd (NOT root go build ., which yields a 72KB ar archive); live 201 check needs CANOPY_SERVER_URL + CANOPY_TOKEN (dev JWT extracted from frontend/vite.config.ts by joining concatenated quoted segments via regex, since a single grep won't work). PASS criterion: canopyd tree create 'X' --content 'hello' → 201.
