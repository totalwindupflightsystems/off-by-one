Answer

Diagnosis and fix complete. The self-contained write-up is at /workspace/scheduler/SOLUTION-SCHED-GAP-1734.md.

Root cause

TestUsagePoolLeaseReleasedWhenStartFails treated an empty SCHEDULER_DISPATCH_TARGETS file as "dispatch disabled". It is not: per dispatch_targets.go, empty/missing means "no lane is remote", so every lane keeps its historical local transport. The test's spawner (NewSpawner(db, 1)) had no gateway client and noExecFallback == false, so Spawn() fell through to exec.Command("hermes", …) — the live CLI/gateway. The SQLite RAISE(IGNORE) trigger makes StartRunning return nil (only the row update is skipped), so the slot pool proceeds past the cleared gate and dispatches. Confirmed by code trace and a safe repro:

SPAWN: start-fails-dbg tick=… pid=… workdir=/tmp
LEAK: hermes invoked with: chat -q [Scheduler tick: start-fails-dbg-…] … Workdir: /tmp.

It's intermittent because SlotPool.Spawn is fire-and-forget and Wait returns when Running()==0; when the goroutine loses the race, test cleanup closes the DB first (sql: database is closed) and nothing leaks — which is why only some suite runs produced a phantom tick.

Fix

internal/scheduler/usage_pool_policy_test.go — added newHermeticBookkeepingSpawner (no gateway client + SetNoExecFallback(true)) and used it in the two bookkeeping fixtures, removing the misleading empty-targets setup. dispatch_targets.go — documented the "empty ≠ disabled" footgun at EnvDispatchTargets. Byte semantics of the targets file are intentionally unchanged.

Verification

  • Fixed test passes, and with a stub hermes first on PATH, zero hermes invocations occur; the fixed spawner now logs DEFERRED … no gateway client and exec fallback disabled.
  • Safe original-vs-fixed A/B demonstrated the leak and its elimination.
  • TestUsagePool*, TestRemote*, TestDispatchLeg* pass (1.045s), go build ./... clean.
  • Live-box check documented: count Scheduler tick: start-fails- lines in ~/.hermes/foreman/logs/agent.log before/after — count must not increase while the lease assertion still passes.

Fleet-side detection: fixture-named tick + workdir /tmp + empty worker model/provider = leaked test dispatch — report, do not provision.
