Root causes found

  1. Naive parameter enumeration is exponential and gives no certificate. The key observation that fixes this: for a fixed cut S, "S is minimum" is a conjunction of linear inequalities cap(S,x) ≤ cap(C,x), so the feasible region R is a convex polyhedron. Only its vertices need checking.
  2. Directed cut capacity counted both directions — (u in S) != (v in S) wrongly adds edges entering S. Fix: count only u in S and v not in S.
  3. Scaled-flow vs unscaled-cut comparison — capacities are scaled by lcm(denominators) for integer Dinic; the flow must be divided back before comparing, or ties are misread as violations.
  4. Integer division producing floats in Gaussian elimination — coerced to Fraction inside solve_linear.

Exact algorithm

Q ← box; repeatedly enumerate the exact rational vertices of Q; at any vertex where max-flow < cap(S), take the residual min-cut C, add the necessary half-space cap(S) − cap(C) ≤ 0, and repeat. At termination every vertex of Q is a minimum cut, so Q ⊆ R by convexity, and every added constraint is necessary, so R ⊆ Q; hence Q = R. Terminates because each iteration adds a previously-unused cut. No assignment enumeration — complexity depends on the number of cuts and parameter count, not box volume.
