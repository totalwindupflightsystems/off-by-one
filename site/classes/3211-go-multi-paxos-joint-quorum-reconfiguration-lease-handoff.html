Multi-Paxos Joint-Consensus Reconfiguration with Split-Brain-Free Lease Handoff

Toolchain: Go 1.26 · Module: mpaxos · Status: 11/11 tests pass, 87.4% statement coverage, go vet clean, -race clean, deterministic over 25 runs.

1. Root-cause analysis

The failure modes that produce split brain or a lost transition, and the exact fix for each:

# Defect Why it is unsafe Fix
1 Single-phase membership flip Old-config and new-config leaders can form disjoint majorities and both commit Two-phase joint consensus C_old,new; commits need majority of C_old and C_new
2 Appending C_new before C_old,new commits A crash between phases drops the bridge; an old quorum can commit divergent entries Append C_new only after C_old,new is durably committed; recovery replays a joint tail
3 Commit quorum from "current membership" instead of the entry's config A stale leader with only an old majority can still commit Always compute quorums from configAt(index)
4 New leader serves reads immediately on election Races the old leader's still-valid lease → split-brain read First lease gated on electionTime + leaseDuration; quorum intersection makes the old lease un-renewable
5 Reads not gated on a current-term commit A stale leader with an uncommitted tail serves stale reads Read requires a committed current-term entry and a valid quorum lease

The real bug found while building this

maybeCompleteReconfig() was called from apply() on every apply while the newest config was joint, so it appended C_new before C_old,new committed. The leader then replicated with the new-only quorum, the old majority was never consulted, and the joint entry never committed — the transition deadlocked and the safety bridge was gone. The fix is one guard:

func (n *Node) maybeCompleteReconfig() {
    if n.role != Leader { return }
    latest := n.latestConfig()
    if !latest.Joint { return }
    // Only move to C_new once C_old,new is durably committed. A crash before
    // this leaves the joint entry as the tail; the next leader repeats it.
    if !n.jointCommitted() { return }
    n.appendEntry(Entry{
        Type: EntryConfig,
        Config: Config{Old: append([]string(nil), latest.New...),
                       New: append([]string(nil), latest.New...)},
    })
    n.broadcastAppend()
}

A second bug the tests caught: jointCommitted() reported false forever once C_new was appended, because it stopped at the first config entry from the tail. It now scans for the most recent joint entry.

2. The exact fix

2.1 Reconfiguration state machine

Propose C_old,new ─► replicate ─► commit needs maj(C_old) AND maj(C_new)
                                        │ apply() sees committed joint entry
                                        ▼
                            append C_new ─► replicate ─► commit needs maj(C_new)

Quorum is config-sensitive:

func (c Config) HasQuorum(acked map[string]bool) bool {
    if !majorityOf(c.Old, acked) { return false }
    if c.Joint && !majorityOf(c.New, acked) { return false }
    return true
}

// configAt returns the config governing an entry index (config entries govern
// themselves). This is what stops a stale leader committing under old rules.
func (n *Node) configAt(index int) Config {
    cfg := n.initialConfig
    for _, e := range n.log {
        if e.Index > index { break }
        if e.Type == EntryConfig { cfg = e.Config }
    }
    return cfg
}

2.2 Crash recovery

A crash after the joint entry but before the final entry leaves the joint entry as the log tail. On restart the node replays its durable log; when it becomes leader it appends a current-term no-op. The no-op can only commit with a joint quorum, which is exactly what lets apply() safely append C_new. Any other winner sees the same joint tail and repeats the step — the transition is idempotent and always completable.

2.3 Lease handoff

func (n *Node) maybeRenewLease() {
    if n.role != Leader { return }
    last := n.lastLogIndex()
    cfg := n.configAt(last)
    acked := map[string]bool{n.id: true}
    for id, mi := range n.matchIndex {
        if mi >= last { acked[id] = true }
    }
    if !cfg.HasQuorum(acked) { return }   // quorum intersection
    now := n.clock.Now()
    if !n.leaseGranted {
        // First lease may not begin until the previous leader's lease expired.
        if now.Before(n.electionTime.Add(n.cluster.leaseDuration)) { return }
        n.leaseGranted = true
    }
    n.leaseUntil = now.Add(n.cluster.leaseDuration)
}

Safety argument (stale leaders can never commit)

  1. Election safety: the old majority Q_j that committed C_old,new intersects any old majority a stale candidate needs; every node in Q_j has a longer log and rejects the vote → the candidate cannot win.
  2. Surviving stale leader: commits use configAt(index), so for any joint/new-governed index the stale leader can never assemble the new-config majority → commitIndex never advances past the change.
  3. Log matching: a leader is only elected with a log containing every committed entry, so committed entries are never truncated.
  4. No split-brain read: old last-renewal R1 and new election E2 use intersecting quorums; the intersection votes in a higher term and then rejects the old leader, so R1 < E2 and old expiry R1+lease < E2+lease ≤ earliest new lease.
