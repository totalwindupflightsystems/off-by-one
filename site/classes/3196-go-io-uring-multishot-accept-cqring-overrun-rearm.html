Answer

I diagnosed the failure, built a raw io_uring implementation in Go, reproduced the stall, fixed it, and verified the fix on the real kernel. The full write-up is in:

~/uringfix/SOLUTION.md

Root cause

A multishot accept is owned by the kernel until a CQE arrives with IORING_CQE_F_MORE clear. When the CQ ring fills, the kernel parks completions on a hidden overflow list and sets IORING_SQ_CQ_OVERFLOW; those entries are not counted by cq.tail - cq.head. An event loop that only inspects the visible ring never sees the terminating CQE (which may also have terminated the multishot request), so it never re-arms — zero outstanding accepts, no error, permanent stall.

The fix (three coupled rules)

  1. Detect overrun from ring state: sq.flags & IORING_SQ_CQ_OVERFLOW != 0 || cq.overflow != 0.
  2. Flush with io_uring_enter(fd, 0, 0, IORING_ENTER_GETEVENTS), then drain again.
  3. Quiesce, then re-arm: only arm an un-armed listener after both the visible ring and the overflow list are empty. This makes re-arm idempotent, so it can't double-accept, and every res >= 0 fd is consumed before re-arming, so it can't leak. Also require IORING_FEAT_NODROP (or size the CQ ring) because a truly dropped completion is unrecoverable.

Verification (go1.26.8, Linux 7.0.0)

  • Buggy loop (no overflow flush): accepted only 9/100 connections then stalled while overflow stayed pending.
  • Fixed loop: accepted 100/100, with 10 automatic re-arms (the kernel really did terminate multishot on overflow), Duplicates == 0, and TrackedConns() == 0 after drain — no double-accept, no fd leak.
  • Deterministic state-machine unit tests pin the MORE/re-arm/overflow-ordering invariants.
  • go test -count=5 and go test -race -count=2 pass.
  • The Go blocks were extracted straight out of SOLUTION.md into a clean dir, then built and tested — so the document is self-contained and directly usable.

Supporting sources live alongside it: uring.go (raw ring + overflow state), loop.go (quiesce-then-re-arm state machine), loop_unit_test.go, server_test.go.
