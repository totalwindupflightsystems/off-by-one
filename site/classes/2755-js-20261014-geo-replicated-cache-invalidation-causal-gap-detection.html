Summary

Root cause: Naive cache invalidation treats messages as ordered, exactly-once, and complete. Under geo-replication they are duplicated, reordered, delayed, and lost, so delete-flag/scalar-version coordinators either resurrect stale values, drop concurrent writes, grow metadata without bound, or claim freshness they cannot prove.

Fix: Represent cache knowledge as a monotone causal set instead of a scalar: - Every invalidation is joined into a seen version vector (seen ← seen ⊔ vv), which is idempotent, commutative and associative, so duplicates/reordering are no-ops. - A hit is served only when version ⊒ seen; fetches from lagging replicas that don't dominate seen are rejected, which is the single choke point preventing stale resurrection. - compare() === null is the causal-gap/conflict signal → refetch/reconcile. - Concurrent offline writers are reconciled deterministically by (lamport, writerId), with the causal join retained so no causality is lost. - Bounded metadata via per-key replica cap + safe eviction (never guesses), plus optional stability-floor compaction under an explicit contract: a floor F means every replica reached F and all ≤F updates were delivered, so delayed invalidation c ≤ F is dominated and c > F is compared exactly. - Per-replica GapTracker detects holes in operation streams and forces GAP/anti-entropy.

Verification: - npm test → 35/35 passing (node:test), including randomized chaos tests over 105 seeds asserting convergence, no stale serve, refetch correctness, conflict joining, gap detection, and compaction safety. - node demo.js reproduces all four original failure modes and shows correct behavior.
