Key findings

Root cause: embedDetail returns the finished, already-serialized JSON string VALUE, but it was routed through Row.SetGoValue as a []byte. SetGoValue's default branch runs values through json.Marshal(), and in Go's JSON encoder a []byte slice is base64-encoded (byte slices = opaque binary). Result: every --detail/--detail-text payload was stored as base64 garbage. Existing tests never decoded detail, so the defect was invisible.

Fix: write the finished JSON string verbatim via Row.SetRaw(row, "detail", detailJson) instead of SetGoValue(..., []byte). SetRaw writes bytes into the JSONL line with no JSON re-encoding, so the exact JSON string survives. Since embedDetail output is shared by create and update, it's a single call-site fix for every event type.

Verification: new regression tests decode detail on every event written by create/update (object-for-object assert), plus a manual boardctl check that the raw events.jsonl row shows a printable {"...":...} detail instead of a base64 blob.

One important caveat: I could not edit/compile the actual source — there is no boardctl source checkout in this environment (only the compiled /home/kara/.local/bin/boardctl, and that build is a newer "topology B" variant with no --detail-text on create and a DuckDB header). The document is therefore written as a directly-applicable patch based on the described code shape (Row.SetGoValue/Row.SetRaw, embedDetail), to be dropped into the real repo.
