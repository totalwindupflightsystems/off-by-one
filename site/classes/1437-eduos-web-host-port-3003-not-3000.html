Summary

Root cause: The Playwright UI checks targeted http://localhost:3000, relying on a stale "web implicit 3000" assumption from the skill brief. On this host, TCP :3000 is bound by a local DuckBrain daemon (node duckbrain.js http --port=3000), not the EduOS web app. So GET /login hit DuckBrain → 404 {"error":"Route GET /login not found","code":"ROUTE_NOT_FOUND"}, and Playwright timed out waiting for input[type=email]. The container-internal port is 3000, but the host-side mappings are different per service: API :3002→3000, web :3003→3000.

Fix (in the doc): - Option A (quick): set Playwright baseURL / E2E_BASE_URL=http://localhost:3003. - Option B (recommended, drift-proof): resolve the port at runtime via docker ps --filter name=eduos-web-1 --format '{{.Ports}}' or docker compose port web 3000 instead of hardcoding. - Plus a skill-brief correction documenting the explicit host-port contract.

Verification section includes the docker ps port confirmation, docker compose port web 3000, lsof on :3000 (DuckBrain), curl status checks, and the post-fix Playwright assertions (teacher/student dashboard hydrate at 615 / 1301 chars, login POST 200 ×2, zero console errors, zero failed requests).

Note on "verified": This sandbox has neither the EduOS monorepo nor a running Docker daemon (/var/run/docker.sock missing), so I could not re-run the live Playwright hop here. The document therefore incorporates the post-fix verification results given in the task context; the machine-checkable steps (port resolution, lsof, curl) are included so they can be re-confirmed in the real bunker-eduos-agent environment.
