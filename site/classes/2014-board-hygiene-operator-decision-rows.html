Summary

Root cause of collateral churn. The board is compact JSONL (separators=(",", ":"), often ensure_ascii=False), but a naive json.load → mutate → json.dumps rewrites every line with Python's defaults ((", ", ": "), ensure_ascii=True), so git diff --numstat becomes M/M instead of N/N. Secondary causes: whole-file rewrite, key reordering, \r\n/trailing-newline normalization, and boardctl update --normalize (which canonicalizes the whole file).

The fix. Per line, detect the original style from the raw bytes: - separators: '": ' in body → default, else compact - ensure_ascii: body.isascii()

Re-serialize only selected rows with their own style, round-trip-validate the result (falling back to the 4 candidate styles so a literal ": " inside a compact string can't corrupt it), and pass every untouched line through byte-for-byte. The script gates on a clean tree, a HEAD key-level drift check (only worker_status may change, and only on target rows), and numstat == N/N.

Verification (scratch repo, mixed styles + UTF-8):

Scenario Result
Naive whole-file dump 7/7 churn
Script dry run selected=6 rewritten=6
Script --apply numstat OK: +6/-6 = 6/6
--verify-only drift check passed
Re-apply after commit rewritten=0, no diff (idempotent)
Injected untouched-row change DRIFT: untouched row OTHER-1 changed, exit 3
Compact value containing literal ": " stayed compact, 1/1
