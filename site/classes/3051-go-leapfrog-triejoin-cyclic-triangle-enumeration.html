I built the solution from scratch (the workspace only contained problem.json), verified it, and wrote the full self-contained write-up to /workspace/SOLUTION.md. Here's the summary.

Diagnosis (root cause)

The natural left-deep plan (R ⋈ S) ⋈ T blows up on the cyclic triangle query: for dense stars it materialises up to Θ(N²) intermediate tuples and does O(N³) raw-loop work even when the answer is tiny. A cursor implementation also typically hard-codes column 0 as the join key, so it breaks when a relation is stored in the other physical order.

The fix is a Leapfrog Triejoin over global variable order (a,b,c) with query-driven views R(a,b), S(b,c), T(a,c). At each level it intersects the active cursors and descends only on agreed keys, never building a cross product.

The bug I actually hit and fixed: the seek target must be the maximum of the current cursor keys, not the minimum. A common value must be ≥ every cursor's current key, so min re-selects the slowest cursor forever (an infinite loop); max strictly increases each failed round and terminates. This is documented in §1.3 of the write-up.

Exact fix

A Go module in /workspace/leapfrog (relation.go, iterator.go, lftj.go, triangle.go, histogram.go, report.go) implementing: - Iterator with Open/UpTo/Next/Key/Valid - Relation (physical, deduped, set-valued) + View that remaps columns by attribute name per query - a generic LFTJ Plan.Run that walks the trie levels with max-leapfrog intersection - count, SHA-256 digest over lexicographically ordered (a,b,c) triples, and a per-relation-per-level seek histogram + operation-trace digest

Verification (all passing)

  • Brute-force oracle: 500 randomized inputs plus all-empty, empty S/T, duplicates, self-loops, negatives, dense stars — exact match.
  • Independent Python reference (/workspace/ref.py, shares no code): byte-for-byte identical count, tuple digest, trace digest and histogram on 10 adversarial inputs (diff → 0).
  • Frozen golden trace: testdata/reference.txt + TestGoldenReferenceTrace.
  • Attribute-mapping invariance: all 8 physical column-order combinations of R,S,T give identical count/digest/histogram.
  • Worst-case optimality: on a dense star with sparse output, each doubling of n multiplies seeks by ≈4 (quadratic in n, linear in N=n²) where a left-deep plan would grow ≈8. On the complete dense star work tracks O(N^1.5).
