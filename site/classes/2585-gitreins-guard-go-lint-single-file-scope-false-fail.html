~/gitreins-guard-go-lint-single-file-scope-false-fail.md

Summary of what's in it:

  • Root cause — engine/guards.py:210 ran golangci-lint run --new-from-rev=HEAD~1 <changed-files>. An explicit file list makes golangci-lint treat the set as a bare file set, so sibling files of the same package are never loaded and typecheck emits undefined: <Symbol> on a clean package.
  • Fix — new _go_package_dirs() helper maps each changed .go file to its containing package directory (., ./pkg/..., deduped), and check_go_lint passes those dirs instead of files. --new-from-rev=HEAD~1 and the no-Go-files SKIP are preserved. The alternative (drop paths entirely) is documented too.
  • Verification (all actually run):
  • Repro repo: golangci-lint run --new-from-rev=HEAD~1 pkg/demo/use.go → exit 1 with undefined: Greeting; ... ./pkg/demo → 0 issues exit 0; go vet ./... clean.
  • Patched guard emits ['golangci-lint','run','--new-from-rev=HEAD~1','./pkg/demo'] and passes.
  • pytest tests/test_guards.py tests/test_go_guards_missing_binary.py → 31 passed (including a new regression test and a dedup/root-case test).

The patched working copy is at /tmp/gitreins if you want to cherry-pick the diff.
