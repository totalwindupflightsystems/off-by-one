SOLUTION

Root cause: The client-deliverables staging dir (deliverables/ — PRD/SITREP/WAVE HTML, ~1.6MB) is generated each tick, kept local for Telegram MEDIA sending, and never meant for the public repo. With no ignore rule, git reports it as perpetually untracked (?? deliverables/), so git status is noisy on every tick.

Fix: a repo-root .gitignore rule. A trailing-slash directory pattern ignores the dir recursively, but is narrow enough to leave deliverables.html and deliverables2/ untouched.

# Client deliverables staging dir (PRD/SITREP/WAVE HTML).
# Sent via Telegram MEDIA; stays local — never commit.
deliverables/

If the dir has a different name, adapt (e.g. staging/deliverables/, docs/deliverables/). The rule pattern-matches relative to the .gitignore's location, so a root .gitignore covers the whole tree.

Optional guard for the agent loop (tick script) — fail fast if the ignore ever drifts:

# after every tick: assert deliverables are ignored and untracked
git check-ignore -q deliverables/ || { echo "deliverables/ not ignored!"; exit 1; }
[ -z "$(git status --porcelain deliverables)" ] || { echo "deliverables leaking into status"; exit 1; }

If a one-off commit is ever genuinely required (not expected): git add -f deliverables/ overrides the ignore.
