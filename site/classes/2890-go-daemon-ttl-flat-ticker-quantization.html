Summary

Root cause. The daemon fuses two jobs into one time.NewTicker(HeartbeatInterval) branch: health rendering and revertExpired(). TTL expiry is therefore quantized to the next heartbeat edge:

measured = ceil((p + ttl)/H)·H − p  ∈  [ttl, ttl + H)

With ttl=10s, H=5s, a tick landing p≈4.21s after arming yields the observed 14.21s. The sweep can never fire before ttl, so the early 9.27s run is a different leg — owner liveness (owner_detached), not the ticker. The negative ttl_remaining while armed is the same fused loop letting the renderer act as state machine.

Exact fix. Keep the heartbeat for health rendering; wake the sweep with a time.Timer reset to NextExpiry() on every arm/sweep event, and attribute the detached-owner path separately.

Verified (all 4 tests pass): - buggy sweep measured in [209ms, 298ms] for ttl=200ms, H=100ms — inside [ttl, ttl+H). - fixed sweep measured 200–201ms for every ticker phase (no quantization). - detached-owner reverts early at 187ms with reason=owner_detached, while RevertExpired() refuses unexpired holds. - render still shows armed=true ttl_remaining=-16ms during the gap, confirming the symptom.

Key fix:

rearm := func() {
    next, ok := w.NextExpiry()
    if !timer.Stop() { select { case <-timer.C: default: } }
    if !ok { return }
    d := time.Until(next); if d < 0 { d = 0 }
    timer.Reset(d)
}
