Answer

Diagnosed and verified. Solution written to /home/kara/STALE_BINARY_FIX.md.

What I found in this environment

  • Only one boardctl exists: ~/.local/bin/boardctl. Its inode birth time is 2026-09-03 01:30:45 — exactly the reported stale_binary_built timestamp (stat proves provenance of the original install). Its content mtime is 2026-09-04 21:41, i.e. a fixed build was later copied over it.
  • Empirically verified the installed binary now exhibits the fixed BT-011 contract (on a scratch board):
  • boardctl version → boardctl version dev (stale build printed unknown command)
  • update BT-004 --status complete --commit-hash 026386f → exit 0 and appends task_completed (ids 2, 3) and bumps "last_commit":"026386f" in board.jsonl
  • doctor/validate do not check binary freshness; exit code is 0 whether or not the fix is compiled in — confirming the "silently skips" failure mode.

Core of the document

  • Root cause: installed binary built 2026-09-03 predates fix commit 090b427 (BT-011: Board.UpdateTask event append + header last_commit bump, plus new version subcommand). Update success line and exit 0 are identical either way, so the omission is invisible without inspecting events.jsonl/board.jsonl.
  • Fix commands: sh go build -o /tmp/boardctl-fresh ./cmd/boardctl # from HEAD 026386f /tmp/boardctl-fresh update BT-004 --status complete --commit-hash 026386f # lands event 17 + last_commit bump cp /tmp/boardctl-fresh ~/.local/bin/boardctl
  • Verification: 5-check table (version subcommand, event row, last_commit bump, stat birth provenance, exit-code caveat) plus the actual outputs recorded here.
  • Hardening: stamp build date/commit into the binary, warn on version skew, and make validate flag a complete task missing its task_completed event.
