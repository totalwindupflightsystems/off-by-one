What I built

A deterministic Go 1.26 verifier for MVCC histories with range reads, predicate locks, and concurrent schema changes. It classifies each history as SERIALIZABLE_SSI, SERIALIZABLE, SNAPSHOT_ISOLATION, or NOT_EXPLAINABLE, and emits the smallest conflicting cycle.

Root causes diagnosed

A naive point-conflict serialization graph fails in seven ways:

  1. Phantom blindness — point-only rw edges miss inserts of new keys inside a scanned range.
  2. Partition splits — testing an insert against one physical partition misses sibling partitions.
  3. Commit-timestamp ties — timestamp-only version ordering makes ww direction, "next version", and "first to commit" nondeterministic.
  4. SI vs. serializability conflation — write skew is valid SI but non-serializable; they are orthogonal checks.
  5. First-committer-wins is not a graph property — concurrent committed writers must be checked explicitly.
  6. Schema changes ignored — concurrent DDL invalidates predicate locks and needs schema-version chains.
  7. Non-minimal/nondeterministic cycles — "first cycle found" is wrong; needs all-pairs BFS + canonical lexicographic tie-break.

The fix

  • Snapshot visibility from real-time begin: commitIndex(u) < beginIndex(t).
  • Version chains ordered by the total order (commit_ts, txn_id).
  • wr/ww/rw edges, with range reads taking predicate locks over the union of Parts (catching phantoms across splits) plus concurrent-DDL rw edges.
  • Explicit concurrent write-write check for SI; acyclicity for serializability; T1→rw T2→rw T3 with T3 first-to-commit for SSI danger.
  • Globally shortest cycle via all-pairs BFS with deterministic lexicographic canonicalization.
