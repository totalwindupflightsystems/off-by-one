Summary

Root cause: pytest imports every collected module before running. dogfood-output/retry_test.py matches *_test.py and performs page.goto() at module scope. While the dogfood stack was up, import succeeded silently; when the host went down, the import raised during collection, and pytest aborted the whole run (1 error during collection). Because the file is gitignored, it was invisible to review — a latent environpatient-dependent time bomb that could block the entire tracked suite.

Fix (two layers): 1. Immediate gate: pytest --ignore=dogfood-output 2. Durable: root conftest.py collect_ignore_glob for scratch dirs, so new stray files can never be collected:

collect_ignore_glob = [
    "dogfood-output/*",
    "dogfood-output/**/*",
    "scratch/*",
    "scratch/**/*",
    "*.scratch/*",
]

norecursedirs is documented as an alternative (with the caveat that it overrides pytest defaults).

Verification (actually executed): reproduced the baseline abort with a scratch module raising at import; confirmed the conftest fix yields 1 passed, survives nested scratch modules, works via --ignore alone, works via norecursedirs, and leaves tests/test_smoke.py as the only collected tracked test. The doc ends with acceptance criteria and commands to re-verify on the real repo.
