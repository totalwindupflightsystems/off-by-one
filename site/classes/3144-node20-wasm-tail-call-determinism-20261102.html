Deterministic WebAssembly Tail-Call Lowering

Problem class: node20-wasm-tail-call-determinism-20261102

TL;DR

wasm-tail-lower.js removes the tail-call proposal (return_call 0x12, return_call_indirect 0x13). Two strategies:

strategy lowering stack behavior
call return_call f → call f; return grows with depth — changes traps
trampoline direct tail-call SCCs merged into one dispatcher loop; args/results in module globals constant, like real tail calls

It is deterministic (canonical LEB128, array-driven ordering, untouched sections copied verbatim), preserves imports/exports/name sections, handles nested blocks, unreachable code, multi-value returns, malformed modules, and section-size rewrites. Bundled suite: 170/170 checks pass.

Root-cause analysis

1. The opcodes aren't portable. Engines without the tail-call proposal reject the module, so they must be rewritten to MVP instructions.

2. The obvious rewrite breaks traps/stack-depth. return_call f → call f; return preserves values but pushes a new native frame. For mutually recursive functions this converts a constant-stack loop into unbounded recursion and introduces a stack-overflow trap. Verified:

is_even(1000000)  original (tail calls) : 1
is_even(1000000)  after call; return    : RangeError: Maximum call stack size exceeded

Because the requirement is no change to traps or stack-depth observability, per-instruction substitution is insufficient — mutual tail recursion must compile to iteration.

3. Raw byte scanning for 0x12/0x13 is wrong. Those bytes occur inside immediates (i32.const 0x12 = 41 12). A correct pass must decode every instruction and skip memargs, branch tables, block types, v128.const, select type vectors, SIMD lanes, etc., while tracking structured control nesting so a br to the implicit function frame is distinguished from a br to a real block.

4. Binary bookkeeping/determinism. Changing opcode widths changes body sizes → code-section size → module. Sizes must be re-encoded with canonical LEB128; unmodified sections must be copied byte-for-byte. SCC/global/function ordering must not depend on hash-map iteration.

5. Debug mappings. Replacing a body with a wrapper that has fewer locals invalidates the name section (wasm-validate: expected local name count (N) <= local count (M)). Keeping each wrapper's original declared locals (unused) preserves the name section's local-name map exactly.

The fix

Artifacts (all in ~/wasm-tail-lowering/): - wasm-tail-lower.js — 946-line transformer (decoder, encoder, both strategies, CLI) - test/run-tests.js — 323-line end-to-end suite - SOLUTION.md — self-contained write-up with full source embedded

# Baseline: portable but stack-growing
node wasm-tail-lower.js --strategy=call in.wasm -o out.wasm

# Fix: trampoline direct mutual tail recursion (constant stack)
node wasm-tail-lower.js --strategy=trampoline in.wasm -o out.wasm

Trampoline design. For each SCC of the direct tail-call graph with no indirect calls and a common result type (guaranteed by tail-call validation):

  1. Each member index keeps its signature but its body becomes a wrapper: store params into per-member argument globals, set a tag, call the dispatcher, load shared result globals.
  2. Append a dispatcher () -> (): a loop around nested block + br_table dispatch; each member body is inlined with its locals remapped into a per-member slot range.
  3. return_call g(args) → store args into g's globals in reverse, set tag, br to the loop header:
// from rewriteMemberBody():
for (let p = tty.params.length - 1; p >= 0; p--)
  parts.push(bU(0x24, info.paramGlobals[j][p]));   // global.set
parts.push(bS(0x41, j), bU(0x24, info.tagGlobal)); // i32.const j; global.set tag
parts.push(bU(0x0c, ins.ctrlDepth + (k - 1 - i))); // br to loop header
  1. Returns store into shared per-SCC result globals (all tail-call-connected functions share one result type) and return — this was the key correctness fix over the first attempt.
  2. External/imported tail calls become call target + store-results-and-return.
  3. return_call_indirect cycles can't be resolved statically, so those SCCs fall back to call.

The globals are scratch only between branch points, which makes the transform re-entrancy safe even when a member makes a non-tail call to another member.

Verification

node test/run-tests.js     # -> PASS 170  FAIL 0

Covered and passing: - both strategies validate with wasm-validate (which also checks the name section) - trampolined output matches the un-lowered reference for: mutual is_even/is_odd; self tail recursion with i64 accumulator + locals; different param types (f64); multi-value (i32 i32); nested blocks + unreachable code after a tail call; return_call_indirect fallback; two independent SCCs; tail calls to helper and import; non-tail call inside an SCC - is_even(1000000) succeeds after trampolining while the baseline is asserted to overflow; divide-by-zero traps with identical messages before/after - sections 2 (imports) and 7 (exports) byte-identical; custom/name sections byte-identical - malformed modules (bad magic/version, truncation, trailing bytes) rejected cleanly - determinism: repeat-run identical, idempotent, and a variant with non-canonical body-size LEBs lowers to the exact same bytes - no-tail/empty/imports-only modules round-trip byte-for-byte

Limitations (documented in SOLUTION.md): indirect tail-call cycles fall back to stack-growing call; offset-based DWARF line tables are not re-based (the name section is preserved); appending globals/types/functions never shifts existing indices.
