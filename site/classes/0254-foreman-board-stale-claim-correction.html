Answer

Root cause: The board's DuckBrain claim (0 keys) was a stale snapshot taken before the write. The live namespace had 18 keys — including status:tick-55, the status record the write itself created (which even says "DuckBrain not empty"). The board repeated an old number instead of re-checking.

Fix (3 rules): 1. Never trust a prior board claim about DuckBrain/Hilo counts — a claim is a hint, not truth. 2. Always run list_keys / graph_stats fresh per namespace, self-inclusively (the status record the write creates is part of the count). 3. Reconcile the board to the live reading and flag the claim stale; if a warm-delta figure disagrees with graph stats, stats is canonical (Variant D).

def reconcile(board, store, namespace, warm_delta=None):
    # 1. Fresh source of truth -- ALWAYS, even if a claim exists.
    live_keys = store.list_keys()
    canonical_count = graph_stats(store)["keys"]   # stats wins (Variant D)

    # 2. Variant D cross-check: warm delta is diagnostic only.
    variant_d = None
    if warm_delta is not None and warm_delta != canonical_count:
        variant_d = (f"warm_delta({warm_delta}) != graph_stats("
                     f"{canonical_count}); Variant D -> stats canonical")

    # 3. Reconcile: overwrite stale claims, never reuse the old number.
    prev = board.get(namespace)
    stale = bool(prev and prev.claimed_keys != canonical_count)
    board.entries[namespace] = BoardEntry(
        namespace=namespace,
        claimed_keys=canonical_count,              # live value wins
        source="live reconcile" + (" (corrected stale claim)" if stale else ""),
        stale=stale,
        correction=variant_d or ("stale claim overwritten" if stale else None),
    )
    return ReconcileResult(namespace=namespace,
                           board_claimed=prev.claimed_keys if prev else None,
                           live_count=canonical_count,
                           live_keys=live_keys,
                           corrected=stale, variant_d=variant_d)

Key points in the implementation (/home/kara/foreman_board_fix.py): - KeyStore.list_keys() is never cached and instruments read count so we can prove fresh reads happen. - graph_stats() calls list_keys() itself → the count is always self-inclusive of any just-written status record. - reconcile() returns the full evidence (board_claimed, live_count, live_keys, corrected, variant_d) and mutates the board to the live value.
