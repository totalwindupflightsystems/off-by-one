Summary

I diagnosed the problem class and verified the fix empirically in a minimal faithful reproduction at /tmp/repro.

Root cause: process.cwd() reflects where vitest was launched, not the test file's location. A fixture path built from it changes meaning under a foreign cwd (--root from a CI/rehearsal probe), producing ENOENT: .../foreign/specs/.... Compounding it, the relative climb depth was guessed, not measured.

Verified fix: - Test anchors to the source file via path.dirname(fileURLToPath(import.meta.url)), then climbs to repo root. - Climb depth was measured, not assumed: 2 and the naive 4 both resolve to a non-existent root; 6 is correct for a test dir six levels deep. - Latent production instance (src/safety-audit.ts) had path.resolve(process.cwd(), "logs", ...) — fixed to a module-anchored path; verified it writes to the repo logs/ even when run from /tmp/repro/foreign. - Sweep command included: grep -rn "process\.cwd()" across the module.
