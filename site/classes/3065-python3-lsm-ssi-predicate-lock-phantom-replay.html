Diagnosis — root causes

The failure class is a wrong SSI decision, not a crash. Five defects cause it:

  1. Phantom gaps at page boundaries — range reads are tracked as the physical fragments actually scanned ([lo,p1], [p2,hi], …); a concurrent insert landing in the gap or exactly on the boundary creates no rw anti-dependency, so a real cycle is missed.
  2. Wrong anti-dependency visibility — R →rw W must exist only when W.commit_ts > R.start_ts (and W isn't the version R read). Getting this wrong reverses cycles and silently accepts write-skew/phantoms.
  3. Ignored bounded lock memory — when a transaction reads more ranges than the budget, the engine must escalate to a full-table predicate lock. Not modelling escalation drops conflicts the real engine observes.
  4. Retries mishandled — an aborted attempt must contribute nothing; a retry (retry_of, new start_ts) starts clean and now sees the competitor's committed value.
  5. Causality ignored — decisions must happen at commit time in commit_ts order; an offline "abort the smallest set" can abort an already-committed transaction.

Exact fix

ssi_solver.py (stdlib only) implements:

  • merge_ranges() — union of predicate fragments, merging touching ranges (next.lo <= cur.hi + 1), closing inter-page phantom holes.
  • _add_lock() — escalates a table to (-inf,+inf) and logs ESCALATE_TO_TABLE once the transaction's distinct range count exceeds lock_budget.
  • _candidate_edges() — builds wr/ww/rw over the committed set; rw guarded by commit_ts > start_ts plus predicate membership (catches phantoms).
  • _commit() — commits in timestamp order; aborts iff adding the transaction closes a cycle, keeping the committed DSG acyclic ⇒ serializable.
  • _shortest_cycle_through() — BFS returns the minimal cycle plus per-edge witness strings (keys, snapshots, predicates, timestamps) as the minimal conflict explanation.
  • Attempts are auto-numbered (T, T#2, …) and only committed attempts enter the version store, so retries are isolated.
