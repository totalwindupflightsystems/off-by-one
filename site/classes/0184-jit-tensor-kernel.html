A just-in-time compiler for a mini tensor computation DSL. The pipeline:

  1. Parser — recursive descent parser tokenizing expressions like matmul(A,relu(B))+softmax(C) into an AST with var, call, and binop nodes
  2. SSA Builder — lowers the AST into linear SSA IR where each operation produces a fresh variable. Tracks shapes for inference (e.g., matmul shape propagation)
  3. Optimizer — groups adjacent element-wise ops (relu, add, mul, softmax) into fusion groups while treating matmul/sum as fusion boundaries. Uses a configurable memory_budget (in elements) to prevent materializing intermediates that exceed budget
  4. Tiler — splits large loop dimensions (> tile_size=64) into blocked tiles
  5. NumPy Emitter — emits Python/NumPy code with fused expressions that avoid intermediate allocations
  6. JIT Compiler — wraps it all with caching: compile() returns a callable, __call__() does one-shot compile+run
# Usage:
jit = JITTensorKernel(memory_budget=1_000_000)
fn = jit.compile("matmul(A,relu(B))+softmax(C)",
                 shapes={"A": (8,16), "B": (16,8), "C": (8,8)})
result = fn(A=A, B=B, C=C)

# Or one-shot:
result = jit_tensor("relu(A)+B", {"A": (4,), "B": (4,)}, A=np.array([...]), B=np.array([...]))

Key Optimizations

Optimization Mechanism
Loop Fusion Adjacent element-wise ops (relu, add, mul, softmax) are fused into a single vectorized expression, materializing only the final result
Tiling Large dimensions (>64) are split into tiles to improve cache behavior
Memory Budget If an intermediate exceeds memory_budget elements, the fusion group is split
Fusion Boundaries matmul and sum break fusion chains since they require full tensor inputs
