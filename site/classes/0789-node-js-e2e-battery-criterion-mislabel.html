node-js-e2e-battery-criterion-mislabel

Answer

Root cause. The app loads sql.js the standard CDN way — the sql-wasm.js loader script defines initSqlJs on window (a top-level var that lands on the global in a classic <script>), and the app calls it to obtain the SQL module. The symbol sqlJs does not exist anywhere: not in the vendor artifact, not in the app. Battery test T93's 'sqlJs': 'function' criterion was a mislabel carried forward from an earlier version, so it failed against every healthy build — a false FAIL with no app defect.

The fix is a one-line criterion change, not an app change.

// battery/t93.js — BEFORE (mislabel carried forward): asserts a global the app never defines
module.exports = {
  id: 'T93',
  target: 'window.sqlJs',
  expect: 'function',            // false FAIL on every healthy build
};

// battery/t93.js — AFTER (fixed): assert the loader symbol the app actually loads
module.exports = {
  id: 'T93',
  target: 'window.initSqlJs',    // sql.js CDN loader (sql-wasm.js) exports initSqlJs
  expect: 'function',            // PASS — zero app code changes
};

If the battery engine evaluates criteria like typeof window[target] === expect, the fix is literally the target string swap above. A belt-and-braces variant that also covers the post-init contract (only if the battery can poll asynchronously — SQL is populated only after the initSqlJs() promise resolves, so a synchronous page-load check must use the loader symbol):

const crit = [
  { target: 'window.initSqlJs', expect: 'function' }, // loader present (sync, always assertable)
  { target: 'window.SQL',       expect: 'object'   }, // module exposed after async init (poll)
];

Generalized fix procedure (the lesson, codified): 1. Read the app's loader code and note the real symbol: const SQL = await initSqlJs({ locateFile }) → the loader symbol is initSqlJs, the exposed module is SQL. 2. Verify against the vendor artifact, don't guess: grep -c 'sqlJs' sql-wasm.js → 0; grep -o 'initSqlJs' sql-wasm.js | wc -l → 11. 3. Fix the criterion to the verified symbol; re-run the battery. 4. Only if the corrected criterion still fails (or the app's initSqlJs/SQL globals are genuinely absent at runtime) treat it as a regression.
