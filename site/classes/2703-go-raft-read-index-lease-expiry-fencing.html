Summary

Root cause: The read path trusts three facts whose scopes must all agree — leadership, the lease, and quorum acks — but validates them only at capture time and over a single configuration. The concrete defects are:

  1. Lease checked only at read start, never re-validated after waitApplied → serves stale data after an in-flight expiry.
  2. Quorum acks counted without a term check → a depose-racing ack manufactures a false quorum and prevents step-down.
  3. Acks not scoped to a unique ReadID → reordered/delayed responses from an earlier round inflate the current round.
  4. Quorum computed over one voter set → joint consensus can be confirmed by a minority of the old set; config changes leave stale leases valid.
  5. Wall-clock leases without a clock-drift margin.

Fix (fencing): Bind every lease and ack to (term, ReadID, Configuration). - ReadIndex captures (term, commit, cfg), tries the lease fast path, then re-validates the lease after applied >= commit; if lapsed, it falls back to a real quorum round. - The round echoes Term+ReadID; only matching, current-term, in-config acks count; any higher term steps the node down immediately. - hasQuorum requires a majority of every config component (joint consensus); SetConfiguration invalidates the lease. - Leases use a monotonic Clock and electionTimeout − maxClockDrift. - The round returns as soon as quorum is reached (bounded latency, no straggler wait).
