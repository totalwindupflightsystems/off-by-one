1. Gitignore subdirectory negation (docs-gitignore-subdir-negation)

The bug: .gitignore contains docs/* plus !docs/*.md. docs/* matches the directory docs/integrations/ and marks it ignored. Git never descends into ignored directories, so the negation !docs/*.md can never re-include anything inside it — and a file-level negation like !docs/integrations/guide.md is equally unreachable. Result: new doc subdirectories are silently dropped by git add docs/ / git add . (exit 0, nothing staged) or explicitly refused (exit 1, "The following paths are ignored…"), so new docs never get committed.

The fix: un-ignore the directory first, then git descends and the two-level path no longer matches docs/*:

docs/*
!docs/*.md
!docs/integrations/

Verification of the mechanism:

$ printf 'docs/*\n!docs/*.md\n!docs/integrations/\n' > .gitignore
$ git check-ignore docs/integrations/guide.md   # exit 1  → NOT ignored anymore
$ git add docs/integrations/guide.md            # stages fine
$ git commit -m "docs: add integrations guide"

Why the wrong fix fails — !docs/integrations/guide.md alone is dead because the parent dir docs/integrations/ is already ignored:

$ printf 'docs/*\n!docs/*.md\n!docs/integrations/guide.md\n' > .gitignore
$ git check-ignore docs/integrations/guide.md   # exit 0  → STILL ignored
$ git add docs/integrations/guide.md            # exit 1  → "The following paths are ignored…"

For deeper trees, add a negation at each level you want to re-include (e.g. !docs/integrations/ then !docs/integrations/api/ for a second level).

2. Docker build-from-source doc paths

The bug: the README says cd 9router/app && docker build -t 9router ., but the repo has no app/ directory (source lives at 9router/), so the documented path rots: cd 9router/app → No such file or directory. The documented command can never run.

The fix: make the repo root the build context and document that explicitly. Dockerfile at repo root:

FROM python:3.12-slim
WORKDIR /srv/9router
COPY 9router/main.py 9router/lib/ ./
CMD ["python", "main.py"]
