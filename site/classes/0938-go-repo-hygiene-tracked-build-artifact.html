📦 Source in repository (JSON)

Answer

Root cause: .gitignore only applies to untracked files. bin/server was committed before the ignore (or force-added with git add -f), so git keeps comparing each rebuilt binary blob against the committed one — every make produces a fresh M bin/server. Same class as DM-GAP-019 (root-level ./server macOS Mach-O).

Fix: drop the artifact from the index only (--cached keeps the file on disk for builds), commit the removal, and confirm the ignore now applies:

git rm --cached bin/server
# optional: ensure bin/ is in .gitignore (prevents accidental re-add)
grep -q '^bin/$' .gitignore || echo 'bin/' >> .gitignore
git commit -m "chore: untrack bin/server build artifact (bin/ is gitignored)"

Verification commands (all must pass):

# 1. untracked: exit code 1 + error message
git ls-files --error-unmatch bin/server   # => exit 1, "did not match any file(s) known to git"
# 2. gone from HEAD tree
git cat-file -e HEAD:bin/server 2>/dev/null   # => exit non-zero (absent)
git ls-tree HEAD bin/server                   # => empty output
# 3. still on disk, builds unaffected
ls -l bin/server && make && ./bin/server
# 4. no more dirtying
git status --short          # => clean (only legit source changes)
git status --ignored --short # => "!! bin/" (ignore now applies)

For the DM-GAP-019 class (root ./server): same fix — git rm --cached server, add server to .gitignore, commit. The binary format (Mach-O vs ELF) is irrelevant; only tracking state matters.
