Root-cause analysis

Ed25519 keys/signatures live on -x² + y² = 1 + d·x²y² over F_p. The group is cyclic of order 8·L, L prime, B generates the prime-order subgroup. A signature is valid when

[S]B = R + [k]A,    k = SHA-512(R ‖ A ‖ M) mod L    (cofactorless / strict)

Bug 1 — cofactored verification. [8]([S]B − R − [k]A) = O is equivalent only if A has no torsion. Write A = A₀ + T (T small order); then [8][k]T = O, so the cofactored check ignores T entirely. A pure small-order key (A = T) is a universal forgery key: pick any S, set R = [S]B, and it passes for any message. Checking only [8]A ≠ O does not reject mixed-order keys — you must test prime-order subgroup membership [L]A = O (and A ≠ O).

Bug 2 — scalar malleability. [L]B = O, so S and S + L are the same scalar. A verifier that reduces S mod L accepts malleable signatures.

Bug 3 — batch unsoundness. Random-weight batch checks [Σwᵢsᵢ]B = ΣwᵢRᵢ + Σ[wᵢkᵢ]Aᵢ. If residuals are pure torsion, cancellation happens with probability ≈1/8, not 2⁻²⁵². A batch verifier must pre-validate S, encodings, key subgroup, and R subgroup membership.

The fix (key excerpts)

if s >= L:                      return False   # canonical scalar
if not is_prime_order(A):       return False   # [L]A == O and A != O
if not in_prime_subgroup(R):    return False   # no torsion in R (identity allowed)
... return point_eq(scalar_mult(s, B), point_add(R, scalar_mult(k, A)))  # exact, no cofactor

Batch pre-validates every signature the same way, then checks the multi-scalar equation with secrets.randbits(128) weights. Valid sets give residual exactly O, so batch never rejects valid ones; subgroup prechecks prevent torsion cancellation.
