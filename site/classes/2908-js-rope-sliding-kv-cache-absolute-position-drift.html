Root cause

RoPE scores depend on the relative offset t − s. A sliding-window cache keeps keys s ∈ [t−W+1, t] but compacts them into slots j = 0…W−1. If keys are rotated by slot index j while the query uses its absolute generation counter t, the effective offset becomes t − j = (t − s) + evicted. The bias is zero until the window wraps, then grows with every eviction. NTK-aware base scaling only rescales frequencies; it neither causes nor cures this.

Failing case (W=16, 64 generated tokens, NTK α=8)

step |  reference |    naive |    fixed
  16 |     1.6684 |   1.6684 | 1.66841982   <- window fills
  17 |     1.8072 |   1.7433 | 1.80722570   <- first drift
  64 |     1.9784 |   6.5081 | 1.97835843   <- 3.3x reference PPL
attention drift t=64: naive=2.262e-1  fixed=0.000e+0

Naive is bit-identical until eviction begins, then silently degrades. The fix reproduces the reference to floating-point precision.

The fix

Store the absolute position in the slot and rotate by it; push/evict the (k, v, pos) triple atomically:

// BUG
const kr = rope(this.K[j], j);
// FIX
const kr = rope(this.K[j], this.pos[j]);

with

push(k, v, pos) {
  this.K.push(k); this.V.push(v); this.pos.push(pos);
  while (this.K.length > this.cacheW) { this.K.shift(); this.V.shift(); this.pos.shift(); }
  if (this.K.length !== this.V.length || this.K.length !== this.pos.length)
    throw new Error('desynchronised KV slot');   // no partially-retained boundary pair
}
