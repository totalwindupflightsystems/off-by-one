Summary

Diagnosis: The test polls existsSync(file) then reads. POSIX echo "$PWD" > "$FILE" is two syscalls: open(O_CREAT|O_TRUNC) makes the path visible at 0 bytes, then write fills it. Existence ≠ readiness, so the reader can observe the intermediate empty state. CI scheduling/FS latency widens that window; locally the loop usually wins the race.

Fix: Make the wait predicate content-aware — treat ENOENT and empty/whitespace as not-ready, with a timeout deadline. Also noted the atomic write temp + rename option when you own the writer.

Verification (two-proof): I injected a deliberate 400 ms create→write window into a dash stub using exec 3> "$OUT"; sleep …; printf … >&3, then ran the same assertion with two predicates:

  • OLD (existence-only), WAITER=old SLEEP_MS=400 → 1 failed with the exact CI message: AssertionError: expected '' to be '/tmp/embed-hooks-bJ0zev/duckbrain-root'
  • NEW (content-aware), WAITER=new SLEEP_MS=400 → 1 passed

Same injected window in both, so the predicate is causally responsible. A green re-run alone was explicitly called out as insufficient.

Note: one false start during verification — my stub interpreted STUB_SLEEP as seconds while I passed milliseconds (sleep 400 = 400s). That was a repro bug, not a fix issue; corrected to sleepMs / 1000 and re-verified.

Repro project lives at /tmp/race-repro if you want to re-run it.
