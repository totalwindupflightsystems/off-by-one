Summary

Root cause (the bug class)

The tempting GC rule — "drop a bottom-level tombstone when seq < min(live snapshots)" — is insufficient. A bottom tombstone can be dropped while an older version of the same key still lives in an un-compacted upper level. The tombstone used to shadow that older copy for the latest read; removing it resurrects the old value (shadowing loss / key resurrection). Two secondary defects: overflowing the target budget instead of choosing inputs, and order-dependent merging of overlapping runs. I also found and fixed two verifier traps that mask real bugs: requiring preservation at non-live historical seqnos (GC is allowed below the oldest watermark), and tolerating duplicate (key, seq) pairs (impossible in a real LSM).

Exact fix

A tombstone t is removed only if all hold: output goes to the bottom level; t.seq < min(snapshots); and no older version survives outside the compaction inputs (min_seq_outside[key] > t.seq). When an older external version exists, t is retained but the entries strictly older than t inside the merge are still collapsed:

if min_seq_outside.get(t["key"], INF) > t["seq"]:
    result.extend(group[:cut])        # safe: drop t and everything older
else:
    result.extend(group[:cut + 1])    # keep t, GC only older collapsed data

Plus: deterministic (key asc, seq desc) merge; greedy input selection so every step satisfies bytes_out <= budget[to_level]; WA = Σbytes_out / Σbytes_in; a fixed-point multi-pass scheduler (terminates because Φ = Σ entries·(bottom − level) strictly decreases).
