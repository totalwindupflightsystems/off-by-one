Answer

The fixture tick had three concrete defects, all confirmed against the environment:

  1. h3-test has no -o flag (argparse rejects it — verified). The JSON must be captured by redirecting stdout to a file.
  2. Inline python3 <<EOF heredoc parses are blocked by the cron filter. The parse must live in a standalone script file, run separately.
  3. Go-build variant: no prebuilt h3echo binary exists, so the harness must be compiled from sdk-go/examples/echo with go build -o /tmp/h3echoNNN . each tick, run in the background on the canonical port :9191, torn down after, and the port verified free via ss. Pre-flight must accept :919x free at fire and ignore the pre-existing :8000 zombie.

The fix — run-h3-e2e.sh (the due-cycle body):

#!/usr/bin/env bash
set -euo pipefail
PORT="${H3_E2E_PORT:-9191}"
ENDPOINT="http://localhost:${PORT}"
ECHO_DIR="${H3_ECHO_DIR:-sdk-go/examples/echo}"
H3_TEST="${H3_TEST:-h3-test}"
PARSE="${H3_PARSE:-/tmp/h3parse.py}"
OUT_JSON="$(mktemp /tmp/h3-e2e-XXXXXX.json)"
BIN="$(mktemp /tmp/h3echoXXXXXX)"; rm -f "$BIN"
SRV_PID=""

cleanup() {
  if [[ -n "${SRV_PID}" ]] && kill -0 "${SRV_PID}" 2>/dev/null; then
    kill "${SRV_PID}" 2>/dev/null || true; wait "${SRV_PID}" 2>/dev/null || true
  fi
  rm -f "${OUT_JSON}" "${BIN}"
}
trap cleanup EXIT

# Pre-flight: :919x must be free at fire (only :8000 zombie is expected).
if ss -tln | awk '{print $4}' | grep -qE "(:${PORT})$"; then
  echo "FATAL: port ${PORT} already in use before E2E" >&2; exit 3
fi

# Go-build variant (no prebuilt binary).
( cd "${ECHO_DIR}" && go build -o "${BIN}" . )
( cd "${ECHO_DIR}" && "${BIN}" -addr "localhost:${PORT}" ) &
SRV_PID=$!

ready=0
for _ in $(seq 1 50); do
  curl -fsS "${ENDPOINT}/health" >/dev/null 2>&1 && { ready=1; break; }
  kill -0 "${SRV_PID}" 2>/dev/null || break
  sleep 0.1
done
[[ "${ready}" == 1 ]] || { echo "FATAL: harness not ready" >&2; exit 4; }

# Redirect stdout to file — there is NO -o flag.
"${H3_TEST}" --endpoint "${ENDPOINT}" --json > "${OUT_JSON}"

# Parse via separate script file (heredoc parses are blocked).
python3 "${PARSE}" "${OUT_JSON}"; rc=$?

# Teardown + verify port free via ss.
kill "${SRV_PID}" 2>/dev/null || true; wait "${SRV_PID}" 2>/dev/null || true; SRV_PID=""
if ss -tln | awk '{print $4}' | grep -qE "(:${PORT})$"; then
  echo "FATAL: port ${PORT} still bound" >&2; exit 5
fi
exit "${rc}"

The fix — /tmp/h3parse.py (separate parser file; normalizes JSON category names to board shorthand per the #240 note):

#!/usr/bin/env python3
import json, sys

BOARD_SHORTHAND = {"echo.http": "http", "echo.websocket": "ws", "echo.stream": "sse"}

raw = open(sys.argv[1], encoding="utf-8").read() if len(sys.argv) > 1 else sys.stdin.read()
doc = json.loads(raw)  # fail loudly on malformed JSON

passed, failed = int(doc["passed"]), int(doc["failed"])
lat = doc.get("latency") or {}
print(f"total={doc['total']} passed={passed} failed={failed}")
print(f"duration_ms={doc.get('duration_ms')} p50={lat.get('p50')} p95={lat.get('p95')} p99={lat.get('p99')}")
for raw_name, c in (doc.get("categories") or {}).items():
    name = BOARD_SHORTHAND.get(raw_name, raw_name)
    print(f"[{'PASS' if c['failed']==0 else 'FAIL'}] {name}: {c['passed']}/{c['passed']+c['failed']}")
print(f"all_passing={doc.get('all_passing')}")
sys.exit(0 if (failed == 0 and doc.get("all_passing")) else 1)
