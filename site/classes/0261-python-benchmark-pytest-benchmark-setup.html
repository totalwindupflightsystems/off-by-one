Answer

The repo was /tmp/bench-demo (hermes-sdk, src-layout, uv 0.11.17, py3.14, pytest 9.1.1, pytest-benchmark 5.2.3). Four changes:

1. Move the dep from [dependency-groups] into the existing dev extra, re-lock

uv add --dev wrote a PEP 735 group that pip cannot see. Fix by editing pyproject.toml, then re-locking:

[project.optional-dependencies]
dev = [
    "pytest==9.1.1",
    "pytest-benchmark==5.2.3",   # moved here
]

# [dependency-groups]           <- delete (or keep only non-dev groups)
# dev = [
#     "pytest-benchmark==5.2.3",
# ]

uv lock && uv lock --check        # re-resolve; uv.lock now binds to extra == 'dev'
pip install -e ".[dev]"           # classic workflow works again

(Alternative that never writes the group: uv add --optional dev pytest-benchmark.)

2. Replace bare ini keys with addopts — pytest-benchmark 5.2.3 registers no benchmark_* ini keys (only --benchmark-* CLI options), so bare keys trigger PytestConfigWarning and are ignored:

[tool.pytest.ini_options]
addopts = ["--benchmark-min-rounds=3", "--benchmark-max-time=0.5"]
# (remove benchmark_min_rounds / benchmark_max_time bare keys)

3. Sync test driving a dedicated event loop — pytest-benchmark never awaits coroutines; it times construction (~1 µs). The benchmark must be a plain sync def wrapping asyncio.run:

# tests/test_bench_hermes.py
import asyncio
from hermes_sdk import MockHermes

def test_mock_hermes_benchmark(benchmark):
    mock = MockHermes()

    async def _run() -> str:
        return await mock.generate("hello")

    def _sync_run() -> str:
        return asyncio.run(_run())     # dedicated event loop per round

    result = benchmark(_sync_run)
    assert result == "reply-to:hello"   # assert on the awaited value

4. Gitignore the artifact dir:

.benchmarks/

Bonus gotcha found during verification: pytest's default collection pattern is test_*.py/*_test.py — a file named bench_hermes_buggy.py was silently not collected in suite runs (it only ran when passed explicitly). Rename benchmark modules to test_bench_*.py.
