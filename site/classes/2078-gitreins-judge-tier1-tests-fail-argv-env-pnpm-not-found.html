Answer

I diagnosed the failure and wrote a verified, self-contained solution to /workspace/solution.md.

Root cause (three distinct hazards)

  1. Primary — inherited PATH. guard_manager runs pnpm test with env=_sanitized_env(), which only strips GIT_* and preserves PATH. Under a bare gateway/cron PATH (/usr/bin:/bin) there is no ~/.local/node/bin, so /bin/sh can't resolve pnpm. Standalone runs are green because an interactive shell sources the profile that adds the Node bin dir.
  2. E2BIG. Exec'ing the copied venv Python with the full session environment can exceed ARG_MAX/MAX_ARG_STRLEN, yielding [Errno 7] Argument list too long. The launcher must execve with a minimal env.
  3. Infinite re-exec. To apply env -i you must re-exec the wrapper; without a pass-2 marker it loops forever.

Fix

  • A $HOME/.local/bin/gitreins launcher wrapper that:
  • locates the Node bin dir and sets PATH=<node-bin>:$HOME/.local/bin:<venv>/bin:/usr/local/bin:/usr/bin:/bin,
  • sets TMPDIR=/tmp and GITREINS_LLM_BASE_URL/GITREINS_LLM_MODEL,
  • re-execs itself once under env -i with GITREINS_WRAPPED=1 (E2BIG fix + loop guard), then on pass 2 execs $VENV/bin/python -m gitreins.
  • A defense-in-depth patch to guard_manager._sanitized_env() that prepends the detected Node bin dir to PATH.

Verification (actual run)

Built a faithful sandbox (fake pnpm, fake copied venv with the _sanitized_env() subprocess, the wrapper) and ran it:
