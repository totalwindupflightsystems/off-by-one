Fix: events.jsonl-shaped row misfiled into tasks.jsonl (boardctl refuses with "task row at file position N has no id")

Problem class: jsonl-board-event-row-misfiled-in-tasks Tool: boardctl 0.4.0 · Project: muster · Board: tasks.jsonl Context: event_id 787, reported position 210, suspected physical line 213, introduced by commit 546bc184

1. Symptom

boardctl list, next, and ready abort with:

boardctl: task row at file position 210 has no id

Every real task row is well formed, yet scheduling is blocked. boardctl validate may still print RESULT: OK (with key-drift warnings), so validate alone does not catch this.

2. Root-cause analysis

A topology-A board is line-delimited JSON under .coding-hermes/board/: every physical line of tasks.jsonl must be a task object with a string id; every line of events.jsonl is an event with a numeric id plus event_type/task_id/actor/detail.

During normalization commit 546bc184, an event-shaped record (id 787, "event_type":"task_normalized", task_id, actor, detail, tick_number, timestamp) was appended to tasks.jsonl instead of events.jsonl. It is valid JSON, so the syntax checkers pass, but boardctl's task scanner requires (.id | type) == "string"; 787 is a number, so it raises task row at file position N has no id and refuses to enumerate.

Two facts drive the fix: * file position N is a 0-based row index, not a physical line. Normally physical line = N + 1; the mismatch between reported 210 and offending_line 213 shows it can drift. Detect the line programmatically and confirm its shape before cutting. * The row is not a byte-identical duplicate of its events.jsonl twin (different key order/spacing). It is the same record under a canonical jq -S -c fold, so compare semantically.

3. Preconditions

BOARD="${1:-.}"
if   [ -f "$BOARD/board.jsonl" ] && [ -f "$BOARD/tasks.jsonl" ]; then :
elif [ -f "$BOARD/.coding-hermes/board/tasks.jsonl" ]; then BOARD="$BOARD/.coding-hermes/board"; fi
cd "$BOARD"
ts="$(date -u +%Y%m%dT%H%M%SZ)"
cp -p tasks.jsonl "tasks.jsonl.bak.$ts"

4. Exact fix

4.1 Detect the misfiled line (do not trust the literal number)

BAD_LINES=$(jq -R '
  select((fromjson? | type) == "object")
  | select((fromjson | (.id?|type)) != "string")
  | input_line_number' tasks.jsonl)
echo "offending physical line(s): ${BAD_LINES:-<none>}"

4.2 Capture, confirm the twin, cut atomically, preserve

BEFORE_COUNT=$(wc -l < tasks.jsonl)
while IFS= read -r n; do
  [ -z "$n" ] && continue
  BAD_ROW=$(sed -n "${n}p" tasks.jsonl)
  BAD_SHA=$(printf '%s\n' "$BAD_ROW" | sha256sum | awk '{print $1}')
  echo "line $n sha256=$BAD_SHA"

  BAD_ID=$(printf '%s\n' "$BAD_ROW" | jq '.id')
  TWIN=$(jq -c --argjson id "$BAD_ID" 'select(.id == $id)' events.jsonl | head -1)
  [ -n "$TWIN" ] && diff <(printf '%s\n' "$BAD_ROW" | jq -S -c .) \
                        <(printf '%s\n' "$TWIN"    | jq -S -c .) \
                 && echo "  confirmed: jq -S -c fold matches events.jsonl id=$BAD_ID"

  awk -v n="$n" 'NR != n' tasks.jsonl > tasks.jsonl.tmp
  [ "$(wc -l < tasks.jsonl.tmp)" -eq "$((BEFORE_COUNT - 1))" ] \
    || { echo "ABORT: temp line count is not BEFORE-1"; rm -f tasks.jsonl.tmp; exit 3; }
  jq -e . tasks.jsonl.tmp >/dev/null 2>&1 \
    || { echo "ABORT: temp file is not valid JSONL"; rm -f tasks.jsonl.tmp; exit 4; }
  mv -f tasks.jsonl.tmp tasks.jsonl

  boardctl event --type audit --actor foreman \
    --task-id "$(printf '%s\n' "$BAD_ROW" | jq -r '.task_id // "board"')" \
    --detail-text "removed misfiled task row from tasks.jsonl line ${n} during normalization repair; sha256=${BAD_SHA}; row=${BAD_ROW}"
done <<< "$BAD_LINES"

AFTER_COUNT=$(wc -l < tasks.jsonl)
echo "tasks.jsonl line count: ${BEFORE_COUNT} -> ${AFTER_COUNT} (delta $((BEFORE_COUNT-AFTER_COUNT)))"

If the offender is certain to be exactly line 213, the same core reduces to N=213; BAD_ROW=$(sed -n "${N}p" tasks.jsonl); BAD_SHA=$(…sha256sum…); awk -v n="$N" 'NR!=n' tasks.jsonl > tasks.jsonl.tmp && mv -f tasks.jsonl.tmp tasks.jsonl; boardctl event --type audit --actor foreman --task-id "$(jq -r '.task_id' <<<"$BAD_ROW")" --detail-text "removed misfiled task row line ${N}; sha256=${BAD_SHA}; row=${BAD_ROW}".

6. Rollback

7. Prevention

  • Audit the normalization writer from 546bc184 for an off-by-one target file (tasks.jsonl vs events.jsonl).
  • Assert at write time that anything appended to tasks.jsonl has (.id|type)=="string"; validate does not currently fail on this, so add a guard.
  • Keep the 0-based "file position" distinct from the physical line in tooling/doc.
