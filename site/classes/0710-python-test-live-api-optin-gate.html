python-test-live-api-optin-gate

Answer

Root cause (AP-GAP-004): Live tests were gated only by @pytest.mark.live and/or an OPENROUTER_API_KEY-presence check. A real key in the environment was therefore treated as consent → 1 paid OpenRouter call + 1 >30s hang during documented pytest tests/. Fix: make the opt-in explicit and fixture-level, and let the two fixture styles (session-scoped function fixture, class-autouse fixture) share one gate.

tests/conftest.py — register the flag, expose the env helper, define the session gate:

import os
import pytest

def pytest_addoption(parser):
    """Lesson 2: register --live-api or pytest errors 'unrecognized arguments'."""
    parser.addoption("--live-api", action="store_true", default=False,
                     help="Run tests that call live (paid) LLM APIs. Default: off.")

def pytest_configure(config):
    config.addinivalue_line("markers", "live: requires a live (paid) LLM API call")

def _live_enabled() -> bool:
    """Module-level opt-in helper: PTP_LIVE=1 env var."""
    return os.getenv("PTP_LIVE") == "1"

@pytest.fixture(scope="session")
def _require_live(request):
    """Lesson 1: gate at the FIXTURE level, not just the mark."""
    if not (request.config.getoption("--live-api") or _live_enabled()):
        pytest.skip("opt-in gate: pass --live-api or set PTP_LIVE=1")
    return True

First test file (function-style) — live tests take _require_live; @pytest.mark.live remains as documentation only:

@pytest.mark.live
def test_live_chat_completion(_require_live):
    assert b"ok" in _call_llm()   # hits OpenRouter only when opted in

Second test file (class-style) — the class-level autouse _check_prereqs gets the same OR'd gate (import the helper from conftest):

from conftest import _live_enabled

class TestLiveLLM:
    @pytest.fixture(autouse=True)
    def _check_prereqs(self, request):
        if not (request.config.getoption("--live-api") or _live_enabled()):
            pytest.skip("opt-in gate: pass --live-api or set PTP_LIVE=1")

    @pytest.mark.live
    def test_live_stream(self):
        assert b"ok" in _call_llm()

Key points: (1) fixture-level gating covers both function and class-autouse styles; (2) pytest_addoption must register the CLI flag; (3) the skip reason is explicit ("opt-in gate: …"), so -rs proves the gate fired rather than a missing-key skip.

Evidence & signatures

No repo was checked out here, so I reproduced the exact structure in `/tmp/apgap004` (conftest + two live test files with the two fixture styles + normal tests) and ran it against a **local counting HTTP server** standing in for OpenRouter (logs one line per request). All runs used pytest 9.0.2 with a real-looking `OPENROUTER_API_KEY` exported.

This matches the reported repo outcome (3860 passed / 14 skipped, zero network) and generalizes the `_check_prereqs` autouse fixture pattern to the second file.
