Diagnosis

The affected artifact is /usr/local/lib/terminal-jail/plugin/terminal_jail/seccomp.py. Three defects:

  1. glibc routing miss. The deny table had 159 (adjtimex), but glibc's adjtimex(3) wrapper calls clock_adjtime, NR 305. Confirmed with strace: clock_adjtime(CLOCK_REALTIME, {...}) = 0 (TIME_OK) 305 (and aarch64 266) were absent, so the libc call was allowed.

  2. JEQ jf fall-through skip. Non-final deny checks were encoded JEQ(nr, jt=<deny block>, jf=1). On a miss, jf=1 skips the next deny check. With the 18-entry table that silently bypassed exactly the 9 reported entries: [159, 164, 167, 174, 176, 246, 249, 305, 320] (including adjtimex and clock_adjtime). Fix: jf = 0.

  3. Inverted arch prologue (latent, blocking). JEQ(arch, jt=0, jf=1) fell into RET KILL_PROCESS on a matching arch — the as-shipped filter SIGSYS-killed its own loader. Fix: JEQ(arch, jt=1, jf=0).

Fix

Add 305 (x86_64) / 266 (aarch64); change the arch branch to (arch_value, 1, 0) in both code paths; drop remaining/jf and emit every deny check with jf=0, so jt lands on RET ERRNO|EPERM and a miss falls through to the next check.

Verification (all run here)

  • python3 -m pytest -q test_seccomp_regression.py → 4 passed (includes a forked kernel test calling the glibc adjtimex wrapper and asserting EPERM).
  • Pure BPF differential: fixed → all 18 deny NRs return ERRNO; jf=1 variant → 9 bypasses including 159 and 305.
  • Kernel strace under the fixed filter: prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, {len=24, ...}) = 0 clock_adjtime(CLOCK_REALTIME, ...) = -1 EPERM # glibc adjtimex(3) adjtimex(...) = -1 EPERM # raw 159 clock_adjtime(CLOCK_MONOTONIC, ...)= -1 EPERM # raw 305
  • patch -p1 --dry-run on the as-shipped file succeeds; the result is byte-identical to the tested fixed copy.

The doc also notes an optional hardening fix: set PR_SET_NO_NEW_PRIVS before PR_SET_SECCOMP so an unprivileged jail cannot silently fall back to running unfiltered.
