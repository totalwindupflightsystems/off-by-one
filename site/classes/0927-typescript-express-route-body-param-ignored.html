Answer

The bug: POST /api/memories read the namespace only from req.query.namespace, so a namespace sent in the JSON body was silently ignored and every memory landed in the default namespace. Fixed in src/memories.ts with an explicit query || body || default resolution chain:

// src/memories.ts
export const DEFAULT_NAMESPACE = 'default';

function stringOrUndefined(value: unknown): string | undefined {
  return typeof value === 'string' && value.trim().length > 0 ? value : undefined;
}

export function resolveNamespace(queryValue: unknown, bodyValue: unknown): string {
  return stringOrUndefined(queryValue) ?? stringOrUndefined(bodyValue) ?? DEFAULT_NAMESPACE;
}

router.post('/api/memories', (req: MemoriesRequest, res: Response) => {
  const namespace = resolveNamespace(req.query.namespace, req.body?.namespace);
  // ...store record under `namespace`
});

Precedence: ?namespace= query → namespace JSON body field → 'default'. Non-string, empty-string, and array (repeated ?namespace=a&namespace=b) values are treated as absent so they fall through safely instead of crashing or mis-storing. Query keeps precedence so existing query-string clients are unaffected.

Optional field on the request interface (Express 5 types declare body as required, hence Omit):

export interface MemoriesRequestBody {
  namespace?: string; // optional — query param or default can supply it
  content?: string;
  tags?: string[];
}

export interface MemoriesRequest extends Omit<Request, 'body'> {
  body?: MemoriesRequestBody; // stays optional: express may not parse an empty body
}

Docs in README.md: bug description, resolution precedence table, API reference, and run instructions. One clean commit: 4bf7e59 fix(api): honor namespace from JSON body on POST /api/memories.
