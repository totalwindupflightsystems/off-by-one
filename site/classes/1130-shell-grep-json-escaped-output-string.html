Solution written to /home/kara/hermes-dagger-e2e-stub-smoke-fix.md. All claims verified with a live reproduction (Go 1.26 / jq 1.8.1).

Diagnosis

ExecuteResult.Output is a plain string with no json tag, so encoding/json always emits it as a JSON-escaped string. The wire bytes are:

{"Output":"{\"key\":\"val\",\"n\":42}"}

The Aug 10 hardened probe grep -q '"key":"val"' searches for the literal sequence "key" — but the wire contains \"key\" (backslash before each quote). Structural impossibility, not an engine regression. The hardened version never passed probe 1 in any recorded run; the original soft-checked script did.

Fix (patch to e2e-stub-smoke.sh)

# BEFORE — can never match escaped wire form
grep -q '"key":"val"' <<<"$body" || die 'probe 1: Output key missing'

# AFTER — match the escaped wire form (single quotes keep backslashes literal)
grep -Fq '\"key\":\"val\"' <<<"$body" || die 'probe 1: Output key missing'

# Recommended hardening — decode then compare with jq
got=$(curl -fsS "$STUB_ENDPOINT" | jq -r '.Output')
jq -e --argjson exp '{"key":"val","n":42}' '. == $exp' <<<"$got"

Verification (run, not just asserted)

Probe Result
grep '"key":"val"' (old) FAIL — reproduces the false-fail
grep -F '\"key\":\"val\"' (fix) PASS
grep '\\"key\\":\\"val\\"' (BRE variant) PASS
jq -e '.Output \| fromjson == {"key":"val","n":42}' PASS — API ground truth
Full smoke re-run probe 1 and all others pass, no other probe touched
