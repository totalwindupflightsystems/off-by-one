Fix: Hermetic scratch daemon readiness gate must not trust a stale fixed-port listener

Symptom

A hermetic Bash self-test starts a scratch daemon on the hard-coded port 18997 and waits for readiness. The green gate fails intermittently (or passes against the wrong process) because ss sees a listener owned by a previous scratch clone whose directory was deleted. The orphan still holds 18997, and its executable shows a path ending in (deleted):

LISTEN 0 8 <ip-address>:18997 <ip-address>:* users:(("scratchd",pid=1855,fd=3))
/proc/1855/exe -> /tmp/scratch.old/bin/scratchd (deleted)

This produces two failure modes:

  • False negative — the gate reads the listener's /proc/<pid>/exe, sees (deleted) / a foreign path, and fails even though the current build is healthy. This is the reported bug.
  • False positive — a lax gate only checks "is something listening on 18997?" and passes while the current daemon actually died with EADDRINUSE, talking instead to a stale wrong-version process.

Root cause

  1. A fixed port is a global shared resource, not owned by the test. A leaked prior daemon keeps it bound; the new daemon's bind() fails and it exits. SO_REUSEADDR does not let two live listeners share an address.
  2. The probe equates "a listener exists" with "my listener exists." ss -ltn "sport = :18997" cannot distinguish the current artifact from an orphan.
  3. Identity is checked by path only. A stale process's /proc/<pid>/exe ends in (deleted); readlink -f returns empty for such a link, so the path comparison can never succeed. A path-only check is also fooled by a same-path rebuild.
  4. No cleanup guarantee, so a killed/errored run orphans the daemon and poisons the next run.

Correct invariant: the test owns a uniquely allocated port, and the process listening on it is provably the artifact this run just built.

The exact fix

1. Let the kernel allocate a unique port

The daemon should accept port 0 and print the port it bound via getsockname. The kernel guarantees uniqueness at bind time — no TOCTOU window.

2. Prove process identity before accepting the listener

Accept only when: /proc/<pid>/exe is readable and not (deleted); its dev:inode equals the just-built artifact's dev:inode; the process started at/after the test began; and a functional health request succeeds. Use readlink (no -f) so the (deleted) marker is visible.

#!/usr/bin/env bash
# lib-gate.sh — reusable hermetic readiness helpers.

pick_free_port() {           # fallback only; prefer daemon port 0
  python3 - <<'PY'
import socket
s = socket.socket(); s.bind(("<ip-address>", 0))
print(s.getsockname()[1]); s.close()
PY
}

proc_start_ticks() {         # start time in clock ticks, robust to spaces in comm
  sed 's/.*) //' "/proc/$1/stat" 2>/dev/null | awk '{print $20}'
}

# prove_owned <pid> <artifact> [min_start_ticks]
prove_owned() {
  local pid="$1" artifact="$2" min_start="${3:-0}" exe got_id want_id start
  [[ -r "/proc/$pid/exe" ]] || return 1
  exe=$(readlink "/proc/$pid/exe" 2>/dev/null) || return 1
  [[ "$exe" != *"(deleted)" ]] || return 1
  got_id=$(stat -Lc '%d:%i' "/proc/$pid/exe" 2>/dev/null) || return 1
  want_id=$(stat -Lc '%d:%i' "$artifact" 2>/dev/null) || return 1
  [[ "$got_id" == "$want_id" ]] || return 1
  if [[ "$min_start" != 0 ]]; then
    start=$(proc_start_ticks "$pid")
    [[ -n "$start" && "$start" -ge "$min_start" ]] || return 1
  fi
  return 0
}

# wait_for_owned_listener <port> <artifact> [min_start_ticks] [tries]
wait_for_owned_listener() {
  local port="$1" artifact="$2" min_start="${3:-0}" tries="${4:-100}" i pid
  for ((i = 0; i < tries; i++)); do
    for pid in $(ss -ltnpH "sport = :$port" 2>/dev/null | grep -oP 'pid=\K[0-9]+' | sort -u); do
      if prove_owned "$pid" "$artifact" "$min_start"; then
        printf '%s\n' "$pid"; return 0
      fi
    done
    sleep 0.1
  done
  return 1
}

#!/usr/bin/env bash
# gate-fixed.sh — kernel-assigned unique port + real process-identity proof.
set -euo pipefail
SCRATCH="${1:?usage: gate-fixed.sh <scratch-dir>}"
ARTIFACT="$SCRATCH/bin/scratchd"
source ./lib-gate.sh
TEST_START=$(proc_start_ticks $$)

portfile=$(mktemp)
"$ARTIFACT" 0 >"$portfile" 2>/dev/null &
DPID=$!
trap 'kill "$DPID" 2>/dev/null || true; rm -f "$portfile"' EXIT

PORT=""
for _ in $(seq 1 50); do
  PORT=$(sed -n 's/^PORT=\([0-9]\{1,\}\)$/\1/p' "$portfile" | head -1)
  [[ -n "$PORT" ]] && break
  sleep 0.1
done
[[ -n "$PORT" ]] || { echo "FIXED: FAIL (daemon never reported a port)"; exit 1; }

owned=$(wait_for_owned_listener "$PORT" "$ARTIFACT" "$TEST_START" 100) \
  || { echo "FIXED: FAIL (no listener owned by $ARTIFACT)"; exit 1; }
[[ "$owned" == "$DPID" ]] || { echo "FIXED: FAIL (port held by pid $owned, expected $DPID)"; exit 1; }

curl -fsS --max-time 3 "http://<ip-address>:$PORT/health" | grep -q '^ok' \
  || { echo "FIXED: FAIL (health check on port $PORT)"; exit 1; }
echo "FIXED: PASS (port=$PORT pid=$owned artifact=$ARTIFACT)"

Fallback when the daemon must receive an explicit port — retry on collision:

for attempt in $(seq 1 20); do
  PORT=$(pick_free_port)
  "$ARTIFACT" "$PORT" >"$portfile" 2>/dev/null &
  DPID=$!
  if owned=$(wait_for_owned_listener "$PORT" "$ARTIFACT" "$TEST_START" 20); then break; fi
  kill "$DPID" 2>/dev/null || true
done
[[ -n "${owned:-}" ]] || { echo "FAIL: could not obtain an owned listener"; exit 1; }

For the strongest guarantee, pass an already-bound listening socket to the daemon (socket activation) so the port is never released.

Verification

/workspace/repro/verify.sh plants a stale (deleted) listener on 18997, then asserts the fixed gate ignores it, binds a different ephemeral port, proves ownership, and passes. It exits non-zero on any failed assertion. Observed:

ASSERT OK: fixed gate chose unique port 46457 and proved pid=1867 is /tmp/verify.jlGsMr/current/bin/scratchd
VERIFY: PASS

The same stale state drives the old gates:

Gate Behaviour with stale 18997 Result
Lax (ss sees any listener) passes against the orphan false positive
Buggy (fixed port + path check) readlink -f of deleted exe is empty → mismatch false negative
Fixed (unique port + inode/start-time proof) ignores 18997, owns a new port correct pass

I also confirmed the fallback loop (pick_free_port + retry) and rejection of a same-path/wrong-inode artifact and a deleted exe, and ran the fixed gate 15× with no flakes.
