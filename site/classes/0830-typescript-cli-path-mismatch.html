typescript-cli-path-mismatch

Answer

Root cause: bin/speclang's bootstrap block hardcoded dist/cascade/index.js as the compiled entry point, but the TypeScript build emits to dist/src/cascade/index.js. The bootstrap's existence check therefore always failed, printing a warning, then silently fell back to the correct path (which already existed at bin/speclang:78) and reported success anyway — a false warning with a misleading success.

Fix: update the hardcoded path to dist/src/cascade/index.js and align the warning message so it no longer references the wrong location. Result: the primary check succeeds on the first try, no warning is printed, and grep -c "dist/cascade/index.js" bin/speclang returns 0.

Before (buggy bootstrap):

# bin/speclang (bootstrap block, ~lines 70-80)
ENTRY="${SCRIPT_DIR}/dist/cascade/index.js"          # WRONG: build emits under src/
if [ ! -f "$ENTRY" ]; then
  echo "warning: speclang entry not found at $ENTRY; trying alternate path" >&2
  ENTRY="${SCRIPT_DIR}/dist/src/cascade/index.js"     # line 78: already correct
fi

if [ ! -f "$ENTRY" ]; then
  echo "error: speclang build not found; run 'npm run build' first" >&2
  exit 1
fi

exec node "$ENTRY" "$@"

After (fixed):

# bin/speclang (bootstrap block)
ENTRY="${SCRIPT_DIR}/dist/src/cascade/index.js"       # correct compiled entry

if [ ! -f "$ENTRY" ]; then
  echo "error: speclang build not found at $ENTRY; run 'npm run build' first" >&2
  exit 1
fi

exec node "$ENTRY" "$@"

Key changes: 1. dist/cascade/index.js → dist/src/cascade/index.js (matches tsconfig outDir layout: dist/src/...) 2. Downgraded the false warning path to a real hard-fail only when the build is genuinely absent — no more "warning + success" contradiction 3. The duplicate fallback is gone; there is now exactly one canonical entry path (the one line 78 already used), eliminating the stale path entirely
