Comparative CLI probe reports false data loss — operand-order mismatch

Problem class: comparative-cli-probe-operand-order-mismatch One-line rule: before declaring a divergence, read the wrapper's own --help/descriptor for its operand order and pass each tool its own documented order; then re-run the arm whose failure started the investigation, not just the arm being debugged.

1. Symptom

A differential probe fed the same operand order to a repo wrapper and to its GNU reference. It printed FAIL diff3-disjoint-keeps-ours-edit. Inspection showed the conflict block's ours side carried the base line — looking exactly like the wrapper dropping the user's edit. The wrapper was correct: re-run with each tool's documented order, output is byte-identical to GNU diffutils 3.12.

tool documented order
GNU diff3 MYFILE OLDFILE YOURFILE → ours base theirs
toolsd diff3 (wrapper) <base> <ours> <theirs>

A single "neutral" order cannot be correct for both; one tool silently rotates base and ours.

2. Root-cause analysis

diff3 -m MYFILE OLDFILE YOURFILE merges the change OLDFILE → YOURFILE into MYFILE: MYFILE=ours, OLDFILE=base, YOURFILE=theirs. The wrapper toolsd diff3 base ours theirs internally runs diff3 -m ours base theirs.

A probe sharing (ours, base, theirs):

GNU:     diff3 -m ours base theirs        # correct by construction
wrapper: toolsd diff3 ours base theirs
             └─ internally ─► diff3 -m base ours theirs
                                      MYFILE=base  OLDFILE=ours  YOURFILE=theirs

The merge base is now ours, and the "ours" side is the real base, so the conflict renders base content on the ours side — the false "drops our edit". The same rotation creates a spurious conflict where GNU produced a clean disjoint merge.

Secondary traps: 1. printf eats \n in fixture bodies. printf '{"a":"x\ny"}' emits a real newline → invalid JSON. An error arm expecting rc=1 then passes vacuously. 2. An error-path assertion is only evidence if the surrounding success path passes. If the fixture is broken, you cannot distinguish a correct rejection from a broken harness.

3. The exact fix

Read the usage of the tool you are calling:

$ diff3 --help | sed -n '1,2p'
Usage: diff3 [OPTION]... MYFILE OLDFILE YOURFILE
$ toolsd diff3 --help      # or docs/reference.md
usage: toolsd diff3 <base> <ours> <theirs>

Encode each order in its own adapter so no call site can share one:

# GNU reference: MYFILE(ours) OLDFILE(base) YOURFILE(theirs)
run_gnu() { diff3 -m "$OURS" "$BASE" "$THEIRS"; }
# repo wrapper: <base> <ours> <theirs>
run_bin() { "$BIN" diff3 "$BASE" "$OURS" "$THEIRS"; }

Fixtures via quoted heredoc, never printf:

# WRONG: printf turns \n into a real newline -> invalid JSON
bad=$(printf '{"kind":"merge","msg":"x\ny"}')
# RIGHT
cat > fixture.json <<'EOF'
{"kind":"merge","msg":"x\ny"}
EOF

Pair every error arm with its success path:

assert_rc 0 mycmd valid.json     # success path must pass ...
assert_rc 1 mycmd broken.json    # ... before the error-path pass means anything

Reference fixed probe (probe_v2.sh):

#!/bin/sh
# Fixed probe: each tool receives its OWN documented operand order.
set -u
BIN=./bin/toolsd
pass=0; fail=0
check() { if [ "$2" = "$3" ]; then pass=$((pass+1)); echo "PASS $1";
  else fail=$((fail+1)); echo "FAIL $1"; printf '  expected: %s\n  actual:   %s\n' "$2" "$3"; fi; }
check_rc() { if [ "$2" = "$3" ]; then pass=$((pass+1)); echo "PASS $1";
  else fail=$((fail+1)); echo "FAIL $1 (expected rc=$2 got rc=$3)"; fi; }

run_gnu()  { diff3 -m ours.txt base.txt theirs.txt 2>/dev/null || true; }
run_bin()  { "$BIN" diff3 base.txt ours.txt theirs.txt 2>/dev/null || true; }

GNU_EXPECT='ALPHA-OURS
bravo
charlie
DELTA-THEIRS'
check diff3-gnu-keeps-ours-edit      "$GNU_EXPECT" "$(run_gnu)"
check diff3-wrapper-keeps-ours-edit  "$GNU_EXPECT" "$(run_bin)"
check diff3-byte-identical-vs-gnu    "$(run_gnu)"   "$(run_bin)"
cat > ours2.txt <<'X'
ALPHA-OURS
bravo
charlie
DELTA-THEIRS
X
check diff3-disjoint-keeps-both \
  "$(diff3 -m ours2.txt base.txt theirs.txt)" \
  "$("$BIN" diff3 base.txt ours2.txt theirs.txt)"
if "$BIN" diff3 base.txt ours.txt >/dev/null 2>&1; then rc=0; else rc=$?; fi
check_rc toolsd-diff3-rejects-bad-argcount 2 "$rc"
echo "--- v2: pass=$pass fail=$fail"
[ "$fail" -eq 0 ]

4. Verification

rm -rf /tmp/diff3-demo && mkdir -p /tmp/diff3-demo/bin && cd /tmp/diff3-demo
cat > base.txt <<'EOF'
alpha

charlie
delta
EOF
cat > ours.txt <<'EOF'
ALPHA-OURS
bravo
charlie
delta
EOF
cat > theirs.txt <<'EOF'
alpha
bravo
charlie
DELTA-THEIRS
EOF
cat > bin/toolsd <<'EOF'
#!/bin/sh
case "$1" in
  diff3)
    shift
    [ "$#" -eq 3 ] || { echo "usage: toolsd diff3 <base> <ours> <theirs>" >&2; exit 2; }
    base=$1; ours=$2; theirs=$3
    exec diff3 -m "$ours" "$base" "$theirs" ;;
  *) echo "toolsd: unknown command $1" >&2; exit 2;;
esac
EOF
chmod +x bin/toolsd

Reproduce the false read:

diff3 -m ours.txt base.txt theirs.txt            # clean: ALPHA-OURS ... DELTA-THEIRS
./bin/toolsd diff3 ours.txt base.txt theirs.txt  # wrapper rotates base/ours

Observed (GNU diffutils 3.12), exit 1:

<<<<<<< ours.txt
ALPHA-OURS
=======
alpha
>>>>>>> theirs.txt
bravo
charlie
DELTA-THEIRS

Confirm the fix:

./bin/toolsd diff3 base.txt ours.txt theirs.txt > /tmp/w.out
diff3 -m ours.txt base.txt theirs.txt           > /tmp/g.out
cmp -s /tmp/w.out /tmp/g.out && echo "BYTE-IDENTICAL"
# => BYTE-IDENTICAL (38 bytes)

Probe results:

FAIL diff3-disjoint-keeps-ours-edit        (v1, buggy shared order)
--- v1: pass=0 fail=2

PASS diff3-gnu-keeps-ours-edit
PASS diff3-wrapper-keeps-ours-edit
PASS diff3-byte-identical-vs-gnu
PASS diff3-disjoint-keeps-both
PASS toolsd-diff3-rejects-bad-argcount
--- v2: pass=5 fail=0

Secondary traps:

printf-built JSON:  INVALID          (printf emitted a real \n inside the string)
heredoc-built JSON: valid
error-path arm   (expect rc=1): PASS   # vacuous: fixture itself was invalid
success-path arm (expect rc=0): FAIL -> the error arm passed for the wrong reason

5. Checklist / rule

  • [ ] Read the usage block of the tool being called; copy its operand order verbatim.
  • [ ] Put each tool's order in its own adapter; never share one order across tools.
  • [ ] Build fixtures with quoted heredocs or checked-in files; never printf bodies with \n.
  • [ ] Every error-path assertion is paired with the success-path assertion around it.
  • [ ] After any probe fix, re-run the arm whose failure started the investigation.
  • [ ] Before filing a bug, prove divergence by comparing each tool under its documented order, byte-for-byte, including conflict bodies.
