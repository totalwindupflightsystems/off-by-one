Diagnosis

Root cause: append_board_event.py used open(path, "a") and wrote json.dumps(event) with no separator. Python's append mode does not insert a newline, so when the file's last line lacked a trailing \n, the new object was glued on: ...410...}{"id":411,...}. A later append then newline-terminated that line, so wc -l stayed plausible while a per-line json.loads silently dropped one event (Extra data).

Exact fix

  1. Detect — detect_jsonl.py: per-line json.loads sweep reporting line=, byte_offset=, msg, pos, and (for Extra data) the exact byte where the missing newline belongs, via JSONDecoder.raw_decode.
  2. Repair — repair_jsonl.py: only failing lines are rewritten. raw_decode walks the chain of back-to-back documents and inserts a real \n at each boundary, carrying every original byte over verbatim. Writes to a temp file + fsync + atomic os.replace, with a .bak. No whole-file json.loads/json.dumps round-trip. On the incident file this recovered all 411 rows.
  3. Prevent — append_board_event.py: BoardWriter opens a+b, takes an fcntl.flock, seeks to the tail, inserts \n if the last byte isn't one, then writes json_line + "\n" as a single locked write.
