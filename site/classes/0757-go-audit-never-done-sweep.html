The fix is the gate runner itself — a fresh-audit harness that derives every number from the environment and refuses to emit inherited state:

#!/usr/bin/env bash
# gates/fresh-sweep.sh — NEVER-DONE audit runner (no prior-tick state consumed)
set -euo pipefail
REPO_ROOT="${1:?usage: fresh-sweep.sh <repo-root>}"
cd "$REPO_ROOT"

# 1) Environment truth first — never assume the repo exists.
if [[ ! -d .git ]]; then
  echo "GATE env: no .git in $REPO_ROOT (exit 3: no auditable artifact)" >&2
  exit 3   # distinct from code failure (1) so callers classify, not conflate
fi
if [[ ! -f go.mod ]]; then
  echo "GATE env: no go.mod in $REPO_ROOT (exit 3)" >&2
  exit 3
fi

# 2) Gates run fresh on the module — each count produced now, not copied.
go build ./...            && echo "GATE build: PASS"
go vet ./...              && echo "GATE vet: PASS"
test -z "$(gofmt -l .)"   && echo "GATE fmt: PASS"
go mod verify             && echo "GATE mod verify: PASS"
go test ./...             && echo "GATE suite: PASS ($(go test ./... -count=1 | wc -l) lines)"
echo "GATE complete: all numbers derived this tick; CI failures re-checked as 0-step provisioning before classifying external."

The fix to the codebase is a no-op here: there is no module to patch. The only correct "code change" is the runner above plus honest triage — a gate that cannot execute because its input is absent must report exit 3, never a replayed prior count.
