What I did

I reproduced the failure in a scratch git repo and verified the remedy empirically, then documented it.

Root cause confirmed: The tier-1 arm ruff format --check $files is a file-level predicate. When a prior --no-verify commit leaves a file unformatted, every later commit touching that file fails the check regardless of the new change's quality — the unformatted bytes at base always fail. It's sticky and cannot be fixed by any content change.

Remedy verified: Two commits — 1. A style-only prerequisite: restore the drifted baseline, ruff format, prove ast.dump(parse(old)) == ast.dump(parse(new)) vs parent, commit. 2. The real fix reapplied on the formatted base.

Notable finding during verification: the intuitive git stash + format + stash pop approach conflicts (the stashed diff was generated against the unformatted base). The robust recipe preserves the desired final file content instead of the diff, avoiding the conflict.

Evidence captured in the doc: - Clean fix blocked with EXIT=1 before remedy. - AST equality vs parent: True. - Style diff is whitespace-only; fix diff is exactly the one-line semantic change. - Both commits pass the hook, and subsequent commits pass too. - History: <fix> → <style> → <drift> → <base>, mapped to auger 593acc8 + 0851846.

The document includes a reusable shell script, a minimal inline version, multi-file and accidental-commit variations, and prevention notes.
