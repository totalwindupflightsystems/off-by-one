Fixing a false INCOMPLETE judge verdict caused by generated-register drift and concurrent-suite state contention

Repo: dexdat/eduos.dexdat.com.co Broken commit: 94e8adc4 · Repair commit: 229998a8 · Judge verdict: a8cc7e76 (INCOMPLETE/FAIL)

1. Summary

gitreins task complete marked the task as complete on the canonical JSONL board, then exceeded the foreground timeout before the post-completion hook could regenerate the derived disposition register. The follow-up Tier‑1 judge read the stale register, saw completions on the board that were missing from the register, and returned INCOMPLETE/FAIL. In parallel, a second full-suite run was executing against the same shared state (auth sessions, FK-constrained fixtures, fixed timeouts), producing six unrelated red tests. The correct response is not to edit the judge's verdict or the failing tests: regenerate the derived artifact, prove synchronization with a focused test, and re-run the full suite without overlap to show the earlier red run was harness/state contention.

2. Root-cause analysis

2.1 Primary cause — derived register drift (the judge-blocking failure)

The GitReins governance model has two layers:

Layer Artifact Role
Source of truth docs/gitreins/board.jsonl Append-only canonical record of tasks/verdicts
Derived docs/gitreins/disposition-register.md Rendered register consumed by the judge

task complete writes a completion record to the JSONL board. The register is generated from the board, so if generation does not run (or is interrupted) the two disagree. The judge's Tier‑1 check compares the register against the board (or against the completed-task set) and reports INCOMPLETE — a false verdict with respect to the underlying task state, but a correct observation that the workspace is inconsistent.

2.2 Why generation never ran — foreground timeout

gitreins task complete performed the board write and then continued running inside the same foreground invocation (suite/hook), exceeding the harness timeout. The process was reaped after the board mutation but before the register regeneration/commit. Result: non-atomic completion. The board advanced; the derived register lagged by exactly the just-completed records.

2.3 The six unrelated failures — concurrent state contention

While the judge ran Tier‑1, another full-suite run was in flight. Those suites share mutable global state:

  • auth failures — shared token/session store overwritten or expired between sign-in and assertion;
  • foreign-key failures — parallel workers seeding/truncating the same relational fixtures;
  • timeouts — CPU/DB contention from two Vitest pools plus a single shared connection pool.

These are not dependency incompatibilities: the failing files do not touch the changed code, and the failures do not reproduce in isolation. They are the signature of overlapping test execution.

2.4 Verdict interpretation

The judge verdict a8cc7e76 is honest and must be preserved. It correctly flagged (a) a real derived-artifact drift and (b) a red suite captured under contention. The repair is to remove both causes and record independent evidence that the clean run passes, then re-evaluate — not to rewrite history.

Step 1 — Deterministic register generator with drift check

Create scripts/gitreins/sync-disposition-register.mjs:

#!/usr/bin/env node
// Regenerates the derived disposition register from the canonical JSONL board.
// Usage: node scripts/gitreins/sync-disposition-register.mjs [--check]
import { readFileSync, writeFileSync, existsSync } from "node:fs";
import { resolve } from "node:path";

const ROOT     = process.cwd();
const BOARD    = process.env.GITREINS_BOARD    ?? "docs/gitreins/board.jsonl";
const REGISTER = process.env.GITREINS_REGISTER ?? "docs/gitreins/disposition-register.md";
const CHECK    = process.argv.includes("--check");
const STATUS   = new Set(["todo", "in_progress", "blocked", "complete"]);

const parseBoard = (text) =>
  text.split("\n")
    .map((line, i) => [i + 1, line.trim()])
    .filter(([, l]) => l && !l.startsWith("#"))
    .map(([n, l]) => {
      try { return JSON.parse(l); }
      catch (e) { throw new Error(`${BOARD}:${n} invalid JSON: ${e.message}`); }
    });

const esc = (v) => String(v ?? "").replace(/\|/g, "\\|").replace(/\s*\n\s*/g, " ");
const key = (id) => String(id).replace(/\d+/g, (m) => m.padStart(8, "0"));

function render(records) {
  const rows = [...records].sort((a, b) => key(a.id).localeCompare(key(b.id)));
  const count = (s) => rows.filter((r) => r.status === s).length;
  const out = [
    "# Disposition Register",
    "",
    "> GENERATED FILE — do not edit by hand. Regenerate with `pnpm gitreins:register`.",
    "",
    `Source of truth: \`${BOARD}\``,
    "",
    "## Summary",
    "",
    "| Status | Count |",
    "| --- | --- |",
    ...["todo", "in_progress", "blocked", "complete"].map((s) => `| ${s} | ${count(s)} |`),
    `| **total** | **${rows.length}** |`,
    "",
    "## Dispositions",
    "",
    "| ID | Title | Status | Owner | Completed | Commit | Verdict |",
    "| --- | --- | --- | --- | --- | --- | --- |",
  ];
  for (const r of rows) {
    out.push(`| ${esc(r.id)} | ${esc(r.title)} | ${esc(r.status)} | ${esc(r.owner)} | ${esc(r.completedAt)} | ${esc(r.commit)} | ${esc(r.verdict)} |`);
  }
  out.push("");
  return out.join("\n");
}

const records = parseBoard(readFileSync(resolve(ROOT, BOARD), "utf8"));
records.forEach((r, i) => {
  if (!r.id) throw new Error(`board record ${i + 1} missing "id"`);
  if (!STATUS.has(r.status)) throw new Error(`board record ${i + 1} (${r.id}) invalid status "${r.status}"`);
});
const expected = render(records);
const target   = resolve(ROOT, REGISTER);
const actual   = existsSync(target) ? readFileSync(target, "utf8") : "";

if (CHECK) {
  if (expected !== actual) {
    const a = actual.split("\n");
    const b = expected.split("\n");
    let line = 0;
    for (let i = 0; i < Math.max(a.length, b.length); i++) {
      if (a[i] !== b[i]) { line = i + 1; break; }
    }
    console.error(`[disposition-register] DRIFT: ${REGISTER} is out of sync with ${BOARD}`);
    console.error(`  line ${line}:\n  - ${a[line - 1] ?? "<missing>"}\n  + ${b[line - 1] ?? "<missing>"}`);
    process.exit(1);
  }
  console.log(`[disposition-register] OK (${records.length} dispositions, in sync with ${BOARD})`);
} else {
  writeFileSync(target, expected, "utf8");
  console.log(`[disposition-register] wrote ${REGISTER} (${records.length} dispositions)`);
}

Add the wire-up scripts to the root package.json:

{
  "scripts": {
    "gitreins:register": "node scripts/gitreins/sync-disposition-register.mjs",
    "gitreins:register:check": "node scripts/gitreins/sync-disposition-register.mjs --check"
  }
}

Step 4 — Eliminate suite overlap (lock + serialize)

Create scripts/gitreins/run-suite.sh:

#!/usr/bin/env bash
# Runs the full monorepo suite with overlap protection.
set -euo pipefail

LOCK="${TMPDIR:-/tmp}/gitreins-full-suite.lock"
exec 9>"$LOCK"
if ! flock -n 9; then
  echo "[gitreins] another full-suite run owns $LOCK; refusing to overlap" >&2
  exit 75
fi

# Refuse if orphaned Vitest workers are still alive (previous timed-out run).
if pgrep -af "vitest" | grep -v "run-suite.sh" | grep -q .; then
  echo "[gitreins] stray vitest processes detected; refusing to overlap:" >&2
  pgrep -af "vitest" >&2
  exit 75
fi

# Workspaces sequentially; files sequentially inside each workspace to protect shared DB.
pnpm -r --workspace-concurrency=1 test -- --no-file-parallelism

chmod +x scripts/gitreins/run-suite.sh

Step 5 — Make completion atomic (prevent recurrence)

Change gitreins task complete so the board write, register regeneration, and commit happen before returning, while heavy suites run out-of-band:
