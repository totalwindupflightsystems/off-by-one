The deliverable:

Fix: Disposition register stale after foreman board appends (gitreins tier1)

Problem class: eduos-disposition-register-stale-after-board-appends

TL;DR (exact order)

cd "$(git rev-parse --show-toplevel)"

# 0. Board appends/flips are FINISHED. Do not touch tasks.jsonl after this.
# 1. Regenerate the register appendix from the board
python3 scripts/gen-disposition-register.py --write

# 2. Prove sync (must print exactly: validation: OK)
python3 scripts/gen-disposition-register.py --validate

# 3. Commit board AND register together
git add .coding-hermes/board/tasks.jsonl \
        docs/governance/beta-risk-and-feature-disposition-register.md
git commit -m "chore(board): regenerate disposition register for EDU-GAP-050/051/052"

# 4. Only now launch the judge / tier1

If step 2 does not print validation: OK, stop — do not commit, do not run the judge.

Root cause

.coding-hermes/board/tasks.jsonl is the append-only source of truth. The register docs/governance/beta-risk-and-feature-disposition-register.md embeds a derived appendix between generated-block markers. scripts/gen-disposition-register.py --validate regenerates in memory and diffs against on-disk; --write rewrites the block.

A stand-in PM cycle appended EDU-GAP-050/051/052 (and/or flipped rows) but the register was not regenerated. Validation therefore exited 1, and apps/api/test/release-gate-matrix.test.mjs:106:42 (expect(result.status, result.stderr).toBe(0)) fails. Because the failure is a subprocess assertion over a generated-vs-on-disk comparison, tier1 shows the exit code with little/no diff context. The register is committed, so the judge re-fails on every run until it is regenerated and committed. The worker's board commit alone is insufficient.

The trap

Do not debug --validate with scripts/release-gate-matrix.mjs — that is the gate-matrix generator and causes gate-matrix.json/gate-matrix.md timestamp churn. Recover with:

git restore docs/governance/gate-matrix.json docs/governance/gate-matrix.md

Only scripts/gen-disposition-register.py knows --validate/--write.

Verification

  • Primary (mirrors failing test): bash pnpm --filter @eduos/api exec vitest run test/release-gate-matrix.test.mjs --no-file-parallelism Required: 8/8 passed.

  • Idempotency: second --write → register: already up to date, then --validate → validation: OK.
  • pnpm -r run test (full tier1 equivalent) green, and git status --short shows no gate-matrix churn.
