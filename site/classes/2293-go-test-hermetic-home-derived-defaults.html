Fix: go test reads live user state via HOME-derived default corpus dir

Repo: get-h3/logsey · Commit: fefe048 · Files: internal/cli/cli_test.go, internal/cli/sources_cmd_test.go

Symptom

--- FAIL: TestSourcesListAgainstEmptyCorpusDir: empty corpus dir must list zero honestly: registered sources: 3

Passes on a clean CI runner, fails on a multi-user host with real ~/.local/share/logsey state. -count=1 makes it deterministic — it is flaky by environment, not over time.

Root-cause analysis

  1. Corpus/state dir resolution honors an explicit override, then falls through to a HOME-derived default:

LOGSEY_CORPUS_DIR -> XDG_DATA_HOME/logsey -> ~/.local/share/logsey

The last hop comes from os.UserHomeDir(), not from the package env hook.

  1. The CLI tests install a neutral stub:

go Getenv = func(string) string { return "" }

This neutralizes LOGSEY_CORPUS_DIR/XDG_DATA_HOME, but os.UserHomeDir() is not routed through the hook, so resolution falls through to the real default — the live user's ~/.local/share/logsey.

  1. TestSourcesListAgainstEmptyCorpusDir then reads the real sources.json and counts 3 sources instead of 0.

The bug is test hermeticity, not production resolution.

Exact fix

Pin the app-specific override inside the same Getenv stub; keep empty returns for everything else.

internal/cli/cli_test.go

package cli

import "testing"

// stubEmptyEnv neutralizes unrelated environment lookups while pinning the
// app-specific corpus override to a throwaway directory. HOME-derived defaults
// (os.UserHomeDir) are not controlled by the Getenv hook, so leaving
// LOGSEY_CORPUS_DIR unset would let tests read the live user's real state.
func stubEmptyEnv(t *testing.T) string {
    t.Helper()
    dir := t.TempDir()

    old := Getenv
    Getenv = func(key string) string {
        if key == "LOGSEY_CORPUS_DIR" {
            return dir
        }
        return ""
    }
    t.Cleanup(func() { Getenv = old })

    return dir
}

internal/cli/sources_cmd_test.go

package cli

import "testing"

func TestSourcesListAgainstEmptyCorpusDir(t *testing.T) {
    dir := stubEmptyEnv(t)

    got, err := CorpusDir()
    if err != nil {
        t.Fatalf("resolve corpus dir: %v", err)
    }
    if got != dir {
        t.Fatalf("corpus dir resolution must honor the stubbed override: got %q want %q", got, dir)
    }

    sources, err := ListSources(got)
    if err != nil {
        t.Fatalf("list sources: %v", err)
    }
    if len(sources) != 0 {
        t.Fatalf("empty corpus dir must list zero honestly: registered sources: %d", len(sources))
    }
}

Notes: - t.Setenv("LOGSEY_CORPUS_DIR", ...) alone is not sufficient — the test replaces Getenv entirely, so os.Getenv is never consulted. The override must live in the stub (or the stub must fall back to os.Getenv). - The assertion got == dir proves the override is actually being exercised.

Verification (pre-existing vs merge-introduced)

# 1. Reproduce with live state present.
mkdir -p "$HOME/.local/share/logsey"
printf '{"sources":["live-a","live-b","live-c"]}' > "$HOME/.local/share/logsey/sources.json"
go test ./internal/cli/ -run TestSourcesListAgainstEmptyCorpusDir -count=1 -v
# -> FAIL: registered sources: 3

# 2. Run the same test on a tree WITHOUT the suspect change.
git worktree add /tmp/logsey-parent fefe048^
(cd /tmp/logsey-parent && go test ./internal/cli/ -run TestSourcesListAgainstEmptyCorpusDir -count=1)
# -> "no test files": the test/stub did not exist before the merge, so the failure is
#    merge-introduced by the neutral test stub, not a pre-existing production bug.
git worktree remove /tmp/logsey-parent --force

# 3. Apply the fix, then re-run under every environment.
go test ./internal/cli/ -run TestSourcesListAgainstEmptyCorpusDir -count=1 -v   # PASS (live state present)
rm -rf "$HOME/.local/share/logsey"
go test ./... -count=1                                                          # PASS (clean runner)
mkdir -p /tmp/otherhome/.local/share/logsey
printf '{"sources":["x","y"]}' > /tmp/otherhome/.local/share/logsey/sources.json
HOME=/tmp/otherhome go test ./... -count=1                                      # PASS (different live state)

My reproduction confirmed all four outcomes: FAIL with the neutral stub → [no test files] on the parent tree → PASS after the fix with 3 live sources, with 0, and with 2 under a different HOME.

One-line summary

Tests replaced Getenv with a blanket empty function; that cannot neutralize the os.UserHomeDir() default, so corpus resolution fell through to the real ~/.local/share/logsey. Stub LOGSEY_CORPUS_DIR to t.TempDir() inside the same Getenv stub so resolution lands on a throwaway dir.
