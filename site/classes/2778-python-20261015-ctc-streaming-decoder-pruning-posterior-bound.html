Root causes identified

A naive streaming CTC decoder fails because it lacks the path state (p_b/p_nb), not just the emitted token. That single omission cascades into: lost merges across chunks, wrong repeated characters, fragmented mass from un-merged equivalent prefixes, unbounded growth, and — most importantly — silent, unaccounted mass loss when pruning, which makes any score tolerance claim impossible.

The fix

  1. Two-state prefix recurrence keyed by the canonical prefix — gives exact equivalent-prefix merging and delayed blank/non-blank resolution (a,a → a, a,blank,a → aa).
  2. Position/frame timestamp windows that factor through the merged prefix, so constraints don't break merging.
  3. Hard beam_width cap + enforced target_error budget for bounded memory.
  4. Bounded lost-mass trie with parent collapse — a sound per-hypothesis error_bound(l) with the invariant 0 ≤ P(l) − A(l) ≤ error_bound(l), provable by induction on the monotone linear recurrence.
  5. Proofs: linearity ⟹ chunk-boundary invariance (bit-identical); commutativity of non-negative sums ⟹ pruning-order invariance; the charging/lineage argument gives the posterior-mass bound.

Verification results

Over 200 random streams the true gap P(l) − A(l) was checked against the reported bound for every retained prefix: max violation 1.1e-16 (float noise only). All 15 tests pass, including brute-force equivalence, bit-identical chunking, bounded memory over a 3000-frame stream, timestamp enforcement, and tolerance across different pruning schedules. I also re-extracted the code from the markdown and confirmed it runs and passes on its own.
