Raft Snapshot Linearizability Fence

Problem class: go-raft-snapshot-linearizability-fence-20261102 · Go 1.26

Guarantee proven: a read served at readIndex R reflects every committed entry through at least R, and once the machine reaches R it can never regress below R — even if a snapshot at S ≤ R installs afterwards, an Apply is delayed/reordered, a membership change occurs, or the process restarts.

Root-cause analysis

Linearizable reads have two obligations: (1) confirmation — heartbeat quorum under the configuration committed at the read index; (2) freshness/fence — a monotonic, truthful applied watermark. The bug class is getting (2) wrong. I reproduced five failure modes:

# Failure Effect
F1 lastApplied = S set before InstallSnapshot read at R=S returns pre-snapshot state
F2 Delayed/reordered Apply at i ≤ S applied unconditionally machine rolls back below S while watermark stays S
F3 Late snapshot guarded against lastSnapshotIndex instead of the applied watermark snapshot overwrites already-applied newer state
F4 On restart watermark starts at 0 / reads served before replay read above snapshot boundary sees empty/partial state
F5 Quorum computed from an appended but uncommitted config two disjoint quorums → two leaders serve reads

F3 was a genuine subtlety my own test caught: comparing a late snapshot against the last snapshot boundary is insufficient once commands have been applied past it.

Exact fix — the fence

Single-writer apply loop with four invariants: mutate-then-publish, drop anything ≤ F, install+advance atomically, restart from LastIncludedIndex. Core code:

// Fence is a monotonic watermark of the highest index visible in the machine.
func (f *Fence) Wait(idx uint64) {
    f.mu.Lock()
    for f.applied < idx { f.cond.Wait() }
    f.mu.Unlock()
}
func (f *Fence) Advance(idx uint64) {
    f.mu.Lock()
    if idx > f.applied { f.applied = idx; f.cond.Broadcast() }
    f.mu.Unlock()
}

// The ONLY goroutine that mutates the state machine.
func (n *Node) apply(msg ApplyMsg) {
    switch {
    case msg.SnapshotValid:
        if msg.SnapshotIndex <= n.fence.Applied() { return } // F3: compare to watermark
        n.machine.InstallSnapshot(msg.Snapshot)              // F1: mutate first...
        n.fence.Advance(msg.SnapshotIndex)                   // ...publish second
        n.snapshotIndex, n.snapshotTerm = msg.SnapshotIndex, msg.SnapshotTerm
    case msg.CommandValid:
        if msg.CommandIndex <= n.fence.Applied() { return }  // F2: drop delayed Apply
        n.machine.ApplyCommand(msg.Command)
        n.fence.Advance(msg.CommandIndex)
    }
}

// Linearizable read: obtain readIndex via ReadIndex, then fence.
func (n *Node) Read(readIndex uint64, key string) (string, bool) {
    n.fence.Wait(readIndex)
    return n.machine.Get(key)
}

Raft integration: - InstallSnapshot handler: reject if Term stale or LastIncludedIndex <= commitIndex; persist snapshot+state atomically; set commitIndex = max(commitIndex, LastIncludedIndex); hand the snapshot to the service via the same applyCh. Never touch the service watermark here. - ReadIndex: heartbeat quorum under committedConfig() (never a pending config), returns commitIndex. - Get: idx := rf.ReadIndex(); fence.Wait(idx); get(key). - Snapshot payload: includes KV and the committed configuration, so a follower adopts the correct voter set atomically (F5). - Recovery: load snapshot → restore machine → F = LastIncludedIndex → replay only > F.
