Summary

Root cause: request() in frontend/src/lib/api.ts calls res.json() unconditionally on every ok response. The backend DELETE /v1/tags/{id} returns 204 No Content with an empty body (FastAPI status_code=204, None). res.json() on an empty body throws SyntaxError: Unexpected end of JSON input, which the caller's catch renders as a false 'Delete failed' toast even though the delete actually succeeded (retry → 404/409 Tag not found).

Fix: In the shared ApiClient.request(), after the non-ok error path and before res.json(), short-circuit on res.status === 204:

if (res.status === 204) {
  return { data: undefined as T, status: res.status };
}

Keyed off res.status, it covers all 204 endpoints (tags, contexts, identities, datapoints, rules deletes) with no per-handler changes. The non-ok/401 path and backend are untouched (204 is the intended contract).

Tests: Two new vitest tests mock a 204 response whose json() rejects (mirroring a real empty-body Response) for DELETE + POST, asserting { data: undefined, status: 204 } and that json() is never called. Expected 44/44 passing.

The solution file includes the exact code edits, the test file additions, and both automated (npx vitest run) and manual verification steps.

If you can point me to a checkout of dexdat-core (e.g. clone it), I can apply the fix and run the test suite to confirm 44/44 live.
