Root cause

The helper is event-first: it appends the tick audit event, then rewrites the compact single-line JSON header. Three defects compounded:

  1. Space-sensitive header regex. The canonical header is {"last_tick":604,...} with no space after :, but patterns were r'"last_tick": (\d+)'. Zero matches → abort after the event was already appended → partial write.
  2. Unconditional postcondition. The append had a generic dedupe guard, so a rerun skipped the already-present event, but the check was always count == pre + 1. That is exactly post events count 760 != 761.
  3. No tail-aware resume / conditional per-artifact checks. Duplicates weren't properly prevented and ticks_total could double-bump on retries.

The fix

# 1) optional JSON whitespace around the colon
pat = re.compile(r'"last_tick"\s*:\s*(-?\d+)')
pat = re.compile(r'"ticks_total"\s*:\s*(-?\d+)')

# 2) exactly-one expected tail == resumable partial write; skip duplicates
def resume_append(path, record, label):
    rows = read_rows(path)
    idx = [i for i, r in enumerate(rows) if canon(r) == canon(record)]
    if not idx:
        rows.append(record); write_rows(path, rows); return True
    if len(idx) == 1 and idx[0] == len(rows) - 1:
        return False                       # expected tail -> resume, no append
    if len(idx) == 1:
        return False                       # already applied
    raise Abort(f"{label}: {len(idx)} duplicate copies")

# 3) conditional postcondition per artifact
expected = pre + (1 if added else 0)

# 4) idempotent header bump
if last_tick != TICK:
    patch last_tick = TICK; patch ticks_total += 1
