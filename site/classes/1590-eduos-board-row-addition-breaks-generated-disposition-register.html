Fix: board mutation leaves generated disposition register stale

Problem class: eduos-board-row-addition-breaks-generated-disposition-register Repo: dexdat/eduos.dexdat.com.co · Branch: Beta · Area: apps/api Failing test: apps/api/test/release-gate-matrix.test.mjs > BETA-110 release gate matrix > keeps the generated disposition register synchronized with canonical board events

1. Symptom

After a new canonical task row is appended to the board:

.coding-hermes/board/tasks.jsonl      # e.g. A11Y-LOGIN-001

the API release-gate matrix fails:

validation failed: generated appendix differs from register
(register lacks the new task row's appendix section)

and the suite summary is 1 failed / 2969 passed / 34 skipped. The failing assertion spawns python3 scripts/gen-disposition-register.py --validate and expects exit code 0 with stdout containing validation: OK.

2. Root-cause analysis

docs/governance/beta-risk-and-feature-disposition-register.md is a generated artifact, not hand-maintained. Its appendix is rendered by scripts/gen-disposition-register.py from the canonical board events in .coding-hermes/board/tasks.jsonl, grouping task IDs by prefix (a new A11Y-LOGIN-001 row produces a new ### Other - A11Y section).

The generator has two modes:

Mode Behavior
--write Re-renders the register from the current .jsonl and overwrites the markdown.
--validate Re-renders in memory and byte-compares to the committed markdown; non-zero exit + validation failed: ... on drift.

A board mutation (task_created row, task completion row, ID/prefix change) changes the generator's output. Because the markdown is committed, the tree and CI keep the old register until regenerated. The test finds the diff (missing ### Other - A11Y) and fails.

This is purely a generated-artifact sync bug — the underlying task work is correct. The dangerous interaction is with the GitReins judge:

  • tier1 runs the root suite / register check → FAIL (stale register)
  • tier2 passes
  • Result: Overall FAIL for a correct task

Invariant: every change to .coding-hermes/board/tasks.jsonl must be accompanied (same commit or the immediately following commit) by a regenerated register, and both pushed before the judge runs.

3. Exact fix

cd "$(git rev-parse --show-toplevel)"

# 1. Reproduce the drift (optional)
python3 scripts/gen-disposition-register.py --validate
# -> non-zero: validation failed: generated appendix differs from register

# 2. Regenerate the register from canonical board events
python3 scripts/gen-disposition-register.py --write

# 3. Confirm the generator accepts its own output
python3 scripts/gen-disposition-register.py --validate
# -> expected: validation: OK; tasks: N

# 4. Inspect the diff: only the new appendix section(s), e.g. "### Other - A11Y"
git diff --stat docs/governance/beta-risk-and-feature-disposition-register.md
git diff      docs/governance/beta-risk-and-feature-disposition-register.md

# 5. Stage the regenerated register (and board row if not yet committed)
git add docs/governance/beta-risk-and-feature-disposition-register.md
# git add .coding-hermes/board/tasks.jsonl   # if step 2 preceded the board commit

Commit (remedy commit)

Use the repo's governance form and the required co-author trailer. Copy the exact trailer from the last governance commit instead of guessing:

git log --format='%H %s' --grep='chore(governance)' -n 5
git log -1 --format='%B' --grep='chore(governance)'

git commit -m "chore(governance): refresh disposition register for A11Y-LOGIN-001" \
  -m "Co-authored-by: <agent-name> <agent@users.noreply.github.com>"

Replace <...> with the identity GitReins expects. Do not omit the trailer.

Push before judging

git push origin Beta

Order matters: regenerate → commit → push → then run the GitReins judge.

5. Prevent recurrence

5.1 Canonical refresh helper — scripts/refresh-disposition-register.sh

#!/usr/bin/env bash
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"
python3 scripts/gen-disposition-register.py --write
python3 scripts/gen-disposition-register.py --validate
git add .coding-hermes/board/tasks.jsonl \
        docs/governance/beta-risk-and-feature-disposition-register.md
echo 'Register refreshed. Commit with:'
echo '  git commit -m "chore(governance): refresh disposition register for <task-id>"'

5.2 Pre-commit guard — .githooks/pre-commit

#!/usr/bin/env sh
set -eu
if git diff --cached --name-only | grep -qx '.coding-hermes/board/tasks.jsonl'; then
  if ! python3 scripts/gen-disposition-register.py --validate >/dev/null 2>&1; then
    echo '[pre-commit] disposition register out of date; regenerating...'
    python3 scripts/gen-disposition-register.py --write
    git add docs/governance/beta-risk-and-feature-disposition-register.md
  fi
  python3 scripts/gen-disposition-register.py --validate
fi

chmod +x .githooks/pre-commit
git config core.hooksPath .githooks

5.3 CI hard gate

- name: Disposition register is in sync with the board
  run: python3 scripts/gen-disposition-register.py --validate

6. Quick reference

cd "$(git rev-parse --show-toplevel)" \
  && python3 scripts/gen-disposition-register.py --write \
  && python3 scripts/gen-disposition-register.py --validate \
  && git add docs/governance/beta-risk-and-feature-disposition-register.md .coding-hermes/board/tasks.jsonl \
  && git commit -m "chore(governance): refresh disposition register for <task-id>" \
                -m "Co-authored-by: <agent-name> <agent@users.noreply.github.com>" \
  && git push origin Beta
# expected validate output: validation: OK; tasks: N

Golden rule: never leave a board mutation as the last commit — regenerate and push the register in the same or the very next commit, before the judge.
