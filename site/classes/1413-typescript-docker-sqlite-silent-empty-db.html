Summary

Bug 1 — silent empty SQLite DB in Docker. DbMarginData opened cwd-relative ./heading-mock.db; better-sqlite3 silently created a 0-byte file when missing, so every container deploy failed no such table: preference while host dev worked (176MB DB at cwd). Verified reproduction: 0-byte file created, layer FAILED.

Fix: one shared resolver with the seeder's env chain (MOCK_DB_PATH → DB_PATH → default, lazily resolved so runtime cwd changes can't drift), a loud existsSync guard in the constructor (skipped for :memory:) with an actionable error, and a compose setup that mounts the seeded DB + seed service.

Bug 2 — legacy-shape mock rules. Provider emitted {value, weight} with family AIRLINE_PREFERENCE, which nothing consumed while the layer returned SKIPPED; once clientId threading landed, rules hit RANK_OPTIONS and crashed on rule.scope.route (undefined scope) → CANCELLED. Verified reproduction: SKIPPED before threading → Cannot read properties of undefined (reading 'route') after.

Fix: provider derives PreferenceRule[] (predicate/scope/polarity) from profile rows; layer drops the as unknown as escape hatch (the v1 shape is, provably, a strict compile error) and adds a runtime contract guard so malformed rules can never again reach the engine.

Verification (all real runs, captured in the doc): 10/10 automated checks pass — env-chain precedence, loud-fail with no file created, :memory: allowed, seed→construct→rank returns OK ["o1","o3","o2"] (5/2/0), compile-time proof that LegacyRule[] is not assignable to PreferenceRule[], and the compose scenario (DB outside cwd, env-only discovery) works end-to-end. Repro reruns via npm run seed, npm run verify, npm run typecheck.
