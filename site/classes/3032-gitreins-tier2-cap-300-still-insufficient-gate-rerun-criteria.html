The complete markdown:

helios-425 recovery audit: cap-artifact INCOMPLETE is not a gate failure

Problem class: gitreins-tier2-cap-300-still-insufficient-gate-rerun-criteria Environment: linux, gitreins 0.15.x, hermes api_server Task: helios-425-recovery (repo helios-work), tier-2 async judge Evidence: caps 150 and 300 both exhausted; progressive partial verification (run 3 reached event 751 + manifest closed + header last_commit before dying); verdicts 21b5706b-class, 6ee29cc3, 98435097.

TL;DR

Two independent defects were conflated:

  1. Authoring defect. The recovery-audit criterion asked the judge to re-execute the release gate (go 76/76 and vitest 64/64). A judge loop is the wrong place for a full gate re-run — it is unbounded relative to any iteration cap, so raising the cap from 150 to 300 only moves the cliff.
  2. Verdict-semantics defect (gitreins 0.15.x). When the cap fired, every criterion the run never reached was written status="FAIL" with detail "Not verified", and all three renderers (judge.py, pipeline.py, persist.py) folded any non-PASS status to ✗. The cap artifact therefore looked exactly like a merit failure.

The fix is not a bigger cap. It is:

  • Move the gate re-run to foreman-side evidence and phrase the audit criteria as cheap record-existence checks (event id present, manifest finished_at set, merge-base output captured).
  • Make the judge distinguish "not examined" from "failed": introduce status="UNVERIFIED" and a single item_glyph() renderer (PASS ✓, FAIL ✗, everything else —). It still fails closed — a partial verdict is INCOMPLETE unless every item is PASS.
  • Accept the cap-artifact INCOMPLETE only when the checklist advances each run and every item is PASS-or-not-yet, never FAIL.
  • Check tasks.yaml first: gitreins task complete flips the task to status: complete before it calls the judge, so a judge killed by the tool timeout does not lose the flip.

Upstream reference: gitreins commit ad4844b ("an unexamined criterion is not a failed one — status UNVERIFIED and a — mark", addresses DF-CRIER-462, measured on DF-CRIER-461 run 68649f1e), first shipped in gitreins 0.17.1.

Root-cause analysis

1. The criterion asked the judge to re-run the whole gate

The tier-2 judge (engine/evaluator.py) is an agentic loop. Each LLM turn costs 1.0 iteration credit and each tool call costs tool_call_weight (default 0.1). A criterion that shells out to the full Go and Vitest suites makes the judge spend its entire budget inside one criterion. The loop is capped by EvalCap (GITREINS_MAX_ITERATIONS), so at 150 it dies mid-criterion and at 300 it dies mid-criterion later. The cap is not the variable; the per-iteration cost of the criterion is.

2. The cap artifact lied about unreached criteria

AgenticEvaluator._extract_partial_verdict() in 0.15.x marked unreached criteria status="FAIL" / "Not verified", and every renderer hard-coded "✓" if ... == "PASS" else "✗". The cap-hit checklist printed ✓ criterion 1 / ✗ criterion 2 — indistinguishable from an examined-and-false criterion. Any acceptance rule keyed on "no FAIL" rejects the artifact even though nothing failed.

3. The task flip already happened

gitreins task complete <id> calls TaskManager.complete() (writes status: complete + completed_at) before it constructs the judge. A judge killed by the tool timeout leaves a complete task with an INCOMPLETE verdict. Always read .gitreins/tasks.yaml before concluding the flip was lost.

The exact fix

A. Rewrite the audit criteria as record-existence checks (foreman-side gates)

Before (unbounded, judge-side re-run):

tasks:
  - id: helios-425-recovery
    title: helios tick 425 recovery audit
    criteria:
      - "Re-run go test ./... and confirm 76/76 pass"
      - "Re-run npx vitest run and confirm 64/64 pass"
      - "Confirm the recovery completed"

After (bounded record-existence, foreman-side evidence):

tasks:
  - id: helios-425-recovery
    title: helios tick 425 recovery audit
    criteria:
      - "Recovery event id 751 is present in .coding-hermes/board/events.jsonl"
      - "Recovery manifest exists and has a non-empty finished_at"
      - "Foreman evidence file records the merge-base output for the recovery commit"
      - "Evidence header last_commit equals the commit in the manifest/event"

Foreman writes the gate result once, next to the recovery artifacts:

// .coding-hermes/evidence/helios-425-recovery.json
{
  "task": "helios-425-recovery",
  "event_id": 751,
  "commit": "<recovery-commit-sha>",
  "merge_base": "<git merge-base output sha>",
  "manifest": ".coding-hermes/recovery/manifest.json",
  "manifest_finished_at": "2026-10-28T21:00:00Z",
  "gates": {
    "go":     {"cmd": "go test ./...",   "passed": 76, "total": 76, "exit_code": 0},
    "vitest": {"cmd": "npx vitest run",  "passed": 64, "total": 64, "exit_code": 0}
  }
}

The judge now only needs read_file(evidence), search_pattern("751", events.jsonl), read_file(manifest.json) — a bounded checklist that fits in any cap.

C. Acceptance rule for a cap-artifact INCOMPLETE

Accept a cap-hit INCOMPLETE iff:

  1. verdict == "INCOMPLETE" and the summary names a cap.
  2. No item is FAIL — every item is PASS or UNVERIFIED.
  3. The checklist advanced vs the previous run (at least one new PASS).
#!/usr/bin/env python3
"""Accept a cap-artifact INCOMPLETE only when it advances and nothing FAILed."""
import json, sys

CAP_MARKERS = ("Cap exceeded", "Iteration cap", "Time cap", "resource cap", "token budget")

def load(p):
    with open(p, encoding="utf-8") as fh:
        return json.load(fh)

def statuses(doc):
    return [(i.get("criterion", "?"), (i.get("status") or "").upper())
            for i in doc.get("items", [])]

def is_cap_artifact(doc):
    return ((doc.get("verdict") or "").upper() == "INCOMPLETE"
            and any(m in (doc.get("summary") or "") for m in CAP_MARKERS))

def main():
    if len(sys.argv) != 3:
        print(__doc__); return 2
    prev, cur = load(sys.argv[1]), load(sys.argv[2])
    cur_statuses = statuses(cur)
    if not is_cap_artifact(cur):
        print("REJECT: not a cap-artifact INCOMPLETE"); return 1
    fails = [c for c, s in cur_statuses if s == "FAIL"]
    if fails:
        print(f"REJECT: FAIL item(s): {fails}"); return 1
    bad = [(c, s) for c, s in cur_statuses if s not in {"PASS", "UNVERIFIED"}]
    if bad:
        print(f"REJECT: neither PASS nor UNVERIFIED: {bad}"); return 1
    prev_pass = {c for c, s in statuses(prev) if s == "PASS"}
    cur_pass  = {c for c, s in statuses(cur)  if s == "PASS"}
    if not (cur_pass - prev_pass):
        print("REJECT: checklist did not advance"); return 1
    print(f"ACCEPT: cap artifact; advanced {sorted(prev_pass)} -> {sorted(cur_pass)}")
    return 0

if __name__ == "__main__":
    sys.exit(main())
