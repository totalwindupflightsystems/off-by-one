Diagnosis

The task is to implement GPTQ/OBQ error-compensated quantization plus a per-output-group clipping-scale search. The real failure modes (all reproduced in demo.py):

# Root cause Symptom
R1 No inverse-Hessian error propagation avoidable reconstruction error vs RTN
R2 Bare inv(H) on a PSD/rank-deficient Hessian LinAlgError or garbage
R3 [Hinv]_jj → 0 for dead inputs inf/NaN contaminating later columns
R4 Fixed scale = max|w|/maxq clipping/rounding trade-off not optimized
R5 (d_row,) scale vs (d_row,1) column broadcasting silent (d_row,d_row) corruption
R6 Assuming greedy always beats RTN false verification failures

Fix (in gptq_obq.py, embedded verbatim in the markdown)

  • damped_inverse — scale-aware ridge damp·mean(diag(H)), Cholesky inverse with pinv fallback, plus a dead-column mask (diag ≤ 1e-10·mean_diag).
  • gptq_quantize — left-to-right update W[:,k] -= (e/[Hinv]_jj)·[Hinv]_jk, guarded: dead or |[Hinv]_jj|<1e-14 columns are quantized without propagation (skipped_columns).
  • gptq_scale_search — for each output row group, sweep clip factors alpha, run GPTQ, and keep the alpha minimizing exact hessian_loss; falls back to alpha=1 by construction.
  • build_hessian — sums per-input-block activations (X Xᵀ) or precomputed Hessians.

Verification

  • 15/15 pytest tests pass, including exact equality with an independent from-scratch Schur-complement OBQ reference (max|Wq−Wref| = 0), analytic single-column optimality by random perturbation, dead/all-zero/rank-deficient Hessian safety, and scale-search monotonicity.
  • Demo shows ~5–8% Hessian-loss reduction over RTN across bit widths, the naive pinv update producing NaN while the guarded path stays finite, and the scale search lowering loss (13 613 → 13 032).
