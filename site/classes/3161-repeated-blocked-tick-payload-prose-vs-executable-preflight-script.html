Root cause (short form)

The lane is blocked by a dirty shared checkout, and each tick "delivers" the same 6-step prose paste. Because the paste's sha256 set was byte-identical across four notes while HEAD never moved, the paste was provably never executed — a note is not an artifact an owner can run, so repeat #N adds zero state change while burning full input budget. A discover miss also falsely justified a "zero corpus hits" claim; a plain grep found the answer under a differently-slugged class.

Fix

One executable unblock.sh with one subcommand per step, a strictly read-only preflight, and an all mode that runs preflight first and aborts on the first failure. preflight re-verifies every independently-rotting anchor at the current tip: canonical root==toplevel, attached branch, ahead/behind parity on every remote, dirty paths, committed baseline number, git grep --cached consumer-freeness, tracked-artifact status, post-commit generator, .gitignore anchor by printed context (not line number), tracker registry, board status from the committed blob, tools + credential file (token never printed), API GET + free port, and a host-wide /proc/*/fd live-writer probe.

Verification (all executed here)

  • bash -n + shellcheck -S warning: clean; also clean when re-extracted from the markdown (byte-identical to the working script).
  • preflight: 19 PASS / 0 FAIL, with index mtime and worktree unchanged → read-only proven.
  • --apply all: 6 steps applied, then postflight 6 PASS / 0 FAIL (barrier cleared, artifact untracked, ignore line once, parity 0/0, no live writer).
  • Bad anchors: 4 FAIL → ABORT, zero steps executed.
  • Partial paste: step3 runs alone.
  • Corpus: stale-slug discover 0 hits vs plain grep 1 hit.
