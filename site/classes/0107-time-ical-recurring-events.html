The implementation is in /home/kara/rrule_expander.py — a clean module that wraps Python's dateutil.rrule (which implements RFC 5545 Section 3.3.10) and adds full timezone, DST, and EXDATE support.

Core API — expand_rrule():

from datetime import datetime
from zoneinfo import ZoneInfo
from rrule_expander import expand_rrule, RecurrenceExpander

# Canonical problem: FREQ=WEEKLY;BYDAY=MO,WE;COUNT=10
occurrences = expand_rrule(
    "FREQ=WEEKLY;BYDAY=MO,WE;COUNT=10",
    dtstart=datetime(2025, 1, 1, 10, 0, 0),
)
# Result: 10 datetimes on Jan 1, 6, 8, 13, 15, 20, 22, 27, 29 and Feb 3

# Timezone-aware with exclusions
occurrences = expand_rrule(
    "FREQ=WEEKLY;BYDAY=MO,WE,FR;COUNT=12",
    dtstart=datetime(2025, 3, 3, 10, 0, 0, tzinfo=ZoneInfo("America/New_York")),
    exdates=[datetime(2025, 3, 10, 10, 0, 0, tzinfo=ZoneInfo("America/New_York"))],
)

# Or use the RecurrenceExpander class
expander = RecurrenceExpander(
    dtstart=datetime(2025, 3, 10, 9, 0, 0),
    rrule_str="FREQ=WEEKLY;BYDAY=MO,WE,FR;COUNT=10",
    tz_name="America/New_York",
    exdates=[datetime(2025, 3, 17, 9, 0, 0)],
)
for occ in expander.expand():
    print(occ)

Key design decisions:

  • Timezone handling: When a timezone name is provided (e.g., "America/New_York"), naive datetimes are localized using zoneinfo.ZoneInfo. Timezone-aware datetimes are normalized to the target zone. This ensures consistent UTC offsets throughout the recurrence set.

  • DST transitions: dateutil.rrule natively handles DST by computing occurrences in local time. When spring-forward occurs (e.g., 2:30 AM becomes 3:00 AM), dateutil adjusts automatically. Fall-back (1:30 AM occurring twice) yields a single unambiguous occurrence at the first (EDT) occurrence.

  • EXDATE exclusion: Excluded dates are normalized to match the timezone of dtstart. Exclusions match on the second-precision datetime (truncating microseconds), which aligns with how RFC 5545 EXDATE values are specified.

  • BYSETPOS / complex rules: dateutil.rrule fully supports BYSETPOS, BYMONTH, BYWEEKNO, BYEASTER, BYHOUR, BYMINUTE, BYSECOND, and all other RFC 5545 rule parts.

**Edge cases verified:**
1. **Spring-forward (2025-03-09)**: 2:30 AM doesn't exist → `dateutil` adjusts to the next valid time, producing a valid occurrence without crashing or skipping the day entirely.
2. **Fall-back (2025-11-02)**: 1:30 AM occurs twice → our expander produces exactly one occurrence, no duplication.
3. **Mixed timezone-aware/naive inputs**: Library raises clear errors when UNTIL is timezone-aware but DTSTART is naive (per RFC 5545).
4. **EXDATE at DST boundaries**: Excluding a date that crosses a DST boundary works correctly when both DTSTART and EXDATE are in the same timezone.
