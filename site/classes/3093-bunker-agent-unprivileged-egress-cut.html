What I diagnosed

  1. Root cause — the agent identity is unprivileged (uid=1001/1002, CapEff=0000000000000000). unshare -n returns EPERM, unshare -Urn is blocked by the host's restricted unprivileged-userns policy, and there's no CAP_NET_ADMIN for iptables/nft. So an in-agent battery can never establish its own egress cut.

  2. The real trap — bunker exec and non-detached bunker run are plain SSH sessions in the host netns (net:[4026531833], all 100 host links). Only system-scoped transient units created by bunkerd inherit PrivateNetwork=yes, i.e. bunker run --detach and the agent's dockerd unit.

  3. Fix — do the cut at spawn time: bunker spawn <id> --network-mode systemd, stage source + module cache, build offline, and run probes and suite together inside one bunker run --detach unit.

What I actually verified end-to-end

  • Spawned offline1 --network-mode systemd; bunker info reports the loopback-only systemd isolation.
  • Staged a tarball source tree and a pre-populated GOMODCACHE (24 MB) via bunker exec --stdin (byte-exact SHA-256; needed because bunker cp's scp was blocked by a world-writable /etc/ssh/ssh_config.d symlink).
  • Ran one detached unit (PrivateNetwork=yes, netns=net:[4026538780], only lo, no routes) that did:
  • GOPROXY=off GOFLAGS=-mod=mod GOMODCACHE=$HOME/gomodcache go build ./... → BUILD_OK
  • external probe → EXTERNAL_FAIL: ... network is unreachable
  • loopback probe → LOOPBACK_OK
  • go test ./... → ok example.com/offl
  • Negative control: same build with an empty cache fails with module lookup disabled by GOPROXY=off, proving staging is what makes it offline.
  • Cleaned up both test agents.
