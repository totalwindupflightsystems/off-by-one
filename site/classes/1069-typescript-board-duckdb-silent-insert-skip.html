Answer

Root cause. The per-tick append path ran without the duckdb-providing uv environment. The duckdb write degraded to a silent no-op (swallowed ImportError/insert error) while the plain-fs events.jsonl append — which can never fail — kept growing. Result: DB 270 vs JSONL 318 rows with max ids equal (323) — a middle-block gap (272–319) that a naive max-id-only parity check cannot see.

Three-part fix (implemented in /home/kara/ring-runner/):

1. Detect — board_jsonl_parity_probe.py. Compares row counts, full id sets, and ordered sequence gaps — never max id alone (the incident trap):

report = {
  "verdict": ..., "jsonl_rows": ..., "db_rows": ...,
  "max_ids_equal": max(jsonl_ids) == max(db_ids),   # reported, NOT the verdict
  "missing_ids": sorted(jset - dset), "db_sequence_gaps": [...],
}
# verdict: MATCH only if counts equal AND sets equal AND no sequence gaps

VERDICT: DIVERGENCE → exit 1, machine-readable JSON on stdout. MATCH → exit 0. Also flags duplicate ids in the JSONL and handles missing DB files/empty tables cleanly.

2. Repair — sync_board_from_jsonl.py. Re-derives board.db from the JSONL (source of truth), then verifies internally:

con.execute("BEGIN TRANSACTION")
con.execute("DROP TABLE IF EXISTS events")
for ev in events: con.execute("INSERT INTO events (id,tick,ts,payload) VALUES (?,?,?,?)", ...)
con.execute("COMMIT")
# verify: counts, max ids, id-set equality -> "board.db sync OK" or exit 1

Full rebuild is atomic; --incremental upserts only missing ids; duplicate ids in the source resolve last-wins with a warning; idempotent.

3. Prevent — the root cause watch. run.sh is the only permitted tick entrypoint:

#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"
exec uv run --with duckdb python tick.py "$@"   # EVERY tick, every time

tick.py hard-imports duckdb (running outside the uv env aborts loudly — no silent skip) and re-queries each inserted row (SELECT COUNT(*) WHERE id=? must be 1) so a lost write can't masquerade as success. runner.ts documents the TS-board contract: fail-fast constructor, no silent catch, verify-after-insert. Run the probe after every tick and in cron; DIVERGENCE pages.
