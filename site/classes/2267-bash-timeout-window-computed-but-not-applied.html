Diagnosis

The bug is a bound-never-applied + ordering + circular-sizing defect:

  1. Ordering — disc_window was computed after timeout 240 run_suite_disconnect, so it only fed the FAIL prose, never the enforcement.
  2. Circular sizing — the sizing input came from the disconnect run itself. A run can't be bounded by a duration measured from that same run.
  3. Masking — the FAIL string still named disc_window, so a string-presence test stayed green. The tier-2 judge caught it by reading the generated script.

Fix (314f672 + dc7459ed)

Compute the window before the run, from the independent earlier ci-pass native run already timed with date +%s, apply the env override as a floor (-gt), and pass the variable into timeout:

suite_t0=$(date +%s); run_suite_native; suite_t1=$(date +%s)
suite_dur=$((suite_t1 - suite_t0))

disc_window=$((suite_dur*2+30))
if [ -n "$DISC_TIMEOUT_WINDOW" ] && [ "$DISC_TIMEOUT_WINDOW" -gt "$disc_window" ]; then
  disc_window=$DISC_TIMEOUT_WINDOW
fi

timeout "$disc_window" run_suite_disconnect

Verification

Two test layers, both runnable:

  • test_window_applied.sh — asserts on __gen-remote output that (1) the timeout line consumes $disc_window, (2) its line number is after the computation, (3) no hardcoded numeric window remains.
  • test_behavior.sh — stubs date/timeout and runs the generated script, asserting the real argv (50 run_suite_disconnect, or 100 with the override).

Results: - RED (BUGGY=1, pre-fix e18a260): 3 assertions fail; runtime argv is 240. - GREEN (fixed): all pass; runtime argv is the computed 50, override floor 100 honored, override below computed stays at 50.

The key takeaway, generalized: for any computed bound, assert on the generated artifact that the enforcing call consumes the variable and that the definition precedes use — message-text assertions cannot catch this class.
