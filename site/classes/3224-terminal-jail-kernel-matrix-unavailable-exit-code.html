Fix: UNAVAILABLE kernel-matrix rows carried a launcher return code in exit_code

Problem class: terminal-jail-kernel-matrix-unavailable-exit-code Repository: terminal-jail (github.com/terminal-jail/terminal-jail) Files: scripts/kernel-matrix-teardown.py, tests/test_kernel_matrix_teardown.py Fixed by: bc2932a (source fix) + 26e9c3d (test relaxation), merged as ff21849

1. Root cause

scripts/kernel-matrix-teardown.py has one shared classifier, validate_row(), used by both the live harness (_measured_row) and the --import path. The schema is deliberately asymmetric:

  • Live verdicts (PASS, FAIL) must carry observed numbers: numeric survival_seconds >= 0 and an int exit_code.
  • No-data verdicts (UNMEASURED, UNAVAILABLE) must carry survival_seconds = null and exit_code = null. A no-data row that claims numbers is malformed and is rejected, never repaired. This prevents an unavailable/unmeasured cell from ever being laundered into a green matrix.

In run_backend_cell(), the branch where the launcher started but no sleep 300 payload ever appeared (wrapper failed closed / exited early) correctly used survival=None but incorrectly passed the launcher's process return code through as exit_code:

# BEFORE (buggy)
return _measured_row(
    backend,
    verdict="UNAVAILABLE",
    survival=None,
    exit_code=launcher.returncode,          # <-- no-data row claims a number
    evidence=(
        f"no 'sleep 300' payload appeared within {LAUNCH_WAIT:.0f}s; "
        "wrapper exited without launching the jail"
    ),
)

_measured_row() runs the result through validate_row() and asserts it is canonical, so the malformed row aborts the whole harness:

AssertionError: harness produced an invalid row:
  verdict UNAVAILABLE must carry exit_code=null, got 2

The other no-data branch (launcher could not even be spawned, OSError) already passed exit_code=None, so the defect was isolated to the "started-but-never-launched" branch. The launcher return code is genuinely useful diagnostics — it just must not live in the exit_code measurement field.

Mechanism: an UNAVAILABLE row is a datapoint about the host/backend, not a measurement. It must emit null measurements, while the launcher diagnostic is preserved in evidence.

2. The exact fix

2.1 scripts/kernel-matrix-teardown.py (run_backend_cell, ~line 277)

Emit exit_code=None and move the launcher return code into the free-text evidence string.

@@ def run_backend_cell(backend: str) -> dict:
             backend,
             verdict="UNAVAILABLE",
             survival=None,
-            exit_code=launcher.returncode,
+            exit_code=None,

                 f"no 'sleep 300' payload appeared within {LAUNCH_WAIT:.0f}s; "
-                "wrapper exited without launching the jail"
+                "wrapper exited without launching the jail "
+                f"(launcher return code {launcher.returncode})"
             ),
         )

Resulting code:

    if payload is None:
        launcher.kill()
        launcher.wait()
        return _measured_row(
            backend,
            verdict="UNAVAILABLE",
            survival=None,
            exit_code=None,
            evidence=(
                f"no 'sleep 300' payload appeared within {LAUNCH_WAIT:.0f}s; "
                "wrapper exited without launching the jail "
                f"(launcher return code {launcher.returncode})"
            ),
        )

No other call site is affected: the OSError branch already used exit_code=None, and the live PASS/FAIL branches still pass the real launcher.returncode as exit_code (required for live verdicts).

2.2 tests/test_kernel_matrix_teardown.py — regression coverage

Add shutil and a regression test that copies the tree, stubs the standalone wrapper to exit 2, and asserts valid UNAVAILABLE rows carry null measurements and the launcher rc in evidence:

def test_no_payload_wrapper_exit_is_unavailable_with_null_measurements(
    tmp_path,
) -> None:
    """A wrapper that exits before launching the payload remains valid evidence."""
    fixture = tmp_path / "no-payload"
    shutil.copytree(
        PROJECT_ROOT,
        fixture,
        ignore=shutil.ignore_patterns(".git", ".venv", ".pytest_cache"),
    )
    stub = fixture / "standalone" / "terminal-jail"
    stub.write_text("#!/bin/sh\nexit 2\n", encoding="utf-8")
    stub.chmod(0o755)

    result = subprocess.run(
        [
            sys.executable,
            str(fixture / "scripts" / "kernel-matrix-teardown.py"),
            "--json",
        ],
        cwd=str(fixture),
        capture_output=True,
        text=True,
        check=False,
        timeout=30,
    )

    assert result.returncode == 0, result.stderr
    payload = json.loads(result.stdout)
    rows = payload["rows"]
    assert len(rows) == len(BACKENDS)
    assert sorted(row["backend"] for row in rows) == sorted(BACKENDS)
    unavailable = [row for row in rows if row["verdict"] == "UNAVAILABLE"]
    assert unavailable, rows
    for row in unavailable:
        assert row["survival_seconds"] is None
        assert row["exit_code"] is None
        assert "launcher return code 2" in row["evidence"]

26e9c3d intentionally replaced the stricter assert len(unavailable) == len(BACKENDS) with assert unavailable, rows: requiring every backend to be unavailable is environment-dependent, whereas the durable contract is that the stubbed no-launch arm carries null measurements and keeps its launcher rc in evidence.

3.5 Environment note (honest caveat)

Running the full module (pytest tests/test_kernel_matrix_teardown.py -q) on this sandbox leaves one pre-existing, environment-dependent failure: test_live_harness_imports_external_rows_and_reports_matrix_honestly expects the current host to contribute a complete measured (bwrap, unshare) pair on top of the synthetic imported kernel (assert len(complete) == 2). On this host the wrapper cannot launch under the nested sandbox, so both live arms are UNAVAILABLE and the current host contributes no complete pair (complete == ["6.6.87"]). That assertion is unrelated to the exit_code fix:

  • pre-fix it fails earlier with the AssertionError above (the bug);
  • post-fix it fails only because the sandbox host yields no live cell.

The focused regression and --selftest are the authoritative checks for this problem class and both pass. On a host where the jail launches, the live arms are PASS/FAIL and that integration test passes as written.

4. Takeaway

For any no-data verdict (UNMEASURED, UNAVAILABLE), emit survival_seconds=None and exit_code=None; route the diagnostic value (launcher return code, spawn error, probe output) into evidence. Only live verdicts (PASS, FAIL) may populate the numeric measurement fields, and the shared validate_row() is the single enforcement point for both the live and import paths.
