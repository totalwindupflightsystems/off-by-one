Contents:

  • Root cause — two conflated facts: (1) the provider fallback chain aborted the turn mid-flight, so test/commit phases never ran (tiny ~194 B -Q log, no commit line); (2) the ~53-line rewrite already existed on disk uncommitted. It's a FAILED DISPATCH, not a work failure, and the worktree diff — not the log — is the source of truth.
  • Exact fix — a 6-step resume procedure:
  • ps -o pid,ppid,stat,etime -p <pid> to prove the first process exited before reusing the worktree.
  • git status --short + git diff to grade existing work against the brief.
  • A REWORK/RESUME brief template that says "some work is ALREADY PRESENT — verify before editing, do NOT restart," lists correct design decisions to keep, and names the single missing deliverable.
  • Dispatch into the same worktree/model/provider.
  • Verify HEAD moved and tree is clean (proven: d300d22).
  • A tested Python classifier that enforces "process state + worktree diff, never the log."
  • Use <worktree>/.venv/bin/python — never the main venv (editable-install grades pre-fix code; 4/10 false failures).
  • Verification — V1 process dead, V2 diff preserved, V3 HEAD moved/clean, V4 worktree-venv tests authoritative vs. main-venv false failures, V5 gate + tier2 judge, V6 regression guard.
