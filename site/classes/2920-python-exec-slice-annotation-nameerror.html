What I diagnosed and verified

Root cause: The test extracts a function slice from scripts/router_seed.py via ast, so it carries the signature def overlay_update(overlay: Any, updatable: Any) but not the module-level from typing import Any. On eager-annotation Pythons (≤3.13, incl. CI's 3.11) the def raises NameError at exec time. The local box runs 3.14, where PEP 649 makes annotations lazy, so the failure is invisible until __annotations__ is accessed.

Exact fix (test-side, matches commit 2a3eb5f):

+from typing import Any
 ...
-    ns = {}
+    ns = {"Any": Any}
     exec(textwrap.dedent(src), ns)

The doc also provides a generic exec_slice() helper that auto-seeds every referenced annotation name from typing/builtins and forces annotation evaluation so 3.11-style failures surface on 3.14.

Verification actually run in this environment: | Interpreter | Pre-fix | Post-fix | | --- | --- | --- | | py3.11.15 (uv, CI-like, eager) | NameError: name 'Any' is not defined — 1 failed | 1 passed | | py3.12 (eager) | same NameError — 1 failed | 1 passed | | py3.14 (PEP 649 lazy) | passes (bug hidden); forced fn.__annotations__ → NameError | passes, incl. forced eval |

Detection rule captured: run slice-exec on the lowest supported Python, or force __annotations__ evaluation on delayed-eval interpreters via getattr(obj, "__annotate__", None) → obj.__annotations__.
