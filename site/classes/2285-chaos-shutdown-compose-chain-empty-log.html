Fix: chaos-shutdown compose chain produces an empty sd.log with no attribution

Problem class: chaos-shutdown-compose-chain-empty-log Repo: heading — bunker-qa.sh, chaos-shutdown cell Reference fix: home-repo commit 13f3b87 Evidence: qa-logs-20812/sd.log = 0 bytes, dc.log = 27 KB proving build+up were clean

1. Root cause

The cell chained every compose verb with &&, placing each step marker behind the success of all prior verbs:

# BEFORE (reconstructed)
docker compose up -d       >>"$dc" 2>&1 &&
docker compose stop        >>"$dc" 2>&1 && echo "STOP=$?"        >>"$sd" &&
docker compose restart     >>"$dc" 2>&1 && echo "RESTART=$?"     >>"$sd" &&
docker compose kill        >>"$dc" 2>&1 && echo "KILL=$?"        >>"$sd" &&
docker compose up -d       >>"$dc" 2>&1 && echo "KILLRECOVER=$?" >>"$sd" &&
docker compose down        >>"$dc" 2>&1 && echo "DOWN=$?"        >>"$sd"
  1. Silent short-circuit. If the first verb (up) fails, the chain aborts and no echo runs → sd.log stays 0 bytes.
  2. No UP= marker. The baseline up is never recorded.
  3. Wrong attribution. The grader emits FAIL rc=1 without knowing which verb failed, and the OK branch can fire even when up failed.
  4. dc.log looks healthy because build/up output went there, making the failure look like a mystery.

2. The fix

Run every verb unconditionally, capture each exit code, emit a marker per step, derive sd_rc as the first failing step, gate OK on up_rc=0, and name the failing verb in each grading branch:

# AFTER — chaos-shutdown cell
chaos_shutdown_cell() {
    local dc="$1" sd="$2"
    local up_rc stop_rc restart_rc kill_rc killrecover_rc down_rc
    local sd_rc first_fail pair name rc

    : >"$dc"; : >"$sd"

    docker compose up -d        >>"$dc" 2>&1; up_rc=$?;          echo "UP=$up_rc"                   >>"$sd"
    docker compose stop         >>"$dc" 2>&1; stop_rc=$?;        echo "STOP=$stop_rc"               >>"$sd"
    docker compose restart      >>"$dc" 2>&1; restart_rc=$?;     echo "RESTART=$restart_rc"         >>"$sd"
    docker compose kill         >>"$dc" 2>&1; kill_rc=$?;        echo "KILL=$kill_rc"               >>"$sd"
    docker compose up -d        >>"$dc" 2>&1; killrecover_rc=$?; echo "KILLRECOVER=$killrecover_rc" >>"$sd"
    docker compose down         >>"$dc" 2>&1; down_rc=$?;        echo "DOWN=$down_rc"               >>"$sd"

    # sd_rc = first failing step, in execution order.
    sd_rc=0; first_fail=""
    for pair in "UP:$up_rc" "STOP:$stop_rc" "RESTART:$restart_rc" \
                "KILL:$kill_rc" "KILLRECOVER:$killrecover_rc" "DOWN:$down_rc"; do
        name="${pair%%:*}"; rc="${pair##*:}"
        if [ "$rc" -ne 0 ]; then
            sd_rc="$rc"; first_fail="$name"; break
        fi
    done

    # Grading: gate OK on up_rc=0, then name the failing verb.
    if [ "$up_rc" -ne 0 ]; then
        echo "FAIL chaos-shutdown: compose UP failed (UP=$up_rc)" >&2
        return 1
    fi
    if [ "$sd_rc" -ne 0 ]; then
        echo "FAIL chaos-shutdown: step ${first_fail} failed (rc=$sd_rc)" >&2
        return 1
    fi
    echo "PASS chaos-shutdown: UP=$up_rc STOP=$stop_rc RESTART=$restart_rc KILL=$kill_rc KILLRECOVER=$killrecover_rc DOWN=$down_rc"
    return 0
}
Requirement Implementation
Every verb runs unconditionally no &&; statements separated by ;
Per-step markers UP=/STOP=/RESTART=/KILL=/KILLRECOVER=/DOWN= appended to sd.log
sd_rc = first failing step ordered for loop over step:rc, break on first nonzero
OK gated on up_rc=0 explicit if [ "$up_rc" -ne 0 ] returns 1 first
Failing verb named compose UP failed / step ${first_fail} failed

4. Acceptance criteria

  • sd.log is non-empty whenever any compose verb fails and contains all six markers.
  • The grader names the first failing verb.
  • PASS is reachable only when UP=0 and all other steps are 0.
  • No verb is skipped because a prior verb failed.
