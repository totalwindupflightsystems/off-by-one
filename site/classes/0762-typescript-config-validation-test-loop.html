The fix wires the config-validation gate into the test lifecycle and closes the two doc gaps, all in one mechanical tick (commit 3e04ed6).

1. package.json — pretest hook that gates every npm test on config validity

{
  "name": "ring-runner",
  "scripts": {
    "validate:configs": "tsx scripts/validate-configs.ts",
    "pretest": "npm run validate:configs",
    "test": "vitest run",
    "typecheck": "tsc --noEmit",
    "build": "vite build",
    "guard": "npm run typecheck && npm run build && npm run test"
  }
}

The pretest hook runs before test automatically (npm lifecycle), so npm test — and any guard/CI chain that shells out to it — now blocks on config validity before vitest even starts.

2. scripts/validate-configs.ts — deep-parse shipped configs through the real Zod loader (reuses the same schema the game imports, not a re-declared copy):

import { readdirSync, readFileSync } from "node:fs";
import { resolve } from "node:path";
import { ConfigSchema } from "../src/config/schema"; // the real loader schema

const CONFIG_DIR = resolve(import.meta.dirname, "../configs");

let failed = false;
for (const file of readdirSync(CONFIG_DIR).filter((f) => f.endsWith(".json"))) {
  const key = file.replace(/\.json$/, "");
  const raw = JSON.parse(readFileSync(resolve(CONFIG_DIR, file), "utf8")); // malformed JSON throws here
  const parsed = ConfigSchema.safeParse(raw);
  if (!parsed.success) {
    failed = true;
    for (const issue of parsed.error.issues) {
      // prints exactly: `scoring: ringPoints: Expected number, received string`
      console.error(`  ${key}: ${issue.path.join(".") || "(root)"}: ${issue.message}`);
    }
  }
}
if (failed) {
  console.error("\nConfig validation FAILED — fix the configs above before running tests.");
  process.exit(1);
}
console.log(`validate:configs OK (${...count} config files deep-parsed through Zod)`);

process.exit(1) is what makes pretest hard-fail and short-circuits vitest; a plain warn would not.
