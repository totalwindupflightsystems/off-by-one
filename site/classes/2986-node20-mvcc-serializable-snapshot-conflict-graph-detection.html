Serializable Snapshot Isolation (SSI) Conflict Detector — Diagnosis & Verified Fix

Problem class: node20-mvcc-serializable-snapshot-conflict-graph-detection Stack: Node.js 20+, plain JS, no dependencies.

1. Symptom

The detector must guarantee the committed history is always conflict-serializable, abort exactly one transaction per cycle, and never false-abort read-only or commute-safe transactions. A naive implementation fails in three ways:

  1. Non-serializable committed histories appear on loss-update, 3-cycle, and read-only schedules.
  2. Read-only or purely commutative transactions get aborted when safe.
  3. Cycles survive even after a dangerous structure is seen, because detection runs at the wrong time or aborts too few transactions.

2. Root-cause analysis

RC1 — Missing Snapshot-Isolation first-committer-wins. When two concurrent transactions write the same non-commutative key, the later committer must abort. Without it, T1 r(y) … T1 w(y) vs T2 w(y) commit yields T1 →rw T2 plus T2 →ww T1 — a 2-cycle.

RC2 — Commutative writes treated as conflicts. An increment does not invalidate a read and commutes with other increments, so it must not create rw/ww edges. Otherwise commute-safe workloads abort.

RC3 — Late second rw edge / read-only anomaly. In T1 -rw-> T2 -rw-> T3, the theorem requires T3 first to commit; T2 is the pivot. If the second edge is created after both writers committed (a read under an older snapshot), a pivot-only check misses it:

T1: w(y); commit
T2: w(x); r(y); commit      # r(y) under older snapshot
T3(read-only): r(x); r(y); commit

The only transaction left to abort is T3. This is the known read-only transaction anomaly; refusing to ever abort a read-only txn here makes serializability impossible. It is a necessary abort, not a false one.

RC4 — One abort per sweep + self-read early return. Two independent dangerous structures can appear on one operation; aborting one left the other. And read returned early when the key was in the txn's own write set, skipping the sweep entirely.

RC5 — Strict-2PL oracle was unsound. A self-read downgraded the txn's own X lock to S (X→S), letting other transactions build cycles. A 2PL oracle must never downgrade; a broken oracle masks real engine bugs.

3. The fix

  • Shared logical clock for begin/commit; concurrency = interval overlap [startTs, endTs) (endTs = commitTs if committed, +Infinity while running).
  • Track readSet (key → version commitTs/txnId) and writeSet (key → {value, commutative}).
  • Recompute the rw graph from scratch after every read/write/commit/abort. This makes missed edges impossible and handles committed-but-invisible and still-running predecessors uniformly.
  • Detection rules over all structures A -rw-> P -rw-> B:
  • first-committer-wins (commit of t): abort t if a committed overlapping txn wrote a non-commutative key t wrote.
  • successor commits first (t = B): if A and P are running, abort t.
  • pivot after committed successor (t = P): if B committed and A did not commit before B, abort t.
  • late structure (any sweep): if B committed first and P running, abort P; else if P committed and A running, abort A.
  • Sweep to a fixpoint (loop until no late structure remains); every read triggers a sweep, including self-reads.
  • Read-only/commutative txns can never be pivot or successor (both wrote), so they are only touched by rule 4's last resort, which is provably required.

The full engine is in ~/ssi-detector/ssi.js (embedded verbatim in SOLUTION.md); the fuzzer and regression tests are in ~/ssi-detector/fuzz.js.

4. Verification

Targeted regressions (node fuzz.js --tests) — 7/7 pass: write-skew prevention; read-only never aborted (common case); commutative writes create no rw edge; pivot commits between edge creation and sweep; pivot aborted after already-committed successor; committed-but-invisible predecessor forms an edge; multiple independent late structures all resolved.

Deterministic differential fuzzer. For each generated schedule it: replays through SSI; builds the committed conflict graph (wr + ww + rw); asserts acyclic via DFS; asserts no unjustified read-only/commute-only abort; and replays through a strict-2PL oracle asserting its graph is acyclic. A failure prints the offending schedule and cycle.

Abort breakdown over 20k schedules: first-committer-wins 5050, late-pivot 2273, successor-commits-first 623, pivot-after-committed-successor 93, late-predecessor 57 (the unavoidable read-only/late case).

5. Exact fixes

# Defect Fix
1 No first-committer-wins abort later committer on concurrent non-commutative ww
2 Commutative writes conflict skip commutative writes in every conflict rule
3 Late second rw edge / read-only anomaly late sweep: abort running pivot, else running predecessor
4 Single abort / self-read skips sweep loop sweep to fixpoint; every read sweeps
5 2PL oracle X→S downgrade never downgrade an X lock held by the same txn
