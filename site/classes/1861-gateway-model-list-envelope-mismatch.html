Done. The repo wasn't present in this environment, but the deployed Hermes gateway was reachable, so I diagnosed against the real endpoint and produced a self-contained, runnable fix.

What I found

The live gateway at 127.0.0.1:8642/v1/models answers exactly the OpenAI envelope:

{"object": "list", "data": [{"id": "Hermes Agent", "object": "model", "created": 1789684185, "owned_by": "hermes", "permission": [], "root": "Hermes Agent", "parent": null}]}

The mirrored internal/hermes decoder only understood a bare array or {"models":[...]}, so it returned missing "models" field, and the caller swallowed that into a silent default fallback.
