Fix Clean-Machine FileNotFoundError: 'psql' by Running Migration SQL In-Process

Scope: tests/integration/test_sidecar_first_fresh_db_migration.py in &lt;project&gt;/&lt;project&gt;-core
Failure: _run_rls_migration shells out to psql; on a clean host/CI runner psql is not on PATH, so the test dies at process launch.

Root cause

The test has an unnecessary process-boundary dependency:

subprocess.run([
    "psql", "-h", url.host, "-p", str(url.port), "-U", url.username,
    "-d", dbname, "-f", str(REPO_ROOT / "migrations" / "consensus" / "002_rls.sql"),
], env=env, capture_output=True, text=True)

psql is resolved through PATH. The API container already ships /usr/bin/psql, but the host/native QA leg does not. The image-build premise was false; the real defect is reliance on ambient host tooling.

The repo already depends on psycopg2-binary, which is libpq-backed and can execute the migration in-process.

Critical detail: simple protocol

Call cursor.execute(sql_text) with no parameters. Parameters force the extended protocol, which cannot run multi-statement SQL. With no params, psycopg2 uses libpq's simple-query protocol, supporting:

  • multiple statements,
  • explicit BEGIN; ... COMMIT;,
  • DO $$ ... $$; blocks.

asyncpg cannot provide this behavior.

Replacement helper

def _run_rls_migration(database_url: str) -> None:
    """Apply migrations/consensus/002_rls.sql using psycopg2/libpq.

    The whole file is sent as one statement, with no query parameters, so
    libpq uses the simple-query protocol. That permits multi-statement SQL,
    explicit BEGIN/COMMIT, and DO $$ ... $$ blocks in a single execute().
    """
    url = make_url(database_url)
    sql_path = REPO_ROOT / "migrations" / "consensus" / "002_rls.sql"
    sql_text = sql_path.read_text(encoding="utf-8")

    conn = None
    try:
        conn = psycopg2.connect(
            host=url.host or "localhost",
            port=url.port or 5432,
            user=url.username,
            password=url.password,
            dbname=url.database,
            connect_timeout=10,
        )
        # Mirror psql: let the SQL file control its own transactions.
        conn.autocommit = True
        with conn.cursor() as cur:
            cur.execute(sql_text)  # no params -> simple protocol
    except psycopg2.Error as exc:
        if conn is not None:
            conn.rollback()
        raise AssertionError(
            f"Failed to apply {sql_path.name} to database "
            f"{url.database!r}: {exc}"
        ) from exc
    finally:
        if conn is not None:
            conn.close()

Do not use cur.execute(sql_text, ()) or any parameterized form; that can switch to the extended protocol and break multi-statement SQL.

If 002_rls.sql contains psql-only meta-commands such as \set, \gexec, or \copy, replace those with SQL/library equivalents. Ordinary SQL, transactions, and DO blocks work.

General rule: when a repository test shells out to an external CLI, prefer an in-tree/library path so the test carries its own dependency. If a binary is genuinely required, skip with a named reason rather than dying with FileNotFoundError, and probe the shipped image before accepting “install it in the image” as the fix.
