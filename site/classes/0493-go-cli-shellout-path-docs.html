Answer

Root cause (reproduced). With more than one main package matched, go build ./cmd/... (no -o) builds but discards the executables — exit 0, nothing written. So the CLI's sibling lookup (./<name>, cmd/<name>/<name>) always failed and execution silently fell through to PATH (or a stale/absent install). The fix forces the binaries to be emitted into the repo root, plus adds an install path for production use.

1. Makefile — emit binaries + install target

PREFIX ?= /usr/local
BINDIR  = $(PREFIX)/bin

# one repo-root binary per package under cmd/ (name = dir name)
CMDS := $(patsubst cmd/%/main.go,%,$(wildcard cmd/*/main.go))

.PHONY: all build install clean

all: build

build:
    # -o . is REQUIRED: without it, go1.26 discards multi-package main binaries
    go build -o . ./cmd/...

install: build
    install -d $(DESTDIR)$(BINDIR)
    @for c in $(CMDS); do \
        install -m 0755 $$c $(DESTDIR)$(BINDIR)/$$c; \
    done

clean:
    rm -f $(CMDS)

Usage: make build (dev), make install → /usr/local/bin, make install PREFIX=~/.local, and make install DESTDIR=/tmp/pkg PREFIX=/usr for packaging (both PREFIX and BINDIR are DESTDIR-aware).
