Title

RFC 9204 QPACK Encoder/Decoder State Machines for a Simulated HTTP/3 Connection

Root-cause analysis (the traps a naive implementation hits)

  1. Truncated Huffman table — hand-built table had 228/257 symbols (Kraft sum 0.546 instead of 1), producing invalid codes. Fixed by deriving the table from RFC 7541 Appendix B; the known vector "www.example.com" → f1e3c2e5f23a6ba0ab90f4ff now matches.
  2. Buffer/string type drift — decoder stored dynamic-table values as Buffer while names were strings, breaking exact-match lookup. Fixed by normalizing at the single insertion point.
  3. Relative vs post-base indexing — abs = Base-1-i vs abs = Base+i. Both mappings are now explicit; the encoder defaults Base = RIC and accepts {base} to force post-base encoding.
  4. Required Insert Count is a modulo code — resolved relative to totalInserts + MaxEntries; only unambiguous within the live window totalInserts-MaxEntries < RIC <= totalInserts.
  5. Eviction — must evict to capacity - newSize, protect entries referenced by unacknowledged sections, and refuse a too-large entry (QPACK_ENCODER_STREAM_ERROR), not blindly clear as HPACK does.
  6. Blocked sections — a section with RIC > inserts received must be buffered, never decoded.
  7. Three disjoint error domains — field section → QPACK_DECOMPRESSION_FAILED, encoder stream → QPACK_ENCODER_STREAM_ERROR, decoder stream → QPACK_DECODER_STREAM_ERROR; stream cancellation must not be a decompression failure.
