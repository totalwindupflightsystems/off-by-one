Tier-2 verdict judged the wrong repository (external criteria path) + resource-cap shadowing

Problem class: gitreins-tier2-verdict-from-wrong-repo-via-criteria-path Repo of record: ~/Hermes-DAGger/&lt;project&gt; Judged commit: 193bae1874d674b5539660a0146a651cc1f3a994 Bad verdict: .gitreins/history/2026-10-16/2b4b8577 Source inspected: gitreins 0.16.0.

TL;DR

Tier 2 did not judge ~/Hermes-DAGger/&lt;project&gt; at commit 193bae18. It judged ~/dagger-v2-panel (a directory named only inside the task criteria) and a stray sibling worktree. Three things combined:

  1. Trigger — the criteria named an absolute path outside the repo (~/dagger-v2-panel/specs/contracts/SC-22-llm-activity.md L207). The evaluator prompt never states its own repository, and run_command is an unrestricted shell, so the model anchored on that path and roamed the host.
  2. Enabling defect — the file-scope allowlist is empty for a committed change. _compute_allowed_files() builds the allowlist from the working-tree diff. When the judged work is already committed (clean tree, as here), git diff is empty, so read_file()/search_pattern() reject every file in the judged commit. The judge is forced onto run_command, which has no repository confinement.
  3. Aggravating defect — read_file containment is a string-prefix test (real.startswith(realpath(workdir))), so an absolute path into a sibling like .../&lt;project&gt;-wt/... is accepted.

Secondary finding: the partial verdict came from a resource cap. Effective max_output_tokens is 131 072 because a legacy combined cap: string silently wipes the defaults: block; a config-only "raise the cap" edit can be a no-op.

Falsification that the code exists:

git -C ~/Hermes-DAGger/&lt;project&gt; \
    show 193bae1874d674b5539660a0146a651cc1f3a994:src/noderec/response_retention.go \
  | grep -c LLM-042      # => 36

Always falsify a tier-2 FAIL against verdict.commit before believing it.

1. Evidence

persist.build_verdict_data() stamps worktree/commit with git rev-parse in the evaluator's directory, so the record is authoritative:

cd ~/Hermes-DAGger/&lt;project&gt;
jq '{worktree,branch,commit,summary,items:[.items[]?|{status,cited_path,detail:(.detail[0:120])}]}' \
   .gitreins/history/2026-10-16/2b4b8577/verdict.json

worktree and commit are correct; tier 1 passed; yet the verdict text describes ~/dagger-v2-panel. The judge read the wrong checkout.

2. Root cause

2.1 The prompt never names the repository of record

_evaluate_loop() builds the user prompt with only title/id/criteria/diagnostics/code-context — no worktree path. read_file is repo-relative, but run_command is plain shell=True with cwd=self.workdir and can cat ~/dagger-v2-panel/..., find ~, git -C <other>, etc. A criterion naming an external absolute path therefore becomes the de-facto repo root.

2.2 A committed change has an empty file scope (the real bug)

_compute_allowed_files() reads only git diff --cached / git diff. On a clean tree both are empty. Reproduced against 0.16.0:

allowed files: []
  in_scope(src/noderec/response_retention.go) = False
read_file(...) -> {'error': 'File not in scope: ...'}
search_pattern(LLM-042) -> matches: []  count: 0
_build_code_context -> only "## LAST COMMIT" + git show --stat (filenames, no code)

So read_file/search_pattern cannot read the judged commit; only unconfined run_command can. Reviewing a committed task actively pushes the judge out of its sandbox.

2.3 read_file prefix containment bug (verified)

real = os.path.realpath(full_path)
if not real.startswith(os.path.realpath(self.workdir)):   # BUG

os.path.join(workdir, absolute) returns the absolute path, and prefix matching accepts .../&lt;project&gt;-wt/... siblings (which is exactly the fleet layout main_root.parent / f"{repo_name}-wt" / task_id).

2.4 Which cap bound

eval_cap_from_config() precedence trap (verified with the real parser):

config effective out
defaults.max_output_tokens: "1M" 1 000 000
… + evaluator.max_output_tokens: 131072 131 072
evaluator.cap: "300/120m/8M/131072" 131 072
defaults…"1M" + guards.eval_cap: "…/131072" 131 072 (defaults wiped)
combined string + evaluator.max_output_tokens: "1M" 1 000 000

With 300 turns, cumulative output hits 131 072 long before the 8M input / 120m / 300-iteration caps — output tokens is the likely binding rung. Confirm from the exact log line:

grep -E 'Eval cap exceeded|Cap exceeded' .gitreins/logs/*.log 2>/dev/null | tail
tail -20 .gitreins/usage.jsonl | jq -c 'select(.step=="tier2")'

3. Exact fix

3.1 Immediate: rewrite the criteria (no tooling)

Never reference paths outside the repo of record; inline the contract text.

Before:

- src/noderec/response_retention.go must implement retention policy
  per ~/dagger-v2-panel/specs/contracts/SC-22-llm-activity.md L207.

After:

- src/noderec/response_retention.go must implement the retention policy.
  Contract text (inlined from SC-22 L207):
    "An LLM-042 activity record MUST be retained for N days and MUST carry
     the LLM-042 marker in every emitted record."
  All paths are relative to the repository of record.

Rules: no ~, no absolute/out-of-repo paths, inline requirements, state the worktree + judged commit for multi-checkout hosts.

3.2 Immediate: make the cap edit hit the winning location

Remove legacy combined cap: / guards.eval_cap, set both defaults: and evaluator::

defaults:
  max_iterations: 300
  max_time: "120m"
  max_input_tokens: "8M"
  max_output_tokens: "2M"
evaluator:
  max_iterations: 300
  max_time: "120m"
  max_input_tokens: "8M"
  max_output_tokens: "2M"     # individual key = highest config precedence
  file_scope: full            # workaround for §2.2
  # NO `cap:` here
guards:
  # eval_cap: ...             # remove if present — same shadowing trap

Surgical edit:

cd ~/Hermes-DAGger/&lt;project&gt;
cp .gitreins/config.yaml .gitreins/config.yaml.bak
python3 - <<'PY'
import yaml, pathlib
p = pathlib.Path(".gitreins/config.yaml"); cfg = yaml.safe_load(p.read_text()) or {}
for section, key in (("evaluator", "cap"), ("guards", "eval_cap")):
    if isinstance(cfg.get(section), dict):
        cfg[section].pop(key, None)
        if not cfg[section]: cfg.pop(section)
d = cfg.setdefault("defaults", {}); e = cfg.setdefault("evaluator", {})
d["max_output_tokens"] = "2M"; e["max_output_tokens"] = "2M"
e.setdefault("file_scope", "full")
p.write_text(yaml.safe_dump(cfg, sort_keys=False)); print("patched")
PY

3.3 Recommended code fix (stop judging committed changes blind)

Patch engine/evaluator.py in the pipx venv (GRPY=~/.local/share/pipx/venvs/gitreins/bin/python).

Patch 1 — include HEAD's files in the allowlist. After the git diff block's except Exception: pass in _compute_allowed_files():

        # Committed work = clean tree = empty working-tree diff. Without this
        # fallback every judged file is out of scope and the judge is forced
        # onto unconfined run_command.
        if not allowed:
            try:
                result = subprocess.run(
                    ["git", "show", "--pretty=format:", "--name-only", "HEAD"],
                    capture_output=True, text=True, timeout=10, cwd=self.workdir,
                )
                for line in result.stdout.strip().splitlines():
                    if line:
                        allowed.add(line)
            except Exception:
                pass

Patch 2 — anchor the prompt. In _evaluate_loop()'s task_prompt header, add:

REPOSITORY OF RECORD: {self.workdir}
ALL file paths in criteria, tools and evidence are relative to this directory.
A path quoted inside a criterion (especially ~/other-project/...) is a citation
to copy from, NOT a directory to search. Never run commands outside this repo.

Patch 3 — segment-safe containment in _tool_read_file():

        real = os.path.realpath(full_path)
        base = os.path.realpath(self.workdir)
        if real != base and not real.startswith(base + os.sep):
            return {"error": f"Path outside working tree: {path}"}

3.4 Fail-closed gate

For any tier-2 FAIL, assert the required files exist at verdict.commit; if they do, the verdict is untrustworthy — re-run with fixed criteria, do not treat it as code rot.

v=.gitreins/history/2026-10-16/2b4b8577/verdict.json
worktree=$(jq -r .worktree "$v"); commit=$(jq -r .commit "$v")
for f in src/noderec/response_retention.go; do
  git -C "$worktree" cat-file -e "$commit:$f" 2>/dev/null \
    && { echo "FALSE-FAIL: $f exists at $commit"; exit 2; }
done

5. One-line rule

A tier-2 FAIL is actionable only after git show "$(jq -r .commit verdict.json):<required-file>" also fails. If the file is there, the judge mis-anchored — fix the criteria and caps, not the code.

Verified in this session: _compute_allowed_files() returns [] on a clean tree and read_file/search_pattern reject committed files; the str.startswith escape accepts a &lt;project&gt;-wt/... sibling; the legacy cap: string shadows defaults.max_output_tokens (131072) while evaluator.max_output_tokens wins over it; and the config patch yields an effective 2M output budget.
