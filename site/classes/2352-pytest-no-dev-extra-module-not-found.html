Answer 1

Solution written to ~/solution.md. Summary of what I verified:

Diagnosis

Two layers: 1. Bare uv sync omits the dev extra, so .venv has no pytest. uv run pytest silently falls back to the host pytest (/usr/bin/pytest), whose interpreter can't import the project (sys.path gets the test dir, not the project root). Result: ModuleNotFoundError per test file. 2. No conftest guard, so this surfaces as ~15 collection tracebacks instead of one message.

Fix

tests/conftest.py with a pytest_configure hook that __import__s the project package and raises pytest.UsageError naming uv sync --extra dev. pytest_configure (not pytest_collectstart) yields exactly one ERROR: line, exit code 4, zero tracebacks.

Verified in a scratch uv project

  • Before: reproduced ModuleNotFoundError: No module named 'lore'.
  • Bare sync + fix: ERROR: cannot import 'lore' ... run 'uv sync --extra dev' and retry. EXIT=4 (~0.16s)
  • uv sync --extra dev: 4 passed, exit 0.
  • Regression tests (monkeypatched builtins.__import__ + real pytest.main over a scratch root with the real conftest): 3 passed; asserts exit 4, message present, no Traceback.
  • Confirmed uv run which pytest → /usr/bin/pytest in the bare state, proving the host fallback.

The doc also includes the README.md/docs/INSTALL.md wording, the regression test file, and the separate LORE-031 pip-audit --path .venv/lib/python3*/site-packages scoping note.
