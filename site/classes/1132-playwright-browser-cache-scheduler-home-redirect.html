Summary

Root cause (3-link chain, each link proven):

  1. Playwright's browser cache resolution — registryDirectory = PLAYWRIGHT_BROWSERS_PATH || $HOME/.cache/ms-playwright. The scheduler spawns sessions with HOME=/tmp/dogfood-muster/home, so Playwright looks for browsers in /tmp/dogfood-muster/home/.cache/ms-playwright/... → browserType.launch: Executable doesn't exist (reproduced byte-for-byte with playwright-core 1.62.0, including the chromium_headless_shell-1234 revision).
  2. The guard mislabels the failure — frontend/tests/setup.ts's isServerRunning() wraps chromium.launch() in a catch-all and returns false on any error, reporting "Dev server not running" when really the browser is missing.
  3. False green — all 49 tests across 9 files (46 guard occurrences) do if (!serverAvailable) { console.warn(...); return; }, so the suite "passes" in ~2.9 s with zero assertions. Vitest 4's console intercept can even hide the warnings.

Fix (one command):

env PLAYWRIGHT_BROWSERS_PATH=/home/kara/.cache/ms-playwright npm run test:integration

Verification performed live (repo cloned, deps installed, real browsers at /home/kara/.cache/ms-playwright, Vite running): - Path/launch matrix — bug env fails with the exact reported error; fix env launches OK even with HOME still redirected - Detection probe with the repo's own node_modules: LAUNCH FAIL → LAUNCH OK - Real vitest run of tests/navigation.test.ts: bug → 9/9 "passed" in ~500 ms with 9 skip warnings; fix → 9/9 real browser tests in 7.64 s, zero warnings — matching the production 2.9 s vs 52.7 s deltas
