Answer

Reject placeholder-only probe-fields-x1 submissions before the solver runs

Root-cause analysis

/workspace/problem.json contains no actionable engineering problem:

{
  "problem_class": "probe-fields-x1",
  "environment": "",
  "language": "",
  "version": "",
  "description": "answer text here",
  "error_message": "",
  "stack_trace": "",
  "context": {}
}

problem_class is a synthetic probe/canary name, description is template filler, and every diagnostic field is empty. There is no code, error, stack, environment, language, version, or context to diagnose.

The solver bridge accepts it because validateProblem() in scripts/pi-agent (deployed as ~/.local/bin/pi-agent) only checks for non-empty strings:

const hasText = (v) => typeof v === 'string' && v.trim() !== '';
...
if (!hasText(problem.description) && !hasText(problem.error_message) &&
    !hasText(problem.stack_trace) && !contextPresent) {
  return 'missing problem content (description/error_message/stack_trace/context)';
}

hasText("answer text here") is true, so the bridge proceeds to launch a full solve. The queue row sub_9153e4 confirms the consequence: it reached status = in_progress, stage = solver_running, consuming a 25-minute sandbox slot.

Historical probe rows (probe-shape, probe-gap-audit-x, probe-gap-audit-x2, mixed-case-probe-gap) failed correctly with pi-agent: invalid problem file ... missing problem content because all fields were empty. probe-fields-x1 is the same class of invalid input with filler in description, so it bypasses the presence check.

One-sentence root cause: the validator checks that a field is present, not that it contains substantive problem content.

No real software defect can be diagnosed from the supplied data. The correct behavior is to reject the submission before any expensive solve.

Exact fix

1. Harden validateProblem in the solver bridge

Replace the entire validateProblem function in both copies:

  • scripts/pi-agent (repo copy)
  • ~/.local/bin/pi-agent (deployed copy)

with the following. The two copies are separate; patch both, or patch the deployed copy in place if it carries newer hardening than the repo copy.

// Template filler that has appeared in probe submissions. A non-empty
// string is not enough to make a problem solvable.
const PLACEHOLDER_TEXT = new Set([
  'answer text here', 'answer here', 'description', 'description here',
  'problem', 'problem description', 'problem description here',
  'error', 'error message', 'error message here',
  'stack trace', 'stack trace here', 'paste error here', 'paste stack trace here',
  'details', 'context', 'todo', 'fixme', 'tbd', 'n/a', 'na', 'none',
  'null', 'nil', 'undefined', 'placeholder', 'example', 'sample',
  'test', 'testing', 'coming soon', 'lorem ipsum', '...',
]);

function isPlaceholderText(value) {
  if (typeof value !== 'string') return true;
  let text = value.trim().toLowerCase();
  if (text === '') return true;

  // Ignore wrapper punctuation: "Answer text here." and "<answer text here>".
  text = text.replace(/^[\s"'`([{<]+|[\s"'`)\]}>.!?,;:]+$/g, '');
  text = text.replace(/\s+/g, ' ');

  if (PLACEHOLDER_TEXT.has(text)) return true;
  if (/^(?:\.{3,}|-+|_+|\?+)$/.test(text)) return true;
  if (/^(?:todo|fixme|tbd)\b/.test(text)) return true;
  if (/^(?:lorem ipsum|answer text here|description here|error message here|stack trace here)\b/.test(text)) return true;
  if (/^(?:<[^>]*>|\{\{[^}]*\}\}|\[[^\]]*\])$/.test(text)) return true;
  return false;
}

function validateProblem(problem) {
  if (!problem || typeof problem !== 'object' || Array.isArray(problem)) {
    return 'expected a JSON object';
  }
  const hasText = (v) => typeof v === 'string' && v.trim() !== '';
  const hasContent = (v) => hasText(v) && !isPlaceholderText(v);
  const contextPresent =
    problem.context && typeof problem.context === 'object' &&
    !Array.isArray(problem.context) && Object.keys(problem.context).length > 0;
  if (!hasText(problem.problem_class)) {
    return 'missing required field "problem_class"';
  }
  if (!hasContent(problem.description) && !hasContent(problem.error_message) &&
      !hasContent(problem.stack_trace) && !contextPresent) {
    return 'missing problem content (description/error_message/stack_trace/context)';
  }
  return null;
}

Result: probe-fields-x1 with "description": "answer text here" is rejected with the existing missing problem content path, before model selection, key selection, or sandbox startup. A real problem still passes if any one of description, error_message, stack_trace, or a non-empty context is substantive.
