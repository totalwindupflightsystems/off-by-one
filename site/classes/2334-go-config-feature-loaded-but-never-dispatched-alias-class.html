Fix: config aliases: parsed but never dispatched (openapi-cli <alias> → unknown command)

Problem class: go-config-feature-loaded-but-never-dispatched-alias-class Repo: github.com/wojons/muster · Commit: ad42238b Fix files: internal/builtin/, pkg/protocol/, docs/guides/

Symptom

A config file containing an aliases: block parses cleanly and is documented, but invoking an alias fails:

$ cat openapi-cli.yaml
aliases:
  ls: list

$ openapi-cli ls
error: unknown command "ls" for "openapi-cli"
$ echo $?
1

Root-cause analysis

The aliases block was loaded but never consumed. The data flow was:

config.Load(path) ──► cfg.Aliases = {"ls": "list"}   ✅ parsed
        │
        ▼
builtin.NewRootCmd(cfg)  ──► cobra tree               ✅ constructed
        │
        ▼
root.SetArgs(os.Args[1:]) ──► cobra dispatch          ❌ "ls" never rewritten
        │
        ▼
root.ExecuteContext(ctx)  ──► unknown command "ls"    ❌ exit 1

Cobra only knows about commands registered via AddCommand. A value that lives solely inside cfg.Aliases is invisible to the dispatcher. There was no step between loading config and executing the command that turned the user-typed token into a real command name, so a valid config key behaved exactly like a typo'd key. "Loaded but not dispatched" is indistinguishable from "not supported".

The missing piece is an argv-rewriting dispatch step performed before ExecuteContext (and therefore before Cobra parses arguments).

Exact fix

Rewrite argv[1] through cfg.Aliases at command-construction time, just before SetArgs.

internal/builtin/root.go

// NewRootCmd builds the root command. rawArgs is os.Args[1:] (program name
// already stripped). Aliases are resolved here so every entry point — the
// real binary and tests — gets identical dispatch semantics.
func NewRootCmd(cfg *config.Config, rawArgs []string) *cobra.Command {
    root := &cobra.Command{
        Use:           "openapi-cli",
        Short:         "OpenAPI CLI",
        SilenceUsage:  true,
        SilenceErrors: true,
    }

    root.AddCommand(newListCmd())
    root.AddCommand(newStatusCmd())

    // THE MISSING STEP: rewrite argv[1] from the config alias map before
    // Cobra parses it.
    root.SetArgs(ResolveAliases(root, rawArgs, cfg.Aliases))
    return root
}

// ResolveAliases rewrites argv[1] through the configured alias table.
// - flags (`--help`) pass through untouched;
// - real commands (and registered cobra aliases) win over config aliases, so
//   a stale alias can never shadow a built-in;
// - unknown tokens pass through and still produce a normal unknown-command
//   error (a typo stays a typo).
func ResolveAliases(root *cobra.Command, rawArgs []string, aliases map[string]string) []string {
    if len(rawArgs) == 0 || len(aliases) == 0 {
        return rawArgs
    }
    first := rawArgs[0]
    if len(first) > 0 && first[0] == '-' {
        return rawArgs
    }
    if isKnownCommand(root, first) {
        return rawArgs
    }
    target, ok := aliases[first]
    if !ok || target == "" {
        return rawArgs
    }
    out := make([]string, len(rawArgs))
    copy(out, rawArgs)
    out[0] = target
    return out
}

func isKnownCommand(root *cobra.Command, name string) bool {
    for _, c := range root.Commands() {
        if c.Name() == name || c.HasAlias(name) {
            return true
        }
    }
    return false
}

// Execute is the single production entry point.
func Execute(ctx context.Context, cfg *config.Config, rawArgs []string) error {
    root := NewRootCmd(cfg, rawArgs)
    return root.ExecuteContext(ctx)
}

cmd/openapi-cli/main.go

func main() {
    cfgPath := os.Getenv("OPENAPI_CLI_CONFIG")
    if cfgPath == "" {
        cfgPath = "openapi-cli.yaml"
    }
    cfg, err := config.Load(cfgPath)
    if err != nil {
        cfg = &config.Config{Aliases: map[string]string{}}
    }
    if err := builtin.Execute(context.Background(), cfg, os.Args[1:]); err != nil {
        fmt.Fprintln(os.Stderr, "error:", err)
        os.Exit(1)
    }
}

If the existing NewRootCmd signature must stay unchanged, do the rewrite at the call site instead — still before ExecuteContext:

go root := builtin.NewRootCmd(cfg) root.SetArgs(builtin.ResolveAliases(root, os.Args[1:], cfg.Aliases)) if err := root.ExecuteContext(ctx); err != nil { ... }

Docs / protocol follow-up

  • docs/guides/: state explicitly that aliases are resolved before Cobra dispatch, that real commands take precedence, and that unknown aliases still fail. A documented config key must describe a code path that actually runs.
  • pkg/protocol/: if the command catalog is exposed to clients, surface the resolved alias map (or the expanded command) so remote callers see the same names the local CLI accepts.

The rule this bug earns

Every config-driven behaviour needs a regression test that starts from a config file on disk. Hand-constructing a *Config struct in a test skips the loader and hides "loaded but not dispatched" bugs.

Verification

1. Regression test (internal/builtin/root_test.go)

func writeConfig(t *testing.T, body string) *config.Config {
    t.Helper()
    path := filepath.Join(t.TempDir(), "openapi-cli.yaml")
    if err := os.WriteFile(path, []byte(body), 0o600); err != nil {
        t.Fatalf("write config: %v", err)
    }
    cfg, err := config.Load(path) // really read the file from disk
    if err != nil {
        t.Fatalf("load config: %v", err)
    }
    return cfg
}

func run(t *testing.T, cfg *config.Config, args ...string) (string, error) {
    t.Helper()
    root := NewRootCmd(cfg, args)
    var out bytes.Buffer
    root.SetOut(&out)
    root.SetErr(&out)
    return out.String(), root.ExecuteContext(context.Background())
}

func TestAliasDispatchFromConfigFile(t *testing.T) {
    cfg := writeConfig(t, "aliases:\n  ls: list\n  st: status\n")

    out, err := run(t, cfg, "ls")
    if err != nil {
        t.Fatalf("alias `ls`: unexpected error: %v", err)
    }
    if !strings.Contains(out, "list: ok") {
        t.Fatalf("alias `ls` did not dispatch to list; output=%q", out)
    }
    // ... same for "st" -> "status"
}

The suite also covers: extra args forwarded, a real command not being shadowed by an alias, unknown commands still failing, and an empty config file.

  • [x] Real/registered commands are never shadowed by an alias.
