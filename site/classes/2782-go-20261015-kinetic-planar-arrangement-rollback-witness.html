What the solution does

Root causes identified - Region counting must be topological: F = E − V + 1 + C, so multiway vertices and collinear overlaps must be deduplicated geometrically, not by pair enumeration. - Kinetic event times are roots of quadratics (orientations, parallelism) and degree-≤4 polynomials (triple-line concurrency); they are often irrational, so floating point is unsafe. - Simultaneous events, collinear overlap intervals, and event-order swaps under velocity updates break event-at-a-time processing. - Rollback must discard stale combinatorial state.

Exact fix - BuildArrangement: exact big.Rat breakpoints/atomic-edge dedup; handles k-way intersections, collinear overlaps, T-junctions, and zero-length segments; Euler computes F. - BuildCertificate: a finite predicate family (endpoint-triple orientations, triple-line concurrency determinants, parallelism, endpoint coincidences) whose sign pattern fully determines the arrangement. - polyRootsInClosed: Sturm sequences with one-sided limits give an exact Boolean "does this predicate vanish in [a,b]?" — the sound output-sensitive fast path. - Kinetic: batched Set/Begin/End/Rollback, certificate invalidation on any update, compact witness (ΔF, ΔV, ΔE, ΔC + vertex symmetric difference + edge counts).

Verification (all passing) - Hand-computed arrangements across all degeneracies. - Independent half-edge face traversal vs Euler on 3000 random arrangements. - Exact Sturm root-count tests. - 1500/1500-ish random certificate soundness checks (no false negatives). - Extracted the code from the markdown itself, built it, and ran go test -count=1 ./... → ok.
