Answer

I diagnosed the flake, applied/verified the fix, and wrote the full solution to ~/solution.md.

Root cause

TestBringUpUserManager_LingerTimeoutRetriedUntilMarkerAppears drives the real bring-up through the userManagerRunner seam. The fake loginctl enable-linger applies the linger asynchronously, via a goroutine that sleeps lingerApplyDelay = 1ms and then writes the marker (internal/agent/rootless_runtimedir_test.go). Production polls for that marker with pollLingerMarker(..., lingerEnablePollWindow, ...).

The test installed per-attempt windows of 20 ms (retry case) and 80 ms (first-window case). Under scheduler starvation the 1 ms writer goroutine can be delayed far past 20 ms. Then attempt 1 expires structurally (the fake schedules no write before attempt N), attempt 2 schedules the write but its 20 ms poll expires before the writer runs, attempt 3 is issued (no second write scheduled) and its poll expires too — so the bounded 3-attempt sequence legitimately reports linger enable attempts: 3. Production retry logic was correct; only the test seam's timing slack was wrong.

Exact fix (internal/agent/rootless_runtimedir_test.go, test-only)

-           window:            80 * time.Millisecond,
+           window:            time.Second,
            wantAttempts:      1,
...
-           window:            20 * time.Millisecond,
+           window:            time.Second,
            wantAttempts:      2,

plus an explanatory comment. Early exit still works (pollLingerMarker checks the marker before every wait), wantAttempts is unaffected (attempt 1 in the retry case expires structurally regardless of window length), attempts stay bounded at 3, the existing 5 s elapsed assertion holds, and the negative control (..._WithoutMarkerStillFails, 10 ms window) is untouched. Production constants in rootless.go are unchanged.

Verification (on this host)

go build ./...   # exit 0
go vet ./...     # exit 0
go test ./internal/agent \
  -run 'TestBringUpUserManager_LingerTimeoutRetriedUntilMarkerAppears|TestBringUpUserManager_LingerTimeoutWithoutMarkerStillFails' \
  -count=20
# ok  github.com/deployBunker/bunker/internal/agent  20.984s

I also confirmed the mechanism deterministically by temporarily setting the fake async delay to 120 ms (emulating jitter): the old 20 ms window fails with linger enable attempts: 3, while the fixed 1 s window passes with attempts: 2.
