--attr values containing = are rejected as invalid JSON

Root Cause

The bug is in parseArgs in src/cli/human.ts (parseArgs splits named flags into key/value pairs):

const [key, value] = arg.slice(2).split("=");

String.prototype.split("=") splits on every = character, not just the first. Then array destructuring [key, value] keeps only the first two pieces: key becomes the flag name, and value becomes the segment up to the second =; everything after the second = is silently dropped.

For the failing example:

--attr={"board_state":"ticks_total=80","note":"works"}
  1. arg.slice(2) → attr={"board_state":"ticks_total=80","note":"works"}
  2. .split("=") → ["attr", "{\"board_state\":\"ticks_total", "80\",\"note\":\"works\"}"]
  3. Destructured value → {"board_state":"ticks_total" (the 2nd split segment)
  4. rememberCommand calls JSON.parse('{"board_state":"ticks_total') → throws
  5. Caught → Error: --attr must be valid JSON + process.exit(1)

The dropped =80"...} leaves the JSON unterminated/truncated, so any JSON whose value contains = fails. Workarounds (spaces/colons instead of =) avoid the issue but don't fix the parsing defect.

The Fix

Split on the first = only, using indexOf. This keeps key as everything before the first = and value as everything after — including any embedded =. Edit src/cli/human.ts, replacing the -- branch of the loop:

// src/cli/human.ts  (inside for loop in parseArgs)
if (arg.startsWith("--")) {
  const body = arg.slice(2);
  const eqIndex = body.indexOf("=");
  if (eqIndex === -1) {
    flags[body] = "true";
  } else {
    const key = body.slice(0, eqIndex);
    const value = body.slice(eqIndex + 1);
    flags[key] = value || "true";
  }
} else if (arg.startsWith("-")) {
  // Short flags
  flags[arg.slice(1)] = "true";
}

Behavior is preserved in all existing cases: - --foo → flags.foo = "true" (no =). - --foo=bar → flags.foo = "bar" (first = split). - --foo= → flags.foo = "true" (value || "true" kept). - --attr=<json-with-=> → full JSON string preserved.
