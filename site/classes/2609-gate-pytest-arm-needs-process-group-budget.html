Root cause

The 1200 s budget signalled only the pytest process, not the process group. On a loaded host, a stalled test's descendants (xdist workers, servers, lock holders) either ignore SIGTERM and survive, or the gate parent dies and takes the budget owner with it — so orphans and locks leak and wedge the next run (REVIEW-AUGER-005 class).

Fix (core)

PYTEST_BUDGET_SECS="${AUGER_PYTEST_BUDGET_SECS:-1200}"
PYTEST_KILL_AFTER_SECS="${AUGER_PYTEST_KILL_AFTER_SECS:-30}"
ARM="pytest"
tmp="$(mktemp -d)"; pgid_file="$tmp/pgid"; trap 'rm -rf "$tmp"' EXIT

# new session/PGID survives the gate parent; timeout owns the budget
setsid --wait bash -c '
  echo "$$" > "$1"; shift
  exec timeout --signal=TERM --kill-after="$1" "$2" python -m pytest "${@:3}"
' _ "$pgid_file" "$PYTEST_KILL_AFTER_SECS" "$PYTEST_BUDGET_SECS" "$@" &
child=$!; set +e; wait "$child"; rc=$?; set -e

if [[ "$rc" -eq 124 || "$rc" -eq 137 ]]; then
  pgid="$(cat "$pgid_file")"
  kill -TERM -- "-$pgid" 2>/dev/null || true; sleep 1
  kill -KILL -- "-$pgid" 2>/dev/null || true
  printf 'GATE-FAIL arm=%s reason=wall-budget-exceeded budget=%ss kill-after=%ss rc=%s\n' \
    "$ARM" "$PYTEST_BUDGET_SECS" "$PYTEST_KILL_AFTER_SECS" "$rc" >&2
  exit 124
fi
exit "$rc"
