Root cause (summary)

loadModelLibrary() fired all 60 model fetches in a single Promise.all burst with {cache:'no-store'}, and treated a dropped request as "model intentionally absent": if (!r.ok) return plus an empty catch. No retry, and the success toast was computed only from what loaded — the manifest's 60 was never compared, so Loaded 59 models shipped with zero signal. The drop itself is a one-off cold-load/CDN event (the same file loads 60/60 on reload).

Fix

Replaced the loader with one that: 1. Bounds concurrency — waves of 8 (mapWithPool) instead of a 60-way burst; 2. Retries per file — up to 3 tries with linear backoff + jitter, so a transient drop self-heals without aborting the pool; 3. Reconciles against the manifest — if anything is still missing, the toast is a red warning stating Partially loaded 59 of 60 models — missing: <ids> instead of a silent success line.

Helpers are nested inside loadModelLibrary() so the build-standalone.js splice still yields a fetch()-free standalone (verified: 60 models embedded, 0 fetch() calls).
