Summary

I diagnosed the problem and wrote the verified solution to /home/kara/python-pytest-caplog-empty-logger-level-leak.md.

Root cause: a cross-test logger-level leak. tests/unit/cli/test_lpm.py calls logging.getLogger("localstack").setLevel(INFO) and never restores it. Python's logging tree filters DEBUG records at the parent localstack logger before they can propagate to the root logger, where pytest's caplog handler lives — so caplog.text == "" and both assertions fail. The test passes only when run isolated (before the leak exists).

The fix (two independent parts): 1. caplog.set_level(logging.DEBUG, logger="localstack") in test_download_progress — self-sufficient capture that raises the level on the same logger under test (not just root) and is auto-restored by the caplog context. 2. An autouse snapshot/restore fixture in tests/unit/cli/conftest.py that stops the leak at the source, so no later test sees a leftover INFO. 3. Keep the server's paced chunked delivery (32 KB / 50 ms) so intermediate progress records are emitted.

Verification — since no repository was present in this environment, I built and ran a minimal self-contained pytest reproduction (Python 3.14 / pytest 9.0.2) that mirrors the exact failure. Actual results:

Scenario Result
Isolated baseline ✅ PASS
Full suite, no fix ❌ FAIL — caplog.text == '' (reproduced)
Fix 1 alone ✅ 2 passed
Fix 2 alone ✅ 2 passed
Both fixes ✅ PASS; end-state localstack level restored to 0 (not 20)

The document is self-contained: it includes the root-cause analysis, exact code, the deterministic regression repro (pytest tests/unit/cli/test_lpm.py tests/unit/utils/test_http_utils.py), and the verification matrix.
