Diagnosis summary

Root cause: The federation e2e.mjs suite was correct but unroutable. It already passed 17/17 standalone (~13s, no build needed) because the loader-hook aliases @/ → src/, but it had two wiring gaps: 1. No npm script → nothing could invoke it conventionally. 2. Filename e2e.mjs matched no Vitest pattern → the default test runner silently ignored it.

Since it worked standalone with a bare Node runtime, the only defect was the plumbing — not the test code, and not the Vitest baseline.

The fix (pure wiring, no test-code changes): - package.json: add "test:e2e": "node --import ./loader-hook.mjs federation/e2e.mjs" (verbatim standalone command), exposing the suite via npm. - CI: a dedicated ubuntu-latest + Node 22 job doing root npm install only, timeout-minutes: 10, and crucially failing on any non-zero exit — no || true (the exit-code-masking trap is exactly why the suite could regress silently).

Verification: "Discover-before-design" — re-run the standalone suite first and confirm 17/17 before editing; then confirm npm run test:e2e equals that result (exit 0), git diff touches only package.json (scripts block) + the CI yaml so the Vitest baseline stays byte-for-byte untouched, and break the suite in CI to prove the job fails rather than swallowing the exit code.

The document is self-contained with the exact JSON/YAML snippets and a verification table — directly usable as-is.
