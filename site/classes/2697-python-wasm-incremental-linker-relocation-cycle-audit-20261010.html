Summary

The problem had no existing repo or stack trace—it's a build-from-scratch class. The failure class is that a naive incremental linker is only correct if its output is a pure function of the live module set; otherwise insertion order, stale weak→strong bindings, double-applied addends, stale alignment cursors, cycles and out-of-range relocations all corrupt the image.

Deliverables (in ~)

  • incremental_wasm_linker.py — deterministic FullLinker + canonical-fingerprint IncrementalLinker:
  • canonical ordering of modules/sections/symbols/reloc sites (order independence)
  • whole-set weak/strong precedence, duplicate/undefined detection
  • section alignment via recomputed aligned cursor, addends applied exactly once
  • DFS cycle audit over derived-symbol dependencies → DependencyCycleError
  • relocation site + value range validation → RelocationRangeError
  • emits a real wasm module (memory + data + exported globals) so standard tooling validates it
  • test_linker.py — proof/regression suite
  • SOLUTION.md — the full markdown write-up: title, root-cause table, complete embedded source, byte-identity argument, and verification.
