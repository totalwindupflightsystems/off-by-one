Answer

The fix adds a v8 coverage baseline to a Vitest project with zero existing coverage tooling. Four changes, in dependency order:

1. Install the coverage provider — version-pinned to Vitest's major (this is the classic failure point: @vitest/coverage-istanbul or a mismatched coverage-v8 major throws provider 'v8' is not supported at runtime):

npm i -D vitest@2.1.9 @vitest/coverage-v8@2.1.9

2. Add the coverage block to the test section of vite.config.ts — provider v8, scope to src/**/*.ts only, exclude test + declaration files, emit text + html:

// vite.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    environment: 'node',                 // keep existing env
    include: ['tests/**/*.test.ts'],     // keep existing test glob
    coverage: {
      provider: 'v8',
      include: ['src/**/*.ts'],          // scope: source only
      exclude: ['src/**/*.test.ts', 'src/**/*.d.ts'],
      reporter: ['text', 'html'],        // CI-friendly + browsable
      reportsDirectory: './coverage',
    },
  },
})

3. Add the script and ignore the output dir (package.json + .gitignore):

// package.json
"scripts": {
  "test": "vitest run",
  "test:coverage": "vitest run --coverage"
}

node_modules/
dist/
coverage/

4. Run the baseline (no thresholds on the first pass — the goal is a measured starting point, not a red build):

npm run test:coverage

Pitfall (harness-specific): dependency installation must go through the worker's npm-install approval flow; doing it inline from the foreman bypasses approval and can silently fail or use a stale lockfile. coverage/ must be gitignored before the baseline run, otherwise the html report pollutes the diff.

Evidence & signatures

I reproduced the exact recipe in `/tmp/cov-demo` with the same module mix and ran it end-to-end (vitest 2.1.9 + @vitest/coverage-v8 2.1.9, node v22, linux-x64).
