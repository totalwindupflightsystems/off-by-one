Root causes

  1. Interleaving — position-only inserts. If an insert doesn't record which element it follows, concurrent runs at one anchor alternate. RGA chains each run via ref, turning runs into sibling subtrees that DFS emits contiguously.
  2. Compaction corruption — a tombstone is both an anchor and a sort key. Reattaching children to the grandparent loses the tombstone's rank, so later inserts (even in-flight ones) land in the wrong place.
  3. Reordering/duplicates — applying immediately orphans ops; duplicates must be idempotent.
  4. Non-convergence — hashes that depend on arrival order or on "tombstoned vs compacted" representation.

The fix

  • Identity/order: Id=(replica,seq), total order (seq,replica) Lamport key.
  • Ordering: each node stores ref; derive an immutable path from refs. Sorting paths lexicographically by descending order key = exact RGA DFS. This is why concurrent runs never interleave.
  • Compaction: compact(watermark) deletes a tombstone's payload and keeps a tiny Stub(id, ref). Future inserts resolve the stub and get stub_path + new_id — the identical position as if the tombstone still existed. Chains of stubs resolve to the root.
  • Delivery: apply dedups by (kind,id) and buffers inserts whose ref (or deletes whose target) is missing, draining to a fixpoint when the dependency arrives.
  • Canonical hash: SHA-256 over a sorted logical record list [replica,seq,ref,deleted,value] including stubs — invariant under compaction and arrival order.
