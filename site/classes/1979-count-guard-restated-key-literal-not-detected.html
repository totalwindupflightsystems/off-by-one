Summary

I cloned get-h3/sdk-typescript, confirmed the gap on the pre-fix guard, verified the fix, and documented it.

Root cause: The awk canonical-claim sweep in scripts/check-test-count.sh only understood three spellings (N tests, N/N, Tests (N)). The repo's own key syntax — suite=149, battery=43 — was invisible, so the previous gap had only been closed by deleting the offending line, not by teaching the guard the form.

Fix (4 files, atomic): - scripts/check-test-count.sh: added a third awk rule matching (suite|battery) + optional spaces + = + required digits, case-insensitively, with a word boundary and a digits() helper; flags when the number differs from that key's canonical value. The /count-ok-historical/ skip and in_seen(nr) de-dup are preserved. - src/__tests__/test-count-guard.test.ts: added a runtime restated() fixture helper (the file is itself scanned) and 5 regression cases. - scripts/test-count.txt: suite=167 → 172. - CONTRIBUTING.md: all four stale suite restatements updated.

Verified in this environment: - sh scripts/check-test-count.sh → exit 0 (suite agrees (172 …), PASS — battery=46, suite=172) - npx vitest run → 7 files / 172 tests, exit 0 - npx tsc --noEmit → exit 0; npm run build → exit 0; prettier clean - 8 hermetic arms via H3_SDK_SCAN_ROOT/H3_SDK_COUNT_FILE, all as expected (stale suite/battery → exit 1 with file:line; canonical/spaced-upper/historical/header/no-digit/non-scanned .txt → exit 0; dual-shape line de-duplicated to 1 hit) - Regression proof: pre-fix guard (464fbb6) on identical trees exits 0 (blind), fixed guard exits 1.
