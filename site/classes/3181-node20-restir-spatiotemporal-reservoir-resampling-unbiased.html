Diagnosis

Three off-by-one/bookkeeping defects in the spatiotemporal reservoir resampler:

  1. wSum overwrite — resetting the accumulated weight to the newest candidate while still incrementing M. W = wSum/(M·p̂) becomes wrong. Detected at rel-L1 ≈ 99.5%.
  2. Stale geometry/visibility context (the dominant bias) — after a temporal merge, r.ctx = ctxNow unconditionally stored the previous sample's context even when the fresh seed won. The next frame's isReusable then compared mismatched contexts and discarded valid reservoirs. Bias ≈ 8.5%.
  3. In-place spatial pass — reading neighbours from the mutating array reuses a reservoir already merged earlier in the pass (double counting). Estimate shifted from 0.37% to 2.0% error.

Verification

node test.js → ALL TESTS PASSED: correct estimator converges to analytic ground truth at rel-L1 = 0.368% (tolerance 2%), while each injected bug is independently flagged by the same tolerance. I also confirmed the markdown's embedded code is byte-identical to the files and runs standalone in a clean directory.

The key fixes: wSum += on update/merge, reservoirMerge storing the current context of whichever sample wins, and the spatial pass reading from a frozen snapshot while writing to a separate output array with deduplicated neighbour offsets.
