Bunker QA Launch: Silent Foreground SIGTERM While Waiting on the Per-Server Battery Lock

Problem class: bunker-qa-launch-sigterm-lock-wait-silent-refusal Component: ~/.hermes/scripts/bunker-qa.sh (launch), fleet JIT agents over ssh/tailscale Board row: QA-TROUBLE-FOREMAN-2

Full document written to /tmp/qa-repro/SOLUTION.md. Summary:

Root cause

The launcher serializes batteries per server with a shared blocking lock:

exec 9>"/tmp/bunker-qa-<server>.battery.lock"
flock 9          # blocking, SILENT

Two defects combine: - D1 (invocation): a foreground launch under the terminal tool's ~180 s timeout cannot survive a contended wait — the tool SIGTERMs it at 180 s (observed 20:05:26Z → 20:08:26Z). - D2 (observability): flock prints nothing while waiting, and the TERM trap writes only an evidence-JSONL row (agent=""). So stdout shows neither LAUNCHED nor ERROR — a silent refusal.

Exact fix

Primary (procedural, no edit): launch detached with a redirected log, then poll for a marker:

LOG=/tmp/bunker-qa-<server>-$(date -u +%Y%m%dT%H%M%SZ).launch.log
setsid bunker-qa.sh launch <repo-dir> >"$LOG" 2>&1 </dev/null &
for i in $(seq 1 90); do grep -Eq 'LAUNCHED|ERROR' "$LOG" && break; sleep 2; done
grep -E 'LAUNCHED|ERROR' "$LOG" | head -1

A reusable qa-launch-bg.sh wrapper is in the full doc; it also falls back to printing the newest trap evidence if no marker appears.

Hardening (recommended, 3 lines): print WAITING on battery lock ... before flock 9, and mirror the trap message to stdout:

printf 'ERROR: %s\n' "$trap_msg"

After this, the launcher always emits exactly one of LAUNCHED/ERROR, even on a timeout kill.

After-the-fact detection: grep the newest /tmp/bunker-qa-evidence-*.jsonl for "kind":"FAIL" and check .meta for agent= empty.

Verification (actually run in this sandbox)

Since bunker-qa.sh was absent, I verified against a faithful minimal repro of its lock/trap contract:

Test Result
Foreground + contended lock under timeout --signal=TERM 6 rc=124, no LAUNCHED/ERROR, one FAIL row with agent="" — bug reproduced
Background + free lock (setsid ... >log &) LAUNCHED in ~2 s with a non-empty agent — procedural fix verified
Patched launcher, foreground + contended WAITING on battery lock ... then ERROR: launch terminated by SIGTERM ... — observability fix verified

This matches the production proof chain: foreground+contended = silent SIGTERM at 180 s (empty agent); background+free lock = LAUNCHED with agent=4b8b03ae, launch_exit=0, remote qa-run.sh live at HEAD 04aca3f. Same launcher/server/repo — only lock state and foreground-vs-background changed.

Operator rule: never invoke launch foreground under a tool timeout; treat a missing marker as a failed launch and inspect the evidence JSONL.
