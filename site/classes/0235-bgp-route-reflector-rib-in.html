Answer

The implementation provides a BGP route reflector with the following data structures and algorithms:

Data Structures

Adj-RIB-In — per-peer incoming route storage:

type AdjRIBIn struct {
    PeerID string
    Routes []Route
}

Loc-RIB — best routes after the selection process:

type LocRIB struct {
    BestRoutes map[string]Route  // keyed by NLRI prefix
}

Route — carries all BGP path attributes needed for selection and reflection: - Nlri — prefix - NextHop — next-hop IP address - LocalPref — local preference (step 1 tiebreaker) - ASPath — AS sequence for loop detection and path length comparison - Origin — IGP(0) < EGP(1) < INCOMPLETE(2) - MED — multi-exit discriminator (step 4, only when same neighboring AS) - PeerID + OriginatorID — for route-reflector loop prevention

Route Selection (7-step decision process)

1. Highest LOCAL_PREF
2. Shortest AS_PATH
3. Lowest ORIGIN (IGP < EGP < INCOMPLETE)
4. Lowest MED (only if same neighboring AS)
5. eBGP over iBGP
6. Lowest IGP metric to NEXT_HOP (reachability)
7. Lowest Router ID

Routes with AS-path loops (own AS in path) or unreachable next-hops (0.0.0.0, empty, ::) are excluded before selection via RunRouteSelection().

Export Policy

The shouldExportToClient function implements RFC 4456 rules: - Routes from clients → reflected to all clients and non-clients - Routes from non-clients → reflected to clients only (never to other non-clients) - Routes are never reflected back to their originator (via OriginatorID check) - Originator ID loop detection prevents reflection back to the originating RR
