e2e-output-contract-prompt-mismatch

Answer

Root cause (tick 43): the worker compared engine output against a hand-written contract that demanded 2 lines, but the fixture source that was actually executed printed 1 line. trigger=none lives in the canonical flow source (print(6 * 7)\nprint("trigger=none")), not in engine output. The engine never regressed — the fixture/contract did. BUG-001 was a false positive.

The fix — baseline-first triage. Before any regression is filed, derive the truth from the fixture source itself by running it with the bare interpreter (no engine), and only then run the engine. Order of checks:

  1. baseline = run(fixture_source) — engine-independent truth
  2. baseline != contract → CONTRACT/FIXTURE bug (false-positive class) — fix the fixture or regenerate the contract; engine never runs
  3. engine_output != baseline → REAL engine regression — now file BUG
def check_contract(flow_path, contract, engine_cli):
    # Step 1: baseline BEFORE the engine — the tick-43 guard.
    baseline_lines = normalize(run_baseline(flow_path))   # bare interpreter
    if baseline_lines != contract.expected_lines:
        raise ContractError(
            "CONTRACT/FIXTURE bug (false-positive class, do NOT file a regression):\n"
            + diagnose(flow_path, contract, baseline_lines)
            + "\nFlow source must contain every expected line, or regenerate "
              "the contract with generate_contract().")
    # Step 2: only now run the engine; CLI prints exactly engine output.
    engine_lines = normalize(run_engine(flow_path, engine_cli))
    if engine_lines != baseline_lines:
        raise ContractError("REAL ENGINE regression: ...")
    return "passed"

def generate_contract(flow_path):      # derive, never hand-maintain
    return OutputContract(flow_path, normalize(run_baseline(flow_path)))

Fixture-side fix (the actual correction for tick 43):

# flows/tick_43.py  — canonical source; every contract line must be printed here
print(6 * 7)
print("trigger=none")

Two supporting rules the guard enforces: (a) "42" is a computed line (6 * 7), so only the baseline run can prove it — a static line in source scan alone would false-flag it; (b) compare line lists via splitlines() (drops terminal newline, keeps interior blanks, tolerates \r\n), and stdout only — stderr noise never enters the contract. A musterflow_triage() entry point reproduces the worker's run and returns FALSE POSITIVE / CONTRACT-FIXTURE vs BUG / ENGINE so the foreman's verdict is automated, not manual.
