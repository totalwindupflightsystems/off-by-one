Fully Dynamic MST with Link-Cut Trees: Null-Sentinel Collision and Preferred-Path Invariants

Root-cause analysis

The actual bug — null sentinel collides with graph vertex 0. A link-cut tree uses node 0 as the null sentinel. The natural-but-wrong setup allocates nodes 0..n and maps graph vertex v to node v, making vertex 0 the same node as null. It silently corrupts after ≥2 operations: node 0 acquires real splay children while isRoot(x) still returns true for them, so rotations skip parent updates and the preferred-path decomposition desynchronizes. Symptoms: PathMax(a,b) returns an edge not on a..b, Connected is wrong after evert, and the forest accumulates cycles.

Reproduced on vertices {0,1,2} with edges 0-1 (w=5), 1-2 (w=1):

PathMax(0,1) = (5,id0)
PathMax(1,2) = (5,id0)   <-- WRONG, should be (1,id1)

Exact fix: reserve node 0 exclusively for null; store vertex v at LCT node v+1. The DynamicMST layer applies the offset at every call boundary (FindRoot(u+1), Link(u+1, e.node), PathMax(u+1, v+1), Cut(e.U+1, ...), …).

Secondary invariants also covered: - best[x] must be recomputed by pushup after every structural change; it is reversal-invariant, so it's safe across lazy evert. - splay must push lazy tags top-down before any rotation; FindRoot pushes before descending left. - Deterministic tie-breaking needs a total order (weight, id): path max = largest; insert replaces only if w < wmax || (w == wmax && id < idmax); replacement = smallest crossing edge. - Insertions use the cycle property, deletions the cut property.

Exact fix (core)

// NewLCT reserves node 0 for null; graph vertex v lives at node v+1.
func (d *DynamicMST) Insert(id, u, v int, w int64) {
    e := &Edge{ID: id, U: u, V: v, W: w, node: d.L.AddNode(w, id)}
    d.Edges[id] = e
    if d.L.FindRoot(u+1) != d.L.FindRoot(v+1) {   // different components
        d.L.Link(u+1, e.node); d.L.Link(e.node, v+1); e.inTree = true; return
    }
    _, maxID, _ := d.L.PathMax(u+1, v+1)          // cycle property
    if maxID >= 0 {
        max := d.Edges[maxID]
        if w < max.W || (w == max.W && id < max.ID) {
            d.cutTreeEdge(max); d.NonTree[maxID] = max
            d.L.Link(u+1, e.node); d.L.Link(e.node, v+1); e.inTree = true; return
        }
    }
    d.NonTree[id] = e
}

func (d *DynamicMST) Delete(id int) (int, bool) {
    e, ok := d.Edges[id]; if !ok { return 0, false }
    delete(d.Edges, id)
    if !e.inTree { delete(d.NonTree, id); return 0, false }
    d.cutTreeEdge(e)                              // cut property
    var best *Edge
    for _, f := range d.NonTree {
        if d.L.FindRoot(f.U+1) != d.L.FindRoot(f.V+1) {
            if best == nil || f.W < best.W || (f.W == best.W && f.ID < best.ID) { best = f }
        }
    }
    if best == nil { return 0, false }
    delete(d.NonTree, best.ID)
    d.L.Link(best.U+1, best.node); d.L.Link(best.node, best.V+1); best.inTree = true
    return best.ID, true
}

One honesty note on complexity: each LCT primitive is O(log n) amortized and insertion is O(log n); the deletion replacement step scans the maintained non-tree set, so it is O(k log n) for k non-tree edges. The document notes that layering the Holm–de Lichtenberg–Thorup weight hierarchy on top makes replacement polylogarithmic without changing any of the invariants above.
