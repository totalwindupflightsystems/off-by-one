Fix: bunker-qa.sh ci-pass runs infra-gated workflows under act

Root-cause analysis

bunker-qa.sh ci-pass generated a remote script via build_remote_script and ran the local CI emulator with no workflow selector:

act

act with no -W/--workflows argument discovers and runs every workflow file in .github/workflows/. On the affected repo that directory contains not just ci.yml but also an infra-gated ghcr publish workflow. The publish workflow needs registry credentials / network / publish permissions the bracketed QA sandbox does not have, so it fails deterministically. Because act aborts on the first failing workflow, ci-pass stayed red even though hosted CI was green at the exact same HEAD (hosted CI either runs only ci.yml or gates the publish job behind repo-level secrets/environments).

This is an environment-gating problem, not a code defect: the same commit is green where the required infra exists and red where it does not. The harness was ascribing the infra-gated publish failure to the code under test.

Two secondary issues made this hard to see and easy to regress:

  1. The detection of "what is CI" lived inline, untestable on the host.
  2. build_remote_script must expand the chosen command at generation time; it relies on an unquoted heredoc. Changing <<EOF to <<'EOF' would silently ship the literal string $ci_cmd to the remote and break the fix (verified below).

Exact fix

Add a single host-side detection function, use it everywhere the CI command is needed, and expose it as a debug subcommand so it can be tested without booting a sandbox.

# Native CI suite used only when the repo has no GitHub workflows at all.
NATIVE_TEST_CMD="${NATIVE_TEST_CMD:-make test}"   # e.g. "go test ./..." for Go repos

# detect_cmds <repo>
#   Echo the CI command for <repo>:
#     - repo has .github/workflows/ci.yml        -> act -W <repo>/.github/workflows/ci.yml
#     - workflows exist but no ci.yml            -> act            (unfiltered fallback)
#     - no .github/workflows at all              -> $NATIVE_TEST_CMD (native suite)
detect_cmds() {
  local repo="${1:?detect_cmds: repo path required}"
  local wf_dir="$repo/.github/workflows"

  if [[ -f "$wf_dir/ci.yml" ]]; then
    printf 'act -W %s/ci.yml\n' "$wf_dir"
  elif [[ -d "$wf_dir" ]] && {
         compgen -G "$wf_dir/*.yml"  >/dev/null ||
         compgen -G "$wf_dir/*.yaml" >/dev/null
       }; then
    printf 'act\n'
  else
    printf '%s\n' "$NATIVE_TEST_CMD"
  fi
}

Wire it into the remote-script builder. Keep the heredoc unquoted so $ci_cmd expands while the script is generated (reviewer guard comment added deliberately):

build_remote_script() {
  local repo="$1"
  local ci_cmd
  ci_cmd="$(detect_cmds "$repo")"

  # UNQUOTED <<EOF is intentional: $ci_cmd MUST expand at generation time.
  # Do NOT change to <<'EOF' or the remote receives the literal "$ci_cmd".
  cat <<EOF
set -euo pipefail
cd "$repo"
$ci_cmd
EOF
}

Expose the detection layer for host-side testing:

case "${1:-}" in
  ci-pass)         shift; run_ci_pass "$@" ;;
  __detect-cmds)   shift; detect_cmds "${1:-$PWD}" ;;
  # ... existing subcommands ...
esac

Net effect on the reported repo: act → act -W "$repo/.github/workflows/ci.yml", so only the real CI workflow runs and infra-gated publishes are ignored.

Hardening note: if the repo path can contain spaces, emit printf 'act -W %q\n' "$wf_dir/ci.yml" instead, or quote -W "$wf_dir/ci.yml".

Verification

1. Build fixtures

rm -rf /tmp/qafix && mkdir -p /tmp/qafix && cd /tmp/qafix
mkdir -p ci/.github/workflows ci-noci/.github/workflows nowf
printf 'name: ci\non: [push]\n'            > ci/.github/workflows/ci.yml
printf 'name: ghcr publish\non: [push]\n'  > ci/.github/workflows/ghcr-publish.yml
printf 'name: ghcr publish\non: [push]\n'  > ci-noci/.github/workflows/ghcr.yml

ci/ = a CI repo that also has an infra-gated publish workflow (the failure case). ci-noci/ = workflows but no ci.yml. nowf/ = no workflows.

2. Probe the detection layer

echo "ci.yml repo     : $(./harness.sh __detect-cmds ci)"
echo "workflows no ci : $(./harness.sh __detect-cmds ci-noci)"
echo "no workflows    : $(./harness.sh __detect-cmds nowf)"

Observed:

ci.yml repo     : act -W ci/.github/workflows/ci.yml
workflows no ci : act
no workflows    : make test

3. Generated remote scripts

--- ci ---
set -euo pipefail
cd "ci"
act -W ci/.github/workflows/ci.yml

--- ci-noci ---
set -euo pipefail
cd "ci-noci"
act

--- nowf ---
set -euo pipefail
cd "nowf"
make test

4. Pre-fix failure and heredoc plumbing

== BUGGY (pre-fix) generated script for ci.yml repo ==
set -euo pipefail
cd "ci"
act

Counterfactual with a quoted heredoc (<<'EOF') leaves the variable unexpanded, shipping literal shell to the remote — proving the unquoted heredoc is load-bearing:

== counterfactual: quoted heredoc leaves $ci_cmd unexpanded ==
set -euo pipefail
cd "$repo"
$ci_cmd

5. Live probes on the real repo

bunker-qa.sh __detect-cmds /path/to/repo   # before -> act
bunker-qa.sh __detect-cmds /path/to/repo   # after  -> act -W /path/to/repo/.github/workflows/ci.yml
bunker-qa.sh ci-pass                        # green at the same HEAD hosted CI was green

Why this is correct

  • ci-pass now mirrors hosted CI's workflow selection instead of "everything".
  • Infra-gated publish workflows are excluded from the sandbox verdict.
  • Behavior is defined for all three repo shapes (scoped / fallback / native).
  • Detection is host-testable (__detect-cmds), so a regression is caught by fixture tests.
  • The unquoted-heredoc requirement is documented exactly where a future edit would break it.
