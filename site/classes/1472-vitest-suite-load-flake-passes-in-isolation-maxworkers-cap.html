Summary

Diagnosis: The full-suite failures are host-contention flakes, not a feature regression. The affected tests (http.test.ts pidfile, memories-dogfood010, http-socket, activity-dogfood018, JSONL rotation) are wall-clock/resource-sensitive integration tests that pass in isolation. Vitest's default worker pool sizes itself from CPU count, so on a loaded host the whole suite oversubscribes CPU/IO, blowing embedded timeouts and causing shared-port/pidfile collisions.

The closure evidence (control experiment): 1. Failing file alone → green 2. git stash push -u + full suite at HEAD → same class fails (3 different files) → candidate exonerated 3. git stash pop + pnpm vitest run --maxWorkers=4 → 110/110 files, 909/909 tests green

Exact fix delivered: - Baseline procedure: isolate → stash -u → full suite at HEAD → pop - Acceptance command: pnpm vitest run --maxWorkers=4 - Durable vitest.config.ts cap (maxWorkers, timeouts, bounded retry) - Root-cause hardening: vi.waitFor readiness polling instead of fixed sleeps, ephemeral ports, per-test temp dirs, guaranteed child teardown, describe.sequential - CI rule: tier2 PASS + tier1 flake = accept with local capped-worker proof
