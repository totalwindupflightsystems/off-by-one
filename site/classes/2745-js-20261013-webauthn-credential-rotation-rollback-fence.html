Multi-Region WebAuthn Passkey Credential Rotation with a Rollback Fence

Problem class: js-20261013-webauthn-credential-rotation-rollback-fence Runtime: Node 20+ (uses node:test; no external dependencies)

1. Root-Cause Analysis

A multi-region passkey service accepts two mutating operations against a credential id:

  • register — add/rotate a passkey (WebAuthn public key + counter)
  • revoke — permanently disable a passkey

Each region emits events, replicates them to peers, and retries on failure. The network therefore delivers duplicates, retries, and stale updates out of order. The failures this produces are not random; they come from four concrete root causes:

  1. Last-write-wins by wall clock is unsound. Regions have skewed clocks. A register generated before a revoke can carry a later issuedAt (or simply arrive later) and overwrite the revocation. This is the resurrection bug: a revoked credential becomes active again.

  2. Ordering by delivery is non-deterministic. If each replica processes events in arrival order, two replicas seeing the same set of events in different orders reach different states. There is no convergence.

  3. Retries are not idempotent. A redelivered register or revoke must not create a second effect or bump a version.

  4. Whole-list replacement destroys concurrent additions. If state is stored as "the current list of credentials" and updated with LWW, revoking one credential in region A can erase a credential concurrently added in region B.

The key insight: safety (never resurrect) and liveness (keep valid concurrent additions) are two different requirements, and they must not be conflated into one timestamp comparison. Safety must be a monotone property of the state, while concurrent additions must be per-credential and independent.

2. The Fix — Epoch State Machine + Join-Semilattice

2.1 Event shape

{
  "eventId": "us-east:000123",  // globally unique; idempotency key
  "credentialId": "passkey-A",  // partition key
  "type": "register" | "revoke",
  "epoch": 7,                    // per-credential logical version (monotonic)
  "data": { "publicKey": "...", "algorithm": "ES256" },
  "region": "us-east",
  "lamport": 42,                 // origin logical clock (audit ordering)
  "issuedAt": 1700000000         // informational ONLY — never used for ordering
}

issuedAt is deliberately ignored for conflict resolution. Ordering uses (epoch, eventId) for registrations and revoke as an absorbing terminal.

2.2 Per-credential state machine

ABSENT  --register(epoch)----->  ACTIVE
ACTIVE  --register(> epoch)--->  ACTIVE        (rotation)
ACTIVE  --register(<= epoch)-->  ACTIVE        (stale, ignored for status)
ACTIVE  --revoke(epoch)------->  REVOKED       (fence = epoch)
ABSENT  --revoke(epoch)------->  REVOKED       (tombstone-first)
REVOKED --anything------------>  REVOKED       (absorbing / top)

2.3 Deterministic conflict resolution (the join)

Per credential, state is a small lattice value { revoked, fenceEpoch, active }:

  • revoked = a.revoked || b.revoked → REVOKED is the top element, so it absorbs every later value. This is what makes resurrection structurally impossible, not merely policy-checked.
  • fenceEpoch = max(a.fenceEpoch, b.fenceEpoch) → the rollback fence. Any registration with epoch <= fenceEpoch is provably a pre-revocation update that was merely delayed, and is rejected as revoked-fence. A registration with epoch > fenceEpoch is rejected as credential-tombstoned (credential ids are single-use; re-enrollment must use a new id — which is preserved as a normal concurrent addition).
  • active = max((a.active, b.active)) by (epoch, eventId) → deterministic rotation winner for the same id, independent of arrival order.

The join is commutative, associative, and idempotent, so replicas converge and retries are free. Because state is keyed by credentialId, revoking one id cannot touch any other id — concurrent additions are preserved.

2.4 Auditable replay log

Every event is validated, deduplicated by eventId (with a payload fingerprint to catch id reuse), and recorded. exportReplay() returns the unique valid events in a canonical order (credentialId, epoch, revoke-before-register, eventId). Feeding that log back into a fresh ledger reproduces a byte-identical SHA-256 state hash on every replica — this is the deterministic audit artifact.

3. Exact Fix (code)

'use strict';

/**
 * Multi-region WebAuthn passkey credential ledger.
 *
 * Design goals
 * ------------
 *  - Converge despite duplicates, retries and arbitrary (out-of-order) delivery.
 *  - A revoked credential id can NEVER be resurrected (fail-closed tombstone).
 *  - Concurrent additions of *distinct* credential ids are always preserved.
 *  - Every accepted event is written to a deterministic, replayable audit log.
 *
 * The state is a join-semilattice (a state-based CRDT), so `merge` is
 * commutative, associative and idempotent. Replaying the same set of events in
 * any order therefore yields byte-identical state.
 *
 * Per-credential state machine (epoch = per-credential logical version):
 *
 *      ABSENT  --register(epoch)----->  ACTIVE
 *      ACTIVE  --register(> epoch)--->  ACTIVE        (rotation)
 *      ACTIVE  --register(<= epoch)-->  ACTIVE        (stale, ignored for status)
 *      ACTIVE  --revoke(epoch)------->  REVOKED       (fence = epoch)
 *      ABSENT  --revoke(epoch)------->  REVOKED       (tombstone-first)
 *      REVOKED --anything------------>  REVOKED       (absorbing / top)
 *
 * `REVOKED` is the top element of the lattice, which is what makes
 * resurrection structurally impossible rather than merely policy-enforced.
 */

const crypto = require('crypto');

const REGISTER = 'register';
const REVOKE = 'revoke';

/** Audit reasons (stable strings, safe to parse downstream). */
const REASON = Object.freeze({
  APPLIED: 'applied',
  ROTATED: 'rotated',
  STALE: 'stale-epoch',
  FENCED: 'revoked-fence',
  TOMBSTONED: 'credential-tombstoned',
  DUPLICATE: 'duplicate-retry',
  CONFLICT: 'duplicate-conflict',
  INVALID: 'invalid-event',
  NOOP: 'already-revoked',
});

/** Deterministic total order on register revisions: [epoch, eventId]. */
function cmpRevision(a, b) {
  if (a[0] !== b[0]) return a[0] - b[0];
  if (a[1] < b[1]) return -1;
  if (a[1] > b[1]) return 1;
  return 0;
}

/** Stable, key-sorted JSON (so hashes do not depend on insertion order). */
function canonical(value) {
  if (value === null || typeof value !== 'object') return JSON.stringify(value);
  if (Array.isArray(value)) return '[' + value.map(canonical).join(',') + ']';
  const keys = Object.keys(value).sort();
  return (
    '{' +
    keys.map((k) => JSON.stringify(k) + ':' + canonical(value[k])).join(',') +
    '}'
  );
}

function sha256(text) {
  return crypto.createHash('sha256').update(text).digest('hex');
}

/** Identity of an event's semantic content, used to detect id-reuse conflicts. */
function fingerprint(event) {
  return sha256(
    canonical({
      eventId: event.eventId,
      credentialId: event.credentialId,
      type: event.type,
      epoch: event.epoch,
      data: event.data === undefined ? null : event.data,
    }),
  );
}

function typeRank(type) {
  // revoke sorts before register at the same epoch so replay is deterministic
  return type === REVOKE ? 0 : 1;
}

/**
 * Validate + normalize an inbound event. Wall-clock fields (`issuedAt`) are
 * intentionally retained for humans but never used for ordering.
 */
function normalizeEvent(raw) {
  if (!raw || typeof raw !== 'object') {
    return { ok: false, reason: 'event is not an object' };
  }
  const { eventId, credentialId, type, epoch } = raw;
  if (typeof eventId !== 'string' || eventId.length === 0) {
    return { ok: false, reason: 'eventId must be a non-empty string' };
  }
  if (typeof credentialId !== 'string' || credentialId.length === 0) {
    return { ok: false, reason: 'credentialId must be a non-empty string' };
  }
  if (type !== REGISTER && type !== REVOKE) {
    return { ok: false, reason: 'type must be register|revoke' };
  }
  if (!Number.isInteger(epoch) || epoch < 0) {
    return { ok: false, reason: 'epoch must be a non-negative integer' };
  }
  if (type === REGISTER && (raw.data === undefined || raw.data === null)) {
    return { ok: false, reason: 'register requires data' };
  }
  return {
    ok: true,
    value: {
      eventId,
      credentialId,
      type,
      epoch,
      data: raw.data === undefined ? null : raw.data,
      region: typeof raw.region === 'string' ? raw.region : null,
      lamport: Number.isInteger(raw.lamport) ? raw.lamport : 0,
      issuedAt: Number.isInteger(raw.issuedAt) ? raw.issuedAt : null,
    },
  };
}

/* ------------------------------------------------------------------ */
/* CRDT joins                                                          */
/* ------------------------------------------------------------------ */

function emptyCred(credentialId) {
  return {
    credentialId,
    revoked: false,
    fenceEpoch: -1, // highest revoke epoch seen, -1 = none
    active: null, // highest register: { revision, epoch, data, region, eventId }
  };
}

function joinActive(a, b) {
  if (!a) return b;
  if (!b) return a;
  return cmpRevision(a.revision, b.revision) >= 0 ? a : b;
}

function joinCred(a, b) {
  if (!a) return b;
  if (!b) return a;
  return {
    credentialId: a.credentialId,
    revoked: a.revoked || b.revoked, // REVOKED is absorbing (top)
    fenceEpoch: Math.max(a.fenceEpoch, b.fenceEpoch),
    active: joinActive(a.active, b.active),
  };
}

function registerDelta(ev) {
  return {
    credentialId: ev.credentialId,
    revoked: false,
    fenceEpoch: -1,
    active: {
      revision: [ev.epoch, ev.eventId],
      epoch: ev.epoch,
      data: ev.data,
      region: ev.region,
      eventId: ev.eventId,
    },
  };
}

function revokeDelta(ev) {
  return {
    credentialId: ev.credentialId,
    revoked: true,
    fenceEpoch: ev.epoch,
    active: null,
  };
}

/* ------------------------------------------------------------------ */
/* Ledger                                                              */
/* ------------------------------------------------------------------ */

class CredentialLedger {
  constructor(region = 'local') {
    this.region = region;
    this.state = new Map(); // credentialId -> cred state
    this.applied = new Map(); // eventId -> fingerprint
    this.events = new Map(); // eventId -> normalized event (for replay export)
    this.log = []; // arrival-ordered operational audit trail
    this.clock = 0; // Lamport observation clock
  }

  /* ------------------------- queries ------------------------- */

  get(credentialId) {
    return this.state.get(credentialId) || null;
  }

  status(credentialId) {
    const c = this.state.get(credentialId);
    if (!c) return 'absent';
    return c.revoked ? 'revoked' : c.active ? 'active' : 'absent';
  }

  isActive(credentialId) {
    return this.status(credentialId) === 'active';
  }

  listActive() {
    return [...this.state.values()]
      .filter((c) => c.revoked === false && c.active)
      .map((c) => c.credentialId)
      .sort();
  }

  /* ------------------------- apply ------------------------- */

  /**
   * Apply one event. State mutation is exactly the CRDT join of the event's
   * delta, so a live replica converges with snapshot merges. `decision`/`reason`
   * describe how the event related to what the replica already knew (audit).
   *
   * @returns {object} the audit log entry
   */
  apply(raw) {
    const parsed = normalizeEvent(raw);
    if (!parsed.ok) {
      return this.#record(
        {
          eventId: raw && raw.eventId ? raw.eventId : null,
          credentialId: raw && raw.credentialId ? raw.credentialId : null,
          type: raw && raw.type ? raw.type : null,
          epoch: raw && Number.isInteger(raw.epoch) ? raw.epoch : null,
          region: raw && raw.region ? raw.region : null,
        },
        'rejected',
        REASON.INVALID + ': ' + parsed.reason,
      );
    }

    const ev = parsed.value;
    this.clock = Math.max(this.clock, ev.lamport) + 1;

    const fp = fingerprint(ev);
    if (this.applied.has(ev.eventId)) {
      if (this.applied.get(ev.eventId) === fp) {
        return this.#record(ev, 'duplicate', REASON.DUPLICATE);
      }
      // Same id, different payload: never mutate state, flag loudly.
      return this.#record(ev, 'rejected', REASON.CONFLICT);
    }

    const before = this.state.get(ev.credentialId) || null;
    let delta;
    let decision = 'applied';
    let reason = REASON.APPLIED;

    if (ev.type === REVOKE) {
      delta = revokeDelta(ev);
      if (before && before.revoked) {
        decision = 'noop';
        reason = REASON.NOOP;
      }
    } else {
      delta = registerDelta(ev);
      if (before && before.revoked) {
        // The rollback fence: a register issued before the revoke
        // (epoch <= fence) is fenced; one issued after is still refused because
        // the credential id is tombstoned (fail-closed, single-use id).
        decision = 'rejected';
        reason =
          ev.epoch <= before.fenceEpoch ? REASON.FENCED : REASON.TOMBSTONED;
      } else if (
        before &&
        before.active &&
        cmpRevision(before.active.revision, [ev.epoch, ev.eventId]) >= 0
      ) {
        decision = 'stale';
        reason = REASON.STALE;
      } else if (before && before.active) {
        reason = REASON.ROTATED;
      }
    }

    // State is ALWAYS the join, even for rejected/stale events, so that state
    // merges and event replay always agree. Safety comes from `revoked` being
    // absorbing, not from skipping the join.
    this.state.set(
      ev.credentialId,
      joinCred(before || emptyCred(ev.credentialId), delta),
    );
    this.applied.set(ev.eventId, fp);
    this.events.set(ev.eventId, ev);

    return this.#record(ev, decision, reason);
  }

  /** Apply many events. Returns `this` for fluent chaining. */
  applyAll(events) {
    for (const e of events) this.apply(e);
    return this;
  }

  #record(ev, decision, reason) {
    const entry = Object.freeze({
      index: this.log.length,
      eventId: ev.eventId,
      credentialId: ev.credentialId,
      type: ev.type,
      epoch: ev.epoch,
      region: ev.region,
      decision,
      reason,
      stateHash: this.stateHash(),
    });
    this.log.push(entry);
    return entry;
  }

  /* ------------------------- anti-entropy ------------------------- */

  /** Merge another ledger (or a raw state Map) into this one. Idempotent. */
  merge(other) {
    const otherState = other instanceof CredentialLedger ? other.state : other;
    for (const [id, cred] of otherState) {
      this.state.set(id, joinCred(this.state.get(id) || null, cred));
    }
    if (other instanceof CredentialLedger) {
      for (const [id, fp] of other.applied) {
        if (!this.applied.has(id)) this.applied.set(id, fp);
      }
      for (const [id, ev] of other.events) {
        if (!this.events.has(id)) this.events.set(id, ev);
      }
    }
    return this;
  }

  snapshot() {
    return new Map(
      [...this.state.entries()].map(([id, c]) => [
        id,
        JSON.parse(JSON.stringify(c)),
      ]),
    );
  }

  /** Deterministic hash of the full credential state. */
  stateHash() {
    const entries = [...this.state.entries()]
      .sort((a, b) => (a[0] < b[0] ? -1 : a[0] > b[0] ? 1 : 0))
      .map(([id, c]) => ({
        credentialId: id,
        revoked: c.revoked,
        fenceEpoch: c.fenceEpoch,
        active: c.active
          ? {
              revision: c.active.revision,
              epoch: c.active.epoch,
              data: c.active.data,
            }
          : null,
      }));
    return sha256(canonical(entries));
  }

  /**
   * Deterministic, replayable audit log: unique valid events sorted by
   * (credentialId, epoch, revoke-before-register, eventId). Feeding this back
   * into a fresh ledger reproduces the exact same final state on every replica.
   */
  exportReplay() {
    const events = [...this.events.values()];
    events.sort((a, b) => {
      if (a.credentialId !== b.credentialId)
        return a.credentialId < b.credentialId ? -1 : 1;
      if (a.epoch !== b.epoch) return a.epoch - b.epoch;
      if (typeRank(a.type) !== typeRank(b.type))
        return typeRank(a.type) - typeRank(b.type);
      if (a.eventId !== b.eventId) return a.eventId < b.eventId ? -1 : 1;
      return 0;
    });
    return events;
  }

  static fromReplay(events, region = 'replay') {
    const l = new CredentialLedger(region);
    for (const ev of events) l.apply(ev);
    return l;
  }
}

module.exports = {
  CredentialLedger,
  REASON,
  REGISTER,
  REVOKE,
  canonical,
  joinCred,
  joinActive,
  cmpRevision,
  normalizeEvent,
};

3.1 Integration points (adapter)

  • Origin (region write path): assign eventId = "<region>:<monotonic-seq>" and epoch from a per-credential counter (or max(seen epoch)+1). Never trust issuedAt for ordering.
  • Replication: ship the event log and/or call peer.merge(ledger) for anti-entropy. Both are safe and idempotent.
  • Reads: isActive(id) / listActive() are the authoritative checks. A login attempt for a revoked id must be refused even if a stale register is in flight.
  • Audit: persist exportReplay() plus the arrival-ordered log; alert on any duplicate-conflict entry.

5. Why This Is the Right Fix (summary)

  • Epoch replaces timestamps. Conflict resolution uses per-credential logical epochs plus a deterministic eventId tiebreak, so it is immune to clock skew and replay.
  • Revocation is a lattice top, not a flag. revoked = a.revoked || b.revoked makes resurrection impossible by construction; the fenceEpoch additionally classifies why a stale registration is refused, producing an auditable reason (revoked-fence vs credential-tombstoned).
  • State is per-credential, so concurrent additions are preserved. Revoking one id cannot erase another.
  • The join is idempotent/commutative/associative, which is exactly the property that makes out-of-order and duplicate delivery safe and makes replicas converge.
  • Replayability. exportReplay() emits a canonical event order that reconstructs a byte-identical stateHash(), giving auditors a deterministic, reproducible log.

Operational rule that follows from the design: a revoked credential id is single-use and must never be re-enrolled; browsers generate a new credential id for re-enrollment, which the ledger preserves as a normal concurrent addition.
