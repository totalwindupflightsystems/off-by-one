What I found

Your described artifacts aren't currently materialized on this box, but the exact failure class is latent and reproducible:

  • Real toolchain now: npm 10.9.8 at /usr/bin/npm, node v22.23.2 at /usr/bin/node.
  • ~/.local/bin/{node,npm,npx} are dangling symlinks into the missing /home/kara/.hermes/node/bin/*, and ~/.local/bin is on PATH ahead of /usr/bin. The moment that target (or a vite-plus/bin) reappears, it shadows the system toolchain.

Root cause (two layers — the second is the trap)

  1. Name-resolution shadowing: a multi-call vp shim symlinked as npm/node/bun in a first-on-PATH dir intercepts the names. npm -v is answered by the shim (12.0.2), so a normal version check never sees the swap.
  2. Interpreter hijacking: the real npm is a #!/usr/bin/env node script. I verified that invoking the real npm by absolute path is still hijacked — /usr/bin/npm -v returned the shim's node output, because env resolves node through PATH. The only safe pin controls both the entry point and the interpreter.

I reproduced the shim, confirmed which -a npm exposes it, confirmed the ~/.npm/_logs verbose cli line names the actual binary and that the shim writes no log, and verified a hardened gate that refuses/self-heals.

The fix (in the doc)

  • Fix A: sanitize PATH (drop known shim dirs, prepend real bin), then hard-pin with "$REAL_NODE" "$REAL_NPM" "$@" so env node can't hijack it.
  • Fix B: fingerprint node/npm/resolved targets at start and re-assert before each phase; abort on a mid-run PATH flap.
  • Fix C: quarantine the shim dir and remove the dangling ~/.local/bin links, plus find the rc file that prepends them.
  • Detection uses which -a + readlink -f + per-candidate version, and the npm debug log's verbose cli/cwd/node/npm lines. Acceptance checklist included.

Reproduction artifacts remain in /tmp/repro/ if you want to re-run the proofs.
