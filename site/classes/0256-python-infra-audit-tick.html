Answer

Root cause. The board-only commit policy is violated by the hilo graph warm pass: it legitimately dirties edges.jsonl (1556/172 growth vs the 1244/173 Variant D baseline recorded in stats). A naive git add -A && git commit ships derived data, while a naive git checkout edges.jsonl first loses the delta that the audit must record. The fix is a deterministic 4-step tick (h4f_tick.py, 222 lines, orchestrated by h4f_tick.sh):

# STEP 1 — stats FIRST: persist the graph-warm delta before discarding anything
record = {"tick": tick, "edges": count, "variant": "D", "source": "stats-first"}
(stats_path).write_text(stats_path.read_text() + json.dumps(record) + "\n")

# STEP 2 — drop derived-data dirt (graph-warm pass) ONLY AFTER stats are recorded
if is_dirty(repo, EDGES):
    git(repo, "checkout", "--", EDGES)          # edges.jsonl back to committed baseline
    if is_dirty(repo, EDGES):
        raise TickError("failed to discard edges.jsonl; refusing board-only commit")

# STEP 3 — commit the board file ONLY, and only when it changed
if not is_dirty(repo, BOARD):
    print("[board] tasks.md unchanged — no board commit (clean idle tick)")
    return False
git(repo, "add", "--", BOARD)
git(repo, "commit", "-m", f"board: tick {tick} [board-only]", "--", BOARD)

# STEP 4 — DuckBrain key ring: exactly +1 key per tick, persisted between ticks
if self.tick <= self.last_tick:
    print("[duck] already minted (idempotent) — no new key")
else:
    key = f"DB-{self.tick:06d}"; self.keys.append(key)
    state_file.write(json.dumps({"keys": self.keys, "last_tick": self.tick}))

Key behaviors: stats-first ordering (delta is never lost), board-only commit scope (git commit -- tasks.md), idle-tick short-circuit (unchanged board ⇒ no commit, but the tick still counts), idempotent DuckBrain (re-drive of tick 88 does not double-mint), between-tick persistence (state file survives restarts), plus a --strict anomaly gate (aborts on shrink or >2× explosive growth) and --dry-run. Run: bash h4f_tick.sh <repo> <tick>.
