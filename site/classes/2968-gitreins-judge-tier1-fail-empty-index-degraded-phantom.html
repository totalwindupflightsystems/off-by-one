Answer

gitreins judge tier1 FAIL on an empty index is a phantom DEGRADED pass

Disposition

This is not a code failure. The evaluation ran Tier 1 after the work was committed. gitreins guard therefore graded the now-empty Git index, every substantive lane skipped (tests=no staged files, lint=no staged files), and the guard exited 2 because guards.allow_skips is not enabled. The judge's pipeline wrapper treats any nonzero guard exit as stages.tier1.passed=false, even though the guard's own result was passed=true, degraded=true.

Tier 2 independently re-verified the landed commit and passed. The overall FAIL is therefore a zero-work / empty-index phantom, not evidence against the tree.

Do not rewrite history and do not re-run the same judge invocation hoping for a different result: an empty index reproduces the skip deterministically.

Evidence to read (decisive triage)

Read the cited guard log, not the task summary:

for log in \
  .gitreins/logs/guard-20261024T165627*.log \
  .gitreins/logs/guard-20261024T171640*.log
do
  echo "=== $log"
  grep -E 'test_mode:|overall:|skipped_steps:|  - (lint|tests):|\[SKIP\]|\[FAIL\]' "$log"
done

A phantom has all of these:

test_mode: diff
overall: PASS (DEGRADED — skipped checks)
skipped_steps:
  - lint: no staged files
  - tests: no staged files
[SKIP] tests  passed=true  exit_code=n/a  skip_reason=no staged files

Confirm the index was empty at evaluation time:

git diff --cached --name-only | wc -l      # 0 at eval time
git status --porcelain                     # clean, work already in HEAD
git log --oneline -2                       # af8bfd6, a288176

Confirm the substantive gates directly at the landed commit:

git rev-parse HEAD                         # expected a288176
pytest -q                                  # 2169 passed, 62 skipped, 0 failed
gitreins guard --scope working-tree --full # secrets/lint/lsp clean

Interpretation: stages.tier1.passed=false came from the guard process exit code, not from a failing assertion, lint finding, or secret finding. tiers2.passed=true is the real quality signal here.

Durable fix: make eval-time Tier 1 grade the tree, not the empty index

Recommended: run the judge's Tier 1 guard with --full

guard --full is the existing supported switch for exactly this situation. It overrides test_mode: diff, runs the configured test command, and lints the whole tracked+untracked tree even when nothing is staged.

Change the Tier 1 guard step in .gitreins/config.yaml:

 pipeline:
   stages:
     - id: tier1
       on: [pre-eval]
       steps:
         - id: guard
           type: script
-          run: "gitreins guard"
+          run: "gitreins guard --full"

If the same config is also used for a pre-commit trigger where staged-only grading is desired, use a tiny eval wrapper instead:

#!/usr/bin/env bash
# scripts/guard-tier1-eval.sh
# Judge-time Tier 1: grade the landed tree, never the empty index.
set -uo pipefail
if [ -z "$(git diff --cached --name-only)" ]; then
  exec gitreins guard --full "$@"
fi
exec gitreins guard "$@"

chmod +x scripts/guard-tier1-eval.sh

-          run: "gitreins guard"
+          run: "./scripts/guard-tier1-eval.sh"

Keep guards.allow_skips as-is. Setting it to true merely hides future empty-index phantoms; --full actually produces substantive evidence.

Optional upstream hardening for gitreins itself

If the judge owns a GuardManager directly (the legacy path rather than a pipeline step), make an empty eval-time index select whole-tree grading:

# engine/judge.py, in Judge.__init__, before constructing GuardManager
import subprocess

def _has_staged_changes(workdir: str) -> bool:
    proc = subprocess.run(
        ["git", "diff", "--cached", "--name-only", "--quiet"],
        cwd=workdir,
        check=False,
    )
    return proc.returncode == 1   # 0 = no staged changes, 1 = staged changes

# ...
self.guard_manager = GuardManager(
    workdir,
    self.guard_config,
    scope=scope,
    persist_log=persist_log,
    scan_root=self.scan_root,
    # A judge normally evaluates already-committed work; an empty index must
    # not turn every substantive lane into a DEGRADED skip.
    grade_full_tree=(scope == "staged" and not _has_staged_changes(workdir)),
)

For a configurable pipeline whose Tier 1 is an explicit gitreins guard script, the YAML/wrapper fix above is the smaller and less invasive change.

Prevention / guardrails

  • Judge Tier 1 at evaluation time must run gitreins guard --full (or the conditional eval wrapper), never plain diff-mode gitreins guard after the work is committed.
  • Treat DEGRADED PASS from a zero-file change set as N/A, not FAIL, when the evaluation happens after commit. Do not treat it as proof of a passing tree either.
  • Add a regression check that commits a known-good tree, runs the judge's Tier 1 step on the clean worktree, and asserts the persisted log contains test_mode: full and no DEGRADED marker.
  • Distinguish this class from real Tier 1 failures: real failures name a failing test ID, lint finding, secret, or missing tool. This class always carries no staged files plus test mode: diff.
