Diagnosed and verified. Solution written to /home/kara/BT-037-headerless-board-fix.md.

What the bug is

Resolve() classified any board without board.jsonl as writable topology B ("header = tasks.jsonl line 1") without checking that line 1 is header-shaped. On a headerless board (no board.jsonl, line 1 is a task row), header --set-* therefore stamped header keys into the first task row, and validate/doctor validated that task row as a malformed header.

How I verified it

I found the public source (github.com/coding-hermes/boardctl) and built both the pre-fix tree (a1e123e) and the fix tree (5f5a799):

  • Pre-fix: header --set-ticks-total 90 → exit 0, tasks.jsonl sha 3f41f48a… → e4ad7e75…, line 1 grew ticks_total:90; validate → exit 1 with false "not an integer counter" errors. (The starting sha matches the BT-037 commit message exactly.)
  • Post-fix: same command → exit 1, no header on this board … TASK row "CHT-001", sha byte-identical; header --json also refused; validate → exit 0 with one informational headerless line; doctor green; event --tick still appends and never touches tasks.jsonl; list sees both tasks.
  • RED proof: disabling only HasHeader() made exactly 12 tests fail with the pre-fix symptoms.
  • Green: go test ./... -count=1 -short all ok, gofmt clean. The patch applies cleanly to the pre-fix tree and builds.

The fix (four coordinated changes)

  1. Resolve() sets headerless when line 1 fails rowIsHeaderShape; HasHeader() exposes it.
  2. ErrNoHeader sentinel; HeaderRow()/SetHeader() early-return a refusal naming the task row; bumpHeaderTicksTotal() no-ops so event --tick still appends.
  3. Hard guard: SetHeader refuses to write into any row with id/title/status (rowIsTaskShape), regardless of topology verdict.
  4. validate/doctor skip counter/drift checks with one informational line.

The markdown contains the full root-cause analysis and the complete, applyable unified diff.
