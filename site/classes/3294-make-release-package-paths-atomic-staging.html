Fixing a Makefile Release Loop: Package→Binary Mapping + Atomic Staging

Problem

A Go project ships three local commands under ./cmd/, but the released binary names do not match the package directory names:

Package dir Released binary
./cmd/api gateway
./cmd/worker poller
./cmd/cli acmectl

The release target iterates over package paths and derives the output name from the directory, so it produces api, worker, cli, and it wipes the previous dist/ before it knows the build will succeed.

Reproduced failure

With the buggy Makefile, make release yields the wrong names (dist/api, dist/worker, dist/cli). Worse, when one package fails to compile, the loop neither stops nor returns non-zero, so a corrupt partial release is left behind while the old, good dist/ has already been deleted:

# example.com/release-demo/cmd/worker
cmd/worker/main.go:3:15: undefined: undefinedSymbol
tar: worker: Cannot stat: No such file or directory
release written to dist/
make exit: 0        # <-- silent success

The sentinel dist/PRESERVE_MARKER from the previous release is gone, and dist/worker.tar.gz is a 45-byte truncated archive.

Root-Cause Analysis

Three independent defects combine in the original recipe:

release: clean
    @mkdir -p dist
    @for pkg in $(CMDS); do \
        name=$$(basename $$pkg); \          # (1) wrong name source
        $(GO) build -o dist/$$name $$pkg; \
        tar -C dist -czf dist/$$name.tar.gz $$name; \
    done
    @echo "release written to dist/"

clean:
    @rm -rf dist bin

  1. Binary name derived from the package directory. name=$$(basename $$pkg) turns ./cmd/api into api, but the shipped artifact must be gateway. Package layout and artifact naming are different concerns and need an explicit mapping.

  2. The destination is destroyed before the build is attempted. release: clean runs rm -rf dist first. Any later compile/archive error leaves no previous release to fall back on.

  3. Errors are swallowed inside the shell loop. GNU Make runs the whole for loop as one shell command and there is no set -e/pipefail, so a failed go build does not stop the loop, the following tar fails too, and the final echo reports success (exit 0). Partial output is published as if it were a release.

The fix must: (a) carry an explicit package → binary mapping, (b) build all three binaries, and (c) stage into a temporary directory and only publish to dist/ after every step succeeds.

The Exact Fix

SHELL := /bin/bash
GO ?= go

# Explicit package -> binary mapping. Package directories and binary names
# differ, so NEVER derive a binary name from the package path.
# Format: "package:binary"
RELEASE_BINS := api:gateway worker:poller cli:acmectl

DIST := dist

.PHONY: build release clean

# Build all three local binaries.
build:
    @set -euo pipefail; \
    mkdir -p bin; \
    for pair in $(RELEASE_BINS); do \
        pkg=$${pair%%:*}; bin=$${pair##*:}; \
        echo "  build bin/$$bin  <- ./cmd/$$pkg"; \
        $(GO) build -o bin/$$bin ./cmd/$$pkg; \
    done

# Stage everything in a temp dir next to dist, then publish atomically.
# The existing dist is untouched unless every step succeeds.
release:
    @set -euo pipefail; \
    stage=$$(mktemp -d "$(DIST).staging.XXXXXX"); \
    trap 'rm -rf "$$stage"' EXIT; \
    for pair in $(RELEASE_BINS); do \
        pkg=$${pair%%:*}; bin=$${pair##*:}; \
        echo "  build $$bin  <- ./cmd/$$pkg"; \
        $(GO) build -o "$$stage/$$bin" ./cmd/$$pkg; \
    done; \
    for pair in $(RELEASE_BINS); do \
        bin=$${pair##*:}; \
        tar -C "$$stage" -czf "$$stage/$$bin.tar.gz" "$$bin"; \
    done; \
    old="$(DIST).old.$$$$"; \
    if [ -d "$(DIST)" ]; then mv "$(DIST)" "$$old"; fi; \
    if mv "$$stage" "$(DIST)"; then \
        rm -rf "$$old"; \
        trap - EXIT; \
    else \
        [ -d "$$old" ] && mv "$$old" "$(DIST)"; \
        exit 1; \
    fi; \
    echo "release staged in $(DIST)/"

clean:
    rm -rf bin "$(DIST)" "$(DIST)".staging.* "$(DIST)".old.*

Why each part fixes a defect

  • Mapping (RELEASE_BINS) — pkg=$${pair%%:*} / bin=$${pair##*:} split each entry, so ./cmd/api is built as gateway. Adding a command means adding one pkg:bin pair.
  • set -euo pipefail — aborts on the first failed command, so a compile error can no longer be masked by a later successful echo.
  • mktemp -d "$(DIST).staging.XXXXXX" — staging happens in a fresh temp directory next to dist (same filesystem), so the final publish is a rename and the previous dist/ is never touched until all builds and archives exist.
  • trap 'rm -rf "$stage"' EXIT — any failure cleans the staging dir.
  • Publish step — the old dist is renamed aside, the staged dir is renamed into place, then the old dir is removed. If the publish rename fails, the old dist is restored. trap - EXIT disarms cleanup once ownership has moved.

before=$(ls dist | sort)

package main
func main() { undefinedSymbol() }
EOF

make release; rc=$?          # must be non-zero
after=$(ls dist | sort)

echo "exit=$rc"
[ "$before" = "$after" ] && echo "PASS: dist unchanged" || echo "FAIL: dist changed"

sentinel

The previously published dist/ (including PRESERVE_MARKER and all three archives) is byte-for-byte intact, make exits non-zero, and the trap removed the staging directory.

Summary of verified outcomes: binaries are named gateway/poller/acmectl (not api/worker/cli); all three are built by make build; a failed build exits non-zero; and an existing dist/ is fully preserved on failure with no leftover staging directories.
