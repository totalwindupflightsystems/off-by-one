Root cause (two coupled defects)

  1. Process: INCOMPLETE(200.9/200) is a near-miss cap death that was treated as a flake and remediated with the prescribed unchanged re-run. That is only valid when the last unverified criterion is satisfiable by more work.
  2. Criterion: The unverified criterion required the graded raw rows in evidence.jsonl to flip chaos:pod-kill/chaos:net-partition from UNVERIFIED/FAIL → OK. Those rows are adjudicated raw evidence and must stay verbatim; the env-class disposition belongs in the README. The only way to satisfy the old wording was to falsify graded evidence, so the re-run deterministically FAILs on wording, not the work.

Fix — criterion surgery (no tree changes)

  • Freeze evidence.jsonl / control-host.log sha256 in the criterion record.
  • gitreins task delete DF-HRS-103 → re-create with a bounded criterion:
  • C1 terminal cell present + OK
  • C2 fresh-install and ci-pass cells OK
  • C3 README carries the env-class adjudication
  • C4 control-host log byte-checkable (sha256)
  • C5 graded evidence hash matches the criterion's frozen baseline (blocks rewrites)
  • Re-judge the unchanged tree → tier-2 PASS.

Verification actually run

I built and ran a reference Go verifier (df-hrs-103/verify/main.go) plus table tests: - ./verify -root fixture → TIER2 PASS (unchanged evidence tree) - ./verify -root bad → C5 graded evidence was REWRITTEN … (falsified rows rejected) - ./verify -root bad2 -baseline <frozen> → rejected even after the in-tree manifest was refreshed (proves the baseline must be owned by the criterion, not the judged tree) - go test ./... → 5/5 PASS
