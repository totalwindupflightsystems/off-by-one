Fix: TestUninstallCLINoStutter red on hosted runners (DF-56-CI)

Repo: trouble-agent/mischief Test: cmd/mischief/df56_test.go::TestUninstallCLINoStutter Red run: 40761837574 Fix commit: 8ecef33 — DF-56-CI: relax df56 e2e assertion to any uninstall-scoped failure (CI runners lstat-fail before rmdir). Verified HEAD: a702004 (contains 8ecef33)

1. Symptom

CI fails the e2e uninstall test while the same tree is green on the dev box:

uninstall: stat /etc/sudoers.d/mischief: lstat /etc/sudoers.d/mischief: permission denied

The test expected the late failure vehicle — the prefix rmdir on residue — and asserted the literal substring uninstall: rmdir.

2. Root cause

TestUninstallCLINoStutter builds a prefix containing residue and drives the real CLI:

code, stderr := captureStderr(t, func() int {
    return run([]string{"uninstall", "--prefix", prefix, "--runs-dir", ...})
})
if code != 1 { ... }
if !strings.Contains(stderr, "uninstall: rmdir") { // <-- asserted the vehicle
    t.Fatalf("expected the executor's rmdir failure on stderr, got:\n%s", stderr)
}

The uninstall plan always leads with the fixed sudoers drop-in (prefix does not move it):

// internal/ops/install.go
func (o *InstallOpts) dropInPath() string { return DefaultDropInPath } // /etc/sudoers.d/mischief

p.Actions = append(p.Actions, Action{
    Kind: OpRemove, Path: opts.dropInPath(),
    Reason: "sudoers drop-in (the entire privileged surface)",
})

ExecuteUninstall guards every removal with os.Lstat and treats a non-ENOENT error as fatal (fail closed):

case OpRemove:
    if _, err := os.Lstat(real); err != nil {
        if os.IsNotExist(err) {
            continue
        }
        return removed, fmt.Errorf("uninstall: stat %s: %w", a.Path, err)
    }

Which error surfaces depends entirely on host privilege / /etc/sudoers.d mode:

Host lstat /etc/sudoers.d/mischief First failure vehicle
Dev box (/etc/sudoers.d searchable, drop-in absent) ENOENT → continue residue prefix rmdir → uninstall: rmdir …
Hosted runner (/etc/sudoers.d not searchable) EACCES → fatal uninstall: stat /etc/sudoers.d/mischief: … permission denied

The red run 40761837574 took the second path, so the walk never reached the rmdir. The test was asserting an implementation/vehicle detail (“which removal failed first”) that is host-dependent, rather than the property the row actually gates.

The property under test (from the file header) is: the CLI failure line is verb-scoped exactly once — one uninstall: token, no doubled prefix (uninstall: uninstall:). Exit code 1 is part of the contract. The specific step that fails is not.

The executor-side error is correct — it fails closed on EACCES. There is no production bug to fix; the assertion is wrong.

3. Exact fix

Relax the vehicle assertion to the property, and keep the exit-code and no-stutter assertions untouched.

Why this still enforces the property:

  • exit 1 is unchanged — the verb must fail closed on both host classes.
  • uninstall: proves the line is verb-scoped (not a bare/foreign-package error).
  • uninstall: uninstall: proves the doubled-prefix collapse (the actual DF-56 regression) is still pinned.

The rest of the test (--dry-run control arm on stdout, exit 0, plan lines) is untouched.

4.3 Reproduce the CI vehicle deterministically (old assertion reds, new one stays green)

The CI host can't be forced from an unprivileged dev box (no root, user namespaces blocked), so pin the package test seam ops.Root and make etc/sudoers.d unsearchable. The executor then hits EACCES on its very first guard, exactly like the runner. Run this as a temporary test file:

// cmd/mischief/zz_ci_repro_test.go  (temporary; delete after)
package main

import (
    "os"
    "path/filepath"
    "strings"
    "testing"

    "github.com/trouble-agent/mischief/internal/ops"
)

func TestZZCIReproPermissionDeniedVehicle(t *testing.T) {
    saved := ops.Root
    ops.Root = t.TempDir()
    t.Cleanup(func() { ops.Root = saved })

    // Unsearchable sudoers.d: lstat child -> EACCES (as on the runner).
    sudoersD := filepath.Join(ops.Root, "etc", "sudoers.d")
    if err := os.MkdirAll(sudoersD, 0o755); err != nil {
        t.Fatal(err)
    }
    if err := os.Chmod(sudoersD, 0o000); err != nil {
        t.Fatal(err)
    }
    t.Cleanup(func() { _ = os.Chmod(sudoersD, 0o755) })

    // Residue in the prefix so the late rmdir would otherwise be the vehicle.
    prefix := filepath.Join(ops.Root, "var", "lib", "mischief")
    if err := os.MkdirAll(prefix, 0o755); err != nil {
        t.Fatal(err)
    }
    if err := os.WriteFile(filepath.Join(prefix, "stray.txt"), []byte("residue\n"), 0o644); err != nil {
        t.Fatal(err)
    }

    code, stderr := captureStderr(t, func() int {
        return run([]string{"uninstall", "--prefix", "/var/lib/mischief", "--runs-dir", "/tmp/absent-runs"})
    })
    t.Logf("exit=%d stderr=%q", code, stderr)

    if code != 1 {
        t.Fatalf("exit %d, want 1", code)
    }
    if !strings.Contains(stderr, "uninstall: stat /etc/sudoers.d/mischief") ||
        !strings.Contains(stderr, "permission denied") {
        t.Fatalf("did not reproduce the CI permission-denied vehicle:\n%s", stderr)
    }
    // OLD (vehicle) assertion: must be false on this host class.
    if strings.Contains(stderr, "uninstall: rmdir") {
        t.Fatalf("old assertion would pass here; not the CI vehicle:\n%s", stderr)
    }
    // NEW (property) assertion: must be true.
    if !strings.Contains(stderr, "uninstall: ") {
        t.Fatalf("property assertion red on CI vehicle:\n%s", stderr)
    }
    if strings.Contains(stderr, "uninstall: uninstall:") {
        t.Fatalf("stutter regression:\n%s", stderr)
    }
}

5. Generalizable rule

An e2e assertion may pin a contract property (exit code, error is verb-scoped, no doubled prefix) but must not pin the specific failing step when which step fails depends on ambient host privilege, filesystem state, or tooling availability. When a walk can fail at several points, assert the first failing layer's shape, not which layer failed.

Scope note: the same file already asserts the literal uninstall: rmdir in cmd/mischief/ops_report_test.go, but that test pins ops.Root to a temp tree, so it never touches the real /etc/sudoers.d and is not host-fragile — no change needed there.
