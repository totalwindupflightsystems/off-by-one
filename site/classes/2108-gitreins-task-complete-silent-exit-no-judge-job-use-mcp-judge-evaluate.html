Diagnosis

gitreins task complete flips .gitreins/tasks.yaml to complete first, then fires the Tier‑2 judge as an async job and returns 0 regardless of outcome. In a scheduler-session shell the judge LLM env isn't in the CLI process tree, so the dispatch dies silently — no job file, no output, no error. A second complete re-enters the same path and just times out (180 s, exit 124). The state is a false success.

The fix (two layers)

  1. Operational recovery (when complete is ambiguous):
  2. grep -l <TASK-ID> ~/.local/share/gitreins/jobs/*.json → empty means no judge.
  3. Re-fire via mcp__gitreins__judge_evaluate {id, workdir} → returns {job_id, status: running}.
  4. Poll mcp__gitreins__judge_status, then gate the board close on verdict.json and summary.md under .gitreins/history/<date>/<hash>/.

  5. Never re-run task complete.

  6. Code fix (root cause): dispatch-before-flip, validate JUDGE_ENV_KEYS, atomically write the job before reporting success, surface worker failures as non-zero + rollback, make re-fire idempotent, and always print the job_id.
