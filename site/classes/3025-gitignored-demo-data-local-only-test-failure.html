Heading — Local-Only Test Reds: Gitignored Demo Data + Order-Dependent Build-Info Flake

Class: gitignored-demo-data-local-only-test-failure

Root Cause Analysis

Failure A — gitignored demo data leaks into explanations - packages/crm/data/bookings.json is gitignored, so it exists locally but not on CI. - It held a Sep 29 client-al-rashid-family export with 6 CDG–JFK demo bookings. - The CRM runtime feeds those into learned-preferences text, producing: Learned: matches your 6 previous CDG-JFK bookings, decayed weight 0.97 and flipping the path to All primary preferences satisfied. - Negative assertions forbid those strings → red only where the file exists. CI lacks it → green.

Failure B — order-dependent generated build-info - Stale build-info.generated gives a SyntaxError in full-suite runs only; 5/5 green in isolation. Classified as a flake, not a regression (per the pitfall).

Diagnosis Ladder

grep -rn "All primary preferences satisfied" packages/crm/src packages/crm/test
grep -rn "Learned: matches your" packages/crm/src
git check-ignore -v packages/crm/data/bookings.json   # ignored => CI-absent
jq 'length' packages/crm/data/bookings.json
pnpm --filter @heading/api test -- --run auth-boot-prereqs   # isolation check

Exact Fix

# A) Timestamped quarantine of the untracked data (never delete tracked files)
ts="$(date +%Y%m%d-%H%M%S)"; mkdir -p "/tmp/heading-quarantine/$ts"
mv packages/crm/data/bookings.json "/tmp/heading-quarantine/$ts/bookings.json"

# B) Durable: committed fixture + redirect loader
mkdir -p packages/crm/test/fixtures
printf '[]\n' > packages/crm/test/fixtures/bookings.empty.json
git add packages/crm/test/fixtures/bookings.empty.json

process.env.CRM_DATA_DIR = new URL('./fixtures', import.meta.url).pathname;

// loader seam
const dataDir = process.env.CRM_DATA_DIR ?? new URL('../../data', import.meta.url).pathname;

# C) Stabilize build-info
rm -f packages/*/build-info.generated* packages/*/src/build-info.generated*
pnpm -w build

Document the LOCAL-vs-CI baseline rule in CONTRIBUTING.md (gitignored inputs are never assumed present on CI; full-run-only reds must be rerun in isolation first).
