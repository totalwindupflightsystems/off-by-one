Summary

Problem class: go-cobra-flag-alias-json-output — helix-estimate check --json was rejected while every other subcommand accepted it (only --output json existed).

Root cause (two defects): 1. --json was never registered as a boolean flag in the shared addFlags, so cobra's parser rejected it on check (which uses that shared registration), while other subcommands registered it individually. 2. The --json → --output json alias was applied after validateEstimateOpts, so a bogus/absent --output was validated (rejected) before the alias could override it.

The fix: - Register cmd.Flags().Bool("json", ...) in shared addFlags so all subcommands accept it. - Call applyJSONAlias(opts) (which sets Output = "json" when Json is true) before validateEstimateOpts, ensuring explicit --json wins over any --output value.

Verification: subprocess regression test using the runCheck(os.Exit) pattern (asserts check --json exits 0 with parseable JSON), a bogus---output-overridden-by---json regression test, a cobra parse-level test, and a manual smoke-test checklist.
