Answer

I diagnosed the failure against the real gitreins codebase (PyPI wheel gitreins 0.18.0 + the upstream repo at the GR-GAP-064 fix 7f0fc1eb) and reproduced both traps live. The full solution is written to /workspace/SOLUTION.md.

Diagnosis

Trap 1 — range-scoped scan, not tree-scoped. engine/push_secrets.py::_scan_push_range runs git log -p --diff-merges=first-parent <remote>..<local> and grades every + line. A fixture added in an earlier unpushed commit is in the patch stream even after a later commit deletes/rewrites it, so --amend/follow-up cannot help. The DF-026 _CONCAT_GLUE re-scan (["']\s*\+\s*["']) reassembles same-line "ghp_" + "body", so fragmenting on one line doesn't work either.

Trap 2 — env leak. engine/eval_cap.py applies GITREINS_MAX_ITERATIONS as a highest-priority override. Tier-1's child env strips only GIT_*, so the var reaches tests/test_config_priority.py, which asserts config-derived caps via eval_cap_from_config / AgenticEvaluator → red on an untouched tree.

Exact fix

  • (a) Squash while unpushed: BASE=$(git merge-base HEAD @{u}); git reset --soft "$BASE"; git commit -m "...", then verify git diff HEAD@{1} HEAD is empty. Only valid before anything is pushed.
  • (b) Runtime-built fixture: split into _FAKE_GHP_PREFIX = "ghp_" / _FAKE_GHP_BODY = "FAKEKEYnotreal" + "0" * 18 + "1", assemble in _fake_github_token(). No committed line carries a joinable literal.
  • (c) Launcher: env -u GITREINS_MAX_ITERATIONS ... gitreins judge, or env.pop("GITREINS_MAX_ITERATIONS", None) before spawning.

Verification (observed)

  • Repro: before squash: ['GitHub personal access token'], after squash: [], tree unchanged: True; tip-only --amend still reports the finding.
  • Env arms on the same tree: clean env 17 passed; GITREINS_MAX_ITERATIONS=7 → 6 failed, 11 passed, got 7.0 with source='... + GITREINS_MAX_ITERATIONS=7'.
  • Real range: gitreins push-check 7f0fc1eb 171959df → clean (scanned 57 commits; allowlisted paths skipped: 3 files), where the pre-fix module at 365ce223 refused the same range.
