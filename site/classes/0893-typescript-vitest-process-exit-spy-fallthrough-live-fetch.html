Answer

The root cause is a two-sided bug: (1) the test stubs process.exit into a no-op and mocks nothing else, and (2) the command relies on process.exit's never return to stop execution, so a stubbed exit falls through into a live fetch(resolveServerUrl()) + process.stdout.write(payload). The test is green (the spy was called), so the suite passes in isolation while flooding the root turbo run with ~900KB → vitest/turbo output limits → ELIFECYCLE.

Fix 1 — command side: make the exit branches structurally unreachable. process.exit is typed never, but a stubbed spy returns void, so every exit branch in run() needs an explicit return;:

// packages/cli/src/run.ts
export async function run(argv: string[] = process.argv.slice(2)): Promise<void> {
  const { options, error } = parseArgs(argv);
  if (error) {
    process.stderr.write(`cli: ${error}\n`);
    process.exit(1);
    return; // <-- FIX: stubbed process.exit can never fall through to fetch/stdout
  }

  const serverUrl = resolveServerUrl(options.server); // default = live server
  const res = await fetch(
    `${serverUrl}/api/export?format=${options.format}`,
    { headers: { accept: 'application/json' } },
  );
  if (!res.ok) {
    process.stderr.write(`cli: export failed: HTTP ${res.status}\n`);
    process.exit(2);
    return; // <-- same guard on every other exit branch
  }
  const payload = await res.text();
  process.stdout.write(payload);
}

Fix 2 — test side: mock every side effect that lives after the exit point (fetch + process.stdout.write, plus stderr so the assertion is clean):

// packages/cli/test/run.test.ts
import { afterEach, describe, expect, it, vi } from 'vitest';
import { run } from '../src/run';

describe('cli run', () => {
  afterEach(() => {
    vi.restoreAllMocks();
    vi.unstubAllGlobals();
  });

  it('exits with code 1 on invalid format and never falls through to fetch/stdout', async () => {
    const exitSpy = vi
      .spyOn(process, 'exit')
      .mockImplementation((() => {}) as unknown as typeof process.exit); // cast: exit is `never`
    const fetchMock = vi.fn().mockResolvedValue(new Response('{"rows":[0,0]}', { status: 200 }));
    vi.stubGlobal('fetch', fetchMock);                       // no network
    const stdoutWrite = vi.spyOn(process.stdout, 'write').mockImplementation(() => true); // no payload dump
    const stderrWrite = vi.spyOn(process.stderr, 'write').mockImplementation(() => true);

    await run(['--format', 'bogus']);

    expect(exitSpy).toHaveBeenCalledWith(1);
    expect(fetchMock).not.toHaveBeenCalled();
    expect(stdoutWrite).not.toHaveBeenCalled();
    expect(stderrWrite).toHaveBeenCalledWith(
      'cli: invalid format: bogus (expected one of: csv, json, ndjson)\n',
    );
  });
});

The two fixes are complementary: the return; makes the fall-through structurally impossible; the mocks guarantee that even if some future exit branch is missed, the test cannot hit the network or real stdout.

Evidence & signatures

I built a faithful repro in `/tmp/fix-repro` (node 22.22.3, vitest 1.6.1, pnpm 11 workspace `packages/*`, turbo 2.10.9) with a `scripts/mock-export-server.mjs` serving an **879KB** payload at `/api/export`, and `CLI_SERVER_URL` pointed at it so the buggy `run()` performs a *real* fetch exactly like the production scenario.

**Before the fix** (exit spy only, no other mocks, server live):
```
$ vitest run            →  exit 0
  Test Files  1 passed (1)
       Tests  1 passed (1)        ← green in isolation, exactly as described
$ wc -c before.out      →  900,335 bytes   (879KB payload dumped to unmocked stdout)
$ grep -o '"rows":\[0,' before.out → matches (payload leaked via real HTTP fetch)
```
This is the flood that trips vitest/turbo output limits in the root run.

**After the fix** (same command, server still up):
```
$ vitest run            →  exit 0
  ✓ test/run.test.ts   (3 tests)
  ✓ test/guard.test.ts (1 test)
  Test Files  2 passed (2)
       Tests  4 passed (4)
$ wc -c after.out       →  363 bytes       (no payload; fetch never called)
$ grep '"rows":\[0,'    →  0 matches
$ tsc --noEmit          →  OK
$ pnpm test  (root, turbo) →  Tasks: 1 successful, 1 total · exit 0 · no ELIFECYCLE
```

**Edge cases tested:**
- **Invalid format** → exit(1), `fetch` not called, `stdout.write` not called, stderr message intact.
- **Guard-only** (`test/guard.test.ts`): exit spy with *no* fetch/stdout mocks at all — the `return;` alone prevents any fall-through (proves the structural fix, not just the mocks).
- **Upstream HTTP 500** → exit(2), no stdout write, stderr message intact.
- **Happy path** (`--format json`) → fetch URL built from `resolveServerUrl` (`/api/export?format=json`), payload still delivered via stdout — success path unaffected.
- **Hygiene**: `vi.restoreAllMocks()` + `vi.unstubAllGlobals()` in `afterEach` so spies/stubs never leak across tests.
