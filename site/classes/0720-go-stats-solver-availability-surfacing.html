GAP 005 — server silently degrades without a solver (three pieces):

  1. solver.go — detection that requires the full stack, so a half-present stack can't be mistaken for a working solver:
var requiredSolverCmds = []string{"bwrap", "pi-agent"}

func detectSolver() string {
    for _, name := range requiredSolverCmds {
        p, err := exec.LookPath(name)
        if err != nil || strings.TrimSpace(p) == "" {
            return "" // bwrap or pi-agent missing -> no solver
        }
    }
    p, _ := exec.LookPath("pi-agent")
    return strings.TrimSpace(p)
}
  1. main.go — wiring: prominent WARN + cron gating, solver_available derived from solverExec != nil:
const solverWarnMsg = "WARN: solver unavailable: bwrap and/or pi-agent not found on PATH; " +
    "cron loop NOT started and the queue will NOT be drained. " +
    "Install bwrap and pi-agent, or GET /api/v1/stats will report solver_available=false"

func wire(solverExec string) (*http.ServeMux, bool) {
    available := solverExec != ""
    if !available {
        log.Print(solverWarnMsg)          // operator-visible, not silent
    } else {
        startCronLoop(context.Background(), solverExec) // only drains when it can
    }
    mux := http.NewServeMux()
    mux.HandleFunc("GET /api/v1/stats", newStatsHandler(available))
    return mux, available
}
  1. stats.go — GET /api/v1/stats exposes the boolean; cron.go drains the queue only when the loop is running:
type statsResponse struct {
    SolverAvailable bool   `json:"solver_available"`
    QueueDepth      int    `json:"queue_depth"`
    StartedAt       string `json:"started_at"`
    UptimeSecs      int64  `json:"uptime_secs"`
}

**Live smoke test (real binary, real ports):**

- Solver missing (PATH stripped): log shows the WARN, no cron line; `GET /api/v1/stats` → `{"solver_available":false,"queue_depth":0,...}` (200)
- Solver present (this machine genuinely has `/home/kara/.local/bin/pi-agent` + `bwrap`): log shows `cron loop started (solver=/home/kara/.local/bin/pi-agent)`; `GET /api/v1/stats` → `{"solver_available":true,...}` (200)
- Routing: POST → 405, GET → 200, unknown path → 404

**Edge cases hit during verification:** (a) the detection tests initially leaked the ambient PATH, which *contains a real pi-agent and bwrap* — they failed until PATH was isolated; that's exactly the failure mode this fix surfaces instead of hiding. (b) The cron test initially raced temp-dir cleanup against in-flight job exec because the queue is cleared before draining — fixed by waiting for per-job completion markers. (c) The initial port 18080 was occupied by another process in this sandbox — re-ran on free ports.
