Diagnosis complete — verified solution written to /home/kara/solution.md

Root cause: The section-14 cell asserted that bunker destroy <never-seen-id> (non-force) must exit non-zero. But exit 0 is the documented CLI contract: internal/cli/destroy.go:80,90 maps both connect.CodeNotFound and in-band Status=="not_found" to Agent <id> not found. + exit 0, documented in internal/cli/SKILL.md:7, pinned by TestDestroyCommand_CodeNotFound, and requested by DOGFOOD-005. The daemon provably answers correctly (internal/server/service.go:329 → connect.CodeNotFound, live HTTP 404). So the cell could never pass — a harness lie, not a product bug.

Fix (commit 0edfb11, harness-only, +44/-8): Assert each fact at the layer where it lives: 1. CLI: exit 0 and not found text 2. Daemon: raw DestroyAgent RPC → HTTP 404 3. Registry: 0 durable records for the ID 4. Unique per run (gap070-never-seen-$$-$(date +%s)) so an earlier run can't make "never seen" a lie

Verification (all run against the checkout): - go test ./internal/cli/ -run 'TestDestroyCommand_CodeNotFound|TestDestroyCommand_NotFound' → PASS (both) - bash -n e2e-full-battery.sh → OK; grep -c 'unexpectedly succeeded' → 0 - bash e2e-full-battery.sh --self-test → SELF-TEST: PASS - Recorded live: pre-fix red reproduced on the deployed script; post-fix cell → GREEN 3/0 against the production daemon (exit 0 + not found, RPC 404, registry 0)
