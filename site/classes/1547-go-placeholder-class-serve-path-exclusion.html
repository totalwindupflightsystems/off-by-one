Fix: Exclude Placeholder/Self-Test Probe Classes from Serve Paths

Problem class: go-placeholder-class-serve-path-exclusion Fix reference: OB-GAP-061, commit 68a7f32

Summary

Placeholder / self-test probe classes (off-by-one-self-test, canary, dogfood, ds-007, tickN-e2e families) were being returned as verified answers by /api/v1/problems/discover and listed by /api/v1/queue. The Python exporter (scripts/export-answers.py) already excluded these via EXCLUDED_CLASS_PATTERNS, but the Go read/serve path never ported that predicate. The fix ports it into a single reusable Go predicate and applies it at both the lookup and list boundaries, before pagination.

Root Cause

  1. Discovery / serve path. Store.Discovery looked a problem up by title and returned it without consulting the exclusion list. The API handler renders ErrNotFound as the standard 404 not_found, so a placeholder class with a matching title was served as a real verified answer.
  2. Queue list path. Queue.List paginated the raw store slice. Placeholders appeared in results, and filtering bolted on after limit/offset would produce dishonest Total and positions. Filtering must happen in Go before pagination.

A naive strings.Contains(class, "test") would also exclude real test-* classes, so the port must preserve the exact patterns and not over-match.

The Fix

1. New predicate — internal/graph/placeholder.go

package graph

import "regexp"

// placeholderClassPatterns mirrors EXCLUDED_CLASS_PATTERNS in
// scripts/export-answers.py: probe/self-test classes that must never be
// served as real answers. Patterns are matched case-insensitively as an
// unanchored search (regexp .MatchString), exactly like Python re.search.
var placeholderClassPatterns = []*regexp.Regexp{
    regexp.MustCompile(`(?i)off-by-one-self-test`),
    regexp.MustCompile(`(?i)canary`),
    regexp.MustCompile(`(?i)dogfood`),
    regexp.MustCompile(`(?i)ds-007`),
    regexp.MustCompile(`(?i)tick\d+-e2e`),
}

// IsPlaceholderClass reports whether class is a placeholder / self-test probe
// class. Real evaluation classes such as "test-*" are deliberately not matched.
func IsPlaceholderClass(class string) bool {
    for _, re := range placeholderClassPatterns {
        if re.MatchString(class) {
            return true
        }
    }
    return false
}

2. Serve path — Store.Discovery returns ErrNotFound

func (s *Store) Discovery(title string) (Problem, error) {
    p, ok := s.byTitle[title]
    if !ok {
        return Problem{}, ErrNotFound
    }
    // Placeholder/self-test probes are not answers. Returning ErrNotFound
    // keeps the HTTP layer unchanged: it already maps ErrNotFound -> 404.
    if graph.IsPlaceholderClass(p.Class) {
        return Problem{}, ErrNotFound
    }
    return p, nil
}

3. List path — Queue.List filters before pagination

func (q *Queue) List(offset, limit int) (Page, error) {
    // Filter placeholders in Go BEFORE limit/offset so Total and positions
    // describe only the entries a caller can actually see.
    filtered := make([]Entry, 0, len(q.entries))
    for _, e := range q.entries {
        if graph.IsPlaceholderClass(e.Class) {
            continue
        }
        filtered = append(filtered, e)
    }

    total := len(filtered)
    if offset < 0 {
        offset = 0
    }
    if offset > total {
        offset = total
    }
    end := total
    if limit >= 0 && offset+limit < end {
        end = offset + limit
    }
    return Page{Entries: filtered[offset:end], Total: total, Offset: offset, Limit: limit}, nil
}

  • internal/graph/placeholder_test.go — new, predicate truth table

  • internal/graph/queue.go — List filters placeholders before pagination
  • Tests updated for the store and queue boundaries

Notes / Edge Cases

  • Matching is case-insensitive and unanchored to mirror re.search; off-by-one-self-test-v2 is correctly excluded.
  • tick\d+-e2e requires digits, so a real tick-e2e class is not excluded.
  • Filtering before pagination is mandatory; filtering the returned page would under-count Total and shift positions.
  • The HTTP handler is untouched; ErrNotFound already yields the standard 404 not_found.
