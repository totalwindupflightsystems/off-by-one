Fix: pre-commit secret scanner false-positives on kebab slugs

Problem class: git-hook-secrets-regex-false-positive

The pre-commit hook's sk-… secret alternative treats any long run of [A-Za-z0-9_-] as an API key. Legitimate kebab-case identifiers (sk-learn-pipeline-refactor, risk-management-framework) are therefore reported as leaked secrets and the commit is blocked.

1. Root cause

The offending alternative looked like this:

sk-[A-Za-z0-9_-]{16,}

Two independent defects make slug text match:

  1. No left-hand token boundary. sk- is matched as a substring in the middle of a larger token, so risk-management-framework matches on the sk- inside risk-management… (likewise disk-usage-…, task-…).
  2. Permissive body with no entropy requirement. The body charset includes -, and the only constraint is length ≥ 16. A kebab slug is exactly lowercase-words-joined-by-hyphens, so sk-learn-pipeline-refactor-cleanup is a byte-perfect match. Real API keys are opaque high-entropy tokens that in practice always contain at least one digit; ordinary slugs do not.

Both defects must be closed. A boundary alone still matches slugs that literally start with sk-; a digit requirement alone still matches risk-management-v2-framework.

2. Exact fix

Require a token boundary before sk- and at least one digit in the sk- body, while leaving length/charset unchanged.

- sk-[A-Za-z0-9_-]{16,}
+ (?<![A-Za-z0-9])sk-(?=[A-Za-z0-9_-]*[0-9])[A-Za-z0-9_-]{16,}
Fragment Purpose
(?<![A-Za-z0-9]) Left token boundary — char before sk must not be alphanumeric, so risk-, disk-, task- no longer match.
sk- Literal prefix (unchanged).
(?=[A-Za-z0-9_-]*[0-9]) Zero-width lookahead: body must contain ≥ 1 digit. Rejects sk-learn-pipeline-refactor.
[A-Za-z0-9_-]{16,} Original minimum length / charset (unchanged).

Python hook (recommended)

import re

SK_PATTERN = r"(?<![A-Za-z0-9])sk-(?=[A-Za-z0-9_-]*[0-9])[A-Za-z0-9_-]{16,}"
SECRET_RE = re.compile(
    "|".join([r"AKIA[0-9A-Z]{16}", r"ghp_[A-Za-z0-9]{36}", SK_PATTERN])
)

def scan(text: str) -> list[str]:
    return [m.group(0) for m in SECRET_RE.finditer(text)]

Shell hook (grep -P, GNU grep)

#!/usr/bin/env bash
# .git/hooks/pre-commit
set -euo pipefail
SECRET_RE='(AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{36}|(?<![A-Za-z0-9])sk-(?=[A-Za-z0-9_-]*[0-9])[A-Za-z0-9_-]{16,})'

status=0
while IFS= read -r -d '' file; do
  [[ -f "$file" ]] || continue
  if matches=$(grep -PnH -- "$SECRET_RE" "$file" 2>/dev/null); then
    echo "Potential secret in $file:"; echo "$matches"; status=1
  fi
done < <(git diff --cached --name-only -z --diff-filter=ACM)
exit "$status"

Engine compatibility

Lookarounds work in Python re and GNU grep -P (PCRE). They are not supported by Go RE2 (gitleaks) or POSIX ERE. Portable fallback (verified below):

\bsk-[A-Za-z0-9_-]*[0-9][A-Za-z0-9_-]{15,}

\b supplies the boundary; digit-plus-15-trailing-chars enforces a digit. Slightly stricter, so prefer the lookaround form when available.

3c. Portable fallback

grep -nE '\bsk-[A-Za-z0-9_-]*[0-9][A-Za-z0-9_-]{15,}' ere.txt
# 1:sk-a***
# 2:sk-proj-abc123def456ghi789jkl012mno
# 3:sk-9***

Legitimate slugs produce no matches.

4. Optional hardening

A slug embedding a version number, e.g. sk-learn-model-v2-pipeline-refactor, still slips through because it contains 2. To also reject -vN suffixes, require the digit inside an alphanumeric run:

(?<![A-Za-z0-9])sk-(?=[A-Za-z0-9_-]*(?:[A-Za-z0-9][0-9][A-Za-z0-9]|[0-9][A-Za-z0-9]{2}))[A-Za-z0-9_-]{16,}

Verified: still matches all real-key fixtures (including a key starting with a digit) and now rejects the versioned slug.

5. Trade-offs

  • Real keys are assumed to contain a digit; an all-letter key would be missed. This is the deliberate exchange, reinforced by the unchanged 16-char minimum.
  • The boundary is "not preceded by an alphanumeric", keeping keys after =, :, whitespace, quotes, or line start detectable.
  • AWS/GitHub alternatives are untouched.

Key result: every kebab-slug false positive is eliminated while all real-key fixtures still match — confirmed both at the regex level and through an actual git commit that is now correctly blocked.
