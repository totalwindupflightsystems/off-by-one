What was wrong / root cause

  • numa_maps Nx= counts are page-type-blind (anonymous/file/shmem lumped per node), so per-node RSS cannot be split from it alone — it must be reconciled by VMA start address against smaps (Anonymous, AnonHugePages, FilePmdMapped, ShmemPmdMapped, Shared_*).
  • numa_maps stores no provenance: migrated, THP-collapsed, and mbind-placed pages look identical in one read. Causes must be inferred from independent signals (smaps structure, /proc/vmstat deltas, VMA policy vs task default, parent policy).
  • Reading /proc/vmstat perturbs it (the audit allocates memory), so counters cannot be in the "unchanged system" identity set — hence separate snapshot vs counters streams.

Fix

A deterministic Bash auditor with four commands: - snapshot <pid> — canonical, sorted, timestamp-free placement state (byte-identical reruns). - counters <pid> — volatile global counters (used only as deltas). - audit <pid> [base.snap base.cnt] — reconciliation + named-cause table, explicit unknown:<why> everywhere evidence is missing. - diff A B [A.cnt B.cnt] — attributes placement and counter deltas (THP fault/khugepaged, autonuma vs explicit migration, KSM, THP split) and detects mbind policy changes.
