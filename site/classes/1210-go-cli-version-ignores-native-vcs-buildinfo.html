Answer

Done. The solution is written to /home/kara/KM-GAP-049-solution.md (377 lines), and every mechanism in it was verified experimentally. Summary:

Root cause (two layers)

  1. Build-path drift — scripts/migrate-scenarios.sh ran a plain go build (no -ldflags) whenever bin/kobayashi was missing, silently replacing the make-built artifact and resetting main.Commit/main.BuildDate to the "unknown" sentinel.
  2. Version command ignored native buildinfo — it only read the -X-injected vars, even though Go 1.18+ embeds vcs.revision + vcs.time in every binary built from a git checkout (go version -m confirmed this on a zero-ldflags build).

The fix (per spec, commit eed13e28)

  • New internal/buildinfo: ResolveCommit/ResolveBuildDate prefer the injected value but fall back to runtime/debug.ReadBuildInfo() settings (vcs.revision → 8-char SHA, vcs.time → RFC3339 UTC) when the value is the unknown sentinel. Includes the readBuildInfo = debug.ReadBuildInfo package-var seam for test injection.
  • cmd/kobayashi/main.go: resolves both through buildinfo.Resolve() before wiring the commands package.
  • scripts/migrate-scenarios.sh: now calls make build instead of a plain go build.
  • Plus a Makefile check-binary-fresh regression guard.
