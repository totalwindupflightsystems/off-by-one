Repairing a Pretty-Printed JSONL Board Header

Symptom

The smoke canary's board probe failed on the first line of a git-tracked JSONL board store:

PARSE_ERROR: Expecting property name enclosed in double quotes: line 2 column 1 (char 2)

A second, independent check failed in the same run — the tick-history check:

9 new failed/timeout tick(s) since last board entry ()

Two FAILs, one root cause.

Root-Cause Analysis

board.jsonl is a line-wise store with an invariant:

  • line 1 = the board header, exactly one JSON object on one line
  • lines 2..N = one JSON row per line

An agent serialized the header dict through json.dumps(header, indent=2), splitting the single object across 16 physical lines:

{
  "schema": "board/1",
  "last_tick": 42,
  ...
}
{"tick":40,...}

Line-wise consumers read only line 1. That line is now the lone character {, so json.loads raises exactly the reported PARSE_ERROR.

The cascade:

  1. Board probe catches the parse error and prints an empty last_tick baseline.
  2. The tick-history check reads its baseline from the probe's stdout, receives "", and therefore compares every historical failed/timeout tick against nothing → all 9 old ticks are re-counted as new failures.

The damage is formatting only — the header JSON itself is intact. json.loads parses whitespace/newlines freely, so the fix is to parse the multiline object, then re-emit it on one line using the repo's exact separator convention.

The Fix

1. Learn the repo's exact header convention from pre-damage git bytes

Do not guess between compact {"a":1} and default {"a": 1}. Re-dump the pre-damage header and byte-compare:

git log --oneline -- .coding-hermes/board/board.jsonl
# find the commit before the pretty-print damage, e.g. 5fac8c8 / damage b1277dd
git show 5fac8c8:.coding-hermes/board/board.jsonl | head -1

2. Repair script (self-contained, idempotent)

#!/usr/bin/env python3
"""Repair a JSONL board store whose single-line header was pretty-printed.

Header = first JSON value; rows follow, one JSON value per line.
Learns the exact separator convention by byte-comparing against the
pre-damage git revision, then re-emits the header on ONE line.
Usage: repair_board_header.py <path> <pre-damage-rev>
"""
import json, subprocess, sys

PATH = sys.argv[1] if len(sys.argv) > 1 else "board.jsonl"
REV  = sys.argv[2] if len(sys.argv) > 2 else "HEAD^"   # canonical revision


def known_convention(path, rev):
    """Return json.dumps kwargs matching the canonical header bytes."""
    try:
        blob = subprocess.check_output(["git", "show", f"{rev}:{path}"])
    except subprocess.CalledProcessError:
        return None
    first = blob.split(b"\n", 1)[0].decode("utf-8")
    obj = json.loads(first)
    for seps, ascii_ in [((",", ":"), False), (None, False),
                         ((",", ":"), True), (None, True)]:
        kw = {} if seps is None else {"separators": seps}
        kw["ensure_ascii"] = ascii_
        if json.dumps(obj, **kw) == first:
            return kw
    return None


def split_header(text):
    """Parse the first JSON value regardless of internal newlines."""
    i = 0
    while i < len(text) and text[i] in " \t\r\n":
        i += 1
    return json.JSONDecoder().raw_decode(text, i)   # (obj, end_index)


def main():
    raw = open(PATH, "r", encoding="utf-8").read()
    obj, end = split_header(raw)

    body = raw[end:]
    if body.startswith("\n"):
        body = body[1:]
    if body.startswith("\r"):
        body = body[1:]

    conv = known_convention(PATH, REV)
    if conv is None:
        print("WARN: no git baseline; defaulting to compact separators",
              file=sys.stderr)
        conv = {"separators": (",", ":")}

    out = json.dumps(obj, **conv) + "\n" + (body if body.endswith("\n") else body + "\n")
    if out == raw:
        print("OK: header already canonical; no change")
        return 0
    open(PATH, "w", encoding="utf-8").write(out)
    print(f"REPAIRED: header on one line with {conv}")
    return 0


if __name__ == "__main__":
    sys.exit(main())

Run it against the canonical revision and commit:

python3 repair_board_header.py .coding-hermes/board/board.jsonl 5fac8c8
git diff -- .coding-hermes/board/board.jsonl        # header is one changed line
git add .coding-hermes/board/board.jsonl
git commit -m "repair: re-emit board header on single JSONL line"

The re-dump preserves the trailing newline, and because rows are sliced at the first JSON value's end and copied verbatim, no row bytes change.

Prevention: assert single-line format in the canary

Never pass a stored header through a pretty-printing dump. Add this write-time/read-time guard so the class is caught immediately:

import json, sys

def assert_single_line_header(path):
    with open(path, "r", encoding="utf-8") as fh:
        first = fh.readline()
    try:
        hdr = json.loads(first)
    except Exception as e:
        sys.exit(f"CANARY FAIL: header not parseable on line 1: {e}")
    if not isinstance(hdr, dict):
        sys.exit("CANARY FAIL: header is not a JSON object")
    if first.count("\n") != 1 or not first.endswith("\n"):
        sys.exit("CANARY FAIL: header is not a single newline-terminated line")
    print("canary ok: single-line JSONL header")

assert_single_line_header(".coding-hermes/board/board.jsonl")

And write headers only with a single-line dumper:

# GOOD
def write_header(fh, header):
    fh.write(json.dumps(header, separators=(",", ":")) + "\n")

# BAD — do not use on stored lines
# json.dump(header, fh, indent=2)

Key points

  • The corruption is purely presentational; json.loads on the whole slice recovers the header without data loss.
  • The separator convention must be derived from the pre-damage git blob and byte-compared, not assumed.
  • raw_decode locates the true end of the first JSON value, so rows are preserved byte-for-byte.
  • A single-line assertion in the canary converts a silent multi-line write into an immediate, localized failure instead of a downstream cascade.
