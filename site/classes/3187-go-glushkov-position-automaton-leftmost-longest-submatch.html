Solution: Glushkov position automaton with leftmost-longest POSIX submatches

Root-cause analysis

The environment had only problem.json — no starter repo, no harness. The failure modes this problem class encodes are structural:

  1. Epsilon transitions / 2^m blow-up. A Thompson NFA is the obvious compiler, but subset-constructing away its ε-transitions is not O(m). The fix is the position (Glushkov) construction: one state per symbol position + a start state, with ε-reachability folded into first/last/follow.
  2. Counted repetition explodes before you notice. a{1000000} makes 10⁶ positions; (a{1000}){1000} makes 10¹². Budget must be checked with saturated arithmetic before allocation, returning a typed error.
  3. Anchors are zero-width. Modelling ^/$ as symbols makes a^b match. They must be guards on transitions, evaluated at the current offset (^ ⇔ offset 0, $ ⇔ len).
  4. Leftmost-longest is insufficient for submatches. (a|ab)(b?) on ab must give group1=[0,2), not the Perl-greedy group1=a. Needs tag histories + a total POSIX order.
  5. Repeated groups capture the last iteration. (a)+ on aa captures the second a; closing a tag must overwrite, not min/max.
  6. Unset vs empty. (a?)*b on b must report group 1 as [0,0), so nullable groups need explicit open+close events.
  7. Naive leftmost search is O(n²). A backward reachability pass finds the leftmost start in O(n·m); only that start is simulated with tags.
  8. Oracle must be independent. A parse-tree enumerator (derivative view) shares no simulation code with the automaton.

The fix

Architecture: parse → budget(saturated, typed error) → Thompson NFA (symbol positions, tagged ε-edges for groups, guarded ε-edges for anchors) → ε-closure over simple paths → Glushkov automaton (states = positions+1, no ε) → tagged POSIX simulation.

Key pieces (full listing in SOLUTION.md):

  • Budget (regex.go): countPositions saturates at StateBudget+1; Compile returns *StateBudgetError{Limit, Needed} before building.
  • Guards (nfa.go): guard{needStart, needEnd}, DNF-combined through ε-closure; eval(i,n).
  • Tags (nfa.go): group entry --open(g)--> … --close(g)--> exit; applyOps overwrites spans so last iteration wins.
  • ε-elimination (glushkov.go): closure(state) over simple paths yields start, follow, acceptFrom — all consuming a symbol; zero ε-transitions.
  • POSIX order (sim.go): better compares groups 1..G (participating beats unset; smaller start, then larger end); dominates prunes soundly.
  • Leftmost (sim.go): backward reachability B[i] finds the smallest viable start in O(n·m); matchAt then computes the longest end and best history.
