Summary

Root causes found (all reproduced by the tests):

  1. Tombstone elision resurrects sibling L0 data — a compaction may read a tombstone + a lower-level value while leaving an overlapping sibling table that holds an older value. The bottommost test must scan every level, not just deeper ones.
  2. Bottommost must use the full expanded output range — a next-level table pulled in can widen the key range into a sibling source-level table. Testing only the original source window wrongly elides a needed tombstone.
  3. Snapshot pinning — the minimal safe retention set is {newest} plus {newest version ≤ S for each pinned snapshot S}.
  4. Crash mid-step — a step must commit atomically only after all output files are durable; partial outputs are orphans and recovery discards them.

The fix (in planner.py): - retained_versions: exact snapshot retention + guarded tombstone elision. - _bottommost: checks all levels over the full expanded input range. - generate_candidates: iteratively expands next-level overlaps to a fixed point; feasibility is fan_in·read_buffer + write_buffer ≤ memory_cap. - Greedy selection by minimum output_bytes / input_bytes (write amplification). - Step carries per-output SHA-256 checksums; apply_plan re-derives and verifies them; simulate_crash_recovery proves recovery at every output-file boundary.
