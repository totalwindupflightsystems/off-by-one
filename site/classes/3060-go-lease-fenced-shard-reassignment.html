Diagnosis

The root cause is using time as the ownership authority. Leases only say "A may write until T"; under clock skew, GC pauses, or delayed revokes, A can act after T while the controller has already granted ownership to B. Replicas apply by arrival order, so reordered old writes still land. Time-based authority cannot be made safe.

The fix

  1. Fencing token (per-shard Epoch) issued by a single durable authority, persisted before any side effect.
  2. Replica token floor: each replica stores maxToken and rejects any op with token < maxToken.
  3. Quorum commits + quorum fencing: any two quorums intersect, so once a new token commits, no older token can ever reach a quorum.
  4. Three-phase replay-safe handoff: durable Pending{to, epoch} → fence a quorum → durable commit. Resume() replays interrupted handoffs.
  5. Idempotency: monotonic Fence, dedup by reqID, idempotent Reassign.
  6. Per-shard locks (not one global lock) so a slow handoff of one shard never blocks others.

Minimum durable state: controller = {epoch, owner, pending{to,epoch}} per shard (no durable lease timers needed); replica = {maxToken, data, applied[reqID]} per shard. The only production assumption is that the authority itself is linearizable (Raft/etcd).
