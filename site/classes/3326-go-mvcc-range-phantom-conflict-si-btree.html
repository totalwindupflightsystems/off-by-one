Root cause

Snapshot isolation over a COW B-tree already gives stable, repeatable reads (immutable pages + atomic root swap), but it protects data items, not predicates. A transaction that does SCAN [a,z) and later commits has no record that it read that range, and the store keeps no version index of committed writes. So a concurrent PUT m inside [a,z) is never tested against the reader — the classic phantom. Full-range locks and commit-time re-scans don't fix this (deadlock/no composition, and they yield the current set, not the exact changed-key set).

The fix

Four pieces plus one commit-time check (all in txn.go, versionmap.go, btree.go, store.go):

  1. Append-only page log + pinning — immutable pages; every snapshot pins the pages it traverses.
  2. COW B-tree — path-copying insert with root/child splits; inOrder range traversal.
  3. Version interval map — key → []commitTS boundaries, indexed by sorted key list; answers "any key in [lo,hi) written in (from,to]" in two binary searches, no range locks.
  4. Read predicates — every Get records a point key, every Scan records [lo,hi).
  5. Commit protocol — under the single tree commit mutex, allocate commitTS, check all predicates in (snapTS, commitTS], abort with the sorted de-duplicated *ConflictError.Keys, otherwise apply COW writes atomically.
