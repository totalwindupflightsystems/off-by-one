# Watertight Fixed-Point Triangle Rasterization with Perspective-Correct UVs

## TL;DR

The cracks/overlaps are not caused by “not enough epsilon.” They are caused by making the shared-edge decision in floating point (or in a finite-width fixed-point type) and by using an asymmetric `<`/`<=` fill rule. The fix is:

1. Snap each **mesh vertex once** onto an integer subpixel lattice.
2. Evaluate edge functions with **exact arbitrary-precision integers** using coordinate differences local to the triangle.
3. Decide boundary ownership with a **top-left rule**, never with draw order or epsilon.
4. Compute barycentrics from those same exact edge values, then interpolate attributes with the perspective-correct `1/w` formula.

The implementation below is in `~/raster_solution/rasterizer.py`; the verifier is `~/raster_solution/test_rasterizer.py`.

---

## Root-cause analysis

### 1. A shared edge becomes two different edges

A triangle rasterizer normally tests

```text
E(a,b,p) = (b.x-a.x)*(p.y-a.y) - (b.y-a.y)*(p.x-a.x)

For adjacent triangles the shared edge is traversed in opposite directions:

T1: E(A,B,p)
T2: E(B,A,p) = -E(A,B,p)

That exact negation is the whole watertightness proof. It holds only if both triangles use bit-identical snapped endpoints and exact arithmetic. If E is accumulated in float, float32, or a 32-bit fixed-point integer, then at large coordinates the two values are no longer exact negatives. A pixel on the shared edge can become positive for both triangles (double shading) or negative for both triangles (a crack). This is the “precision decay” seen during a long animation: absolute world coordinates grow, products and edge values grow faster, and the available precision is eventually smaller than one subpixel.

Independent per-triangle snapping also breaks the proof if the “same” shared endpoint is regenerated from slightly different floating-point values or is snapped with a different rounding mode.

2. > versus >= is not a tie-break rule

For a sample exactly on an edge, E == 0:

  • E >= 0 in both triangles ⇒ the pixel is shaded twice.
  • E > 0 in both triangles ⇒ the pixel is shaded by neither.

Adding an epsilon makes the situation worse: a pixel can fall inside the epsilon band of both sides or of neither side, and the result depends on triangle order. Draw order is not a valid ownership rule.

3. Finite-width fixed-point arithmetic overflows

Snapping to, say, 8 subpixel bits and then storing edge functions in signed 32-bit or 64-bit integers is safe only for a bounded coordinate range. A long animation eventually exceeds that range. Once the product overflows, the sign of the edge function is arbitrary, so cracks and overlaps appear suddenly.

4. Screen-space interpolation is not perspective-correct

Linearly interpolating u,v in screen space is only correct for affine/orthographic projection. For a perspective projection the correct interpolation is

invW(p) = Σ λ_i * (1 / w_i)
attr(p) = Σ λ_i * (attr_i / w_i) / invW(p)

where λ_i are the triangle barycentrics.

The exact fix

Fixed-point lattice and exact edge test

Choose SUB = 2^S subpixel positions per pixel (the implementation uses S = 8, i.e. 256). Snap every mesh vertex once:

X = floor(x * SUB + 0.5)
Y = floor(y * SUB + 0.5)

Use floor(x+0.5) rather than banker’s rounding so negative coordinates are deterministic too. Cache snapped vertices by vertex index; do not snap the same shared endpoint independently in each triangle.

Pixel (i,j) is sampled at the exact integer point

px = i*SUB + SUB/2
py = j*SUB + SUB/2

All edge functions and the triangle area are computed with Python integers, which are arbitrary precision. Therefore the sign of an edge function is exact at any coordinate magnitude. Differences such as b.x-a.x keep the arithmetic local, so translating the whole scene does not enlarge the products.

Normalize winding by swapping vertices and their attributes when the exact area is negative. Degenerate triangles are skipped.

Top-left ownership rule

For a positively wound triangle the interior is E >= 0. A zero edge is owned by this triangle iff the directed edge is a top or left edge:

top_left(a,b) = (b.y > a.y) or (b.y == a.y and b.x < a.x)

For any edge and its reverse, exactly one satisfies this predicate:

top_left(a,b) XOR top_left(b,a) == True

Therefore:

  • if E != 0, exactly one triangle sees a positive edge value;
  • if E == 0, exactly one triangle’s top-left predicate accepts the edge.

This is independent of triangle order and independent of coordinate magnitude, so it is provably crack-free and overlap-free across every shared edge.

Barycentrics and perspective correction

For normalized positive area A:

λ_A = E(B,C,P) / A
λ_B = E(C,A,P) / A
λ_C = E(A,B,P) / A

Then:

iw = λ_A/w_A + λ_B/w_B + λ_C/w_C
u  = (λ_A u_A/w_A + λ_B u_B/w_B + λ_C u_C/w_C) / iw
v  = (λ_A v_A/w_A + λ_B v_B/w_B + λ_C v_C/w_C) / iw

The edge values and area stay integers; only the final ratios and attribute arithmetic use floating point.

Implementation

"""rasterizer.py — watertight, perspective-correct triangle rasterizer."""

from __future__ import annotations

from dataclasses import dataclass
from math import floor, isfinite
from typing import Dict, Iterable, Sequence, Tuple


@dataclass(frozen=True)
class Vertex:
    x: float
    y: float
    w: float = 1.0
    u: float = 0.0
    v: float = 0.0


Pixel = Tuple[int, int]
UVW = Tuple[float, float, float]


def snap(v: float, subpixels: int) -> int:
    """Deterministic round-to-nearest on the integer subpixel lattice."""
    if not isfinite(v):
        raise ValueError(f"non-finite coordinate: {v!r}")
    return int(floor(v * subpixels + 0.5))


def _cross(ax: int, ay: int, bx: int, by: int, cx: int, cy: int) -> int:
    """Exact 2D cross product (b-a) x (c-a)."""
    return (bx - ax) * (cy - ay) - (by - ay) * (cx - ax)


def _ceil_div(a: int, b: int) -> int:
    return -((-a) // b)


def rasterize_triangle(
    p0: Vertex,
    p1: Vertex,
    p2: Vertex,
    *,
    sub_bits: int = 8,
) -> Dict[Pixel, UVW]:
    """Return {(i,j): (u, v, inv_w)} for all covered pixel samples.

    Pixel (i,j) is sampled at ((i+0.5), (j+0.5)) in world units.
    sub_bits=8 means 256 subpixel positions per pixel.
    """
    if not (1 <= sub_bits <= 16):
        raise ValueError("sub_bits must be in [1, 16]")

    sub = 1 << sub_bits
    half = sub >> 1

    ax, ay = snap(p0.x, sub), snap(p0.y, sub)
    bx, by = snap(p1.x, sub), snap(p1.y, sub)
    cx, cy = snap(p2.x, sub), snap(p2.y, sub)

    area = _cross(ax, ay, bx, by, cx, cy)
    if area == 0:
        return {}  # degenerate after snapping

    # Normalize to positive winding. Swap attributes together with geometry.
    if area < 0:
        bx, by, cx, cy = cx, cy, bx, by
        p1, p2 = p2, p1
        area = -area

    # Exact sample-lattice bounding box.
    min_x = min(ax, bx, cx)
    max_x = max(ax, bx, cx)
    min_y = min(ay, by, cy)
    max_y = max(ay, by, cy)

    ix0 = _ceil_div(min_x - half, sub)
    ix1 = (max_x - half) // sub
    iy0 = _ceil_div(min_y - half, sub)
    iy1 = (max_y - half) // sub

    # Top-left flags, constant for this triangle.
    tl_bc = (cy > by) or (cy == by and cx < bx)
    tl_ca = (ay > cy) or (ay == cy and ax < cx)
    tl_ab = (by > ay) or (by == ay and bx < ax)

    def inv_w(v: Vertex) -> float:
        if v.w == 0.0:
            raise ValueError("w must be nonzero (clip before rasterizing)")
        return 1.0 / v.w

    q0, q1, q2 = inv_w(p0), inv_w(p1), inv_w(p2)
    u0, u1, u2 = p0.u / p0.w, p1.u / p1.w, p2.u / p2.w
    v0, v1, v2 = p0.v / p0.w, p1.v / p1.w, p2.v / p2.w

    out: Dict[Pixel, UVW] = {}

    for j in range(iy0, iy1 + 1):
        py = j * sub + half
        for i in range(ix0, ix1 + 1):
            px = i * sub + half

            e_a = _cross(bx, by, cx, cy, px, py)  # opposite A
            if e_a < 0 or (e_a == 0 and not tl_bc):
                continue

            e_b = _cross(cx, cy, ax, ay, px, py)  # opposite B
            if e_b < 0 or (e_b == 0 and not tl_ca):
                continue

            e_c = _cross(ax, ay, bx, by, px, py)  # opposite C
            if e_c < 0 or (e_c == 0 and not tl_ab):
                continue

            # int/int division is correctly rounded in Python and does not
            # overflow for very large exact integers.
            l0 = e_a / area
            l1 = e_b / area
            l2 = e_c / area

            iw = l0 * q0 + l1 * q1 + l2 * q2
            u = (l0 * u0 + l1 * u1 + l2 * u2) / iw
            v = (l0 * v0 + l1 * v1 + l2 * v2) / iw
            out[(i, j)] = (u, v, iw)

    return out


def rasterize_mesh(
    vertices: Sequence[Vertex],
    indices: Iterable[Tuple[int, int, int]],
    *,
    sub_bits: int = 8,
) -> Tuple[Dict[Pixel, UVW], Dict[Pixel, int]]:
    """Rasterize indexed triangles and fail loudly on double shading."""
    pixels: Dict[Pixel, UVW] = {}
    owner: Dict[Pixel, int] = {}
    for tid, (i0, i1, i2) in enumerate(indices):
        tri = rasterize_triangle(
            vertices[i0], vertices[i1], vertices[i2], sub_bits=sub_bits
        )
        for p, val in tri.items():
            if p in pixels:
                raise RuntimeError(
                    f"overlap at {p}: triangles {owner[p]} and {tid}"
                )
            pixels[p] = val
            owner[p] = tid
    return pixels, owner

Verification

The verifier generates 10,000 randomized convex quadrilaterals, splits each along a diagonal into two triangles that share an edge, and rasterizes both. The animation drift grows with the trial index, so the shared vertices reach large absolute coordinates while each triangle remains small.

For every pair it independently computes the coverage of the union polygon (the quad) using exact integer edge tests. It then checks:

T1 ∩ T2 = ∅                         (no overlap)
(T1 ∪ T2) = coverage(quad)          (no hole and no extra pixel)

It also compares the integer rasterizer against a double-precision rasterizer using the same snapped lattice.

Why the proof holds

For a shared edge A→B:

T1 sees E(A,B,p)
T2 sees E(B,A,p) = -E(A,B,p)

Both values are exact Python integers. If E != 0, exactly one is positive. If E == 0, the top-left predicate is true for exactly one of A→B and B→A. Thus every sample on the shared edge is assigned to exactly one triangle. Since this does not depend on coordinate magnitude, it remains true for the entire animation.

Important boundary conditions

  • Snap by vertex index, not by triangle. If two triangles use independently generated floating-point copies of a shared vertex, snap the mesh’s canonical vertex once and reuse it.
  • T-junctions are not shared edges. A vertex lying in the middle of another triangle’s edge needs explicit stitching or supported edge splitting; the top-left rule cannot repair a geometric T-junction.
  • Clipping is required for w <= 0. This rasterizer assumes triangles have already been clipped against the near plane (w > 0). It raises an error for w == 0.
  • Degenerate after snapping. If a triangle’s snapped area becomes zero, it is skipped. Keep the mesh scale comfortably above one subpixel, or increase sub_bits.
  • Snapping changes geometry by at most 1/(2·SUB) pixel. This is expected. Watertightness is about consistent ownership of the snapped geometry, not about matching the unsnapped float edge pixel-for-pixel. ```
