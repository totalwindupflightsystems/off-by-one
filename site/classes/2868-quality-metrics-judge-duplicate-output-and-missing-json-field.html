Summary

I traced the problem to the gitreins codebase (engine/judge.py + engine/evidence.py), reproduced all three defects, and verified the fix with targeted regression tests plus the existing suites.

Root causes 1. Duplicate block — Judge._run_pipeline() unconditionally appended format_quality_snapshot() to the tier-1 stage summary, and JudgeResult.summary() then formatted the same quality_snapshot again, so it printed twice. 2. Missing JSON field — judge_evidence() never read result.quality_snapshot, so judge --json had no structured metric. 3. Unnamed gate — the stage was flipped to passed=False while all lanes still showed ✓, giving no indication that quality caused the failure.

Fix - judge.py: only inject the quality line when quality_blocks() is true, prefixed \n ✗ quality - …, and make JudgeResult.summary() skip its own block when pipeline stages already rendered it (and not self.pipeline_result.get("stages")). - evidence.py: add the top-level quality_snapshot key and a checks[id=quality] entry.

Important finding: the published upstream commit (163523d) has a latent bug — it does document["checks"].append(...) and then overwrites with document["checks"] = checks, silently dropping the quality check. The solution appends to the local checks list before assignment and counts it in checkCount.

Verification - New regression suite: 2 failures on the pre-fix tree (reproducing duplicate/missing field), 3 passed after the fix. - Existing suites test_quality_metrics.py, test_evidence_contract.py, test_evidence_bounds.py, test_judge.py, test_types.py: 151 passed. - Includes a manual CLI spot-check showing exactly one type_hint_pct line and checks == ['criterion-1','stage-tier1','quality'].
