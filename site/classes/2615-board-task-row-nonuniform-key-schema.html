Key findings (verified, not just asserted)

  1. Root cause: idle-chore rows written by a hand-rolled writer emit either a short key set or extra keys. The canary/smoke check requires the exact canonical key set per row.

  2. Diagnosis trap: boardctl validate's census (N/M rows carry only canon keys) only counts extra keys as drift — short rows are reported as canonical. So boardctl validate can be green while smoke_check.py task_keys_uniform is red. Always use --strict-keys + the smoke check.

  3. boardctl update --normalize does not fix this — it only canonicalizes status/guard_result/ci_result values (confirmed: an 8-key row stayed 8 keys after --normalize). Hence the line-wise edit.

  4. Fix: only drifted lines are rewritten — missing canon keys filled with neutral defaults, extras folded into foreman_note, every other line byte-preserved. The canon is derived at runtime via a throwaway boardctl init, so it tracks whatever schema version is installed (my local probe: 32 keys; incident: 31).
