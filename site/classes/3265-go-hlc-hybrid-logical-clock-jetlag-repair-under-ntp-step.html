Fixing HLC Causality and Runaway Counters Under NTP Backward Steps

Environment: Go 1.26.8, Linux/amd64. Full working project is at ~/hlc (library + tests + SOLUTION.md).

Root-cause analysis

An HLC timestamp is (Wall, Logical) ordered lexicographically. A backward wall-clock step (NTP correction, VM pause/resume) exposes two bugs:

  1. The tempting fix breaks happens-before. Snapping Wall down to the new physical time (wall = pt) makes the next timestamp smaller than one already sent to a peer. A message sent before the step then sorts after its receive event. TestNaiveResetFailsCausality demonstrates this.

  2. The correct monotonic fix lets the counter run away. Keeping Wall monotonic preserves causality, but every event during the repair window increments Logical. With step D and event rate R, the counter reaches ≈ R·D — effectively an unbounded second clock that can overflow and no longer tracks physical time.

The real constraint: you cannot have a hard-bounded counter, strict monotonicity, and a wall that never advances past physical time simultaneously. The right trade-off is to cap Logical and carry into Wall when saturated. A carry costs MaxLogical+1 events, so Wall advances at most 1 ns per MaxLogical+1 events and stays glued to physical time.

The fix

Timestamp: (Wall int64, Logical uint64, Node uint64), lexicographic; Node is a tie-breaker.

Local event / send (Now):

pt = physical()
if pt > Wall:            Wall = pt; Logical = 0      // forward step / recovery
else if Logical < Max:   Logical++                   // same or backward time
else:                    Logical = 0; Wall++         // bounded carry

Receive / merge (Update(msg)):

w = max(Wall, msg.Wall, pt)
if w == Wall == msg.Wall: Logical = max(Logical, msg.Logical) + 1
else if w == Wall:        Logical = Logical + 1
else if w == msg.Wall:    Logical = msg.Logical + 1
else:                     Logical = 0
Wall = w
if Logical > Max:         Logical = 0; Wall++        // enforce cap

+1 is saturating: if the operand is math.MaxUint64, advance Wall and return 0, so an adversarial peer cannot overflow us.

Core code (~/hlc/clock.go)

package hlc

import (
    "math"
    "sync"
    "time"
)

type PhysicalClock interface{ Now() int64 }

type SystemClock struct{}

func (SystemClock) Now() int64 { return time.Now().UnixNano() }

const DefaultMaxLogical = 1 << 20

type Config struct {
    Node       uint64
    MaxLogical uint64
    Clock      PhysicalClock
}

type Stats struct {
    MaxJetlag int64
    Carries   uint64
    Updates   uint64
}

type Clock struct {
    mu         sync.Mutex
    wall       int64
    logical    uint64
    node       uint64
    maxLogical uint64
    phys       PhysicalClock
    maxJetlag  int64
    carries    uint64
    updates    uint64
}

func New(cfg Config) *Clock {
    ml := cfg.MaxLogical
    if ml == 0 {
        ml = DefaultMaxLogical
    }
    p := cfg.Clock
    if p == nil {
        p = SystemClock{}
    }
    c := &Clock{node: cfg.Node, maxLogical: ml, phys: p}
    c.wall = p.Now()
    return c
}

func (c *Clock) Now() Timestamp {
    c.mu.Lock()
    defer c.mu.Unlock()

    pt := c.phys.Now()
    switch {
    case pt > c.wall:
        c.wall = pt
        c.logical = 0
    case c.logical < c.maxLogical:
        c.logical++
    default:
        c.logical = 0
        c.wall++
        c.carries++
    }
    c.trackJetlag(pt)
    return c.ts()
}

func (c *Clock) Update(msg Timestamp) Timestamp {
    c.mu.Lock()
    defer c.mu.Unlock()

    pt := c.phys.Now()
    w := c.wall
    if pt > w {
        w = pt
    }
    if msg.Wall > w {
        w = msg.Wall
    }

    switch {
    case w == c.wall && w == msg.Wall:
        c.logical = bump(&w, maxU64(c.logical, msg.Logical))
    case w == c.wall:
        c.logical = bump(&w, c.logical)
    case w == msg.Wall:
        c.logical = bump(&w, msg.Logical)
    default:
        c.logical = 0
    }
    c.wall = w

    if c.logical > c.maxLogical {
        c.logical = 0
        c.wall++
        c.carries++
    }
    c.updates++
    c.trackJetlag(pt)
    return c.ts()
}

func (c *Clock) Send() Timestamp                  { return c.Now() }
func (c *Clock) Receive(m Timestamp) Timestamp    { return c.Update(m) }
func (c *Clock) Node() uint64                     { return c.node }
func (c *Clock) Snapshot() Timestamp              { c.mu.Lock(); defer c.mu.Unlock(); return c.ts() }
func (c *Clock) Jetlag() int64                    { c.mu.Lock(); defer c.mu.Unlock(); return c.wall - c.phys.Now() }
func (c *Clock) Stats() Stats                     { c.mu.Lock(); defer c.mu.Unlock(); return Stats{c.maxJetlag, c.carries, c.updates} }

func (c *Clock) ts() Timestamp { return Timestamp{c.wall, c.logical, c.node} }

func (c *Clock) trackJetlag(pt int64) {
    if j := c.wall - pt; j > c.maxJetlag {
        c.maxJetlag = j
    }
}

func bump(w *int64, x uint64) uint64 {
    if x == math.MaxUint64 {
        *w++
        return 0
    }
    return x + 1
}

func maxU64(a, b uint64) uint64 {
    if a > b {
        return a
    }
    return b
}

timestamp.go defines Timestamp{Wall, Logical, Node} with Compare, Before, After.

Why it is correct

  • Strict local monotonicity: Now either raises Wall or Logical; Update sets Wall = max(...) ≥ old Wall then raises Logical or Wall.
  • Happens-before: Update always returns a tuple strictly greater than msg (if w == msg.Wall, Logical = msg.Logical+1 or a carry raises Wall; if w > msg.Wall, Wall is already greater). Program order is covered by local monotonicity. Since < is transitive and happens-before is the transitive closure of program-order and send→receive edges, checking direct edges suffices.
  • Bounded counter: Logical ≤ MaxLogical after every operation.
  • Re-convergence: once pt > Wall, Now snaps Wall = pt, Logical = 0.

Provably bounded repair window

With step D, max drift ρ (physical advances at rate ≥ 1-ρ), event rate R, cap M (carry every M+1 events), the window W satisfies:

(1-ρ)W ≥ D + R·W/(M+1)
W ≥ D / ((1-ρ) - R/(M+1))

Finite iff R < (1-ρ)(M+1). If M ≥ R·D/(1-ρ) there are no carries during repair and W = D/(1-ρ) exactly. The default M = 1<<20 absorbs ~1M events per repair window.

Operational notes

  • Choose MaxLogical ≥ R·D/(1-ρ) from the worst repair window; the default 1<<20 is safe for ~1M events.
  • Never reset Wall downward; only Now may snap it up to pt.
  • Use a unique Node id for global uniqueness.
  • Jetlag() = Wall - physical is the repair gauge; it returns to ≤ 0 when physical time catches up.
  • Forward steps / VM resume are handled by the pt > Wall branch (jump forward, reset counter).
