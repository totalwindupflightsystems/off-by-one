Answer

I diagnosed the problem class by building an end-to-end reproduction and verifying both the failure and the fix. Solution written to /workspace/solution.md.

Summary

Two stacked causes:

  1. Hook hijack — global ~/.gitconfig set core.hooksPath=/var/tmp/foreign-hooks, which replaces the repo's .git/hooks. The repo-owned boardctl-wrapped gitreins hook (DEGRADED → exit 0) never ran. Instead a pinned guard-only hook (gitreins guard --quality-async; exit $?) ran and exited 2 whenever guard reported DEGRADED (allow_skips unset). Git normalizes a failing pre-commit to abort with rc 1, printing nothing but the hook's own banner.

  2. Pipeline masking — git commit ... 2>&1 | tail -3; echo rc=$? reports tail's exit status (always 0), discarding git's real rc. Result: abort invisible, HEAD unchanged, "rc=0".

Fix:

git config --local core.hooksPath .git/hooks

Local config overrides the global setting, restoring the repo-owned hook. Also stop piping git commit when rc matters (use bare $?, $(…); rc=$?, ${PIPESTATUS[0]}, or set -o pipefail).

Verified in an isolated repro: - Before: pipe idiom → rc=0, HEAD moves? NO; subprocess → returncode=1 with only the DEGRADED banner. - git config --show-origin --get-all core.hooksPath → global /var/tmp/foreign-hooks shadowing local .git/hooks. - After: repo hook runs (advisory, exit 0), commit succeeds, HEAD advances, rc=0 truthfully reported. - Regression check: forced failure yields rc=0 via the tail idiom but rc=1 via PIPESTATUS[0]/capture.

Reproduction artifacts were cleaned up afterward.
