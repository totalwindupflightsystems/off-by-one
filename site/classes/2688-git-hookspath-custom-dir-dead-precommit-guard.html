What's actually wrong

Git reads hooks from exactly one directory: core.hooksPath if set, otherwise .git/hooks. The repo set core.hooksPath=.githooks, but .githooks/ only contained pre-push. The correct pre-commit (755, calling &lt;tool&gt; guard) sat in .git/hooks/ — dead code. Git never reads .git/hooks while core.hooksPath is set. The commit was never graded; it's a config bug, not a grader bug.

Diagnosis (3 commands)

# 1. did the guard log after the commit? if newest log predates it, the hook didn't run
ls -lt .gitreins/logs | head; git log -1 --format='%cI'
# 2. the ONLY dir git reads
git config --get core.hooksPath
# 3. active vs. where the hook actually lives
echo "active: $(git rev-parse --git-path hooks)"; ls -la "$(git rev-parse --git-path hooks)"; ls -la .githooks
# fast confirmation (Git >= 2.36): respects core.hooksPath
git hook run pre-commit     # broken: "cannot find a hook named pre-commit", exit 1

Fix (either one)

  • Option A: git config --unset core.hooksPath (fix local clone; installer must also stop setting it).
  • Option B (recommended): keep .githooks and install -m 0755 hooks/pre-commit .githooks/pre-commit.
  • Regression-proof the installer: resolve the single active dir with hooks_dir="$(git rev-parse --git-path hooks)" and loop for hook in hooks/*; do install ...; done so a new pre-commit can't be missed again.

Also documented: gitreins guard exit 2 = DEGRADED PASS ("no staged files"), i.e. nothing was graded — not a test failure. Grade an old commit with git checkout <commit> -- <paths> then gitreins guard.
