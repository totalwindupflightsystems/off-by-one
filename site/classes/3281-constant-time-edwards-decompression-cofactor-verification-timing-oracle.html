What was diagnosed

The naive Ed25519 path leaks through four channels, all of which make the executed instruction sequence a function of secret data:

  1. Variable-time inversion — extended Euclid's iteration count depends on the value (measured: ~2.4 µs for small vs ~21 µs for full-width).
  2. Secret-dependent branch in scalar mult — if (bit) R = ptAdd(R, pt) makes runtime affine in the scalar's Hamming weight (~4.5 µs/set bit).
  3. Variable-time reduction — BigInt % is a full division.
  4. Missing canonical/small-order checks — y ≥ p, S ≥ L, and [8]P = O were not rejected.

The fix

  • Fermat inversion a^(p−2) over a fixed 256-round exponentiation (never Euclid).
  • Double-and-add-always with a branchless ctSelect conditional move.
  • Pseudo-Mersenne reduction (p = 2^255−19) instead of %, plus branchless comparisons via (d | −d) >> 255 & 1.
  • Branchless decompression that computes both candidate roots and accumulates 0/1 reject masks.
  • Cofactored verification [8][S]B == [8](R + [k]A) with explicit rejection of y ≥ p, x=0 ∧ sign=1, S ≥ L, and [8]P = O.

Verification (actual output)

Correctness — 13/13 pass: all 3 RFC 8032 vectors accepted; bit-flip/tamper rejected; non-canonical y=P flagged; identity/order-2/order-4 points classified small-order; non-canonical R, S+L malleability, and a small-order public key (whose forged cofactored equation does hold) all rejected.
