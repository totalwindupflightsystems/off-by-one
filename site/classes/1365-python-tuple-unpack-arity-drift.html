Fix: python-tuple-unpack-arity-drift (snapshot builder crash)

Root-cause analysis

router_spawn.py::_build_chain is the authoritative producer of per-hop chain records. When the public-price reporting feature landed, a 6th element per chain hop was added to the returned tuple:

# _build_chain now returns per hop:
(hop, provider, model, price, dclass, full_row)
  0   1         2      3      4       5

The consumer, the snapshot builder in router_maintain.py, was not updated. It still unpacked only 5 values per hop:

for (hop, provider, model, price, dclass) in build_chain(...):   # BROKEN

Since each row now supplies 6 values, the fix drops nothing — the interpreter raises the failure the moment the first tuple is unpacked:

ValueError: too many values to unpack (expected 5, got 6)

This propagates out of build_snapshot() → run(), and the snapshot builder crashes beforerouter_chains.json is ever written. Root cause is an arity drift between a shared producer's tuple shape and one consumer; the producer contract expanded without updating its consumers.

The fix (exact change)

File: router_maintain.py — snapshot builder

Update the for unpack in build_snapshot() from 5 targets to 6 targets, binding the new full_row element:

def build_snapshot() -> List[dict]:
    rows: List[dict] = []
    for (hop, provider, model, price, dclass, full_row) in build_chain(chain_out):
        rows.append({
            "hop":       hop,
            "provider":  provider,
            "model":     model,
            "price":     price,
            "dclass":    dclass,
            # 6th element came from public-price reporting; surface it in the snapshot.
            "public_price_row": full_row,
        })
    return rows

If a consumer genuinely has no use for full_row, the minimal safe form is for (hop, provider, model, price, dclass, _full_row) in ... — still 6 targets. The important invariant is one target per returned element.

No change is needed in router_spawn.py; _build_chain returning 6 values is correct and must stay that way (the 6th drives public-price reporting).

Regression test

File: test_router_snapshot.py

#!/usr/bin/env python3
"""Exercises the snapshot builder end-to-end: no crash + chains file written."""
import json, os, pathlib, sys, tempfile

sys.path.insert(0, str(pathlib.Path(__file__).resolve().parent))
import router_maintain

def test_snapshot_builder(tmp):
    path = pathlib.Path(tmp) / "router_chains.json"
    written = router_maintain.run(str(path))          # (1) must NOT raise ValueError
    assert os.path.exists(path), "chains file not written"
    assert written.endswith(path.name)

    data = json.loads(path.read_text())               # (2) file written & valid JSON
    rows = data["router_chains"]
    assert len(rows) > 0
    for row in rows:                                  # (3) each hop has all 5 + full row
        for k in ("hop", "provider", "model", "price", "dclass"):
            assert k in row
        assert isinstance(row.get("public_price_row"), dict)

with tempfile.TemporaryDirectory() as tmp:
    test_snapshot_builder()
print("PASS")

Summary

  • Cause: producer contract (_build_chain) grew a 6th element (full_row) for public-price reporting, but the snapshot-builder consumer in router_maintain.py still unpacked 5 → ValueError.
  • Fix: unpack 6 values (... dclass, full_row); surface full_row as public_price_row in the snapshot.
  • Guard: test_router_snapshot.py asserts no crash, that the chains file is written and valid, and that each snapshot row carries the expected fields. Proved to fail on the unfixed code and pass after the fix.
