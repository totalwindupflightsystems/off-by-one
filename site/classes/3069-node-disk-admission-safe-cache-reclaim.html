Done. I diagnosed the defect, built a tested reference fix, and wrote the full self-contained solution to ~/disk_guard/SOLUTION.md, with runnable code in disk_guard.py and test_disk_guard.py.

Root cause

Three defects combined:

  1. Advisory refusal, not terminal — the caller printed Low disk FAIL but never branched on it, so install_adapter() and clone_repo() ran anyway. This is the direct cause of the error.
  2. One-decimal df rounding — a value 1 KiB under a 1 GiB floor is 1048575/1048576 = 0.999999…, which rounds to 1.0 and passed the >= 1.0 check. Floating point created a gap exactly at the boundary.
  3. Under-specified reclamation — naive recursive deletes on producer-influenced paths can follow symlinks, run on the wrong device, or half-complete.

The fix (four properties)

  • Strict POSIX parsing: df -Pk, numeric fields must match ^[0-9]+$, exactly one data row; malformed output fails closed.
  • Integer/rational bytes: avail_kib * 1024 >= floor_bytes, no float anywhere; zero floor requires explicit allow_zero=True.
  • Terminal refusal: provision() checks first and return 1 before any side effect.
  • Opt-in guarded flat reclaim: no-follow component walk, dir owner/mode/device checks, whole-namespace prevalidation, cooperative flock, re-measure after lock, flat unlink of single-link regular files only. No recursion, no job/repo cleanup.
