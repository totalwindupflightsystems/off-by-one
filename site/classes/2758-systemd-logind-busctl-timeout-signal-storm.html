Root cause (short)

CI transient-unit churn (user@, user-runtime-dir@, bunker-docker-*) emits ~300 Hz systemd1 UnitRemoved/PropertiesChanged signals. systemd-logind's single-threaded dispatch loop drains that one socket (~3700 epoll iterations/12s) and stops answering D-Bus method calls — so busctl/loginctl time out while the unit still shows active. The monitoring probe's one-arg busctl introspect then compounded it by being a guaranteed false positive.

Fix

  1. Immediate: systemctl reset-failed + systemctl restart systemd-logind, then confirm with two-arg probes.
  2. Durable: correct probe (two-arg + timeouts + atomic textfile write), isolate/reduce runner churn, bound NFailedUnits with a reset-failed timer, and alert on bunker_logind_up == 0 / bunker_logind_failed_units > 200.
