Root cause (3 independent gaps)

  1. Backend: no limit/offset parsing and no LIMIT/OFFSET in the repo listItems → full table returned every request.
  2. Frontend: rendered items 1:1 with no dedup → thousands of DOM nodes.
  3. Formatting: confidence interpolated raw → 7500%.

Fix delivered (exact code)

  • parseLimit (default 25, hard cap 100), parseOffset (≥0)
  • Repository count() + listItems() sharing one buildWhere() so total is filter-aware, with LIMIT ? OFFSET ?
  • Service returns { items, meta: { count, total, limit, offset } }
  • React component: one page, aria-live status, accessible Prev/Next with boundary disabled
  • collapseDuplicates() on message + crisisType + userId with ×N occurrence badge
  • normalizeConfidence() clamped to integer 0–100

Verification (executed)

node check.mjs over a 600-row synthetic dataset printed ALL CHECKS PASSED, confirming: - default page = 25, limit=99999 → 100, offset=25 → first id r25 - filter-aware total (severity=CRITICAL → 200, all rows match) - duplicates collapse to 2 with occurrence count 3; rendered cards ≤ page limit - 7500 → 100, -4 → 0, 82.7 → 83, "abc" → 0
