Summary

Root cause: A .gitignore line with no slash — e.g. canopyd — is a bare pattern that matches a file or directory of that name at any depth. So the root build artifact ./canopyd and the source directory cmd/canopyd/ both match. Tracked files keep working (Git never ignores tracked files), so the breakage stays hidden until a new file is added under that directory. Explicit git add cmd/canopyd/<new>.go then exits 1; git add . silently omits it.

Fix: Anchor the artifact pattern to the tree root with a leading slash:

- canopyd
+ /canopyd
  bin/

bin/ is fine as-is (trailing slash intentionally matches a directory at any depth).

Verified probes (exit codes measured directly, no pipes): - Pre-fix: git check-ignore -v cmd/canopyd/newfile.go → match, rc=0; git add → rc=1. - Post-fix: check-ignore → no match, rc=1; git add → rc=0 (staged). - Unchanged behavior: canopyd still matches /canopyd; bin/canopyd still matches bin/ (using --no-index, since committed files are normally treated as never-ignored).
