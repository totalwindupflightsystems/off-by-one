Answer

The solution is written and verified. Here's a summary:

Diagnosis

On the muster board, events.jsonl contains 4 legacy non-JSON free-text rows from the tasks.md-migration era. append_board_event.py already guards against these by wrapping json.loads() in try/except json.JSONDecodeError and skipping malformed lines with a WARN.

append_board_task_completed.py lacks that guard. When it reads events.jsonl, the legacy rows either: 1. raise json.JSONDecodeError on json.loads(), or 2. (when the decode error is swallowed into {}) flow into {e["id"] for e in events} and raise KeyError: 'id' — the reported crash.

Fix

Add the same json.JSONDecodeError guard to the loader: skip malformed non-JSON lines and non-dict values with a WARN (mirroring append_board_event.py), and guard the id-uniqueness set with if "id" in e.

Verification (all ran successfully)

  • Reproduced the crash: the buggy baseline fails; I demonstrated both the JSONDecodeError path and the exact KeyError: 'id' symptom.
  • Fixed script succeeds on the muster-style board: the 4 legacy rows are skipped with WARN, all original rows are preserved untouched (events.jsonl is append-only), a task_completed audit event is appended, and the T-42 row is updated to status=completed, worker_status=done, commit_hash=abc123.
  • Edge cases pass: a valid-JSON-non-object row is skipped with non-object row (str), and a missing events.jsonl (fresh board) is handled gracefully.

The full self-contained solution is in /home/kara/FIX-append_board_task_completed.md.
