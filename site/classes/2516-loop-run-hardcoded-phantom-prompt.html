Fix: manual loop run stalls on a phantom execution.prompt

Reference: dexdat/hivemind c9cfb3c7 — internal/controller/loop_handler.go (manualLoopPrompt())

Symptom

POST /v1/loops/:id/run blocks and the run stays pending forever. The OpenCode session created by the manual path receives a generic prompt referencing an execution.prompt field. That field exists in no loop schema (neither .ralph.yaml, the API DTOs, nor the DB model). The agent has no concrete instruction to act on and never produces a terminal result, so the controller never moves the run out of pending.

Root-cause analysis

Two code paths start a loop run:

  1. Scheduler path — loads the workspace .ralph.yaml, finds the loop entry, uses its configured prompt.
  2. Manual path — POST /v1/loops/:id/run calls manualLoopPrompt(), which hardcodes a generic base prompt instead of resolving the loop config.

The hardcoded prompt points the model at execution.prompt, a phantom field. The model waits on non-existent input; the handler enforces no resolution/timeout; the run never completes. The bug is not OpenCode — the manual and scheduler entry points disagree about where a loop's prompt comes from.

Fix direction: make the manual path resolve run.prompt from the loop entry in <data-dir>/workspaces/<ws>/.ralph.yaml exactly like the scheduler, and use an honest generic fallback (never naming a non-existent field) for prompt-less loops.

Exact fix

1. Factor out prompt resolution; use it from manualLoopPrompt()

In internal/controller/loop_handler.go, replace the hardcoded body and share one helper with the scheduler so the paths can't drift again:

// loadLoopPrompt returns the prompt configured for loopName in the workspace's
// .ralph.yaml. ok is false when the loop has no prompt configured. It is the
// single source of truth for both the scheduler and manual run paths.
func (h *LoopHandler) loadLoopPrompt(ws, loopName string) (prompt string, ok bool, err error) {
    cfg, err := loadRalphConfig(h.dataDir, ws) // existing scheduler loader
    if err != nil {
        return "", false, fmt.Errorf("load .ralph.yaml for workspace %q: %w", ws, err)
    }
    for _, entry := range cfg.Loops {
        if entry.Name != loopName && entry.ID != loopName {
            continue
        }
        if p := strings.TrimSpace(entry.Prompt); p != "" {
            return p, true, nil
        }
        return "", false, nil
    }
    return "", false, nil
}

// manualLoopPrompt resolves the same prompt the scheduler would use for this
// loop. Manual runs must never invent fields that do not exist in the schema.
func (h *LoopHandler) manualLoopPrompt(ws, loopName string) (string, error) {
    prompt, ok, err := h.loadLoopPrompt(ws, loopName)
    if err != nil {
        return "", err
    }
    if ok {
        return prompt, nil
    }

    // Honest generic fallback for prompt-less loops. Do NOT mention
    // execution.prompt, or any other field, because no such field exists.
    return fmt.Sprintf(
        "Run loop %q manually. No prompt is configured for this loop; "+
            "perform the loop's standard task and report the result.",
        loopName,
    ), nil
}

2. Make the manual handler use the resolved prompt (and fail fast)

func (h *LoopHandler) handleRunLoop(w http.ResponseWriter, r *http.Request) {
    loop, err := h.store.GetLoop(r.PathValue("id"))
    if err != nil {
        http.Error(w, "loop not found", http.StatusNotFound)
        return
    }

    prompt, err := h.manualLoopPrompt(loop.Workspace, loop.Name)
    if err != nil {
        // Surface config problems instead of starting a run that can only hang.
        http.Error(w, err.Error(), http.StatusUnprocessableEntity)
        return
    }

    session, err := h.opencode.CreateSession(r.Context(), prompt)
    if err != nil {
        http.Error(w, err.Error(), http.StatusBadGateway)
        return
    }
    // ... persist run as running and return 202 ...
}

3. Route the scheduler through the helper

Where the scheduler currently inlines "find loop in .ralph.yaml, read prompt", call loadLoopPrompt(...) so both paths share one implementation.

4. Schema note

No schema change is required. The fix removes the only reference to execution.prompt; it is not added anywhere because it was never real.

func TestManualLoopRunUsesConfiguredPrompt(t *testing.T) {
    dir := t.TempDir()
    ws := "ws-1"
    writeRalphConfig(t, dir, ws, `
loops:
  - name: nightly
    prompt: "Summarize yesterday's commits and open a PR."
`)
    fake := &fakeOpenCode{}
    h := newTestLoopHandler(t, dir, fake)

    h.handleRunLoop(recorder(), newPostRequest("/v1/loops/nightly/run"))

    if got := fake.LastPrompt(); !strings.Contains(got, "Summarize yesterday's commits") {
        t.Fatalf("session got %q, want configured .ralph.yaml prompt", got)
    }
    if strings.Contains(fake.LastPrompt(), "execution.prompt") {
        t.Fatalf("phantom field leaked into prompt: %q", fake.LastPrompt())
    }
}

func TestManualLoopRunPromptlessFallbackIsHonest(t *testing.T) {

}

Acceptance criteria

  • Manual run with a configured prompt sends that exact prompt to the OpenCode session.
  • Prompt-less loops get a generic fallback naming the loop and no phantom field.
  • No source or emitted prompt contains execution.prompt.
  • Missing/invalid loop config returns 422 immediately rather than starting a run that can only hang.
  • A manually triggered run reaches a terminal state within the poll window.
