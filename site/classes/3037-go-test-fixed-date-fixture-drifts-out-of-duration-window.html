Answer

Fix: derive the pulse alert fixture from time.Now() instead of a calendar constant

Summary

cmd/pulse/alerts_test.go writes a daily fixture named pulse-2026-09-25.jsonl and places all samples on 2026-09-25T11:40:00Z … 2026-09-25T11:58:00Z.

The CLI child process evaluates alerts with:

query.Scan(dir, time.Now().Add(-window), time.Now())

with --window 720h (30 days). Once the wall clock passes 2026-10-25T11:40:00Z, time.Now().Add(-720h) is later than the newest fixture timestamp. The scan therefore excludes the fixture's UTC day file, and the assertion fails with:

run 1 must show a firing: alerts: escalate+persist over the last 720h0m0s ... ok disk_used > 90 for 10m - no disk data in window

The product code is not regressing; the fixture has silently expired.

Root cause

The test controls the child's data directory and --window, but it does not control the child's wall clock. The child computes its query bounds from its own time.Now(). Therefore every timestamp in the fixture must also be derived from time.Now().

The hard-coded date makes the fixture valid only for a limited calendar interval. A 30-day window sounds generous, but a fixed fixture date eventually falls before now - 30d. Because the day-file selector intersects the window with UTC date names, the expired file is not merely filtered at the sample level—the whole file is skipped. That produces the misleading “no disk data in window” result.

Two additional details matter:

  • Use UTC for both the fixture date and the Z timestamps.
  • Keep all intraday samples on the same UTC day, so a test run near local/UTC midnight still sees one day file covered by the window.

Exact fix

Modify only cmd/pulse/alerts_test.go. Replace the fixed fixture date with a date derived from time.Now().UTC().AddDate(0, 0, -7) and use that same value for both:

  1. the file name: pulse-<date>.jsonl
  2. every timestamp: <date>T11:40:00Z, <date>T11:41:00Z, …, <date>T11:58:00Z

Before

const fixtureDate = "2026-09-25"

fixturePath := filepath.Join(dir, "pulse-"+fixtureDate+".jsonl")

lines := []string{
    // ...
    `{"ts":"2026-09-25T11:40:00Z", ... }`,
    `{"ts":"2026-09-25T11:41:00Z", ... }`,
    // ...
    `{"ts":"2026-09-25T11:58:00Z", ... }`,
}

After

// The child process gets the real wall clock. Derive the fixture from the
// same clock, never from a calendar constant. Seven days ago leaves ~23 days
// of margin inside the test's 720h window.
fixtureDate := time.Now().UTC().AddDate(0, 0, -7).Format("2006-01-02")

fixturePath := filepath.Join(dir, "pulse-"+fixtureDate+".jsonl")

lines := []string{
    // ...
    fmt.Sprintf(`{"ts":"%sT11:40:00Z", ... }`, fixtureDate),
    fmt.Sprintf(`{"ts":"%sT11:41:00Z", ... }`, fixtureDate),
    // ...
    fmt.Sprintf(`{"ts":"%sT11:58:00Z", ... }`, fixtureDate),
}

If the fixture is written by a helper, compute the date once and pass it through rather than recomputing it:

fixtureDate := time.Now().UTC().AddDate(0, 0, -7).Format("2006-01-02")
writeDiskFixture(t, dir, fixtureDate)

Inside the helper:

func writeDiskFixture(t *testing.T, dir, day string) {
    t.Helper()

    path := filepath.Join(dir, "pulse-"+day+".jsonl")
    body := strings.Join([]string{
        fmt.Sprintf(`{"ts":"%sT11:40:00Z", ... }`, day),
        fmt.Sprintf(`{"ts":"%sT11:41:00Z", ... }`, day),
        // ...
        fmt.Sprintf(`{"ts":"%sT11:58:00Z", ... }`, day),
    }, "\n") + "\n"

    if err := os.WriteFile(path, []byte(body), 0o644); err != nil {
        t.Fatalf("write fixture %s: %v", path, err)
    }
}

Do not fix this by widening --window, mocking production time, or changing the product's scan behavior. The fixture is what is wrong.

Optional regression guard inside the test, to catch future fixture drift explicitly:

now := time.Now().UTC()
fixtureTime, err := time.Parse(time.RFC3339, fixtureDate+"T11:40:00Z")
if err != nil {
    t.Fatalf("parse fixture timestamp: %v", err)
}
age := now.Sub(fixtureTime)
if age < 0 || age >= 30*24*time.Hour {
    t.Fatalf("fixture is outside the 720h query window: age=%v", age)
}

General rule

Whenever production code computes a time bound from time.Now(), any test fixture that is read by that code must also be positioned relative to time.Now(). Calendar constants are not safe, even when the test passes a large-looking --window. Choose an offset comfortably inside the shortest window under test, and keep the fixture's timestamps on a single UTC day.
