Environment finding

This box has no repo / no tier1 harness — the gitreins symlink is broken (~/.local/share/pipx/venvs/gitreins/ is missing), and none of gen-disposition-register.py, ops-readiness-rehearsal.mjs, tasks.yaml, or a .git tree exist. The one real artifact is boardctl (version dev), whose event/validate surface matches the spec, so I grounded the runbook on it. The deliverable is therefore a procedural runbook with expected outputs rather than an executed test transcript — I could not "verify" against a live tree that isn't present.

What the document covers

Root cause: the 500-char leg cap hides the tail of the tier1 output; the only real failure is a register-sync assertion. A prior tick appended task_completed/audit to tasks.jsonl after the last gen-disposition-register.py --write, so the committed register lags the board. That drift is inherited/pre-existing (t636 class), not worker-caused. The t637 extension: regen-before-judge is an executor OPENER check (covers prior-tick closes), not just same-tick recovery.

Exact fix (order of operations): 1. Reproduce uncapped: python3 -m pytest -q 2>&1 | tee /tmp/tier1-full.log 2. Confirm drift via --validate + register/board commit timestamps 3. boardctl event (task_completed + audit) first, then boardctl validate 4. gen-disposition-register.py --write then --validate 5. TMPDIR=/tmp node scripts/ops-readiness-rehearsal.mjs 6. One atomic commit of board + register + ops-readiness; push 7. One gitreins judge retry; record the FAIL/PASS run-id + verdict-commit pair 8. If killed pre-verdict: git checkout -- the ops-readiness files (only tasks.yaml completed_at re-stamps are safe) 9. Force-add .gitreins/ history + tasks.yaml + usage.jsonl chore commit 10. Push beta and gitreins; assert git rev-list --count <remote>/<branch>..HEAD == 0 on both

Verification section enumerates the seven must-hold checks (uncapped single failure, register/board validate exit 0, atomic commit, distinct verdict pair, clean tree, zero divergence) plus explicit anti-patterns (no retry before settling, no separate register commit, no hand-editing the board, no retry loops).
