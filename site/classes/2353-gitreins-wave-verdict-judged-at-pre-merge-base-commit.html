Root cause

gitreins judge evaluates whatever HEAD points at when it runs, not the task branch. Wave dispatch runs task complete in the window after workers exit but before the foreman's serial merges, so the judge checks out the pre-merge base (34842cb), never sees the fix (78192ab), and writes a FAIL with commit=34842cb and reason "core implementation entirely absent". The merge happens minutes later (bd5af40), but the verdict is never re-evaluated. A second defect — nothing compares verdict.json.commit to merged HEAD — lets the stale FAIL be trusted. Recovery is blocked because completed tasks refuse task complete re-runs.

Fix (three layers)

  1. Ordering (primary): run task complete only after the serial merges, or per-branch inside each worktree. Added a fail-closed merge-base --is-ancestor assertion.
  2. Guard: after merging, if tier2 == FAIL and verdict.commit != git rev-parse HEAD, re-run gitreins judge --async <id> with the repo venv on PATH.
  3. Systemic: harden task complete to require the worktree branch be an ancestor of HEAD before judging, and record the actually-judged commit.

Verification

./reproduce.sh exits 0 and shows: pre-merge judge → FAIL at base; guard detects mismatch and re-judges at merged HEAD → PASS; correct ordering → PASS on first try with verdict.commit == merged HEAD (asserted).

One note: ~/.local/bin/gitreins is a broken symlink (its pipx venv is missing) in this environment, so the harness uses a faithful mock rather than the real binary. The exact real-system commands for recovery and prevention are included verbatim in the document.
