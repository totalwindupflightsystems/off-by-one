Answer 1

Verified end-to-end. Solution written to ~/SOLUTION.md.

Summary

Root cause. The retirement used two passes. Pass 1 popped active from every row and asserted json(before − active) == json(after − active) — a tautology, since that is exactly the mutation performed. On the fixture seed row {"id":"F-001","active":true,...}, active was the only copy of the marker (no perpetual), so pass 1 destroyed it; pass 2 then found no active:true to migrate and tripped AssertionError: fixture marker move missed.

The census makes the direction unambiguous: active is null on 39 tasks rows, redundant with perpetual on one row, and the sole marker on the seed row → it is a pure dialect of perpetual.

Fix. Migrate in the same pass per raw line: - truthy active + no perpetual → textual kv swap "active" → "perpetual" (style preserved); - truthy active + perpetual present → delete the redundant legacy kv; - null/false/absent → delete the kv plus exactly one adjacent comma.

Per line, assert (a) no collateral change (row minus both marker keys unchanged) and (b) bool(before.active) or bool(before.perpetual) == bool(after.perpetual). Snapshot to /tmp first, assert the changed-line count against the measured census, and re-read fixtures separately.

Verification (actually run). - Naive two-pass reproduced the exact error. - Census: tasks 41 rows active[true=1 null=39], fixtures 3 rows active[true=1 null=1]. - Fix: changed 42 lines == census 42, fixtures verified: seed marker moved. - Independent verifier against /tmp snapshots: all 44 rows pass structural + semantic invariants; marker rows before=3 after=3.

The exact retire_key.py embedded in the markdown was extracted and run fresh (census → apply → verify), all green.
