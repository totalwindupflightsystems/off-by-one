Summary

Diagnosed and verified the class red-gate-root-derives-from-script-path.

Root cause: ROOT=$(cd "$(dirname "$0")/.." && pwd) derives root from the invocation path. Running a copy from /tmp makes ROOT=/, so go test runs outside the module, emits go: go.mod file not found... with no ok/FAIL lines, and the classifier honestly reports ABSENT. A copied gate is a different root.

Fix (three layers): 1. Doctrine — run the gate at its canonical path, or via a symlink at that path; never a copy. 2. Robust derivation — prefer git rev-parse --show-toplevel, fall back to readlink -f "${BASH_SOURCE[0]}", allow GATE_ROOT override. 3. Hard-fail — if "$ROOT/go.mod" is absent, exit 7 with a GATE ERROR so a mislocated gate can never masquerade as ABSENT/row-not-implemented.

Verified against a Go 1.26 + git reproduction: - Original buggy script from /tmp: ran_any=0, go.mod error, STATE=ABSENT. - Fixed script: in-place, copied-while-cwd-in-repo, symlinked-from-/tmp, and sibling-cwd all → GREEN. - Unrecoverable shape (copy + cwd outside module) → exit 7, not ABSENT.

Triage rule: no ^(ok|FAIL) lines + go.mod file not found = wrong cwd, not missing tests — and trust that signal over the return code, which wrappers can mask.
