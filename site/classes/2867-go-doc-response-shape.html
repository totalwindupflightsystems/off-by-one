DOC-10 — Fix truncated /health and /version response shapes in docs/API.md and docs/INTEGRATION.md

Summary

The HTTP API reference docs documented stale, incomplete bodies for two endpoints:

Endpoint What the docs showed What the server actually returns
GET /health a reduced object full object including schema_version, embedded_migrations, relay, version, commit, build_time
GET /version {"version":"dev"} the full build identity serialized from buildinfo

The handlers are the source of truth (internal/server/server.go:723 and buildinfo.go:37-41). The fix is documentation-only: replace the two examples in both docs/API.md and docs/INTEGRATION.md with the complete, live-verified shapes, and add a check that fails CI when the docs drift from the running binary.

Root cause analysis

  1. Hand-written examples, copied once and never re-verified. The /health and /version blocks were written against an early handler. The Go response structs later gained fields (schema_version, embedded_migrations, relay, and the build-identity fields), but because the examples are static Markdown they silently rotted. Go struct fields are the only contract; no test or generator tied the prose to the handler.

  2. /version documented the default variable, not the serialized struct. buildinfo exposes build identity through a struct (around buildinfo.go:37-41) whose JSON tags are version, commit, build_time. The docs showed the compile-time placeholder value dev (the default when no -ldflags -X injection is present) rather than the JSON emitted by the handler, so the real output (e.g. a released version plus commit and timestamp) never appeared.

  3. Build metadata is injected at link time. Values for version/commit/build_time change per build (-X .../buildinfo.version=... etc.), so even a correct hand-written example goes stale. Any durable fix must either (a) mark values as build-dependent and show the shape, and (b) verify field presence against a live server.

  4. Doc-only blast radius. No handler, migration, or schema logic is wrong here — the code is correct; only the published response shapes are. Hence "Foreman-direct (doc-only)."

Notes to keep in the prose next to the blocks:

  • schema_version is the applied database schema revision; embedded_migrations is the count of migrations compiled into the binary.
  • relay reflects relay subsystem state (preserve the exact type serialized by the handler — object vs. string — when you capture it live).
  • version, commit, and build_time are injected at build time via -ldflags -X; they are not constants and will differ per build.

Step 3 — Make the examples verifiable

Commit the live capture as the canonical block, then add a guard so the docs can never drift again. Create scripts/verify_response_docs.sh:

#!/usr/bin/env bash
# Fail if docs/API.md or docs/INTEGRATION.md drift from the live API response shape.
set -euo pipefail

BASE_URL="${BASE_URL:-http://<ip-address>:8080}"
DOCS=(docs/API.md docs/INTEGRATION.md)

tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT

curl -fsS "$BASE_URL/health"  | jq -S . > "$tmp/health.json"
curl -fsS "$BASE_URL/version" | jq -S . > "$tmp/version.json"

fail=0
for doc in "${DOCS[@]}"; do
  for ep in health version; do
    want="$tmp/$ep.json"
    got="$tmp/$(echo "$doc" | tr '/' '_').$ep.json"

    # Extract the first ```json fence following the `/<ep>` mention.
    awk -v ep="/$ep" '
      index($0, ep) { found = 1 }
      found && /^```json/ { inb = 1; next }
      inb && /^```/       { exit }
      inb                 { print }
    ' "$doc" | jq -S . > "$got" 2>/dev/null || true

    if ! diff -u "$want" "$got" >/dev/null; then
      echo "MISMATCH: $doc /$ep" >&2
      diff -u "$want" "$got" >&2 || true
      fail=1
    fi
  done
done

exit "$fail"

Add it to CI after the server is started:

- name: Verify documented response shapes
  run: |
    go build -ldflags "-X main.version=$GIT_TAG \
                       -X main.commit=$GIT_SHA \
                       -X main.buildTime=$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
             -o /tmp/app ./cmd/...
    /tmp/app & APP_PID=$!
    sleep 1
    BASE_URL="http://<ip-address>:${PORT:-8080}" ./scripts/verify_response_docs.sh
    kill "$APP_PID"

Acceptance criteria

  • [ ] docs/API.md /health block contains schema_version, embedded_migrations, relay, version, commit, build_time.
  • [ ] docs/API.md /version block contains full build identity (version, commit, build_time), not {"version":"dev"}.
  • [ ] docs/INTEGRATION.md contains the same two complete shapes.
  • [ ] scripts/verify_response_docs.sh exits 0 against a running build, proving the docs are live-verified.
  • [ ] No non-documentation files changed (doc-only scope).

Prevention

  • Treat internal/server/server.go and buildinfo.go as the single source of truth; never hand-copy response variants out of prose.
  • The verify_response_docs.sh CI step above turns "docs drift" into a build failure.
  • When adding a field to a response struct, update the corresponding doc block in the same PR (the guard will fail otherwise).
