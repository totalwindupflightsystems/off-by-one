All three P2s live on the same metadata path, so they were batched into one worker pass (per the E2E-001 pattern). The fixes are in /home/kara/dashboard (example.com/dashboard): the engine now persists metadata sidecars and gates webhook_url on the Webhook flag, and the CLI wires the full API surface (--source, --description, --webhook).

P2-1 + P2-2: flow create gains --source; --description is persisted. A JSON sidecar <name>.meta.json in dataDir (isolated from the .star sources in flowsDir) stores description + webhook flag, written atomically and reloaded on every read:

// engine.go
type Flow struct {
    Name        string `json:"name"`
    Source      string `json:"source,omitempty"`
    Description string `json:"description,omitempty"`
    Webhook     bool   `json:"webhook"`
    WebhookURL  string `json:"webhook_url,omitempty"` // only when Webhook==true
}
type meta struct { Description string `json:"description,omitempty"`; Webhook bool `json:"webhook"` }

func (e *Engine) Create(_ context.Context, f Flow) (Flow, error) {
    if err := validateName(f.Name); err != nil { return Flow{}, err }
    if strings.TrimSpace(f.Source) == "" { return Flow{}, errors.New("flow source is required") }
    os.WriteFile(e.sourcePath(f.Name), []byte(f.Source), 0o644)       // flowsDir
    e.writeMeta(f.Name, meta{Description: f.Description, Webhook: f.Webhook}) // dataDir sidecar
    return e.Get(f.Name)
}

// readMeta: missing sidecar => zero meta (back-compat), not an error

P2-3: Engine.List() stops synthesizing webhook_url. The URL is derived in Get, only when the persisted Webhook flag is true — previously it was fabricated for every .star file (engine.go:85):

func (e *Engine) Get(name string) (Flow, error) {
    src, err := os.ReadFile(e.sourcePath(name)) // …load sidecar…
    f := Flow{Name: name, Source: string(src), Description: m.Description, Webhook: m.Webhook}
    if f.Webhook { f.WebhookURL = "/hooks/" + name }
    return f, nil
}

CLI (testable cli.Run, thin cmd/flow/main): create now takes --source (required, reads the file into Flow.Source), --description (persisted via sidecar), --webhook; added update --name --description --webhook/--no-webhook to rewrite metadata without touching source; list prints a summary where webhook_url appears only for webhook flows.
