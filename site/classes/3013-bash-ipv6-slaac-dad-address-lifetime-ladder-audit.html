IPv6 SLAAC / RFC 4862 Address-Lifetime Ladder Audit

Root-cause analysis

The audit is unreliable when each snapshot is inspected in isolation:

  1. ip -6 addr show stores flags such as tentative, dadfailed, and temporary on the inet6 line, but lifetimes on the following line. Naive grep/awk parsing can attach them to the wrong address.
  2. Lifetimes are relative to the capture moment. They must be treated as remaining seconds at snapshot time; absolute timestamps need conversion using the captured time.
  3. The required checks are cross-file joins:
  4. route src values vs. tentative/DAD-failed addresses,
  5. default next hops vs. INCOMPLETE neighbour entries,
  6. temporary address lifetimes vs. RA prefix lifetimes,
  7. EUI-64 IIDs across interfaces.
  8. IPv6 text representations are not directly comparable. Addresses must be canonicalized before matching.
  9. Output must be deterministic; findings must be sorted and the exit status must reflect violations.

Exact fix

The complete implementation is in /workspace/solution.sh and is embedded in /workspace/solution.md. Key invocation forms:

chmod +x /workspace/solution.sh

# Snapshot directory
/workspace/solution.sh --dir ./snapshot

# Explicit files in ADDR NEIGH ROUTE RA order
/workspace/solution.sh addr.txt neigh.txt route.txt ra.txt

# Named files plus snapshot time
/workspace/solution.sh -a addr.txt -n neigh.txt -r route.txt -R ra.txt \
  --now 1710000000

# Only violation lines
/workspace/solution.sh --dir ./snapshot --violations-only

Output format:

<interface> <address> <reason>

By default the script emits every address’s ladder state (ladder=preferred, ladder=tentative, ladder=dadfailed, ladder=deprecated, ladder=invalid) plus violations. It exits 1 when any violation is present.

Handled violation reasons include:

valid-lifetime-less-than-preferred-lifetime
temporary-valid-lifetime-exceeds-public-prefix
temporary-preferred-lifetime-exceeds-public-prefix
tentative-address-used-as-route-source
dadfailed-address-used-as-route-source
duplicate-eui64-iid:<other-interface>
default-router-neighbour-incomplete
