Answer

Windowed toolsd read: stream the line window instead of materialising the file

TL;DR

toolsd read --offset/--limit used fsops.Root.Read (os.ReadFile) plus strings.Split(string(data), "\n") before slicing the requested window. On a 60.9 MB / 1,000,000-line file that meant a 60.9 MB read, a 60.9 MB string copy, and 1,000,001 string headers — even for a 10-line window. Measured cost: 137.8 MB/op and 78–105 ms.

The fix keeps confinement via fsops.Root.Path, opens the file with os.Open, uses a 64 KiB bufio.Reader, skips offset-1 lines with ReadSlice discarding fragments, reassembles kept lines across fragments, and appends one trailing newline iff the source's last byte is \n (O(1) via Stat + ReadAt). The no-window path remains raw.

Measured here: 137,824,528 B/op → 67,769 B/op, 26.85 ms → 8.31 ms in-process, and 77–90 ms → 6 ms end-to-end at offset 250,000. The reported target was 105.3 ms → 5.9 ms (17.98×) and 137.8 MB/op → 68.7 KB/op; the fixed 6 ms and B/op numbers match that target closely.

The non-obvious regression guard: byte parity alone cannot catch a regression back to whole-file reading. The regression test must assert the source file offset advanced only to the window end, not EOF. The test below does this and was verified to fail against a whole-file implementation while all byte-parity tests passed.

Root cause

Old path

For a windowed read the old code effectively did:

data, err := root.Read(path)              // os.ReadFile: whole file
lines := strings.Split(string(data), "\n") // 60.9 MB copy + 1M headers
window := lines[offset-1 : offset-1+limit]
out := strings.Join(window, "\n")
// append trailing newline iff source ends with one

Everything before the window slice is proportional to the file, not the window.

Allocation math for the 60.9 MB file

Allocation Bytes
os.ReadFile buffer (size+1) 60,900,001
string(data) copy 60,900,000
strings.Split headers (1,000,001 × 16) 16,000,016
window join/output ~610
Total ~137.8 MB

This matches the reported 137.8 MB/op and the measured benchmark 137,824,528 B/op. RSS was 127–143 MB because the read buffer and string copy coexist.

Evidence the whole file was read

strace on the buggy binary with --offset 250000 --limit 10 on the 60.9 MB file:

read(3, "00000000000000000000000000000000"..., 60900001) = 60900000

The read size is file size + 1; Go's os.ReadFile does one whole-file read. The window never gets a chance to limit it.

Why the old design materialised the file

The old implementation needed the whole file only to reproduce the split/join semantics:

  • strings.Split on "\n" yields a trailing empty element when the source ends with a newline.
  • Slicing the requested lines and joining with "\n" loses the final newline unless the source's last byte is checked.
  • The old code therefore read everything, split everything, and sliced afterward.

A streaming reader can reproduce the same bytes without reading the suffix:

  • Skip offset-1 lines with ReadSlice, discarding fragments.
  • Read only the limit requested lines, reassembling long lines across buffer refills.
  • Join kept lines with "\n".
  • Append one trailing newline iff the source's last byte is "\n"; obtain that in O(1) with Stat + ReadAt(size-1).

Trailing-newline semantics that must be preserved

Source Window Output
a\nb\nc\n offset 1, limit 2 a\nb\n
a\nb\nc offset 1, limit 2 a\nb
a\nb\nc\n offset 2, limit 2 b\nc\n
a\nb\nc\n offset 4, limit 2 empty
a\nb\n\n offset 2, limit 2 b\n\n
x\n offset 1, limit 1 x\n
empty offset 1, limit 1 empty

The critical rule: the trailing newline is present iff the source file's last byte is \n, not iff the window's last kept line happens to end at the source's last line.

The regression byte parity cannot catch

A whole-file implementation and a streaming implementation produce identical stdout. A test that only compares bytes will pass even if the code regresses to os.ReadFile. The regression test must observe the source file offset after the read. With a 64 KiB reader, the offset should be around the window end plus at most one buffer of read-ahead — nowhere near EOF for a middle window.

Exact fix

1. Keep the no-window path raw

When neither --offset nor --limit is given, keep the existing whole-file path. The no-window contract is raw bytes, so binary files round-trip. Do not route it through the line-window code.

2. Stream the windowed path

const readBufferSize = 64 * 1024

// readFile is the subset of *os.File the streaming reader needs. The interface
// is also the seam the regression test uses to observe the final file offset.
type readFile interface {
    io.Reader
    io.ReaderAt
    Stat() (os.FileInfo, error)
    Close() error
}

// openReadFile is a test seam. Production is os.Open.
var openReadFile = func(path string) (readFile, error) { return os.Open(path) }

// sourceEndsWithNewline is O(1) and does not disturb the sequential offset.
func sourceEndsWithNewline(f readFile) (bool, error) {
    info, err := f.Stat()
    if err != nil {
        return false, err
    }
    if info.Size() == 0 {
        return false, nil
    }
    var last [1]byte
    if _, err := f.ReadAt(last[:], info.Size()-1); err != nil {
        return false, err
    }
    return last[0] == '\n', nil
}

// discardLine skips one line, discarding fragments of long lines.
func discardLine(r *bufio.Reader) error {
    for {
        _, err := r.ReadSlice('\n')
        switch err {
        case nil:
            return nil
        case bufio.ErrBufferFull:
            continue
        default:
            return err
        }
    }
}

// readWindow returns exactly the bytes the old split/join implementation would
// have produced for the requested window. It reads only the prefix up to the
// window end and the requested lines.
func readWindow(r *bufio.Reader, offset, limit int, srcEndsNewline bool) ([]byte, error) {
    // Skip offset-1 lines. offset is 1-based.
    for i := 1; i < offset; i++ {
        if err := discardLine(r); err != nil {
            if err == io.EOF {
                return nil, nil // offset past EOF: empty window, exit 0
            }
            return nil, err
        }
    }

    var out []byte
    kept := 0
    for kept < limit {
        frag, err := r.ReadSlice('\n')
        if len(frag) == 0 && err == io.EOF {
            break // no more lines
        }

        // A line exists. Join with a newline between kept lines.
        if kept > 0 {
            out = append(out, '\n')
        }

        for {
            switch err {
            case nil:
                // frag ends with '\n'; drop only the terminator.
                out = append(out, frag[:len(frag)-1]...)
            case bufio.ErrBufferFull:
                // Long line: keep the fragment and continue.
                out = append(out, frag...)
                frag, err = r.ReadSlice('\n')
                continue
            case io.EOF:
                // Final line without a trailing newline.
                out = append(out, frag...)
            default:
                return nil, err
            }
            break
        }

        kept++
        if err == io.EOF {
            break
        }
    }

    // The source's last byte decides the trailing newline, even for a middle
    // window whose last kept line is not the source's last line.
    if kept > 0 && srcEndsNewline {
        out = append(out, '\n')
    }
    return out, nil
}

The runRead branch after the existing positive-value validation:

if !offsetSet && !limitSet {
    // No window: raw whole-file path, binary-safe.
    data, err := root.Read(path)
    if err != nil {
        return err
    }
    _, err = os.Stdout.Write(data)
    return err

// Windowed path: resolve through Root.Path so confinement and symlink checks
// are preserved, then stream.
abs, err := root.Path(path)
if err != nil {
    return err // Root.Path already formats fsops errors
}
f, err := openReadFile(abs)
if err != nil {
    return fmt.Errorf("fsops: read %s: %w", path, err)
}
defer f.Close()

srcEndsNewline, err := sourceEndsWithNewline(f)
if err != nil {
    return fmt.Errorf("fsops: read %s: %w", path, err)
}

window, err := readWindow(bufio.NewReaderSize(f, readBufferSize), offset, limit, srcEndsNewline)
if err != nil {
    return fmt.Errorf("fsops: read %s: %w", path, err)
}
_, err = os.Stdout.Write(window)
return err

3. Regression test

The key test exercises the real runRead path through the openReadFile seam, wraps the opened file to record its offset at Close, and asserts the offset never reached EOF. It also checks byte parity against the old whole-file oracle.

type trackingFile struct {
    *os.File
    offset int64
}

func (t *trackingFile) Close() error {
    // Record before the descriptor goes away.
    t.offset, _ = t.File.Seek(0, io.SeekCurrent)
    return t.File.Close()
}

func TestWindowedReadDoesNotReadToEOF(t *testing.T) {
    dir := t.TempDir()
    const lineLen = 61
    const lineCount = 140_000 // 8,540,000 bytes
    path := filepath.Join(dir, "big.txt")
    if err := makeFixedLineFile(path, lineCount, lineLen); err != nil {
        t.Fatal(err)
    }
    info, err := os.Stat(path)
    if err != nil {
        t.Fatal(err)
    }
    const offset, limit = 50_000, 10
    windowEnd := int64((offset - 1 + limit) * lineLen)
    if windowEnd+readBufferSize >= info.Size() {
        t.Fatalf("test setup: windowEnd %d + buffer %d >= file size %d",
            windowEnd, readBufferSize, info.Size())
    }

    var tf *trackingFile
    oldOpen := openReadFile
    openReadFile = func(path string) (readFile, error) {
        f, err := os.Open(path)
        if err != nil {
            return nil, err
        }
        tf = &trackingFile{File: f}
        return tf, nil
    }
    defer func() { openReadFile = oldOpen }()

    var out bytes.Buffer
    if err := runRead([]string{
        "--root", dir,
        "--offset", strconv.Itoa(offset),
        "--limit", strconv.Itoa(limit),
        "big.txt",
    }, &out); err != nil {
        t.Fatal(err)
    }
    if tf == nil {
        t.Fatal("runRead did not open the file through the seam; streaming path bypassed")
    }

    // Byte parity against the old whole-file implementation.
    data, err := os.ReadFile(path)
    if err != nil {
        t.Fatal(err)
    }
    want := wholeFileWindow(data, offset, limit)
    if !bytes.Equal(out.Bytes(), want) {
        t.Fatalf("byte parity failed: got %d bytes, want %d", out.Len(), len(want))
    }

    // THE NON-OBVIOUS ASSERTION: the source offset must not reach EOF.
    if tf.offset >= info.Size() {
        t.Fatalf("source offset reached EOF: offset=%d fileSize=%d",
            tf.offset, info.Size())
    }
    if tf.offset > windowEnd+readBufferSize {
        t.Fatalf("source offset %d is more than one buffer past window end %d",
            tf.offset, windowEnd)
    }
    if tf.offset <= 0 {
        t.Fatalf("source offset %d is not positive", tf.offset)
    }
    t.Logf("fileSize=%d windowEnd=%d finalOffset=%d (%.2f%% of file)",
        info.Size(), windowEnd, tf.offset,
        100*float64(tf.offset)/float64(info.Size()))
}

The old whole-file oracle used for parity:

func wholeFileWindow(data []byte, offset, limit int) []byte {
    lines := strings.Split(string(data), "\n")
    srcEndsNewline := len(data) > 0 && data[len(data)-1] == '\n'
    if srcEndsNewline {
        lines = lines[:len(lines)-1] // drop trailing empty element
    }
    start := offset - 1
    if start < 0 {
        start = 0
    }
    if start >= len(lines) {
        return nil
    }
    end := start + limit
    if limit > len(lines)-start {
        end = len(lines)
    }
    if end < start {
        end = start
    }
    out := strings.Join(lines[start:end], "\n")
    if srcEndsNewline && end > start {
        out += "\n"
    }
    return []byte(out)
}

Wiring notes

  • Keep the existing positive-value validation for --offset and --limit. The counters in readWindow avoid offset+limit overflow.
  • Return Root.Path errors unchanged. Wrap open/read errors with fmt.Errorf("fsops: read %s: %w", path, err) to preserve the old error text.
  • Buffer the window before writing. This preserves the “refusal prints nothing on stdout” contract and keeps memory at ~64 KiB plus the window size. For a 10-line window that is ~68 KB/op.
  • The no-window path remains unchanged and raw.
  • sourceEndsWithNewline assumes a seekable regular file. That is the workspace use case. For non-regular files, either keep the old whole-file path or handle the Stat/ReadAt error explicitly.

Caveats

  • sourceEndsWithNewline assumes a seekable regular file. That is the workspace use case. For non-regular files, keep the old whole-file path or handle the Stat/ReadAt error explicitly.
  • The window is buffered before writing. For a bounded --limit this is tiny. For --offset alone on a huge file, the suffix window is buffered; the source prefix is still skipped without being materialised. If O(1) output memory for an unbounded window is required, write fragments directly to stdout and accept that a mid-read failure may have already emitted partial output.
  • The fix does not change the no-window path. A no-window read still reads the whole file because its output is the whole file. The bug was specifically that a windowed read did so.
