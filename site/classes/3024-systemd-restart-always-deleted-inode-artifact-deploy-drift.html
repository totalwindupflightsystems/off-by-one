Wrote the runbook to ~/systemd-restart-always-deleted-inode-fix.md.

What I verified empirically

Since no repo is present, I reproduced the exact inode mechanism in the sandbox (/proc/<pid>/exe + hash proof):

  • Built svcdemo v1 → started it (Restart=always proxy).
  • Rebuilt the same path to v2: disk hash changed, /proc/75/exe -> ... (deleted), and the running process still printed VERSION=v1-old while disk was v2-new.
  • Killed MainPID and relaunched: link is clean, hashes equal, and it prints VERSION=v2-new.

Root cause (the part the existing gate misses)

  • In-place builds publish a new inode; the running process keeps the old one, rendered as (deleted) by the kernel.
  • Restart=always is exit-triggered — a successful rebuild never signals the process, so it serves the dead inode indefinitely.
  • check-binary-fresh only diffs source tree vs. built file on disk (both new) → green. It never hashes /proc/<MainPID>/exe.
  • Stale gitreins/tasks.yaml keeps the tree dirty, so the version-stamped target skips/refuses the new stamp — clean the tree first.

Core fix

git restore --source=HEAD --staged --worktree gitreins/tasks.yaml   # clean dirty stamp
make build VERSION="$(git describe --tags --always --dirty)"        # stamped artifact
systemctl restart "$UNIT"                                           # or kill MainPID (Restart=always)

Then verify readlink /proc/<newPID>/exe has no (deleted), sha256 running image == disk artifact, /version shows the new describe, and make check-deploy leg 3 + make tick-closeout pass.

The doc also includes the diagnosis command set, a one-shot remediation script, the missing leg-3 running-image gate to install, and a prevention checklist.
