musterflow-dogfood-tick-0924 — a MusterFlow-submitted dogfood probe is stored and solved, but discover 404s and the queue hides it

Class: off-by-one DF-OFF-BY-ONE-15 (placeholder probe predicates are unanchored) Environment: linux · Language: go 1.26 · Verified against: HEAD=17a481c, fix commit 6046258

1. Symptom

A dogfood probe submitted through the MusterFlow-generated CLI (generated from off-by-one's OpenAPI spec; calls POST /api/v1/problems/submit) is accepted and solved, but is then undiscoverable:

Surface Result
POST /api/v1/problems/submit 200, queued
solve pipeline complete, answer status=verified
GET /api/v1/problems/musterflow-dogfood-tick-0924 200 — class is there
GET /api/v1/problems/musterflow-dogfood-tick-0924/answers 200 — verified answer is there
POST /api/v1/problems/discover 404 {"error":"not_found",...}
GET /api/v1/queue {"entries":null,"total":0}

One defect, three inconsistent symptoms. The only special thing about the class is that its slug merely contains the word dogfood.

2. Root-cause analysis

internal/graph/placeholder.go declares placeholderClassPatterns and IsPlaceholderClass(title) uses Regexp.MatchString, which is an unanchored substring search. The predicate is applied both to discover and, through the ob1_is_placeholder_class SQL scalar function, to queue listings via graph.NotPlaceholderClassSQL (NOT ob1_is_placeholder_class(problem_class)).

At the buggy revision (6046258^) the patterns included raw substrings:

regexp.MustCompile(`(?i)dogfood`),   // matches ANY title containing "dogfood"
regexp.MustCompile(`(?i)canary`),    // matches ANY title containing "canary"
regexp.MustCompile(`(?i)field-test`),
regexp.MustCompile(`(?i)foreman-audit`),
// ... self-test, test-gap-sweep, test-foreman-, e2e-tick, ds-007, etc.

musterflow-dogfood-tick-0924 matches (?i)dogfood, so it is classified as a synthetic placeholder even though it is a real finding. Result: submit → stored/solved/verified; per-class GET returns it (no predicate); discover → not_found; queue list hides it. The MusterFlow CLI is only the submission channel — the defect is entirely server-side in the classifier.

Root cause (one sentence): the placeholder quarantine used unanchored case-insensitive substring regexes, so it matched any class title merely containing a probe word instead of only the actual probe families. Fix = anchor every pattern to its real shape.

3. Exact fix

Anchor each pattern: ^ prefix for prefix families, ^…$ for exact probe titles, and a separator-delimited token for token-shaped families that sit mid-slug.

var placeholderClassPatterns = []*regexp.Regexp{
    regexp.MustCompile(`(?i)^off-by-one-self-test`),
    regexp.MustCompile(`(?i)(?:^|[-_])self[-_]test(?:[-_]|$)`), // separator matters: "selftest" is real
    regexp.MustCompile(`(?i)^self[-_]dogfood`),
    regexp.MustCompile(`(?i)^test-self-dogfood`),
    regexp.MustCompile(`(?i)^dogfood-field-test`),
    regexp.MustCompile(`(?i)^dogfood$`),
    regexp.MustCompile(`(?i)^docs-canary`),
    regexp.MustCompile(`(?i)^canary$`),
    regexp.MustCompile(`(?i)^test$`),
    regexp.MustCompile(`(?i)^test-gap-sweep`),
    regexp.MustCompile(`(?i)^test-foreman-`),
    regexp.MustCompile(`(?i)^e2e-tick`),
    regexp.MustCompile(`(?i)tick\d+-e2e\b`),     // reversed form stays substring-shaped
    regexp.MustCompile(`(?i)^shell-script-e2e$`),
    regexp.MustCompile(`(?i)^e2e-verification-pipeline$`),
    regexp.MustCompile(`(?i)^foreman-e2e-verification-pipeline$`),
    regexp.MustCompile(`(?i)(?:^|[-_])foreman[-_]audit(?:[-_]|$)`),
    regexp.MustCompile(`(?i)^ds-007`),
    regexp.MustCompile(`(?i)^shell-say-hello-test$`),
    regexp.MustCompile(`(?i)^shell-echo-hello-fix$`),
}

Mirror the identical list in scripts/export-answers.py EXCLUDED_CLASS_PATTERNS. The SQL filter needs no separate edit — it evaluates this Go slice:

gofmt -w internal/graph/placeholder.go
go build -o off-by-one ./cmd/off-by-one
go test ./internal/graph/... ./internal/ingest/... ./internal/api/... -count=1
python3 scripts/tests/export_answers_exclusions_test.py
