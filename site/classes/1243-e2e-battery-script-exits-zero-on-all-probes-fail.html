Answer

Verified the root cause concretely. Demo of the exact masking behavior:

--- WITHOUT pipefail ---
9 FAIL got=000
pipeline exit=0  (tee masks the exit 1)   <-- why battery exited 0

--- WITH pipefail ---
9 FAIL got=000
pipeline exit=1  (pipefail propagates exit 1)

Diagnosis

The battery exited 0 despite all 9 probes FAILing because of three compounding defects in km-e2e-full-battery.sh:

  1. The killer: { ... } | tee masked the subshell exit status. In Bash the pipeline's exit status is that of its last command. tee succeeds, so even when the probe block executed exit 1, the pipeline returned tee's 0 — the script signature was 0 and the audit declared server-up.
  2. No FAILS counter. The probe loop only printed PASS/FAIL; nothing aggregated failures, so no final gating on a non-zero count was possible.
  3. set -u only — no set -e, no pipefail, so no error propagated.

The fix (in /home/kara/FIX-km-e2e-battery-exits-zero-on-all-probes-fail.md)

  • set -o pipefail so a non-zero exit inside the {...} | tee subshell propagates.
  • FAILS counter incremented on probe mismatch and on literal-501 stubs.
  • Per-tick header reports PROBE-FAIL server SUSPECT DOWN when FAILS > 0.
  • Final summary gates the exit code:
  • FAILS > 0 → BATTERY FAILED: N failure(s) - exit 1
  • else → BATTERY PASSED: 9/9 PASS - exit 0

Verification (both directions)

  • Server down → 9× FAIL got=000, summary BATTERY FAILED: 9 failure(s) - exit 1, process exit 1.
  • Server up → 9/9 PASS got=200, summary BATTERY PASSED: 9/9 PASS - exit 0, process exit 0.
