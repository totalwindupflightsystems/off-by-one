go-wiring-registry-field-never-populated

Answer

Root cause (U-GAP-024): the target field ApplicationConfig.Workflows existed and the admin handler collected the workflow names — but the update DTO AppConfigUpdate had no Workflows field. So Service.Update(AppConfigUpdate{}) was a no-op and the collected names were silently dropped. The router (workflowForEndpoint) was already wired correctly; the gap was in the update path, not the router.

Fix — three targeted changes:

1. Add the missing field to the update struct (pointer = "unset" vs "set to empty", mirroring the existing APIKeys convention):

type AppConfigUpdate struct {
    Workflows *[]string // FIX: was missing — the wiring gap
    APIKeys   *[]string
}

2. Clone-apply it in Service.Update (same append([]string(nil), ...) defensive-copy pattern as APIKeys):

func (s *Service) Update(u AppConfigUpdate) {
    if u.APIKeys != nil {
        s.cfg.APIKeys = append([]string(nil), (*u.APIKeys)...)
    }
    if u.Workflows != nil { // FIX: clone-apply, mirrors APIKeys
        s.cfg.Workflows = append([]string(nil), (*u.Workflows)...)
    }
}

3. Pass the collected names from the handlers:

// BEFORE (bug): names collected, then dropped
names, _ := collectWorkflowNames(r)
s.Update(AppConfigUpdate{})

// AFTER (fix): attach and pass a pointer
names, _ := collectWorkflowNames(r)
s.Update(AppConfigUpdate{Workflows: &names})   // create
// update handler: s.Update(AppConfigUpdate{Workflows: &names}) — explicit empty clears

Router, engine, and DAG code untouched. Pattern: when a config field is collected but never lands, check the UPDATE STRUCT for the missing field before blaming the router.
