Summary

Verdict: verified-benign. The alert fires because node_vmstat_oom_kill is a host-wide counter that also increments for cgroup-scoped kills, and the rule never checks the kernel's constraint= class. bunker's own cgroup_test.go memory.max probe exhausts /bunker-cgroup-test hourly; the kernel logs constraint=CONSTRAINT_MEMCG, the victim is a small python3, host MemAvailable stays ~83%, and there are zero CONSTRAINT_NONE kills. So the rule's right arm (MemAvailable/MemTotal >= 0.15) is satisfied every time.

Two independent defects documented: 1. Alert scoping — the rule reads a metric that can't distinguish memcg from host OOM. 2. Board drain — re-fires append duplicate ids; validate errors and update refuses as ambiguous.

  • Interim fix 2 — Alertmanager route-to-null / inhibition.
  • Fleet fixes 3–4 — stop the self-test polluting the prod signal; make the drain idempotent by fingerprint.
