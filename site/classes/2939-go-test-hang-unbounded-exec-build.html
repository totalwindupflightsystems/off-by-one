Answer

CHT-155: Stop test hangs by bounding every exec.Command("go", "build", ...)

Also written to ~/CHT-155-solution.md.

Root cause

The test helper (cht130Toolsd and the same shape at seven other sites) rebuilds the binary under test for every test:

out, err := exec.Command("go", "build", "-o", bin, ".").CombinedOutput()

exec.Command has no deadline. CombinedOutput eventually blocks in os/exec.(*Cmd).Wait, waiting forever for the nested go build to finish. On a loaded host that build can sit behind build-cache locks and CPU contention for an unbounded amount of time. Nothing in the helper can terminate it except the outer go test -timeout=N, so the package reports a whole-package timeout with no useful command diagnostic. The 8 call sites multiply the problem by rebuilding repeatedly.

This is an unbounded wait amplified by the environment, not a logic error in the package under test.

Fix

Apply all four parts in every affected test package:

  1. Build the binary once in TestMain (or behind a sync.Once) and share its path.
  2. Start every external command with exec.CommandContext under a timeout of at most 60 seconds, and set WaitDelay so a child that keeps stdout open cannot block Wait after cancellation.
  3. On timeout or failure, fail the test with the full command line and captured output.
  4. Add an AST-based guard test that rejects bare exec.Command in *_test.go.

1. Build once, under a deadline (main_test.go)

package toolsd

import (
    "context"
    "fmt"
    "os"
    "os/exec"
    "path/filepath"
    "testing"
    "time"
)

const maxCommandTimeout = 60 * time.Second

// testBinary is built once for the whole package and reused by every test.
var testBinary string

func TestMain(m *testing.M) {
    code, err := runTestMain(m)
    if err != nil {
        fmt.Fprintf(os.Stderr, "test setup failed: %v\n", err)
        code = 1
    }
    os.Exit(code)
}

func runTestMain(m *testing.M) (int, error) {
    dir, err := os.MkdirTemp("", "toolsd-test-*")
    if err != nil {
        return 1, err
    }
    defer os.RemoveAll(dir) // runs after m.Run(), before os.Exit

    testBinary = filepath.Join(dir, "toolsd-under-test")
    ctx, cancel := context.WithTimeout(context.Background(), maxCommandTimeout)
    defer cancel()

    cmd := exec.CommandContext(ctx, "go", "build", "-o", testBinary, ".")
    cmd.WaitDelay = 5 * time.Second
    out, err := cmd.CombinedOutput()
    if ctx.Err() == context.DeadlineExceeded {
        return 1, fmt.Errorf("build timed out after %s: %s\noutput:\n%s",
            maxCommandTimeout, cmd.String(), out)
    }
    if err != nil {
        return 1, fmt.Errorf("build failed: %s\nerror: %v\noutput:\n%s",
            cmd.String(), err, out)
    }

    return m.Run(), nil
}

For a helper binary that is not the package's main binary, the same pattern applies inside a sync.Once/TestMain; do not rebuild it from individual tests.

2. One bounded command helper (exec_helpers_test.go)

package toolsd

import (
    "context"
    "os/exec"
    "strings"
    "testing"
    "time"
)

// runCmd returns the output and exit error, but treats a timeout as a test-
// fatal condition. Use it when a non-zero exit is an expected test case.
func runCmd(t *testing.T, timeout time.Duration, name string, args ...string) ([]byte, error) {
    t.Helper()
    if timeout <= 0 || timeout > maxCommandTimeout {
        timeout = maxCommandTimeout
    }

    ctx, cancel := context.WithTimeout(context.Background(), timeout)
    defer cancel()

    cmd := exec.CommandContext(ctx, name, args...)
    // Do not let a grandchild that inherited stdout keep Wait blocked forever.
    cmd.WaitDelay = 5 * time.Second
    out, err := cmd.CombinedOutput()

    if ctx.Err() == context.DeadlineExceeded {
        t.Fatalf("command timed out after %s: %s\noutput:\n%s",
            timeout, cmd.String(), out)
    }
    return out, err
}

// mustRunCmd is the normal case: any error is fatal and includes the command
// line plus captured output.
func mustRunCmd(t *testing.T, timeout time.Duration, name string, args ...string) []byte {
    t.Helper()
    out, err := runCmd(t, timeout, name, args...)
    if err != nil {
        t.Fatalf("command failed: %s %s\nerror: %v\noutput:\n%s",
            name, strings.Join(args, " "), err, out)
    }
    return out
}

3. Replace the unbounded sites

Find them first:

rg -n --glob '*_test.go' 'exec\.Command\(\s*"go"' .
rg -n --glob '*_test.go' 'exec\.Command\(' .

Replace the per-test build-and-run pattern:

// BEFORE: rebuilt for every test, no deadline
bin := filepath.Join(t.TempDir(), "toolsd")
if out, err := exec.Command("go", "build", "-o", bin, ".").CombinedOutput(); err != nil {
    t.Fatalf("go build: %v\n%s", err, out)
}
out, err := exec.Command(bin, "apply", "--lease", lease).CombinedOutput()

// AFTER: testBinary was built once in TestMain; the command is bounded
out, err := runCmd(t, 30*time.Second, testBinary, "apply", "--lease", lease)
if err != nil {
    t.Fatalf("toolsd apply failed: %v\noutput:\n%s", err, out)
}

If a test genuinely needs a one-off go build of another helper, still use mustRunCmd(t, 60*time.Second, "go", "build", ...). Do not reintroduce bare exec.Command.

4. Regression guard (exec_guard_test.go)

This is stronger than a grep: it parses the AST, follows aliases of the os/exec import, and rejects every bare exec.Command call in *_test.go. TestMain above uses exec.CommandContext, so it is allowed without a special case.

package toolsd

import (
    "go/ast"
    "go/parser"
    "go/token"
    "path/filepath"
    "strconv"
    "testing"
)

func TestNoUnboundedExec(t *testing.T) {
    files, err := filepath.Glob("*_test.go")
    if err != nil {
        t.Fatal(err)
    }

    fset := token.NewFileSet()
    for _, path := range files {
        f, err := parser.ParseFile(fset, path, nil, 0)
        if err != nil {
            t.Fatalf("parse %s: %v", path, err)
        }

        execNames := map[string]bool{}
        for _, imp := range f.Imports {
            p, err := strconv.Unquote(imp.Path.Value)
            if err != nil || p != "os/exec" {
                continue
            }
            name := "exec"
            if imp.Name != nil {
                name = imp.Name.Name
            }
            execNames[name] = true
        }

        ast.Inspect(f, func(n ast.Node) bool {
            call, ok := n.(*ast.CallExpr)
            if !ok {
                return true
            }
            sel, ok := call.Fun.(*ast.SelectorExpr)
            if !ok || sel.Sel.Name != "Command" {
                return true
            }
            id, ok := sel.X.(*ast.Ident)
            if !ok || !execNames[id.Name] {
                return true
            }
            pos := fset.Position(call.Pos())
            t.Errorf("%s:%d: unbounded exec.Command; use exec.CommandContext with a bounded timeout via runCmd/mustRunCmd",
                pos.Filename, pos.Line)
            return true
        })
    }
}

Place the guard in each package that shells out, or keep one copy in a test-only package that walks the whole module. Format and run:

gofmt -w cmd/toolsd/*_test.go
go vet ./...
go test -count=1 -run '^TestNoUnboundedExec$' ./...
go test -count=1 -timeout=5m ./...

The outer -timeout is now a backstop, not the only bound.

Verification

Validated in a minimal module on Go 1.26.8 linux/amd64 while the shared host was at load average ~31 (same conditions as the report).

  1. Reproduced the hang shape. A test using exec.Command("go", "build", "-o", bin, ".").CombinedOutput() was pointed at a fake go that sleeps (simulating a starved nested build). With the outer timeout deliberately short:

text $ go test -count=1 -timeout=3s ./bad panic: test timed out after 3s ... os/exec.(*Cmd).CombinedOutput(...) example.com/cht155/bad.TestUnboundedGoBuild(...)

This is the same os/exec.Cmd.Wait block as the reported stack.

  1. Fixed package passes. It builds once in TestMain with exec.CommandContext (60 s max), reuses the binary, and runs it through the bounded helper:

text $ go test -count=1 -timeout=60s ./good -v === RUN TestBinaryRuns --- PASS: TestBinaryRuns (0.00s) === RUN TestNoUnboundedExec --- PASS: TestNoUnboundedExec (0.00s) PASS ok example.com/cht155/good 0.231s

  1. Guard catches a regression. Temporarily adding a test file containing exec.Command("go", "build", ...) made the guard fail with file and line:

text --- FAIL: TestNoUnboundedExec (0.00s) good_test.go:101: regression_test.go:9: unbounded exec.Command; use exec.CommandContext with a bounded timeout via runCmd/mustRunCmd

After deleting that file, the guard passed again. A timeout in the fixed helper produces a diagnostic such as command timed out after 30s: /path/toolsd apply ... plus captured output instead of an opaque package-level timeout.
