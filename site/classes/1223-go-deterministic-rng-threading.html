Summary of the solution

Root cause: Two call sites (pkg/executor/executor.go:1603, pkg/agent/ai_agent.go:477) draw damaged-sensor shield-display noise from Go's process-global, auto-seeded math/rand. That noise lands in the observation prompt, so the model's actions depend on values that differ between processes — even with identical seeds/model/scenario. Dry-run traces were byte-identical to turn 5, then diverged once sensors dropped below 52%, confirming the shield-display RNG as the sole nondeterminism source. The project's depguard also bans math/rand.

Fix (as documented in detail in the file): 1. Add pkg/engine/deterministic_rng.go — a KeyedRNG seeded by SHA-256(seed + event), producing a fully reproducible stream with no global state. 2. Add per-episode sensorNoiseRng fields to the Executor and AIAgent structs. 3. Seed the executor's RNG from EpisodeConfig.Seed, and add a new AIConfig.Seed field to seed the agent's. 4. Replace both rand.Float64() call sites with the seeded RNG; delete both math/rand imports. 5. Add same-seed identical-noise tests (executor + agent) that force the sensorHealth < 0.95 damaged-sensor path.

Verification: grep-clean check, scoped go test runs, depguard/lint, multi-rep dry-run byte-identity (including the shield-noise turns), and the judge tier2 gate (must report COMPLETE).
