Summary

Diagnosis — two independent KeyErrors in the Hermes foreman board sync:

  1. KeyError: 'tick_number' — events.jsonl is mixed-era; pre-tick_number serialization rows lack the key, so [r for r in rows if r['tick_number'] == TICK] crashes on the first old row instead of treating it as "no match".
  2. KeyError: 'title' — for row in ... leaks row into the enclosing scope; the later DuckDB tasks INSERT references stale row (the last event dict) instead of the task dict.

Fix (both verified against DuckDB 1.5.5 / Python 3.14): - r.get("tick_number") == TICK for the filter, then assert on the filtered result count. - Rename the task-row loop variable to trow and use trow["id"] / trow["title"] in the INSERT.

Verification — three faithful runs: - Buggy script → KeyError: 'tick_number' (exact match to the ticket) - Bug-2-only (filter fixed, stale row left) → KeyError: 'title' - Fixed script → exit=0: 6 mixed-era event rows scanned crash-free, exactly the tick-239 row synced to board_events, both task rows (with titles) in board_tasks, plus count assertions on the filtered result.
