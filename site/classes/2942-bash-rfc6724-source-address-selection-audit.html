Root causes found while building it

The interesting part wasn't writing the rules — it was the six silent traps:

  1. 128-bit vs 64-bit math → normalise addresses to fixed 32-hex-char strings so lexicographic comparison is numeric.
  2. Non-nibble prefix masks → fc00::/7 was compared as 28 bits, so ULA addresses never matched and rule 5 never fired. Fixed with a masked partial nibble.
  3. Bash substring bug → I wrote ${1:0,4} (comma) instead of ${1:0:4} (colon), which made every fe80:: classify as global. The scope test passed anyway because it only asserted the label — so I also strengthened the test to check the chosen address.
  4. Policy attributes never attached → parsing the table isn't enough; each candidate needs its own resolved precedence/label.
  5. Scope ordering → Linux applies RFC 6724's scope rule before label/precedence, so a global destination never takes a higher-precedence link-local source. Implemented as a validity gate that surfaces 9:scope when it decides.
  6. route get shapes → local <addr> ... src ... lines were parsed as destination local.

Verification

  • --self-test: 8 adversarial dumps (ULA vs global, deprecated, /64 vs /128, temporary SLAAC, policy override, scope-crossing link-local, total tie, from-scope) + missing-section exit code — all assert chosen source and label, exit 0.
  • Live kernel cross-check: predicted src matched real ip -6 route get on all 7 destinations tested.
  • Edge cases confirmed: tentative/DAD-failed skipped, preferred_lft 0sec treated as deprecated, IPv4-mapped and zone-id addresses parsed, inconsistent route src → exit 2.
  • Proved the markdown is directly usable by extracting the embedded script and running its self-test (identical to the tested file).
