DF-MAFIA-AI-BENCHMARK-47 — Deploy-refresh kills in-flight games; stranded runs report RUNNING for 7 days

Status: diagnosed, fixed, tested (server 567/567, shared 422/422, tsc clean, shellcheck clean) Affected: scripts/deploy-refresh.sh, apps/server/src/services/benchmark-runner.ts, apps/server/src/index.ts Evidence run: 8ab81f89-3315-4044-a099-6785df6747a9 (game 6de31446-ec0e-4d10-bdc7-49266f5ffc90, 124 events, last 2026-10-21T07:15:03.504Z, container StartedAt 2026-10-21T07:15:05.260762533Z)

1. TL;DR

The hourly mafia-deploy-refresh.timer rebuilt and recreated the server container 1.8 s after the game's last event. The legacy game engine is a child process of the server process inside that container, so docker compose up -d SIGKILLed the bridge mid-game. No terminal event was ever emitted, so the benchmark_runs row stayed RUNNING and the benchmark_games row stayed completed_at = NULL.

Two independent defects made this unrecoverable:

  1. deploy-refresh.sh recreated the container unconditionally — it never checked whether a benchmark run was live.
  2. BenchmarkRunner.reconcileStrandedRuns() only swept an unfinished run after 7 days (STALE_RUN_MAX_MS) and had no notion of a live bridge, so a run killed at minute 4 reported RUNNING for a week and the orphaned game stayed IN_PROGRESS forever.

The fix makes deploy-refresh drain or defer while a run is QUEUED/RUNNING, and makes the runner retire any non-terminal run whose bridge is gone within one 60 s sweep (at startup and on an interval), marking the unfinished benchmark_games row errored and the ghost games row CANCELLED.

2. Root-cause analysis

2.1 The timestamp identity

Observation Value
Game's last bridge event 2026-10-21T07:15:03.504Z
Server container .State.StartedAt 2026-10-21T07:15:05.260762533Z
.deploy-stamp 8e7caaf6ee7b4322c867741e2d88a04607538c5b (already = newest pushed SHA)
Bridge process after the stall none on host ps and docker exec ps
Control run after the recreate 7ca182d7… COMPLETED 1/1 in 2.5 min (no deploy fired)

StartedAt lands 1.76 s after the last event and after the run began: the container was recreated mid-job. That is a recreate kill, not an LLM/network hang.

2.2 Why the recreate killed the game

LegacyGameAdapter.startGame() spawns legacy-bridge.js (which runs game-engine.js) with child_process.spawn(...):

const childProcess = spawn('node', [this.bridgeScriptPath, ...args], { ... });

The child lives inside the server container. docker compose up -d server web replaces the container, PID 1 gets SIGKILL, and every descendant — all in-flight bridges — dies instantly. The bridge never writes its done message, the in-process GAME_ENDED subscription dies with the process, and nothing ever flips benchmark_games.completed_at.

2.3 Why it did not self-heal

  • reconcileStrandedRuns() ran only at startup and only retired a run when:
  • every benchmark_games row was already terminal, or
  • the run was older than STALE_RUN_MAX_MS (7 days).
  • A run killed at minute 4 has one unfinished game row and is far younger than 7 days, so it was left RUNNING. The next startup saw the same shape and left it again.
  • GET /api/v1/benchmark/runs/:id has no liveness check, so it faithfully reported the stale row. The only bound was the CLI's 30-minute --timeout.

2.4 Secondary defect found while fixing

The bridge close handler in launchLegacyGame() returned early on code === null:

child.on('close', (code) => {
  if (code === 0 || code === null) return;   // SIGKILL/SIGTERM ignored

A signal-killed bridge (the exact container-recreate case, or an operator stop) produced no benchmark_games.error, so even a server that survived the child kill could not retire the run.

3. Discriminator / debug recipe (transferable)

When a long-running server-side job stalls with no error:

  1. Diff the job's last activity time against the host container start time. bash docker inspect -f '{{.State.StartedAt}}' mafia-ai-benchmark-server-1 # compare to the last events/api_calls/child-stdout timestamp A StartedAt within seconds after the job started and at the stall means the container was recreated mid-job and its children were killed. It does not mean the job logic hung.
  2. Find the recreator. bash ls -la .deploy-stamp systemctl --user list-timers | grep deploy journalctl --user -u mafia-deploy-refresh.service -n 50 A .deploy-stamp already equal to the newest pushed SHA proves the refresh fired after that push.
  3. Confirm the child is gone everywhere. bash ps -ef | grep -E 'legacy-bridge|game-engine' | grep -v grep # host docker compose exec -T server ps -ef | grep -E 'legacy-bridge' # container
  4. child alive ⇒ LLM/network hang;
  5. child gone + container StartedAt later ⇒ recreate kill.
  6. Do not read the job's own status as progress. Check benchmark_games.completed_at and the game's last event, not the run status alone. The control (POST /api/v1/benchmark/<id>/cancel → 200 CANCELLED) proves the API cancel path works; it is the automatic path that was missing.

4. The fix

4.1 scripts/deploy-refresh.sh — active-run gate + drain/defer

Before touching docker, probe GET /api/v1/benchmark/runs. If any run is QUEUED/RUNNING, poll until idle; if the drain window expires, defer (leave the stamp unchanged so the next cadence retries). Concurrent triggers serialize on a flock.

Add these variables near the top:

DRY_RUN="${DEPLOY_REFRESH_DRY_RUN:-0}"
FORCE="${DEPLOY_REFRESH_FORCE:-0}"
API_URL="${DEPLOY_REFRESH_API_URL:-http://<ip-address>:3004}"
DRAIN_SECONDS="${DEPLOY_REFRESH_DRAIN_SECONDS:-600}"
POLL_SECONDS="${DEPLOY_REFRESH_POLL_SECONDS:-15}"
CANCEL_ACTIVE="${DEPLOY_REFRESH_CANCEL_ACTIVE:-0}"
ACTIVE_PROBE="${DEPLOY_REFRESH_ACTIVE_PROBE:-}"
NO_DOCKER="${DEPLOY_REFRESH_NO_DOCKER:-0}"
LOCK_FILE="${DEPLOY_REFRESH_LOCK:-$REPO_ROOT/.deploy-refresh.lock}"

After the DRY_RUN short-circuit, add the lock and the gate. The core (full file is in the repo):

# Serialize concurrent triggers (timer + cron + post-merge hook).
if command -v flock >/dev/null 2>&1; then
  exec 9>"$LOCK_FILE"
  if ! flock -n 9; then
    echo "deploy-refresh: another deploy-refresh is already running — skipping"
    exit 0
  fi
fi

# Prints QUEUED/RUNNING run count, or EMPTY when the server is unreachable.
active_run_count() {
  local json="" out=""
  if [[ -n "$ACTIVE_PROBE" ]]; then
    json="$(bash -c "$ACTIVE_PROBE" 2>/dev/null || true)"
  else
    json="$(curl -fsS -m 5 "$API_URL/api/v1/benchmark/runs" 2>/dev/null || true)"
  fi
  [[ -z "$json" ]] && return 0
  if command -v jq >/dev/null 2>&1; then
    out="$(printf '%s' "$json" | jq -r '[.data[]? | select(.status=="RUNNING" or .status=="QUEUED")] | length' 2>/dev/null || true)"
  fi
  if [[ -z "$out" ]] && command -v node >/dev/null 2>&1; then
    out="$(printf '%s' "$json" | node -e '/* parse .data[].status */' 2>/dev/null || true)"
  fi
  [[ -n "$out" ]] && printf '%s' "$out"
}

drain_or_defer() {
  if [[ "$FORCE" == "1" ]]; then
    echo "deploy-refresh: DEPLOY_REFRESH_FORCE=1 — skipping active-run gate"
    return 0
  fi
  local count deadline now remaining
  deadline=$(( $(date +%s) + DRAIN_SECONDS ))
  while :; do
    count="$(active_run_count || true)"
    if [[ -z "$count" ]]; then
      echo "deploy-refresh: active-run probe unavailable (server not reachable) — proceeding with rebuild"
      return 0
    fi
    if [[ "$count" -eq 0 ]]; then
      echo "deploy-refresh: no active benchmark runs — proceeding with rebuild"
      return 0
    fi
    now=$(date +%s)
    if [[ "$now" -ge "$deadline" ]]; then
      if [[ "$CANCEL_ACTIVE" == "1" ]]; then
        cancel_active_runs
        return 0
      fi
      echo "deploy-refresh: still $count active benchmark run(s) after ${DRAIN_SECONDS}s — DEFERRING rebuild"
      echo "deploy-refresh: stamp unchanged; the next timer/cron cadence will retry"
      return 2
    fi
    remaining=$(( deadline - now ))
    echo "deploy-refresh: $count active benchmark run(s); draining (${remaining}s left before defer)"
    sleep "$POLL_SECONDS"
  done
}

gate_status=0
drain_or_defer || gate_status=$?
[[ "$gate_status" -eq 2 ]] && exit 0
[[ "$gate_status" -ne 0 ]] && exit "$gate_status"

cancel_active_runs() (used only with DEPLOY_REFRESH_CANCEL_ACTIVE=1) POSTs /api/v1/benchmark/<runId>/cancel for each active run.

Also add .deploy-refresh.lock to .gitignore.

Operational knobs

Variable Default Purpose
DEPLOY_REFRESH_FORCE=1 off Emergency bypass of the gate
DEPLOY_REFRESH_API_URL http://<ip-address>:3004 Server base URL
DEPLOY_REFRESH_DRAIN_SECONDS 600 Max seconds to wait for idle before deferring
DEPLOY_REFRESH_POLL_SECONDS 15 Drain poll cadence
DEPLOY_REFRESH_CANCEL_ACTIVE=1 off Cancel active runs after the drain expires (instead of deferring)

The post-merge hook (host-local, gitignored) shares this script. If a merge must not block, set DEPLOY_REFRESH_DRAIN_SECONDS=0 for the hook — it will defer instantly instead of waiting.

4.2 benchmark-runner.ts — retire orphaned runs within one sweep interval

New constants:

export const LIVE_EVIDENCE_GRACE_MS = 60_000;        // one sweep interval
export const RECONCILE_SWEEP_INTERVAL_MS = 60_000;
// STALE_RUN_MAX_MS stays as the 7-day absolute backstop.

reconcileStrandedRuns() now takes the live-bridge set (defaults to the adapter's RUNNING children) and has an explicit orphan branch:

reconcileStrandedRuns(liveGameIds?: ReadonlySet<string>): ReconcileSummary {
  const live = liveGameIds ?? this.liveBridgeGameIds();
  // ... SELECT QUEUED/RUNNING ORDER BY created_at ASC ...

  for (const row of rows) {
    const games = /* benchmark_games for row */;
    if (this.reconcileTerminalRun(row.id, games)) { summary.reconciled++; continue; }

    const unfinished = games.filter((g) => g.completed_at === null && g.error === null);
    const hasLiveBridge = unfinished.some((g) => live.has(g.game_id));
    const age = now - row.created_at;

    if (!hasLiveBridge && age >= LIVE_EVIDENCE_GRACE_MS) {
      // DF-47: bridge gone, terminal event can never arrive.
      this.strandRun(row.id, unfinished.map((g) => g.game_id), now);
      if (age >= STALE_RUN_MAX_MS) summary.staleFailed++;
      else summary.strandedFailed++;
    } else if (age >= STALE_RUN_MAX_MS) {
      this.strandRun(row.id, unfinished.map((g) => g.game_id), now);
      summary.staleFailed++;
    } else {
      summary.leftActive++;
    }
  }
  return summary;
}

private liveBridgeGameIds(): Set<string> {
  const live = new Set<string>();
  if (!this.legacyAdapter) return live;
  for (const gameId of this.legacyAdapter.getActiveGames()) {
    const state = this.legacyAdapter.getGameState(gameId);
    if (state && state.status === 'RUNNING') live.add(gameId); // ENDED entries are NOT live
  }
  return live;
}

private strandRun(runId: string, unfinishedGameIds: string[], now: number): void {
  const reason =
    'Run abandoned: bridge/game process is no longer alive and no terminal ' +
    'game event was received (orphaned-run sweep)';
  const markBenchmarkGame = this.db.prepare(
    `UPDATE benchmark_games SET error = ? WHERE game_id = ? AND completed_at IS NULL AND error IS NULL`,
  );
  const markGameRow = this.db.prepare(
    `UPDATE games SET status = 'CANCELLED', ended_at = COALESCE(ended_at, ?)
      WHERE id = ? AND status NOT IN ('ENDED', 'CANCELLED')`,
  );
  for (const gameId of unfinishedGameIds) {
    markBenchmarkGame.run(reason, gameId);
    markGameRow.run(now, gameId);
  }
  const summaryPayload = this.buildRunSummary(runId); // after error markers
  this.db.prepare(
    `UPDATE benchmark_runs
       SET status = 'FAILED', error = ?, completed_at = ?, summary = ?, updated_at = ?
     WHERE id = ? AND status IN ('QUEUED', 'RUNNING')`,
  ).run(reason, now, summaryPayload, now, runId);
}

Key detail: LegacyGameAdapter.getActiveGames() returns every game the process ever started (ended entries included, so /api/v1/games can report them ENDED). Liveness therefore filters on getGameState(id).status === 'RUNNING'; otherwise a killed game would look live for the process lifetime and defeat the sweep.

4.3 index.ts — periodic sweep, not just startup

const reconcileTimer = setInterval(() => {
  try { benchmarkRunner.reconcileStrandedRuns(); }
  catch (e) { console.error('Benchmark run reconciliation sweep failed:', (e as Error).message); }
}, RECONCILE_SWEEP_INTERVAL_MS);
reconcileTimer.unref();
// ... and clearInterval(reconcileTimer) in the SIGTERM/SIGINT shutdown handler.

4.4 launchLegacyGame() — treat a signal kill as a game failure

child.on('close', (code: number | null, signal: NodeJS.Signals | null) => {
  if (code === 0) return;                 // clean exit -> normal GAME_ENDED path
  const row = /* completed_at, error for gameId */;
  if (!row || row.completed_at !== null || row.error !== null) return;
  const how = code === null ? `signal ${signal ?? 'unknown'}` : `code ${code}`;
  const message =
    `legacy bridge process exited with ${how} without publishing ` +
    `a terminal game event (no 'done' — bridge failed to start or was killed)`;
  // set error, then maybeCompleteRun(runId)
});

This catches an isolated child kill in-process, before the 60 s sweep.

7. Rollout / rollback

  • Rollout: merge, then let the timer/cron run once. Because the stamp is only updated after a successful up, the gate cannot strand the stamp. On the first cadence after a live run, the deploy defers; on the cadence after the run finishes, it proceeds.
  • Emergency deploy while a run is wedged: DEPLOY_REFRESH_FORCE=1 bash scripts/deploy-refresh.sh (or DEPLOY_REFRESH_DRAIN_SECONDS=0 + DEPLOY_REFRESH_CANCEL_ACTIVE=1).
  • Rollback: git revert the four source files. The runtime state files (.deploy-stamp, .deploy-refresh.lock) are gitignored and need no cleanup.
  • Compatibility: reconcileStrandedRuns() keeps its zero-argument signature and all prior semantics (COMPLETED/FAILED recovery, 7-day backstop); staleFailed is still populated. The only behavioral change is that a non-terminal run with no live bridge is retired after 60 s instead of 7 days — which is the point of the fix.
