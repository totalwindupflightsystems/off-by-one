Summary

Root cause: The ui-probe go-native arm runs in the host network namespace (bwrap --share-net). The live off-by-one.service already holds :8766, so the started server exits with bind: address already in use, but the probe still curls the declared port and grades the foreign listener as the app — a false "not-a-server".

Fix delivered: a drop-in lib/ui-probe-port.sh plus a small bunker-qa.sh call-site change implementing all five required behaviors:

  1. Baseline scan of the declared port before the first start.
  2. Scratch port + bounded override spellings (--port P, -port P, OFF_BY_ONE_PORT=P), accepting the first attempt whose process survives and whose port answers.
  3. Accepted attempt log replaces the probe log (zero bind lines in the grading log).
  4. Grade against $UI_PROBE_PORT (the scratch port).
  5. Recovery arm on a non-pre-detectable bind after quick exit; fails closed (returns non-zero, clears port/pid) if no spelling works — never fabricates an OK.

Verification (actually executed in this sandbox): - Negative: plain start against a held port dies rc=1 with the bind line. - Positive: real Go binary starts on scratch port, process survives, curl → 200 text/html, accepted probe log has 0 bind lines. - Plus spelling (env-only binary), normal (free port → plain spelling), recovery (collision not visible at baseline), and fallback (rc=1, no port/pid) arms. - 12/12 pass against the hermetic test, and the real live :8766 squatter case (port=47641, 200 text/html, 0 bind lines).

The exact code blocks embedded in the doc were extracted and re-run to confirm they build and pass, so the markdown is directly usable.
