Answer

Fix: atomic pid publication and a load-safe kill deadline in DeliverTimeoutKillsProcessGroup

Root cause

Two defects combine:

  1. The writer is not atomic. The fake harness does:

bash printf '%s\n%s\n' "$$" "$child" > "$dir/pids"

Bash opens/truncates pids before running printf. If SIGKILL lands after the truncate but before the write, the result is a real but zero-byte file. readPIDs sees an existing file with raw == "", parsePIDs("") returns no pids and no error, so the failure is:

text fake harness wrote fewer than 2 pids ... within 5s: ""

  1. The 400ms deadline includes process cold-start. The timeout covers exec, the dynamic loader, bash initialization, and the sleep 30 & fork. Under host load these can consume hundreds of milliseconds, so the kill is correlated with the script's start-up/write window rather than a rare microsecond race.

Exact fix

File: internal/harness/contract_test.go

1. Publish the pid pair atomically

if [ "$mode" = "timeout" ]; then
  sleep 30 &
  child=$!
  # Publish the pair atomically in the same directory. A direct redirect to
  # $dir/pids truncates first, so a SIGKILL between the open and the write
  # leaves a misleading EMPTY file. With temp+rename a reader sees either no
  # file or a complete pair, and an early kill is diagnosable as absent rather
  # than silently empty.
  tmp="$dir/.pids.$$"
  printf '%s\n%s\n' "$$" "$child" > "$tmp" &&
    mv -f "$tmp" "$dir/pids"
fi

2. Give the kill deadline startup margin

// The deadline starts at exec, so it includes bash start-up and the
// fork of the helper. Under host load that cold start can take
// hundreds of ms; 400ms measures scheduler latency, not the kill.
// The invariant is "far below the script's 30s hang, and the whole
// group is dead", which a 3s budget still proves (the elapsed guard
// below remains 10s).
a := tc.build(t, f.bin, f, 3*time.Second)

3. Report size/mtime while polling

Replace readPIDs with a version that records each artifact state transition:

// pidsObservation is one poll of the recorded artifact. Size and mtime matter:
// exists+size=0 is "killed after truncate", stat=absent is "killed before
// create". Without that split the two look like the same empty result.
type pidsObservation struct {
    at     time.Time
    exists bool
    size   int64
    mtime  time.Time
    err    error
}

func (o pidsObservation) String() string {
    if !o.exists {
        return fmt.Sprintf("%s absent (%v)", o.at.Format("15:04:05.000"), o.err)
    }
    return fmt.Sprintf("%s exists size=%d mtime=%s", o.at.Format("15:04:05.000"), o.size, o.mtime.Format("15:04:05.000"))
}

func readPIDs(t *testing.T, path string) []int {
    t.Helper()
    deadline := time.Now().Add(pidsWaitBound)
    var lastRaw string
    var lastErr error
    var last pidsObservation
    var trace []pidsObservation
    for {
        now := time.Now()
        obs := pidsObservation{at: now}
        if fi, err := os.Stat(path); err != nil {
            obs.err = err
            lastErr = err
        } else {
            obs.exists = true
            obs.size = fi.Size()
            obs.mtime = fi.ModTime()
            raw, err := os.ReadFile(path)
            if err != nil {
                lastErr = err
            } else {
                lastRaw = string(raw)
                pids, perr := parsePIDs(raw)
                if len(pids) >= pidsWanted {
                    return pids
                }
                lastErr = perr
            }
        }
        if len(trace) == 0 || obs.exists != last.exists || obs.size != last.size || !obs.mtime.Equal(last.mtime) {
            trace = append(trace, obs)
            if len(trace) > 8 {
                trace = trace[len(trace)-8:]
            }
        }
        last = obs
        if !time.Now().Before(deadline) {
            break
        }
        time.Sleep(pidsPollInterval)
    }
    if lastErr != nil {
        t.Fatalf("read pids: %v (waited %s for %s to hold %d pids; last state: %s; observations: %v)", lastErr, pidsWaitBound, path, pidsWanted, last, trace)
    }
    t.Fatalf("fake harness wrote fewer than %d pids to %s within %s: %q (last state: %s; observations: %v)", pidsWanted, path, pidsWaitBound, lastRaw, last, trace)
    return nil
}

Atomic writer semantics

ARM direct / killed after truncate:
pids: exists size=0 lines=0 raw=''

ARM atomic / killed before rename:
pids: ABSENT
temp: .pids.6215 size=0

ARM atomic / completed:
pids: exists size=10 lines=2 raw=$'6221\n6222'

The invalid state changes from “silently empty pids” to “absent pids”; a completed write always contains the complete pair.

Diagnostics

Old truncated writer now reports:

A kill before publication reports:

size=0 and absent are now unambiguous.
