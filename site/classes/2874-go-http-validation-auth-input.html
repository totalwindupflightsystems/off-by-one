Fixing Phantom Provider Existence on PUT /auth/{providerID}

Problem class: go-http-validation-auth-input Files: internal/shim/opencode/server.go, internal/shim/opencode/server_test.go Affected endpoints: PUT /auth/{providerID}, GET /api/provider/{id}, GET /provider/auth

1. Root cause

PUT /auth/{providerID} decoded the body into an untyped map[string]any and persisted every JSON key verbatim as system_settings rows: auth.<providerID>.<arbitrary-key>.

Provider existence is derived exclusively from those rows by storedProviderAuthMethods(), which scans for the auth. prefix and treats the first path segment as the provider ID. So GET /api/provider/{id} returns 404 only when the ID is absent from that map, and GET /provider/auth serializes it directly.

Therefore a single request with any key — typo, client extension, or malicious field — creates auth.* rows and makes a provider that was never configured appear to exist. The OpenCode contract only permits 5 fields (type, key, refresh, access, expires). Secondary defect: rows were written inside the decode loop, allowing partial writes.

2. Exact fix

2a. Add the whitelist in internal/shim/opencode/server.go:

// api -> type, key ; oauth -> type, refresh, access, expires
var authAllowedFields = map[string]struct{}{
    "type": {}, "key": {}, "refresh": {}, "access": {}, "expires": {},
}

2b. Validate before any persistence (fail closed + atomic):

var raw map[string]any
if err := json.NewDecoder(r.Body).Decode(&raw); err != nil {
    http.Error(w, "invalid JSON body", http.StatusBadRequest)
    return
}

// FIX: validate every key against the whitelist before persisting anything.
for field := range raw {
    if _, ok := authAllowedFields[field]; !ok {
        http.Error(w, "unknown auth field: "+field, http.StatusBadRequest)
        return
    }
}

for field, value := range raw {
    encoded, _ := json.Marshal(value)
    s.store.Set("auth."+providerID+"."+field, string(encoded))
}
w.WriteHeader(http.StatusOK)

Validates everything before the first store.Set, so a rejected request writes nothing.

3. Verification

Three regression tests in server_test.go: 1. TestSetAuthRejectsUnknownField — unknown key → 400, 0 rows persisted. 2. TestRejectedAuthDoesNotCreatePhantomProvider — rejected PUT → GET /api/provider/ghost is 404. 3. TestProviderAuthHasNoPhantomEntry — rejected PUT → GET /provider/auth has no ghost entry.

Plus a positive control (TestSetAuthAcceptsValidCredential) ensuring valid api creds still persist.

go test ./internal/shim/opencode/ -run \
  'TestSetAuthRejectsUnknownField|TestRejectedAuthDoesNotCreatePhantomProvider|TestProviderAuthHasNoPhantomEntry|TestSetAuthAcceptsValidCredential' -v
