Fix: false "Landlock filesystem tier not applied" warning for loaders under an owner-private home (TJ-DF-064)

  • Repo: terminal-jail/terminal-jail
  • Fix commit: ae8524e6b65479467dcc1e02dd115bf707271e68 — "fix landlock launch reachability warning" (addresses TJ-DF-064)
  • Affected surface: the engine-side Landlock tail composer (plugin/terminal_jail/interruptor/landlock.py), plus the three copies of the degrade warning text
  • Symptom: on a host whose $HOME is 0700/0750, every wrapped command prints WARNING: Landlock filesystem tier not applied (… not reachable by the launch's payload uid (a parent of … lacks o+x …)) even though Landlock is attaching and enforcing, and the warning's remedy told the user to set TERMINAL_JAIL_LANDLOCK=0, i.e. to disable working protection.

1. Root-cause analysis

1.1 Two deciders, one of which guessed

The Landlock filesystem tier reaches a payload through two independent decisions:

  1. The wrapper's launch-context decision (standalone/terminal-jail). Before exec it probes the launcher that will actually run the payload with the loader path: bash unshare $UNSHARE_FLAGS test -r "$LANDLOCK_LOADER" # unshare arm "$_TJ_BWRAP_BIN" $BWRAP_FLAGS -- test -r "$LANDLOCK_LOADER" # bwrap arm This authoritatively answers "can the launch read the loader?" under the exact launch flags (uid mapping, --user, bwrap, or the --here composed shape).

  2. The engine's compose decision (plugin/terminal_jail/interruptor/landlock.py, _compute_sandbox_prefix() → sandbox_prefix()), consumed by decider.py:_wrap_payload to splice python3 <loader> -- into auto-sandbox/modify rewrites. Before the fix it inferred reachability from directory mode bits owned by the engine's uid: python def _world_traversable(path: str) -> bool: """True when EVERY directory on ``path`` grants other-execute (o+x).""" ... if not mode & stat.S_IXOTH: # <-- owner-uid inference return False ... if not _world_traversable(loader): return _degrade( "landlock-loader.py is not reachable by the launch's payload " f"uid (a parent of {loader} lacks o+x — e.g. a 0700/0750 home)" )

1.2 Why the inference is invalid

_world_traversable() demands S_IXOTH (o+x) on every ancestor. That answers "can a totally unrelated uid traverse this path?" but the engine runs as the owner, while a uid-mapped launch changes the payload uid. The engine (owner) can always open a loader below its own 0700/0750 home; whether the launch's payload uid can is already answered by the wrapper's launch-context probe using the real launch flags. For a uid-mapped launch the wrapper intentionally skips the filesystem tier (a uid mapping is filesystem isolation — a substitution, not a degradation). So the engine vetoed loaders the actual launch could reach, returning "" and emitting the degrade warning on every command — a false negative that trains users to ignore the true warnings too.

1.3 The second harm: unsafe remediation text

The warning ended with … or disable this warning deliberately with TERMINAL_JAIL_LANDLOCK=0. Following it silences a working kernel filesystem protection.

1.4 What must be retained

  • The genuine missing-loader warning.
  • The genuine unreadable warning when the engine itself cannot read the file.
  • _world_traversable() stays as a diagnostic helper, but must no longer gate the Landlock tail.

2. Exact fix

Replace owner-uid ancestor inference with a launch-context readability seam and rewrite the remediation text. Seven files change.

2.1 Engine: plugin/terminal_jail/interruptor/landlock.py

Keep _world_traversable() but demote it to a diagnostic, and add:

def _world_traversable(path: str) -> bool:
    """True when EVERY directory on ``path`` grants other-execute (o+x).

    This is retained as a diagnostic helper for callers that specifically
    need a DAC-independent path check.  The Landlock tail decision must not
    use it: the engine runs as the owner while uid-mapped launches change the
    payload uid, so owner-uid reachability cannot be inferred from ancestor
    mode bits.
    """
    ...


def _loader_readable_by_launch(path: str) -> bool:
    """Probe the actual launch context instead of owner-uid ancestor stats.

    The engine's process can open a loader below a private home even when the
    subordinate uid used by a mapped launch cannot.  The wrapper performs the
    authoritative launch-context probe; here we only reject a missing or
    owner-unreadable file and let that probe decide whether the tail can run.
    """
    try:
        return os.path.isfile(path) and os.access(path, os.R_OK)
    except OSError:
        return False

In _compute_sandbox_prefix(), swap the gate (loader is None keeps the genuine missing-loader warning):

    loader = loader_path()
    if loader is None:
        return _degrade("landlock-loader.py not found next to the plugin")
    if not _loader_readable_by_launch(loader):
        return _degrade(
            f"landlock-loader.py cannot be read by the engine launch context ({loader})"
        )
    return f"python3 {shlex.quote(loader)} -- "

2.2 Safe warning text (all four warning surfaces)

degradation_warning() in interruptor/landlock.py, and the matching text in standalone/landlock-loader.py, plugin/terminal_jail/_bundled/landlock-loader.py, standalone/terminal-jail, and plugin/terminal_jail/_bundled/terminal-jail (_tj_fs_degrade):

… classify the host with scripts/landlock-capability-probe.py and verify the
loader path and launch context; do not disable filesystem protection to
suppress this warning

The knob itself (documented and honored by _degrade) is unchanged — only the advice to use it to silence a warning is removed.

4. Summary

The engine decided Landlock-loader reachability by walking ancestor mode bits and requiring o+x — a worst-case DAC inference unrelated to the engine's owner uid or the launch's actual uid mapping. On a 0700/0750 home it falsely rejected a loader the launch could read, returned no tail, and printed a "tier not applied" warning on every command whose remedy was to disable the working tier. The fix replaces the inference with a launch-context readability seam (_loader_readable_by_launch, owner-context os.access), letting the wrapper's existing unshare … test -r / bwrap … -- test -r / --here probe make the authoritative call, and rewrites every degrade warning to point at safe diagnostics. Genuine missing-loader and unreadable-loader warnings are retained.
