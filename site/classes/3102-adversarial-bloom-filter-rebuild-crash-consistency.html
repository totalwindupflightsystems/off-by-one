Crash-Consistent Bloom Filter Index

No false negatives under concurrent rebuild, torn pages, version changes, and adversarial hash collisions

Environment: Go 1.26 · Module: bloomlab · Status: verified with go test -race

1. The invariant

MightContain(k) == false means k is definitely absent. False positives are allowed. The hard rule:

No false negatives. Every committed live key must test positive in every state reachable by crash, concurrent insert/delete/rebuild, format/version change, and adversarial hashing.

A naive implementation breaks this in four independent ways.

2. Root-cause analysis

2.1 Rebuild races with insert. A rebuild snapshots live, builds a filter, then publishes. An insert after the snapshot but before publish is missing from the new filter → reader gets false for a live key. Mutating a shared filter in place is also a data race and exposes partial bits.

2.2 Delete clears bits. Bloom filters don't support delete. Clearing the k bits of a deleted key also clears bits shared with other live keys → collateral false negatives.

2.3 Non-atomic publish / torn page. Writing the filter in place, or mutating before the new one is complete, exposes half-built state. A crash mid-write leaves a torn page; loading it drops bits → false negatives.

2.4 Version/hasher mismatch. If recovery loads a filter built with different seeds, k, or hasher, then Add and Test use different bit positions → every key can test negative despite the file "loading fine".

3. The fix

Root cause Mechanism
2.1 rebuild race Immutable generations published by one atomic.Pointer.Store; writers serialized; delta overlay for post-publish inserts
2.2 delete Deletes remove from live/delta, never clear filter bits
2.3 torn page Filters written temp → fsync → rename → dir fsync; SHA-256 checksum verified on load
2.4 version/hasher Header carries magic, format version, WAL sequence, hasher id; mismatch ⇒ discard & rebuild
source of truth CRC-framed, sequence-numbered WAL; torn tail discarded; recover live from WAL

Core data structures

// Immutable once published. Readers do one atomic load and then only read
// immutable data.
type generation struct {
    filter  *Filter
    delta   map[string]struct{} // inserts since the filter was built
    version uint64
}

type Store struct {
    mu      sync.Mutex              // serializes writers + rebuilds
    gen     atomic.Pointer[generation]
    live    map[string]struct{}
    nextSeq uint64
    wal     *WAL
    // ... m, k, seeds, hasher, hashID, dir
}

The no-false-negative operations

func (s *Store) Insert(key string) error {
    s.mu.Lock(); defer s.mu.Unlock()
    if err := s.wal.Append(Record{Seq: s.nextSeq, Kind: OpInsert, Key: key}); err != nil {
        return err
    }
    s.nextSeq++
    s.live[key] = struct{}{}
    g := s.gen.Load()
    nd := cloneDelta(g.delta)
    nd[key] = struct{}{}
    s.gen.Store(&generation{filter: g.filter, delta: nd, version: g.version + 1})
    return nil
}

func (s *Store) Delete(key string) error {
    s.mu.Lock(); defer s.mu.Unlock()
    if err := s.wal.Append(Record{Seq: s.nextSeq, Kind: OpDelete, Key: key}); err != nil {
        return err
    }
    s.nextSeq++
    delete(s.live, key)
    // Remove from delta only. NEVER clear filter bits: they are shared.
    g := s.gen.Load()
    if _, ok := g.delta[key]; ok {
        nd := cloneDelta(g.delta)
        delete(nd, key)
        s.gen.Store(&generation{filter: g.filter, delta: nd, version: g.version + 1})
    }
    return nil
}

func (s *Store) MightContain(key string) bool {
    g := s.gen.Load()
    if g == nil { return false }
    if g.filter.Test(key) { return true } // may be a false positive
    _, ok := g.delta[key]
    return ok
}

// Build a brand-new filter from a snapshot of live, then publish atomically.
func (s *Store) rebuildLocked() error {
    f := NewFilter(s.m, s.k, s.seeds, s.hash)
    for key := range s.live { f.Add(key) }
    seq := uint64(0); if s.nextSeq > 1 { seq = s.nextSeq - 1 }
    g := s.gen.Load()
    s.gen.Store(&generation{filter: f, delta: map[string]struct{}{}, version: g.version + 1})
    return writeFilterAtomic(filepath.Join(s.dir, filterName), seq, s.hashID, f)
}

Recovery — the WAL is authoritative

On Open: replay the WAL to get live; try to load a checksummed filter with sequence S; replay records after S into delta; if the filter is invalid (checksum, magic, format version, or hasher id) rebuild from the full live set. Torn WAL frames (short length or bad CRC) are discarded. Full listings for bloom.go, wal.go, store.go, store_test.go are in the repo.

Proof sketch

Invariant I(g): ∀ k ∈ L: g.filter.Test(k) ∨ k ∈ g.delta. - Insert(k): new delta includes k. - Delete(k): other live keys keep their coverage; k isn't required. - Rebuild: fresh filter is built from the snapshot of L; delta reset. - Recovery: filter with seq S covers keys live at S; later WAL records populate delta; otherwise rebuild over all L.

Each transition is one atomic pointer store, so readers observe complete generations. I holds in all reachable states ⇒ no false negatives.

  • Sequential — real rebuilt filter, live keys always found; deleted keys may remain positive.
  • False positives possible — constant hasher makes an uninserted key test positive.
  • Adversarial collisions — 4000 equal-length keys on 4 bits; all still found (saturation 0.001, false positives only).
  • Concurrent (normal + adversarial) — 8 writers + continuous rebuilder under -race.
  • Torn/truncated/version-mismatched filter — rejected by checksum/magic/version, rebuilt from WAL.
  • WAL torn tail / bad CRC — discarded; committed keys survive.
  • Random crash recovery — 20 reopen cycles with random ops; no committed key ever goes negative.
