What the document contains

Title / problem class — gitreins-tier2-criterion-requires-automated-test-evidence.

Root cause — The feature was correct, but the criterion demanded automated test evidence. The worker produced a manual curl transcript + commit message, so the judge's grep across *_test.go/*.test.ts/test_*.py found nothing. Scope coupling means a from-scratch re-dispatch risks the already-passing sub-requirements and burns an attempt (a FAIL consumes an attempt; judge/parse errors don't).

Exact fix 1. Re-dispatch the same worker on the same tree with the judge finding verbatim + the unmet criterion quoted, explicitly "continue the existing tree, do not restart." 2. Add a stdlib-only Go e2e test (proxy_sse_e2e_test.go) that builds the real proxy binary, runs it as a subprocess pointed at a httptest stub upstream on 127.0.0.1:0, and asserts incremental SSE delivery (second stub frame withheld on a channel — no timer — so a buffering artifact deadlocks and must fail). 3. Require a falsification proof in the same commit: sabotage → test fails → revert → green. 4. Add a make test-e2e target (plus ci: test test-e2e) so the suite is greppable and CI-discoverable.

Verification — a table of 8 checks plus acceptance criteria (re-submit same sha-scope).

Empirical verification performed here

I extracted the document's Go test into a temp module against a minimal real proxy that forwards /stream:

gofmt clean / go vet clean
green    : --- PASS: TestProxyDeliversUpstreamSSE (0.37s)
sabotage : --- FAIL: TestProxyDeliversUpstreamSSE (30.03s)
           request real proxy: context deadline exceeded
revert   : --- PASS: TestProxyDeliversUpstreamSSE (0.43s)

A key correction I made during verification: an earlier draft's stub used case <-time.After(5*time.Second), which let a buffering proxy pass by racing the 5s read deadline. The final test removes that timer so falsification is deterministic; the doc calls out this weak variant explicitly.
