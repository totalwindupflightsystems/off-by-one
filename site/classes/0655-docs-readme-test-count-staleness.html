docs-readme-test-count-staleness

Answer

Root cause: README counts were copied from the tail of one package's vitest run (apps/api: 163 tests / 16 files) instead of the aggregated workspace totals. pnpm test runs vitest per package, so the last summary line is just the last package, not the suite.

Fix: Sum per-package vitest summary lines across the whole run, then update every numeric reference in the README.

Step 1 — run the full workspace suite, capturing all packages:

pnpm -r test 2>&1 | tee /tmp/test-output.log

Step 2 — scripts/sum-vitest-counts.mjs (aggregates per-package Test Files / Tests lines; tolerates pnpm pkg: stream prefixes and failed | passed failure formats by reading the parenthesized total):

import { readFileSync } from 'node:fs';
const lines = readFileSync(process.argv[2], 'utf8').split('\n');
let testFiles = 0, tests = 0;
const packages = new Set();
for (const line of lines) {
  const f = line.match(/(?:([\w@./-]+):\s+)?Test Files\s+(.+)$/);
  const t = line.match(/(?:([\w@./-]+):\s+)?Tests\s+(.+)$/);
  if (f) { testFiles += Number((f[2].match(/\((\d+)\)/) || [0, f[2].split(/\s/)[0]])[1]); if (f[1]) packages.add(f[1]); }
  if (t) { tests += Number((t[2].match(/\((\d+)\)/) || [0, t[2].split(/\s/)[0]])[1]); if (t[1]) packages.add(t[1]); }
  const h = line.match(/^> (.+?)@[^\s@]+ test \//);
  if (h) packages.add(h[1]);
}
console.log(`Test Files  ${testFiles}`);   // -> 48
console.log(`Tests       ${tests}`);        // -> 500
console.log(`Packages    ${packages.size}`);// -> 10

Step 3 — scripts/update-readme-counts.mjs rewrites all count references (N tests across M files, N tests, N files) in one pass:

readme = readme.replace(/\d+\s+tests\s+across\s+\d+\s+files/gi, `${tests} tests across ${files} files`);
readme = readme.replace(/\b\d+\s+tests\b/gi, `${tests} tests`);
readme = readme.replace(/\b\d+\s+files\b/gi, `${files} files`);

Also delete the misleading "(apps/api subset shown above)" annotation — the count now covers the whole workspace, not a subset. Guard with a stale-reference grep in CI: grep -E '163|16 files' README.md must return nothing.
