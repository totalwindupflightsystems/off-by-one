What I found and verified

Root cause: The workflow conflates the Go module path with the GitHub repo host path. actions/checkout's repository: expects OWNER/REPO, but the workflow used wojons/consensus — which is only the module name declared in go.mod, not a real repository.

Identity Value
Go module path github.com/wojons/consensus
Real repo host path github.com/totalwindupflightsystems/consensus
Branch / HEAD master / 576dc076c9c3db113c8fd66edea50345583b6205

Evidence collected by actually running the probes: - git ls-remote --heads https://github.com/wojons/consensus → exit 128, could not read Username (repo doesn't exist) - git ls-remote --heads https://github.com/totalwindupflightsystems/consensus → exit 0, refs/heads/master - Go itself reproduces the failure: go mod tidy runs the same git ls-remote against the module path and dies with exit 128 - A local-path replace github.com/wojons/consensus => /tmp/consensus-real builds and resolves fine (Go validates the replacement against the import path, so host/module mismatch is irrelevant) - After using the correct checkout: all internal/* + pkg/* tests pass; only demo fails — a pre-existing, unrelated TestSmokeKeyless failure (mock LLM returns HTTP 400 "model ambiguous"), now visible because checkout no longer masks it - The pre-push guard script returns OK/exit 0 for the real repo and FAIL/exit 1 for the bogus one (tested both directions)

The fix: change repository: wojons/consensus → repository: totalwindupflightsystems/consensus, keep the replace github.com/wojons/consensus => ../consensus unchanged (do not rewrite imports), and add the git ls-remote --exit-code --heads guard as a pre-push/CI step.
