Layout (/home/kara/infra-smoke-test-idle-tick/): - fleet-cooldown-policy.py — single authoritative policy source - scheduler_idle_tick.sh — the idle tick (discovery + audit + clean commit) - smoke_test.sh — 17-assertion end-to-end verification - jobs/ — empty (repo has zero source files) - board.json — fixture board + tick audit records

1. The policy — fleet-cooldown-policy.py audits board entries. Any status that is not explicitly terminal (done/succeeded/failed/cancelled) counts as pending → 900s cooldown → PUT forbidden. --dry-run emits the decision and provably performs zero network I/O:

TERMINAL_STATUSES = {"done", "succeeded", "failed", "cancelled"}

def audit(board):
    per_entry, pending = [], 0
    for e in board.get("entries", []):
        is_pending = e.get("status") not in TERMINAL_STATUSES  # missing/unknown -> pending
        if is_pending:
            pending += 1
            per_entry.append({"id": e.get("id"), "status": e.get("status"),
                              "cooldown_s": COOLDOWN_PENDING_SECONDS})
        else:
            per_entry.append({"id": e.get("id"), "status": e.get("status"), "cooldown_s": 0})
    return {"pending": pending,
            "cooldown_s": COOLDOWN_PENDING_SECONDS if pending else 0,
            "allowed": pending == 0, "entries": per_entry}

# main: --dry-run prints {"pending":1,"cooldown_s":900,"allowed":false,"put":null} and exits 0.
# (non-dry-run PUTs to $FLEET_URL only when allowed; returns 1 during cooldown)

2. The idle tick — chains the three mandated steps; it never starts worker/guard/judge:

# 1) discovery sweep — repo has zero source files, so jobs/ is empty
DISCOVERED="$(find jobs -type f \( -name '*.yaml' -o -name '*.yml' \) 2>/dev/null || true)"
[ -n "$DISCOVERED" ] || log "discovery: nothing found (repo has zero source files)"

# 2) cooldown policy audit — authoritative via --dry-run, not board prose
AUDIT_OUT="$(./fleet-cooldown-policy.py --dry-run --board board.json)"
PENDING="$(printf '%s' "$AUDIT_OUT" | python3 -c 'import json,sys;print(json.load(sys.stdin)["pending"])')"
COOLDOWN="$(printf '%s' "$AUDIT_OUT" | python3 -c 'import json,sys;print(json.load(sys.stdin)["cooldown_s"])')"
# pending>0 -> "cooldown 900s, NO PUT issued"

# 3) clean board entry — append audit record (status:"done") and commit
git add board.json && git commit -m "board: idle tick audit (pending=${PENDING}, cooldown=${COOLDOWN}s, no PUT)"
git status --porcelain   # -> empty => "tree clean = yes"

3. Key invariants enforced: - --dry-run never PUTs — proven with a live counting HTTP server on FLEET_URL (zero requests received). - Audit records are committed with status:"done" so they don't inflate the pending count (fixture stays pending=1 across ticks). - Harness artifacts (.tick.log, .tick.status, .tick.out) are gitignored and a baseline commit exists, so the post-commit "clean tree" assertion is meaningful. - Verification comes from the policy script's JSON output, never from prose on the board.
