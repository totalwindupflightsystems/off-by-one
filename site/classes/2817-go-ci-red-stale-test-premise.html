Fix: "Test (short mode)" red on main from stale test premises (INT-CI-4)

Verdict

No product bug. Two independent, legitimate product commits (TRBL-107, TRBL-104/TRBL-105) invalidated premises that three tests had frozen in. The correct fix is test-side only (2 files, no product code): assert the spec-true invariants instead of the pre-change totals/refusal semantics.

Repo: github.com/trouble-agent/trouble · Red tree: 84fbdde · Reference fix: e880298 · Spec: specs/SPEC-01-ledger.md#2.4, docs/operations.md#2 + #3.

Symptom

--- FAIL: TestInteriorCorruption: Entries = 6, want 5
--- FAIL: TestLedgerStatusOkAndWriterLiveDegradedSpec01Section24: status with live writer exit = 0, want 1
--- FAIL: TestLedgerVerifyExitCodesSpec01Section24: verify with live writer exit = 1, want 2

Root-cause analysis

Instance 1 — TestInteriorCorruption (internal/ledger)

The boot index build indexes one more record now. TRBL-107 (a970d1e) began writing the documented hole-audit record. docs/operations.md §3:

Hole in seq: reported as TROUBLE-LEDGER-002 on the next read and written into the trail by the next successful batch as lifecycle{op:"hole", from, to}.

The test pinned the pre-feature total (4 well-formed fixture records + 1 boot record = 5). The new record makes it 6. Nothing is broken.

In-package probe on an isolated tree dumps the artifact — seq 6 (and 7) prove the extra record is the spec-required one:

{"seq":6,...,"kind":"lifecycle",...,"payload":{"from":3,"op":"hole","to":3}}
{"seq":7,...,"kind":"lifecycle",...,"payload":{"day":"2026-09-16","file":"2026-09-16.jsonl","last_seq":5,"op":"boot"}}

So: 4 fixture + 1 hole + 1 boot = 6.

Instance 2 — live-writer rows (cmd/trouble)

TRBL-104 (7e2a176) / TRBL-105 (1b00cfa) made ledger status/ledger verify true read-only walks. SPEC-01 §2.4:

trouble ledger verify [--day D] | read-only walk … opens no lock | 0 ok, 1 findings, 2 unreadable

docs/operations.md §2:

trouble ledger verify opens no lock: it is always safe to run against a live ledger.

The tests still asserted the old refusal semantics (--writer-live → exit 1, --writer-live → exit 2), i.e. CheckWriterHeld(). A live writer is not a refusal anymore: status returns exit 0 with real numbers and the real writer_pid; verify still walks and returns its findings. §2.4's 1 degraded row is the index-degraded condition (index.degraded=true, reason seq_gaps_detected); its 2 unreadable row is a genuinely unreadable ledger (TROUBLE-LEDGER-012).

Transferable rules

  1. Prove the premise, not the symptom. git worktree add --detach <suspect>^ + run the failing test there. PASS-at-parent + FAIL-at-HEAD pins the culprit commit.
  2. Read the owning spec/doc and quote it before deciding which side is wrong — the grep is what turns "the test is red" into "the test is wrong".
  3. Dump the artifact with a throwaway in-package probe in an isolated worktree; never reason about counts from memory.
  4. Never weaken an assertion or delete a spec-required artefact. Replace frozen totals with spec-true invariants.
  5. Rename tests and comments that state the old contract, or the next reader re-derives the wrong thing.
