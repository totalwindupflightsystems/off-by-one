Fix: Tier-2 judge must re-run the operational probe, not quote a cross-repo board row

Task: qa-crier-12 Tick: crier-2026-09-20-02-53-43 Bad verdict: 53a6b62a (INCOMPLETE) Deliverable under test: operational change on a remote host (deployed binary), reached over ssh.

1. Symptom

The judged diff was a 9-line tasks.yaml status flip — it could never carry proof of the remote criterion. The Tier-2 judge then resolved the remote criterion (deployed-binary-version on the crier host) by reading a board row that lived in a different repo and quoted a probe taken before the deploy. That row was consumed as authoritative and the verdict came back INCOMPLETE — even though the judge's own probe agents had already produced journalctl lines on the target host showing the criterion satisfied.

2. Root-cause analysis

Four independent defects combine into the false negative:

  1. Evidence precedence is wrong. A board citation outranks a fresh first-party probe. There is no rule that a quote is only usable when it is (a) from the same repo/namespace and (b) newer than the deploy it claims to attest. A foreign, pre-deploy row is accepted verbatim.
  2. Evaluator artifacts are invisible to the criterion. Probe transcripts the judge itself generated on the remote host are treated as scratch output, not as evidence, and are dropped when the verdict is written.
  3. No committable local evidence. Because the remote transcript lives only in the judge's ephemeral process, the local diff has nothing to grade. Any later pass (or audit) re-derives the criterion from the board and re-hits the stale row.
  4. No source correction. After the false negative the stale row was left in place, so the same bad citation is available to every subsequent tick.

The recovery invariant is simple:

A criterion is decided by re-running its own declared probe at verdict time against the operational target; board rows are hints at most, and only first-party, post-deploy hints. The transcript of that run is committed so the verdict has local material. If a cited row is proven stale, the row is corrected in the same tick.

3. The fix

3.1 Declare the probe with the criterion

{
  "task": "qa-crier-12",
  "tick": "crier-2026-09-20-02-53-43",
  "repo": "crier",
  "namespace": "qa",
  "criteria": [
    {
      "id": "deployed-binary-version",
      "probe": "ssh deploy@crier-host \"journalctl -u qa-crier --since '2026-09-20 02:45:00' -o cat | grep -m1 'version='\"",
      "expect": "version=1\\.2\\.3",
      "timeout_s": 20,
      "deploy_at": "2026-09-20T02:45:00Z"
    }
  ]
}

3.2 Judge evidence precedence

for each criterion:
    fresh := run criterion.probe now, capture combined stdout+stderr
    write transcript + hash to evidence/<tick>/        # committable artifact
    if fresh matches criterion.expect: SATISFIED       # first-party probe wins
    else if a board row exists:
        usable := row.repo == task.repo
              && row.namespace == task.namespace
              && row.probe_at >= row.deploy_at
        if usable: score row            # only now may a quote be considered
        else: mark row stale; do NOT score it
verdict = SATISFIED only if every criterion satisfied

3.3 Commit the evidence in the same tick

git add evidence/crier-2026-09-20-02-53-43 tasks.yaml
git commit -m "qa-crier-12: deploy verified + tier2 probe evidence"

3.4 Correct the stale source row

boardctl event --type audit --task-id crier-ops-008 --actor foreman \
  --detail-text "superseded: stale cross-repo board evidence used by a Tier-2 verdict (foreign-repo); re-probe from crier/qa at tick time"

4. Exact implementation: tier2probe

Stdlib-only Go (full source at /home/kara/solution/tier2probe/main.go). Two subcommands: run re-probes and emits committable evidence; stale refuses/corrects non-first-party or pre-deploy rows. The build is go build -o tier2probe ./tier2probe.

3 Foreign/pre-deploy quotes refused tier2probe stale -row stale-row.json UNUSABLE ... foreign-repo + correction command
4 False negatives still honest criteria-bad.json exit 1, INCOMPLETE

6. Operational checklist for the on-call tick

  1. Put the probe, expect, and deploy_at on every operational criterion.
  2. Run tier2probe run before forming the verdict; ignore any board quote until the row passes tier2probe stale.
  3. git add evidence/<tick> with the change; never commit a status flip with no transcript.
  4. On any false negative, run tier2probe stale -apply on the cited row so the stale evidence is retired, then re-issue the verdict.

Key result: the four failure modes each map to one concrete mechanism — fresh first-party probe precedence, transcript-as-evidence, same-tick evidence commit, and stale-row retirement — and all four are verified by the commands above.
