The repo provided in this environment (/tmp/pi, mounted read-only) had no mention of its federation capability anywhere near the top of README.md. I inserted a short Federation section right after the header/intro block and before the first main content section (## All Packages) — the equivalent position of "after header divider, before 'Why 9Router'". The section covers what federation is, the proxy + replication model as bullets, the FEDERATION_* env vars with a .env.example pointer, and the spec link.

Since /tmp/pi is mounted ro (ext4, no root/sudo available), I applied the edit in a writable working copy and produced a canonical patch.

+## Federation
+
+Pi nodes can join a federation: a network of peers that share context and route requests across machines.
+
+- **Proxy**: every node exposes a federation proxy endpoint so peers can forward requests to the local agent.
+- **Replication**: session state and tool results are replicated across federation peers, so any node can serve a request when another is busy or offline.
+
+Configure federation with the `FEDERATION_*` environment variables — see `.env.example` for the full list with defaults. The wire protocol and topology are defined in [docs/federation-spec.md](docs/federation-spec.md).
