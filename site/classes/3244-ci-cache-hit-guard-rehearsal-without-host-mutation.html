Rehearsing a "restore cache first, install only on miss" CI change without host mutation

Problem class: ci-cache-hit-guard-rehearsal-without-host-mutation Environment: GitHub Actions, ubuntu-latest jobs + one busy self-hosted runner, actionlint locally.

1. What is actually being proven

A production CI change does two things:

  1. Restore the tool cache first, using the real cache key.
  2. Install the external tool (and run generation) only on a cache miss, guarded by if: steps.<cache>.outputs.cache-hit != 'true'.

The change is only safe if both arms hold:

  • Hit → restore succeeds, the download is never attempted, job is green even if the download host is unreachable.
  • Miss → the install step actually runs, and if the download is down it fails loudly (a miss can never silently pass). With the download up, the tool is on PATH and generation produces files (end-to-end still works).

The real pipeline, on a warm cache, only ever exercises the miss arm. There is no natural hit+download-down run, so the guard is effectively unproven.

2. Root-cause analysis

  • The real path only exercises a cache miss. A cold branch populates the cache; later runs hit it but with the download up, so they never test the "hit while the download is down" property that the guard exists to provide.
  • Host mutation was the obvious lever, and it is the wrong one. Editing /etc/hosts on a runner to sinkhole the release host is a privileged host change; it hits a consent gate and is not reproducible. The same unreachability can be produced inside the job with HTTPS_PROXY/HTTP_PROXY=http://<ip-address>:9 (localhost discard port, nothing listens).
  • The proxy must be set per step, not job- or workflow-wide. actions/cache also talks to a network service (the GitHub cache backend). A job-level proxy would break the restore and turn the intended hit into a miss, invalidating the rehearsal. Scope the proxy to the download/install steps only.
  • A run-unique key guarantees a miss. key: proto-gen-rehearsal-live-${{ github.run_id }} can never have been written, so a partial/pre-existing cache can never be restored and silently turn the miss arm into a hit.
  • The self-hosted runner traps run-level status. While any self-hosted job is waiting for the busy runner, the whole run stays queued even after the ubuntu-latest jobs are green. Never judge a run by its top-level status: read the per-job and per-step tables. Cancel throwaway runs so they stop occupying the queue.
  • Rehearsals must not pollute the real cache. Use actions/cache/restore@v4 (restore-only, no post-save) in the arms, and seed the real key idempotently with lookup-only: true on a throwaway branch so the cache is branch-scoped.

3. The fix

3.1 Put the rehearsal on a throwaway branch that is never merged

branch="rehearsal/cache-hit-guard-$(date +%Y%m%d%H%M)"
git switch -c "$branch"
# add the two files from 3.2 and 3.4, then:
git add .github/workflows/cache-hit-guard-rehearsal.yml scripts/ci-rehearsal-evidence.sh
git commit -m "ci: throwaway rehearsals for cache-hit guard"
git push -u origin "$branch"

Because the rehearsal lives in its own workflow file triggered only by workflow_dispatch or push on rehearsal/cache-hit-guard-*, it can never run on the self-hosted runner used by the real pipeline.

3.2 .github/workflows/cache-hit-guard-rehearsal.yml

Substitute the tool/URLs/paths for the real one where noted (this uses protoc as a self-contained concrete example).

name: cache-hit-guard-rehearsal

# Throwaway rehearsal workflow. NEVER merge to the default branch.
# Only manual dispatch or the throwaway branch, so it can never contend with
# the busy self-hosted runner that the real pipeline uses.
on:
  workflow_dispatch:
  push:
    branches:
      - "rehearsal/cache-hit-guard-*"

permissions:
  contents: read

env:
  PROTOC_VERSION: "25.3"
  TOOL_ROOT: ${{ github.workspace }}/.toolcache
  TOOL_BIN: ${{ github.workspace }}/.toolcache/bin
  # localhost discard port: nothing listens, so any real download fails fast.
  # Set PER STEP, never job/workflow wide, so actions/cache can still reach
  # the GitHub cache service while the download is unreachable.
  DEAD_PROXY: http://<ip-address>:9

jobs:
  # ------------------------------------------------------------------ seed ---
  # Idempotently make a real-key cache EXIST. Runs on the throwaway branch, so
  # the cache is branch-scoped and can never poison main's real cache.
  seed-real-key:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Probe real-key cache (lookup only, no download)
        id: probe
        uses: actions/cache/restore@v4
        with:
          path: ${{ env.TOOL_ROOT }}
          key: protoc-${{ runner.os }}-${{ env.PROTOC_VERSION }}
          lookup-only: true

      - name: Install tool (only if cache missing)
        if: steps.probe.outputs.cache-hit != 'true'
        run: |
          set -euo pipefail
          url="https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/protoc-${PROTOC_VERSION}-linux-x86_64.zip"
          mkdir -p "$TOOL_ROOT" "$TOOL_BIN"
          curl -fsS --max-time 120 -o /tmp/protoc.zip "$url"
          unzip -o -q /tmp/protoc.zip -d "$TOOL_BIN"
          chmod +x "$TOOL_BIN/protoc"

      - name: Save real-key cache (only if it was missing)
        if: steps.probe.outputs.cache-hit != 'true'
        uses: actions/cache/save@v4
        with:
          path: ${{ env.TOOL_ROOT }}
          key: protoc-${{ runner.os }}-${{ env.PROTOC_VERSION }}

  # --------------------------------------------------------------- ARM A -----
  # HIT + download DOWN. Must stay GREEN because the guarded steps are skipped.
  arm-a-hit-download-down:
    needs: seed-real-key
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Restore cache with the real key
        id: cache
        uses: actions/cache/restore@v4
        with:
          path: ${{ env.TOOL_ROOT }}
          key: protoc-${{ runner.os }}-${{ env.PROTOC_VERSION }}

      - name: "Assert Arm A precondition: real-key HIT"
        run: |
          set -euo pipefail
          test "${{ steps.cache.outputs.cache-hit }}" = "true" || {
            echo "::error::Arm A invalid: expected a cache HIT on the real key."
            exit 1
          }

      - name: Assert download is DOWN via dead proxy
        env:
          HTTPS_PROXY: ${{ env.DEAD_PROXY }}
          HTTP_PROXY: ${{ env.DEAD_PROXY }}
        run: |
          set -uo pipefail
          url="https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/protoc-${PROTOC_VERSION}-linux-x86_64.zip"
          if curl -fsS --max-time 15 -o /dev/null "$url"; then
            echo "::error::Arm A invalid: download unexpectedly succeeded through the dead proxy."
            exit 1
          fi
          echo "OK: download unreachable through ${DEAD_PROXY}."

      - name: "Install tool (guarded: skipped on hit)"
        id: install
        if: steps.cache.outputs.cache-hit != 'true'
        env:
          HTTPS_PROXY: ${{ env.DEAD_PROXY }}
          HTTP_PROXY: ${{ env.DEAD_PROXY }}
        run: |
          set -euo pipefail
          url="https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/protoc-${PROTOC_VERSION}-linux-x86_64.zip"
          mkdir -p "$TOOL_ROOT" "$TOOL_BIN"
          curl -fsS --max-time 60 -o /tmp/protoc.zip "$url"
          unzip -o -q /tmp/protoc.zip -d "$TOOL_BIN"
          chmod +x "$TOOL_BIN/protoc"

      - name: "Generate code (guarded: skipped on hit)"
        id: generate
        if: steps.cache.outputs.cache-hit != 'true'
        run: |
          set -euo pipefail
          "$TOOL_BIN/protoc" --version

      - name: Assert install+generate were SKIPPED (no download attempted)
        run: |
          set -euo pipefail
          test "${{ steps.install.outcome }}" = "skipped" || {
            echo "::error::Arm A invalid: install outcome '${{ steps.install.outcome }}', expected 'skipped'."
            exit 1
          }
          test "${{ steps.generate.outcome }}" = "skipped" || {
            echo "::error::Arm A invalid: generate outcome '${{ steps.generate.outcome }}', expected 'skipped'."
            exit 1
          }
          echo "OK: hit path skipped install+generate; green with download down."

  # --------------------------------------------------------------- ARM B -----
  # MISS + download DOWN. Install must RUN and FAIL LOUDLY, then the harness
  # asserts that failure. A miss can never silently pass.
  arm-b-miss-download-down:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Restore cache with run-unique key (forced MISS)
        id: cache
        uses: actions/cache/restore@v4
        with:
          path: ${{ env.TOOL_ROOT }}
          key: proto-gen-rehearsal-live-${{ github.run_id }}

      - name: "Assert Arm B precondition: MISS"
        run: |
          set -euo pipefail
          test "${{ steps.cache.outputs.cache-hit }}" != "true" || {
            echo "::error::Arm B invalid: the run-unique key unexpectedly HIT."
            exit 1
          }

      - name: Assert download is DOWN via dead proxy
        env:
          HTTPS_PROXY: ${{ env.DEAD_PROXY }}
          HTTP_PROXY: ${{ env.DEAD_PROXY }}
        run: |
          set -uo pipefail
          url="https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/protoc-${PROTOC_VERSION}-linux-x86_64.zip"
          if curl -fsS --max-time 15 -o /dev/null "$url"; then
            echo "::error::Arm B invalid: download unexpectedly succeeded through the dead proxy."
            exit 1
          fi

      - name: Install tool (must RUN and FAIL)
        id: install
        continue-on-error: true
        env:
          HTTPS_PROXY: ${{ env.DEAD_PROXY }}
          HTTP_PROXY: ${{ env.DEAD_PROXY }}
        run: |
          set -euo pipefail
          url="https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/protoc-${PROTOC_VERSION}-linux-x86_64.zip"
          mkdir -p "$TOOL_ROOT" "$TOOL_BIN"
          curl -fsS --max-time 20 -o /tmp/protoc.zip "$url"
          unzip -o -q /tmp/protoc.zip -d "$TOOL_BIN"
          chmod +x "$TOOL_BIN/protoc"

      - name: Assert install RAN and FAILED loudly on miss
        run: |
          set -euo pipefail
          test "${{ steps.install.outcome }}" = "failure" || {
            echo "::error::Arm B invalid: install outcome '${{ steps.install.outcome }}', expected 'failure'."
            echo "A miss must never silently pass."
            exit 1
          }
          echo "OK: miss path attempted the download and failed; failure is not swallowed."

  # --------------------------------------------------------------- ARM C -----
  # MISS + download UP. End-to-end: tool lands on PATH, generation writes files.
  arm-c-miss-download-up:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Restore cache with run-unique key (forced MISS)
        id: cache
        uses: actions/cache/restore@v4
        with:
          path: ${{ env.TOOL_ROOT }}
          key: proto-gen-rehearsal-live-${{ github.run_id }}

      - name: "Assert Arm C precondition: MISS"
        run: |
          set -euo pipefail
          test "${{ steps.cache.outputs.cache-hit }}" != "true" || {
            echo "::error::Arm C invalid: the run-unique key unexpectedly HIT."
            exit 1
          }

      - name: Prepare a self-contained proto
        run: |
          set -euo pipefail
          mkdir -p proto
          printf 'syntax = "proto3";\npackage rehearsal;\nmessage Ping { string msg = 1; }\n' > proto/rehearsal.proto

      - name: Install tool (guarded; runs because of MISS)
        id: install
        if: steps.cache.outputs.cache-hit != 'true'
        run: |
          set -euo pipefail
          url="https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/protoc-${PROTOC_VERSION}-linux-x86_64.zip"
          mkdir -p "$TOOL_ROOT" "$TOOL_BIN"
          curl -fsS --max-time 120 -o /tmp/protoc.zip "$url"
          unzip -o -q /tmp/protoc.zip -d "$TOOL_BIN"
          chmod +x "$TOOL_BIN/protoc"

      - name: Generate code (guarded; runs because of MISS)
        id: generate
        if: steps.cache.outputs.cache-hit != 'true'
        run: |
          set -euo pipefail
          mkdir -p gen
          "$TOOL_BIN/protoc" -I proto --python_out=gen proto/rehearsal.proto

      - name: Assert tool on PATH and generation produced output
        run: |
          set -euo pipefail
          echo "$TOOL_BIN" >> "$GITHUB_PATH"
          export PATH="$TOOL_BIN:$PATH"
          command -v protoc
          protoc --version
          files="$(find gen -type f -name '*_pb2.py')"
          test -n "$files" || { echo "::error::Arm C invalid: generation produced no files."; exit 1; }
          echo "Generated:"; echo "$files"

Key design points (the actual fix):

  • Restore is separate and unguarded; only install/generate carry if: steps.cache.outputs.cache-hit != 'true'.
  • Dead proxy is step-scoped, applied only where a download could happen.
  • actions/cache/restore@v4 (restore-only) in the arms — no post-job save, so no cache pollution; the run-unique key is a guaranteed miss.
  • seed-real-key is idempotent via lookup-only: true, so Arm A always has a real-key hit on the throwaway branch.
  • Negative test is self-checking: Arm B captures the expected install failure with continue-on-error: true and then asserts steps.install.outcome == 'failure'. The job is green only when the miss arm failed exactly as required.

3.4 scripts/ci-rehearsal-evidence.sh (evidence collector)

#!/usr/bin/env bash
# Works around the self-hosted trap: never trust run-level status.
set -euo pipefail

REPO="${REPO:-$(gh repo view --json nameWithOwner -q .nameWithOwner)}"
WORKFLOW="${WORKFLOW:-ci.yml}"
INSTALL_JOB="${INSTALL_JOB:-build}"
BRANCH="${BRANCH:-main}"

run_id="${1:-}"
if [[ -z "$run_id" ]]; then
  run_id="$(gh run list --repo "$REPO" --branch "$BRANCH" --workflow "$WORKFLOW" \
              --limit 1 --json databaseId -q '.[0].databaseId')"
fi

echo "== run $run_id  repo=$REPO  branch=$BRANCH =="

echo
echo "-- per-JOB status (ignore the run-level rollup) --"
gh api "repos/$REPO/actions/runs/$run_id/jobs" \
  --jq '.jobs[] | "JOB \(.name): status=\(.status) conclusion=\(.conclusion)"'

echo
echo "-- per-STEP table for job '$INSTALL_JOB' --"
gh api "repos/$REPO/actions/runs/$run_id/jobs" \
  --jq ".jobs[] | select(.name==\"$INSTALL_JOB\") | [.steps[] | \"\(.number). \(.name) -> \(.conclusion)\"] | .[]"

5. Why this is correct / pitfalls

  • No privileged host mutation: unreachability comes from HTTPS_PROXY/HTTP_PROXY env inside the job, not /etc/hosts.
  • The proxy never touches the restore: step-scoping keeps actions/cache able to reach the cache service; otherwise Arm A would miss and the rehearsal would be vacuous.
  • The miss is real: ${{ github.run_id }} makes the key unguessable and un-writable ahead of time, so a partial cache can never restore.
  • The negative arm is enforced, not observed: continue-on-error + outcome == 'failure' fails the job if the install did not fail, so the miss arm cannot silently pass.
  • Cache hygiene: restore-only in the arms + branch-scoped idempotent seed means no rehearsal key and no throwaway cache leaks into main.
