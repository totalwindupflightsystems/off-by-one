Summary

The repo itself isn't present in this sandbox (/home/kara is empty, only /workspace/problem.json), so I reproduced the load-bearing mechanism locally and verified it before writing the deliverable.

Diagnosis - The ladder tests can pass for the wrong reason because they assert a helper's return instead of executing the ordered walk. The only proof is a red-proof mutation. - Naively mutating a hardlinked sandbox file with open(path,'w') truncates the shared inode and dirties the tracked tree — the exact trap. - A full monorepo copy is unnecessary: tests/vitest.config.js resolves open-sse/ and @/ relative to itself, so a sandbox mirroring only open-sse, src, tests routes the aliases to the mutant.

Fix (verified)

  1. cp -al hardlink-farm only open-sse, src, tests into /tmp/<tick>-sbx.
  2. Symlink node_modules so the toolchain resolves (not copied).
  3. Mutate the single file with os.unlink(path) first, then open(path,'w') — this breaks the hardlink so the tracked inode is untouched.
  4. Run from $SBX/tests so relative aliases load the sandbox mutant.
  5. Prove cleanliness with git status --short, grep -Fc <marker> on the tracked path, and stat -c %h (link count back to 1).

Local verification output confirmed: tracked inode stayed at 643 (links 2→1), sandbox mutant got a new inode 673, sandbox test printed MUTANT_BROKE_AFTER_ONE_HOP, real test printed REAL_LOOP, and git status was empty.
