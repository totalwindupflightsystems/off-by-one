Fix: Requeue Pending tool_requests on Session Claim Expiry

Problem class: session-claim-expiry-requeue · Repo: consensus (Go agent harness) Files: internal/harness/executor.go (production), internal/harness/session_claim_lease_test.go (regression) Observed: 98fe6197 · Fixed: 10475804

Symptom: after ClaimVisibilityTimeout elapses on a planning/tool_exec session, the session parks at paused forever and the model's tool call never completes. Detection signal: status=tool_exec at every poll with repeated session already claimed by another worker, bailing out, then a hard transition to paused once the lease fires.

1. Root-cause analysis

A session has two pieces of state that must move together when a claim dies: the session claim (sessions.claimed_by/claimed_at/lease_expires_at/status) and the work it pulled (tool_requests rows it set to executing). The reaper's claim-expiry recovery resets the session but never touches tool_requests, so the recovery path is missing its last hops:

expired claim -> reset session            [present, insufficient]
             -> requeue pending tool_requests   [MISSING]
             -> wake/resume the dispatcher       [MISSING]
             -> executor re-claims and runs
             -> turn completes

A re-claiming worker queries WHERE session_id=S AND status='pending', finds nothing (the row is still executing), treats the turn as terminal, and parks S at paused. The requeue is needed for data correctness; the wake is needed so it doesn't wait a poll tick (and slip to paused first).

2. The exact fix

(a) In recoverExpiredClaim — requeue before release, wake after commit:

func (e *Executor) recoverExpiredClaim(ctx context.Context, sessionID string) error {
    recovered, err := e.store.RecoverExpiredClaim(ctx, sessionID, e.clock.Now())
    if err != nil {
        return fmt.Errorf("recover expired claim for session %s: %w", sessionID, err)
    }
    if !recovered {
        return nil // lease renewed / another reaper won; do not double-requeue
    }
    e.scheduler.Wake(sessionID) // same path used when a tool_request is inserted
    return nil
}

Minimal in-place form if recovery is a bare UPDATE sessions:

_, err = e.db.ExecContext(ctx, `
    UPDATE tool_requests
       SET status = 'pending', claimed_at = NULL
     WHERE session_id = $1 AND status = 'executing'
`, sessionID)
if err != nil { return err }
e.scheduler.Wake(sessionID)

(b) Store helper — requeue in the same transaction, behind a lease CAS (idempotent, race-safe):

func (s *Store) RecoverExpiredClaim(ctx context.Context, sessionID string, now time.Time) (bool, error) {
    tx, err := s.db.BeginTx(ctx, nil)
    if err != nil { return false, err }
    defer tx.Rollback()

    res, err := tx.ExecContext(ctx, `
        UPDATE sessions
           SET status='thinking', claimed_by=NULL, claimed_at=NULL,
               lease_expires_at=NULL, updated_at=now()
         WHERE id=$1 AND status='tool_exec'
           AND lease_expires_at IS NOT NULL AND lease_expires_at < $2
    `, sessionID, now)
    if err != nil { return false, err }
    n, _ := res.RowsAffected()
    if n == 0 { return false, nil }

    if _, err := tx.ExecContext(ctx, `
        UPDATE tool_requests
           SET status='pending', claimed_at=NULL
         WHERE session_id=$1 AND status='executing'
    `, sessionID); err != nil { return false, err }

    return true, tx.Commit()
}

(c) Defense-in-depth: in the turn loop, a tool_exec session with zero pending and zero executing tool rows should reset to planning and wake, never park at paused.

3. Regression test

func TestSessionClaimLeaseRequeuesToolRequests(t *testing.T) {
    ctx := context.Background()
    st := newTestStore(t)
    sched := newSpyScheduler()
    ex := NewExecutorWithStore(st, sched)

    st.SeedSession(t, "sess-claim-lease", StatusToolExec)
    st.SeedToolRequest(t, "tr-1", "sess-claim-lease", StatusExecuting, time.Now().Add(-time.Minute))
    st.ForceClaimExpiry(t, "sess-claim-lease", time.Now().Add(-time.Second))

    if err := ex.recoverExpiredClaim(ctx, "sess-claim-lease"); err != nil {
        t.Fatalf("recoverExpiredClaim: %v", err)
    }
    tr := st.GetToolRequest(t, "tr-1")
    if tr.Status != StatusPending {
        t.Fatalf("recovered tool_request status = %s, want %s", tr.Status, StatusPending)
    }
    if tr.ClaimedAt != nil {
        t.Fatalf("recovered tool_request claimed_at = %v, want nil", tr.ClaimedAt)
    }
    if !sched.wasWoken("sess-claim-lease") {
        t.Fatalf("scheduler was not woken")
    }
}

Live check: before fix → thinking -> planning -> tool_exec then repeated claim-bail lines then paused (~8.5 min repro); after fix → thinking -> planning -> tool_exec -> idle, one claim bail, no paused.

Review invariants: requeue scoped to executing only; reset+requeue in one transaction behind the lease CAS; wake emitted only when recovery actually happened; wake reuses the existing new-tool-request notification path.

Note: the test/helper identifiers (newTestStore, SeedToolRequest, newSpyScheduler, NewExecutorWithStore, e.clock, e.scheduler.Wake) are placeholders that must be bound to the repo's existing test/executor helpers — the production logic that matters is the transaction and the status='executing' → 'pending' requeue plus the wake.
