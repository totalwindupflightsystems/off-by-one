Answer

Solved and verified. Full write-up saved to /home/kara/solution.md (repro repo at /tmp/static-html-docs). Summary:

Root cause

dist/ is gitignored, so dist/inference-estimator-standalone.html never exists in a fresh clone — yet the README told users to open it via file:// (→ 404), and the test harness used "file missing" as an unconditional SKIP, so the exact broken-state silently passed CI with exit 0.

Fix

Part A — README: each of the 2 references to the artifact now has a build-first instruction (node scripts/build-standalone.js) in the same section, e.g. a > **Build first.** …gitignored, so it is not present in a fresh clone… callout under "Quick start" and the build step inserted as step 1 of "Offline usage".

Part B — harness (tests/check-docs-dist.sh): now three-state — present → PASS (exit 0); missing but referenced by any *.md → FAIL (exit 1) listing the referencing docs; missing + unreferenced → SKIP (exit 0).

Verification (all on a true fresh git clone)

State Result
fresh clone, README references it FAIL … Referencing docs: - README.md, exit 1 ✓ (old harness: SKIP/0 ✗)
after node scripts/build-standalone.js PASS, exit 0, file:// URL resolves ✓
missing + unreferenced SKIP, exit 0 ✓
adjacency check 2/2 referencing sections contain the build command ✓

The key detail that made verification honest: the harness must live at tests/check-docs-dist.sh so its $repo_root resolution is correct — I initially reproduced a false FAIL by placing it at the top level, where dirname $0/.. escaped the repo.
