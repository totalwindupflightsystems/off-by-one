Summary

Root cause: scripts/release.sh gated tagging on raw git status --porcelain. In an agent-harness repo that output is never empty because .gitreins/ (tasks, usage, history, locks) and .coding-hermes/ board files are dirty/untracked by convention — so the gate permanently blocked the tag cut by treating bookkeeping as code dirt.

Fix: filter porcelain to a remainder before refusing:

NON_CODE_RE='^.. [.]gitreins/|^.. [.]coding-hermes/'
dirty_code() { git status --porcelain | grep -Ev "$NON_CODE_RE" || true; }

[ -n "$(dirty_code)" ] && { echo "release: worktree is not clean" >&2; dirty_code >&2; exit 1; }
git rev-parse -q --verify "refs/tags/$TAG" >/dev/null && { echo "release: tag $TAG already exists" >&2; exit 1; }
git tag -a "$TAG" -m "release $TAG"

Verified live in a temp repo simulating the harness: - bash -n → exit 0 - clean code + only .gitreins//.coding-hermes/ dirty → exit 0, annotated tag created - pre-existing v0.7.0 → exit 1 - staged and unstaged code dirt → exit 1, listing only the real path

Key design point noted in the doc: grep -Ev is line-anchored, so only root-level harness prefixes are ignored, genuinely untracked source still blocks, and || true prevents set -e -o pipefail from aborting on a clean tree.
