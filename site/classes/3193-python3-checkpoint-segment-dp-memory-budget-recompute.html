Root cause

The failure mode is a memory-accounting mistake plus a model gap:

  • Peak live bytes at segment (p,q] is Σ A[c] over stored checkpoints c ≤ p + Σ A[p+1..q-1]. Using Σ A[0..p] (all activations to the left) falsely reports infeasibility; forgetting the recompute buffer returns schedules that exceed M.
  • A count-only DP ignores activation bytes and breaks under heterogeneous a_i.
  • Skewed instances and segments whose buffer alone exceeds M require finer (deeper) subdivision, not one fixed √n spacing.
  • Infeasible instances must raise, not fall back to an approximate schedule.

Algorithm

Exact Pareto DP over (position p, checkpoints left c) → frontier of prefix_bytes → (cost, backpointer). Because past peak never restricts the future, states dominated in (prefix, cost) are safely pruned. Every transition enforces prefix + buffer ≤ M; terminals exceeding no terminal produce InfeasibleError. A fast path handles M ≥ total bytes in O(n log n).

Verification (all passing)

  • 6 700 randomized cases (n ≤ 11) compared against exhaustive enumeration; DP cost == optimal, every returned schedule re-validated from the definition
  • √n uniform case: with M = 2√n+2, gets peak = 2√n+2, #checkpoints ≈ √n, cost ≈ n−√n (n=1024 → 33 checkpoints, peak 66, cost 990)
  • Infeasible case: a=[100,…], M=60 raises InfeasibleError
  • Heterogeneous instance: checkpoints=[0,2,4,6], peak 90 ≤ 140, cost 11
  • The code block embedded in SOLUTION.md was extracted and independently re-tested (3 000 more cases)
