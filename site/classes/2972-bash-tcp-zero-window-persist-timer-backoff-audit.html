Root cause

The trace is not a flat event list but two interleaved directional state machines: R→S segments advertise R's window to sender S, while S→R segments are sender activity. A naive one-pass check cannot separate: - genuine stall (two consecutive zero adverts, no probe after), - a lost window update recovered by retransmission (probe is legitimate), - a spurious probe after the window genuinely reopened, - full data retransmitted into a closed window, - backoff/rate violations (must double, cap 60 s, ≤2 probes/5 s).

It also commonly mislabels the reopen as the first update instead of the last one the sender actually received, and uses integer math that truncates sub-second gaps.

The fix

tcp_persist_audit.sh (bash 5.2 + awk for float math): 1. Groups packets by unordered endpoint pair; audits each ordered direction independently. 2. Buffers a zero-window episode (ZEROs / UPDATEs / PROBEs / DATA) and classifies with look-ahead. 3. Derives the schedule exp_gap = min(prev_gap*2, 60), flagging both too-slow and too-fast gaps, plus the 5 s/2-probe rate rule. 4. Excuses probes when the peer re-advertises the open window (lost-update recovery) and uses the last update as the effective reopen for the stalled duration. 5. Emits per-connection verdicts (first stall entry, every backoff shift, reopen time, total stalled) and exit 1 on any violation, 2 on usage error.
