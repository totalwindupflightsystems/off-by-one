Diagnosis

DuckBrain namespaces are git repos at ~/duckbrain/namespaces/<ns>/ with two independent layers:

  • raw_note/<YYYY-MM>/current.jsonl — append-only record log (adds + tombstones)
  • .keys/keys.json — the index that GET /api/keys?namespace=<ns>&tree actually walks

DELETE /api/memories/<id> (204) and MCP forget only tombstone the record log; they never perform the store-level write that rewrites .keys/keys.json. So a wrong-shaped key like /project/h3/tick/565 stays visible in the tree, and the DF-H3-46 census guards (check-duckbrain-tick-chain.sh + duckbrain-tree-census.py) keep reporting 1 unknown drift key(s). The API/CLI cannot fix this — only a store-level edit can.

Secondary trap: bumping ticks_total moves the census END, turning a wrong-shaped-only tick from unknown drift into a hole, so the canonical bare key must be backfilled in the same closeout.

Fix (exact, in solution.md)

  1. Confirm the orphan via GET /api/keys?namespace=h3&tree and capture the memory id.
  2. Defensively prune both the add and tombstone rows from raw_note/*/current.jsonl (matches by key or by the id found on the bad-key add) — makes .bak snapshots.
  3. Remove the entry from .keys/keys.json.
  4. Backfill the bare /tick/565 if it was a real tick.
  5. Commit in the namespace repo, then re-run make verify.

A durable fix is also included: an atomic unindex() helper called from the DELETE handler and the MCP forget tool, plus a regression test, so v1.1.1 can remove such keys through the API.

Verification performed

  • Confirmed live DuckBrain :3000 responds (/health → healthy); authenticated routes require a token not present in this bwrap sandbox (the host ~/duckbrain store and ~/h3 repo are not bind-mounted).
  • Ran the exact repair scripts end-to-end against a synthetic namespace git repo: the bad-key add + tombstone were pruned, the index entry removed, unrelated keys preserved, JSON remained valid, the commit succeeded, and the section-4 one-liner printed PASS: wrong-shaped key fully removed.
  • Caught and fixed a real verification footgun: the naive grep -R matches the .bak snapshots, so the on-disk checks now use --exclude='*.bak' --exclude='*.orig'.

The remaining checks (guards + make verify) must run on the host where the store and umbrella repo exist; the document provides the exact commands and a rollback path.
