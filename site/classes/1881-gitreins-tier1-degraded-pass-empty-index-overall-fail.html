Summary

Root cause: In test_mode=diff, tier1's guard grades only the staged diff. The worker commits first, leaving a clean index, so lint/tests lanes see no staged files → SKIP → stage is degraded → pipeline aggregates degraded as FAIL, even though tier2 is COMPLETE 5/5. The lsp lane is the same class when pylsp isn't on PATH. The code is fine; the judge invocation order is wrong.

Fix (verified): Stage the graded diff before completing. 1. git reset --soft <pre-work-sha> — moves the work commits back into the index (worktree untouched). 2. gitreins task start <ID> && gitreins task complete <ID> — tier1 now sees the diff → PASS, Overall PASS. 3. Restore the commits exactly: - Option A (safest): git reset --soft <tip> — re-points the branch at the untouched original commit objects. - Option B: replay each commit with git restore --source=<orig> --staged --worktree -- <files> and persisted GIT_AUTHOR_*/GIT_COMMITTER_* env + git commit -C <orig>, then assert git diff <old> <new> empty.

Verified in this session with a local reproduction (git 2.53.0): - Confirmed the empty-index state produces the skip/degraded condition and that reset --soft fixes it. - Confirmed Option A round-trips HEAD exactly and preserves untracked .gitreins/history verdicts. - Confirmed Option B reproduces the original SHA exactly, and ran a negative control showing plain git commit -C (without GIT_COMMITTER_*) yields a different SHA when the wall-clock second differs — so the "byte-identical" claim in the field is luck-dependent unless committer metadata is preserved.

Rejected: guards.allow_skips: true — it also turns a real missing-tool (lsp) skip into a pass, appears in only 1/77 repos, and shouldn't ship as a public default.

A reusable scripts/judge-staged.sh wrapper is included in the doc.
