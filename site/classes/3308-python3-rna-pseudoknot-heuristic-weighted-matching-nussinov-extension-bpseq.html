Diagnosis

  • Plain Nussinov cannot represent pseudoknots. Its recurrence only splits intervals into disjoint/nested parts, so pairs (a,b) and (c,d) with a<c<b<d are unreachable.
  • The post-processing step is not greedy-solvable. Choosing crossing stems is max-weight independent set on a circle graph (weighted interval scheduling with nesting). A long stem (weight 10) can cross several compatible short stems (4+4+4=12): greedy takes 10, exact takes 12 — the "long crossing stem invalidates multiple shorter nested stems" subtlety.
  • Base-pair accuracy hides the bug (true negatives dominate; stays ~0.94 even when all pseudoknot pairs are wrong). F1 exposes it.

Exact fix

After the O(n²) stem table and the O(n³) Nussinov core, build candidate crossing stems (disjoint from core, crossing a core pair), then run an exact interval-circle DP. The critical term is the interior loop of a chosen helix:

# best[a][b] = max weight using stems inside [a,b]
# choose stem s=(i,j,L):
left  = best[a][i-1]           # disjoint flank before
inner = best[i+L][j-L]         # loop strictly inside s  <-- naive versions omit this
right = best[j+1][b]           # disjoint flank after
val   = left + s.w + inner + right

Nested stems live only in [i+L, j-L]; a greedy pass evaluates just one branch, the DP evaluates the full trade-off. Hard stem length is a candidate filter; kernel density uses an exact branch-and-bound variant.

Verification (all pass, brute force for n≤14)

  • A Nussinov core == exhaustive optimum, 400 random sequences
  • B exact_schedule == brute-force max-weight stem subset, 300 instances
  • C crafted circle graph: greedy 10 vs exact 12
  • D BPSEQ round-trip + F1 identity
  • E density-constrained B&B == density-aware brute force, 150 instances
  • F full predictions valid + self-BPSEQ F1=1, 200 sequences
