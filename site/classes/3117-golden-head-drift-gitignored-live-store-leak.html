Answer

INT-CI-16 — Make the visibility/soft-gate goldens hermetic (pin ROUTING_AVERAGES_FILE)

Root cause

The TR-354 outcome floor is fed by a rolling, gitignored live store:

  • scripts/router_spawn.py defines the default path as data/state/outcomes-averages.jsonl (AVERAGES), and _averages_path() resolves ROUTING_AVERAGES_FILE first, then falls back to that repo-relative default.
  • load_outcome_stats() reads the file; _outcome_floor_scan() excludes any lane whose measured record has n_success_known >= 8 and success_rate <= 0.35.
  • The file is gitignored. A host checkout therefore has a different routing input than CI's clean clone.

The 2026-11-01 golden re-anchor (ddea7d9) changed the expected heads to commandcode-2/z-ai/glm-5.3-flash after a host run where the live store showed xkiro/openai/gpt-5.6-terra with 955 known outcomes at 0.33 completion — just below the 0.35 floor. CI has no such file, so the floor was inert and the hermetic head was still xkiro/openai/gpt-5.6-terra.

This produced a time bomb in both directions:

  1. CI failed because the committed golden encoded host-only live-store data.
  2. Host failed later because the rolling store aged the xkiro evidence out (n_success_known became 0), so the floor stopped excluding xkiro — and the golden no longer matched either the host or CI.

The three affected assertions were:

  • tests/test_visibility.py:168 (test_corrupt_registry_source_fallback_and_warning)
  • tests/test_visibility.py:202 (test_missing_health_state_reported_false)
  • tests/test_soft_gate.py:130 (test_spawn_resolves_normally_despite_many_in_flight)

A golden derived from a rolling live store is not a fixed point. The test must pin its inputs.

Exact fix

Pin ROUTING_AVERAGES_FILE to an absent file under tmp_path in both fixture helpers. Then restore the hermetic xkiro/openai/gpt-5.6-terra golden with a dated reason, and retarget the soft-gate in-flight rows to that head.

Why this is safe

  • _averages_path() checks the env first. The pinned path does not exist, so load_outcome_stats() returns an empty index and the floor excludes nothing — exactly the same resolution CI already used. The fixture no longer depends on host runtime state.
  • No assertion is weakened. The tests still assert the fixed-point head, and the TR-354 floor's behavior coverage remains in tests/test_tr354_outcomes_floor.py (14 tests), which exercises the gate directly.
  • This is the established pattern: 12 other test files besides the two being fixed already reference/pin ROUTING_AVERAGES_FILE to an absent tmp path (e.g. tests/test_server.py:76); ten-plus siblings use the same hermetic pattern.
