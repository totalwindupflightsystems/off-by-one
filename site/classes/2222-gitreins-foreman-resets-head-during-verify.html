Fix: endOfDueDayUtc() returns undefined for ISO-8601 / Date inputs

Problem class: gitreins-foreman-resets-head-during-verify Repo: eduos.dexdat.com.co · Module: apps/api/src/modules/assessment Suite: vitest run --no-file-parallelism (pnpm, Node 22, per-file workers) Failing assertions: assessment.test.ts:502:28, assessment.test.ts:752:28, gradebook.test.ts:446:21

1. Summary

The three failures are not independent. They all read a value produced by endOfDueDayUtc() in apps/api/src/modules/assessment/services/submission-service.ts, and that function returns undefined whenever its argument is not a bare YYYY-MM-DD string.

After the t780 convention (commit 58ae08a9) the assessment module began persisting/serializing due days as full ISO-8601 UTC timestamps (2024-03-15T00:00:00.000Z) and, in a few code paths, as Date objects. The cutoff helper was never widened, so it silently fell through its guard and returned undefined. The downstream field was therefore undefined, giving the two assertion flavours seen in the log:

  • expect(undefined).toContain("<string>") → "the given combination of arguments (undefined and string) is invalid for this assertion"
  • expect(undefined).toBeDefined() → "expected undefined to be defined"

The class label (…foreman-resets-head-during-verify) is a confound: if the fix is left uncommitted, a verifier that resets the working tree to HEAD re-runs the pre-fix code and reproduces exactly the same 3 failures. Both the code fix and the “keep the tree during verify” step are below.

2. Root-cause analysis

2.1 The value is produced by the cutoff helper

All three stack frames converge on the same source:

endOfDueDayUtc()  ->  submission.dueAt / late-cutoff  ->  assertion

The helper is the only shared dependency, which is why 3 unrelated-looking tests flip together (3 failed / 4350 passed).

2.2 The helper is not total

The version introduced with the t780 convention parses only date-only strings and bails on everything else:

export function endOfDueDayUtc(dueDay?: string): Date | undefined {
  const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(dueDay ?? "");
  if (!m) return undefined;                 // <-- full ISO / Date inputs die here
  const [, y, mo, d] = m;
  return new Date(Date.UTC(+y, +mo - 1, +d, 23, 59, 59, 999));
}

So the convention change (ISO-8601 timestamps) and the parser (YYYY-MM-DD) disagree. Any caller that forwards a DB timestamptz / Date / serialized ISO value gets undefined instead of the end-of-day cutoff.

2.3 Why it looks intermittent

  1. Input-shape drift. Code paths that still pass a date-only string keep working; paths migrated to ISO timestamps (or hydrated Dates) fail. The morning t781 run exercised the former shape and was green.
  2. Verifier resets HEAD. The foreman verification stage checks out / resets to HEAD (see class name). Uncommitted edits are discarded, so the run evaluates the original, still-broken helper.

+const DATE_ONLY_RE = /^(\d{4})-(\d{2})-(\d{2})$/;
+
 /**
- * End of the due day, in UTC.
+ * End of the due day, in UTC.
+ *
+ * Accepts date-only strings ("2024-03-15"), full ISO-8601 timestamps
+ * ("2024-03-15T00:00:00.000Z") and Date objects, because the assessment
+ * module persists due days as timestamptz since the t780 convention.
  */
-export function endOfDueDayUtc(dueDay?: string): Date | undefined {
-  const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(dueDay ?? "");
-  if (!m) return undefined;
-  const [, y, mo, d] = m;
-  return new Date(Date.UTC(+y, +mo - 1, +d, 23, 59, 59, 999));
+export function endOfDueDayUtc(
+  dueDay?: string | Date | null,
+): Date | undefined {
+  if (dueDay === null || dueDay === undefined || dueDay === "") {
+    return undefined;
+  }
+
+  if (dueDay instanceof Date) {
+    if (Number.isNaN(dueDay.getTime())) return undefined;
+    return new Date(Date.UTC(
+      dueDay.getUTCFullYear(),
+      dueDay.getUTCMonth(),
+      dueDay.getUTCDate(),
+      23, 59, 59, 999,
+    ));
+  }
+
+  const raw = String(dueDay).trim();
+
+  // Fast path: date-only values stay byte-for-byte backwards compatible.
+  const dateOnly = DATE_ONLY_RE.exec(raw);
+  if (dateOnly) {
+    const y = Number(dateOnly[1]);
+    const mo = Number(dateOnly[2]) - 1;
+    const d = Number(dateOnly[3]);
+    const out = new Date(Date.UTC(y, mo, d, 23, 59, 59, 999));
+    // Reject silently-normalised dates such as 2024-02-31 -> 2024-03-02.
+    if (
+      out.getUTCFullYear() !== y ||
+      out.getUTCMonth() !== mo ||
+      out.getUTCDate() !== d
+    ) {
+      return undefined;
+    }
+    return out;
+  }
+
+  // Full ISO-8601 (and any Date.parse-able) input: pin to the end of its UTC day.
+  const parsed = new Date(raw);
+  if (Number.isNaN(parsed.getTime())) return undefined;
+  return new Date(Date.UTC(
+    parsed.getUTCFullYear(),
+    parsed.getUTCMonth(),
+    parsed.getUTCDate(),
+    23, 59, 59, 999,
+  ));
 }

Notes: keeps the existing undefined contract for genuinely absent values; uses Date.UTC + getUTC* only, so DST/server timezone cannot shift the cutoff by a day.

6. One-line takeaway

endOfDueDayUtc was written for YYYY-MM-DD but the t780 convention feeds it ISO-8601 timestamps and Dates; the regex guard returned undefined. Widen the parser (keeping date-only compatibility, using UTC only), commit the change so the foreman HEAD reset cannot discard it, and re-run the assessment files.
