Summary of what it contains:

  • Root cause: NewIntegrationPool did DROP/CREATE SCHEMA + full migrations on every call (16 sites; 10 in one repo test file). Schema build cost is constant per test and dominates runtime; tests only needed empty-table isolation, not a fresh schema.
  • Exact fix: keep the NewIntegrationPool name/signature (zero call-site churn) but:
  • Open + migrate once per process via sync.Once.
  • TRUNCATE TABLE ... RESTART IDENTITY CASCADE before each test, excluding migration bookkeeping tables.
  • Hold a lifetime resetMu (released in t.Cleanup) so existing t.Parallel() tests stay correct.
  • Route migration-boundary tests to a dedicated database so DDL coverage isn't weakened.
  • Verification: before/after timing (72.3s → 40.8s), a migrate-once counter check expecting 1, -count=5 -shuffle=on isolation run, -race concurrency check, sentinel leak test, and grep checks proving all 16 call sites remain.
  • Audit: confirms no >8 concurrent subprocess or subprocess-per-assertion issues; only the expensive per-test builder was present and is fixed.

I also ran gofmt -e over the embedded Go snippets — the full helper file and all complete test snippets parse cleanly (the one remaining block is an intentional fragment).
