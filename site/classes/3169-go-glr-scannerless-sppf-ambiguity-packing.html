Root cause (the four traps)

  1. Naive GLR packing is keyed on the GSS edge, not the SPPF node. Since alternation nodes (symbol,start,end) are canonical, all derivations over a span share one GSS edge. If AddPacked runs only when addEdge returns "new", later alternatives are silently dropped — a+a+a under E → E+E | E+E+E | a counts 1 instead of 3.
  2. Nullable cycles loop forever unless vertices/edges are deduped and counting is treated as a least fixpoint (productive cycles saturate, unproductive ones are zero).
  3. Int/u64 accumulators wrap. The E → E+E | a count is Catalan(m), which exceeds 2^64 at m=37.
  4. Precedence must prune in place, not copy the forest or re-parse.

Exact fix

The critical reordering in the reduction (pack first, dedupe the stack edge second):

walkPaths(u, k, func(bottom *gssNode, children []*SPPFNode) {
    sym := f.symbol(prod.LHS, bottom.pos, u.pos) // canonical (LHS,start,end)
    f.addPacked(sym, prod, children)             // ALWAYS install the alternative
    g, ok := g.lr.gotoTab[bottom.state][prod.LHS]
    if !ok { return }
    v := getNode(g, u.pos)
    if addEdge(v, bottom, sym) { push(v) }       // de-dup only the stack edge
})

plus canonical LR(1) tables, math/big counting over Tarjan SCCs with a saturation cap (CountCap = 2^4096, ExactCountUint64 saturates at MaxUint64), and an in-place Disambiguate using the precedence-climbing rule.
