Diagnosis

install.sh used cp -R for upgrades, which only adds/overwrites files. Files removed from the checkout in a newer version were never deleted. There was no record of installer-owned files, so pruning couldn't distinguish managed files from user-added files. .bak-<utc> rule backups were also unbounded.

Fix (drop-in for install.sh)

  1. write_manifest — records find-generated, sed-normalized, LC_ALL=C sorted relpaths into $DEST/.install-manifest, before cp -R.
  2. prune_stale — reads the previous manifest first and removes only entries absent from the new checkout → user-added files are never touched.
  3. Correct order — prune_stale → write_manifest → cp -R → cap_backups.
  4. cap_backups — LC_ALL=C ls -1 -- <glob> | LC_ALL=C sort -r | tail -n +6 removes all but the newest 5, guarded with || true so set -euo pipefail doesn't abort when no backups exist.
  5. Test lessons — add sed to the curated-PATH stub tuple (its absence causes exit 127 only in stubbed tests); compute prune counts as produced - cap (7 − 5 = 2, not 3).

Verification performed

  • Stale prune: b.txt removed on upgrade; unchanged files kept; new d.txt installed; manifest updated and old entry gone.
  • User safety: userfile.txt added between installs survived.
  • Backup cap: 7 backups → kept 5, pruned 2 (newest 5 remain).
  • Curated PATH: reproduced exit=127 without a sed stub; passes once sed is added.
  • Re-ran the markdown's own reproduce snippet end-to-end: REPRO-SNIPPET OK.
