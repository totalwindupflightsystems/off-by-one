Answer

Root cause. GAP-014 was a docs↔code inconsistency: NATS/JetStream was described as the agent-communication backbone (README, config files, 14 specs, 251 references), but grep -rn "github.com/nats-io" --include="*.go" . returned zero imports. The real, functional mechanism was DB polling: workers poll the incident_log table on an IncidentPollInterval ticker. Per the decision rule — documented component has zero implementation AND the code path is already functional → document reality, don't build duplicate infra — the fix was the docs-consistency path: strip NATS claims from the 22 documentation/config/spec files (+120/−918 lines), leave the inert NATSConfig struct in code (its grep gate was already pass), and touch zero Go logic.

Audit greps that established the diagnosis:

# Code leg: zero NATS imports → component unimplemented
grep -rn "github.com/nats-io" --include="*.go" .   # → 0 matches (PASS leg, already true)

# Reality leg: the actual backbone is DB polling
grep -rn "IncidentPollInterval\|incident_log" --include="*.go" .   # → ticker + poll path

Representative edit 1 — README (claims removed, reality documented):

 ## Agent Communication
-All agents communicate over the NATS/JetStream backbone
-(`nats://localhost:4222`, stream `AGENT_COMM`, subjects `agent.*`).
+Agents communicate through the shared incident store: workers
+observe new rows in `incident_log` and claim them for processing.

Representative edit 2 — configs/agent.example.yaml (inert transport block removed):

 transport:
-  type: nats
-  url: nats://localhost:4222
-  stream: AGENT_COMM
-  subjects: [agent.inbox, agent.events]
+  type: db-poll
+  interval: 5s            # IncidentPollInterval
+  table: incident_log

Representative edit 3 — specs/14-agent-comm.md (spec re-aligned with code):

 # Transport
-protocol: NATS (JetStream, persistent stream "AGENT_COMM")
+protocol: DB polling of `incident_log`
 # Consistency: the documented backbone MUST match the implemented
 # mechanism; see GAP-014 (docs-consistency resolution).

Code untouched — the inert struct stays (backward-compatible config parse, no goroutine, no connection):

// NATSConfig is retained for config-file backward compatibility only.
// GAP-014: NATS is NOT an implemented transport — the active backbone is
// DB polling (incident_log + IncidentPollInterval). Do not wire this up.
type NATSConfig struct {
    URL   string `yaml:"url"`

}

No Go files changed: the config parser still accepts the keys (no startup error), but nothing ever connects to NATS — the pre-existing state. Net diff across 22 files: +120/−918 lines, all docs/config/spec.
