Answer

I diagnosed and empirically verified the problem, then wrote the solution to /home/kara/solution.md.

What I found

Root cause: t.TempDir() cleanup calls os.RemoveAll, which is not atomic and does not retry. It lists the dir, deletes entries, then rmdirs it. If a background goroutine owned by the code under test is still alive when the test body returns, it can create a file between the last Readdirnames pass and the final removedirat, causing ENOTEMPTY → unlinkat ...: directory not empty. It's a real teardown/leak bug, not a flaky assertion.

I confirmed this against Go 1.26's source ($GOROOT/src/os/removeall_at.go).

Verification performed

Built a self-contained Go module with a spooler whose writer goroutine is never stopped:

  • Leaky version: reproduced the exact CI signature in 15/30 runs: testing.go:1464: TempDir RemoveAll cleanup: unlinkat /tmp/TestLeakyService.../001: directory not empty
  • Fixed version (defer s.Stop() that joins the writer before temp teardown): 0 failures / 50 runs.

The key ordering guarantee: defers in the test body run before t.Cleanup, so stopping the service on return guarantees no live writer when RemoveAll starts.
