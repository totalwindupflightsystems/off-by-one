Solution written to /home/kara/go-test-port-collision-stray-daemon.md (217 lines). Summary:

Root cause

A previous tick booted a scratch daemon (HOME=/home/kara/trbl008-home bin/troubled ...) bound to the fixed dashboard port 127.0.0.1:7644 and never tore it down. The next tick's TestPreflightBinds* — a port-availability preflight, not the code under test — fails with bind: address already in use. That's a false red, not a regression.

Exact fix

Immediate (prove-then-kill, never pkill -f):

PORT=7644
ss -tlnp | grep ":$PORT"                 # name holder pid -> users:(("troubled",pid=NNNN,...))
ps -o pid=,lstart=,etime=,cmd= -p NNNN   # date it; earlier than this tick = not yours
ps -o lstart= -p "$$"                    # compare to current tick
kill NNNN && sleep 1
ss -tlnp | grep ":$PORT" && kill -9 NNNN
go test ./... -run 'TestPreflightBinds' -count=1

pkill -f troubled matches your own shell/test command — use PID only.

Permanent: bind scratch daemons to an ephemeral port instead of 7644, and reap on every exit path: - Go tests: reserve net.Listen("tcp","127.0.0.1:0"), or start the daemon with --addr 127.0.0.1:0 and read the chosen port back; register t.Cleanup(d.Stop) so t.Fatal still reaps it. - Shell scripts: capture DAEMON_PID=$! and trap cleanup EXIT INT TERM, using kill "$DAEMON_PID"; keep a unique scratch HOME per tick.

Verification

ss -tlnp | grep ':7644' || echo "OK: port free"
ps -o pid=,cmd= -C troubled 2>/dev/null || echo "OK: no stray daemon"
go test ./... -run 'TestPreflightBinds' -count=5 -v
go test ./... -count=1
ss -tlnp | grep ':7644' || echo "OK: suite released :7644"

On this host right now all checks pass: no listener on :7644, no troubled process, no /home/kara/trbl008-home — confirming the leak is intermittent/cross-tick rather than a standing bug. The full runbook includes a drop-in testutil.FreePort helper, a self-reaping scratch-boot script, and a CI orphan-listener guard.
