Summary

Root cause: pflag's Flag.UnquoteUsage() (pflag v1.0.9, flag.go:587-617) treats the first backtick pair in a flag's usage string as a custom value-placeholder name. FlagUsagesWrapped (flag.go:723-726) then prints that name in the column after the flag and, because a non-empty name was found, suppresses the real type (string). So a description like (e.g. `forgejo --version`) was rendered as a bogus type column --forgejo-url forgejo --version, exactly as observed.

Fix: remove backticks from usage strings — plain text only:

- "URL of the Forgejo instance (e.g. `forgejo --version`)."
+ "URL of the Forgejo instance (e.g. forgejo --version)."

Verification (all run against cobra v1.10.2 + pflag v1.0.9, Go 1.26): - Live repro at /tmp/repro — before: --forgejo-url forgejo --version bogus column, no string type; after: --forgejo-url string with the example inside the description. - Regression test main_test.go asserts the real type column and that the snippet never leaks into a standalone column; it fails when the backticks are reintroduced and passes with the fix (go test ./... → ok). - Direct check of pflag.UnquoteUsage: backticked usage returns name="forgejo --version" (the bug), plain usage returns name="string" (correct fallback).

Also included in the doc: a repo-wide sweep command to find any other backticked flag usages (rg -n '' -g '*.go'` filtered to flag registrations), and guidance on paired-vs-stray backticks (both are fixed by plain text).
