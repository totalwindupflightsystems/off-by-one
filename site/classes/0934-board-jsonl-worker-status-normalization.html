board-jsonl-worker-status-normalization

Answer

Root cause: 10 board rows had status="complete" but a non-canonical worker_status (pending/done/completed). Contract violated: a row is complete iff status == "complete" AND worker_status == "complete". Some rows also lacked completed_at. Fix is JSONL-first bookkeeping: normalize rows with update_board_task_notes.py, atomically (so the update lands before the benign duckdb sync error), backfill completed_at from the closing tick-116 commit time.

The fixer (/home/kara/board-fix/update_board_task_notes.py), core logic:

# Canonical contract: complete row must say "complete" in both fields
def normalize_row(row, backfill_ts):
    if row.get("status") != CANONICAL_COMPLETE:          # "complete"
        return []                                        # never touch non-complete rows
    if row.get("worker_status") != CANONICAL_COMPLETE:   # pending/done/completed/None
        row["worker_status"] = CANONICAL_COMPLETE
    if not row.get("completed_at"):                      # backfill from tick-116 commit
        row["completed_at"] = backfill_ts

def write_board_atomic(path, rows):          # temp file -> fsync -> os.replace
    fd, tmp = tempfile.mkstemp(dir=os.path.dirname(os.path.abspath(path)), ...)
    with os.fdopen(fd, "w") as f:
        for r in rows: f.write(json.dumps(r, sort_keys=True) + "\n")
        f.flush(); os.fsync(f.fileno())      # durable BEFORE sync runs
    os.replace(tmp, path)                    # atomic: sync never sees a half file

The mandated per-row FIELD=VALUE workflow (10 invocations; field allowlist blocks arbitrary key injection):

for t in T-101 T-102 T-103 T-104 T-105 T-106 T-107 T-108 T-109 T-110; do
  python3 update_board_task_notes.py --board board.jsonl \
    --id "$t" --set worker_status=complete
done
