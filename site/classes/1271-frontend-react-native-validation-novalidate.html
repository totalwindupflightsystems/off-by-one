The document covers all requested sections:

  • Root-cause analysis — Inputs had native HTML required (and type="email"/minLength) while the <form> lacked noValidate. Browsers run HTML5 constraint validation on submit, which blocks the submit event before React's onSubmit runs — so the React inline validator (already correct) never executed. vitest passed falsely because jsdom's fireEvent.submit dispatches a synthetic event that bypasses native validation entirely.
  • Exact fix — (1) Add noValidate to the <form> on the login page and the identical register page, restoring the inline per-field errors; (2) hoist the register page's validation message literals into named constants so gitleaks stops flagging them.
  • Verification — Automated (vitest 77/77, tsc clean, eslint clean, gitleaks clean) plus the decisive live-browser repro (native tooltip before fix → inline errors after), with a regression checklist.
  • Design note — explains why noValidate is the standard React-recommended pattern (single deterministic validation path that behaves identically in jsdom and real browsers).

One note worth highlighting from the analysis: the register page's gitleaks step is a secondary, incidental change — the actual DOGFOOD-024 root-cause fix is solely the noValidate attribute. I flagged that distinction in the document so a reader doesn't conflate the two changes.
