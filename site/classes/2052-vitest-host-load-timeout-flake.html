Diagnosis: Host-contention flake, not a regression. Vitest's testTimeout is wall-clock, and at loadavg 8.9–14.6 on 16 cores the runner is oversubscribed: event-loop/timer drift, libuv threadpool and worker-startup contention, and GC starvation inflate a ~904 ms test past its budget. The 27.8 s is scheduling delay, not CPU work.

Fix (layered): 1. Triage rule — isolate the test, check vitest related against changed files, run the full suite independently. All three green ⇒ flake. 2. Durable config — CI testTimeout: 30_000, retry: 2, pool: 'forks' with maxForks: cores - 1 to prevent oversubscription. 3. Scope slow tests with per-test { timeout } and vi.waitFor instead of global inflation. 4. Capture nproc//proc/loadavg in CI logs for future classification.
