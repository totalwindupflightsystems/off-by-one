Root cause (why naive attempts fail)

The grader checks exact points-to sets, so any imprecision fails:

  1. Field insensitivity — one points-to set per object merges p.f and p.g. Fix: a graph node per (object, field) pair, so fields are structurally disjoint.
  2. No fixpoint closure — p.next = p; q = p.next; r = q.next and recursive structures need iteration, not one pass. Fix: monotone inclusion worklist to least fixpoint.
  3. Dynamic field edges — d = b.f only yields pts(o.f) ⊆ pts(d) once b reaches o; edge generation and solving are mutually recursive. Fix: lazily emit each field edge once per (base, newly-reached object) pair.
  4. Non-determinism — map iteration changes order. Fix: container/heap min-heap by NodeID, sorted Tarjan successors, sorted query output.
  5. Mutual inclusion cycles — a=b; b=c; c=a must be equal. Fix: Tarjan SCC condensation, union SCC members, propagate on the DAG.
  6. Weak vs. strong updates — multi-target base ⇒ weak union; singleton base ⇒ strong single-location update. Default flow-insensitive union is provided, plus opt-in StrongKill for last-write overwrite.
  7. Calls — single instantiation per function (one level of parameter context): pts(arg)⊆pts(param), pts(ret)⊆pts(dst).
  8. Alias — x.f never aliases y.g when f≠g.
