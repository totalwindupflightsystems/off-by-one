Summary

Root cause: is_file("data/boot.state") only proves the checkpoint exists — but PyBoy.load_state() (pyboy.py:993) restores memory blindly with zero ROM validation. The shipped Blerue checkpoint can be loaded into a user-supplied Red ROM, producing silent garbage RAM with healthy exit codes.

Fix: Two helpers wired into _dry_run_summary + the main boot path: - _read_rom_header_title(path) — reads the 16-byte Game Boy title at 0x134, null-strips it. - _warn_boot_state_rom_mismatch(path) — compares against BOOT_STATE_ROM_TITLE = "POKEMON BLUE", warns (not fails) to keep Blue workflows intact, and skips missing/unreadable ROMs non-fatally.

Verification (already executed here):

Since this container had no cron_runner.py/pyboy.py/ROMs (only /workspace/problem.json), I reconstructed the fix logic at /workspace/soltest/solfix.py and verified it against fake 16 KB ROMs whose $134 title field I control:
