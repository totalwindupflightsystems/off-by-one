Answer

Fix: docker.service stuck in systemd failed state after rootless Docker install on a fresh CI agent uid

TL;DR

The official rootless installer fails because dockerd-rootless-setuptool.sh performs exactly one systemctl --user start docker.service; with the unit's Restart=always + StartLimitBurst=3/StartLimitInterval=60s, three rapid daemon failures trip systemd's start rate limiter. From then on every systemctl --user start fails instantly (Job for docker.service failed because the control process exited with error code) until the rate counter is flushed with systemctl --user reset-failed. A bare re-install cannot fix it because (a) get.docker.com/rootless short-circuits on the leftover $HOME/bin/dockerd and exits 0, and (b) dockerd-rootless-setuptool.sh uninstall never calls reset-failed.

Fix: wrap the install with a one-shot recovery that runs, in this exact order:

  1. systemctl --user is-failed docker.service → if failed, systemctl --user reset-failed docker.service
  2. $HOME/bin/dockerd-rootless-setuptool.sh uninstall -f
  3. $HOME/bin/rootlesskit rm -rf $HOME/.local/share/docker (fallback rm -rf)
  4. retry once via dockerd-rootless-setuptool.sh install --force (NOT the wrapper)
  5. on second failure: fatal error carrying systemctl status + journalctl -u docker.service excerpt

Root-cause analysis

1. The installer has no idempotency and no recovery

/usr/share/docker.io/contrib/dockerd-rootless-setuptool.sh (install_systemd, lines ~355–376):

if ! systemctl --user --no-pager status "${SYSTEMD_UNIT}" > /dev/null 2>&1; then
    INFO "starting systemd service ${SYSTEMD_UNIT}"
    (
        set -x
        if ! systemctl --user start "${SYSTEMD_UNIT}"; then
            set +x
            show_systemd_error          # prints hints, calls journalctl
            exit 1                      # gives up; no reset-failed, no uninstall
        fi
        sleep 3
    )
fi

show_systemd_error() only prints advice ($0 uninstall -f ; rootlesskit rm -rf ...); the script never executes it. The partial ~/.config/systemd/user/docker.service and ~/.local/share/docker are left behind.

2. The unit self-limits, turning one transient failure into a sticky one

The generated unit (lines ~336–352) is:

RestartSec=2
Restart=always
StartLimitBurst=3
StartLimitInterval=60s

systemd(1) man page, StartLimitIntervalSec=/StartLimitBurst=:

Units which are started more than burst times within an interval time span are not permitted to start any more. […] units which are configured for Restart= and which reach the start limit are not attempted to be restarted anymore […] systemctl reset-failed will cause the restart rate counter for a service to be flushed, which is useful if the administrator wants to manually start a unit and the start limit interferes with that.

So Restart=always retries dockerd-rootless.sh every 2 s; when dockerd keeps dying, the unit burns its 3-start budget in ~6 s and enters failed with Result=start-limit-hit. A later manual systemctl --user start is rejected before ExecStart even runs. The only reliable cure is reset-failed (or letting the unit be garbage-collected, which you cannot rely on).

3. The wrapper makes "just re-run it" silently pass

get.docker.com/rootless (downloaded script), lines 129–139:

# Already installed verification (unless force?). Only having docker cli binary previously shouldn't fail the build.
if [ -x "$BIN/$DAEMON" ]; then
    echo "# Existing rootless Docker detected at $BIN/$DAEMON"
    ...
    exit 0
fi

On a retry, $HOME/bin/dockerd already exists from the first extraction, so the wrapper prints "Existing rootless Docker detected" and exits 0 while docker.service is still failed. This is the trap that makes the failure look unrecoverable/unobservable. The retry must go straight to dockerd-rootless-setuptool.sh install, or the daemon binary must be removed first.

4. uninstall does not clear the failed/rate-limit state

cmd_entrypoint_uninstall runs only:

systemctl --user stop  docker.service || :
systemctl --user disable docker.service || :
rm -f "${unit_file}"

No reset-failed. The unit file removal usually lets the manager garbage-collect and flush counters on the next daemon-reload, but that is not guaranteed (a lingering job/reference keeps the unit loaded), so the counter can survive the uninstall and poison the reinstall.

5. Data dir may be owned by the subuid, not the user

dockerd-rootless.sh re-execs through rootlesskit, which maps the user to root inside the userns and the user's subuid (e.g. 100000) outside. Files it creates under ~/.local/share/docker are therefore owned by 100000:100000; a plain rm -rf as the invoking user can fail with EACCES. Use rootlesskit rm -rf first.

6. Why "fresh agent uid" triggers it

On a fresh UID there is no prior state and nothing warmed up. On Ubuntu 24.04+ the kernel restricts unprivileged user namespaces (kernel.apparmor_restrict_unprivileged_userns=1); the only way rootlesskit may create a userns is a loaded AppArmor profile such as:

~<id>/bin/rootlesskit flags=(unconfined) { userns, }

This host has 163 such per-agent profiles under /etc/apparmor.d/ (e.g. home.bunker-adc7bb46.bin.rootlesskit). If that profile has not yet been parsed/loaded when the unit starts — a race, or a failure to run apparmor_parser — rootlesskit exits EPERM, dockerd dies, Restart=always loops, and the start limit trips. The journal excerpt in step 5 is what makes this visible (failed to create user namespace: operation not permitted), instead of the generic systemd job message.

The exact fix

Go (production integration in bunker's rootless-install stage)

This package is the drop-in wrapper. It is the version that was compiled, vetted, and unit-tested in the verification section below.

// Package rootlessrecover makes the official rootless Docker installer
// idempotent when the systemd user unit docker.service fails to start.
package rootlessrecover

import (
    "context"
    "fmt"
    "os"
    "os/exec"
    "path/filepath"
    "strings"
)

// Unit is the systemd user unit installed by dockerd-rootless-setuptool.sh.
const Unit = "docker.service"

// CommandRunner runs one command and returns its combined output. It is an
// interface so the recovery order can be unit-tested without a live systemd.
type CommandRunner interface {
    Run(ctx context.Context, env []string, name string, args ...string) (string, error)
}

// OSRunner is the production CommandRunner.
type OSRunner struct{}

func (OSRunner) Run(ctx context.Context, env []string, name string, args ...string) (string, error) {
    cmd := exec.CommandContext(ctx, name, args...)
    if env != nil {
        cmd.Env = env
    }
    out, err := cmd.CombinedOutput()
    return string(out), err
}

// Recoverer wraps one rootless-Docker installation and repairs the sticky
// "failed" state of docker.service before a single retry.
type Recoverer struct {
    Home     string        // agent home, e.g. ~
    BinDir   string        // defaults to $HOME/bin
    DataDir  string        // defaults to $HOME/.local/share/docker
    Env      []string      // environment, must contain XDG_RUNTIME_DIR for the user manager
    Runner   CommandRunner // defaults to OSRunner
    JournalN int           // journal lines to attach on fatal failure (default 50)
}

func (r *Recoverer) defaults() {
    if r.BinDir == "" {
        r.BinDir = filepath.Join(r.Home, "bin")
    }
    if r.DataDir == "" {
        r.DataDir = filepath.Join(r.Home, ".local", "share", "docker")
    }
    if r.Runner == nil {
        r.Runner = OSRunner{}
    }
    if r.JournalN == 0 {
        r.JournalN = 50
    }
}

// Recover runs install once. If it fails it performs, in order:
//
//  1. systemctl --user reset-failed docker.service  (only when provably failed)
//  2. dockerd-rootless-setuptool.sh uninstall -f
//  3. rootlesskit rm -rf <data dir>, falling back to os.RemoveAll
//  4. one retry through dockerd-rootless-setuptool.sh install --force
//
// On a second failure it returns an error carrying the unit status and
// journal excerpt. A nil error means the retry succeeded.
func (r *Recoverer) Recover(ctx context.Context, install func(context.Context) error) error {
    r.defaults()

    firstErr := install(ctx)
    if firstErr == nil {
        return nil
    }

    // 1. Clear the failed state so the start rate-limit counter is flushed.
    //    Without this, `systemctl --user start` keeps failing instantly with
    //    "Start request repeated too quickly" until reset-failed is run.
    if r.UnitFailed(ctx) {
        _, _ = r.Runner.Run(ctx, r.Env, "systemctl", "--user", "reset-failed", Unit)
    }

    // 2. Remove the partial unit file and CLI context. Best effort: if the
    //    setup tool is gone we still fall through and retry.
    setuptool := filepath.Join(r.BinDir, "dockerd-rootless-setuptool.sh")
    _, _ = r.Runner.Run(ctx, r.Env, setuptool, "uninstall", "-f")

    // 3. Wipe the data dir. Files created through RootlessKit are owned by
    //    the user's subuid (e.g. 100000), so a plain rm can fail; run it
    //    through rootlesskit first and only fall back to a direct remove.
    rootlesskit := filepath.Join(r.BinDir, "rootlesskit")
    if _, err := r.Runner.Run(ctx, r.Env, rootlesskit, "rm", "-rf", r.DataDir); err != nil {
        _ = os.RemoveAll(r.DataDir)
    }

    // 4. Retry once, through the setup tool directly. Re-running the
    //    get.docker.com/rootless wrapper would short-circuit on the leftover
    //    $HOME/bin/dockerd and "succeed" without starting the unit.
    if out, err := r.Runner.Run(ctx, r.Env, setuptool, "install", "--force"); err != nil {
        return fmt.Errorf("rootless docker install failed after one recovery attempt: %w: %s\n\n%s",
            err, strings.TrimSpace(out), r.Diagnostic(ctx))
    }
    return nil
}

// UnitFailed reports whether systemd currently considers docker.service failed.
func (r *Recoverer) UnitFailed(ctx context.Context) bool {
    r.defaults()
    out, err := r.Runner.Run(ctx, r.Env, "systemctl", "--user", "is-failed", Unit)
    if err == nil {
        return true // is-failed exits 0 only in the "failed" state
    }
    return strings.TrimSpace(out) == "failed"
}

// Diagnostic returns the unit status and journal excerpt used on fatal failure.
func (r *Recoverer) Diagnostic(ctx context.Context) string {
    r.defaults()
    var b strings.Builder
    if out, _ := r.Runner.Run(ctx, r.Env, "systemctl", "--user", "--no-pager", "--full", "status", Unit); out != "" {
        fmt.Fprintf(&b, "$ systemctl --user --no-pager --full status %s\n%s\n", Unit, out)
    }
    if out, _ := r.Runner.Run(ctx, r.Env, "journalctl", "--user", "-u", Unit, "-n", fmt.Sprint(r.JournalN), "--no-pager"); out != "" {
        fmt.Fprintf(&b, "$ journalctl --user -u %s -n %d --no-pager\n%s\n", Unit, r.JournalN, out)
    }
    return b.String()
}

Call site (the important part is Env, so systemctl --user can reach the agent's user manager):

If you are not in Go at the call site, the shell function below is the same algorithm and is directly runnable as the agent uid (with XDG_RUNTIME_DIR exported).

Shell recovery function (directly usable)

#!/bin/sh
set -eu

BIN="$HOME/bin"
DATA="$HOME/.local/share/docker"
UNIT=docker.service

# Required so `systemctl --user` reaches the agent's user manager.
export XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}"
export DBUS_SESSION_BUS_ADDRESS="${DBUS_SESSION_BUS_ADDRESS:-unix:path=$XDG_RUNTIME_DIR/bus}"

# The installer you already run. First attempt only.
run_installer() {
    curl -fsSL https://get.docker.com/rootless | sh
}

if run_installer; then
    exit 0
fi
echo "first rootless install failed; recovering" >&2

# 1. Flush the start rate-limit counter, but only for a provably failed unit.
if systemctl --user is-failed "$UNIT" >/dev/null 2>&1; then
    systemctl --user reset-failed "$UNIT" || true
fi

# 2. Remove the partial unit and CLI context.
"$BIN/dockerd-rootless-setuptool.sh" uninstall -f || true

# 3. Best-effort data wipe: rootlesskit maps subuid-owned files back to root.
if ! "$BIN/rootlesskit" rm -rf "$DATA" 2>/dev/null; then
    rm -rf "$DATA" 2>/dev/null || true
fi

# 4. Retry ONCE through the setup tool (never the wrapper that short-circuits).
if "$BIN/dockerd-rootless-setuptool.sh" install --force; then
    exit 0
fi

# 5. Fatal, with the real daemon reason.
echo "rootless docker install failed after recovery" >&2
systemctl --user --no-pager --full status "$UNIT" >&2 || true
journalctl --user -u "$UNIT" -n 50 --no-pager >&2 || true
exit 1

Prerequisite for the retry to actually succeed

If the journal excerpt from step 5 shows failed to create user namespace: operation not permitted, the retry is correct but the host prerequisite is missing. Ensure the per-agent AppArmor profile is parsed before the retry (this is the only userns gate on Ubuntu 24.04+):

# after uninstall, before install --force
printf '/home/%s/bin/rootlesskit flags=(unconfined) { userns, }\n' "$AGENT" \
  > "/etc/apparmor.d/home.${AGENT}.bin.rootlesskit"
apparmor_parser -r "/etc/apparmor.d/home.${AGENT}.bin.rootlesskit"

(or set kernel.apparmor_restrict_unprivileged_userns=0 at the host level). The recovery above is still required: a loaded profile does not clear a start-limit-hit unit.

If it ends failed again, the surfaced journalctl --user -u docker.service excerpt names the real cause (AppArmor/userns, subuid, xtables.lock, cgroup delegation) instead of the generic systemd job error.

Rollout notes

  • Keep the recovery scoped to the agent's own docker.service and run it as that uid; never reset another user's manager.
  • reset-failed is deliberately gated by is-failed so unrelated install errors (missing newuidmap, no XDG_RUNTIME_DIR, bad subuid) are not masked.
  • Retrying through the setup tool (not the wrapper) is mandatory; if you must use the wrapper, delete $BIN/dockerd first or validate is-active docker.service before treating exit 0 as success.
  • Upstream hardening worth carrying: make install_systemd in dockerd-rootless-setuptool.sh run systemctl --user reset-failed before start and uninstall run reset-failed after stop/disable.
