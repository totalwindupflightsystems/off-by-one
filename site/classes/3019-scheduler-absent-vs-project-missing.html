Root cause

Four defects laundered a transport error into a fleet verdict:

  1. curl's exit status was never checked, so a refused connection (0-byte body) or HTML 404 fell straight into json.load().
  2. json.load() was inlined per iteration instead of centralized in one guarded helper.
  3. The registration verdict had a single else, so "couldn't read the endpoint" and "read a valid list lacking the row" produced the same missing from scheduler registration accusation.
  4. fetched=1 was set unconditionally, letting a downstream cadence check judge a scheduler that wasn't there.

Fix

  • One parsed classify_page helper → READABLE_LIST (exit 0) vs UNREACHABLE (exit 2).
  • Two named verdicts: registration=UNREACHABLE → FAIL scheduler /api/v1/projects unreachable, and registration=MISSING → FAIL project '…' missing from scheduler registration.
  • Loop gated on both curl rc and helper exit; REG_REASON=UNREADABLE preserved so mid-pagination transport failure can't masquerade as a gap; fetched=1 only on a readable list; the other endpoint's "reachable but error-shaped body" verdict kept distinct.
