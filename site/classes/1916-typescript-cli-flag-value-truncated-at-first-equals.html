Summary

Root cause — src/cli/human.ts:69 destructures a full split("="):

const [key, value] = arg.slice(2).split("=");
flags[key] = value || "true";

split("=") returns every segment; destructuring keeps only the first two, so content=alpha rc=1 omega dims=4096 tail=END becomes ["content", "alpha rc", "1 omega dims", ...] and stores "alpha rc" (8 chars) while printing a success line.

Fix — cut once at the first =:

const body = arg.slice(2);
const eq = body.indexOf("=");
const key = eq === -1 ? body : body.slice(0, eq);
const value = eq === -1 ? undefined : body.slice(eq + 1);
flags[key] = value || "true";

Verified logic (run in /tmp/eqrepro/check.mjs):

input pre-fix post-fix
--content=alpha rc=1 omega dims=4096 tail=END "alpha rc" (8) RED full 35 chars GREEN
base64 ...YWJj== truncated at = padding preserved
--wait "true" "true" (unchanged)
--namespace=foo=bar "foo" "foo=bar"

Why one file — the sibling parsers (src/cli/search-index.ts:44, src/cli/embeddings.ts:47) already use startsWith("--x=") + slice, i.e. a single cut, so they are correct.

The document includes the full regression suite (remember-eq-value-clitrunc001.test.ts) that spawns the real CLI against a scratch DUCKBRAIN_NAMESPACES_PATH/DUCKBRAIN_CONFIG_PATH root and asserts the persisted JSONL row (never the success line), plus the RED→GREEN procedure with the 0a53debd/4d3746ad md5 negative control.

Note: the expect field names / namespace name in the test sketch may need a one-line adjustment to match your partition schema — the oracle (read the row, compare bytes) is the invariant.
