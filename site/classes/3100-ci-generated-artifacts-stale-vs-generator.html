Fix: CI "Verify committed PRD artifacts are current" fails — generated artifact stale vs. its generator

Problem class: ci-generated-artifacts-stale-vs-generator Recurrence: tatara TAT-077 (2026-10-06), again INT-CI-20261101 (2026-11-01) Canonical case: docs/prd/tatara-PRD.html drifted from scripts/merge-prd.py; deterministic 3-line nested-<strong> diff.

1. Symptom

A GitHub Actions job fails at the step "Verify committed PRD artifacts are current" with an annotation shaped like:

docs/prd/tatara-PRD.html artifacts are stale: scripts/merge-prd.py regenerated them

The source tree looks untouched, the PR is small or empty, and the failing check is the same check that passed on main — until now. The job is doing exactly what it should: it runs the canonical generator and fails if the working tree differs from the committed artifacts.

2. Root cause

The committed generated artifact drifted from the canonical generator output. The gate cannot know why the bytes differ; it only knows regenerate != committed.

Drift happens in one of two ways:

  1. Hand reformat / manual edit of the generated HTML committed without re-running the generator. Here the edit introduced nested <strong><em>…</em></strong> markup — a deterministic rendering difference in the Markdown→HTML pipeline (python-markdown with toc/tables/attr_list), not a flaky render.
  2. A source commit that landed while hosted CI was down (billing / runner outage). The commit touched the generator or its inputs, but the regen gate never screened it, so the artifact was committed one revision behind.

Identifying properties:

  • Deterministic, not nondeterministic. The generator hits the same diff every time. It cannot be "re-run to green".
  • Scope is narrow. The diff is confined to generated artifacts; the source .md files are byte-identical.
  • Process gap, not a code bug. committed artifact == generator(source) was violated at commit time. Generator and verify step are both correct.

Why it recurs

The invariant is enforced only by CI. Any path that bypasses CI (hosted runner outage, --no-verify, a hotfix push, a merge that skipped the gate) can land a commit where the generator source and its outputs are out of sync. The recurrence-class rule:

Any commit that touches a generator source or its generated outputs must run the generator and commit the regenerated outputs in the same commit.

3. Diagnose before fixing

Do not hand-edit the HTML to "match CI". Reproduce, then commit the generator's own output.

3.1 Find the exact generator invocation the CI step uses

rg -n -i "Verify committed PRD artifacts are current" .github/workflows
rg -n -A 25 -i "artifacts are stale|merge-prd" .github/workflows

The verify step typically looks like:

- name: Verify committed PRD artifacts are current
  run: |
    python scripts/merge-prd.py
    if ! git diff --quiet -- docs/prd; then
      echo "docs/prd/... artifacts are stale: scripts/merge-prd.py regenerated them"
      git --no-pager diff -- docs/prd
      exit 1
    fi

3.2 Reproduce deterministically (proves drift, not flake)

cd "$(git rev-parse --show-toplevel)"
source .venv/bin/activate        # or: uv sync && source .venv/bin/activate

python scripts/merge-prd.py
git --no-pager diff -- docs/prd

git checkout -- docs/prd
python scripts/merge-prd.py
git --no-pager diff -- docs/prd   # identical -> deterministic drift

If the two diffs are identical, it is this class. If they differ run-to-run, stop: that is generator nondeterminism (pin versions, sort iteration order).

3.3 Confirm the diff is scoped to the artifacts

git status --short
git diff --stat -- 'docs/prd/*.md'    # expect: empty

Expected: M docs/prd/tatara-PRD.html only.

4. Exact fix

Do not touch the source .md.

set -euo pipefail
cd "$(git rev-parse --show-toplevel)"

# 0. Same interpreter/venv as CI.
source .venv/bin/activate        # or: uv run

# 1. Regenerate ALL generated PRD artifacts from their canonical source.
python scripts/merge-prd.py

# 2. Safety check: diff must be limited to generated artifacts, source .md untouched.
if ! git diff --quiet -- 'docs/prd/*.md'; then
  echo "ERROR: source markdown changed — this is a content change, not stale-artifact drift." >&2
  git --no-pager diff -- 'docs/prd/*.md'
  exit 1
fi
git status --short               # expect only generated .html files

# 3. Commit the regenerated artifact(s).
git add docs/prd
git commit -m "chore(prd): regenerate docs/prd/tatara-PRD.html from scripts/merge-prd.py

Committed artifact drifted from canonical generator output (nested-strong
markup, deterministic 3-line diff). Regenerated with the project venv.
Recurrence class: ci-generated-artifacts-stale-vs-generator."

Only the generator's bytes will ever pass the gate. Hand-patching the HTML guarantees failure on the next render.

If the drift came from a source commit that landed during a CI outage

Keep the (correct) source change and regenerate in that same logical fix. Never split "source edit" and "regenerated output" across two commits — that is what caused the incident.

5. Verification

5.1 Local idempotence (required before claiming done)

cd "$(git rev-parse --show-toplevel)"
source .venv/bin/activate

python scripts/merge-prd.py
if git diff --quiet -- docs/prd; then
  echo "OK: idempotent — regenerating produces no diff"
else
  echo "FAIL: generator is not idempotent" >&2
  git --no-pager diff -- docs/prd
  exit 1
fi
git status --short               # expect: clean

This proves the committed bytes are a fixed point of the generator.

5.2 Exact-head CI confirmation

git rev-parse HEAD
git push

gh run list --commit "$(git rev-parse HEAD)" --limit 5
gh run watch "$(gh run list --commit "$(git rev-parse HEAD)" --json databaseId \
  -q '.[0].databaseId')"

Done criteria:

  • [ ] python scripts/merge-prd.py leaves git diff -- docs/prd empty after the fix commit.
  • [ ] The fix commit's diff contains only generated artifacts (no .md changes).
  • [ ] The GitHub Actions run on the fix commit's exact SHA shows "Verify committed PRD artifacts are current" green.
  • [ ] A follow-up regen in a clean checkout is a no-op.

5.3 Reproduction used to validate this runbook

Exercised on a minimal replica (generator → committed hand-reformatted HTML with nested <em> inside <strong>):

verify step (pre-fix):  FAIL: ... artifacts are stale: scripts/merge-prd.py regenerated them
diff scope:             M docs/prd/tatara-PRD.html   (source .md: none)
fix commit:             chore(prd): regenerate docs/prd/tatara-PRD.html ...
post-fix regen:         OK: idempotent, empty diff
source .md check:       OK: no source .md changes
git status:             clean

6. Prevention (close the recurrence class)

  1. Single-commit rule. Land generator-source changes and regenerated outputs in the same commit. Add it to the PR template / contributor docs.
  2. Regenerate in a pre-commit hook so the artifact is staged automatically:

bash #!/usr/bin/env bash set -euo pipefail if git diff --cached --name-only | grep -qE '^(scripts/merge-prd\.py|docs/prd/.*\.(md|html))$'; then source .venv/bin/activate python scripts/merge-prd.py git add docs/prd fi

Prefer a portable pre-commit config or a make prd / uv run merge-prd target. 3. Expose a single entrypoint (make prd or scripts/merge-prd.py) referenced by both CI and hooks, so "the generator" is one command everywhere. 4. Keep the CI verify step on every PR (no path filters that skip docs/prd or the generator). 5. After any hosted-CI outage, re-run the verify step on main before trusting merges that landed during the window.

7. Quick reference

# diagnose
source .venv/bin/activate
python scripts/merge-prd.py && git --no-pager diff -- docs/prd   # deterministic?
git diff --stat -- 'docs/prd/*.md'                               # must be empty

# fix
python scripts/merge-prd.py
git add docs/prd
git commit -m "chore(prd): regenerate PRD artifacts from scripts/merge-prd.py"

# verify
python scripts/merge-prd.py && git diff --quiet -- docs/prd && echo OK
gh run list --commit "$(git rev-parse HEAD)"
