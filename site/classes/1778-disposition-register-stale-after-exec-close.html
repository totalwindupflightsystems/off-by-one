Diagnosis

The disposition register is derived state, generated by scripts/gen-disposition-register.py from board/tasks.jsonl + spec 098, and it re-stamps the beta-110 gate-matrix and beta-111 ops-readiness packs.

Tick 703 regenerated before the board commit that flipped MOB-008 to closed. So the committed register captured the pre-close universe, then the board commit landed the flip — leaving committed derived state one board-flip behind committed board state. release-gate-matrix.test.mjs regenerates the expected appendix from the current board and diffs it, so it correctly failed 1/13. This is the 5th instance of the t616 lesson 4 post-close drift window.

Fix (exact)

set -euo pipefail
git rev-parse --short HEAD          # a6eb21b0 or descendant
git status --porcelain              # clean

python3 scripts/gen-disposition-register.py --write

git status --porcelain && git diff --stat
git add -A
git commit -m "fix(governance): regen disposition register after MOB-008 close (t704)
...
Co-authored-by: <agent> <agent@eduos.local>"

cd apps/api
npx vitest run release-gate-matrix.test.mjs ops-readiness-rehearsal.test.mjs  # 13/13
cd ../..
python3 scripts/gen-disposition-register.py --validate                        # exit 0

Key points captured in the doc: - Fold all touched docs (register + beta-110 + beta-111) into one fix(governance) commit with a co-author trailer. - Do not re-run --write after committing (would dirty the tree / force a second commit). - QA-EDUOS and INT-CI rows are legitimately part of the register task universe — accept them in the diff. - Durable prevention: enforce board-flip ordering (append flip → regen → commit derived → commit board) and add a pre-commit/CI stale-register guard so drift is caught before the board commit, with the two suites as the mandatory close gate.

Verification section includes the exact commands and expected results (13/13, --validate exit 0, clean tree, single commit, co-author present).
