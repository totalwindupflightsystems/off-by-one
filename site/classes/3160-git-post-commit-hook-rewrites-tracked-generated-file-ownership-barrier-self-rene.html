Fix: post-commit hook rewrites a tracked generated file, so the checkout can never be clean and the ownership barrier blocks forever

Problem class: git-post-commit-hook-rewrites-tracked-generated-file-ownership-barrier-self-renewing

Scope: any shared repo checkout where (a) a .git/hooks/post-commit (or other hook, or a lane step) regenerates a file inside the work tree after the commit lands, (b) that file is tracked, and (c) a foreman/agent lane treats non-empty git status --porcelain as a hard ownership barrier. The barrier is self-renewing: every sibling commit re-dirties the tree, so the lane blocks on every tick (measured: 18 consecutive blocked ticks on &lt;project&gt;, ~3.5M tokens each).

1. Symptom

git status --porcelain is never empty in a shared checkout, even immediately after a supposedly clean commit. Three paths persistently appear:

Path Kind Appearance
.gitreins tracked M (record flip)
.vfs/graph/coverage.json tracked, generated M (whole-tree census)
.cache/hilo/... untracked, not ignored ??

A lane that gates on [ -z "$(git status --porcelain)" ] therefore blocks on every tick and never acquires ownership.

2. Root-cause analysis

2.1 The mechanism

.git/hooks/post-commit runs hilo graph warm --changed after each commit completes. That rewrite replaces the whole-tree census (discovered_files 701 → 24). The write lands ~1–2 s after the commit, so the post-commit snapshot the working tree was committed from is immediately invalidated.

Two independent facts make this self-renewing:

  1. A tracked file cannot be fixed with .gitignore. .gitignore only affects untracked paths. As long as .vfs/graph/coverage.json and .gitreins are in the index, git keeps reporting their modifications no matter what .gitignore says (git check-ignore prints nothing for a tracked path).
  2. A hooks-bypassed commit does not stop recurrence. git -c core.hooksPath=/dev/null commit runs no hooks, so that commit leaves the tree clean — but the next normal commit by any sibling lane sharing the checkout runs the hook again and re-arms the barrier. Filing the hook behaviour as a future work item does not stop the blocking.

2.2 Why the census is a corruption, not output

The census shrank (701 → 24). A generated artifact that loses most of its discovered set is the hook overwriting a full-tree census with a partial/changed-scope warm run. When the content diff shows a shrink, restore the committed bytes (git checkout --) — do not commit the smaller file. Only a file that merely gained lines might be legitimate output.

2.3 The three dirty sources need three different treatments

  • tracked generated file (coverage.json): git rm --cached + ignore.
  • tracked machine record (.gitreins): git rm --cached + ignore (only after a consumer scan).
  • untracked cache (.cache/...): ignore only; git rm --cached is a no-op because it was never tracked.

3. Diagnosis (discrimination steps that save tokens)

Run these against the dirty checkout before writing any fix. They are ordered so each one can rule out the entire downstream investigation.

DIRT=".gitreins .vfs/graph/coverage.json .cache/hilo/warm.idx"

# (1) Fingerprint first. Identical sha256 across two ticks proves nothing changed
#     between pastes, i.e. the previous "repeat block" paste was never executed.
sha256sum $DIRT

# (2) Tracked or untracked? Do this BEFORE editing .gitignore: a tracked path
#     can never be fixed by ignore rules.
git ls-files --error-unmatch .gitreins .vfs/graph/coverage.json   # -> tracked
git ls-files --others --exclude-standard                          # -> untracked population

# (3) Read the CONTENT diff, not just the status letter. A census that SHRANK is
#     corruption; a file that only gained lines may be legitimate output.
git diff --numstat -- .vfs/graph/coverage.json .gitreins
python3 - <<'PY'
import json, subprocess
old = json.loads(subprocess.check_output(["git","show","HEAD:.vfs/graph/coverage.json"]))
new = json.load(open(".vfs/graph/coverage.json"))
print("discovered_files HEAD=%s worktree=%s" % (old["discovered_files"], new["discovered_files"]))
PY

# (4) Name the writer and date the write.
sed -n '1,50p' .git/hooks/post-commit          # -> exec hilo graph warm --changed
CT=$(git log -1 --format=%ct)                  # commit committer time
MT=$(stat -c %Y .vfs/graph/coverage.json)      # dirty file mtime
echo "delta=$((MT-CT))s"                       # seconds => hook; minutes => separate lane step

# (5) Consumers in the tracked tree before untracking. Zero hits => git rm --cached is safe.
git grep -n -e 'coverage.json' -e '\.vfs/graph' -e '\.gitreins' -- \
  '*.go' '*.sh' '*.mk' 'Makefile' '*.yml' '*.yaml' '*.md' || echo "zero consumers"

Observed on the reproduction: delta=2s, writer named as the hook, census HEAD=701 worktree=24, zero consumers.

Step (5) is a tripwire, not a proof: a consumer that builds the path from a variable will evade a literal git grep. If a release/build step genuinely needs the census, keep it working by regenerating on demand (hilo graph warm) in a build precondition; git rm --cached leaves the current working-tree copy in place, so runtime readers are unaffected.

4. The fix

Land everything in one bookkeeping commit made with hooks bypassed, so the fix itself does not re-dirty the tree.

set -euo pipefail

# --- 0. Preflight: confirm the paths are exactly the known generated set -------
git status --porcelain -uall

# --- 1. Restore a corrupted (shrunk) generated artifact ------------------------
git checkout -- .vfs/graph/coverage.json
# only if step 3 showed a shrink and a consumer still expects the full census

# --- 2. Untrack generated artifacts (working-tree copies are preserved) --------
git rm --cached --quiet .vfs/graph/coverage.json .gitreins

# --- 3. Ignore generated artifacts AND the untracked cache in the same commit --
cat > .gitignore <<'EOF'
# generated by `hilo graph warm` on every commit; not source
.vfs/graph/
.gitreins
# local warm cache, never part of source
.cache/
EOF
git add .gitignore

# --- 4. Commit with hooks bypassed: no post-commit re-dirty --------------------
git -c core.hooksPath=/dev/null commit -m \
  "chore: untrack hilo-generated census/.gitreins; ignore cache"

# --- 5. Confirm clean right now ------------------------------------------------
test -z "$(git status --porcelain -uall)" && echo "CLEAN"

Key points:

  • git rm --cached without -f is deliberate: it removes the path from the index while leaving the file in the working tree, so any runtime reader keeps working.
  • The bypass (core.hooksPath=/dev/null) is only to make the bookkeeping commit atomic and clean. It is not the fix; the .gitignore + untracking is what stops recurrence.
  • .git/hooks/* is not version-controlled, so the durable fix must live in the tracked tree (.gitignore), not in a hand-edited hook.

4.1 Defense-in-depth: make the barrier ignore generated paths

Even after the fix, harden the barrier so a sibling re-tracking a generated path, or a new generated path, cannot block the lane again. Scope the porcelain check with pathspec exclusions:

dirty="$(git status --porcelain -uall -- . \
  ':(exclude).vfs/graph/**' \
  ':(exclude).gitreins' \
  ':(exclude).cache/**')"
if [ -n "$dirty" ]; then
  echo "ownership barrier: unexpected dirty state"; echo "$dirty"; exit 1
fi

This was verified to return empty even while .vfs/graph/coverage.json was still tracked and modified (git 2.53). Use it as a guard, not as a replacement for the untrack fix.

4.2 Optional: move generation out of the tracked tree

The true root cause is the hook writing a derived artifact into the source tree. If hilo supports an output/cache location, point it at a git-ignored or out-of-tree location (e.g. $XDG_CACHE_HOME/hilo/) so no tracked path is ever a hook target:

# illustrative only — use hilo's real config key / env var
git config --local hilo.graphCensusPath "$XDG_CACHE_HOME/hilo/coverage.json"

Since .git/hooks is per-clone, any hook change must be delivered by the tool that installs hooks (or by a committed setup script), not by editing the checkout.

5. Verification

A self-contained reproduction models the exact mechanism and asserts the outcome end-to-end. Full script is in Appendix A; run it with bash /tmp/verify.sh.

5.1 What it proves

  1. Before fix: a normal sibling commit runs the hook; git status --porcelain shows M .gitreins, M .vfs/graph/coverage.json, ?? .cache/hilo/warm.idx → barrier blocks. mtime − commit = 2s and the hook is named as the writer.
  2. Diagnosis: tracked-vs-untracked split, content shrink 701 → 24, zero tracked consumers.
  3. After fix: one hooks-bypassed bookkeeping commit; immediate porcelain is empty.
  4. Durability: three further non-bypassed sibling commits each run the post-commit hook (census in the working tree is rewritten to 24) yet porcelain stays [].
  5. Hook still runs: the census is still regenerated; it is simply untracked and ignored (.gitignore:2:.gitreins, :3:.cache/).
  6. Negative control: re-tracking the census while leaving the .gitignore rule in place makes porcelain dirty again after the next hook run — proving that ignore-only cannot fix an already-tracked path, and that untracking is the load-bearing step.

6. Rollback

If a consumer genuinely required the file to be tracked, undo in the same style (bypassed commit):

git add -f .vfs/graph/coverage.json .gitreins
git -c core.hooksPath=/dev/null commit -m "revert: re-track generated artifacts"

Then the barrier must use the pathspec-excluded form from §4.1, because a tracked hook target will re-dirty forever.

Appendix A — self-contained reproduction / verification script

Save as /tmp/verify.sh and run bash /tmp/verify.sh. It writes its sandbox to /tmp/repro and is safe to re-run (it recreates the sandbox).

#!/usr/bin/env bash
# Verifies: post-commit hook rewrites a tracked generated file -> ownership barrier.
set -euo pipefail

ROOT=/tmp/repro; BIN="$ROOT/bin"; REPO="$ROOT/repo"
export PATH="$BIN:$PATH"
hr() { printf '\n== %s ==\n' "$*"; }

rm -rf "$ROOT"; mkdir -p "$BIN" "$REPO"; cd "$REPO"
git init -q; git config user.email t@t; git config user.name t
git config commit.gpgsign false
mkdir -p .vfs/graph bin data .git/hooks .cache/hilo

python3 - <<'PY'
import json
files=[f"src/file_{i:04d}.go" for i in range(701)]
json.dump({"discovered_files":701,"files":files}, open(".vfs/graph/coverage.json","w"), indent=2)
PY
printf 'tick=0\n' > .gitreins
printf 'cache-v1\n' > .cache/hilo/warm.idx
cat > bin/tool.sh <<'SH'
#!/usr/bin/env bash
echo "tool ok"
SH
chmod +x bin/tool.sh

# fake generator: shrinks census 701 -> 24, bumps a marker, flips .gitreins
cat > "$BIN/hilo" <<'SH'
#!/usr/bin/env bash
set -euo pipefail
if [ "${1:-}" = "graph" ] && [ "${2:-}" = "warm" ]; then
  python3 - <<'PY'
import json, time
p=".vfs/graph/coverage.json"; d=json.load(open(p))
d["discovered_files"]=24; d["files"]=d.get("files",[])[:24]
d["warmed_at"]=time.time_ns()
json.dump(d, open(p,"w"), indent=2, sort_keys=True)
PY
  printf 'tick=%s\n' "$(date +%s%N)" > .gitreins
fi
SH
chmod +x "$BIN/hilo"

# hook: simulate the ~2s post-commit rewrite
cat > .git/hooks/post-commit <<'SH'
#!/usr/bin/env bash
sleep 2
exec hilo graph warm --changed
SH
chmod +x .git/hooks/post-commit

hr "0. baseline: commit ONLY intended tracked files, hooks bypassed"
git add .vfs/graph/coverage.json .gitreins bin/tool.sh
git -c core.hooksPath=/dev/null commit -qm "baseline"
echo "porcelain paths: $(git status --porcelain -uall | wc -l)  (untracked cache already visible)"

hr "1. a sibling lane commits normally -> hook re-dirties the tree"
echo "sibling change" >> data/note.txt; git add data/note.txt
git commit -qm "sibling lane commit"
for _ in $(seq 1 12); do
  [ "$(git status --porcelain -uall | wc -l)" -ge 3 ] && break; sleep 1
done
echo "--- git status --porcelain (the barrier input) ---"
git status --porcelain -uall
echo "barrier sees non-empty -> BLOCK"

hr "2. DIAGNOSE"
git ls-files --error-unmatch .vfs/graph/coverage.json .gitreins 2>&1 | sed 's/^/   tracked: /'
git ls-files --others --exclude-standard | sed 's/^/   untracked: /'
git diff --numstat -- .vfs/graph/coverage.json .gitreins
python3 - <<'PY'
import json, subprocess
old=json.loads(subprocess.check_output(["git","show","HEAD:.vfs/graph/coverage.json"]))
new=json.load(open(".vfs/graph/coverage.json"))
print(f"   discovered_files HEAD={old['discovered_files']} worktree={new['discovered_files']} -> SHRANK = corruption")
PY
sed 's/^/   /' .git/hooks/post-commit
CT=$(git log -1 --format=%ct); MT=$(stat -c %Y .vfs/graph/coverage.json)
echo "   commit=$CT census_mtime=$MT delta=$((MT-CT))s"
if git grep -n -e 'coverage.json' -e '\.vfs/graph' -e '\.gitreins' -- \
     '*.go' '*.sh' '*.mk' 'Makefile' '*.yml' '*.yaml' '*.md' 2>/dev/null; then
  echo "   !! consumers found"; exit 1
else
  echo "   zero consumers -> git rm --cached is safe"
fi

hr "3. FIX: restore, untrack, ignore, ONE bypassed commit"
git checkout -- .vfs/graph/coverage.json
echo "restored discovered_files: $(python3 -c 'import json;print(json.load(open(".vfs/graph/coverage.json"))["discovered_files"])')"
git rm --cached --quiet .vfs/graph/coverage.json .gitreins
cat > .gitignore <<'EOF'
.vfs/graph/
.gitreins
.cache/
EOF
git add .gitignore
git -c core.hooksPath=/dev/null commit -qm "chore: untrack generated; ignore cache"
echo "post-fix immediate porcelain: [$(git status --porcelain -uall)]"

hr "4. VERIFY after later NON-bypassed sibling commits"
for n in 1 2 3; do
  echo "lane-$n" >> "data/note_$n.txt"; git add "data/note_$n.txt"
  git commit -qm "sibling lane $n (hooks active)"; sleep 3
  printf 'after sibling %d: porcelain=[%s]\n' "$n" "$(git status --porcelain -uall)"
done

hr "5. VERIFY the hook still RUNS"
echo "census (working tree): $(python3 -c 'import json;print(json.load(open(".vfs/graph/coverage.json"))["discovered_files"])')"
echo "tracked? $(git ls-files --error-unmatch .vfs/graph/coverage.json 2>&1 || echo 'no (untracked)')"
echo ".gitreins ignored? $(git check-ignore -v .gitreins)"
echo "cache ignored?     $(git check-ignore -v .cache/hilo/warm.idx)"
FIXED_PORCELAIN="$(git status --porcelain -uall)"

hr "6. NEGATIVE CONTROL: ignore-only while still TRACKED"
git add -f .vfs/graph/coverage.json
git -c core.hooksPath=/dev/null commit -qm "negative control: census tracked again"
hilo graph warm --changed
echo "porcelain after hook with tracked+ignored census:"
git status --porcelain -uall
echo "(proves ignore alone cannot fix an already-tracked path)"

hr "RESULT"
echo "fixed repo porcelain after 3 non-bypassed sibling commits: [$FIXED_PORCELAIN]"
