HotStuff Chained Pacemaker with Locked-Node Safety

Root-cause analysis

Unsafe behavior in this problem class comes from several interacting missing invariants:

  1. Unverified high QCs — accepting a proposal whose carried QC is fake, sub-quorum, or for a different block.
  2. Votes that ignore the lock — allowing a replica to vote on a branch that does not extend lockedHash, especially when the proposal’s high QC is not applied before voting.
  3. A non-HotStuff commit rule — committing a block after one QC instead of the chained 3-chain rule.
  4. Loss of durable state across crashes — losing lastVoted, lockedQC, highQC, or the committed tip enables double-voting or unlocking.
  5. A non-replayable harness — randomized scheduling without a recorded event log cannot prove safety.

The fix is an explicit invariant-preserving protocol plus an event-sourced checker:

  • one vote per view, persisted before sending;
  • a vote requires a valid high QC and extension of the locked branch;
  • applying the proposal’s parent QC as a lock barrier before voting;
  • committing the ancestor at QC.Height - 2;
  • view changes driven by a verified aggregate view-change certificate;
  • deterministic simulation with reordering, phase crashes, persistence, and equivocation;
  • exhaustive log replay checking same-height uniqueness and monotone committed prefixes.

Critical vote rule:

if err := r.W.verifyBlock(b); err != nil {
    reject
}
if b.ParentQC != nil {
    r.onQC(b.ParentQC) // apply carried high QC as a lock barrier
}
if !r.extendsLock(b.Hash) {
    reject
}
if !r.LockedHash.IsZero() &&
   (b.ParentQC == nil || b.ParentQC.BlockHeight < r.LockedHeight) {
    reject
}
if prev, ok := r.LastVoted[r.View]; ok && prev != b.Hash {
    reject
}
r.LastVoted[b.View] = b.Hash
r.save() // persist before sending the vote

The single certificate gate used by both prepare QCs and view-change certificates:

func VerifyCertificate(c *Certificate, n, f int, pub []ed25519.PublicKey) error

It checks distinct signers, one valid Ed25519 signature per signer, at least n-f signers, embedded high-QC validity, and that the selected view-change high QC is the maximum present in the votes.

Chained commit rule:

if haveBlock && block.Height >= 3 {
    r.commitAncestor(block, block.Height-2, c)
}

CheckLog replays every certificate-bearing record and every commit, checking:

  • valid 3-chain justification;
  • no different block committed at the same height;
  • parent linkage to already-committed heights;
  • no replica commits decreasing heights;
  • every new commit extends that replica’s committed prefix.

MinimizeViolation delta-debugs the recorded trace and prints the smallest failing suffix/prefix.
