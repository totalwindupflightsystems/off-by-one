Answer

I reproduced all four failure modes, implemented the structural merge fix, and verified it end-to-end. The full self-contained document is at /workspace/SOLUTION.md (708 lines), with the tested tool source at /workspace/wavemerge-src/main.go and /workspace/union_additive.py.

What I did

Built a minimal Go repo (/workspace/repro) with a shared server.go and created 4 feature branches that each add a mux registration, a handler func, and a case inside the existing isV2EnvelopeRoutePath. Then reproduced each symptom against real git merge output.

Root causes (all reproduced)

  1. Shared trailing } — the conflict hunk ends inside OURS's new func; git shows the closing } as shared context, so union leaves handleA unclosed: server.go:31:6: expected '(', found handleB
  2. Interleaved 3-way diff — a text union splices two funcs together.
  3. Dropped intra-declaration hunk — a case added inside isV2EnvelopeRoutePath is lost by "new decls + mux line" extractors. The tree builds, and only the envelope test fails.
  4. Stale sibling control — a branch test asserting GET /experimental/b == 404 fails once b lands (got 200).

The fix

wavemerge (go/parser + go/ast): keeps ours verbatim, then splices in only what the branch added — new top-level decls (with doc comments), added runs inside pre-existing declarations anchored by up to 3 preceding common lines, and imported-spec union. It exits 1 if an added run can't be anchored, so nothing is dropped silently.

Per-branch runbook:

# gate the branch first: gofmt -l, go build ./..., go vet ./..., package tests
git show main:server.go      > /tmp/base.go
git show "$BRANCH":server.go > /tmp/theirs.go
go run ./tools/wavemerge -base /tmp/base.go -ours server.go -theirs /tmp/theirs.go -out server.go
# repeat for server_test.go, then:
gofmt -w server.go server_test.go
go build ./... && go vet ./... && go test ./internal/shim/opencode/...

Plus: rewrite stale sibling-404 controls to assert the sibling's own contract, and regenerate declared-vs-served JSON/YAML from the merged tree.
