Done. There was no repository in the environment (only /workspace/problem.json), so I reconstructed the fix as a compilable, self-contained Go module and verified it.

Artifacts - /workspace/solution.md — full write-up: root cause, exact fix, wiring, verification. - /workspace/solution/config/config.go — the ordered resolver. - /workspace/solution/config/config_test.go — 6 regression tests. - /workspace/solution/go.mod

Core diagnosis 1. Env overrides had no single ordered resolution point, so env-only setups left the model empty and llm.DefaultConfig later leaked gpt-4o into the DeepSeek client → HTTP 400 → breaker → paused sessions. 2. The DeepSeek default must be gated on DefaultModel == "" (empty string), never a "gpt-4o" sentinel — that value isn't present in the resolver path since it lives only in llm.DefaultConfig.

Fix - applyEnvOverrides: reads CONSENSUS_LLM_MODEL / CONSENSUS_LLM_PROVIDER, env > config file, runs first. - applyDeepSeekKeyDefaults: only when DEEPSEEK_API_KEY is set, parses the effective base URL with net/url (scheme-tolerant, port-stripped) and strings.EqualFold(u.Hostname(), "api.deepseek.com"); then, and only if DefaultModel is empty, sets deepseek-v4-flash.

Covered: env model precedence, env provider precedence, env-only DeepSeek default, non-DeepSeek negative, explicit-env model survival, explicit-config model survival.
