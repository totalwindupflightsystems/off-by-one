Empty-string content is not "missing": fixing the fresh-start seed 400 VALIDATION_ERROR

Repo: coding-hermes/auger · Fix commit: e3df3af (AUG-072) · Substrate: DuckBrain POST /api/memories (DB-GAP-058)

Symptom

A fresh auger start with no --seed / --seed-file aborts:

remember /auger/<pid>/seed failed (400): {'error': 'Missing required fields: key, domain, content', 'code': 'VALIDATION_ERROR'}

The payload clearly carries key, domain, and content, so the message sends you hunting for a dropped field that is not dropped. The project row is inserted, but the seed note is never stored/embedded and the process exits 1.

Root-cause analysis

  1. The caller posts an empty string. cmd_start derives the seed and then writes it unconditionally:

python seed = a.seed or "" # no --seed -> seed == "" ... insert(ns, "project", row) # succeeds remember(ns, f"/auger/{pid}/seed", seed) # content == "" -> 400

remember() (auger.py:614) sends {"key", "namespace", "domain", "content"} and raises SystemExit on any non-2xx, so the 400 becomes the hard failure above.

  1. DuckBrain's DB-GAP-058 gate treats MISSING and EMPTY-BLANK as the same rejection. The route's content check is effectively:

ts const contentAbsent = content === undefined || content === null || content === ""; if (!key || !domain || contentAbsent) { return res.status(400).json({ error: "Missing required fields: key, domain, content", code: "VALIDATION_ERROR", }); }

Two distinct arms — field absent and field present but blank — share one message. content: "" therefore fires the "Missing required fields" arm even though the key exists in the JSON.

  1. Why only "fresh/empty" runs trip it. With --seed/--seed-file the content is non-empty and the same code path succeeds. With no seed it is always "", so every no-seed start hits the blank-content arm.

  2. Which layer is wrong. The server gate is correct: an empty note has no text to store and nothing to embed. Fabricating placeholder content or relaxing the gate would pollute the memory index. The bug is caller-side: cmd_start must not attempt a write that has no content.

  3. Not fully atomic. insert(ns, "project", row) runs before remember, so a failed start leaves the project row behind. Skipping the empty write avoids the partial half-start entirely (the project row still lands, but nothing fails).

The exact fix

Guard the optional write on non-empty content. Commit e3df3af changed cmd_start (auger.py, ~line 3199):

     insert(ns, "project", row)
-    remember(ns, f"/auger/{pid}/seed", seed)
+    if seed:
+        # An empty seed has nothing to store or embed: POSTing it makes DuckBrain's
+        # required-content gate (DB-GAP-058) 400 the call and abort a fresh start.
+        remember(ns, f"/auger/{pid}/seed", seed)
     print(f"project {pid} in namespace {ns}")
     print(f"seed stored ({len(seed)} chars) + embedded")
     return 0

insert, remember()'s signature, and the non-empty path (store + embed + both print lines) are untouched.

# apply the one-line guard (equivalent to git cherry-pick e3df3af)
cd ~/auger
git show e3df3af -- auger.py | git apply
# or simply edit cmd_start to wrap the remember(...) call in `if seed:`

Verification

1. Regression tests (unit, no live service)

tests/test_auger.py gained two cases:

  • test_start_with_empty_seed_never_calls_remember — stubs remember/insert, runs start --id P-EMPTYSEED with no seed, asserts remember was never called and stdout says seed stored (0 chars).
  • test_start_with_a_seed_stores_and_embeds_exactly_once — runs start --seed "hello seed", asserts exactly one call ("auger-worker072-unit", "/auger/P-SEEDED/seed", "hello seed").
cd ~/auger
python3 -m pytest tests/test_auger.py \
  -k "empty_seed or a_seed_stores" -v
# 2 passed

RED proof (revert only the auger.py hunk, keep the new tests):

tests/test_auger.py::test_start_with_empty_seed_never_calls_remember FAILED
E  AssertionError: remember was called with an empty seed:
E    [('auger-worker072-unit', '/auger/P-EMPTYSEED/seed', '')]
tests/test_auger.py::test_start_with_a_seed_stores_and_embeds_exactly_once PASSED
1 failed, 1 passed

GREEN after the guard: both pass. Existing start test test_start_stores_the_project_row_and_embeds_the_seed still passes (live arm skipped without a token). ruff check auger.py tests/test_auger.py → All checks passed!; python3 -m py_compile auger.py → OK.

2. End-to-end against a faithful DB-GAP-058 stub

Because the sandbox's live DuckBrain requires an API key it does not expose, the gate was reproduced exactly with a local stub that returns, for POST /api/memories:

  • 400 {"error": "Missing required fields: key, domain, content", "code": "VALIDATION_ERROR"} when content is absent, null, or "";
  • 200 when content is non-empty.

Then auger was run with DUCKBRAIN_URL=http://<ip-address>:3909 DUCKBRAIN_API_KEY=stub-token (a /tmp server logged every request):

Run Code cmd_start invocation Result
1 unfixed start --id P-EMPTY (no seed) POST /api/memories with content=""; exits 1 with the exact 400 text
2 fixed start --id P-EMPTY (no seed) exit 0, zero /api/memories requests, prints project P-EMPTY … / seed stored (0 chars) + embedded
3 fixed start --id P-SEEDED --seed "hello seed" exit 0, exactly one /api/memories request carrying content="hello seed"

Reproducer: /tmp/verify_072.py (starts the stub, runs the unfixed and fixed scripts, asserts request counts/payloads). Output ended with ALL STUB VERIFICATIONS PASSED.

The upstream commit's own live test against <ip-address>:3000 reached the same conclusions (unfixed no-seed → the 400 line and exit 1; fixed no-seed → exit 0, no 400; fixed --seed "hello seed" → retrievable via recall at 1.000 /auger/P-.../seed).

3. Manual one-liner check

# before: prints the misleading 400 and exits 1
python3 auger.py -n scratch start --id P-TEST
# after : exit 0, "seed stored (0 chars) + embedded", no 400

General diagnostic rule

When DuckBrain answers Missing required fields: key, domain, content but the fields look present, do not hunt for missing keys first — inspect the values. An empty string ("") is rejected by the same arm as an absent key under DB-GAP-058. Confirm which arm fired by grepping the server gate:

grep -rn "contentAbsent\|Missing required fields" duckbrain/src/http/routes/memories.ts

If the misfiring value is optional content on the caller side, skip the write when it is empty; do not add placeholder text and do not weaken the server gate.

Files touched

  • auger.py — cmd_start: wrap remember(...) in if seed: (commit e3df3af).
  • tests/test_auger.py — test_start_with_empty_seed_never_calls_remember, test_start_with_a_seed_stores_and_embeds_exactly_once.

Minor non-blocking note: the fixed no-seed path still prints seed stored (0 chars) + embedded, which is cosmetically inaccurate (nothing was embedded). It is harmless and outside the scope of the 400 fix.
