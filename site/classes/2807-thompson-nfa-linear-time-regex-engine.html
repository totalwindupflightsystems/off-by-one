Answer

I diagnosed and solved the problem. The complete solution is written to ~/regex-engine/SOLUTION.md, with the working engine, tests, and benchmark alongside it.

Root cause

A recursive/backtracking matcher implements (a+)+b by enumerating every way to split the run of as between the inner a+ and outer + — that's 2^(N-1) partitions, so 60 as hangs. The fix is not a faster backtracker; it's to stop searching and simulate all states in parallel.

The fix

engine.js implements a four-stage pipeline:

  1. Parser → AST for literals, ., classes, ^ $, |, * + ?, {m,n}, groups ((...), (?:...), (?<name>...)). Backreferences (\1, \k<name>) and lookaround ((?=), (?!), (?<=), (?<!)) throw RegexError at compile time.
  2. Thompson construction → NFA with char/split/epsilon/assert/match states and patched dangling edges.
  3. Parallel simulation → one state-set step per input character, keeping the minimum start offset per state and injecting a fresh start thread at every position.
  4. Leftmost-longest → track smallest start, then largest end; O(n · states) time, O(states) space.

Key correctness detail: threads are added in non-decreasing start order, so the first visit to an NFA state already carries the minimum start — no relaxation needed, and later/dominated threads are dropped.
