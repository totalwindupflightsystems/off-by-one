Single-value Bulletproofs range proof over secp256k1 (pure Python)

Problem class: python3-bulletproofs-single-range-proof-ipa-fiat-shamir Environment: Python 3 — only integer modular arithmetic + hashlib (no external crypto packages) Files: ~/bulletproofs.py, ~/test_bulletproofs.py, ~/SOLUTION.md, ~/test_output.txt

1. Root-cause analysis — where naïve implementations break

Since the task is to build the proof from scratch, the "failure modes" are the subtle crypto bugs that make a hand-written Bulletproofs either reject honest proofs or accept forgeries:

  1. Fiat–Shamir not binding every prover message. If challenges are computed from only a subset of the proof (A, T1, T2, …), an attacker fixes the challenge in advance and forges. Fixed with a running SHA-256 Transcript where every point/scalar is absorbed and the challenge itself is folded back into the state before the next challenge.

  2. Missing Pedersen blinding in tau_x. For T1 = t1·B + τ1·H, T2 = t2·B + τ2·H, V = v·B + γ·H, the identity t_hat·B + τ_x·H = z²·V + δ·B + x·T1 + x²·T2 forces τ_x = z²·γ + τ1·x + τ2·x². Copying the paper and dropping z²·γ makes every honest proof fail. Fixed in prove.

  3. Wrong y-power folding of the H generators. The range relation requires H'_i = y^(-i)·H_i so the y^i factors cancel in <r, H'>. Both prover and verifier build this.

  4. Incorrect IPA fold / final relation. Correct fold is L = <a_L,G_R>+<b_R,H_L>+<a_L,b_R>·Q, R = <a_R,G_L>+<b_L,H_R>+<a_R,b_L>·Q, a'=u·a_L+u⁻¹·a_R, b'=u⁻¹·b_L+u·b_R, G'=u⁻¹G_L+uG_R, H'=uH_L+u⁻¹H_R, and the folded verifier check is P + Σ(u_j²L_j + u_j⁻²R_j) = a·G_f + b·H_f + (<a,b> − t_hat)·Q. Extra u factors on the Q terms or using +t_hat·Q breaks it.

  5. Range not enforced. The prover must reject v ≥ 2^64, and the verifier must never accept a truncated-bit proof. prove raises ValueError outside [0, 2^n).

  6. Statement not bound. V, n, and the generator digest are absorbed before any challenge, so proofs can't be replayed against another commitment.

2. Exact fix (core protocol in bulletproofs.py)

The library implements secp256k1 in Jacobian coordinates, deterministic hash-to-curve generators, the SHA-256 transcript, and:

Prover (RangeProof.prove)

a_L = bits(v) (n=64 bits, LE);  a_R = a_L - 1
A = α·B_blinding + <a_L,G> + <a_R,H>
S = ρ·B_blinding + <s_L,G> + <s_R,H>
y = H(A,S); z = H(y)
t(X) = <a_L - z + s_L·X,  y^n∘(a_R + z + s_R·X) + z²·2^n>
     = t0 + t1·X + t2·X²,   t0 = z²·v + δ(y,z)
T1 = t1·B + τ1·B_blinding;  T2 = t2·B + τ2·B_blinding
x = H(T1,T2)
t_hat = <l,r>,  τ_x = z²·γ + τ1·x + τ2·x²,  μ = α + ρ·x
IPA on (l, r) with H'_i = y^(-i)·H_i  proving <l,r> = t_hat

Verifier (RangeProof.verify)

recompute y, z, x, u_j from the transcript
check  t_hat·B + τ_x·B_blinding == z²·V + δ·B + x·T1 + x²·T2
reconstruct P = A + x·S − μ·B_blinding − z·<1,G> + z·<1,H> + z²·<2^n,H'>
fold P and generators with u_j
check  P_folded == a·G_folded + b·H_folded + (a·b − t_hat)·Q

All parsing/arithmetic is wrapped in try/except → False, so malformed proofs (including the point at infinity) are rejected.

4. Usage

import bulletproofs as bp
rp = bp.RangeProof(64)
v, gamma = 12345, 0xdeadbeef
V  = rp.commit(v, gamma)      # Pedersen commitment (public statement)
pr = rp.prove(v, gamma)       # Proof
assert rp.verify(V, pr)       # True
assert not rp.verify(rp.commit(v + 1, gamma), pr)   # tampered statement -> False

Why forgeries fail: tampering any proof element changes the transcript (so all later challenges change) and breaks the t_hat identity or the folded IPA equation; v = 2^64 has no 64-bit decomposition, so the honest prover refuses and the truncated-bit forgery fails the g-coefficient match against z²·V.
