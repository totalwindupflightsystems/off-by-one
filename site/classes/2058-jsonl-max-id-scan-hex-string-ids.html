Fix: jsonl-max-id-scan-hex-string-ids in .coding-hermes/board/events.jsonl

Root cause

The board log is written by multiple writers. The foreman appender emits integer ids (578, 579, 580), while a foreign/sync writer appended rows carrying 8‑hex‑char string ids ("ef6e3908"). The append helper assumed every id converts to a decimal int:

max_id = max(max_id, int(str(v)))   # dies on "ef6e3908"

Two things are wrong:

  1. int("ef6e3908") raises ValueError: invalid literal for int() with base 10. The two id sequences are independent, so they must not be combined in one integer scan.
  2. The same bare int() conversion is duplicated in the duplicate-detection pass, so fixing only the max() line still leaves a crash. Every conversion site must share one guarded helper.

Note: this is not the documented int-vs-str mix (where int(str(v)) handles "578" fine). Here the string is non-decimal, so int(str(v)) raises instead of comparing cleanly — a scan written for the documented mix still dies.

Exact fix

Create/repair the append script so one helper guards all conversion sites, and assert the max id is unique before appending:

import json

PATH = ".coding-hermes/board/events.jsonl"

def _num(v):
    """Decimal int if possible, else -1 (non-numeric id from a foreign writer)."""
    try:
        return int(str(v))
    except (ValueError, TypeError):
        return -1

def load(path=PATH):
    with open(path, encoding="utf-8") as f:
        return [json.loads(l) for l in f if l.strip()]

def append_event(path=PATH, **fields):
    rows = load(path)

    # Site 1: max scan over every row -- skip non-decimal ids.
    max_id = max((_num(r.get("id") or 0) for r in rows), default=0)

    # Site 2: duplicate-detection pass -- same guard, same helper.
    numeric_ids = [_num(r.get("id") or 0) for r in rows]
    if numeric_ids.count(max_id) != 1:
        raise SystemExit(f"refusing append: max id {max_id} occurs "
                         f"{numeric_ids.count(max_id)} times")

    new_id = max_id + 1
    line = json.dumps({"id": new_id, **fields}, ensure_ascii=False)

    # Append-only write: never rewrite existing lines.
    with open(path, "a", encoding="utf-8") as f:
        f.write(line + "\n")
    return new_id

if __name__ == "__main__":
    eid = append_event(event="appended")
    print(f"appended event id={eid}; append-only verified")

Key points:

  • _num returns -1 for "ef6e3908" (and for None/other types), so foreign ids are ignored, not crash-inducing. The numeric sequence stays independent.
  • default=0 keeps an empty file from raising max() on an empty sequence.
  • The duplicate check now uses the same _num mapping, so it can't crash on hex ids either.
  • Append via open(path, "a") guarantees an append-only edit (1 insertion, 0 deletions).
