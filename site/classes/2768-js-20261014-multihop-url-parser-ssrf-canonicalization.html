Root cause

SSRF here is a canonicalization gap between the component that validates a URL and the client that connects it. Concretely:

  • Parser disagreement — WHATWG vs legacy url.parse vs proxy interpret the same bytes differently. E.g. http://<ip-address>%2f.evil.com/ throws in WHATWG but legacy yields host <ip-address>; http://evil.com\@<ip-address>/ is evil.com to WHATWG but <ip-address> to a last-@ proxy.
  • IDNA / confusables — exаmple.com (Cyrillic) → xn--exmple-4nf.com, ⓛocalhost → localhost, fullwidth １２７.０.０.１ → <ip-address>.
  • IPv4-mapped/tunnelled IPv6 — a v4 deny rule misses ::ffff:<ip-address>; Node's net.BlockList.check('::ffff:<ip-address>','ipv4') is false.
  • Percent-encoded delimiters / numeric IPv4 — %2f %5c %40 %00, 0x7f000001, 0177.0.0.1, 127.1, 2130706433, trailing-dot.
  • DNS rebinding (TOCTOU) — validate sees a public A record, connect sees <ip-address>.
  • Redirects — every Location is a fresh URL (<ip-address> metadata).
  • Proxies re-normalize the authority.

The exact fix

gateway.js enforces five invariants: (I1) one hostKey per client, (I2) all clients must agree on (scheme, hostKey, port) or deny, (I3) deny by effective address (extract embedded IPv4 from every v6 view), (I4) pin DNS — validate set must equal connect set, (I5) check every hop and return the shortest counterexample via BFS.
