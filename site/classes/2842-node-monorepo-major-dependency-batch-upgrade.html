Answer

Batching Deferred Major Upgrades in a pnpm + Turborepo TypeScript Monorepo

Problem class: node-monorepo-major-dependency-batch-upgrade
Reference case: wojons-mythos DEP-MAJOR-002 (5 packages, ~5,200 vitest tests)

1. Root-cause analysis

Deferred majors are not one dependency change. They are independent compatibility contracts, each able to fail in a different layer:

Layer Example failure Why a bulk upgrade hides it
Runtime export shape archiver@8 removed the default callable export One bad import breaks every package importing the archive helper
Type ownership uuid now ships its own types; @types/uuid is a deprecated stub Duplicate/older type surface masks or creates errors
Native ABI better-sqlite3@13 is a native addon built for a Node ABI Works on one Node version, fails with NODE_MODULE_VERSION on another
Peer/toolchain graph @eslint/js@10 expects eslint@^10 Lint config becomes inconsistent; failures look unrelated
Verification Turbo replays a cached test result A green replay is not evidence the new tree works
Lockfile/build policy pnpm blocks dependency build scripts Install fails with ERR_PNPM_IGNORED_BUILDS, or a later native require fails
Workspace scope pnpm -r up <email> ignores non-direct dependencies The requested range silently does not land in the manifest

The relevant distinction is not “major vs minor.” It is:

  • Mechanical/safe major: public API, ABI, and type ownership used by the repo are unchanged. Range bump plus the normal battery is enough.
  • Breaking major: requires a code migration, type-package change, peer upgrade, or native rebuild. It needs its own commit/group so failures are attributable and revertible.

All packages in this monorepo are "type": "module", so ESM-only majors are safe at the module-system level. “ESM-only” is not the problem by itself; the problem is an ESM package that also changed or removed an export.

The specific breaks

  1. archiver@8 is ESM-only and dropped the default callable export.
    Its package is "type": "module" with "exports": "./index.js". Its ESM namespace contains only:

text Archiver, JsonArchive, TarArchive, ZipArchive

There is no default export. Code written for v7 such as import archiver from "archiver"; archiver("zip", opts) fails with a missing-default-export error, or archiver is not a function after interop. The v8 replacement is the named ZipArchive class:

ts const { ZipArchive } = await import("archiver"); const archive = new ZipArchive(opts);

  1. uuid owns its types now. uuid@14 ships dist/index.d.ts. @types/uuid@11 is a deprecated stub whose dependency is uuid: "*". Keeping it installs a redundant/older type surface. Remove @types/uuid when moving to uuid@^14; do not “upgrade” the stub.

  2. better-sqlite3@13 is a native-ABI change. It requires Node >=22 and must be prebuilt/rebuilt for the Node version running install and tests. The call-site API used here is unchanged: new Database(...), .pragma, .prepare still work. The risk is installation/ABI, not source code.

  3. The lint dependency graph was out of sync. @eslint/js@10 peers on eslint@^10. globals@17 and eslint-plugin-react-hooks@7 are compatible with current ESLint, but the repo had missed a fleet-wide alignment. Move the lint stack together and confirm the ESLint peer.

  4. Turbo cache is not verification. A cached test task may replay a result produced before the lockfile/manifests changed. Only a forced run with Cached: 0 cached is acceptable proof.

2. The split that works

Batch Packages Reason for grouping
1 — safe / mechanical @types/node, @types/tar, yauzl, supertest, archiver No runtime API changes except archiver’s mechanical named-export migration
2 — breaking / higher blast radius uuid@^14, nanoid@^6, remove @types/uuid, @testing-library/jest-dom@^7, eslint-plugin-react-hooks@^7, globals@^17, @eslint/js@^10, better-sqlite3@^11 -> ^13 Type ownership, native ABI, and lint peer graph

Rules:

  • One commit per group.
  • Every commit names old -> new ranges and any migration.
  • Run the same five gates after each group.
  • Push after each commit and verify remote read-back before starting the next group.
  • If a single package needs more than a mechanical migration, split it out of the group and give it its own commit.

The proven target ranges are:

Batch 1: @types/node -> ^<runtime-major> (Node 22 here), @types/tar -> ^7,
         yauzl -> ^3, archiver -> ^8, supertest -> ^7
Batch 2: uuid -> ^14, nanoid -> ^6, @testing-library/jest-dom -> ^7,
         eslint-plugin-react-hooks -> ^7, globals -> ^17,
         @eslint/js -> ^10, better-sqlite3 ^11 -> ^13

@types/node should track the major version of the CI Node runtime (^22 here). Taking the newest types major while running an older Node hides runtime API gaps; the reverse is merely conservative.

Never guess the old side. Capture it from pnpm outdated before editing and use those exact values in the commit subject.

3.2 Inventory and classification

jq -r 'to_entries[]
  | [.key, .value.current, .value.wanted, .value.latest,
     .value.dependencyType, (.value.isDeprecated|tostring)]
  | @tsv' /tmp/dep-major-outdated.json | column -t -s $'\t'

rg -n '"(archiver|@types/archiver|@types/node|@types/tar|yauzl|supertest|uuid|nanoid|@types/uuid|@testing-library/jest-dom|eslint-plugin-react-hooks|globals|@eslint/js|better-sqlite3)"\s*:' \
  --glob '**/package.json'

# If the repo uses pnpm catalogs, the version lives here:
rg -n 'catalog:|catalogs:' pnpm-workspace.yaml packages/*/package.json 2>/dev/null || true

If a dependency is declared as catalog:, bump the catalog entry in pnpm-workspace.yaml and run pnpm install; pnpm up does not edit catalog entries in every pnpm version.

Classify a package as breaking if any of these is true:

  • it removed/changed an export or constructor the repo uses;
  • it changes who owns the TypeScript types;
  • it is a native addon whose ABI must match Node;
  • it changes a peer range another installed package must satisfy;
  • it requires a config migration (ESLint flat config, test setup, etc.).

Everything else is safe and can share a commit.

3.3 Batch 1 — safe group + archiver migration

Record the old ranges for the commit message:

jq -r 'to_entries[]
  | select(.key|IN("archiver","@types/archiver","@types/node","@types/tar","yauzl","supertest"))
  | "\(.key) \(.value.current)->\(.value.latest)"' \
  /tmp/dep-major-outdated.json

Bump the group:

# Track the runtime major; Node 22 in this reference case.
NODE_MAJOR="$(node -p 'process.versions.node.split(".")[0]')"

pnpm -r --include-workspace-root up \
  "@types/node@^${NODE_MAJOR}.0.0" \
  @types/tar@^7.0.0 \
  yauzl@^3.0.0 \
  supertest@^7.0.0

pnpm -r --include-workspace-root up archiver@^8.0.0

# Only if the repo declares @types/archiver. archiver@8 does not bundle .d.ts,
# so its types package must move with it.
pnpm -r --include-workspace-root up @types/archiver@^8.0.0

pnpm -r up updates direct dependencies only. It prints a warning and ignores the requested range for a package that is not declared in a project. Check the manifest output after every up. If a package lives only at the workspace root, --include-workspace-root is required.

archiver v7 -> v8 migration

Find every import and factory call:

rg -n -C 2 "from ['\"]archiver['\"]|\barchiver\s*\(" \
  --glob '*.{ts,tsx,mts,cts,js,mjs,cjs}' .

Apply these replacements at all 7 call sites:

v7 (default callable) v8 (named class)
import archiver from "archiver" const { ZipArchive } = await import("archiver")
archiver("zip", opts) new ZipArchive(opts)
archiver("tar", opts) new TarArchive(opts)
archiver("json", opts) new JsonArchive(opts)
archiver("zip") new ZipArchive()

Before:

import archiver from "archiver";

export async function buildZip(out: NodeJS.WritableStream) {
  const archive = archiver("zip", { zlib: { level: 9 } });
  archive.pipe(out);
  archive.append("hello", { name: "hello.txt" });
  await archive.finalize();
}

After:

export async function buildZip(out: NodeJS.WritableStream) {
  const { ZipArchive } = await import("archiver");
  const archive = new ZipArchive({ zlib: { level: 9 } });
  archive.pipe(out);
  archive.append("hello", { name: "hello.txt" });
  await archive.finalize();
}

Tar and JSON use the same pattern:

const { TarArchive } = await import("archiver");
const archive = new TarArchive({ gzip: true });

const { JsonArchive } = await import("archiver");
const archive = new JsonArchive();

If a file uses more than one format, import all needed classes in one destructure:

const { ZipArchive, TarArchive } = await import("archiver");

Because every package is "type": "module", a static top-level import is also valid when the call site does not need lazy loading:

import { ZipArchive } from "archiver";
const archive = new ZipArchive({ zlib: { level: 9 } });

Do not keep the old format string as the first constructor argument. new ZipArchive("zip", opts) treats "zip" as the options object.

Audit the migration before running the gates:

# Every former factory call should now be a constructor.
rg -n "new (Zip|Tar|Json)Archive" --glob '*.{ts,tsx,mts,cts,js,mjs,cjs}' .

# No default import and no callable factory left.
! rg -n "import\s+archiver\s+from\s+['\"]archiver['\"]" .
! rg -n "\barchiver\s*\(" --glob '*.{ts,tsx,mts,cts,js,mjs,cjs}' .

The first command should report the expected 7 constructor sites; the last two should report nothing. If the constructor count is higher, verify whether the extra sites are tests or helpers; if it is lower, a call site was missed.

Batch 1 gates

set -euo pipefail

pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm lint

NO_COLOR=1 pnpm turbo run test --force --output-logs=full 2>&1 \
  | tee /tmp/gate-batch1.log

grep -Eq 'Tasks:[[:space:]]+10 successful, 10 total' /tmp/gate-batch1.log
grep -Eq 'Cached:[[:space:]]+0 cached' /tmp/gate-batch1.log

If the workspace has a different number of test tasks, change 10 to the actual total. The Cached: 0 cached check is not optional.

Commit and push:

git add -A
git status --short
git diff --cached --stat
git diff --cached -- '**/package.json' pnpm-lock.yaml

NODE_MAJOR="$(node -p 'process.versions.node.split(".")[0]')"
git commit \
  -m "chore(deps)!: batch 1 majors - @types/node <old>->^${NODE_MAJOR}, @types/tar <old>->^7, yauzl <old>->^3, supertest <old>->^7, archiver <old>->^8" \
  -m "archiver v8 is ESM-only and dropped the default callable export; migrated all 7 call sites to const { ZipArchive } = await import(\"archiver\") + new ZipArchive(opts)."

git push origin HEAD:main
git fetch origin

# Remote read-back: the push is not complete until this is zero.
test "$(git rev-list --count origin/main..HEAD)" -eq 0
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)"

Replace <old> with the values printed from dep-major-outdated.json. If the repo uses a PR workflow, push the branch, merge it, then perform the same read-back on the merged main checkout.

3.4 Batch 2 — breaking group

Bump the group:

pnpm -r --include-workspace-root up uuid@^14.0.0 nanoid@^6.0.0

# uuid >= v9 ships its own types; the @types package is now a deprecated stub.
pnpm -r --include-workspace-root remove @types/uuid

pnpm -r --include-workspace-root up \
  @testing-library/jest-dom@^7.0.0 \
  eslint-plugin-react-hooks@^7.0.0

pnpm -r --include-workspace-root up \
  globals@^17.0.0 \
  @eslint/js@^10.0.0

pnpm -r --include-workspace-root up better-sqlite3@^13.0.0

Check peer requirements that can turn this batch red:

pnpm why -r eslint
pnpm why -r @testing-library/dom
  • @eslint/js@10 peers on eslint@^10. If ESLint is older, bump it in the same commit:

bash pnpm -r --include-workspace-root up eslint@^10.0.0

  • @testing-library/jest-dom@7 peers on @testing-library/dom >=10 <11. If the repo is on 9, bump it in the same commit:

bash pnpm -r --include-workspace-root up @testing-library/dom@^10.0.0

Check uuid call sites. uuid@14 exposes named exports such as v4, validate, version, and UUID; it does not provide a default export:

rg -n "from ['\"]uuid['\"]" --glob '*.{ts,tsx,mts,cts,js,mjs,cjs}' .

Use named imports:

import { v4 as uuidv4, validate, version } from "uuid";

nanoid@6 keeps the named API used here:

import { nanoid, customAlphabet } from "nanoid";

Native smoke test for better-sqlite3@13:

node --input-type=module <<'EOF'
import Database from "better-sqlite3";

const db = new Database(":memory:");
db.pragma("journal_mode = WAL");
db.exec("CREATE TABLE t (id INTEGER PRIMARY KEY, v TEXT NOT NULL)");
db.prepare("INSERT INTO t (v) VALUES (?)").run("ok");
console.log(db.prepare("SELECT v FROM t").get());
db.close();
EOF

If the native module is missing or built for the wrong ABI:

pnpm rebuild better-sqlite3
# If pnpm still blocks the build:
pnpm approve-builds --all

The expected output is { v: 'ok' }. There is no source migration for new Database, .pragma, or .prepare; the fix is a correct Node/native build.

4. Verification

4.1 Five-gate battery

Run exactly these five gates for each batch:

Gate Command Pass condition
Lockfile pnpm install --frozen-lockfile exit 0; lockfile is up to date
Build pnpm build exit 0; every package builds
Types pnpm typecheck exit 0; no TypeScript errors
Lint pnpm lint exit 0; no new errors
Tests pnpm turbo run test --force --output-logs=full all tasks successful; 0 cached; all vitest tests pass

Reusable gate script:

#!/usr/bin/env bash
set -euo pipefail

expected_tasks="${1:-10}"
log="$(mktemp)"

pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm lint

NO_COLOR=1 pnpm turbo run test --force --output-logs=full 2>&1 | tee "$log"

grep -Eq "Tasks:[[:space:]]+${expected_tasks} successful, ${expected_tasks} total" "$log"
grep -Eq 'Cached:[[:space:]]+0 cached' "$log"
echo "all gates passed; tests were executed, not replayed"

Do not accept pnpm test alone, a worker summary, or a log containing Cached: 10 cached, 10 total. Only the forced, zero-cache run proves the new tree.

4.4 Package/runtime facts independently checked

These checks were run on Node v22.23.2 and pnpm 12.14.0 in isolated installs, separate from the target repo:

  • archiver@8.0.0 has "type": "module" and "exports": "./index.js". Its ESM namespace is exactly Archiver, JsonArchive, TarArchive, ZipArchive; default is undefined. new ZipArchive({ zlib: { level: 9 } }) constructs, and append / pipe / finalize remain available.
  • @types/uuid@11.0.0 is marked deprecated as a stub and depends on uuid: "*"; uuid@14.0.3 ships dist/index.d.ts.
  • better-sqlite3@13.0.3 declares Node >=22; its prebuilt binary loaded on Node 22 (ABI 127), and a new Database / .pragma / .prepare smoke test passed.
  • nanoid@6.0.2 declares Node ^22 || ^24 || >=26; nanoid and customAlphabet work on Node 22.
  • @eslint/js@10.0.1 peers on eslint@^10.0.0; eslint-plugin-react-hooks@7.1.1 supports ESLint through ^10; @testing-library/jest-dom@7.0.1 requires Node >=22, vitest >=0.32, and @testing-library/dom >=10 <11.

5. Rollback

If a batch fails before it is pushed:

git reset --hard <pre-batch-sha>
pnpm install --frozen-lockfile

If a batch is already pushed:

set -euo pipefail

# Revert the newer batch first.
git revert --no-edit <batch2-sha>
# or: git revert --no-edit <batch1-sha>

pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm lint
NO_COLOR=1 pnpm turbo run test --force

git push origin HEAD:main
git fetch origin
test "$(git rev-list --count origin/main..HEAD)" -eq 0

If only archiver@8 is the problem, revert its batch and then re-apply the safe packages without archiver in a fresh commit, or pin archiver@^7 and restore the v7 default import. Do not force-push a shared main.
