Fix: http.client requests rejected 403 by the strict header allowlist (Accept-Encoding: identity)

Summary

A stdlib loopback gateway enforced an exact HTTP header allowlist before authorization. Every request made with http.client.HTTPConnection was rejected with 403 because CPython's client unconditionally appends an implicit Accept-Encoding: identity header in HTTPConnection.putrequest() (unless skip_accept_encoding=True). identity was not on the allowlist, so the gate fired before the credential resolver ever ran. The fix special-cases only Accept-Encoding: identity inside the header gate, leaves compression codings and upstream-override headers denied, and keeps the gate ahead of the credential resolver.

Root cause

http.client.HTTPConnection.putrequest() contains (CPython 3.11+):

# we only want a Content-Encoding of "identity" since we don't
# support encodings such as x-gzip or x-deflate.
if not skip_accept_encoding:
    self.putheader('Accept-Encoding', 'identity')

A plain request

conn = http.client.HTTPConnection("<ip-address>", port)
conn.request("GET", "/", headers={"Authorization": "Bearer good-token"})

puts Host, Authorization, and the implicit Accept-Encoding: identity on the wire. The exact allowlist accepted host/authorization but had no accept-encoding entry, so it returned 403 at the gate. The same request with skip_accept_encoding=True succeeded, proving the implicit header was the sole cause.

Constraints that must be preserved:

  1. Compression stays refused: gzip, deflate, br, or lists like identity, gzip must not be tolerated.
  2. Denial ordering is unchanged: malformed / unknown / upstream-override headers are still rejected before the credential resolver, and the general allowlist is not widened.

The exact fix

Special-case the implicit header rather than adding it to the allowlist:

+IDENTITY_ENCODING = "identity"
+
 def check_headers(headers):
     for raw_name, value in headers:
-        name = raw_name.lower()
+        name = raw_name.strip().lower()
+        value = value.strip()
+
+        # http.client.putrequest() emits `Accept-Encoding: identity`
+        # unconditionally. Tolerate exactly that implicit value; every other
+        # content coding stays denied.
+        if name == "accept-encoding":
+            if value.lower() != IDENTITY_ENCODING:
+                raise HeaderDenied(
+                    f"content-coding negotiation refused: {value!r}"
+                )
+            continue

         if name in UPSTREAM_OVERRIDE_HEADERS:
             raise HeaderDenied(f"upstream override header refused: {name}")
         if name not in ALLOWED_HEADERS:
             raise HeaderDenied(f"header not on allowlist: {name}")

ALLOWED_HEADERS is not modified — accept-encoding stays out of it. The special case continues, cannot smuggle other headers, and runs after malformed-name/value checks but before the general allowlist and upstream-override checks.

Do not: - add "accept-encoding" to ALLOWED_HEADERS (would accept gzip/deflate); - move header validation after the credential resolver; - trust X-Forwarded-* / Forwarded / Via / X-Real-IP.

A caller-side workaround (skip_accept_encoding=True) fixes only one client, so fix the gateway.

3. Manual sanity check (verified 200 / 403)

import http.client, gateway
srv, _ = gateway.serve(accept_identity_encoding=True)
h, p = srv.server_address
try:
    c = http.client.HTTPConnection(h, p, timeout=5)
    c.request("GET", "/", headers={"Authorization": "Bearer good-token"})
    print(c.getresponse().status)   # 200
    c.close()
    c = http.client.HTTPConnection(h, p, timeout=5)
    c.request("GET", "/", headers={"Accept-Encoding": "gzip"})
    print(c.getresponse().status)   # 403
    c.close()
finally:
    srv.shutdown(); srv.server_close()
