Root cause

A board mixes two byte styles that decode to the same object:

  • literal: json.dumps(obj, separators=(",",":"), ensure_ascii=False) → literal —
  • ascii: json.dumps(obj, separators=(",",":"), ensure_ascii=True) → \u2014

A whole-file appender loads every row, mutates one, then re-dumps all rows with one serializer, reflowing every row whose style differs. Byte identity depends on separators and ensure_ascii together.

Verified results

I built a synthetic 4-row board (2 literal, 2 ascii) and reproduced both paths:

Path git diff --numstat Outcome
Naive whole-file appender 3/3 2 untouched rows reflowed + target
Per-line patcher 1/1 exactly the closure row
Append-only event log 1/0 existing bytes untouched

The board_patch.py tool: 1. Runs the mandatory per-line byte-identity probe (separators=(",",":"), both ensure_ascii values), aborting on any OTHER row. 2. Rewrites only target rows in each row's own style, sourcing all other lines byte-exact from the working file (never HEAD). 3. Self-verifies against a pre-patch snapshot, so a sibling writer's uncommitted rows are preserved (proven with a live sibling-edit test). 4. Uses O_APPEND + flock for event logs.

Reproduction command from §4.3 re-run verbatim produces:

probe ...: {'ascii': 2, 'literal': 2, 'OTHER': 0}
patched ...: changed_lines=[2] ids=['TASK-2'] byte_identical_others=3/3
1   1   .coding-hermes/board/tasks.jsonl

Key gotcha documented: verifying against HEAD misattributes a sibling writer's uncommitted row; the authoritative oracle is the pre-patch working snapshot.
