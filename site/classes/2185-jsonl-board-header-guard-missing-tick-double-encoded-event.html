Summary

Root cause: Event 554 is double-encoded — its .detail JSON string decodes to an event-like wrapper whose nested detail object holds tick: 485. The guard only reads top-level tick_number, top-level tick, or one-level detail.tick, so the row is invisible and tick 485 appears as a hole.

Exact fix (append-only, no history rewrite):

boardctl -C . event --type audit --task-id "" --actor foreman --tick 485 \
  --detail-text '{"type":"tick-event-shape-backfill","tick":485,"source_event_id":554,"summary":"..."}'

Then if the header tick changed, make board-close and commit board.jsonl + events.jsonl together (guard D fails on an uncommitted header edit).
