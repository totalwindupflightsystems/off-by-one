Fix: permission denied for sequence <table>_id_seq (SQLSTATE 42501) under SET ROLE

Problem class: postgres-role-missing-usage-on-sequences Environment: PostgreSQL 16 (pgvector/pgvector:pg16); Go service whose AfterConnect hook runs SET ROLE app_role and sets an RLS GUC.

Symptom

After a migration that grants table privileges, every insert into a table with a bigserial primary key fails:

ERROR:  42501: permission denied for sequence documents_id_seq
LOCATION:  nextval_internal, sequence.c:652

Root cause

PostgreSQL keeps separate ACLs per object kind. GRANT ... ON ALL TABLES walks pg_class entries whose relkind is a table/view/foreign table and rewrites only their relacl. Sequences are relkind = 'S' and have their own relacl, so a table-only grant never touches them.

bigserial expands to:

id bigint NOT NULL DEFAULT nextval('documents_id_seq')

and the sequence functions require:

Sequence function Required privilege (at least one)
nextval() USAGE or UPDATE
currval(), lastval() USAGE or SELECT
setval() UPDATE

The table owner (migration role) can use the sequence implicitly, but app_role cannot. Because the service runs every connection under SET ROLE app_role, every insert reaches nextval() as app_role and is denied.

Verified reproduction:

GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_role;  -- misses sequences
SET ROLE app_role; SET app.tenant_id='…';
INSERT INTO documents(tenant_id, body) VALUES ('…','hello');
-- ERROR: 42501: permission denied for sequence documents_id_seq

The fix

Add a new numbered migration (never edit an applied one) granting sequence privileges catalog-wide, and cover future sequences too:

-- migrations/0002_grant_app_role_sequence_usage.sql
BEGIN;

-- 1. Existing sequences in public.
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_role;

-- 2. Future sequences created by the migration role.
ALTER DEFAULT PRIVILEGES FOR ROLE app_owner IN SCHEMA public
    GRANT USAGE, SELECT ON SEQUENCES TO app_role;

COMMIT;

Apply: psql "$DATABASE_URL" -f migrations/0002_grant_app_role_sequence_usage.sql

Notes: - USAGE is what nextval() needs; SELECT covers currval()/ORM introspection. Do not grant UPDATE/ALL (that would allow setval). - ON ALL SEQUENCES IN SCHEMA is point-in-time; ALTER DEFAULT PRIVILEGES closes the future-sequence hole for the named creator role(s). - GENERATED … AS IDENTITY sequences are internally managed, need no USAGE, and are excluded from information_schema.sequences (via pg_depend.deptype='i'). This fix targets explicit serial/bigserial. - No Go change needed for the defect; the service login role just needs membership in app_role.

Verification

1. Catalog check (authoritative — run as owner/superuser)

information_schema.sequences is privilege-filtered, so querying it as app_role can return 0 rows and pass vacuously.

-- Should return 0 rows.
SELECT s.sequence_name
FROM information_schema.sequences s
WHERE s.sequence_schema = 'public'
  AND NOT has_sequence_privilege('app_role', s.sequence_name, 'USAGE');

Exhaustive variant that excludes identity sequences (which need no grant):

-- Should return 0 rows.
SELECT c.oid::regclass AS seq
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE c.relkind = 'S'
  AND n.nspname = 'public'
  AND NOT EXISTS (
      SELECT 1 FROM pg_depend d
      WHERE d.classid = 'pg_class'::regclass
        AND d.objid = c.oid AND d.deptype = 'i'
  )
  AND NOT has_sequence_privilege('app_role', c.oid, 'USAGE');

2. Behavioral probe (always SET ROLE + set the RLS GUC)

BEGIN;
SET LOCAL ROLE app_role;
SET LOCAL app.tenant_id = '11111111-1111-1111-1111-111111111111';
INSERT INTO documents (tenant_id, body)
VALUES ('11111111-1111-1111-1111-111111111111', 'probe') RETURNING id;
ROLLBACK;

before fix:  ERROR: 42501: permission denied for sequence documents_id_seq
after fix:   INSERT 0 1   (id returned)

3. Layer-attribution gotcha (RLS vs. sequence) — verified nuance

  • For a classic bigserial/serial default, nextval() is evaluated during tuple projection before the RLS WITH CHECK (ExecWithCheckOptions). The sequence 42501 surfaces whether or not the GUC is set.
  • The RLS-first ordering does occur for GENERATED … AS IDENTITY PKs: without the GUC the insert reports new row violates row-level security policy, and with the GUC it succeeds (identity sequences need no grant).
  • Rule: always run the probe with the RLS GUC set and confirm with the catalog query — never infer the layer from a GUC-less probe or one run as the app role.

4. Future-sequence check

-- as app_owner
CREATE TABLE notes (id bigserial PRIMARY KEY, tenant_id uuid NOT NULL, body text);

SELECT sequence_name, has_sequence_privilege('app_role', sequence_name, 'USAGE')
FROM information_schema.sequences WHERE sequence_schema = 'public' ORDER BY 1;
-- documents_id_seq | t
-- notes_id_seq     | t

5. Go regression test (env-gated, skips when unset)

package seqprivtest

import (
    "database/sql"
    "os"
    "testing"

    _ "github.com/lib/pq"
)

// Connect with a migration/owner (or superuser) URL: information_schema.sequences
// is privilege-filtered and would otherwise return zero rows and pass vacuously.
func TestAllPublicSequencesGrantUsage(t *testing.T) {
    dsn := os.Getenv("TEST_DATABASE_URL")
    if dsn == "" {
        t.Skip("TEST_DATABASE_URL not set; skipping sequence-privilege regression test")
    }
    role := os.Getenv("APP_ROLE")
    if role == "" {
        role = "app_role"
    }

    db, err := sql.Open("postgres", dsn)
    if err != nil {
        t.Fatalf("open: %v", err)
    }
    defer db.Close()

    rows, err := db.Query(`SELECT s.sequence_name
        FROM information_schema.sequences s
       WHERE s.sequence_schema = 'public'
       ORDER BY s.sequence_name`)
    if err != nil {
        t.Fatalf("list sequences: %v", err)
    }
    var seqs []string
    for rows.Next() {
        var name string
        if err := rows.Scan(&name); err != nil {
            t.Fatalf("scan: %v", err)
        }
        seqs = append(seqs, name)
    }
    if err := rows.Err(); err != nil {
        t.Fatalf("iterate: %v", err)
    }
    if len(seqs) == 0 {
        t.Fatalf("no sequences in public; wrong database or insufficient visibility")
    }

    for _, seq := range seqs {
        var ok bool
        if err := db.QueryRow(
            `SELECT has_sequence_privilege($1::name, $2::text, 'USAGE')`,
            role, seq).Scan(&ok); err != nil {
            t.Fatalf("has_sequence_privilege(%s, %s): %v", role, seq, err)
        }
        if !ok {
            t.Errorf("role %q lacks USAGE on sequence %q", role, seq)
        }
    }
}

Checklist

  • [ ] New numbered migration grants USAGE, SELECT ON ALL SEQUENCES IN SCHEMA ….
  • [ ] ALTER DEFAULT PRIVILEGES FOR ROLE <migration_role> covers future sequences.
  • [ ] Catalog query (as owner/superuser) returns 0 rows.
  • [ ] Behavioral probe under SET ROLE + RLS GUC succeeds.
  • [ ] Go regression test in CI with an owner URL, skipping when unset.

What I actually verified (live PG18; same ACL semantics as PG16): the 42501 repro, the fix, has_sequence_privilege catalog checks, ALTER DEFAULT PRIVILEGES covering a post-fix bigserial, the identity-PK RLS-first ordering, the vacuous-pass of the privilege-filtered view, and the Go test passing/failing/skipping. One correction to the problem's framing, verified and documented rather than repeated: for a classic bigserial default nextval() runs before the RLS WITH CHECK, so RLS does not mask the sequence error there — it only reorders for identity PKs, which don't need the grant. The fix and the mandatory "set the GUC + run the catalog check" probe design are unaffected.
