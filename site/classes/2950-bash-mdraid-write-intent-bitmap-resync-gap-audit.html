Answer

Done. I diagnosed the failure mode, built a strictly read-only auditor, and verified it against deterministic fixtures. The full solution is written to ~/md-bitmap-gap-audit.md (title, root-cause analysis, the complete tool, and verification).

Root cause

The internal write-intent bitmap is replicated to every in-sync member by write_sb_page(), each with its own copy of the bitmap superblock. bitmap_end_write() advances events_cleared to mddev->events as soon as a write completes, but the bitmap-superblock write is asynchronous, while the md superblock (which bumps events) can land first. If power fails in between, the durable state is:

md sb     : events = N+1
bitmap sb : events = N, events_cleared = N
bitmap bits: the in-flight region is already clear

On reassembly bitmap_load() takes start = resync_offset (often MaxSector) whenever degraded == 0, so md_bitmap_init_from_disk() marks nothing and the stale region is silently trusted. The kernel compounds this by tolerating an event-counter difference of exactly one (if (ev1 + 1 < mddev->events) return -EINVAL;) and accepting an older device when ev1 >= bitmap.events_cleared.

Discriminator: genuinely clean ⇔ events == events_cleared == array events and an empty bit map; lost dirty region ⇔ an all-clean bit map but events_cleared < array events (or a +1 lagging member).

The fix (tool)

~/md-bitmap-gap-audit.sh parses /proc/mdstat, md/{bitmap,sync,dev-*} sysfs, and each member's raw v1 + bitmap superblock (event counters, resync_offset/recovery_offset, bad-block log, dirty bits). It never writes, tolerates missing/removed members, and emits JSON with per-device offset ranges plus a provenance[] list of every read with UTC timestamps.

sudo ./md-bitmap-gap-audit.sh --out /var/tmp/md-audit.json   # live, read-only
MD_COMPARE=1 ./md-bitmap-gap-audit.sh                        # add byte-for-byte ranges

Exit codes: 0 clean · 2 gap suspected · 3 resync/known-dirty · 4 inconclusive.

Verification

tests/make_fixtures.py builds synthetic member images and a fake sysfs tree reproducing the exact on-disk layout; tests/run.sh asserts five scenarios. Sequential re-run, shellcheck-clean:

PASS clean                 (rc=0, GENUINELY_CLEAN)
PASS lost-dirty-gap        (rc=2, LOST_DIRTY_REGION_SUSPECTED)
PASS event-behind-tolerated(rc=2, LOST_DIRTY_REGION_SUSPECTED)
PASS known-dirty           (rc=3, KNOWN_DIRTY_PENDING)
PASS missing-member        (rc=4, INCONCLUSIVE_MISSING_MEMBER)
== 5 passed, 0 failed ==

On the incident fixture the auditor returns hypothesis_supported: true, classifies both members bitmap_lag (events=42, events_cleared=41, empty map), and with MD_COMPARE=1 pins the stale extent to array sectors [4096, 4224). The v1/bitmap-superblock offsets in the tool were derived from the actual kernel headers (md_p.h) and md-bitmap.h semantics, so it works without mdadm and on a real host as well.

Artifacts: md-bitmap-gap-audit.md, md-bitmap-gap-audit.sh, tests/make_fixtures.py, tests/run.sh.
