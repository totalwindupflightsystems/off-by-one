Answer

The fix: a self-contained, reproducible live-smoke battery that owns the echo harness lifecycle and asserts HTTP status codes — incorporating every lesson from tick #164. Three structural rules are encoded, not assumed:

  1. Assert curl -w '%{http_code}', never curl's exit code — a 404/400 response body still exits 0.
  2. Restart the server per battery run — EchoHarness.responseCount is a global shared-instance counter: the first 2 result calls ever return echo-002 then echo-end; all later calls return echo-end. The script kills any stale server on :9191 so the counter starts at 0 and the result end-flow checks (echo-002 → echo-end → echo-end) are deterministic.
  3. Rebuild examples/echo/echo-server from source before smoke — the checked-in binary may predate route changes; the binary is gitignored so building dirties nothing.

Core of the battery (smoke-battery.sh):

PORT=9191; BASE="http://127.0.0.1:${PORT}"; PASS=0; FAIL=0

# lesson 4: binary is gitignored -> rebuild dirties nothing
go build -o echo-server ./echo   # from the sdk-go repo root, not /tmp

# lesson 2: kill anything on :9191 so the GLOBAL counter resets (refuse stale)
STALE_PID=$(lsof -ti tcp:${PORT} 2>/dev/null)
[ -n "${STALE_PID}" ] && kill "${STALE_PID}"
./echo-server "127.0.0.1:${PORT}" & SERVER_PID=$!
trap 'kill "${SERVER_PID}"' EXIT
# wait for /health ...

# lesson 1: return the STATUS CODE; assert it, not curl's exit
http() { curl -s -o "$BODY" -w '%{http_code}' -X "$1" "${BASE}$2" ${3:+-d "$3"}; }
expect_status() {  # name expected actual
  [ "$3" = "$2" ] && PASS=$((PASS+1)) || { FAIL=$((FAIL+1)); }
}

# result end-flow: first 3 result calls on a FRESH server, in order:
S=$(http POST /v1/result --data "{\"session_id\":\"$SID\"}")
[ "$(jq -r .result "$BODY")" = "echo-002" ] && pass "result #1 == echo-002" || fail ...
# ... #2 and #3 must both be "echo-end"; any result on a missing session -> 404

# cancel / result require an existing session (lesson 3):
expect_status "cancel missing session -> 404" 404 "$(http POST /v1/cancel --data '{"session_id":"ghost"}')"
expect_status "invalid body -> 400"           400 "$(http POST /v1/process --data '{broken')"

**Edge cases tested, and why each lesson is required (verified live):**

- **Status-vs-exit trap (lesson 1):** `curl -X POST /v1/result -d '{"session_id":"ghost"}'` → HTTP **404** body `{"error":"SESSION_NOT_FOUND"}`, but **curl exit code 0**. An exit-code-only check would report success on a broken session.
- **Global counter trap (lesson 2):** on a fresh server, first 3 result calls returned exactly `echo-002, echo-end, echo-end`; a 4th call on the *same un-restarted* server returned `echo-end`, so a battery re-run without restart would fail its `echo-002` assertion. The script's `lsof`-kill guarantees a reset per run.
- **Session-required (lesson 3):** cancel/result on a never-created and on a deleted session both → 404; empty `session_id` → 400.
- **Unicode:** `héllo wörld 世界 🚀` survives JSON encode/decode byte-exact.
- **Streaming:** SSE starts with a data chunk and closes with the `echo-end` terminator.
- **Rebuild (lesson 4):** the script builds before smoke; failure to bind/health after rebuild fails fast with exit 2.
