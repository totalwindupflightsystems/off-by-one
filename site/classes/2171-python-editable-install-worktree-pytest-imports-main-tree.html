Silent import shadowing: PEP 660 editable install + git-worktree wave dispatch

Problem class: python-editable-install-worktree-pytest-imports-main-tree Environment: Python 3.10/3.11/3.14, setuptools or hatchling PEP 660 editable install (__editable___<pkg>_<ver>_finder.py and/or __editable__.<pkg>-<ver>.pth), pytest pythonpath=['.'], parallel git-worktree dispatch.

Symptom: worktree edits appear ignored; tests pass while validating main-tree code. No traceback — only pkg.__file__ reveals it.

1. Root cause

An editable install bakes absolute paths of the original checkout into the venv. Two mechanisms, both absolute:

Mechanism Resolution Location
finder (flat layout) MAPPING = {'pkg': '/abs/main/pkg'} installed via .pth → install() sys.meta_path.append(_EditableFinder) — after PathFinder
simple .pth (src layout) .pth contains /abs/main/src appended to sys.path at startup

Because the finder is appended after PathFinder, resolution is context-dependent:

  • Unrelated cwd (/tmp, worktree subdir): PathFinder finds nothing → editable finder → main tree.
  • Bare python from worktree root: '' on path → PathFinder → worktree.
  • pytest with pythonpath=['.'] from worktree root: worktree root at sys.path[0] → PathFinder wins → worktree.
  • pytest without pythonpath: appended finder → main tree silently.
  • src/ layout is NOT saved by pythonpath=['.']: worktree root doesn't contain the package; the absolute main src .pth wins → main tree always.
  • python -m pytest from the root masks it (the -m flag adds cwd), which is why it's silent.

Verified live

$ cd /tmp && main/.venv/bin/python -c "import mypkg"      -> /tmp/er/main/mypkg   main-tree
$ cd wt   && main/.venv/bin/python -c "import mypkg"      -> /tmp/er/wt/mypkg     worktree
$ cd wt/tests && main/.venv/bin/python -c "import mypkg"  -> /tmp/er/main/mypkg   main-tree
$ cd wt   && pytest  (no pythonpath)                      -> /tmp/er/main/mypkg   main-tree  <-- BUG
$ cd wt   && pytest  (pythonpath=['.'])                   -> /tmp/er/wt/mypkg     worktree
src/ layout, WITH pythonpath=['.']                        -> /tmp/er2/main/src/spkg/__init__.py  main-src  <-- still BUG

Finder source proving the append:

def install():
    if not any(finder == _EditableFinder for finder in sys.meta_path):
        sys.meta_path.append(_EditableFinder)

2. Exact fix

Step 1 — Probe from a neutral cwd. Run probe_editable.py (full script in the file) with the venv python:

cd / && /path/to/repo/.venv/bin/python /path/to/probe_editable.py

It detects both the meta-path MAPPING and simple .pth source roots and prints resolved paths — the ground truth.

Step 2 — Add a worktree import guard test (full snippet in the file) that asserts PackedPath(mypkg.__file__).is_relative_to(git_root). Turns silent shadowing into a loud failure.

Step 3 — Foreman dispatch rules: - (a) Probe before every wave. - (b) Test/script-only diff on a flat layout: symlink $MAIN/.venv into the worktree, then verify in-worktree pytest resolves the worktree package (safety comes from pythonpath=['.'] beating the appended finder). - (c) Any engine/package diff — or any src/ layout — needs a real per-worktree venv: uv venv --system-site-packages .venv && uv pip install -e . --no-build-isolation --python .venv/bin/python. pythonpath=['.'] can't cover src/, plugins, entry points, namespaces, extensions, or dist-info. - (d) Check wrappers with rg -n 'VIRTUAL_ENV|\.venv|sys\.prefix|--project|uv run' Makefile justfile .github scripts.
