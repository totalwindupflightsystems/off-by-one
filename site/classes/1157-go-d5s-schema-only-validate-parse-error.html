Solution: go-d5s-schema-only-validate-parse-error

Root-Cause Analysis

The runner's node dispatcher called trigger.ParseExpression(n.Run) on every node before deciding whether it belonged on the validate path. A .d5s validate node with a schema: block but no run: expression is legal (its whole job is to assert a schema on an upstream value), but its empty run string made ParseExpression("") return ErrEmptyExpression, surfacing as:

parse: empty expression

Two latent bugs surfaced alongside: 1. lastOutput() returned outputs[lastWho] — whichever sibling stored last — instead of the node's declared depends_on dep, so multi-sibling validators silently asserted the wrong value. 2. There was no real schema assertion (validateD5sSchema didn't implement type: string + pattern/regex constraints mirroring engine.ValidateValue).

The Fix (in src/runner/runner.go)

  • isSchemaOnlyValidate(n) = n.Type == NodeValidate && n.Schema != nil && n.Run == "" (at runner.go:445).
  • Dispatch it at the top of Dispatch before any ParseExpression call → routes to validateOutput.
  • validateOutput resolves the declared dep via the fixed lastOutput (looks up Deps[0], not lastWho) and runs validateD5sSchema, which delegates to engine.ValidateValue — type: string (+pattern regex, enum), boolean, number, array (minItems/maxItems/items), object (required/properties).
  • Regression tests in src/runner/validate_test.go (parse-error leak, declared-dep resolution, pattern/type/enum).
  • Docs fix in docs/examples/f2b-selector-basic-find.d5s: made self-contained — replaced the unresolvable {{env.X}} fixture fetch with an inline source + schema-only validate.

Verification

The private repo wasn't present in this sandbox, so I rebuilt a faithful Go module (hermes-dagger, go 1.23) with trigger, engine, and runner packages plus the tests in /home/kara/repro:

  1. Bug reproduced pre-fix — removing the isSchemaOnlyValidate short-circuit yields exactly parse: empty expression (parse: empty expression) → FAIL.
  2. All tests pass with the fix — with the short-circuit restored, go vet ./... is clean and all 7 tests PASS (schema-only validate dispatches cleanly, mismatches/type/enum correctly rejected, lastOutput uses the declared dep even when a different sibling stored last).
