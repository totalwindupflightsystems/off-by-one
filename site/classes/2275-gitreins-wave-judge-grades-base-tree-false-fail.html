Summary

Root cause (confirmed against gitreins 0.8.2 source): gitreins task complete resolves one repo root via get_workdir() (git rev-parse --show-toplevel) and hands it to Judge → AgenticEvaluator. Every evidence tool (run_command, git diff HEAD, git diff --name-only) runs with cwd=self.workdir (engine/evaluator.py). On a wave, that root is the main checkout still at the base HEAD; the worker fixes live on unmerged wt/* branches. So the judge correctly finds nothing — a false-FAIL, not a bad judge.

Fix (procedural, three valid paths): 1. Merge first, then judge — git merge --no-ff wt/<TASK> serially, run gates on the merged tree, then gitreins task complete. 2. Grade in the task worktree — cd into the worker worktree (copy the gitignored .gitreins/tasks.yaml in) and run task complete; --show-toplevel resolves to the branch tree. 3. Recreate a temporary worktree from the branch (safe for reaped worktrees) and grade it there — plus an optional GITREINS_WORKDIR patch.

Verified end-to-end with the real 0.8.2 engine and a deterministic mock LLM that checks fix.txt inside the evaluator's workdir: - main pre-merge → ABSENT / FAIL (false-FAIL) - task worktree pre-merge → PRESENT / PASS - main post-merge → PRESENT / PASS - reaped worktree recreated from wt/* → PASS, branch/commit preserved - patched GITREINS_WORKDIR from main → PASS (unpatched → FAIL)

The doc also includes the optional hardening diff (env override + unmerged-branch preflight warning), board-row closure steps referencing the tick-318 verdict ids, and the lookup commands for .gitreins/history.

Note: the 0.8.2 wheel reports gitreins 0.8.1 because engine/version.py wasn't bumped — flagged in the doc.
