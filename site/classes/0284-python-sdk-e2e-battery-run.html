python-sdk-e2e-battery-run

Answer

Root cause. The shipped src/h3_harness/examples/echo.py breaks the 43-test battery in two ways: 1. No top-level app — the FastAPI app is built only inside if __name__ == "__main__":. uvicorn module-import serving (uvicorn h3_harness.examples.echo:app) fails with Attribute "app" not found in module ..., and the harness loader requires an importable app object. 2. Hardcoded 0.0.0.0:8000 — collides with dexdat-api → [Errno 98] address already in use.

Plus the operational trap: batteries run against root _run_*.py temp scripts (app in __main__, add_middleware omitted) yield a false 40/43.

Fix — wrapper script with a module-level app on a dedicated loopback port:

# src/h3_harness/examples/serve_echo.py
from fastapi import FastAPI
from h3_harness import EchoHarness, add_middleware, create_router

app = FastAPI(title="h3-echo-example", version="0.1.0")
app.include_router(create_router(EchoHarness()))   # FastAPI + router + harness
add_middleware(app)                                # CORS + per-request X-Request-Id

if __name__ == "__main__":
    import uvicorn
    uvicorn.run("h3_harness.examples.serve_echo:app",   # string re-import
                host="127.0.0.1", port=8777, reload=False)

uvicorn h3_harness.examples.serve_echo:app --host 127.0.0.1 --port 8777
h3-test --endpoint http://127.0.0.1:8777    # -> BATTERY echo: 43/43

Never run the battery against root _run_*.py temp scripts — they omit add_middleware and produce the false 40/43 signal. The broken echo.py (app only in __main__, port 8000) must be replaced by this wrapper.

Evidence & signatures

Verified live (fastapi 0.141.1 / uvicorn 0.52.0 / httpx 0.28.1, Python 3.14.4) with a faithful reproduction of the SDK layout at `/tmp/h3sdk` (`h3_harness/{harness,router,middleware}.py`, `examples/{echo,serve_echo}.py`, `h3_shim/cli.py` implementing the same `h3-test` entry contract with the full 43-test echo battery).

- **Both reported failures reproduced:** `uvicorn h3_harness.examples.echo:app` → `Attribute "app" not found in module "h3_harness.examples.echo"`; `python echo.py` → `[Errno 98] address already in use` on port 8000. The collision is **real in this environment**: `127.0.0.1:8000` was already bound by dexdat-api before any of my processes ran (`/health`→200, `/docs`→200, `/openapi.json`→200, `/`→404); even my mock got `Errno 98`.
- **Fixed wrapper → 43/43, exit 0** on `http://127.0.0.1:8777` (all 43 PASS including the 3 middleware tests). Both `uvicorn serve_echo:app` and `python -m h3_harness.examples.serve_echo` (string re-import) pass. `ss -tlnp` confirms **loopback-only** binding `127.0.0.1:8777`.
- **False 40/43 reproduced exactly:** `_run_echo_debug.py` (no `add_middleware`, ad-hoc port 8778) → `BATTERY echo: 40/43` — the 3 middleware assertions fail while 40 pass.
- **Edge cases:** no server → honest `0/43` exit 1; CORS spec-compliance (header only emitted when `Origin` is sent — the test must send it like a browser; initial test omission gave 42/43, fixed the test, then 43/43); unicode bodies/paths; 100 KB payloads; HEAD→200 empty; 204 no-body; malformed JSON→400; unknown routes→404; multi-value query grouping; concurrent 8777/8778 servers coexist; all test processes cleaned up afterward.
