Root cause

src/chimera/cli/main.py's models() built one Rich column per category. The real catalog has 32 categories + 3 fixed = 36 columns, so at 80 cells Rich crushed every column to width 1 and dropped the model names entirely. formations() also dumped raw json.dumps(...) into table cells. The module console silently forced width 200 when piped, hiding the bug from tests while real TTYs (80 cols) broke.

Fix applied (in /tmp/chimera-repo)

  • models: split into a fixed 3-column overview (model/provider/tier, all no_wrap=True) plus a transposed 2-column weights table (model · category | weight) sorted strongest-first. The weight column is not no_wrap, so long pairs wrap (never ellipsize).
  • formations: added formation_summary() / _render_summary_value() helpers replacing the JSON blob, plus rich.markup.escape so aggregators=[...] isn't eaten by Rich markup.
  • Tests: test_cli_models_renders_without_overflow_at_columns_80 (asserts no …/... and full longest name at width 80) and test_cli_formations_uses_human_summary.
  • .gitreins/config.yaml: evaluator.max_iterations and tier2.max_iterations 100 → 200 per the judge note.

  • tests/test_cli.py: 34 passed (was 5 unrelated failures until mcp/fastapi/uvicorn installed).
  • Real chimera.yaml.example at width 80: no ellipsis, longest name openrouter/x-ai/grok-4.20-multi-agent fully present, table width exactly 80.
  • Real pty COLUMNS=80 probe (the isatty path): VERIFICATION PASSED.
