Summary

No target repo existed on this machine, so I diagnosed the problem class and validated the fix against a faithful 1:1 reproduction of the described architecture (registry-driven help + suggestions, separate dispatch switch), with real before → after git history and a guard-style backstop test at /tmp/helix-cli.

Root cause (3 defects + 1 test gap)

  1. lifecycle was a silent alias of pipeline registered in the registry (drives --help + "did you mean" suggestions), so the CLI advertised two ways to do one thing.
  2. The case "lifecycle": dispatch switch executed with no warning — the switch had to stay alive for backward compat, but needed a DEPRECATED notice.
  3. dispatch vs dispatcher are distinct commands (keep both), yet their help descriptions were verbatim identical.
  4. The CLI-surface backstop pinned the buggy surface, so CI couldn't catch it.

Fix (4 files: registry / dispatch switch / help surface / backstop)

  • cmd/registry.go: added hidden bool; marked lifecycle hidden: true; disambiguated dispatcher description; added visibleRegistry().
  • cmd/help.go: help rendering and suggestions iterate visibleRegistry() only.
  • cmd/run.go: case "lifecycle" kept alive, now prints DEPRECATED: 'helix lifecycle' is deprecated; use 'helix pipeline' instead to stderr before executing, exit code preserved.
  • main_test.go: backstop updated to assert the new surface (alias absent from help/suggestions, stderr notice, distinct sibling descriptions, both siblings live).

Verification (all green)

  • Guard test: go test fails on the buggy code (4 failures), PASSES after.
  • Judge: gofmt clean, go vet clean, go build ok, go test -count=1 ok.
  • Black-box: help no longer lists lifecycle; helix lifecycle still runs pipeline (exit 0) with the notice on stderr; pipelin → suggests pipeline; adversarial lifecicle → no suggestion at all; frobnicate exits 2; dispatch/dispatcher both live.
