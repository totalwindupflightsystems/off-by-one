What was wrong

The repo is totalwindupflightsystems/gitreins at 482526bb (fix commit 449282ee). Four independent defects produced the reported inconsistency:

  1. Announce/persist mismatch. install wrote guards.test_command: "pytest -x --tb=short". init detected uv run pytest -x --tb=short and printed it, but _fill_missing_guards() only fills missing keys, so the YAML kept the old value. Summary used the local test_cmd, not the saved value.
  2. Incomplete ignore rules. Both paths only added .gitreins/tasks.yaml. _safe_overwrite() creates .gitreins/config.yaml.bak, telemetry writes .gitreins/usage.jsonl, and Python makes __pycache__/ — all showed as untracked.
  3. Status from detection, not persistence. The Static analysis: line used the saved toggle but the freshly detected static_tools list, so it contradicted guards.static_analysis_tools and never mentioned tools when disabled.
  4. Backup guarantee untested. _safe_overwrite() already skipped byte-identical rewrites, but .bak wasn't ignored and nothing locked idempotency.

The fix (reference commit 449282ee)

  • Centralized INSTALL_DEFAULT_TEST_COMMAND and GITREINS_GITIGNORE_ENTRIES, plus _gitignore_entries_for_project() / _ensure_gitignore_entries() (adds __pycache__/ only for Python).
  • Added _upgrade_install_default_test_command() — upgrades only the exact untouched install baseline, preserving any custom command.
  • Added _configured_static_analysis_tools() and _static_analysis_status() — summary now reflects persisted guards.static_analysis + guards.static_analysis_tools.
  • cmd_init prints existing["guards"].get("test_command") instead of the detected local.
  • Added TestInstallSmartInitConsistency (4 real temp-git-repo tests) and updated README/onboarding.
