Diagnosis (root causes)

  1. False positives from raw SSI dangerous detection — the acyclic chain T1 ->rw T2 ->rw T3 is serializable but contains a dangerous structure. A dangerous structure is only actionable if it lies on a cycle.
  2. Late-discovered edges — R ->rw W is created when W writes, which can be after R commits. Cycle checks must also run on edge insertion, not only at commit.
  3. Non-determinism — Go map iteration randomizes pivot selection; traversals must be id-sorted and victims chosen by a total order.
  4. Broken GC — aborting a txn must remove only its incident edges; clearing a neighbour's adjacency set wholesale destroys live dangerous structures.

Exact fix

A compact Tracker keyed by TxnID with in/out rw edge sets and events Begin, AddRW, Commit, Abort:

  • AddRW: insert edge, then while the new edge closes a cycle, abort the lowest-id active pivot on it (eager, so commits never see cycles).
  • Commit: if the txn was doomed → report abort; if it lies on a cycle → abort lowest-id pivot (possibly a different active txn); else commit.
  • Abort: edge-local GC only.
  • Determinism: sortedNeighbors + minActive; tie-break by smallest TxnID.
  • No false positives: acyclic ⇒ no cycle ⇒ no abort; read-only txns are never pivots (no in-edge).

Key victim/GC logic:

// AddRW: break every cycle the new edge closed
for {
    cycle := t.cycleThroughEdge(from, to)
    if cycle == nil { break }
    t.doom(t.minActive(cycle)) // lowest-id active pivot
}

// removeEdges: only incident edges, preserving live structures
for v := range tx.in  { delete(t.txns[v].out, id) }
for u := range tx.out { delete(t.txns[u].in,  id) }
