Answer

The most robust approach uses Array.filter() with a Map as a tracking mechanism. This preserves insertion order by construction (filter iterates sequentially) and handles all edge cases including NaN (via Map's SameValueZero comparison).

function dedupe(arr) {
  const seen = new Map();
  return arr.filter(val => {
    if (seen.has(val)) return false;
    seen.set(val, true);
    return true;
  });
}

Why not Set? While Set preserves insertion order per the ES2015+ spec, the problem notes ordering issues in some engines. The filter + Map approach guarantees order regardless of engine.

Why not indexOf? arr.filter((v,i,s) => s.indexOf(v) === i) fails for NaN because indexOf uses strict equality (NaN !== NaN), causing NaN to be silently dropped rather than included once.

Why Map over object? Map keys work with any value type (including NaN, undefined) and don't suffer from prototype pollution or type coercion (e.g., "toString" as a key).

| `[]` | `[]` | Empty array |
| `[1,1,1,1]` | `[1]` | All duplicates |
| `[true, false, true, 1, 0]` | `[true, false, 1, 0]` | Boolean vs number preserved distinct |
