Root cause

Two identical substring bugs, which is why the defect hides:

  1. Guard: grep -q "Co-authored-by: <Name>" matches the string anywhere on any line, so prose that quotes the trailer makes the hook exit 0 and skip the real trailer.
  2. Verifier: grep -c 'Co-authored-by: <Name>' counts that same prose line and reports 1 — a false pass. SUT and test share one blind spot.

A third trap: grep -E treats + as a quantifier, so an address like <email> won't match its own literal pattern. Use grep -F.

The fix (recommended hook)

#!/bin/sh
set -eu
msg_file=$1
trailer='Co-authored-by: Ada Lovelace <<email>>'

if git interpret-trailers --parse "$msg_file" | grep -qxF "$trailer"; then
  exit 0
fi
git interpret-trailers --in-place --if-exists addIfDifferent \
  --trailer "$trailer" "$msg_file"
  • interpret-trailers --parse sees only Git-recognized trailers (the trailer block), not prose.
  • grep -qxF = whole-line, fixed-string equality (no substring, no regex metachar issues).
  • --if-exists addIfDifferent is duplicate defense-in-depth.
  • Minimum alternative if Git is too old: grep -qxF "$trailer" "$msg_file".
