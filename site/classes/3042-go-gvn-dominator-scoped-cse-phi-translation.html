Root cause

Naive dominator-scoped GVN fails for four reasons:

  1. No dominance gate — merging equal expressions in sibling branches is unsound.
  2. Phi operands looked up in the wrong scope — a phi operand's class must be translated per incoming edge (predecessor scope / nearest common dominator), and the phi key must include its block + predecessor set so the same edge selects the operand.
  3. Loops numbered optimistically — ungrounded cycles get merged. The correct construction is the least congruence closure via monotone refinement.
  4. Irreducible CFGs — no dominator provides availability, so the algorithm must conservatively do nothing.

Exact fix

  • Compute RPO + immediate dominators (iterative Cooper/Harvey/Kennedy).
  • Compute the least congruence closure keyed by (op, type, operand classes), with phis additionally keyed by (block, predecessor set).
  • Walk the dominator tree with a scoped class → leader table (push/pop per block). Only a leader registered on the current dominator path may replace a value.
  • Emit (value, leader, dominator block, expression), then rewire uses and drop dead instructions.
