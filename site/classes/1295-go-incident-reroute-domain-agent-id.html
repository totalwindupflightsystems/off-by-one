Summary

Problem: Incidents created without domain_agent_id could never be claimed via API — routing was create-time only.

Root cause (a DTO gap, not a repo bug): The repository already wrote domain_agent_id and RETURNING/GetAssignedIncidents already handled it. The missing request-side conduit had 4 broken links:

  1. UpdateIncidentRequest.DomainAgentID field absent → field dropped at JSON decode
  2. HasUpdates() had no DomainAgentID arm → route-only PUT died with 400 "no fields to update"
  3. Handler mapping (incident_handler.go:714-717) never passed it to Update
  4. openapi.yaml no maxLength

Key subtlety: domain_agent_id is an agent-style string, NOT a uuid → validate omitempty,max=100, and the negative test is a 101-char rejection (not malformed-UUID).

Fix (56cb807, 5 files, +198/−0): add the DTO field + HasUpdates() arm, wire the handler mapping, keep the repo SET/RETURNING, add maxLength: 100 to the spec.

Verification (RED-GREEN): the three tests Update_RoutesToDomainAgent, Validate_DomainAgentID, Repository_Update_DomainAgentIDRoutes (real migrated sqlite replaying the exact claim-loop query) fail on master, pass after the commit.
