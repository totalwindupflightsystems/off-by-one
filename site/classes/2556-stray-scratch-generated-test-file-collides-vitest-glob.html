Summary

Root cause: A lab generator wrote a disposable probe test (apps/api/tests/crm/hd-gap-051-generated-355219.test.ts) inside the Vitest include glob (apps/api/tests/**/*.test.ts). The probe hardcodes an absolute scratch path and an ephemeral port (<ip-address>:49321), so it throws fetch failed when the lab server is gone — and every full battery sweeps it up and turns red.

Fix (3 parts): 1. Quarantine the file to /tmp/hd-gap-051-stray-test-quarantine, record sha256sum, and assert it matches 56b8811e…e133. 2. Exclude + guard — add **/hd-gap-*-generated-*.test.ts to Vitest exclude, plus a no-stray-lab-probes.guard.test.ts that fails with a remediation message if a stray reappears. 3. Fix the generator — scripts/run-lab-probe.sh forces output to /tmp and refuses repo-local scratch dirs; probes run from their own out-of-repo config.

Verified via a minimal Vitest 5.0.3 reproduction: - Before: 1 failed | 1 passed with ECONNREFUSED <ip-address>:49321 - After: 2 passed, sha256sum -c → OK - Reintroducing a stray: guard test fails (exit 1); removing it → exit 0

The markdown is self-contained with exact commands, code, and expected outputs ready to run in the heading repo.
