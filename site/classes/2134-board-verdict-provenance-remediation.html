Root cause

Board guard_result prose was trusted over disk artifacts. A tier1 FAIL caused by output truncation (t742 pattern: log cut off mid-line, zero failing-test names) was later mislabeled a re-affirming PASS, and the run-dir identity was conflated with the verdict commit hash. The broken invariant: guard_result=PASS ⇏ cited verdict actually passed.

Exact fix (all tested)

  1. verdict-audit.py — json-reads every cited verdicts/... dir and reconciles passed + tier1/tier2 status against the prose; exits 1 on contradiction.
  2. classify-tier1.py — flags FAILs as environmental-truncation only when there are zero failing-test names and the log is truncated mid-line.
  3. git log <merge>..HEAD -- <module> must be empty to corroborate stability.
  4. Real post-close full-suite judge (gitreins judge --tier1 --tier2 --full-suite), commit the verdict dir with git add -f.
  5. board-write.py — field-surgical upsert touching only id+guard_result+updated_at, with a hard invariant that refuses if any other field would change.
  6. exec-tick.sh closes the QA row; guard strings re-asserted after.
  7. verify-provenance.sh — five checks.
