BBRv2 Probe-Response Classifier: Policer-Aware Loss Classification

Root Cause

The failure mode is a loss-classification bug, not a pacing-gain bug:

  1. Every loss was treated as congestion.
    A policer/shaper bucket drop is still a packet loss. If the classifier sees lost > 0 and immediately applies the congestion backoff (0.7x), a 100 Mbps policer quickly collapses to 70, 49, 34 Mbps, etc.

  2. No hysteresis window.
    A single jittery 5G sample caused an immediate state flip. The classifier oscillated between PROBE_UP and PROBE_DOWN, repeatedly spending probe credit and then cutting.

  3. No policer-rate estimate.
    The classifier had no concept of “the observed stable rate is the shaper ceiling.” It could not distinguish:

  4. policer loss: rate plateau + stable RTT + bursty loss

  5. congestion loss: delivery-rate collapse + RTT growth + sustained loss

  6. No explicit loss labels.
    Explicit policer drops and explicit congestion marks were indistinguishable from inferred loss.

  7. No bounded DOWN window.
    Persistent jitter could keep the sender in PROBE_DOWN forever, starving the shaper credit.

The fix is to separate loss detection from loss classification, add per-round hysteresis, estimate the policer rate, and use a soft backoff for policer loss vs. a multiplicative cut for true congestion.

1. Explicit loss labels and ACK event

type LossKind uint8

const (
    LossUnknown LossKind = iota
    LossPolicer
    LossCongestion
    LossExplicit // ECN/CE or explicit congestion mark
)

type AckEvent struct {
    Round          uint64
    Time           time.Duration
    DeliveredBytes uint64
    AckedBytes     uint64
    LostBytes      uint64
    InflightBytes  uint64
    DeliveryRate   float64 // bytes/sec
    RTT            time.Duration
    MinRTT         time.Duration
    AppLimited     bool
    LossKind       LossKind
}

3. Loss classifier: RTT is the primary congestion discriminator

func (c *Classifier) classifyLoss(ev AckEvent, lossRate float64) LossKind {
    switch ev.LossKind {
    case LossPolicer:
        return LossPolicer
    case LossCongestion:
        return LossCongestion
    case LossExplicit:
        return LossExplicit
    }

    // An application-limited sample cannot prove a rate collapse.
    if ev.AppLimited {
        return LossPolicer
    }

    rateDrop := c.rateDrop()
    rttInc := c.rttIncrease()

    // Queue build-up almost always shows up as RTT growth.
    if rttInc >= c.cfg.RTTIncreaseThreshold {
        return LossCongestion
    }
    if rateDrop >= c.cfg.RateDropThreshold &&
        rttInc >= c.cfg.RTTIncreaseThreshold/2 {
        return LossCongestion
    }
    if rateDrop >= c.cfg.RateDropThreshold*2 &&
        lossRate >= c.cfg.CongestionLossThreshold/2 {
        return LossCongestion
    }
    if lossRate >= c.cfg.CongestionLossThreshold &&
        rateDrop >= c.cfg.RateDropThreshold/2 {
        return LossCongestion
    }

    // Stable rate/RTT with bursty loss is policer-shaped, even at high loss.
    if lossRate >= c.cfg.PolicerLossThreshold {
        return LossPolicer
    }
    return LossPolicer
}

4. Hysteresis: require consecutive lossy rounds

func (c *Classifier) confirmedLossClass() LossKind {
    if c.congestionLossStreak >= c.cfg.HysteresisRounds {
        return LossCongestion
    }
    if c.policerLossStreak >= c.cfg.HysteresisRounds {
        return LossPolicer
    }
    return LossUnknown
}

A single loss sample is held. Explicit labels and strong loss bypass the hysteresis window. The classifier also tracks lastLossRound and will not start a new probe until a clean hysteresis window has elapsed.

5. State machine

switch c.state {
case ProbeUp:
    // Any confirmed loss while probing means the probe found a limit.
    if lossClass == LossCongestion {
        c.enterDown(ev, LossCongestion, "probe_up:congestion")
        return
    }
    if lossClass == LossPolicer {
        c.enterDown(ev, LossPolicer, "probe_up:policer")
        return
    }
    if c.probeRounds >= c.cfg.ProbeUpRounds {
        response := c.response()
        if response < c.cfg.RateResponseThreshold ||
            c.probeRounds >= c.cfg.MaxProbeRounds {
            c.enterDown(ev, LossUnknown, "probe_up:response_plateau")
            return
        }
    }

case ProbeDown:
    if lossClass == LossCongestion {
        c.updateCongestionTarget(ev)
        c.lastLossClass = LossCongestion
        c.lastReason = "probe_down:congestion_hold"
        return
    }
    if lossClass == LossPolicer {
        c.updatePolicerTarget(ev)
        c.lastLossClass = LossPolicer
        c.lastReason = "probe_down:policer_hold"
        if c.roundsInState >= c.cfg.MaxDownRounds {
            c.enterCruise(ev, "probe_down:policer_max_rounds")
        }
        return
    }
    if c.roundsInState >= c.cfg.ProbeDownRounds && c.cleanStreak >= 1 {
        if c.drained(ev) {
            c.enterCruise(ev, "probe_down:drained")
            return
        }
    }
    if c.roundsInState >= c.cfg.MaxDownRounds {
        c.enterCruise(ev, "probe_down:max_rounds")
        return
    }

case ProbeCruise:
    if lossClass == LossCongestion {
        c.enterDown(ev, LossCongestion, "cruise:congestion")
        return
    }
    if lossClass == LossPolicer {
        c.enterDown(ev, LossPolicer, "cruise:policer")
        return
    }
    if c.lastLossRound > 0 &&
        ev.Round-c.lastLossRound < c.cfg.HysteresisRounds {
        c.lastReason = "cruise:loss_hold"
        return
    }
    if c.roundsInState >= c.cfg.ProbeIntervalRounds {
        c.enterUp(ev)
        return
    }
}

6. Policer-aware target rate

func (c *Classifier) updatePolicerTarget(ev AckEvent) {
    rate := c.sampleRate(ev)
    if rate <= 0 {
        if c.policerRate > 0 {
            c.policerTarget = c.policerRate * (1 - c.cfg.Headroom)
        }
        return
    }
    if c.policerRate <= 0 || rate < c.policerRate {
        c.policerRate = rate
    }
    c.policerTarget = c.policerRate * (1 - c.cfg.Headroom)
}
  • Policer loss → target ≈ policerRate * 0.98, not rate * 0.70.
  • Congestion loss → target = rate * (1 - Beta) = rate * 0.70.
  • PROBE_UP is allowed to use 1.25x, but only up to 1.25 * policerRate when the ceiling is known.
  • On clean rounds, the policer estimate recovers slowly by PolicerRecovery (default 1.01 per RTT), avoiding permanent starvation after a jittery low sample.
