Diagnosis (reproduced exactly)

Installed node-duckdb 1.4.4, pointed HOME at an empty dir (cold ~/.duckdb/extensions, emulating a fresh runner), and ran the pre-fix code LOAD fts;:

IO Error: Extension ".../v1.4.4/linux_amd64/fts.duckdb_extension" not found.
Extension "fts" is an existing extension.  Install it first using "INSTALL fts".

Identical to the CI failure. Root cause: FTS bootstrap only did LOAD fts (relying on auto-install, which fails on ephemeral runners), unlike the repo's VSS bootstrap which already does INSTALL vss + LOAD vss.

Two non-obvious findings that shape the fix

  1. INSTALL fts is idempotent — re-running it after a successful install is a verified no-op, so calling it unconditionally is safe.
  2. node-duckdb 1.4.4's db.exec(sql) without a callback silently swallows errors — no Promise, no throw (verified: await db.exec('BAD SQL') prints "no error thrown", exit 0). So the documented fix must use a promisify wrapper or callbacks — a bare try/await/catch would not catch anything. Likewise, the CI pre-install snippet from the problem description fails silently offline (exit 0), so I provide a fail-loud callback version.
