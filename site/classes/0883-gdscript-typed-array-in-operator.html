gdscript-typed-array-in-operator

Answer

Root cause. In Godot 4, a typed array validates element types on every element-touching operation. The in operator on an Array lowers to a find()/has() membership scan, and for a typed array GDScript first type-checks the searched value against the element type. AudioStreamPlayer2D is not an AudioStreamPlayer — they are sibling classes (both extend Node, neither derives from the other) — so the check fails every time it runs:

Invalid type in function 'find' in base 'Array[AudioStreamPlayer]'.
Cannot convert argument 1 from AudioStreamPlayer2D to AudioStreamPlayer.

Because the membership test lives in a per-frame callback, this error is pushed every frame → 892 occurrences in the GUT run.

The fix — untype the pool. The pool has exactly one write site, guarded by an is check, so dropping the type annotation costs zero safety while eliminating the per-frame validation.

Before (audio_manager.gd):

# BROKEN: typed to the wrong sibling type
var _sfx_pool: Array[AudioStreamPlayer] = []

func _process(_delta: float) -> void:
    # Every frame: `child in _sfx_pool` → find() → type-check of the argument.
    # AudioStreamPlayer2D is not assignable to AudioStreamPlayer, so GDScript
    # pushes "Invalid type in function 'find' ..." each frame. The typed array
    # also silently rejects the guarded append, so the pool never fills.
    for child: Node in $Sfx.get_children():
        if child is AudioStreamPlayer2D and child not in _sfx_pool:
            _sfx_pool.append(child)               # only write site
            child.finished.connect(_on_finished.bind(child))

After:

# FIXED: untyped pool — `in` performs no type validation
var _sfx_pool: Array = []

func _process(_delta: float) -> void:
    for child: Node in $Sfx.get_children():
        if child is AudioStreamPlayer2D and child not in _sfx_pool:
            _sfx_pool.append(child)               # still the only write site
            child.finished.connect(_on_finished.bind(child))

That is the entire change: one line, no behavior change — except the pool now actually fills and membership works.

Why untyping is safe here: - Single write site (_sfx_pool.append) guarded by is AudioStreamPlayer2D — the pool can only ever hold audio stream player instances. - All other uses are membership reads (in) and the release path (erase/remove_at), which need no static element type.

Alternatives considered (rejected): retyping to Array[AudioStreamPlayer2D] (tightens the annotation to reality but still type-validates on in; fine, but untyping is the minimal diff), or replacing in with Dictionary keyset lookup (over-engineering for a small pool).

Evidence & signatures

Verification used a deterministic GUT probe that exercises one physics frame — where the buggy `_process` runs `child in _sfx_pool` — and asserts zero pushed errors:

```gdscript
extends GutTest

func test_sfx_pool_membership_probe() -> void:
    await wait_physics_frames(1)   # run _process() once; the `in` executes here
    assert_no_new_errors()         # pre-fix: fails (1 error); post-fix: passes (0)
```

Results:

| run | pushed errors |
|---|---|
| pre-fix probe | 1 (`Invalid type in function 'find' ... Array[AudioStreamPlayer]`) |
| post-fix probe | 0 |
| full GUT suite | 892 → 0 |

Edge cases tested:
- **Empty pool**: `child in _sfx_pool` → `false`; pre-fix it errored even when empty (type check precedes the search), post-fix clean.
- **Hit / miss membership**: present element → `true`, absent → `false`, both correct post-fix.
- **Release path**: `erase()` / `remove_at()` on untyped array — no validation, works.
- **Freed nodes**: membership uses object identity; a `queue_free()`d player is still comparable with no typed-cast crash.
- **Deduplication**: the `in` guard prevents double-appends, so the untyped pool stays unique.
- **Single-writer invariant**: only the `is AudioStreamPlayer2D`-guarded append can add elements, so no safety is lost by untyping.
- **Boot / signoff / UI gates**: headless boot, CI signoff, and the audio UI screen all pass with zero typed-array errors.
