INT-CI-014: cmd/server 60s package timeout caused by a test paying the production webhook-retry budget

Repo: &lt;project&gt;-dev/&lt;project&gt; Broken HEAD: bedc7cb Fix commit: dd9b96e Evidence file: cmd/server/session_dispatch_test.go

1. Summary

make test is go test ./... -count=1 -timeout 60s -p 1. -p 1 serializes packages, so this is not cross-package contention — cmd/server exceeds its own 60s deadline. One of three long tests, TestSessionFanoutWebhookFailureIsRefused, spent ~30s waiting on the production default CR_SESSION_DELIVERY_TIMEOUT_MS (30000ms) while asserting only the final refusal outcome. The fix points that test at the existing config seam with the smallest budget that still exercises retry + classification, and adds regression gates. ~30s is removed, but two independent policy-shaped blockers remain.

2. Root-cause analysis

Timeout stack (go test ./cmd/server/ -count=1 -timeout 60s) panics at the package deadline and names the other long test, which is why the raw stack misleads:

Why the 30s: the test registers a blocking webhook with a 500 response. internal/webhook/webhook.go classifies 5xx as Retryable: true; internal/webhook/driver.go retries with backoff(n) = 1s, 2s, 4s, 8s, 16s (capped) until the delivery budget expires. Default budget is registry.DefaultSessionDeliveryTimeoutMs = 30000. The test asserted outcome == "refused", no reply row, skipped == 1 — none of which depend on the budget's magnitude.

The seam already exists in config/config.go: CR_SESSION_DELIVERY_TIMEOUT_MS (1..30000, default 30000) and RUNTIME_TIMEOUT_MS (1..25000, default 20000, must be strictly less than delivery). Since backoff(1) == 1s, the smallest budget that shows a retry is just over 1s; the fix uses 2000ms / 1500ms.

3. Exact fix

Only cmd/server/session_dispatch_test.go changes: add a sessionDispatchFixtureAtRootWithEnv variant (caller keys win), set CR_SESSION_DELIVERY_TIMEOUT_MS=2000 / RUNTIME_TIMEOUT_MS=1500, and add wall-clock + attempt-count assertions. The full patch is embedded in ~/SOLUTION.md; the core of it:

func sessionDispatchFixtureAtRootWithEnv(t *testing.T, hook http.Handler, verdict, logRoot string, extra map[string]string) (...) {
    ...
    env := map[string]string{
        "CR_SESSION_BACKEND": "jsonl", "CR_SESSION_LOG_ROOT": logRoot,
        "CR_REQUIRE_AGENT_SIG": "false",
        "CR_GROUP_LOG_ROOT":    t.TempDir(), "CR_GUARD_ENABLED": "true", "SESSION_GUARD_TEST_KEY": "test-key",
    }
    for k, v := range extra { // caller-supplied keys win
        env[k] = v
    }
    base := startTestServerWithEnv(t, env)
    ...
}

func TestSessionFanoutWebhookFailureIsRefused(t *testing.T) {
    const (
        sessionBudget = 2000
        runtimeBudget = 1500
        wallCeiling   = 10 * time.Second
    )
    for _, status := range []int{http.StatusBadRequest, http.StatusInternalServerError} {
        t.Run(http.StatusText(status), func(t *testing.T) {
            ...
            base, room, _, envelopes := sessionDispatchFixtureAtRootWithEnv(t, hook, "allow", root, map[string]string{
                "CR_SESSION_DELIVERY_TIMEOUT_MS": strconv.Itoa(sessionBudget),
                "RUNTIME_TIMEOUT_MS":             strconv.Itoa(runtimeBudget),
            })
            started := time.Now()
            msg := sendDispatchMessage(t, base, room)
            elapsed := time.Since(started)
            ... existing outcome assertions ...
            require.Less(t, elapsed, wallCeiling,
                "a failed blocking webhook took %s against a %dms budget: the delivery budget must bound this wait", elapsed, sessionBudget)
            attempts := 0
            for { select { case <-envelopes: attempts++; continue; default: } break }
            if status == http.StatusInternalServerError {
                require.Greater(t, attempts, 1, "a 5xx is retryable: the blocking delivery must retry inside its budget (attempts=%d)", attempts)
            } else {
                require.Equal(t, 1, attempts, "a non-retryable 4xx must not be retried (attempts=%d)", attempts)
            }
        })
    }
}

Gates red-proven then green: - Restore default budget → "30.002589382s" is not less than "10s" … the delivery budget must bound this wait, FAIL in 30.03s. - Budget below first backoff (500ms) → "1" is not greater than "1" … must retry inside its budget (attempts=1), FAIL in 0.53s.

Remaining independent blockers: on the fixed tree go test ./cmd/server/ -count=1 -timeout 60s still panics at 60s on TestDocsClaimsBehaviors (docsclaims_hooks_test.go:38, make doctor-hooks-selftest). Excluding both docs-claims tests: go test -count=1 -timeout 300s -skip 'TestDocsClaims' ./cmd/server/ → ok ... 62.241s, still over 60s. These are policy-shaped (parallelize the idle-bound suite, split out integration-shaped tests, or widen the per-package budget) and need an owner decision.

5. Takeaway

A test that asserts an outcome should not inherit a production retry budget it never checks. State the budget at the existing seam (2000ms/1500ms), keep the production retry/classify/refuse path, and assert wall clock plus attempt count so a regression reds instead of silently eating half the package deadline.
