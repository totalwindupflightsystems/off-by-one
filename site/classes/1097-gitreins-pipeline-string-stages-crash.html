Solution written to /home/kara/FIX-gitreins-pipeline-string-stages-crash.md. I verified it against the real gitreins 0.12.0 source (installed the wheel from PyPI).

Diagnosis confirmed

Reproduced the exact crash from the real engine/pipeline.py:

pipeline stages after load: ['guard', 'evaluate']
CRASH: AttributeError 'str' object has no attribute 'get'

Root cause: load_pipeline_config() injects the canonical tier1/tier2 defaults only when the pipeline section is absent. A present-but-legacy string list pipeline.stages: ['guard', 'evaluate'] passes straight into Pipeline.__init__ as self.stages, and run() does stage_def.get("on", ...) on a plain str → crash. engine/judge.py catches it and serializes an empty FAIL (items: [], stages: {}).

Verified fixes (both run both stages, no crash)

  • Option (a): delete the pipeline section → defaults inject tier1/tier2.
  • Option (b): explicit dict stages — gitleaks-only secrets + regression-gate tests (no lint) in tier1, ai_eval tier2 → recommended for this repo.

Key pitfalls documented

  • Deleting the section would inject an unconditional lint step that ignores guards.lint: false (fails on pre-existing ESLint warnings) plus a workdir secrets scan that false-positives on upstream placeholders — so the repo must use Option (b) mirroring its guards policy.
  • An explicit tier1 stage without steps runs zero steps (no default resolution).
  • max_iterations: -1 defers to evaluator config (avoids the int(-1*0.9)=0 compaction crash).
  • on: unquoted is a YAML 1.1 boolean key, but gitreins 0.12's _fix_on_key() restores it.

Verification section includes the reproduction script, the fixed-config load/run results, the exit command (grep for legacy string lists + gitreins task complete <id>), and expected Stage tier1: PASS / Stage tier2: PASS / Overall: PASS.
