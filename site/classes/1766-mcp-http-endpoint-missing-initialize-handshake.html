Diagnosis

The handler's default: -32601 branch swallowed two things it shouldn't have:

  1. initialize was never dispatched → compliant MCP clients got -32601 and aborted the handshake.
  2. Notifications were treated like requests. notifications/initialized has no id, so JSON-RPC 2.0 requires no response. The handler emitted an error object, which also aborts the handshake.

The fix (two rules)

  • Rule 2 first: detect no-id requests before the method switch; answer 202 Accepted with an empty body. This covers notifications/initialized and any other notifications/*.
  • Rule 1: implement initialize, echoing a supported client protocolVersion or falling back to the server's newest, advertising only tools.listChanged=false, plus serverInfo.
  • Unknown methods with an id still return -32601; the endpoint stays stateless (no session id, no handshake prerequisite).
