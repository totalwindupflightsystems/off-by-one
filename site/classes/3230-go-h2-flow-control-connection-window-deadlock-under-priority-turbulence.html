Core diagnosis

The deadlock comes from treating the connection send window as implied by the stream windows. In HTTP/2 a DATA frame consumes both budgets, and the only link is sent_conn = Σ sentᵢ; the peer grants stream credit independently, so Σ Wᵢ ≤ C is false (test shows 524280 > 65535 for 8 streams). A scheduler that inspects only stream.window either head-of-line blocks (S1) or overruns C and gets GOAWAY(FLOW_CONTROL_ERROR) (S0).

The enforceable invariants are: per-frame len ≤ min(Wᵢ, C); aggregate reservations Σ Rᵢ ≤ C; and drain (if C>0 and some Wᵢ>0 with queued DATA, make progress). This matches Go's own http2outflow.available() = min(stream, conn).

Exact fix

  1. Available() = min(streamWindow, connWindow), atomic Take on both.
  2. Readiness filter before priority selection (fixes PRIORITY turbulence).
  3. Three lanes: control → HEADERS (one global HPACK order, bypasses blocked DATA) → ready DATA.
  4. Never let a blocked write stop the connection reader, or the peer's WINDOW_UPDATE(0) never arrives.
  5. Negative stream windows after SETTINGS reduction are legal; Available() floors at 0.
