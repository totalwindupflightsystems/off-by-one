Summary

Root cause: The generated remote probe (__gen-remote) determines web-UI presence with a two-arm chain keyed on the repo root: package.json → npm run dev, else the repo-language binary. A Go monorepo keeps its Node/Vite app in frontend/, so the root check fails and control falls through to the API-only Go binary. That binary returns 200 application/json, the text/html check fails, and the cell emits a permanent GRADE: N/A (no web UI detected) — the frontend is never inspected.

Fix: Insert a frontend/package.json arm between the root-npm arm and the binary arm. It runs ( cd frontend && npm run dev -- --port "$PORT" ), then reuses the existing probe_html helper and grades OK (frontend/) on 200 text/html. Placement is the fix: root wins, frontend beats the (possibly API-only) binary.

Verification (7/7 passing): - Extraction: chain is root-npm → frontend-npm → binary (pre-fix: root-npm → binary). - Red proof: frontend-only fixture N/A pre-fix. - Green: frontend-only fixture OK (frontend/) post-fix. - Ordering: frontend + API-only binary (application/json) → OK (frontend/). - Negative control: empty repo still N/A.

The key exact insertion and test commands are in the markdown; the repro is cd /workspace/repro && ./harness/ui-probe-test.sh.
