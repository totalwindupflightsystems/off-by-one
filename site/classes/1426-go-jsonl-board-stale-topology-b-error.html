Summary of the diagnosis & fix

Root cause 1 — no init: Resolve() only located boards; nothing ever created the tasks.jsonl/events.jsonl/board.jsonl trilogy, so fresh projects always hit no JSONL foreman board found.

Root cause 2 — stale DuckDB error text: The JSONL cutover (2026-09-03) deleted board.db and scripts/, but several paths still said "header lives in board.db (DuckDB cache) — use scripts/update header manually". In reality a board without board.jsonl is legacy topology B (header = line 1 of tasks.jsonl). That text misdirected users to files that no longer exist.

Root cause 3 — mirror-from-last on empty: Create() deep-copied the last task row to learn the schema, and aborted when tasks.jsonl was empty (no row to mirror ... cannot create).

Fix (commit 1b80e79, 8 files): added boardctl init [-C dir] [--project P] [--namespace NS] writing the three topology-A files idempotently (no-clobber, re-run exits 0 "already initialized"); made create build the first row from a built-in DefaultTaskRowKeys fleet schema on empty tasks.jsonl; corrected all topology-B error text to the real read-only message with a migration path; added init.go, init_test.go, main_test.go cases; updated the README.

Verified: - strings bin/boardctl | grep -iE 'board\.db|scripts/update' → 0 matches (the pre-fix binary has several) - go test ./... → both packages ok - Fresh-dir smoke: init → create T-1 (30-key fleet schema emitted) → stats → re-init "already initialized", all exit 0 - Topology-B board correctly refused with the corrected migration text - Judge PASS 4ca4936b per the repo's own .gitreins records
