Root cause (MAF-GAP-048)

getModelStats() in apps/server/src/db/repository.ts (~line 489) aggregated player rows, not games: - COUNT(*) as games_played → a model in a 5-player game counts 5, not 1 - SUM(CASE WHEN p.won = 1 ...) as wins → a game with 4 town winners of the same model inflates wins to 4 (live report: 6 shown vs only 2 distinct won games; row-count 41 vs distinct-game 11) - raw GROUP BY p.provider, p.model → openai/gpt-4o-mini and gpt-4o-mini spellings split into two rows, then merge-maxed into contradictory results

This violates the documented contract in specs/api-specs.md: "A game counts at most once per model."

The fix (commit c84e02c, on main)

-- group by normalized model expression == normalizedModelSql('p') (MAF-GAP-036)
CASE WHEN p.model LIKE p.provider || '/%' THEN substr(p.model, length(p.provider) + 2) ELSE p.model END

SELECT p.provider, <expr> as model,
  COUNT(DISTINCT p.game_id) as games_played,
  COUNT(DISTINCT CASE WHEN p.won = 1 THEN p.game_id END) as wins,
  ...
FROM players p WHERE p.provider IS NOT NULL
GROUP BY p.provider, <expr>
ORDER BY games_played DESC
