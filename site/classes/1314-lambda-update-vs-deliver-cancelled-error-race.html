Summary

Diagnosis — CancelledError race on Lambda update: - update_function_code triggers a version rollover that stops the old version's executor (lambda_service.py:580-588). - The executor's shutdown() cancels the in‑flight invocation_future (executor_endpoint.py:180-184). - The cancellation surfaces as asyncio.CancelledError in the assignment layer (assignment.py:94-97), logged as "Failed invocation." - The event manager treats it as undelivered and re‑queues with exponential backoff (event_manager.py:311-344), delivering the S3 event minutes later (at‑least‑once). - Non-deterministic by nature — only invocations in flight at the exact rollover instant are hit, which matches the live "3rd of 4 bursts" observation.

Fix (driver-side, since Core = DO-NOT-EDIT): 1. Barrier — wait for State==Active and LastUpdateStatus==Successful around every update, and serialize bursts with a settle window. 2. Warm — one synchronous (RequestResponse) invoke after the barrier, before real S3 traffic. 3. Idempotent handlers — dedupe on object identity to accept at‑least‑once delivery. 4. Sink poll 60‑90 s before declaring success.

Verification — four concrete checks: log assertion (0 CancelledError), exactly‑once sink count, idempotence/dedup proof, and a failure-mask check targeting the actual rollover race (with a PASS/FAIL gate).
