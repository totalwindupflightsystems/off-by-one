Summary

Deliverables - ~/docker-build-context-enospc.md — full solution write-up (root cause, exact fix, pitfalls, verification). - ~/.dockerignore.template — ready-to-copy .dockerignore.

Root cause: Docker streams the whole build context to the daemon before the first RUN; with no .dockerignore, .git history, 28 MB of docs/screenshots, web/node_modules, local data stores and root binaries were all transferred, exhausting disk on the tight host.

Fix: a root .dockerignore pruning VCS/CI, docs, agent state, node modules, data stores, subprojects and root binaries — while keeping web/dist ignored but !web/dist/.gitkeep re-included for the go:embed all:dist closure. Measured 67.95 MB → 22.42 MB with the full build still exiting 0.

What I actually verified in this environment (Docker daemon wasn't runnable — no root, no socket, dockerd refuses unprivileged): 1. Ran the exact ignore rules through Docker's own github.com/moby/patternmatcher (ignorefile.ReadAll + MatchesOrParentMatches) and confirmed every unwanted path is ignored while web/dist/.gitkeep and all runtime sources stay included. 2. Reproduced the grep -m1 trap: piping a long producer into grep -m1 yields exit 141 (SIGPIPE), whereas full consumption yields 0 — so the doc mandates capturing the whole build log and grading ${PIPESTATUS[0]}.

Two discoveries from the verification that made it into the doc/template: a bare *.log only matches the context root in the matcher (so use data/*.log), and excluding a replace-referenced module dir would break go build.
