Decayed HyperLogLog Merge: Correct Register Semantics and Epsilon-Budget Accounting

Root cause

Under decay, an HLL register is no longer just “max rank.” It depends on event time. Two common naive implementations fail:

  1. Summing per-shard decayed estimates — overlapping keys are counted once per shard. The operation is not idempotent, so it violates the set-union assumption and breaks the usual error-bound argument.
  2. Decaying each shard to its local wall-clock “now” before merging — a fast clock makes that shard’s registers look too large by Δ/H. The merge becomes non-associative, late arrivals are underweighted or lost, and a register from one shard can incorrectly dominate the union.

The correct object is an event-time register envelope, not a shard-local estimate.

Exact fix

For each event, derive a continuous uniform hash variate U ∈ (0,1). Store in register j:

D_j = max(D_j, -log2(U) + (t - epoch) / H)

where:

  • t is the event timestamp normalized to a common event-time epoch,
  • H is the half-life,
  • j is selected by the low p bits of the hash,
  • U comes from the remaining hash bits.

Merge is exactly:

merged.D[j] = max(left.D[j], right.D[j])

Query at common event time T:

N_hat(T) = m^2 * 2^(-(T-epoch)/H) / sum_j 2^(-D_j)

This merge is commutative, associative, and idempotent:

max(max(A), max(B)) = max(A ∪ B)

So duplicate or overlapping keys cannot double-count. Older late arrivals produce a smaller D and are ignored; newer arrivals refresh the key. Shard clocks must be normalized to the common event-time epoch before ingestion. The merge itself never reads a wall clock.

For small cardinalities, the implementation keeps an optional exact key -> last_time map until a sparse limit is exceeded. The dense HLL registers are maintained all along, so switching modes loses no events.

Epsilon-budget accounting

eps_time   = (2^(max_clock_skew/H) - 1)
           + (2^(timestamp_quantum/H) - 1)
eps_sketch = eps - eps_time
z          = Phi^-1(1 - delta/2)
m          >= (1.04 * z / eps_sketch)^2
p          = ceil(log2(m))
eps_achieved = eps_time + z * 1.04 / sqrt(m)

Merge consumes no additional epsilon because the union sketch has the same m registers as a single sketch of the union. Do not divide the budget by number of shards and sum estimates.

All shards being merged must use the same p, half-life, event-time epoch, hash function, and hash seed.

Core update/merge/query logic:

j = h & (m - 1)
u = (h >> p) / float(1 << (64 - p))
if u == 0.0:
    u = 0.5 / float(1 << (64 - p))

d = -math.log2(u) + (t - epoch) / half_life
if d > regs[j]:
    regs[j] = d

def merged(self, other):
    out.regs = [max(a, b) for a, b in zip(self.regs, other.regs)]
    return out

def estimate(self, T):
    neg_d = [-d for d in self.regs if d != -math.inf]
    mx = max(neg_d)
    log2_s = mx + math.log2(sum(2.0 ** (x - mx) for x in neg_d))
    t_rel = (T - self.epoch) / self.half_life
    return 2.0 ** (math.log2(self.m * self.m) - t_rel - log2_s)
