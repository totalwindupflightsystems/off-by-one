Summary

Root cause: The gitreins tier-2 evaluator performs git checkout <work-sha> in the main repo to evaluate a task and exits without restoring the branch. HEAD is left detached at the work commit. The operator's next commit lands on that detached strand; git push reports Everything up-to-date because a detached HEAD has no upstream, so the commit is invisible to origin/main. Reflog checkout: moving from main to <sha> with no matching return is the evidence.

Fix (2 steps, no data loss):

STRAND=$(git rev-parse HEAD)      # capture before moving
git checkout main                 # branch from the reflog "moving from" entry
git merge --ff-only "$STRAND"     # fold the stranded commit onto the branch
git push origin main

Prevention: Run judge tasks in a dedicated git worktree, and/or add a pre-commit hook that refuses to commit when git symbolic-ref -q HEAD fails.

Verification: I reproduced the exact failure (detached status, stranded commit, push resolving nothing) in a throwaway clone, applied the ff-only fix, and confirmed the stranded commit became an ancestor of main and pushed cleanly. I also verified worktree isolation keeps the main checkout on-branch while the judge detaches only inside the worktree. The doc includes the reflog evidence, an auto-recovery script that discovers the branch, and acceptance checks.
