Root cause

REG-003-asg's picker selected an assignment whose class the student is not enrolled in, but it did not require that class to have a teacher:

WHERE a.class_id NOT IN (SELECT class_id FROM enrollments WHERE student_id = :student_id)

After the reseed, every unenrolled assignment's class had teacher_id IS NULL. So: - student leg 404 → correct (not enrolled) - teacher leg 404 → correct (no owner; foreign-teacher scoping) - probe expected 200 → false FAIL

The candidate census (unenrolled AND c.teacher_id IS NOT NULL) returned 0 — no probe-proof candidate exists, so the only correct outcome is a fixture-gap SKIP.

Fix

-WHERE a.class_id NOT IN (
+WHERE c.teacher_id IS NOT NULL
+  AND a.class_id NOT IN (
         SELECT class_id FROM enrollments WHERE student_id = :student_id
       )

plus a zero-candidate SKIP mirroring the existing db_asg_total == 0 branch:

if cand is None:
    return skip("REG-003-asg",
        "fixture-gap: no unenrolled assignment in a teacher-bearing class")

Verification

Harness output reproduces the exact false FAIL and proves the fix:

buggy    asg=100 cls=10 t=None   student=404 teacher=404 FAIL
fixed    <none>                  n/a (0 candidates) SKIP
after backfilling class 10 with teacher 7:
  candidate=asg=100 cls=10 t=7  student=404 teacher=200  result=PASS

Reproduce with python3 /workspace/verify_reg003.py.

General rule captured in the doc: rotation-battery probes that assume a role relationship on the picked row must verify that relationship exists in the live fixture before asserting a success status, otherwise reseed churn produces phantom regressions. Filed as QA-EDUOS-17.
