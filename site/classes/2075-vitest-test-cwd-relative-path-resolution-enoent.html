Fix: vitest-test-cwd-relative-path-resolution-enoent

Problem class: vitest-test-cwd-relative-path-resolution-enoent Affected file: apps/api/src/modules/safety/__tests__/safety-eval.test.ts (QA‑EDUOS‑29) Symptom: ENOENT when the suite resolves its baseline/fixture via path.resolve(process.cwd(), ...), but only when Vitest is launched from a directory other than the canonical checkout.

1. Root cause

The test built its fixture path from the process current working directory:

const reportPath = path.resolve(process.cwd(), '../../specs/baselines/...');

process.cwd() is whatever directory the runner was launched from — it is not the test file's location and it is not changed by Vitest's root/--root option.

  • Vitest's --root only tells the runner where the project/config is. The worker's process.cwd() still points at the shell's cwd.
  • In a monorepo the same test is invoked from repo root, apps/api, a foreign cwd with --root, CI shards, or pnpm exec from another package. Each yields a different reportPath.
  • One invocation happens to produce the correct absolute path (e.g. cwd = apps/api, so ../../specs lands on the repo root) and masks the bug; every other cwd resolves outside the repo and readFileSync throws ENOENT.

The path is a function of cwd, when it should be a function of the test file.

Reference resolution matrix (measured)

process.cwd()-relative ../../specs/baselines/safety-baseline.json:

Launch cwd Resolved path Result
repo root (/…/eduos) /tmp/specs/baselines/… ❌ ENOENT
apps/api /…/eduos/specs/baselines/… ✅ (accidental pass)
foreign cwd + --root /…/eduos /specs/baselines/… ❌ ENOENT

The single pass is coincidental — exactly the "works on my invocation" trap.

2. Exact fix

Anchor the path to the test module using ESM's import.meta.url, then climb the fixed number of levels to the repo root.

apps/api/src/modules/safety/__tests__/safety-eval.test.ts:

// BEFORE (buggy — depends on the launch cwd)
const reportPath = path.resolve(process.cwd(), '../../specs/baselines/...');

// AFTER (cwd-independent)
import path from 'node:path';
import { fileURLToPath } from 'node:url';

// __dirname does not exist in ESM; derive it from import.meta.url.
const testDir = path.dirname(fileURLToPath(import.meta.url));

// apps/api/src/modules/safety/__tests__ -> repo root = six levels up
//   1 .. safety   2 .. modules   3 .. src
//   4 .. api      5 .. apps      6 .. repo root
const repoRoot = path.resolve(testDir, '../../../../../..');

const reportPath = path.resolve(repoRoot, 'specs/baselines/safety-baseline.json');

If the file already imports path, keep it and only add the node:url import.

Why six levels (and how to check)

apps/api/src/modules/safety/__tests__/safety-eval.test.ts
└── testDir = …/apps/api/src/modules/safety/__tests__
    ../../../..  #1–4 → …/apps/api/src
    ../..        #5–6 → …/apps          → repo root

The literal with six .. is '../../../../../..'. Sanity check:

node -e "const p=require('path');console.log(p.resolve('apps/api/src/modules/safety/__tests__','../../../../../..'))"
# prints the absolute repo root

Hardened variant (optional, move-proof)

A fixed climb breaks if the file moves. Walk up to a repo marker instead:

import fs from 'node:fs';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

const testDir = path.dirname(fileURLToPath(import.meta.url));

function findRepoRoot(start: string): string {
  let dir = start;
  while (dir !== path.dirname(dir)) {
    if (
      fs.existsSync(path.join(dir, 'pnpm-workspace.yaml')) ||
      fs.existsSync(path.join(dir, '.git'))
    ) {
      return dir;
    }
    dir = path.dirname(dir);
  }
  throw new Error(`Could not locate repo root above ${start}`);
}

const reportPath = path.resolve(
  findRepoRoot(testDir),
  'specs/baselines/safety-baseline.json',
);

Use the markers your repo actually contains. Prefer the six-level climb for a minimal diff; prefer the marker walk if the test is likely to move.

Rules of thumb

  • Never derive a fixture path from process.cwd() in a test.
  • In ESM/Vitest use path.dirname(fileURLToPath(import.meta.url)).
  • Keep import.meta.url in the test file (or a module colocated at the same depth); don't push it into a util at a different depth.
  • Let path.resolve/path.join handle separators — no string concatenation.
