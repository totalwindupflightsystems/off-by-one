I diagnosed the bug and verified the fix pattern in a standalone Go module. Solution written to /home/kara/solution.md:

Fix: POST /api/v1/export always returns 500 export_failed (missing ClassID)

Problem class: go-export-handler-missing-class-id-500 Symptom: every POST /api/v1/export request fails with HTTP 500 and body {"error":"export_failed", ...}, even for valid answer IDs and a valid target_repo. Affected layer: the HTTP handler that assembles export.ExportItems, not the export engine/store.

1. Root cause

The export engine's writeItem requires a problem class before it can write an item:

func (e *Engine) writeItem(ctx context.Context, item ExportItem) error {
    class, err := e.store.GetProblemClass(ctx, item.ClassID) // ClassID is required
    if err != nil {
        return fmt.Errorf("get problem class %d: %w", item.ClassID, err)
    }
    // ... render + commit the item ...
}

The handler never populated ClassID:

// BUGGY
for _, id := range req.AnswerIDs {
    items = append(items, export.ExportItem{AnswerID: id}) // ClassID == 0
}

GetProblemClass(ctx, 0) always misses, writeItem errors on the first item, Engine.Export aborts, and the handler maps the error to 500 export_failed. It fails deterministically even when the answer and class both exist, because the answer→class link is never copied.

2. The fix

Resolve each answer in the handler and copy its ClassID; return 404 answer_not_found for unknown IDs.

     items := make([]export.ExportItem, 0, len(req.AnswerIDs))
     for _, id := range req.AnswerIDs {
-        items = append(items, export.ExportItem{
-            AnswerID: id,
-            // ClassID left at 0 -> GetProblemClass(0) fails -> 500
-        })
+        answer, err := h.store.GetAnswerNode(r.Context(), id)
+        if err != nil {
+            if errors.Is(err, store.ErrNotFound) {
+                writeError(w, http.StatusNotFound, "answer_not_found",
+                    fmt.Sprintf("answer %d not found", id))
+                return
+            }
+            writeError(w, http.StatusInternalServerError, "export_failed", err.Error())
+            return
+        }
+        items = append(items, export.ExportItem{
+            AnswerID: answer.ID,
+            ClassID:  answer.ClassID, // <-- the fix
+        })
     }

Details: - Resolve all answers before Engine.Export, so an unknown ID can't leave a partial commit. - Use errors.Is(err, store.ErrNotFound) (the store wraps its sentinel). - Genuine engine failures still return 500 export_failed; only unknown answers become 404. - Empty answer_ids remains a successful no-op.

3. Handler-level success test (real bare repo, Push: true)

func TestHandleExport_Success(t *testing.T) {
    dir := t.TempDir()
    if out, err := exec.Command("git", "init", "--bare", "--initial-branch=main", dir).CombinedOutput(); err != nil {
        t.Fatalf("init bare: %v: %s", err, out)
    }

    s := NewStore()
    s.AddClass(&ProblemClass{ID: 42, Name: "two-sum"})
    s.AddAnswer(&AnswerNode{ID: 7, ClassID: 42, Text: "hash map"})
    h := NewHandler(s, NewEngine(s)) // handler sets cfg Push:true

    body := fmt.Sprintf(`{"answer_ids":[7],"target_repo":%q}`, dir)
    req := httptest.NewRequest(http.MethodPost, "/api/v1/export", strings.NewReader(body))
    rec := httptest.NewRecorder()
    h.handleExport(rec, req)

    if rec.Code != http.StatusOK {
        t.Fatalf("want 200, got %d (%s)", rec.Code, rec.Body.String())
    }
    out, err := exec.Command("git", "-C", dir, "log", "--oneline").CombinedOutput()
    if err != nil || !strings.Contains(string(out), "export") {
        t.Fatalf("expected export commit in bare repo: err=%v out=%s", err, out)
    }
}

5. One-line summary

Replace export.ExportItem{AnswerID: id} (which leaves ClassID == 0, making writeItem's GetProblemClass(ClassID) fail every time) with a Store.GetAnswerNode(ctx, id) lookup that copies answer.ClassID, and map unknown IDs to 404 answer_not_found; add a handler-level success test against a real bare repo with Push: true.
