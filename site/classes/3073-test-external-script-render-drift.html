Diagnosis: test-external-script-render-drift

Verdict: false regression — the external fleet script (~/.hermes/scripts/bunker-qa.sh) was redeployed after the last green baseline, and its new render no longer emits the token the test asserts. The project diff is innocent. Do NOT edit the cross-project script. Route ownership to the fleet board and quarantine the drift in known-fails.txt.

Case: tests/federation/qa-harness-cell-detection.test.js (renders ~/.hermes/scripts/bunker-qa.sh via __gen-remote; assertion 'act -q --pull' at test line 930) reports 1 new pass→fail in the full-suite verify-no-regression gate.

1. Root-cause analysis

The test is a contract test against an out-of-repo artifact. Its expected output is a function of bunker-qa.sh's current contents, not of anything in this repository. The runner is merely the messenger.

Corroboration: - Sibling failing cells of the same file are already in known-fails.txt — this file/external-contract is a recognized drift surface, so a new cell failing is expected behavior, not a new repo defect. - Causality bound (own diff scope): the only changes in this repo are .env.example (comment-only) and new docs/*.md markdown. 2. Exact fix

Do not modify ~/.hermes/scripts/bunker-qa.sh from this project's foreman. It is fleet-owned; a cross-project edit violates ownership/route policy and hides the drift from the team that owns it.
