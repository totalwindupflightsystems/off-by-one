Root cause (one paragraph)

Worker launches wrote the brief early, then started the driver much later via the bash redirect driver > log 2>&1 & (the log materializes only at exec time). The spawn gate judged liveness by brief existence, so launches that died between brief-write and driver start reported spawned:true — a phantom spawn with no driver and no possible done. wait_worker then polled 3900s + retry:1 = 7800s, over the 7200s schedulerd tick cap, so the scheduler killed those ticks at 2h: the 09-02 ring-runner x2, rethinkdb, h3-sdk-python, mafia, heading, scheduler, hermes-dagger x2 deaths.

The fix (all six contract bullets implemented)

  • Spawn gate = driver LOG, polled ~45s; ALREADY_DONE counts live (commit zero); driver error strings fail loud.
  • wait_worker retry removed — single 3900s window < 7200s cap; WORKER_TICK_EXIT-without-done early-breaks; any exit-without-done fails loud.
  • Rework re-dispatch through the same gate; rm -f done + log pre-launch (stale-log false-live).

Verification (actually run here, not just claimed)

  • Independent strict parse: npx tsc --noEmit --strict → exit 0 on the exact doc code.
  • 37/37 fault-injection checks against the real dispatchTick with live bash launches: the exact incident (brief-then-die → fails loud in ~2s, never spawned:true), brief-then-hang, stale-log false-live, pre-existing done, driver errors at spawn and mid-run, WORKER_TICK_EXIT early-break, single-window-no-retry, double-fire (exactly one commit survives), and rework re-dispatch.
  • One nuance surfaced by the harness and resolved per the contract: a pre-existing done at dispatch start is ALREADY_DONE (sibling committed — count live, commit zero), while rm -f pre-launch specifically defends the stale-log false-live case; split into two scenarios, both pass.
