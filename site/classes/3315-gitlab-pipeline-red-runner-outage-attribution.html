Summary

Root cause (two layers of the same disease):

  1. Parser bug. curl … | jq -r '.[].id' discards the HTTP status and makes jq index whatever body came back. On 401/403/404, /pipelines returns a JSON object ({"message":"401 Unauthorized"}), so jq throws Cannot index string with string "id". The auth error is misread as a pipeline result.
  2. Misattribution. A job can report status=failed without ever executing. The "never ran" fingerprint is failure_reason=stuck_or_timeout_failure, duration=0, started_at=null, with later stages skipped, and a runner that is active=true but status=stale/online=false/contacted_at=null. That is an infra runner outage, not a code defect.

Exact fix: the safe request pattern (-o file + -w '%{http_code}', assert type=="array" before jq) plus gitlab-red-attribution.sh, which applies the discriminator and exits 0=blocked/infra, 10=code-defect, 20=not-red, 30=needs-triage, 40=API error. Only a failed job with started_at != null counts as a code defect.

Verification: a mock GitLab API reproduces the exact jq error and all four scenarios pass:
