Fix: Add Missing Standard Governance Docs to a Python Project

Problem class: python-project-missing-standard-governance-docs

Summary

The repository passed its code-quality gates but failed a fresh documentation audit because two standard root-level governance documents were absent:

  • SUPPORT.md — where and how users get help.
  • CODE_OF_CONDUCT.md — expected community behaviour and enforcement.

It also failed the audit's linkage rule: help must point security reports at the existing SECURITY.md rather than public trackers. The fix adds both files at the repo root with project-specific content, links SECURITY.md from SUPPORT.md, and verifies the files plus the staged diff before committing.

Root-cause analysis

  1. Governance docs were never part of the code gates. Linters, type checkers, and tests validate source, not repository policy. Nothing in CI asserted the presence of SUPPORT.md / CODE_OF_CONDUCT.md, so their absence was invisible until a separate documentation audit ran.
  2. No single source of truth for "how to get help". Without SUPPORT.md, users default to filing bugs or, worse, disclosing vulnerabilities in public issues.
  3. Security routing was implicit. SECURITY.md existed but nothing in the user-facing help path referenced it, so the private-disclosure process was discoverable only by luck.
  4. Community expectations were undefined. Without a Code of Conduct there was no stated standard or enforcement path for maintainers to rely on.

The correction is purely additive documentation, so it carries no runtime risk and does not alter the code gates.

Exact fix

Run from the repository root. Replace my-python-proj, <email>, and <email> with the project's real values. If SECURITY.md does not exist, create it first (its presence is required for the linkage check).

1. Create SUPPORT.md

# Support

Thanks for using **my-python-proj**! This document explains where to get help
and how to report different kinds of issues.

## Where to get help

| Need | Where to go |
| --- | --- |
| Usage questions / "how do I…" | Open a **Question** discussion or issue |
| Bug reports | Open a **Bug report** issue with a minimal reproduction |
| Feature requests | Open a **Feature request** issue describing the use case |
| Documentation problems | Open an issue referencing the page and the correction |
| Security vulnerabilities | **Do not** use public trackers — see [SECURITY.md](SECURITY.md) |

## Before you ask

1. Check the README and existing issues/discussions for an answer.
2. Confirm you are on a supported Python version (see `pyproject.toml`).
3. Reduce your problem to the smallest reproducible example.

## What to include

- `my-python-proj` version (`pip show my-python-proj`).
- Python version and operating system.
- Exact command run and the full traceback.
- A minimal code snippet that reproduces the behaviour.

## Security issues

Please follow the private disclosure process in [SECURITY.md](SECURITY.md).
Never report vulnerabilities in public issues, discussions, or pull requests.

## Support scope

This is a community-maintained project. Maintainers help on a best-effort basis;
there is no guaranteed response time or commercial support.

Run these checks before committing. The audit must exit 0.

# 1. Both files exist at the repo root and are substantive.
for f in SUPPORT.md CODE_OF_CONDUCT.md; do
  test -f "$f" || { echo "FAIL: $f missing"; exit 1; }
  [ "$(wc -c < "$f")" -ge 200 ] || { echo "FAIL: $f too thin"; exit 1; }
  echo "PASS: $f present ($(wc -c < "$f") bytes)"
done

# 2. SUPPORT.md routes security reports to SECURITY.md.
test -f SECURITY.md || { echo "FAIL: SECURITY.md missing"; exit 1; }
grep -qi "SECURITY.md" SUPPORT.md \
  && echo "PASS: SUPPORT.md links SECURITY.md" \
  || { echo "FAIL: SUPPORT.md does not link SECURITY.md"; exit 1; }

# 3. Diff check before commit: no whitespace errors / conflict markers.

Optional: prevent regressions

Add a lightweight CI check so the docs cannot silently disappear again:

# .github/workflows/docs-governance.yml
name: docs-governance
on: [push, pull_request]
jobs:
  governance:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Check governance docs
        run: |
          set -e
          for f in SUPPORT.md CODE_OF_CONDUCT.md SECURITY.md README.md; do
            test -f "$f" || { echo "missing $f"; exit 1; }
          done
          grep -qi "SECURITY.md" SUPPORT.md
          echo "governance docs OK"

Notes
