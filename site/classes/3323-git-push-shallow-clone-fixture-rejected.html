Answer

Fix CI-only shallow update not allowed in the release fixture

Root cause

actions/checkout with the default fetch-depth: 1 creates a shallow checkout. Its .git/shallow file marks HEAD as a grafted commit whose parents are absent.

The test fixture then does:

git clone --shared . release-repo

A clone of a shallow repository is still shallow: Git copies the .git/shallow boundary into the new clone. --shared only changes object storage/linking; it cannot invent the missing parent commits.

When the test later pushes from that fixture clone, receive-pack sees an incomplete ancestry and rejects the update because receive.shallowUpdate defaults to false:

! [remote rejected] HEAD -> release-fixture (shallow update not allowed)

A normal local checkout has full history, so the same clone has no shallow boundary and the push succeeds. The Python version matrix is incidental: this is a CI checkout/fixture-history problem, not a Python bug.

Exact fix

Do not clone the CI checkout. Build an independent, complete fixture repository from the working-tree files, then create a separate bare origin.

Replace the fixture in tests/test_release_workflow.py with:

from __future__ import annotations

import shutil
import subprocess
from pathlib import Path

import pytest

REPO_ROOT = Path(__file__).resolve().parents[1]


def _git(cwd: Path, *args: str) -> subprocess.CompletedProcess[str]:
    return subprocess.run(
        ["git", *args],
        cwd=cwd,
        check=True,
        capture_output=True,
        text=True,
    )


@pytest.fixture
def release_repo(tmp_path: Path) -> Path:
    work = tmp_path / "repo"
    work.mkdir()

    # Copy only the versioned files the code under test reads.
    # Adjust this list to match the real test.
    versioned_files = (
        "pyproject.toml",
        "src/your_package/__init__.py",
        "src/your_package/version.py",
        "CHANGELOG.md",
    )
    for rel in versioned_files:
        dst = work / rel
        dst.parent.mkdir(parents=True, exist_ok=True)
        shutil.copy2(REPO_ROOT / rel, dst)

    _git(work, "init", "-q")
    _git(work, "config", "user.name", "Fixture Bot")
    _git(work, "config", "user.email", "<email>")
    _git(work, "add", "-A")
    _git(work, "commit", "-q", "-m", "fixture baseline")

    # A fresh, complete, pushable origin.
    remote = tmp_path / "remote.git"
    _git(tmp_path, "init", "--bare", "-q", str(remote))
    _git(work, "remote", "add", "origin", str(remote))

    assert not (work / ".git" / "shallow").exists()
    return work

Key points:

  • mkdir all needed subdirectories before copying.
  • shutil.copy2 only copies versioned working-tree files; no .git history is inherited.
  • git init, git add -A, and git commit create a complete one-commit history with no shallow boundary.
  • git init --bare remote.git and git remote add origin ... provide the push target.
  • Configure the fixture-local Git identity so CI runners without a global identity still work.

Do not fix this with git fetch --unshallow or by enabling shallow updates on the remote; those make the fixture depend on network/upstream history or weaken the remote. Building the fixture from scratch keeps the test hermetic.

Verification

Reproduce the CI condition using a shallow clone, not the full local checkout:

REPO="$(git rev-parse --show-toplevel)"
rm -rf /tmp/shallow-check
git clone --depth 1 --no-local "file://$REPO" /tmp/shallow-check
cd /tmp/shallow-check

# Confirm the checkout really is shallow.
test -s .git/shallow && cat .git/shallow

python -m pytest -q tests/test_release_workflow.py

With the old fixture, this fails with:

! [remote rejected] HEAD -> release-fixture (shallow update not allowed)

With the new fixture, it passes, and the fixture repository has no shallow file:

.                                                                        [100%]
1 passed

I verified both the red and green cases locally using a git clone --depth 1 --no-local file://... checkout. The old git clone --shared fixture fails with the exact reported error; the from-scratch fixture passes under Python 3.12 and 3.14.
