Fixing CI-only Go test failures caused by DATABASE_URL/DB_HOST/DB_PORT pollution

Root cause

The CI job exports PostgreSQL service variables for the build:

env:
  DATABASE_URL: postgres://ci:<email>:5432/app
  DB_HOST: db
  DB_PORT: "5432"

The product code deliberately treats these as a signal that a PostgreSQL backend is configured. When any of them is present it:

  1. Prefers DATABASE_URL over the test's intended SQLite path, so CLI tests connect to the live CI database instead of the fixture DB (surfacing as Tree is empty, because that database has no expected schema/data).
  2. Refuses SQLite-only code paths with an error such as:

DATABASE_URL/DB_HOST/DB_PORT suggest a PostgreSQL backend; unset them (or use SQLITE_DB_PATH)

which is what breaks reset-password applies to SQLite installs only.

The tests are correct; they are simply not hermetic — they inherit ambient process environment. The same failure reproduces locally with DATABASE_URL=… go test ./.... This is the same class of bug previously fixed for AWS_PROFILE in repo precedent commit 90281816, and the fix belongs in test setup, not in the product (weakening the preference would re-open the original product requirement).

Exact fix

Add a shared hermetic scrub helper. It must truly unset the variables (setting them to "" is not enough if the product uses os.LookupEnv), so t.Setenv alone cannot express it. Use os.LookupEnv to capture, os.Unsetenv to clear, and t.Cleanup to restore — mirroring the AWS_PROFILE precedent.

internal/testutil/env.go:

package testutil

import (
    "os"
    "testing"
)

// postgresEnvVars are the variables CI exports for its database service. The
// product intentionally prefers DATABASE_URL and rejects SQLite-only commands
// when any of them is set, so tests targeting SQLite must scrub them.
var postgresEnvVars = []string{"DATABASE_URL", "DB_HOST", "DB_PORT"}

// ScrubPostgresEnv removes PostgreSQL-related environment variables for the
// duration of the test and restores the exact prior state in t.Cleanup.
//
// Values are captured with os.LookupEnv (so "present but empty" is preserved),
// cleared with os.Unsetenv (t.Setenv cannot unset), and restored on cleanup.
func ScrubPostgresEnv(t *testing.T) {
    t.Helper()
    for _, key := range postgresEnvVars {
        key := key
        value, ok := os.LookupEnv(key)
        if err := os.Unsetenv(key); err != nil {
            t.Fatalf("testutil: unset %s: %v", key, err)
        }
        if ok {
            t.Cleanup(func() {
                if err := os.Setenv(key, value); err != nil {
                    t.Errorf("testutil: restore %s: %v", key, err)
                }
            })
        }
    }
}

Call it at the top of every affected test (all CLI/integration tests that expect SQLite):

func TestTree(t *testing.T) {
    testutil.ScrubPostgresEnv(t)
    // ... existing test body ...
}

func TestResetPasswordSQLite(t *testing.T) {
    testutil.ScrubPostgresEnv(t)
    // ... existing test body ...
}

If a whole package is affected, do it once for the package so no test can be forgotten. t.Cleanup is unavailable in TestMain, so restore explicitly:

func TestMain(m *testing.M) {
    type saved struct {
        key   string
        value string
        ok    bool
    }
    var restore []saved
    for _, key := range []string{"DATABASE_URL", "DB_HOST", "DB_PORT"} {
        v, ok := os.LookupEnv(key)
        restore = append(restore, saved{key, v, ok})
        _ = os.Unsetenv(key)
    }

    code := m.Run()

    for _, s := range restore {
        if s.ok {
            _ = os.Setenv(s.key, s.value)
        } else {
            _ = os.Unsetenv(s.key)
        }
    }
    os.Exit(code)
}

When the test needs an explicit SQLite target, set it deterministically instead of relying on inherited state:

t.Setenv("SQLITE_DB_PATH", filepath.Join(t.TempDir(), "test.db"))

Quick local/CI workaround without a code change:

env -u DATABASE_URL -u DB_HOST -u DB_PORT go test ./...

Optional Makefile hardening so local runs match hermetic tests:

test:
    env -u DATABASE_URL -u DB_HOST -u DB_PORT go test ./...

(Or env DATABASE_URL=... DB_HOST=... DB_PORT=... go test ./....)

  1. Restoration check — confirms the scrub is hermetic and does not leak state to sibling tests. Add temporarily or keep as a regression test:

go func TestScrubRestoresEnv(t *testing.T) { t.Setenv("DATABASE_URL", "postgres://original") testutil.ScrubPostgresEnv(t) if _, ok := os.LookupEnv("DATABASE_URL"); ok { t.Fatal("DATABASE_URL still set after scrub") } t.Cleanup(func() { if got := os.Getenv("DATABASE_URL"); got != "postgres://original" { t.Fatalf("cleanup did not restore original value, got %q", got) } }) }

  1. End-to-end confirmation — the two reported symptoms disappear:

Why not fix it in the product?

The PostgreSQL preference is intentional product behavior. Scrubbing in tests is the correct fix: it makes the test suite hermetic, leaves the product contract untouched, and follows the existing AWS_PROFILE precedent (commit 90281816).
