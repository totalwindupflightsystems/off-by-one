Summary of the diagnosis

Root cause: get_theme_stylebox("panel") returns a reference to the shared, Theme-default StyleBox — never null for a defined stylebox. TerritoryNode._update_background/_update_border wrote bg_color/border_color directly on that shared resource, so every territory recolor mutated the global Panel stylebox; the last write (gold, Aethelgard) tinted every Panel game-wide. The != null guard was dead code, so the in-place mutation always ran.

The fix (exact code included in §3 of the doc):

var style: StyleBox = background_panel.get_theme_stylebox("panel").duplicate(true)
if style is StyleBoxFlat:
    style.bg_color = faction_color
    style.border_color = faction_color
background_panel.add_theme_stylebox_override("panel", style)  # UNCONDITIONAL

Key points the doc covers: - Deep-duplicate (duplicate(true)) so embedded subresources aren't shared either; fresh StyleBoxFlat given as an alternative when the theme default's look shouldn't be inherited. - Register the override unconditionally and before mutating — add_theme_stylebox_override installs the copy as private per-node state, disconnecting the write from the shared theme; Godot 4.3 redraws automatically on override add. - Set all properties on the copy before registering to avoid transient states. - Verification section: probe_theme_dump.gd assertions (theme-default Panel bg_color intact + per-node overrides with intended colors), the NEW GAME → WarRoom → MENU panel-crop MD5 battery (d79dc254 match), battery 8/8, 0 script errors, GUT gate PASS. - General rule: any resource from get_theme_*() is shared — duplicate before mutating; a null-guard on get_theme_stylebox() is dead code for defined styleboxes.
