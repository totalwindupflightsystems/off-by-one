Diagnosed and verified. Full solution written to ~/hermes-worker-worktree-cwd-resolution.md. Summary of what it contains:

Root causes (two, independent)

RC-1 — shell cd never reaches the agent session. hermes chat builds its session from the project workdir, ignoring the launcher's cwd. So cd <worktree> && hermes chat runs the agent in ~/<proj>; the worktree stays clean while the canonical checkout gets edited.

RC-2 — worktree venv resolves the canonical source. A fresh worktree has no .venv, and the pre-commit guard runs the canonical .venv/bin/python. A symlinked venv only works for flat layouts (cwd sys.path[0]=='' shadows the editable finder). For src/ layouts the editable finder wins and the guard grades the canonical tree — a phantom pass.

The fix

  1. Self-locating brief preamble prepended to every worker brief: cd <ABS_WORKTREE> → pwd → abort with STATUS: FAILED - WRONG TREE <pwd> if not exact; all paths absolute; canonical checkout forbidden.
  2. Fail-closed venv preflight in the dispatcher: assert realpath(import <pkg>.__file__) is under the worktree; otherwise build a real venv (uv venv && uv pip install --python .venv/bin/python -e . pytest pytest-xdist ruff).
  3. Post-wave audit: canonical must show no worker-authored changes; each worktree must show a non-empty diff.

Verification (reproduced here, not just asserted)

  • Flat layout, symlinked canonical venv → imported /tmp/vtest/worktree/mypkg/__init__.py ✅
  • Src layout, symlinked canonical venv → imported /tmp/vtest2/canonical/src/mypkg/__init__.py ❌; the assertion correctly failed closed (rc=3)
  • After building a real venv in the worktree → imported the worktree copy ✅

The document also records the field verification from the 2026-10-20 gitreins wave (both workers wrote only inside their own worktrees; canonical stayed clean) and the acceptance checks for future waves.

Acceptance rule: each worker must prove its own pwd, its worktree must show a diff, and the canonical git status --porcelain must show no worker edits.
