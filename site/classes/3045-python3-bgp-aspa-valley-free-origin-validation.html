Fix: RPKI Origin Validation + ASPA Valley-Free Path Validation

Root cause

Origin validation alone only checks whether the rightmost external ASN is authorised by a covering ROA. It cannot detect a forged path that keeps a legitimate origin but contains:

  • a provider-to-customer hop followed by a customer-to-provider hop — a valley violation;
  • an unauthorised customer/provider edge;
  • obscured routing through AS_SET, confederation segments, or prepends;
  • MOAS ambiguity where several origins have valid ROAs.

The fix validates origin and path independently, then combines them: invalid dominates, otherwise unknown dominates, otherwise valid.

Exact fix

Implemented in:

  • ~/bgp_aspa.py — complete standard-library-only validator and CLI
  • ~/test_bgp_aspa.py — 57-path verification corpus
  • ~/solution.md — full markdown solution including both source files

Core rules:

  • BGP paths use normal wire order: rightmost ASN is the origin.
  • ASPA validation reverses the external sequence to reason from origin to receiver.
  • For each adjacent pair:
  • up: next AS is an authorised provider of the current AS.
  • down: current AS is an authorised provider of the next AS.
  • conflict: both directions are authorised → invalid.
  • unknown: neither direction is authorised by available ASPA data.
  • A down followed by a later up is a valley → invalid.
  • AS_SET origin uses any-member ROA matching; path validation becomes unknown.
  • AS_CONFED_SEQUENCE / AS_CONFED_SET are ignored.
  • Consecutive prepends are collapsed.
  • MOAS is handled by matching any authorised origin.
  • Invalid paths report the shortest contiguous witness subpath and offending edge indexes.
  • Prefixes, paths, witnesses, and JSON keys are deterministically ordered.

Run directly:

cd ~
python3 bgp_aspa.py \
  --roas roas.json \
  --aspas aspas.json \
  --paths paths.json \
  --output report.json

Input JSON may be bare arrays or objects with roas, aspas, and paths keys.
