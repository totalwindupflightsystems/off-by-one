Summary

Root cause: gitreins task complete prints a job/run id (7be0b5f8) that is not guaranteed to equal the verdict directory name (46139e5a). The two are different namespaces. The durable key is the task_id field inside verdict.json, not the printed id and not the directory name.

Fix (three parts): 1. Resolver — glob .gitreins/history/<date>/*/verdict.json, keep entries whose task_id matches the completed task, sort by mtime descending, take the newest. Never use the printed id. 2. Byte-safe repair — read events.jsonl as bytes and replace the exact wrong id only; refuses 0 or >1 matches; atomic write; preserves all other rows' whitespace/key-order byte-for-byte. 3. Sweep — per-line json.loads over the whole file to prove every row still parses. 4. Commit discipline — new disclosed commit, never amend/force-push already-pushed history.

Verified: - Resolver correctly rejected a decoy dir literally named 7be0b5f8 (wrong task_id) and an older same-task verdict, selecting 46139e5a. - Byte-safe replace preserved a double-space string exactly; JSONL sweep passed all rows. - Guards correctly refused an ambiguous 2-occurrence match and a missing id. - Git log demonstrated original + disclosed correction commit rather than an amend.
