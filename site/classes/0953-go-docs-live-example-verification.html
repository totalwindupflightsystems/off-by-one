Correction pattern applied to each of the 7 stale areas (each ✗ WRONG → ✓ CORRECT pair was live-probed, not eyeballed):

1. Health path        ✗ GET /healthz {"ok":true}
                      ✓ GET /health  -> 200 {"status":"ok","version":"1.4.2"}
                        (dependency down -> 503 {"status":"degraded",...})
2. Command tree       ✗ flctl run --pipeline nightly.yaml
                      ✓ flctl flows run --source <api|file> [--spec <yaml>] [--name <n>]
3. MCP tool names     ✗ run_flow / get_run_state
                      ✓ flow_run_start, flow_run_status, flow_list
4. Flow run shape     ✗ {"id":"abc","state":"running"}
                      ✓ {"flow_id":"fr_000003","status":"queued","phase":"pending",
                         "source":"api","started_at":"2026-08-11T03:00:02Z"}
                        (status: queued|running|succeeded|failed — no "state" key)
5. Webhook mechanism  ✗ unsigned POST on every state change
                      ✓ POST /api/webhooks/flow-run-events, terminal events only,
                        header X-Webhook-Signature: sha256=<hex hmac-sha256(secret, body)>
                        204 valid / 401 invalid / 405 non-POST
6. --source semantics ✗ --source <yaml path>
                      ✓ --source selects provenance (api|file); YAML path is --spec,
                        required for source=file, rejected usage -> exit 2
7. /api/flows shape   ✗ {"flows":[{"name":...}]}
                      ✓ {"items":[{flow_id,name,status,phase,source,started_at}],
                         "total":N,"page":1,"page_size":20}  (items=[] never null)

Verification harness (the reusable fix — one command, JSON-free, runs against any HEAD build):

# probe.sh: asserts the CORRECTED contract; every check is a live HTTP/CLI probe
check() { code=$(curl -s -o "$TMP/h.json" -w '%{http_code}' "$BASE/health"); ... }
record() { [ "$ok" -eq 0 ] && PASS++ || FAIL++; }   # ok=0 default = success
# e.g. flow-run shape: 201 + status=queued + flow_id + NO "state" key
ok=0; [ "$code" = "201" ] && [ "$st" = "queued" ] && [ -n "$fid" ] \
  && [ "$has_state" = "false" ] || ok=1

Dispatch protocol (foreman → worker): before dispatch, foreman builds fresh HEAD, runs probe.sh + a stale-example detector against it, and embeds a VERIFIED FACTS block (the 7 corrected facts above) in the worker prompt; the worker then edits only integration-guide.md and re-runs probe.sh to prove each corrected example. Judge fallback (imhotep S02 exception): GitReins failed twice — attempt 1: non-JSON truncated output → do not parse judge output; attempt 2: 2M input-token cap → verify from criteria.json only (each corrected doc example maps 1:1 to a probe check name), never feed the full diff into the judge prompt. All fallbacks documented in criteria.json.
