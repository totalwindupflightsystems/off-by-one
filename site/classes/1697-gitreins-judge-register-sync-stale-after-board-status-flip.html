Fixing stale governance register/pack after a task-board status flip

Problem class: gitreins-judge-register-sync-stale-after-board-status-flip Symptom: After any commit that rewrites the JSONL task board (sponsor classification pass, QA-driven status flip), the register-sync test leg is red at HEAD. The generated register and the beta-110 assurance pack no longer match the board.

1. TL;DR (the fix, in order)

  1. Flip the board row first with an appended last-row-wins row plus an explicit-id task_status_change event.
  2. python3 scripts/gen-disposition-register.py --write → then --validate must pass.
  3. Regenerate the beta-110 assurance pack with scripts/release-gate-matrix.mjs.
  4. Align the three stale test assertions in apps/api/test/release-gate-matrix.test.mjs to the canonical sponsor-decision states, with rationale comments.
  5. Run the targeted vitest before committing.
  6. Run the tier2 judge on the settled tree before the board commit (events.jsonl is not a register input, but settling first avoids tier1 false reds).
  7. Commit the fix and the board separately, push, verify git rev-list --count <remote>/<branch>..HEAD is 0.
  8. Harden: assertions must be state-anchored (sponsor doc), not status-value-anchored, so a future flip only needs a regen — not another assertion edit.

2. Root-cause analysis

Layer Artifact Truth source
Board docs/governance/**/task-board.jsonl (append-only; last row wins for an id) human/agent intent
Events docs/governance/**/events.jsonl (task_status_change with explicit id) audit trail
Generated docs/governance/beta-risk-and-feature-disposition-register.md appendix (scripts/gen-disposition-register.py) and docs/release/beta-110 gate matrix assurance pack (scripts/release-gate-matrix.mjs) derived from the board
Enforcement apps/api/test/release-gate-matrix.test.mjs (vitest, register-sync leg) asserts generated == board

Four failure mechanisms stack:

  1. Generated artifacts are committed. Any board mutation without a regeneration commit leaves them stale; the register-sync leg fails at HEAD, not at edit time.
  2. A status flip has transitive blast radius. Dependency edges (blocked_by / depends_on) mean flipping a complete row to blocked reopens dependent deferred/planned gate rows to blocked. One flip can change N generated rows — a hand patch can never be correct.
  3. The test hardcodes prior row states. Regenerating artifacts leaves the test asserting the old world, so --write alone is insufficient.
  4. Ordering hazard (settle-before-judge). events.jsonl is not a register input, but the judge observes events; committing the board before settling can produce a tier1 false red on an intermediate tree.

Why the naive fixes fail: hand-editing the register leaves the pack stale; regenerating alone leaves assertions red; patching the test alone leaves --validate red; committing the board first exposes a red intermediate HEAD to the judge.

4. The exact fix

Step 0 — Freeze baseline

BASE=$(git rev-parse HEAD)
BRANCH=$(git rev-parse --abbrev-ref HEAD)
REMOTE=$(git config --get branch."$BRANCH".remote || echo origin)

Step 1 — Flip the board row (append-only) + explicit event

Never rewrite existing JSONL lines. Append a same-id row carrying the new status; canonical state is the last occurrence. Also append an explicit-id task_status_change event.

TASK_ID='<ROW-ID>'          # e.g. FEAT-123
NEW_STATUS='blocked'
TS=$(date -u +%Y-%m-%dT%H:%M:%SZ)

python3 - "$BOARD" "$TASK_ID" "$NEW_STATUS" "$TS" <<'PY'
import json, sys
board, tid, new, ts = sys.argv[1:5]
rows = [json.loads(l) for l in open(board) if l.strip()]
base = next(r for r in reversed(rows) if str(r.get("id")) == tid)  # current canonical
old = base.get("status")
row = dict(base); row["status"] = new; row["updated_at"] = ts
with open(board, "a") as f:
    f.write(json.dumps(row, separators=(",", ":")) + "\n")
print(f"board: {tid} {old} -> {new}")
PY

python3 - "$EVENTS" "$TASK_ID" "$NEW_STATUS" "$TS" <<'PY'
import json, sys
events, tid, new, ts = sys.argv[1:5]
with open(events, "a") as f:
    f.write(json.dumps({
        "event": "task_status_change",
        "id": tid,                 # explicit id, never inferred from position
        "to": new, "ts": ts, "actor": "agent",
    }, separators=(",", ":")) + "\n")
PY

Dependency propagation is expected. If dependents flip (deferred/planned → blocked), that is correct board semantics; the generators will encode it.

Step 2 — Regenerate the disposition register

python3 scripts/gen-disposition-register.py --write
python3 scripts/gen-disposition-register.py --validate   # must exit 0

Step 3 — Regenerate the beta-110 assurance pack

node scripts/release-gate-matrix.mjs --write
node scripts/release-gate-matrix.mjs --check || true

Step 4 — Align the three stale test assertions (state-anchored)

The test pins prior status values. Re-point the three expectations at the canonical sponsor-decision states, with rationale comments. Discover new canonical values from the generated artifacts:

git diff -- "$REGISTER" | sed -n '1,200p'
git diff -- "$PACK"     | sed -n '1,200p'

// apps/api/test/release-gate-matrix.test.mjs
// Sponsor decision (doc: beta-risk-and-feature-disposition-register.md): <DECISION>.
// State is anchored to the sponsor decision, not to the row's raw status value.
// A future board flip changes the generated pack; it must not require editing this test.

// BEFORE (status-value anchored -> breaks on every board flip):
// expect(row('<GATE-ID>').status).toBe('planned');

// AFTER (state anchored to the canonical sponsor decision):
expect(dispositionOf('<GATE-ID>')).toBe('<CANONICAL-STATE>'); // was 'planned' pre-flip

If dispositionOf does not exist, add a thin accessor reading the generated pack's decision field:

import pack from '../fixtures/beta-110-assurance-pack.json' assert { type: 'json' };
const dispositionOf = (id) => pack.rows.find((r) => r.id === id)?.disposition;

Rule: assert on the sponsor decision/disposition, never on the raw board status.

5. Make it durable

  • CI drift guard: run both generators with --write, then git diff --exit-code -- "$REGISTER" "$PACK".
  • State-anchored assertions only — no test references raw board status.
  • Append-only board — always append a last-row-wins row plus an explicit-id event.
  • Settle-before-judge — judge the settled tree; commit board and fix separately afterward.
