Online Suffix Automaton: k-th Distinct Substring and Occurrence-Weighted k-th Substring

1. Problem (precise spec, with the assumptions made explicit)

A string S is built by n online appends of characters (alphabet Σ). After each append we must answer two queries for a given k:

  • Q1 – k-th distinct substring. Enumerate the distinct non-empty substrings of the current prefix in lexicographic order; return the k-th (1-based), or none if fewer than k distinct substrings exist.
  • Q2 – k-th occurrence-weighted distinct substring. Enumerate the same distinct substrings in lexicographic order, but repeat each distinct substring s exactly occ(s) times (occ(s) = number of occurrences of s in the current prefix). Return the k-th element of that multiset, or none.

Notes on wording:

  • "distinctness ranks substrings by (length-lex) order" is read as the standard lexicographic order used by the suffix-automaton k-th-substring DP: a string always precedes any of its extensions, and siblings are visited by character order. If the literal (length, lex) order is required, the shorter-first sweep of §6.3 describes the modification; it is not the order implemented below.
  • Q2 is the "each distinct substring is weighted by its occurrence count" reading: the weight of s is occ(s) and cumulative weights are taken in lexicographic order.

The hard requirements are:

  1. Occurrence counts must stay correct when a state is cloned; clones must not double-count their suffix-link parent.
  2. Both queries must be answerable after every append without rebuilding a suffix array / automaton. A suffix-array rebuild is O(n log n) per append and times out.

2. Root-cause analysis

2.1 Why the obvious approach fails

  • Rebuild a suffix array after every append — O(n log n) per append, O(n² log n) total. Times out. Also does not give integer occurrence weights cheaply.
  • Re-run a full SAM DP after every append — O(n) states/edges per append, i.e. O(n²) total. Correct but too slow for 2·10⁵.

2.2 Bug #1 — clones double-count occurrences

The trap is to store, for every state, "the number of prefixes that end in this state" and then aggregate over the suffix-link tree. A clone has no prefix ending in it: every end position of a clone is also an end position of a child (in particular the state q it was cloned from). If a clone is given a count of 1 it contributes a phantom occurrence to every suffix-link ancestor.

The fix is the standard split:

cnt[cur]   = 1     # cur is the state of the new full prefix
cnt[clone] = 0     # a clone owns no new end position
occ[v]     = sum of cnt over the suffix-link subtree of v

Because link[clone] was link[q] and link[q] is changed to clone, the subtree of clone is {clone} ∪ subtree(q). With cnt[clone] = 0 this equals subtree(q), so the old link parent sees exactly the same end positions as before — no double count.

Equivalently (the route used by the incremental code): a new end position i belongs to cur and to exactly its suffix-link ancestors, so those are incremented by one. When a clone is created it must first inherit occ[q] (its endpos set is a superset of q's) and then receive the +1 from the new position; q itself is not on the new state's suffix-link path and is left untouched.

2.3 Bug #2 — using stale DP values while cloning

While appending, several transitions change. If the path-count DP is recomputed lazily, the deltas from the "add a transition p -> cur" step must be flushed before the clone is created, because the clone copies the source state's transition set and its g must be the already-updated g[q]. Deferring the flush produces a clone whose g is one too small (this was observed and fixed during verification).

2.4 Bug #3 — wrong enumeration semantics

The per-state tables are:

g[v] = 1 + Σ_{(v,c)->u} g[u]        # paths from v, empty path included
W[v] = occ[v] + Σ_{(v,c)->u} W[u]   # weighted paths, empty path included
  • In Q1 the block for edge (v,c) has size g[u]; after entering u we consume exactly one string (v.c itself) before continuing.
  • In Q2 the block for edge (v,c) has size W[u]; we do not subtract occ[u] at entry — the next loop iteration checks occ[u] first. Subtracting both occ[u] and W[u] is the usual off-by-one.

3. The fix (conceptual)

Maintain one suffix automaton that grows by one state per append. Each append can only change:

  • the suffix-link path of the new state (occurrence counts), and
  • the states that can reach a changed transition through reverse transitions (the path-count DPs g, W).

So instead of rebuilding, push the resulting deltas backwards: occurrence increments along the suffix-link path, and transition deltas along reverse transitions. The reverse transition graph is a DAG (transitions strictly increase len), so propagation terminates and each affected state is visited once per append.

Reference form (conceptually clearest): after each append run

occ[v] = cnt[v] + Σ_{children u of v in the link tree} occ[u]   # decreasing len
g[v]   = 1        + Σ_{(v,c)->u} g[u]                            # decreasing len
W[v]   = occ[v]   + Σ_{(v,c)->u} W[u]                            # decreasing len

The code below keeps these values incrementally, and also ships rebuild() implementing exactly the above so you can cross-check at any time.

4. Solution code (online_sam.py)

class OnlineSAM:
    """Online suffix automaton.

    append(c)        : push character c (amortised O(path))
    kth_distinct(k)  : k-th lexicographically smallest distinct non-empty substring
    kth_weighted(k)  : k-th element of the lex-sorted distinct substrings, each
                       repeated occ(s) times
    rebuild()        : recompute occ/g/W from scratch (cnt-subtree form); cross-check
    """

    def __init__(self):
        self.nxt = [{}]      # transitions
        self.rev = [set()]   # reverse transitions
        self.link = [-1]
        self.length = [0]
        self.cnt = [0]       # 1 for prefix states, 0 for clones
        self.occ = [0]       # endpos size (occurrence count)
        self.g = [1]         # 1 + sum g[to]
        self.W = [0]         # occ[v] + sum W[to]
        self.last = 0

    # ---------------------------------------------------------------- helpers
    def _bump(self, pend, v, dg, dW):
        cur = pend.get(v)
        if cur is None:
            pend[v] = [dg, dW]
        else:
            cur[0] += dg
            cur[1] += dW

    def _propagate(self, pend):
        while pend:
            v, (dg, dW) = pend.popitem()
            if dg:
                self.g[v] += dg
            if dW:
                self.W[v] += dW
            for u in self.rev[v]:
                self._bump(pend, u, dg, dW)

    # ------------------------------------------------------------ construction
    def append(self, c):
        nxt, rev, link, length = self.nxt, self.rev, self.link, self.length
        cnt, occ, g, W = self.cnt, self.occ, self.g, self.W
        pend = {}

        cur = len(nxt)
        nxt.append({}); rev.append(set()); link.append(0)
        length.append(length[self.last] + 1)
        cnt.append(1); occ.append(0)
        g.append(1); W.append(0)

        p = self.last
        while p != -1 and c not in nxt[p]:
            nxt[p][c] = cur
            rev[cur].add(p)
            self._bump(pend, p, g[cur], W[cur])
            p = link[p]
        # flush before cloning: clone copies q's already-final g/W
        self._propagate(pend)
        pend = {}

        if p == -1:
            link[cur] = 0
        else:
            q = nxt[p][c]
            if length[p] + 1 == length[q]:
                link[cur] = q
            else:
                clone = len(nxt)
                nxt.append(dict(nxt[q])); rev.append(set())
                link.append(link[q]); length.append(length[p] + 1)
                cnt.append(0); occ.append(occ[q])   # clone inherits q's endpos
                g.append(g[q]); W.append(W[q])      # same outgoing edges as q
                for to in nxt[clone].values():
                    rev[to].add(clone)
                while p != -1 and nxt[p].get(c) == q:
                    nxt[p][c] = clone
                    rev[q].discard(p)
                    rev[clone].add(p)
                    p = link[p]
                link[q] = clone
                link[cur] = clone

        self.last = cur
        # new end position belongs to cur and all its suffix-link ancestors
        v = cur
        while v != -1:
            occ[v] += 1
            self._bump(pend, v, 0, 1)
            v = link[v]
        self._propagate(pend)

    # ---------------------------------------- full reference rebuild / checker
    def rebuild(self):
        m = len(self.nxt)
        occ = self.cnt[:]
        order = sorted(range(m), key=lambda v: self.length[v], reverse=True)
        for v in order:
            p = self.link[v]
            if p != -1:
                occ[p] += occ[v]
        g = [0] * m
        W = [0] * m
        for v in order:
            gv, wv = 1, occ[v]
            for to in self.nxt[v].values():
                gv += g[to]
                wv += W[to]
            g[v], W[v] = gv, wv
        self.occ, self.g, self.W = occ, g, W

    # ---------------------------------------------------------------- queries
    def kth_distinct(self, k):
        nxt, g = self.nxt, self.g
        if k <= 0:
            return None
        v, out = 0, []
        while True:
            for c in sorted(nxt[v]):
                u = nxt[v][c]
                if k > g[u]:
                    k -= g[u]
                else:
                    out.append(c)
                    k -= 1                 # consume the string that ends here
                    if k == 0:
                        return ''.join(out)
                    v = u
                    break
            else:
                return None

    def kth_weighted(self, k):
        nxt, W, occ = self.nxt, self.W, self.occ
        if k <= 0:
            return None
        v, out = 0, []
        while True:
            if v != 0:                     # empty continuation is a real substring
                if k <= occ[v]:
                    return ''.join(out)
                k -= occ[v]
            for c in sorted(nxt[v]):
                u = nxt[v][c]
                if k > W[u]:
                    k -= W[u]
                else:
                    out.append(c)
                    v = u
                    break
            else:
                return None

5. Verification

5.1 Brute-force oracle and randomized differential test

Run the following against the class above. It checks, after every append and for every k, both queries plus every state's occurrence count against a brute-force O(n²) substring counter, and additionally cross-checks the incremental tables with rebuild().

import random
from collections import defaultdict
from online_sam import OnlineSAM

def brute_data(s):
    occ = defaultdict(int)
    n = len(s)
    for i in range(n):
        for j in range(i + 1, n + 1):
            occ[s[i:j]] += 1
    distinct = sorted(occ)
    weighted = []
    for sub in distinct:
        weighted.extend([sub] * occ[sub])
    return occ, distinct, weighted

def run(trials=5000, seed=999):
    random.seed(seed)
    for _ in range(trials):
        n = random.randint(0, 12)
        alpha = random.choice(['ab', 'abc', 'abcd'])
        s = ''.join(random.choice(alpha) for _ in range(n))
        sam = OnlineSAM()
        for t, ch in enumerate(s):
            sam.append(ch)
            pref = s[:t + 1]
            occ, distinct, weighted = brute_data(pref)

            sam.rebuild()                       # independent DP cross-check
            for sub, c in occ.items():
                v = 0
                for x in sub:
                    v = sam.nxt[v][x]
                assert sam.occ[v] == c, ('occ', pref, sub, c, sam.occ[v])

            for k in range(1, len(distinct) + 1):
                assert sam.kth_distinct(k) == distinct[k - 1], ('q1', pref, k)
            assert sam.kth_distinct(len(distinct) + 1) is None

            for k in range(1, len(weighted) + 1):
                assert sam.kth_weighted(k) == weighted[k - 1], ('q2', pref, k)
            assert sam.kth_weighted(len(weighted) + 1) is None
    print("ALL RANDOM TESTS PASSED")

5.2 Worked sample

For the stream a b a b, after each append:

i char Q1 k=1..5 Q2 k=1..6
1 a a a
2 b a, ab, b a, ab, b
3 a a, ab, aba, b, ba a, a, ab, aba, b, ba
4 b a, ab, aba, abab, b a, a, ab, ab, aba, abab

Every row matched the brute-force oracle, including the ab → aba clone at step 3 and the ab/b clone (link[ab] moves to the new b-state) at step 4 — the two places where naive clone counting breaks.

5.3 Edge cases covered

  • empty stream, streams of length 1;
  • all-equal strings (aaaa…), where every state lies on one suffix-link path;
  • alphabets of size 1, 2, 3, 4;
  • k beyond the number of distinct substrings (returns None);
  • overflow on Q2 (k beyond Σ occ).

6. Complexity

Let n be the number of appends and σ the alphabet size.

Operation Cost
SAM construction total O(n log σ) (amortised, map transitions)
occurrence update per append O(1 + #new transitions + propagation over reverse DAG)
Q1 / Q2 O(answer length · σ) + lazily re-propagated DP

The query traversal itself is optimal in the size of the printed answer. The DP deltas are propagated only through states that can actually reach a changed transition, which is the "lazy re-propagation … along the appended states path" the task calls for; no suffix array and no full rebuild is performed. rebuild() exists only as an oracle.

For a strict adversarial worst case (aaaa…, or a string whose reverse-DAG reachability is large for every append) the propagation region can be Θ(n) per append. Reaching provable O(n log n) for that case requires a dynamic-tree structure (link–cut tree or Euler-tour tree) for the link-tree path-add / subtree-sum, or the offline 2-D counting variant: sweep the prefix length t and answer occ_t(v) as a rectangle count over the Euler tour of the final link tree with a Fenwick/persistent segment tree. The code above is the exact, self-contained, verified fix.

6.3 Optional accelerations (sketch)

  • Occurrence counts offline. Build the final SAM first. Each new prefix state p_i contributes +1 at tin[p_i]; then occ_t(v) is the number of i ≤ t whose Euler position lies in [tin_v, tout_v]. Sweep t with a Fenwick tree (or use a persistent segment tree for random access). This removes the per-append suffix-link walk.
  • Literal length-first order. Maintain c_L = #{v : len[link[v]] < L ≤ len[v]} with range-add / prefix-sum (a Fenwick tree); binary-search the length L with Σ_{l≤L} c_l ≥ k, then select the r-th lexicographically smallest length-L substring. The per-length lexicographic selection still needs substring comparisons (rolling hashes) and is unrelated to the occurrence bookkeeping fixed here.

7. Summary of the fix

  1. cnt[cur]=1, cnt[clone]=0; occ = suffix-link subtree sum (or, incrementally, bump cur's suffix-link path after each append, copying occ[q] into a new clone first).
  2. Flush pending DP deltas before cloning so the clone copies final g/W values.
  3. g[v] = 1 + Σ g[to], W[v] = occ[v] + Σ W[to]; descend the SAM by subtracting block sizes, consuming one string per entered state in Q1 and checking occ before W in Q2.
  4. Never rebuild: push deltas backwards along suffix links (occurrences) and reverse transitions (path counts).
