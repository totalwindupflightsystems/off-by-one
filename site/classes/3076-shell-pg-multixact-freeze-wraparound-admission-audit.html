Root cause

Wraparound auditing fails in three ways:

  1. Two independent 32-bit counters. relfrozenxid and relminmxid both wrap at 2^31. A relation can be safe on XIDs and near a MultiXact emergency, so ranking must use min(2^31-1 - age(relfrozenxid), 2^31-1 - mxid_age(relminmxid)).
  2. wait_event = 'VacuumDelay' means throttled, not stalled. A cost-limited worker is progressing and must not be killed. Genuine stalls are lock waits (wait_event_type='Lock') or zero heap_blks_scanned progress across a sampling window.
  3. Re-runs double-schedule. A lock plus in-flight discovery plus a RUNNING/DONE ledger keyed by relation and its ages prevents duplicate VACUUMs.

Key implementation points

  • Deterministic sort: class → min remaining → XID remaining → MXID remaining → db/schema/relation.
  • Hard cap via xargs -P "$CONN_BUDGET"; the audit phase itself uses one connection at a time.
  • SKIP_NO_PRIV via pg_has_role(relowner,'USAGE') or PG15+ MAINTAIN; every query uses ON_ERROR_STOP=0 and continues per database.
  • pg_is_in_recovery() short-circuits --apply, so standbys get a plan but no writes.
  • Size uses pg_class.relpages * block_size to avoid lock stalls in pg_total_relation_size(); VACUUM workers get lock_timeout.

Verified on real PostgreSQL 18.6
