Root cause

Doc-to-code drift in admin-key-rotation.md: - The runbook sends ttl_hours: 2160 (hours) and reads a key response field. - The real handler (internal/api/billing.go:250 parses requests, :326 builds responses) accepts expires_in = seconds from now — 90 d = 2160 h = 7,776,000 s — and returns api_key + key_prefix, with no expires_at in the create response.

Fix (exact)

  1. Inspect the handler first: sed -n '240,335p' internal/api/billing.go
  2. In the runbook: replace ttl_hours: 2160 → expires_in: 7776000
  3. Replace jq -r .key → jq -r .api_key (keep .key_prefix as the identifier); drop any expires_at reference from the create-response handling
  4. One-shot: sed -i -e 's/ttl_hours\s*:\s*2160/expires_in: 7776000/g' -e 's/jq -r \.key"/jq -r .api_key"/g' docs/runbooks/admin-key-rotation.md
