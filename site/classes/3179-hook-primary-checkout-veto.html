Summary

Note: the coding-hermes-scheduler repo is not present in this sandbox (only stale systemd unit files and /etc/coding-hermes), so I reconstructed the two affected components faithfully from the spec and verified the fixes by execution.

Root causes (both required)

  1. worktree-ensure.sh: git worktree list --porcelain always lists the primary checkout first, so the "already a registered worktree" scan matched the primary path, skipped creation, and then the HEAD != lane-branch guard fired die 65. It's a misclassification, not a real branch mismatch.
  2. internal/lanehook/runner.go: every non-zero exit was mapped to state=failed, retried, and passed to on_failure=closed, ignoring the contract's reserved exit 10 = "nothing to do" (already emitted by lane-merge).
  3. Secondary hazard: with policy=persistent, the old path could run reset --hard origin/main + clean -fdq against the primary tree.

Fix

  • Shell: after arg parsing and before any mutation, resolve the primary as the first worktree line, canonicalize with pwd -P on the primary, --worktree, and --repo, and if they match print skip reason=workdir-is-primary-checkout ... and exit 10. 65/75/78 unchanged.
  • Go: classifyExit as a tagged switch (satisfies staticcheck QF1003) mapping 10 → stateSkipped; skipped is non-fatal, terminal (no retry), receipt state=skipped carrying child output, plus INFO hook.<phase>.skipped.

Verification performed

  • Pre-fix shell on primary → rc=65 (matches reported symptom).
  • Post-fix shell on primary (persistent) → rc=10, reason token printed, primary still on main and clean.
  • Post-fix dedicated wrong-branch worktree → rc=65; correct lane worktree → rc=0.
  • Go RED proof against pre-fix runner → a skip must not be retried, got "3" attempt(s) (exact expected message) and the veto test fails; post-fix → gofmt/vet/test all clean.

The doc also includes the full test snippets and the CI gotcha that gofmt/build/vet/test don't cover golangci-lint/QF1003.
