Diagnosis

The compactor's predicate is snapshot-blind: it drops a version whenever a newer version exists, ignoring active read snapshots. That removes the version an active snapshot is pinned to.

Minimal interleaving (4 ops):

# op chain k active
1 put("k","old") (seq 1) old@1 —
2 S = beginSnapshot() (ts=1) old@1 S(ts=1)
3 put("k","new") (seq 2) old@1, new@2 S(ts=1)
4 compact() (buggy) new@2 S(ts=1)
5 read(S,"k") → "new" (expected "old") SI violated

A second read-path defect — falling back to the oldest surviving version when no version <= ts exists — turns "lost version" into "silently sees newer data," and produces phantom creates:

put(k,"v0") -> del(k) -> S=begin(ts=2) -> put(k,"v1") -> compact()
read(S,"k") == "v1"   // key was deleted at snapshot time

Fix

  1. Track active snapshots; W = min(ts) (or seq if none).
  2. Per key retain the anchor = newest version with seq <= W, plus every version with seq > W; drop only versions older than the anchor. GC a chain whose anchor is a tombstone with nothing newer.
  3. Reads must be strict (newest seq <= ts, else ABSENT); never substitute a newer version.
_compactFixed() {
  const W = this.lowWatermark();
  for (const [key, chain] of this.data) {
    const after = retentionForChain(chain, W); // anchor + suffix(>W)
    if (after.length === 0) this.data.delete(key);
    else this.data.set(key, after);
  }
}

Memory: with no snapshots W = seq so chains collapse to ≤1 version; tombstones below W are deleted. While a snapshot lives it retains only the anchor plus versions committed since it began — the required working set. endSnapshot() must delete the registry entry so W advances.

Proof (no needed version dropped)

For any ts >= W, fix the newest version v <= ts in chain C. If v.seq <= W it is the anchor (nothing lives in (v.seq, W], else v wouldn't be newest), so v ∈ R. If v.seq > W, R contains the entire > W suffix, so v ∈ R. Nothing after v is <= ts, so R selects v too. Tombstone-GC preserves ABSENT. ∎
