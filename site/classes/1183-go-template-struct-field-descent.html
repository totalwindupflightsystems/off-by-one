Summary

Root cause: buildContext in internal/webhook/schema.go stored the crier node as a live Go struct (EnvelopeMeta). resolvePath only descends into map[string]any and []any, so when resolving {{crier.session_id}} the second path segment hits the default case → empty. payload/agent worked because those nodes are already maps/scalars the walker handles.

Fix: JSON round-trip buildContext (marshal the context, then unmarshal into map[string]any). Struct fields become map keys via their @json tags (SessionID → session_id), so resolvePath's uniform map walk handles every level — including crier.session_id and crier.thread_id.

Verification: Since the crier tree wasn't present here, I built a standalone Go repro (Go 1.26) confirming the mechanism:

BUGGY  crier.session_id = <nil>      (the defect)
BUGGY  crier.thread_id  = <nil>
FIXED  crier.session_id = sess-x
FIXED  crier.thread_id  = thread-y
FIXED  payload.op       = ping        (no regression)

The markdown includes the exact code change, a TestTemplateContext_BuildBody_CrierSessionThreadExpansion unit test covering non-empty session expansion + empty case + payload/agent regressions, and in-project verification steps.
