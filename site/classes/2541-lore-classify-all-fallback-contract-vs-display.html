TL;DR

classify_all() always emits one (entry, label) pair per input entry and uses UNCLASSIFIED as the fallback label. That is its real, test-pinned contract (test_lore016, test_lore043). The bug is not in the classifier — it is that the match display path assumed the classifier had already removed unclassified rows and/or that the fix for the stray row was applied inside classify_all. Do not filter in the classifier. Restore/keep the fallback in classify_all and filter UNCLASSIFIED in _cmd_match.

Symptoms

  • match output shows a trailing/extra unclassified group (or, after an attempted fix, classified rows disappear).
  • Editing classify_all to drop UNCLASSIFIED makes test_lore016 and test_lore043 fail, because those tests assert the fallback is present.
  • The classify_all docstring contradicts the code: it claims entries without a match are omitted, while the implementation appends the fallback.

Root-cause analysis

Two different requirements are being conflated:

  1. Classifier contract (data layer). classify_all is a total function: given N entries it returns N (entry, label) pairs, in input order, assigning the UNCLASSIFIED fallback to anything that matches no rule. Callers rely on a 1:1 correspondence between input and output (counts, ordering, joining back to source records). This is exactly what test_lore016 / test_lore043 pin.

  2. Display requirement (presentation layer). The match command should not print rows whose label is UNCLASSIFIED.

The faulty change put requirement (2) inside requirement (1): classify_all was made to if label != UNCLASSIFIED: out.append(...). That breaks the total-function contract and the count/order guarantees callers depend on, breaks test_lore016 / test_lore043, still leaves the docstring wrong, and scatters display policy across layers.

The fix belongs in _cmd_match, which is the only place that knows it is producing human-facing match output.

Exact fix

1. Keep classify_all total (do not filter here)

UNCLASSIFIED = "unclassified"


def classify_all(entries, rules):
    """Classify every entry.

    Returns exactly one ``(entry, label)`` pair per input entry, preserving
    input order. Entries matching no rule are returned with the
    ``UNCLASSIFIED`` fallback; they are never dropped. Callers that want only
    classified rows must filter on ``UNCLASSIFIED`` themselves (see
    ``_cmd_match``).
    """
    return [(entry, classify(entry, rules)) for entry in entries]

If the current implementation already looks like this, leave it alone — the regression is elsewhere. If it currently filters, revert that filter.

2. Filter at the display boundary in _cmd_match

def _cmd_match(entries, rules):
    # classify_all always returns every entry, using UNCLASSIFIED as the
    # fallback. The match command only displays classified rows.
    return [
        (entry, label)
        for entry, label in classify_all(entries, rules)
        if label != UNCLASSIFIED
    ]

If _cmd_match prints while iterating, apply the same guard at the print site:

for entry, label in classify_all(entries, rules):
    if label == UNCLASSIFIED:
        continue
    print(f"{label}\t{entry}")

Regression guard

def test_classify_all_is_total():
    entries = ["alpha", "zzz"]
    rules = [("a", lambda e: e.startswith("a"))]
    assert classify_all(entries, rules) == [
        ("alpha", "a"),
        ("zzz", UNCLASSIFIED),
    ]


def test_match_hides_unclassified():
    entries = ["alpha", "zzz"]
    rules = [("a", lambda e: e.startswith("a"))]
    assert _cmd_match(entries, rules) == [("alpha", "a")]

Rule to remember

classify_all is total and always appends the UNCLASSIFIED fallback. Display filtering lives only in _cmd_match. Never move that filter into the classifier.
