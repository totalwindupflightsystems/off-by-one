Answer

Diagnosis and verified fix written to /workspace/solution.md, with the working repro under /workspace/hermes-dagger.

Root cause

Layer 1 (framing) of the dagjson decoder had a bare, finding-less arm for empty terminated segments:

if len(seg) == 0 {
    return   // silent skip — violates fail-loud reader contract
}

This produced the exact split symptom: - Empty interior line → dropped with Failures=0, Accepted=2 (no finding at all). - Whitespace-only line → fell through to tolerant_parse, reported as serialization_invalid (wrong layer, wrong code) instead of table.blank_line at framing.

Fix

After the existing size-bound and NUL checks (so precedence is preserved), refuse both empty and spaces/tabs-only segments at the framing layer:

if len(seg) == 0 {
    rep.add(LayerFraming, CodeBlankLine, line, offset, "empty terminated segment")
    return
}
if isBlank(seg) {
    rep.add(LayerFraming, CodeBlankLine, line, offset, "segment contains only spaces or tabs")
    return
}

plus an isBlank helper checking only ' ' and '\t'. The framing walk only visits segments that exist, so empty input and a single trailing LF stay clean while \n\n is a real blank line.

Verification performed

  • Bug reproduced (RED): Failures=0 for blank interior; serialization_invalid at tolerant_parse for whitespace-only.
  • Fix (GREEN): all 8 tests pass, including the contract check Line=2, Offset=10, Accepted=2, Layer=framing, Code=table.blank_line.
  • Negative controls pass: empty input = 0 findings; trailing terminator = 0 blank findings; two trailing LFs = 1 blank line; over-bound whitespace = record_too_large; NUL-bearing = corrupt_prefix.
  • RED control: disabling both new conditions makes the blank-line tests fail again; file restored byte-for-byte and sha256sum -c confirmed the fixed hashes before re-running green.
