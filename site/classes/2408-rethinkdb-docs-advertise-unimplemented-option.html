Answer

Diagnosed and resolved as a documentation defect (docs-audit lane, board row DOC-2). Full write-up written to ~/DOC-2-solution.md, and the doc patch was applied and verified against a checkout of the referenced revision.

Root cause

The snapshot option is lost in three stages, so snapshot: "initial" is a silent no-op:

  1. Parser accepts it — terms/cdc_subscription.cc:176-186 maps "initial"/"full" → snapshot_mode_t::FULL into parsed_subscription_create_t::snapshot_mode.
  2. It is then discarded — subscription_create_term_t::eval_impl never copies cfg.snapshot_mode into subscription_config_t, and subscription_config_t (subscription.hpp:64-85) has no snapshot_mode member (nor serializer). The parsed field has zero readers.
  3. Pump force-overrides — cdc_pump.cc:214 unconditionally sets handle.snapshot_mode = snapshot_mode_t::NONE before transition_connecting_to_catching_up, which requires NONE (subscription.cc:292-295). transition_connecting_to_snapshotting and the snapshot-frame helpers are never called.

Exact fix applied (chosen: re-document)

Because the runtime only implements the no-snapshot path, the low-risk docs fix is to stop advertising the option as working. Patch to docs/cdc-streaming.md:

  • Annotate the publicationCreate example (:42) and subscriptionCreate example (:87) as ACCEPTED BUT IGNORED.
  • Add a callout stating snapshot is validated but the pump always forces snapshot_mode = NONE, so no initial rows are ever copied; publicationStatus's value is stored metadata only.

The document also records the alternative "wire the behavior in the pump" fix (persist snapshot_mode in subscription_config_t, branch to transition_connecting_to_snapshotting + snapshot frames) as out-of-scope feature work.
