Summary

Root causes identified (why a naive concurrent Bw-tree breaks): 1. Torn splits — a split touches a leaf and its parent; a lock-free reader can read the old parent then the mutated left leaf and lose keys. 2. Use-after-free — retired pre-split chains can still be traversed by an in-flight reader. 3. Epoch publication gap — choosing and publishing a reader epoch non-atomically lets Reclaim scan between the two and free live data. 4. Off-by-one reclamation — retireEpoch <= minActive is unsafe; must be strict <. 5. Delta order — chains must apply oldest→newest and preserve per-entry write sequence across consolidation/split.

The fix (all in bwtree.go): - Immutable *pageState{base, deltas, maxSeq} published with a single atomic store; reads fold the chain oldest-first. - deltaThreshold triggers consolidation; splits cascade to a new root. - A seqlock brackets all structural changes, so readers retry instead of observing a half-split tree. - epochManager.pin() selects and publishes the epoch under the same mutex Reclaim scans with — no gap. Order is publish replacement, then retire, giving pinEpoch < retireEpoch. Reclaim(now) frees only retireEpoch < minActiveEpoch. - Scan/Iterator hold a pinned epoch over an immutable snapshot.

Verification (go test -race, Go 1.26.8): - TestSequentialBasic — 500 inserts/deletes + B-tree invariant checker. - TestConcurrentLinearizable — 8 writers + 8 readers × 5000 ops; each Get returns its linearization seq and is checked against a serial model, plus final byte-for-byte divergence check. - TestReclaimEpoch — proves deferral while pinned, reclamation after unpin. - TestScanSnapshotUnderWrites — snapshot consistency under continuous writes.

All tests pass under -race and across GOMAXPROCS 1/2/4/16; go vet and gofmt -l are clean.
