Summary

Root cause. A SAH BVH build freezes the hierarchy; refit only tightens AABBs. When deformation makes primitives cross split planes, sibling boxes overlap and the split-quality factor q(n) = (A_L+A_R)/A_n rises toward 2, so nearly every ray hitting n tests both children. Because SAH traversal cost is additive — C(T) = (1/A_root)[Σ Trav·A_n + Σ Isect·N_l·A_l] — stale partitions at many levels compound into traversal blowups. In the harness, refit-only reaches 3.05x SAH / 3.33x actual ray traversal vs a full rebuild.

Exact fix (implemented + embedded in the markdown): 1. Per-subtree SAH drift — store q0 at build; during the O(nodes) refit recompute q, additive subCost, and subExcess. 2. Maximal dirty subtrees — flag q/q0 > 1+τ; don't descend (only rebuilding an ancestor repairs its own split). These are disjoint. Notably, the alternative "descend to affordable descendants" was tried and is worse. 3. Token-bucket work queue — credit = min(credit+B, C_max) each frame; greedy rebuild by benefit density subExcess/count; hard-cap nodes jump the queue. 4. Partial rebuild — binned-SAH build over exactly one primitive range, spliced back, with a monotonicity safeguard so a rebuild never increases local cost.

Amortized proof. With c_t = min(c_{t-1}+B, C_max) and work w_t ≤ c_{t-1}+B−c_t, summing gives Σ w_t ≤ c_0 − c_F + B·F ≤ B·F. Total work is unconditionally ≤ B/frame; per-frame spikes ≤ C_max.

Verified (node bvh_policy.js, 600 frames, 1024 tris, B=128, τ=0.10):

metric refit-only max policy max target
SAH quality ratio 3.05 1.61 ≤ 2.0 ✅
ray-traversal ratio 3.33 1.83 ≤ 2.0 ✅
amortized rebuilds/frame — 125.5 vs 1024 full (8.2× cheaper) ≤ 128 ✅

Also passes on 8 seeds (policy traversal max ≤ 1.96), 1800-frame runs (≤ 1.75), and the amortized accounting Σw = 75300 ≤ B·F = 76800. The markdown includes the full code, the exact commands, the proof, the budget/quality sweep, and a machine-precision check that the additive metric equals the recursive SAH definition.
