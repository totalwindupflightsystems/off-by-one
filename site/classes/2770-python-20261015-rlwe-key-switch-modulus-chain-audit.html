What the problem actually is

There is no pre-existing source to fix — /workspace/problem.json has empty error_message/stack_trace. The task is to build an auditor for leveled RLWE evaluation traces. The hard part is that the trace producer can emit a structurally valid but unsafe trace:

  • Dropped rescale — a CKKS product (scale Δ²) is multiplied again before being rescaled, exhausting the noise budget while all levels stay in range.
  • Adversarial parameter rounding — key-switch digits recompose to a value almost equal to the target (small residual leaks noise), or a rescale records a rounded scale_out.
  • Noise under-reporting — the trace claims a lower noise_var than the parameters/graph imply.
  • Probability overrun — even with correct-looking numbers, 1 − p_fail < requested.

A checker that only validates structure and trusts recorded noise passes all of these.

The fix

Implemented /workspace/rlwe_audit.py (stdlib-only, Python 3.8+):

  • Recomputes per-coefficient noise variance through encrypt/add/mul/relinearize/rescale using a documented conservative model; refuses to trust recorded noise_var (noise_underreport).
  • Modulus-chain transitions: same-level binary operands, exact level−1 on rescale/modswitch, and a pending-rescale tracker that fires dropped_rescale when an un-rescaled product is multiplied again (end-of-trace strict mode opt-in).
  • Key-switch decomposition: digit count vs ceil(log_T(Q_L)), [0,T) range, exact recomposition; residual is folded into the variance.
  • Correctness probability: Gaussian union bound p_fail ≤ 2N·Q(τ/√v) with scheme thresholds Q_l/(2t) (BFV/BGV) or scale/2 (CKKS), checked at every intermediate and against requested_probability.
  • Parameter validation: power-of-two N, strictly ascending prime RNS chain (Miller-Rabin), valid t/scale.
  • CLI (python3 rlwe_audit.py trace.json) emits a JSON AuditReport and exits non-zero on failure.
