Board reconciliation: compare writer-owned JSONL headers field-wise in --live mode

Task: BOARD-VERIFY-002 · Repo: gethilo/hilo · Files: scripts/verify_board_reconciliation.py, scripts/tests/test_board_reconciliation.py

Symptom

The optional board reconciliation verifier is red on every ordinary tick in --live mode:

RESULT: FAIL (1 finding(s): 1 reconciliation, 0 live-content) - board.jsonl keeps every <rev> line: header lines lost: ['{"project":"WarpFS (Hilo)",...']

The repro is a single legitimate writer call — a plain counter bump:

boardctl header --set-ticks-total 187

Nothing is corrupt. The default (byte-exact) mode is green. Live mode contradicts the writer by construction.

Root cause

On JSONL-canonical boards the board header is line 1 of board.jsonl, and every tick rewrites it (ticks_total, last_tick, updated_at). The live check was implemented as line presence:

# pre-fix live check (conceptually)
missing = [line for line in pinned_lines
           if line.strip() and line not in set(live_lines)]
if missing:
    fail("board.jsonl keeps every <rev> line: header lines lost: %r" % missing)

A file that a writer legitimately owns can never satisfy “every pinned line still exists verbatim”, because the header line is rewritten on each tick. The same failure is not counter-specific: boardctl header --set-*, the tick writer stamping last_tick, and the SetHeader path refreshing updated_at all trip it.

Wrong invariant: byte/line equality for a writer-owned file. Right invariant: field-wise equality with an explicit allowlist for mutable fields.

Exact fix

Keep default mode byte-exact. In --live mode, parse the pinned header row and the live header row and compare fields, not lines. Split the file into three classes:

class fields rule
writer-owned (mutable) ticks_total, ticks_idle, last_commit, last_tick, updated_at value may change → accept and report
identity project, namespace, version, git_branch, git_remote must never change → fail
content (after header) all other JSONL rows append-only; pinned rows must survive verbatim → fail on rewrite/loss, extra rows allowed

1. Add the allowlists and helpers

import json
from collections import Counter
from typing import List, Tuple

MUTABLE_HEADER_FIELDS = {
    "ticks_total",
    "ticks_idle",
    "last_commit",
    "last_tick",
    "updated_at",
}

IDENTITY_HEADER_FIELDS = {
    "project",
    "namespace",
    "version",
    "git_branch",
    "git_remote",
}


def _first_nonblank_index(lines: List[str]):
    for i, line in enumerate(lines):
        if line.strip():
            return i
    return None


def _parse_header(line: str):
    try:
        obj = json.loads(line)
    except (json.JSONDecodeError, TypeError):
        return None
    return obj if isinstance(obj, dict) else None


def _compare_tail(pinned_tail: List[str], live_tail: List[str]) -> List[str]:
    """Pinned content lines after the header must still be present.

    Extra lines appended after the header are accepted (an append is not a
    loss); only pinned lines that were rewritten or dropped are reported.
    """
    live_count = Counter(l for l in live_tail if l.strip())
    missing = []
    for line in pinned_tail:
        if not line.strip():
            continue
        if live_count[line]:
            live_count[line] -= 1
        else:
            missing.append(line)
    return missing


def compare_writer_owned_jsonl(pinned_text: str, live_text: str) -> Tuple[List[str], List[str]]:
    """Return (errors, notices) for a writer-owned JSONL file in --live mode."""
    errors: List[str] = []
    notices: List[str] = []

    pinned_lines = pinned_text.splitlines()
    live_lines = live_text.splitlines()

    p_idx = _first_nonblank_index(pinned_lines)
    l_idx = _first_nonblank_index(live_lines)

    # --- header must exist and parse on both sides ---
    if p_idx is None:
        return ["pinned revision has no header row"], notices
    p_obj = _parse_header(pinned_lines[p_idx])
    if p_obj is None:
        return ["pinned header row is unparsable or not a JSON object"], notices

    if l_idx is None:
        return ["live board.jsonl has no header row (empty file)"], notices
    l_obj = _parse_header(live_lines[l_idx])
    if l_obj is None:
        return ["live header row is unparsable or not a JSON object"], notices

    # --- lost keys ---
    lost = [k for k in p_obj if k not in l_obj]
    if lost:
        errors.append("header lost key(s): " + ", ".join(sorted(lost)))

    # --- added keys, unless documented mutable ---
    added = [k for k in l_obj if k not in p_obj]
    bad_added = [k for k in added if k not in MUTABLE_HEADER_FIELDS]
    if bad_added:
        errors.append("header gained unauthorized key(s): " + ", ".join(sorted(bad_added)))

    # --- changed values: mutable vs identity vs everything else ---
    changed_mutable, changed_identity, changed_other = [], [], []
    for key, old in p_obj.items():
        if key not in l_obj:
            continue
        if l_obj[key] == old:
            continue
        if key in MUTABLE_HEADER_FIELDS:
            changed_mutable.append(key)
        elif key in IDENTITY_HEADER_FIELDS:
            changed_identity.append(key)
        else:
            changed_other.append(key)

    if changed_identity:
        errors.append("header identity field(s) changed: " + ", ".join(sorted(changed_identity)))
    if changed_other:
        errors.append(
            "header field(s) changed outside mutable allowlist: "
            + ", ".join(sorted(changed_other))
        )
    if changed_mutable:
        notices.append(
            "header updated in documented mutable field(s): "
            + ", ".join(sorted(changed_mutable))
        )

    # --- pinned lines after the header must survive ---
    missing = _compare_tail(pinned_lines[p_idx + 1:], live_lines[l_idx + 1:])
    if missing:
        errors.append(
            "board.jsonl lost or rewrote %d pinned line(s) after the header: %r"
            % (len(missing), missing)
        )

    return errors, notices

2. Replace only the live dispatch

def verify(pinned_text: str, live_text: str, live: bool):
    if live:
        # writer-owned file: compare field-wise, report documented mutations
        errors, notices = compare_writer_owned_jsonl(pinned_text, live_text)
        for n in notices:
            report_info(n)          # e.g. "header updated in documented mutable field(s): ..."
        return errors
    # default mode: contract UNCHANGED -- byte-exact
    if pinned_text != live_text:
        return ["board.jsonl differs from pinned revision (byte-exact)"]
    return []

In the real verifier, feed errors into the existing finding builder and surface notices on stdout so the mutation is visible, not merely tolerated.

What each failure covers

  • lost key → header lost key(s): …
  • added key not in allowlist → header gained unauthorized key(s): … (an unauthorized write is not a documented update)
  • changed non-allowlisted field → header field(s) changed outside mutable allowlist: …
  • changed identity field → header identity field(s) changed: project, …
  • unparsable / empty header → …unparsable… / …no header row (empty file)
  • pinned line after header rewritten or lost → board.jsonl lost or rewrote N pinned line(s) after the header: […]
  • allowlisted value change → accepted, and reported as header updated in documented mutable field(s): …
  • extra rows appended after the header → accepted (an append is not loss)

Caution that must not be re-learned

The first cut of this fix also forbade added lines, which broke the repository's own legitimate “appended tick line” fixture. The rule was re-fitted to the writer's real contract (content is append-only, so only pinned tail lines are checked), not the fixture. Test 15 below pins that behaviour.

Residual / do not fake the green

The repo-wide suite still has one red end-to-end test that runs the live check against the drifting live board. That is board drift, not verifier behaviour:

  • two rows carry a status outside the board vocabulary, and several rows carry free-form prose in guard/ci enum fields;
  • the board's own validator (boardctl validate) reports the same two statuses as hard errors.

Clearing that test would require either broadening live mode past the documented allowlist or editing out-of-scope board rows. It was reported, not hidden. Separate “the checker is wrong” from “the data is dirty” before widening a checker.

Reusable pattern

When a verifier compares a version-controlled snapshot against a file some writer legitimately owns, byte/line equality is the wrong invariant. Partition the file into:

  1. writer-owned fields — explicit allowlist, compared by value, changes accepted and reported;
  2. identity fields — must not change, compared by value;
  3. content — append-only, pinned entries must survive.

Assert each class separately, and refit the rule to the writer's real contract — never to the fixture that happened to be lying around.
