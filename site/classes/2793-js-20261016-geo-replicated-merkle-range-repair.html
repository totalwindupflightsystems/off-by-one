Geo-Replicated Ordered-Range Merkle Repair — Diagnosis and Verified Fix

Files: /workspace/merkle-repair.js, /workspace/test.js, /workspace/SOLUTION.md Environment: Node 20+ (verified on Node 22.23.2), zero dependencies.

Root-cause analysis

The reported symptom — Merkle summaries may be stale after concurrent inserts, deletes, and range tombstones — decomposes into six concrete defects:

  1. Live-value summaries erase deletes. A summary computed only over present values makes a range where a key was deleted identical to a range that never held it. Repair either skips the delete or copies the peer's old value back, causing resurrection.
  2. Range tombstones are absent from the summary. A deleted interval with no live keys hashes the same as an empty interval, so [a,f) tombstones never propagate.
  3. Cached internal nodes are not invalidated. A cached root still reflects the pre-mutation state; replicas compare equal while diverging.
  4. Concurrent equal-valued writes are unresolvable. If only values are hashed, two replicas that concurrently wrote c=v1 appear equal and LWW can never pick a deterministic winner.
  5. Duplicate/reordered repair messages are re-processed, re-emitting responses down every tree level — exponential message growth and non-quiescence.
  6. Causal visibility is lost because effects are exposed before their causes arrive.

The fix — invariants

# Invariant
I1 A leaf hashes all stored state: LWW registers (live and point-deleted) + range tombstones.
I2 Every hashed record includes its clock (n, replicaId) and mutation id.
I3 Leaves use a fixed, shared boundary list (range metadata).
I4 Merge = LWW by (clock.n, clock.r) with id tie-break + tombstone set-union ⇒ commutative, associative, idempotent.
I5 Op delivery is buffered on a version vector; reads filter by depsSatisfied.
I6 Repair walks hashes top-down and descends only into differing children.
I7 Requests dedup by (syncId, type, range); merges are idempotent.
I8 Tree cache is keyed by a monotonic version, invalidated on every mutation.

Range-tombstone dominance is clockCmp(t.clock, reg.clock) > 0, so a later put survives an earlier tombstone and vice-versa. Because the hashed leaf captures tombstones and clocks, delete state is now visible to anti-entropy.

Protocol

  1. Initiator sends sync-request(root, rootHash, vv).
  2. Responder replies sync-equal (nothing downloaded), sync-leaf(payload) (leaf), or sync-diverge(children hashes) (internal).
  3. Initiator requests only differing children.
  4. On sync-leaf, receiver pushes its own leaf then merges the peer's — converges in one round.
  5. mergeTransfer is LWW + set-union + vv advance ⇒ idempotent under reordering/duplication.

Message cost is O(differingLeaves · log N); leaf payloads transferred equal the differing leaves exactly.

Operational notes

  • Boundaries are shared range metadata. Splits/merges must publish a new boundary list to all replicas; never compare across different lists.
  • Tombstone GC is only allowed once every replica's version vector is at or above the tombstone clock (tie GC watermark to the minimum acked vv), otherwise lagging replicas can resurrect data.
  • Wire format is plain JSON (kind/id/key/.../clock/deps); vv piggybacks on requests and payloads to advance causal context.
