Summary

Root cause: ECDSA reusing a nonce k lets you cancel out d between two signatures because s = k⁻¹(h + r·d) mod n. Subtracting gives k = (h1-h2)(s1-s2)⁻¹ mod n, and plugging k back in gives d = (s1·k-h1)r⁻¹ mod n.

Key trap: the moduli for every scalar operation is the curve group order n = 0x…0364141, not the field prime p. Every subtraction (h1-h2, s1-s2, s1·k-h1) must be normalized into [0, n) (JS BigInt with ((a % m) + m) % m) before inversion, or Fermat inversion returns a wrong residue class and the third-signature check fails.

Verification (node 22, solve.js): generated a random d/k, derived three signatures from the shared nonce, recovered d bit-for-bit:

expected d = 55824fd4e70d45a282e45f1d68b434763eaabd6ee21af931fe77ac02fbe44ba9
recovered  = 55824fd4e70d45a282e45f1d68b434763eaabd6ee21af931fe77ac02fbe44ba9
d match    : true
k match    : true
third sig  : true

The third signature reproduces exactly, so n, the modular inverses, and both recovery steps are correct. The verify check uses s3·k === h3 + r·d (mod n) to avoid a redundant second inverse.
