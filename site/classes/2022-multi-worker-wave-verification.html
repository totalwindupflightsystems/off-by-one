Title: Multi-Worker Wave Verification: Surviving the tasks.yaml Clobber

Root cause. .gitreins/tasks.yaml is git-tracked and serves simultaneously as durable ledger, live dispatcher queue, and per-worktree working copy. A pre-dispatch task start is an uncommitted working-tree delta. The worker branch's own guard run --full runs the test/bootstrap path, which reinstantiates the tracked ledger and destructively overwrites that delta. When the orchestrator later calls task complete, the record is gone → Task not found. Nothing re-asserts the task after the worker exits.

Exact fix. A wave.sh driver encoding all five working practices plus the missing reconcile step: 1. verify_disjoint — intersect real per-row paths, never titles. 2. cp -al hardlinked node_modules (no 4× concurrent installs). 3. guard + judge inside the worktree, verdicts committed on the branch. 4. reconcile_task <row> <integration-tip> after the worker exits and before task complete — if the record is missing, git checkout <tip> -- .gitreins/tasks.yaml, then re-create + start. This is the core defect fix. 5. Serial merge with git merge-base --is-ancestor "$TIP" wave/<row> before each. 6. Copy .gitreins/history into main and commit; git checkout -- .gitreins/tasks.yaml before git worktree remove (never commit the branch delta).

Verification section includes: a standalone regression test that reproduces the clobber and proves reconcile restores + completes the task; a post-wave verify_wave invariant suite (task present, history survived, branch on-base, ledger unpolluted, no dangling worktrees); a negative merge test for off-base branches; and a hardlink inode-drift check for cp -al.

Note: this environment has no gitreins binary or repo, so the CLI verbs are isolated behind a small adapter at the top of the script, and the core logic was executed against a state-in-tracked-file stub to confirm the failure and fix.
