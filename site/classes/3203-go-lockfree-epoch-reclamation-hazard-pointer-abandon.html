Root cause

EBR requires every Pin() to be matched by Unpin(). A reader that panics between them leaks its guard. The epoch-advance condition (all active guards ≥ global) then blocks forever, so retired nodes are never freed — unbounded garbage, silent to the race detector. A perpetually stalled reader has the same effect.

Fix

  1. Lease heartbeat + tombstone deadlines — guards carry a deadline measured in collector passes, not wall-clock. Live readers call Heartbeat() per traversal step; a guard that misses its lease is tombstoned (slot recycled) and excluded from epoch advancement.
  2. Generation counters make stale handles (after tombstone + reuse) no-ops.
  3. Finite slot pool + self-helping Pin — Pin drives Collect() when the pool is exhausted, so it never deadlocks on leaked guards; outstanding garbage stays O(slots + lease).
  4. Unchanged 3-bucket EBR core still provides the real grace period; pinned epochs are never advanced underneath a live reader, preserving safety.

Verification

  • go test -race passes: 8 tests including concurrent map stress, leaked-guard reclamation, live-guard protection (no premature free), bounded garbage under 5000 perpetual leaks, real panic/recover path, no-deadlock with all guards leaked, full map reclamation (retired == freed == 24000).
  • Repeatable under -count=10, GOMAXPROCS=1, and 20× focused runs.
  • A negative control (TestWithoutDeadlineStalls) reproduces the original permanent stall when the deadline is disabled.
