Solution

Fix: Dashboard docs omit session_id on 7 session-scoped routes (DF-AIPP-12)

Summary

The dashboard route table documented session_id only for /control/start. Seven other routes accept the same parameter (session_id: str = "default") but did not mention it, so consumers could not discover how to target a non-default session. Documentation-only defect; API behavior was already correct and backwards-compatible.

Affected (7): /status, /screenshots/latest, /actions/recent, /metrics, /control/pause, /control/resume, /control/stop — already correct: /control/start.

Root cause

Handlers resolve a session from a query param defaulting to "default":

@app.get("/status")
async def status(session_id: str = "default"): ...

The route table was written when only one implicit session existed. When multi-session support landed, only the /control/start row was updated. The State model section also never stated that non-default sessions are invisible in the default dashboard view, compounding the doc/behavior mismatch.

Exact fix

Corrected rows (insert (`?session_id=<id>`; default = `"default"`) after each description):

Method Route Description
POST /control/start Start a session (?session_id=<id>; default = "default").
GET /status Session status (?session_id=<id>; default = "default").
GET /screenshots/latest Latest screenshot (?session_id=<id>; default = "default").
GET /actions/recent Recent actions (?session_id=<id>; default = "default").
GET /metrics Session metrics (?session_id=<id>; default = "default").
POST /control/pause Pause session (?session_id=<id>; default = "default").
POST /control/resume Resume session (?session_id=<id>; default = "default").
POST /control/stop Stop session (?session_id=<id>; default = "default").

Add to the State model:

### State model

Sessions are keyed by `session_id`. Sessions created with a non-default id are
**invisible** in the dashboard's default view and must be addressed explicitly
by passing `?session_id=<id>`. Omitting the parameter preserves the previous
behavior and resolves to the `"default"` session.

One-shot patch (set DOCS to the real path):

DOCS=docs/dashboard.md
python3 - "$DOCS" <<'PY'
import pathlib, re, sys
p = pathlib.Path(sys.argv[1]); text = p.read_text()
routes = ["/status", "/screenshots/latest", "/actions/recent", "/metrics",
          "/control/pause", "/control/resume", "/control/stop"]
out = []
for line in text.splitlines():
    if any(f"`{r}`" in line for r in routes) and "?session_id=<id>" not in line:
        line = re.sub(r"\s*\|\s*$", "", line.rstrip())
        line += ' (`?session_id=<id>`; default = `"default"`). |'
    out.append(line)
text = "\n".join(out)
if "invisible" not in text.lower():
    text += ("\n\n### State model\n\nSessions are keyed by `session_id`. Sessions created "
             "with a non-default id are **invisible** in the dashboard's default view and "
             "must be addressed explicitly by passing `?session_id=<id>`. Omitting the "
             "parameter resolves to the `\"default\"` session.\n")
p.write_text(text); print(f"patched {p}")
PY
