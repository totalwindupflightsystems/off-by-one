MVCC Serializable-Snapshot-Isolation Validator with Predicate Anti-Dependency Cycle Resolution

Root-cause analysis

Snapshot isolation is not serializable. Its anomalies come from anti-dependencies (rw): T reads a version and a concurrent W later writes that key/range. A history is serializable iff the serialization graph (wr, ww, rw) is acyclic. Naive implementations fail because:

  1. Heuristic SSI over-aborts — the dangerous structure T1 →rw T2 →rw T3 is necessary but not sufficient for a cycle. Aborting on it rejects acyclic histories. You must detect actual cycles.
  2. Predicates are intervals, not keys — scan([lo,hi)) conflicts with any overlapping write; per-key tracking explodes or misses overlaps under adversarial ranges.
  3. Wrong wr visibility — a reader sees the latest committed writer per sub-range at its snapshot. Painting every overlapping writer invents edges and false cycles.
  4. Commit races — two transactions can each pass validation yet together close a cycle; validation + edge insertion must be atomic.
  5. Serial wraparound — fixed-width IDs/timestamps need modular comparison and a live-window invariant < half the space.
  6. Vacuuming — a committed record may only be dropped once commit_ts <= min(active start_ts); otherwise cycles are missed.
  7. Bounded memory — coalesce intervals exactly; cap per-txn intervals and retained transactions, aborting deterministically under pressure.

The fix

The validator keeps read/write interval sets (RangeSet, exact normalized unions), a serial clock with modular comparison, and a committed-transaction graph. At commit it computes, against every retained committed transaction:

  • wr predecessors using a RangeMap that paints the latest visible writer over each read sub-range,
  • rw successors (committing txn read a version; the other wrote later) and rw predecessors (the other read; the committing txn wrote),
  • ww predecessors (overlapping writes).

A cycle exists iff some successor can already reach some predecessor. Commits are serialized by a re-entrant lock; the deterministic victim is the committing transaction (or the oldest active transaction under memory/window pressure). Vacuuming uses the watermark min(active start_ts); wraparound maintains a live span below 2**(bits-1).

Key interface:

v = MVCCValidator(bits=64)
t = v.begin()
v.read(t, 0, 10)          # predicate read of [0, 10)
v.write(t, 5, 6)          # write key 5
v.commit(t)               # True (committed) / False (aborted on cycle)
