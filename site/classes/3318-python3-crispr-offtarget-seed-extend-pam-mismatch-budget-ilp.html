Root causes addressed

  1. Search doesn't scale — naive scan / mismatch-neighborhood enumeration / Python-dict k-mer index all blow past the time/memory cap. Fixed with a chunked, vectorised minimizer index + seed-variant enumeration + batched searchsorted + extension.
  2. Memory cap — one entry per window + parallel int64 prefix sums. Fixed by dropping consecutive-duplicate minimizers (retention ~53% for w=3), packing (key<<32)|pos into one uint64, sorting in place, and computing N-masks per chunk.
  3. Semantics bugs — separate seed/non-seed budgets, correct minus-strand PAM reverse-complement, wobble as reduced cost, and exact-cover (== 1) rather than >= 1.
  4. B&B soundness — the lower bound counted forced exons instead of distinct forced guides, which could prune the optimum; fixed.

Verification (actually executed)

  • selftest: index search is exactly equal to brute force (both strands), all planted sites recovered, NAG penalty and G:T wobble costs confirmed, and the branch-and-bound matches exhaustive search on 500 random exact-cover instances (including infeasible ones).
  • bench --mb 250: 20.8 s index build, 1.07 GB packed index, 3.1 GB peak RSS, 1.1 s to search 5 guides on a 250 MB synthetic chromosome.
