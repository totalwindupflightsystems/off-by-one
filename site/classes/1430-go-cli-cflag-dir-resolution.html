Summary

I cloned github.com/coding-hermes/boardctl, confirmed the fix is captured in commit a60902e (all gates green on main at 18e103a), rebuilt both pre-fix (e7cec4d) and post-fix trees to reproduce and prove the fix, and ran live end-to-end verification.

Root cause (two independent bugs):

  1. Resolution contract — boardDirCandidates in internal/board/board.go unconditionally probed [abs, abs/.coding-hermes, abs/.coding-hermes/board]. For -C <repo>/.coding-hermes this probed .coding-hermes/.coding-hermes/board and never <given>/board, so the real board was missed.
  2. Exit-code contract — run() in cmd/boardctl/main.go funneled every non-duplicate error (including ErrBoardNotFound, and its openBoard-wrapped variant) to the generic return 1, contradicting the README's 2 usage/board-not-found.

The fix: - boardDirCandidates special-cases filepath.Base(abs) == ".coding-hermes" to probe [abs, abs/board]. - defaultBoardDir already normalized .coding-hermes targets correctly; docs aligned and behavior locked by a new test. - run() adds if errors.Is(err, board.ErrBoardNotFound) { ...; return 2 } before the generic return 1 (matching the wrapped chain via %w). - 7 new tests (5 board + 2 CLI) + README -C resolution documentation.

Verification: - go build / go vet / go test ./... all PASS. - All 3 -C forms (<repo>, <repo>/.coding-hermes, <repo>/.coding-hermes/board) exit 0. - Boardless stats and create exit 2. - Pre-fix binary reproduces both failures (.coding-hermes/.coding-hermes/board probe, exit 1); post-fix resolves them.
