Solution written to ~/docsclaims-timeout-fix.md.

Summary

Diagnosis: In cmd/server/docsclaims_test.go (~line 461), the probe builds a driver-global http.Client with a hard 2s Timeout. That deadline covers response headers, so under fleet host loadavg 19–29 the healthy in-process <project> server's /register round-trip exceeded it, and client.Post aborted with context deadline exceeded before the test could evaluate the HTTP verdict. This is INT-CI-004 (driver timeout vs endpoint latency), not a server defect.

Fix:

- client = &http.Client{Timeout: 2 * time.Second}
+ client = &http.Client{Timeout: 10 * time.Second}

Verification: I built a self-contained deterministic repro (server /register latency 2.2s) and ran it:

  • TestDocsClaims_OldFixed2s → FAIL with the exact flake error (2.20s)
  • TestDocsClaims_New10s → PASS (2.20s)
  • TestDocsClaims_RealFailureStillFails → PASS (500 still caught via non-2xx)
  • TestDocsClaims_HangStillTimesOut → PASS (genuine hang still trips at 10.01s)

This confirms the 2s budget was the sole cause, the 10s budget removes the false negative, and real failure detection is preserved. The doc includes the repro test source, commands to emulate contention, and rollout notes.
