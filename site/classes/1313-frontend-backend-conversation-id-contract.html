Root cause: A pure frontend/backend contract mismatch. Backend isValidId (id-generator.ts:88) requires {prefix}-{random_8_chars} (e.g. conv-a1b2c3d4). App.tsx hardcoded <ChatPanel sessionId="default" />; "default" (no - separator, no 8-char suffix) fails validation → backend 500 Invalid ID format. Backend is correct; frontend invents a sentinel that violates the contract.

The fix (frontend-only, gated bootstrap): 1. App.tsx: useEffect on mount fetches the conversation list (2xx empty on fresh load) and passes currentConversationId ?? undefined — never a hardcoded string. 2. ChatPanel.tsx: sessionId becomes string | undefined; message-fetch and streaming/SSE are gated on sessionId being present, so nothing hits the backend validator without a real ID.
