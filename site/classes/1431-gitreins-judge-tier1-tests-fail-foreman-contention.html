What I found

  • The live judge/foreman hosts can't be inspected from this sandbox (gitreins is a dangling symlink, cube-root SSH is blocked by a broken /etc/ssh/ssh_config.d permissions error, and hermes has no local venv). The problem statement itself carries the verified evidence, and the tooling the fix relies on (pnpm, pgrep) is present.
  • This is fundamentally a runner-orchestration bug, not a code fault: two vitest runs (gitreins judge tier1 + foreman gate battery, both pnpm -r run test) raced on one box. Under contention tier1 exited 1; an idle standalone rerun exited 0 with 2452 passed / 33 skipped = baseline, proving flake, not regression.

The deliverable contains

  1. Root-cause analysis — the two-runner race and why the counts prove flake-vs-regression.
  2. The fix (protocol + commands):
  3. Root fix: a pgrep-gated loop that defers the foreman battery until no judge/vitest is in flight (and vice-versa), so only one suite is ever live per host.
  4. Diagnosis: pgrep -alf vitest / pgrep -alf 'pnpm -r run test' + timestamp overlap check before treating exit 1 as a failure.
  5. Settling: one clean idle-box rerun of the exact step command; exit 0 and 2452/33 baseline-equal counts → not a regression (no rerun-until-lucky loop).
  6. Verification table mapping the observed facts (verdict 50c5f8fd exit 1 under contention → 13:03 UTC standalone exit 0 baseline) to the settled conclusion.
