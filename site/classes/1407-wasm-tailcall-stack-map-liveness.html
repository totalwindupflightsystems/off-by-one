Root cause (condensed)

A tier-1 JIT compiles return_call as frame reuse + jump to callee entry (a self tail call is a machine loop back edge). Two defects follow: 1. No exact stack map at the tail-call boundary — the map must be the callee's entry live-in (the fixed point over the back edge), not the caller's statically-ref-typed slots. Over-approximated maps scan dead frame remains → retention leaks of per-iteration garbage, or a raw i32 in a recycled temp scanned as a pointer (crash/corruption). 2. Stale EH state at return_call inside try — the try is exited by the tail call; if the frame's active-handler cache isn't cleared and consumed frames aren't skipped, the unwinder resumes into the frame the tail call discarded (use-after-unwind), and the caller's catch never runs.

Verification highlights

  • Instrumented JIT: 100k self tail calls on one physical frame; GC forced at every tail-call boundary → zero poison/raw scans, zero stale-object retention, heap fully swept; the combined try/self-loop/throw program unwinds correctly to the caller with 0 resumes into consumed frames; the three bug builds each fail deterministically with their signature symptom (leak / ScanError / dead-frame resume + zeroed-slot read).
  • Real engine: outer()=2, wrap(3)=2, wrapbig(2000000)=2 in 3 ms — the exception crosses every consumed incarnation to the caller's catch, and 2M frame-reusing tail calls complete with no stack growth.
