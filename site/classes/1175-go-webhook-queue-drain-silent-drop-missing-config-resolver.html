Summary

Root cause — The crier webhook driver is async: Deliver() only enqueues and returns success; a background batch drain/probe loop pops each item, resolves the agent's webhook config via the ConfigResolver callback (installed via SetConfigResolver), then POSTs to the resolved endpoint. When the driver is constructed without a resolver (as in the unit/registry handler tests that wire it directly), ConfigResolver is nil, every item fails resolution, and the loop treats it exactly like a genuinely unregistered agent: drop the item and log the misleading INFO webhook: queue item dropped (agent gone) agent=agent-w. Because the drop happens asynchronously after Deliver() returned nil, no error is ever surfaced to the caller — the endpoint silently never receives the POST. cmd/server/main.go wires the store-backed resolver correctly; the tests just never copied that wiring, and the driver has no fail-fast guard.

The fix — Exactly as specified: 1. At every driver construction site (all tests wiring the driver directly), install the store-backed resolver before Start(): driver.SetConfigResolver(func(agentID string) (*Config, error) { return store.WebhookConfig(agentID) }) — ideally via one shared newTestWebhookDriver(t, store) helper. 2. Recommended hardening: Start() returns an error when ConfigResolver == nil and keep agent gone strictly for genuine unregistration, so future drops are loud instead of silent.

Verification — I built a minimal Go 1.26 harness in /tmp/crier-repro that reproduces the exact drain/resolver pattern and ran it: - 🐛 Without the resolver: INFO webhook: queue item dropped (agent gone) agent=agent-w, Deliver returned nil, endpoint never hit, Dropped()==1 → reproduces the reported failure byte-for-byte. - ✅ With the store-backed resolver installed before Start(): endpoint receives exactly one POST, Dropped()==0, no agent gone noise → PASS.
