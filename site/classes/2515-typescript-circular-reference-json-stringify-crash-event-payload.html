Fix: TypeError: Converting circular structure to JSON killing the event bridge

Problem class: typescript-circular-reference-json-stringify-crash-event-payload

Summary

A long-running game/bridge process embedded live Player objects directly into serializable event payloads. During the night a doctor can self-protect, setting player.nightTarget = player — a cycle. When that player is later included in a death payload (MORNING_REVEAL SHOT/KILLED, PLAYER_LYNCHED), JSON.stringify throws TypeError: Converting circular structure to JSON and the bridge exits 1 mid-game (~1 in 10 mock games).

Fix: serialize a plain projection of each player at the event boundary, omitting nightTarget. No downstream consumer reads it.

Root-cause analysis

  1. Player is a live mutable domain object with an internal back-reference: ts class Player { id: string; name: string; role: Role; alive = true; nightTarget: Player | null = null; // set during the night phase }
  2. Self-protection creates the cycle: doctor.nightTarget = doctor;
  3. Event builders pass the object reference, not a value: { ..., shot: state.shot, killed: state.killed }.
  4. The bridge calls JSON.stringify(payload).
  5. Walking player.nightTarget -> player throws: TypeError: Converting circular structure to JSON --> starting at object with constructor 'Player' --- property 'nightTarget' closes the circle
  6. The unhandled error at the bridge boundary exits 1. Because self-protection is random (~10%), the failure looked flaky.

The defect is leaking a live mutable object across the serialization boundary; nightTarget is internal-only.

Exact fix

// src/events/player-view.ts
import type { Player, Role } from '../game/types';

export interface PlayerView {
  id: string; name: string; role: Role; alive: boolean;
  // NOTE: no nightTarget — internal only, and can be self-referential.
}

export function toPlayerView(p: Player): PlayerView {
  return { id: p.id, name: p.name, role: p.role, alive: p.alive };
}

// src/events/payloads.ts
import { toPlayerView } from './player-view';

function buildMorningRevealPayload(state: GameState): MorningRevealEvent {
  return {
    type: 'MORNING_REVEAL',
    day: state.day,
    shot: state.shot ? toPlayerView(state.shot) : null,   // was: state.shot
    killed: state.killed.map(toPlayerView),               // was: state.killed
  };
}

function buildLynchPayload(state: GameState): PlayerLynchedEvent {
  return {
    type: 'PLAYER_LYNCHED',
    day: state.day,
    player: toPlayerView(state.lynched),                  // was: state.lynched
  };
}

Optional defense-in-depth — Player.toJSON() strips nightTarget via rest destructuring, so any missed call site still serializes.

Minimal inline repro

class Player { constructor(id, name, role) {
  this.id = id; this.name = name; this.role = role; this.alive = true; this.nightTarget = null;
} }
const doctor = new Player('p2', 'Bo', 'doctor');
doctor.nightTarget = doctor;
JSON.stringify({ type: 'MORNING_REVEAL', shot: doctor }); // throws TypeError

const toPlayerView = (p) => ({ id: p.id, name: p.name, role: p.role, alive: p.alive });
JSON.stringify({ type: 'MORNING_REVEAL', shot: toPlayerView(doctor) }); // works

Prevention rule

Never embed live mutable domain objects directly into event payloads — serialize a plain projection at the boundary. Keep internal back-references out of the PlayerView type so the compiler prevents leaks, and add a serialization test whose actor self-targets.
