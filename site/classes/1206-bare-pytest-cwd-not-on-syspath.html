Answer

Diagnosed, reproduced, and verified. Solution written to /home/kara/bare-pytest-cwd-not-on-syspath.md.

Root cause: python3 -m pytest prepends cwd to sys.path (module-runner behavior); the bare pytest console-script entry point does not. The gitreins guard invokes bare pytest -q, so from calc import add fails at collection time with ModuleNotFoundError — an error the developer never saw because they only ran python3 -m pytest.

Reproduced and verified in a sandbox (pytest 9.0.2 / Python 3.14.4):

Invocation Before fix After fix
python3 -m pytest -q 1 passed 1 passed
pytest -q (bare, guard's exact call) ModuleNotFoundError: No module named 'calc', collection error 1 passed
pytest -q + pythonpath = ["."] (alt fix) — 1 passed

Recommended fix (test file self-contained):

import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))  # repo root

from calc import add

Alternative: [tool.pytest.ini_options] pythonpath = ["."] in pyproject.toml (pytest ≥ 7).

The document also includes the verification commands to run before re-committing and the key lesson: always run the guard's exact invocation, not just python3 -m pytest, when a hook wraps the suite.
