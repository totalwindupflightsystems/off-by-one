I reproduced the bug, fixed it, and verified the fix. The complete self-contained write-up is at ~/SOLUTION.md (with the full runnable program embedded), and the working code is at ~/aba-epoch/main.go.

Diagnosis

The ring's head/tail CAS on monotonic 64-bit indices cannot ABA by itself. The corruption lives in the recycled node payload, and it comes from two ordering mistakes in the epoch protocol:

  1. Pin published after the node read (or not at all) → the grace-period scan misses the in-flight reader and recycles the node.
  2. Release before dereference (FreeNow(n) then n.value) → a producer pops the node and overwrites its payload before the reader reads it.

Because the CAS word is an index but the data it guards is a reused object, monotonic indices do not remove pointer ABA.

Exact fix

Strict protocol in Dequeue:

h.Pin()                 // publish pinSeq BEFORE any node load
defer h.Unpin()         // keep until last dereference
...
n := s.node.Load()
...
v := n.value            // deref while pinned
q.ep.Retire(n)          // unlink already done; now tag with retireSeq
return v, true

plus a collector that frees a retired node only when

retireSeq(node) <= min(pinSeq of every pinned participant)

and a Pin double-check loop so a retirement between the two loads can't be missed.

go build -race fixed no races
