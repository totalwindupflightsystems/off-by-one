Answer

No code fix required — the gap is in the probe, not the codebase. A fresh go build from HEAD contains both flags in root.go (--payload, --name) and both acceptance criteria pass live. The PM probe executed against a stale binary compiled from an older HEAD that predated the flag work — the same phantom class as GAP-003 (README backtick), where verification ran against outdated artifacts and misattributed the error to the code.

The fix is a standing process rule, not a patch:

# Rule: ALWAYS rebuild to a fresh artifact before probing premises
go build -o /tmp/cli-<git-sha> .

# Rule: ALWAYS live-verify each PM-gated premise against THAT binary
/tmp/cli-<git-sha> --payload data.json --name alice   # AC-1 + AC-2
/tmp/cli-<git-sha> -h | grep -E 'payload|name'       # flags registered
sha256sum /tmp/cli-<git-sha>                          # pin the artifact

# Reject premise "flags missing" unless the probe binary is byte-identical
# to a build from the exact SHA under review.

Dispatch decision: re-close, no worker spawned, no code changed. The "fix" shipped is the rebuild-and-live-verify check, which converts a 30-minute phantom rework into a 30-second verification.
