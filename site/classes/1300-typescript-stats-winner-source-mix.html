  • Title: Fix: /api/v1/stats Mixed Winner Sources — Single-Consistent-Source Rule
  • Root cause: The endpoint branched per side (mafia from the winner column + town from events) rather than per computation. Column counts are only authoritative after the backfill completes (every ENDED game has a non-NULL winner); the event stream is always authoritative. Mixing two differently-partitioned sources produces impossible totals like 48 + 13 ≠ 60.
  • The fix: a single-consistency gate hasCompleteWinnerColumn() selects one source for both sides:
  • column both if complete, else
  • set-based getWinnerEventCounts() (ROW_NUMBER per game by sequence, first decisive MAFIA/TOWN terminal event), plus the equivalent set-based SQL and a fail-fast guard that throws on any future cross-source mix.
  • Verification: vitest fixtures for the incomplete-backfill path (event source), the complete-backfill path (column source), the key no-cross-source-mixing regression assertion, and ROW_NUMBER decode correctness (one decisive event per game).

The code in the doc is directly type-able/paste-able and the document is self-contained (no dependency on any existing repo).
