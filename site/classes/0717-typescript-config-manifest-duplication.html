Answer

SOLUTION

Bug class (RR-GAP-003/007): the levels list existed twice — hardcoded in src/main.ts (CONFIG_MANIFEST) and hardcoded in scripts/validate-configs.mjs. Adding a level required editing both source files; forgetting either side produced silent drift (new level never boots, or a broken level passes CI).

Fix: delete both hardcoded lists. The filesystem becomes the single source of truth, discovered by two mechanisms that agree on directory, filter, and sort order:

side mechanism phase
src/main.ts import.meta.glob("../configs/levels/*.json", { eager: true, import: "default" }) build-time (vite/client typed)
scripts/validate-configs.mjs readdirSync(LEVELS_DIR).filter(f => f.endsWith(".json")).sort() CI/runtime

src/main.ts (with shared src/types.ts):

import type { LevelConfig } from "./types";

// Build-time discovery — no hand-maintained list. eager: true inlines every
// JSON payload into the bundle (no TLA, no runtime fetch); import:"default"
// unwraps the module namespace. vite/client types the call; the cast narrows.
const levelModules = import.meta.glob("../configs/levels/*.json", {
  eager: true,
  import: "default",
}) as Record<string, LevelConfig>;

// "../../configs/levels/level-01.json" -> "level-01" (browser-safe, no node:path)
function toId(modulePath: string): string {
  return modulePath.slice(modulePath.lastIndexOf("/") + 1).replace(/\.json$/, "");
}

// Derived manifest — keys = ids, values = parsed configs. Sorted with the
// same default comparator the validator uses, so boot order == CI order.
export const CONFIG_MANIFEST: Record<string, LevelConfig> = Object.fromEntries(
  Object.entries(levelModules)
    .map(([modulePath, config]) => [toId(modulePath), config])
    .sort(([a], [b]) => (a < b ? -1 : a > b ? 1 : 0)),
);

export function bootLevels(): string[] {
  return Object.keys(CONFIG_MANIFEST).sort((a, b) => (a < b ? -1 : a > b ? 1 : 0));
}

scripts/validate-configs.mjs (plain ESM, no TS):

import { readdirSync, readFileSync } from "node:fs";
import { fileURLToPath } from "node:url";
import path from "node:path";

const ROOT = path.resolve(path.dirname(fileURLToPath(import.meta.url)), "..");
const LEVELS_DIR = path.join(ROOT, "configs", "levels");

// Auto-discover the same directory main.ts globs; readdirSync order is
// fs-dependent, so .sort() normalizes it to match boot order exactly.
const levelFiles = readdirSync(LEVELS_DIR)
  .filter((file) => file.endsWith(".json"))
  .sort();

function validateLevel(file) {
  const raw = JSON.parse(readFileSync(path.join(LEVELS_DIR, file), "utf8"));
  const errors = [];
  if (typeof raw.id !== "string" || raw.id.length === 0) errors.push("id must be a non-empty string");
  if (typeof raw.name !== "string" || raw.name.length === 0) errors.push("name must be a non-empty string");
  if (!Number.isInteger(raw.difficulty) || raw.difficulty < 1) errors.push("difficulty must be int >= 1");
  if (!Number.isInteger(raw.steps) || raw.steps < 1) errors.push("steps must be int >= 1");
  const rectangular = Array.isArray(raw.grid) && raw.grid.length > 0 &&
    raw.grid.every((row) => Array.isArray(row) && row.length === raw.grid[0].length);
  if (!rectangular) errors.push("grid must be a non-empty rectangular matrix");
  return { raw, errors };
}

if (levelFiles.length === 0) {
  console.error(`✗ no level files found in ${LEVELS_DIR}`);
  process.exit(1);
}

let failed = 0;
for (const file of levelFiles) {
  try {
    const { raw, errors } = validateLevel(file);
    if (errors.length) { failed++; console.error(`✗ ${file}: ${errors.join("; ")}`); }
    else console.log(`✓ ${file} (${raw.name})`);
  } catch (err) {
    failed++; console.error(`✗ ${file}: ${err.message}`);
  }
}
console.log(`\nvalidated ${levelFiles.length} discovered level(s); ${failed} failed`);
console.log(`order: ${levelFiles.map((f) => f.replace(/\.json$/, "")).join(", ")}`);
process.exit(failed ? 1 : 0);

Sort parity is exact: all glob keys and readdirSync entries share the .json suffix, so default .sort() on full filenames ≡ the same comparator on bare ids. Both sides therefore derive identity from filename, never from file content.
