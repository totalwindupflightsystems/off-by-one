cargo-target-dir-host-dropin-release-binary-mislocation

Problem class: cargo-target-dir-host-dropin-release-binary-mislocation

Summary (TL;DR)

The build succeeds, but the judge probes the wrong path. When CARGO_TARGET_DIR (or build.target-dir / CARGO_BUILD_TARGET_DIR) points at a host drop-in such as /var/tmp/hermes-cargo-target, cargo writes the release binary to /var/tmp/hermes-cargo-target/release/hilo, while the judge still looks for <workspace>/target/release/hilo. The judge therefore reports a build failure even though the artifact exists. This is an environmental false negative, not a compile error.

Fix (one line): never hard-code target/release/<bin>. Either stage the artifact into target/release/ after building, or have the judge resolve the real target directory with cargo metadata / cargo build --message-format=json.

Symptoms

  • cargo build --release exits 0 and prints Finished release.
  • The judge fails with a "binary not found" / test -x target/release/<bin> failure.
  • The binary exists by hand at /var/tmp/hermes-cargo-target/release/<bin>.
  • Reproduces only where the host exports CARGO_TARGET_DIR; a clean shell passes.

Root-cause analysis

Cargo target-dir precedence (highest first):

  1. --target-dir <path>
  2. CARGO_TARGET_DIR env var
  3. build.target-dir in .cargo/config.toml (also CARGO_BUILD_TARGET_DIR)
  4. default target/ in the workspace root

A host drop-in (profile script, /etc/environment, systemd unit, CI wrapper, or .cargo/config.toml) sets CARGO_TARGET_DIR=/var/tmp/hermes-cargo-target to keep artifacts off a small root filesystem. Cargo honors it. The judge hard-codes the default location, so the two disagree. Two defects combine: the build's output location is environment-dependent, and the judge assumes the default instead of asking cargo. The contract should be: the build system's own report is the source of truth (cargo metadata → target_directory; cargo build --message-format=json → exact executable, including triple subdirs).

Diagnosis

env | grep -E 'CARGO_(TARGET_DIR|BUILD_TARGET_DIR)'
grep -R "target-dir" .cargo/config.toml .cargo/config 2>/dev/null
cargo metadata --format-version 1 --no-deps | jq -r '.target_directory'
ls -la target/release/hilo 2>&1 || true
find "$(cargo metadata --format-version 1 --no-deps | jq -r '.target_directory')" \
     -type f -name hilo -perm -u+x

Fixes

Fix A — Judge resolves the real target directory (preferred)

scripts/find-bin.sh:

#!/usr/bin/env bash
# Resolve a cargo-built binary regardless of where CARGO_TARGET_DIR points.
set -euo pipefail
BIN="${1:?binary name required}"
PROFILE="${2:-release}"
ROOT="$(cd "$(dirname "$(readlink -f "$0")")" && pwd)"

TARGET_DIR="$(cargo metadata --format-version 1 --no-deps 2>/dev/null \
              | jq -r '.target_directory // empty')"

CANDIDATES=()
if [[ -n "${TARGET_DIR:-}" ]]; then
  CANDIDATES+=("$TARGET_DIR/$PROFILE/$BIN")
  while IFS= read -r d; do
    [[ -n "$d" ]] && CANDIDATES+=("$d/$PROFILE/$BIN")
  done < <(find "$TARGET_DIR" -maxdepth 1 -mindepth 1 -type d -print 2>/dev/null)
fi
CANDIDATES+=("$ROOT/target/$PROFILE/$BIN")

for c in "${CANDIDATES[@]}"; do
  if [[ -x "$c" ]]; then echo "$c"; exit 0; fi
done
echo "find-bin: no executable '$BIN' found. Tried:" >&2
printf '  %s\n' "${CANDIDATES[@]}" >&2
exit 1

Fix B — Stage the artifact into target/release/ (gold standard)

scripts/build-release.sh:

#!/usr/bin/env bash
set -euo pipefail
BIN="${1:-hilo}"
cd "$(dirname "$(readlink -f "$0")")"

EXE="$(cargo build --release --message-format=json \
  | jq -r 'select(.reason=="compiler-artifact")
           | select(.executable != null)
           | select(.target.name=="'"$BIN"'")
           | .executable' | tail -n1)"

[[ -n "$EXE" && -x "$EXE" ]] || { echo "build-release: no executable for $BIN" >&2; exit 1; }
install -Dm755 "$EXE" "target/release/$BIN"
echo "build-release: staged $EXE -> target/release/$BIN"

Lighter variant (no --target):

cargo build --release
target_dir="$(cargo metadata --format-version 1 --no-deps | jq -r '.target_directory')"
install -Dm755 "$target_dir/release/hilo" target/release/hilo

Fix C — Force the default target dir (simplest)

env -u CARGO_TARGET_DIR cargo build --release --target-dir ./target
# or: export CARGO_TARGET_DIR="$PWD/target"; cargo build --release

Fix D — State the real path in the criterion

artifact: ${CARGO_TARGET_DIR:-target}/release/hilo
# or host-specific: /var/tmp/hermes-cargo-target/release/hilo

Verification

A self-contained fake cargo reproduces the exact CARGO_TARGET_DIR behavior and emits compiler-artifact JSON. Results observed:

  1. Failure reproduced: build succeeds, target/release/hilo not found, artifact at /var/tmp/hermes-cargo-target/release/hilo.
  2. Fix B: build-release: staged /var/tmp/hermes-cargo-target/release/hilo -> target/release/hilo → PASS.
  3. Fix A: resolved: /var/tmp/hermes-cargo-target/release/hilo → binary runs.
  4. Fix C: env -u CARGO_TARGET_DIR cargo build --release --target-dir ./target → PASS.
  5. Cross-compile: artifact lands in /var/tmp/hermes-cargo-target/x86_64-unknown-linux-gnu/release/hilo, which is why Fix B parses --message-format=json.

Prevention checklist

  • [ ] Never hard-code target/release/<bin> in a judge or criterion.
  • [ ] Resolve artifacts via cargo metadata or cargo build --message-format=json.
  • [ ] Stage judged binaries into target/release/ after the build.
  • [ ] Log the resolved target_directory for triage.
  • [ ] Print env | grep CARGO at CI job start to expose drop-ins early.
