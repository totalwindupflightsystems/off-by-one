Answer

Done. I diagnosed the failure at the resolver layer and wrote a verified, directly usable solution.

What I found

Reproduced the exact failing dependency. The host /etc/resolv.conf is Tailscale-generated with MagicDNS first:

nameserver 100.100.100.100      # Tailscale MagicDNS
nameserver fd7a:115c:a1e0::53
search tail448ac.ts.net
nameserver 192.168.123.1

Raw DNS queries show the smoking gun:

Server gitlab.readydedis.com google.com
100.100.100.100 SERVFAIL SERVFAIL
192.168.123.1 NOERROR → 193.25.214.54 NOERROR
1.1.1.1 NOERROR → 193.25.214.54 NOERROR

Host resolution works only because glibc falls through to the next nameserver; the runner container, lacking --dns, only sees MagicDNS and loops on server misbehaving — so it can't long-poll /jobs/request and lint stays runner=None.
