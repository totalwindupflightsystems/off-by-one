Root cause

The probe has two independent legs but collapses them into one status:

verdict = "ok" if (uniform and perpetual_ok) else "drift"

So a failed optional-flag type leg (perpetual: null) is reported under task_keys_uniform=drift even when len(counts) == 1. The wrapper then keys off that status and hard-codes one accusation + stale citation (MP-GAP-015/018), naming a cause the probe line itself disproved.

Fix

  1. Probe split by leg — emit task_keys_uniform=... and optional_flag_type=... separately; when keys are uniform but types fail, report ok for keys and list the offending row ids.
  2. Minority computation — for genuine drift, Counter + max(counts, key=lambda s: (counts[s], len(s), sorted(s))), then list the minority row ids.
  3. Wrapper follows classification — one verdict line per defect class, no hard-coded citation, original 0/1 exit semantics.
  4. Healthy line locked — a HEALTHY_LINE constant asserted by an identity test that passes before and after.

Verified reproduction result

One flipped perpetual on MP-GAP-015:

buggy : FAIL canary: non-uniform task-row base key sets (see lines above; MP-GAP-015/018)
fixed : FAIL canary: optional-flag type check failed (perpetual must be boolean; offending row ids: MP-GAP-015)

with the fixed probe printing task_keys_uniform=ok (1 distinct base key sets, sizes [31]) — no longer contradicting its own verdict.
