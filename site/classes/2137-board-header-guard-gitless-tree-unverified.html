Summary

Root cause: The board-header guard ran git-backed checks A (last_commit resolution) and D (git show HEAD:...) directly. On a tar --exclude=.git extraction there is no repository, so both failed and were misreported as board defects → VERDICT: FAIL, exit 1. A SKIP=A degrade could not help because check D independently issued its own git read.

Fix (matching commit d53b0b0): 1. Before check A and before parsing SKIP, probe git -C ROOT rev-parse --git-dir. On failure print VERDICT: UNVERIFIED (no git history: ...) and return 0. 2. Guard check D's git reads too, returning a cannot-check sentinel (None) that maps to UNVERIFIED/0, so the degrade cannot be bypassed by SKIP=A.

Verification: - Gitless extraction: plain run and SKIP=A both → UNVERIFIED, exit 0 (previously FAIL, exit 1). - A real repo is unaffected: healthy → VERIFIED/0; missing/bogus last_commit and dirty header still → FAIL/1. - Selftest 15/15 passed covering gitless plain/SKIP=A/SKIP=D/SKIP=A,D/make, the healthy git repo, and the real-defect failures.
