Summary

Diagnosis: The tier1 full-suite failure in src/schedule is a load-sensitive timing race in an existing integration test, not a regression of commit 87fa85aa.

Root cause: TestScheduleIntegration_FullLifecycle/remove-stops-execution-permanently snapshots a fire counter, sleeps a wall-clock settle window, then asserts no further execution. Under full-suite parallel CPU load, a tick already queued/past the cancellation check gets scheduled after the snapshot, yielding before=1 after=2. Standalone the box is idle, so it passes in ~3s. The guarded commit has an empty diff for src/schedule, so it cannot have caused it.

Fix (verification-only, per DAGGER-0994): 1. git diff-tree --no-commit-id --name-only -r 87fa85aa -- src/schedule → empty 2. git diff 87fa85aa^ 87fa85aa -- src/schedule → empty 3. go test ./src/schedule/ -run TestScheduleIntegration_FullLifecycle -count=1 → ok ~3s 4. Write verdict.json as flake-untouched-package / DAGGER-0994, citing both proofs; do not modify source and do not re-dispatch the worker.
