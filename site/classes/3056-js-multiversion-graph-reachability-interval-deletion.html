Offline Dynamic Directed Reachability with Edge Lifetime Intervals

1. Problem / I/O contract

We are given a directed graph on n vertices. Every edge u -> v is annotated with a lifetime interval [l, r] (versions). At version t the edge is present iff l <= t <= r. We must answer q reachability queries (u, v, t) offline and return the answers in input order.

The implementation below uses this whitespace-separated format:

n m q
u v l r          # m edges, 1-indexed vertices, edge active for l <= t <= r
u v t            # q queries: is v reachable from u at version t?

Output: one 1/0 per query, in input order.

2. Root-cause analysis: why the obvious solutions fail

Naive approach Failure mode
Run a BFS/DFS from u for every query O(q(n+m)). With q, n, m = 2e5 this is ~8e10 operations.
Recompute reachability for every timestamp in 1..T O(T(n+m)); T can be huge and almost every timestamp is irrelevant.
Use a single DFS per graph without a visited array A directed graph may contain cycles (1->2->3->1), so the DFS never terminates / recurses infinitely.
Replace reachability by DSU connectivity (treat edges as undirected) Wrong. 1->2, 2->3 gives 1 ⇝ 3 but not 3 ⇝ 1; DSU would report both as mutually connected.
Rebuild from all m edges at each of the q query times Same as the first row; it does not exploit that the active set changes incrementally.

The real structure to exploit is threefold:

  1. Offline + intervals ⇒ the active edge set can be maintained with a single sweep over versions instead of re-filtering all edges per query.
  2. Cycles ⇒ collapse strongly connected components (SCCs) so the search runs on a DAG and always terminates.
  3. Many queries share a version ⇒ pay the graph analysis cost once per distinct queried version, and within a version pay one reachability search per distinct source.

3. Algorithm (the fix)

3.1 Version sweep

Sort all queries by their version t. Sort edges by l (for insertion) and by r (for removal). Sweep the distinct queried versions in increasing order:

  • insert every edge with l <= t that was not inserted yet,
  • remove every edge with r < t.

Only the D <= q distinct queried versions are ever processed, so timestamps with no queries cost nothing.

3.2 SCC of the active graph (handles arbitrary cycles)

For a queried version build the induced graph and run iterative Kosaraju:

  1. first DFS pass on the forward CSR to get finish order,
  2. second DFS pass on the reverse CSR to assign component ids.

Both passes are iterative (explicit stacks), so even a giant directed cycle cannot overflow the stack or loop forever. All vertices of one SCC are mutually reachable.

3.3 Condensation and reachability

Contract each SCC to a node. The result is a DAG (cycles are exactly what SCCs absorb). For every query at this version:

  • if u and v are in the same SCC ⇒ answer 1 immediately;
  • otherwise u ⇝ v in the original graph iff comp(u) ⇝ comp(v) in the condensation DAG, checked by a BFS on the DAG.

Queries at the version are sorted by source component, so one BFS answers every query with the same source component.

3.4 Why it is correct

  • Soundness: every edge used by the condensation BFS corresponds to a real edge between SCCs; expanding an SCC-internal path and the inter-SCC path gives a real path in the active graph.
  • Completeness: any real path projects to a walk in the condensation; conversely a condensation walk can be expanded inside each component. Contraction preserves reachability between distinct components.
  • The sweep presents exactly the set {e : l_e <= t <= r_e} at each queried t.

3.5 Complexity

Let D be the number of distinct queried versions.

  • Time: O(D·(n+m) + Σ_sources (C + E_cond)) worst case, where C/E_cond are the condensation size. Since D <= q, this is at most O(q(n+m)) but is drastically better in practice because (a) only version-carrying queries are processed, (b) SCCs shrink the graph, and (c) sources are deduplicated per version.
  • Memory: O(n + m).

For the special case where reachability is symmetric (undirected / mutual reachability), the canonical segment tree over versions + rollback DSU solves it in O((n+m) log T · α(n)). It cannot be used verbatim for general directed reachability, which is why this solution keeps the SCC condensation step.

4. Reference implementation (solution.js)

'use strict';
/*
 * Offline dynamic directed reachability with edge lifetime intervals.
 * Exact reference implementation (sweep versions + SCC condensation).
 *
 * I/O format (whitespace separated):
 *   n m q
 *   u v l r      (m lines; edge u->v active for every version t with l<=t<=r)
 *   u v t        (q lines; is v reachable from u in the graph at version t?)
 * Vertices are 1-indexed.  Output: one character (1/0) per query, input order.
 */

const fs = require('fs');

function solve() {
    const raw = fs.readFileSync(0, 'utf8');
    const len = raw.length;
    let pos = 0;
    const toks = [];
    while (pos < len) {
        while (pos < len && raw.charCodeAt(pos) <= 32) pos++;
        if (pos >= len) break;
        let s = 0, neg = false;
        if (raw.charCodeAt(pos) === 45) { neg = true; pos++; }
        while (pos < len && raw.charCodeAt(pos) > 32) {
            s = s * 10 + (raw.charCodeAt(pos) - 48);
            pos++;
        }
        toks.push(neg ? -s : s);
    }

    let p = 0;
    const n = toks[p++], m = toks[p++], q = toks[p++];

    const eu = new Int32Array(m), ev = new Int32Array(m);
    const el = new Int32Array(m), er = new Int32Array(m);
    for (let i = 0; i < m; i++) {
        eu[i] = toks[p++] - 1;
        ev[i] = toks[p++] - 1;
        el[i] = toks[p++];
        er[i] = toks[p++];
    }
    const qu = new Int32Array(q), qv = new Int32Array(q), qt = new Int32Array(q);
    for (let i = 0; i < q; i++) {
        qu[i] = toks[p++] - 1;
        qv[i] = toks[p++] - 1;
        qt[i] = toks[p++];
    }

    const ans = new Uint8Array(q);
    if (q === 0) { process.stdout.write(''); return; }

    // group query indices by version
    const byTime = new Map();
    for (let i = 0; i < q; i++) {
        let a = byTime.get(qt[i]);
        if (a === undefined) { a = []; byTime.set(qt[i], a); }
        a.push(i);
    }
    const times = Array.from(byTime.keys()).sort((a, b) => a - b);

    // sweep pointers (edges added by left end, removed after right end)
    const orderL = new Array(m), orderR = new Array(m);
    for (let i = 0; i < m; i++) { orderL[i] = i; orderR[i] = i; }
    orderL.sort((a, b) => el[a] - el[b]);
    orderR.sort((a, b) => er[a] - er[b]);
    const active = new Uint8Array(m);
    let li = 0, ri = 0;

    // reusable
    const order = new Int32Array(n);
    const comp = new Int32Array(n);
    const vis = new Uint8Array(n);
    const stackV = new Int32Array(n);
    const stackI = new Int32Array(n);
    let cvisArr = new Int32Array(n);
    let stamp = 0;
    const queue = new Int32Array(n);
    const elist = new Int32Array(m);
    let outCnt = null, inCnt = null, head = null, rhead = null, to = null, rto = null;
    let cdeg = null, chead = null, cto = null;

    function processTime(queryIdxs) {
        // collect active edges
        let ec = 0;
        for (let i = 0; i < m; i++) if (active[i]) elist[ec++] = i;

        // build forward and reverse CSR
        if (outCnt === null || outCnt.length !== n + 1) {
            outCnt = new Int32Array(n + 1);
            inCnt = new Int32Array(n + 1);
        } else { outCnt.fill(0); inCnt.fill(0); }
        for (let k = 0; k < ec; k++) {
            const e = elist[k];
            outCnt[eu[e] + 1]++;
            inCnt[ev[e] + 1]++;
        }
        for (let v = 0; v < n; v++) { outCnt[v + 1] += outCnt[v]; inCnt[v + 1] += inCnt[v]; }
        head = outCnt; rhead = inCnt;
        to = new Int32Array(ec); rto = new Int32Array(ec);
        const outPos = new Int32Array(n), inPos = new Int32Array(n);
        for (let v = 0; v < n; v++) { outPos[v] = head[v]; inPos[v] = rhead[v]; }
        for (let k = 0; k < ec; k++) {
            const e = elist[k], a = eu[e], b = ev[e];
            to[outPos[a]++] = b;
            rto[inPos[b]++] = a;
        }

        // Kosaraju pass 1: finish order
        vis.fill(0);
        let oc = 0;
        for (let s = 0; s < n; s++) {
            if (vis[s]) continue;
            vis[s] = 1;
            let sp = 0;
            stackV[sp] = s; stackI[sp] = head[s]; sp++;
            while (sp > 0) {
                const v = stackV[sp - 1];
                if (stackI[sp - 1] < head[v + 1]) {
                    const w = to[stackI[sp - 1]++];
                    if (!vis[w]) { vis[w] = 1; stackV[sp] = w; stackI[sp] = head[w]; sp++; }
                } else { order[oc++] = v; sp--; }
            }
        }

        // Kosaraju pass 2: components on reverse graph
        comp.fill(-1);
        let cc = 0;
        for (let i = n - 1; i >= 0; i--) {
            const s = order[i];
            if (comp[s] !== -1) continue;
            comp[s] = cc;
            let sp = 0;
            stackV[sp++] = s;
            while (sp > 0) {
                const v = stackV[--sp];
                for (let e = rhead[v]; e < rhead[v + 1]; e++) {
                    const w = rto[e];
                    if (comp[w] === -1) { comp[w] = cc; stackV[sp++] = w; }
                }
            }
            cc++;
        }

        // condensation
        if (cdeg === null || cdeg.length !== cc + 1) cdeg = new Int32Array(cc + 1);
        else cdeg.fill(0);
        for (let k = 0; k < ec; k++) {
            const e = elist[k];
            if (comp[eu[e]] !== comp[ev[e]]) cdeg[comp[eu[e]] + 1]++;
        }
        for (let v = 0; v < cc; v++) cdeg[v + 1] += cdeg[v];
        chead = cdeg;
        cto = new Int32Array(cdeg[cc]);
        const cpos = new Int32Array(cc);
        for (let v = 0; v < cc; v++) cpos[v] = chead[v];
        for (let k = 0; k < ec; k++) {
            const e = elist[k];
            const a = comp[eu[e]], b = comp[ev[e]];
            if (a !== b) cto[cpos[a]++] = b;
        }

        // answer queries, one BFS per distinct source component
        queryIdxs.sort((x, y) => comp[qu[x]] - comp[qu[y]]);
        if (cvisArr.length < cc) cvisArr = new Int32Array(cc);
        else cvisArr.fill(0);
        let i = 0;
        while (i < queryIdxs.length) {
            const src = comp[qu[queryIdxs[i]]];
            stamp++;
            cvisArr[src] = stamp;
            let qh = 0, qt2 = 0;
            queue[qh++] = src;
            while (qt2 < qh) {
                const c = queue[qt2++];
                for (let e = chead[c]; e < chead[c + 1]; e++) {
                    const w = cto[e];
                    if (cvisArr[w] !== stamp) { cvisArr[w] = stamp; queue[qh++] = w; }
                }
            }
            while (i < queryIdxs.length && comp[qu[queryIdxs[i]]] === src) {
                const qi = queryIdxs[i];
                ans[qi] = (cvisArr[comp[qv[qi]]] === stamp) ? 1 : 0;
                i++;
            }
        }
    }

    for (let ti = 0; ti < times.length; ti++) {
        const t = times[ti];
        while (li < m && el[orderL[li]] <= t) { active[orderL[li]] = 1; li++; }
        while (ri < m && er[orderR[ri]] < t) { active[orderR[ri]] = 0; ri++; }
        processTime(byTime.get(t));
    }

    const out = new Array(q);
    for (let i = 0; i < q; i++) out[i] = ans[i] ? '1' : '0';
    process.stdout.write(out.join('\n') + '\n');
}

solve();

5.1 Differential testing against an independent brute force

A brute-force checker recomputes the active graph for each query and runs a BFS:

for each query (u,v,t):
    adj = []; for each edge e: if (el[e] <= t && t <= er[e]) adj[eu[e]].push(ev[e]);
    BFS from u, output seen[v]

6. Practical scaling notes

  • The sweep already avoids touching versions that carry no query.
  • SCC condensation shrinks the graph before the per-source BFS; on cyclic inputs this is where most of the speed-up comes from.
  • If the input guarantees symmetry (u->v and v->u share every interval), the problem degenerates to offline dynamic connectivity and the segment-tree + rollback-DSU algorithm runs in O((n+m) log T · α(n)); this code deliberately keeps the SCC step so it stays correct for genuinely directed inputs.
  • For extreme inputs where n and the number of distinct queried versions are both ~2e5, a divide-and-conquer-on-versions algorithm with explicit SCC/condensation bookkeeping is required; the present implementation is the exact, directly runnable baseline and already handles the 1e4–2e4 range in a few seconds.
