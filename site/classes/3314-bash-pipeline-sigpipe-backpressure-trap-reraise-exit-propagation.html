What it contains

Root-cause analysis of six independent failure modes:

  1. Job control off ⇒ the background pipeline shares the supervisor's process group; kill -- -$$ would kill the supervisor, and killing only the launcher orphans the stages (I reproduced this: the shell dies 143 instantly while sleep survives).
  2. set -e + pipefail short-circuit ⇒ the shell exits 141 before PIPESTATUS can be read.
  3. Trap args ⇒ trap on_signal TERM passes no $1; under set -u the handler aborts and leaks the sink.
  4. kill -0-gated wait ⇒ bash auto-reaps on SIGCHLD, so the gate is already false and the recorded status is skipped (rc stays 0).
  5. The exit-status race ⇒ a second signal interrupts the handler's wait, which returns 128+sig, losing the real 141.
  6. TERM-ignoring stages ⇒ need SIGKILL escalation.

The fix (supervisor.sh): setsid pipeline in its own process group; a track wrapper records each stage's real PID and resets signal dispositions; the inner runner keeps -e off, captures PIPESTATUS to a file, and ignores TERM/INT so it survives teardown; the trap does kill -0 probing + bounded grace + SIGKILL escalation, blocks re-entrant signals, and reaps with an unconditional wait ... || rc=$?; final_status decides from the persisted statuses (141 re-raised for a mid-stage SIGPIPE, otherwise the sink's code).

Verification section with two self-contained harnesses (embedded in the doc and confirmed byte-accurate against the tested scripts): - selfverify.sh — 10/10 checks pass (SIGPIPE→141, sink 7→7, sink 42→42, SIGPIPE beats sink 3, orphan/fd release on SIGTERM, grace→SIGKILL, repeated-signal non-reentrancy). - race_demo.sh — naive handler exits 137 (loses 141); hardened handler exits 141.

Also documented: the SIGINT-ignored-for-background-jobs caveat, setsid/pgrep dependencies, the SIGKILL-can't-be-trapped limitation, and the deliberate SIGPIPE-over-sink precedence.
