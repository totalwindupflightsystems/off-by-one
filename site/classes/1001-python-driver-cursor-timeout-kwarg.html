Answer

Premise check (RT-GAP-016): The task premise — that upstream Cursor.next() already has a timeout= kwarg — is false. I fetched and grepped the live sources: - master: def next(self, wait=True) — no kwarg - PyPI 2.4.10.post1 (the vendored base): def next(self, wait=True) → self._get_next(Cursor._wait_to_timeout(wait)) — a timeout is only reachable positionally through the wait slot, never as timeout= - v2.5.0 branch (gabor/python3-v2.5.0): def next(self, wait=True) — no kwarg - Async adapters (fetch_next(wait=True), _get_next(timeout)) likewise lack it

So this was implemented as a fork enhancement: a bounded-timeout kwarg on Cursor.next(), threaded straight into the driver's existing deadline machinery (recvall already computes settimeout(max(0, deadline - now)) and raises ReqlTimeoutError on socket timeout).

The patch (vendored rethinkdb/net.py, minimal 3-hunk diff):

class Cursor(object):
    # unchanged static validator (kept for the timeout=None path)
    @staticmethod
    def _wait_to_timeout(wait):
        if isinstance(wait, bool):
            return None if wait else 0
        elif isinstance(wait, numbers.Real) and wait >= 0:
            return wait
        else:
            raise ReqlDriverError("Invalid wait timeout '%s'" % str(wait))

    def next(self, wait=True, timeout=None):          # <-- fork enhancement
        if timeout is not None:
            # validate: Real >= 0, else ReqlDriverError
            if not isinstance(timeout, numbers.Real) or not timeout >= 0:
                raise ReqlDriverError(
                    "Invalid timeout '%s' - must be a non-negative number of seconds"
                    % str(timeout)
                )
            # pass a deadline (now + timeout) straight to _get_next
            return self._get_next(time.time() + timeout)
        # timeout is None -> keep the _wait_to_timeout path untouched
        return self._get_next(Cursor._wait_to_timeout(wait))


class DefaultCursor(Cursor):
    def _get_next(self, deadline):                    # now takes a deadline
        while len(self.items) == 0:
            self._maybe_fetch_batch()
            if self.error is not None:
                raise self.error
            self.conn._read_response(self.query, deadline)
        return self.items.popleft()

Note the validation form is not timeout >= 0, not timeout < 0 — this is deliberate: nan >= 0 is False, so NaN is rejected; nan < 0 is also False and would have let it through.

Usage:

import rethinkdb as r

conn = r.connect("localhost", 28015)
feed = r.table("events").changes().run(conn)     # changefeed stream

try:
    change = feed.next(timeout=2.0)              # bounded: ReqlTimeoutError after 2s
except r.ReqlTimeoutError:
    print("no event within 2s")

feed.next(timeout=0)                             # non-blocking: value or ReqlTimeoutError
feed.next(timeout=-1)                            # -> ReqlDriverError
feed.next(timeout="2")                           # -> ReqlDriverError
feed.next(timeout=float("nan"))                  # -> ReqlDriverError

feed.next()                                      # unchanged: block until first value
feed.next(wait=False)                            # unchanged: upstream non-blocking behavior
