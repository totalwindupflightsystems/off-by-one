Fix: Webhook delivery attempt ignores the caller budget (504 vs. false 200)

Task: INT-CI-004 — go-blocking-webhook-attempt-unbounded-by-caller-budget Repo: github.com/crier-dev/crier · Base commit: 267005b Fix files: internal/webhook/driver.go, internal/webhook/webhook.go, internal/webhook/driver_budget_test.go, internal/webhook/driver_ctx_test.go

Symptom

go test -short -count=1 ./... was intermittently red only under parallel-package load. TestDeliver_Blocking_TimeoutIs504/endpoint_hangs_past_the_budget got 200 with an empty reply instead of 504, while passing 3/3 in isolation and 10/10 with -count=10.

Root cause

DeliverBlocking enforced the caller deadline only between attempts, never during one. It computed deadline := now.Add(budget) and checked time.Now().After(deadline) at the top of the retry loop, but called the HTTP client with no context (http.NewRequest, not NewRequestWithContext). The only bound on an in-flight attempt was the driver-global http.Client.Timeout fixed at NewClient(timeout, secret). The per-agent Config.TimeoutMs never reached the client.

Why nondeterministic: the test endpoint slept 2s and the harness global client timeout was also 2s — a photo-finish. Client timeout first → retryable → budget exhausted → 504 (pass); server write first (loaded case) → 200 empty body → driver treated as SUCCESS (fail).

Production impact: a delivery with timeout_ms=100 could hold a session-gate slot for the full global timeout, and an over-budget attempt that eventually answered 2xx was reported as SUCCESS despite its own timeout expiring.

The fix (additive, no caller churn)

Add context-aware methods while keeping old signatures:

func (c *Client) Post(cfg Config, env Envelope, body []byte) (*http.Response, error) {
    return c.PostContext(context.Background(), cfg, env, body)
}

func (c *Client) PostContext(ctx context.Context, cfg Config, env Envelope, body []byte) (*http.Response, error) {
    req, err := c.postBody(ctx, cfg, env, body)
    if err != nil { return nil, err }
    return c.hc.Do(req)
}
// PostBatch / PostBatchContext follow identically.

func (c *Client) postBody(ctx context.Context, cfg Config, env Envelope, body []byte) (*http.Request, error) {
    // ...
    req, err := http.NewRequestWithContext(ctx, http.MethodPost, cfg.URL, bytes.NewReader(body))
    // ...
}

Bound each attempt by whatever budget remains:

deadline := time.Now().Add(budget)
for attempt := 0; ; attempt++ {
    if time.Now().After(deadline) {
        return errBudgetExhausted // Retryable -> 504
    }
    remaining := time.Until(deadline)
    if remaining <= 0 { remaining = time.Nanosecond } // WithTimeout requires > 0
    attemptCtx, cancel := context.WithTimeout(ctx, remaining)
    res, err := client.PostContext(attemptCtx, cfg, env, attempt)
    cancel() // every path; no timer leaks
    // ... error classification unchanged: deadline overrun stays Retryable -> 504;
    //     non-retryable rejection / unmappable 2xx stays ErrPermanent -> 502
}

Semantics preserved

  • Budget overrun / context deadline → Retryable (never ErrPermanent) → 504.
  • Non-retryable endpoint rejection and unmappable 2xx → ErrPermanent → 502.
  • cancel() runs on every path.

Verification

Deterministic regression test (driver_budget_test.go): 2s endpoint, 10s global client timeout (deliberately larger than the hang), 100ms budget. It asserts err != nil, not ErrPermanent, and elapsed < 1s.

  • Pre-fix: FAILS with err=nil after ~2.00s — "an over-budget endpoint 2xx was reported as a SUCCESS".
  • Post-fix: PASSES, returns promptly with a retryable/deadline error.
  • Non-vacuous: reproduced by reverting only driver.go.
  • go test -short -count=1 ./... green 3× consecutively (13/13 packages); TestDeliver_Blocking_TimeoutIs504 green -count=10; internal/webhook and internal/registry suites green; tier-1 guard PASS.

General lesson

A caller-supplied budget is not enforced by checking a deadline between retries; the attempt itself must carry the context deadline (context.WithTimeout(remaining) + http.NewRequestWithContext). Any test whose outcome depends on which of two equal-duration timers wins is a flake by construction — make one strictly longer, or bound the attempt explicitly.
