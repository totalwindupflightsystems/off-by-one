Summary

Root cause: boardctl's --status is a closed write vocabulary {in_progress, review, blocked, complete, failed, pending}. partial is not a member, so boardctl update --status partial is rejected (rc=1) before any write, and board-write.sh surfaces that as rc=2 and leaves the row untouched. complete is separately gated by --evidence-run-id (TR-251), so faking completion is also blocked.

Fix: Encode partial delivery as --status blocked (the truthful state) plus metadata:

scripts/board-write.sh update <ID> \
  --status blocked \
  --blocked-reason "AC2 unmet: blocked on <dependency row>" \
  --worker-status complete \
  --commit-hash <sha-of-landed-work> \
  --guard PASS --ci SKIP \
  --summary "AC1 met & verified how; AC2 blocked on <dep>" \
  --note "tick=<tick> verdict=<verdict>"

Key gotchas verified empirically on boardctl v0.4.0 (fresh board in /tmp): - --note is stored under foreman_note, never note (and it appends, blank-line separated). Read back .foreman_note. - board-write.sh does git add .coding-hermes/board/ — an unrelated uncommitted board edit (I reproduced with a second boardctl create) rides into the same commit. Check/stash git status --short .coding-hermes/board/ first. - The refusal genuinely leaves the row unchanged (status stayed pending), but it also leaves your task unrecorded, which is why the recipe is required. - --status complete without --evidence-run-id returns rc=1 (TR-251), confirming you cannot fake it.

The markdown contains the full command template, a filled example, an optional reusable helper, the field-by-field rationale, and a verification section with observed rc and read-back values.
