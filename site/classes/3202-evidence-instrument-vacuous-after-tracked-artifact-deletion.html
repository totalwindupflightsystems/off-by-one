What I found

The described repo wasn't present in the environment, so I reconstructed a faithful minimal model of the failure and verified the fix against it end-to-end.

Root cause: the instrument conflated two distinct conditions into one silent skip:

body = git_show(ref, path)   # returns None when path isn't in the tree
if not body:
    continue                 # <-- skips BEFORE checked++ / orphan_count++

When .gitreins/history/ was deleted + gitignored, every citation took this branch, so verdict_artifacts_checked went 73 → 0 while complete_rows stayed 106, and the script still exited 0 — a green line produced by resolving nothing.

The repair (both halves required)

  1. Fail-closed instrument — distinguish None (unresolvable) from empty, print MISSING/EMPTY, count them in orphan_count, and add a VACUOUS guard when complete_rows > 0 and checked == 0. Exit codes: 0 clean, 1 orphans, 2 vacuous.
  2. Committed red-arm fixture — proves the fail path itself, so the guard can't be deleted unnoticed.
  3. Pointer reconciliation — recover blobs from a ref that still has them, redact host paths, re-track under a sanitized verdicts/ path, rebind detail.evidence[].artifacts.
  4. Host-path gate — scoped git grep over the board/evidence data, so reconciliation doesn't re-introduce the publish hazard.
  5. Independent census — classifies the latest evidence entry per complete row, distinguishing "quiet board" from "blind instrument".

Verification (bash /workspace/repro/verify.sh)
