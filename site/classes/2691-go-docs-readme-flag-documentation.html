Solution: documenting Go CLI flags from source (go-docs-readme-flag-documentation)

Symptom / problem class

A Go CLI's README.md describes the tool but omits or misstates its flags — especially mode-dependent behavior: a flag that parses fine in one mode but is refused in another, or a mode that prints a specific banner/validation message. The documentation drifts because the only authority is the Go source (and the binary's --help output), and nothing forces the README to cite the tracking tickets (BT-* / DF-*) or to be checked after commit.

The tier‑2 judge does not read prose; it greps the committed README for the flag names, the refusal/banner semantics, and the ticket ids.

Root-cause analysis

  1. Two sources of truth. Flags are registered in Go (flag.StringVar, cobra/pflag, urfave/cli, kong, …) and reported by --help, while the README is a separate hand-written narrative. Nothing reconciles them.
  2. Mode-dependent semantics live in validation branches, not in the flag table. --help lists -C/--hook-path uniformly. Only the run/Validate code reveals that fleet mode refuses it and that warn mode prints a literal banner (e.g. WARN-ONLY — commit allowed) while still allowing the commit.
  3. No provenance / no post-commit check. The README bullets were not tied to BT-*/DF-* tickets, so reviewers cannot tell which change introduced the behavior, and the tier‑2 judge has nothing stable to grep.

The fix is procedural: extract the contract from the binary + source, encode it in README bullets that quote the exact literals and cite ticket ids, then assert it against the committed blob.

The exact fix

Step 1 — Enumerate flags from the authority (--help)

go run ./cmd/&lt;tool&gt; --help
go run ./cmd/&lt;tool&gt; <subcommand> --help   # per-subcommand flags

Step 2 — Cross-check the flag definitions in source

Find the registries and shorthands so the README covers both forms:

# stdlib flag
rg -n 'StringVar|BoolVar|IntVar|Var\(|flag\.' cmd/&lt;tool&gt;
# spf13/cobra + pflag
rg -n 'Flags\(\)\.(String|Bool|Int|Var)|MarkFlag|StringVarP|PersistentFlags'
# urfave/cli
rg -n 'cli\.(String|Bool|Int|Duration)Flag'
# kong
rg -n 'flag:"|cmd:".*help'

Step 3 — Read the refusal / validation branches

This is where the --help table lies by omission. Look for the mode switch and its error/banner literals:

rg -n 'mode|refus|WARN-ONLY|hook.path|return fmt\.Errorf|errors\.New' cmd/&lt;tool&gt;

Capture verbatim every string the judge is likely to grep: error text and banner text. For the reference case:

  • fleet mode + -C/--hook-path ⇒ fleet mode refuses -C/--hook-path: hooks are centrally managed (BT-1421).
  • warn mode ⇒ prints WARN-ONLY — commit allowed and the commit proceeds (DF-3097).

Step 4 — Add README bullets (single file, docs-only)

Write one bullet per flag, include shorthand + long form, the mode restriction, the exact literal, and the ticket citation. Reference diff:

@@
 See `dtx --help` for the available commands.
+
+## Flags
+
+- `-C, --hook-path <path>` — path to a hook script. Accepted in `safe` and
+  `warn` modes, but **refused in `fleet` mode** with the error
+  `fleet mode refuses -C/--hook-path: hooks are centrally managed` (BT-1421).
+- `--mode <safe|warn|fleet>` — operation mode, default `safe`. In `warn` mode
+  `dtx` prints the literal banner `WARN-ONLY — commit allowed` and the commit
+  is allowed to proceed (DF-3097). `fleet` is centrally managed and rejects
+  `-C/--hook-path`.
+- `-v` — verbose output.
+
+Source of truth: `cmd/dtx/main.go` (`newFlagSet` registrations and the `run`
+mode/refusal branches) cross-checked against `go run ./cmd/dtx --help`.

Step 5 — Foreman-direct / gitreins task lifecycle

A docs-only, single-file change takes the direct path (no full review pipeline). Create the task before committing and complete it after, anchoring it to the commit:

gitreins task create \
  --kind docs --files README.md \
  --tickets BT-1421,DF-3097 \
  --title "Document -C/--hook-path and warn/fleet mode semantics"

# ... edit README.md ...

git add README.md
git commit -m "docs(readme): document -C/--hook-path and --mode semantics (BT-1421, DF-3097)"

gitreins task complete --task "$TASK_ID" --commit "$(git rev-parse HEAD)"

Harness note: in this sandbox &lt;tool&gt; is a broken symlink, so the lifecycle commands above are the canonical form to run where the harness is installed. The tier‑2 assertion itself is reproduced by the local judge in the Verification section, which greps the committed blob.

Verification

The judge must read the committed README (git show HEAD:README.md), not the working tree, so a dirty edit cannot pass. Drop this next to the repo and run it:

#!/usr/bin/env bash
# verify-readme.sh [ref]   default ref: HEAD
set -euo pipefail
ref="${1:-HEAD}"
readme="$(git show "${ref}:README.md")"
fail=0
require() {
  local label="$1" pattern="$2"
  if printf '%s' "$readme" | grep -qF -- "$pattern"; then
    printf 'PASS  %-28s %s\n' "$label" "$pattern"
  else
    printf 'FAIL  %-28s %s\n' "$label" "$pattern"; fail=1
  fi
}
require "flag -C"             "-C"
require "flag --hook-path"    "--hook-path"
require "flag --mode"         "--mode"
require "fleet refusal"       "refused in"
require "fleet wording"       "fleet"
require "warn literal banner" "WARN-ONLY — commit allowed"
require "commit allowed"      "allowed to proceed"
require "ticket BT-1421"      "BT-1421"
require "ticket DF-3097"      "DF-3097"
exit "$fail"

PASS  flag --hook-path             --hook-path
PASS  flag --mode                  --mode
PASS  fleet refusal                refused in
PASS  fleet wording                fleet

Negative control (run against the README from before the fix) must exit non-zero and print FAIL for the missing tokens — proving the judge is discriminating:

./verify-readme.sh "$(git rev-list --max-parents=0 HEAD)"   # exits 1

Behavioral cross-check that the README matches the binary:

go run ./cmd/dtx deploy --mode fleet -C ./hook.sh   # exit 1, prints refusal
go run ./cmd/dtx deploy --mode fleet                # exit 0
go run ./cmd/dtx commit --mode warn                 # prints WARN-ONLY banner, exit 0

Minimal reproduction harness

The worked example (/workspace/demo-repo) uses this source. It is stdlib-only and reproduces the fleet refusal and warn banner so the procedure can be exercised without the original repo.

// cmd/dtx/main.go
package main

import (
    "flag"
    "fmt"
    "os"
)

const warnBanner = "WARN-ONLY — commit allowed"

const (
    ticketFleetRefusal = "BT-1421"
    ticketWarnBanner   = "DF-3097"
)

type options struct {
    hookPath string
    mode     string
    verbose  bool
}

func main() {
    if len(os.Args) < 2 {
        usage()
        os.Exit(2)
    }
    cmd := os.Args[1]
    fs := newFlagSet(cmd)
    var o options
    fs.StringVar(&o.hookPath, "C", "", "path to hook script (shorthand)")
    fs.StringVar(&o.hookPath, "hook-path", "", "path to hook script (long form)")
    fs.StringVar(&o.mode, "mode", "safe", "operation mode: safe|warn|fleet")
    fs.BoolVar(&o.verbose, "v", false, "verbose output")

    switch cmd {
    case "deploy", "commit", "-h", "--help", "help":
    default:
        usage()
        os.Exit(2)
    }
    if err := fs.Parse(os.Args[2:]); err != nil {
        os.Exit(2)
    }
    switch cmd {
    case "deploy", "commit":
        if err := run(cmd, o); err != nil {
            fmt.Fprintln(os.Stderr, "error:", err)
            os.Exit(1)
        }
    default:
        usage()
    }
}

func newFlagSet(name string) *flag.FlagSet {
    fs := flag.NewFlagSet(name, flag.ExitOnError)
    fs.Usage = usage
    return fs
}

func usage() {
    fmt.Fprint(os.Stderr, `dtx - example deployment tool

Usage:
  dtx <command> [flags]

Commands:
  deploy     apply the pending release
  commit     record the release

Flags:
  -C, --hook-path string   path to hook script (refused in fleet mode)
      --mode string        operation mode: safe|warn|fleet (default "safe")
  -v                       verbose output
`)
}

func run(cmd string, o options) error {
    switch o.mode {
    case "safe":
    case "warn":
        fmt.Println(warnBanner)
    case "fleet":
        if o.hookPath != "" {
            return fmt.Errorf("fleet mode refuses -C/--hook-path: hooks are centrally managed (%s)", ticketFleetRefusal)
        }
    default:
        return fmt.Errorf("unknown mode %q (want safe|warn|fleet)", o.mode)
    }
    if o.verbose {
        fmt.Printf("dtx: cmd=%s mode=%s hook-path=%q\n", cmd, o.mode, o.hookPath)
    }
    fmt.Printf("%s: ok\n", cmd)
    return nil
}

Pitfalls checklist

  • [ ] Grep the committed blob (git show HEAD:README.md), never the worktree.
  • [ ] Cover every alias/shorthand (-C and --hook-path); --help may show only one line for two registrations.
  • [ ] Quote the banner/error verbatim, including the em dash —; a normalized hyphen fails a fixed-string grep.
  • [ ] Record mode restrictions even when the flag appears in the global flag table — they come from validation branches, not the flag table.
  • [ ] Cite every BT-*/DF-* ticket that introduced the behavior.
  • [ ] Docs-only single file ⇒ foreman-direct; still run gitreins task create before commit and gitreins task complete after.
  • [ ] Keep the negative control in CI so the judge cannot silently pass on an empty/unrelated README.
