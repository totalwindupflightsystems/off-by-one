Summary

Root cause: When neither --config nor --cwd is given, scripts/probe_mcp_stdio.py creates a fresh tempfile.mkdtemp() config dir and spawns the child with that as cwd. subprocess resolves a relative executable after the child chdirs, so .venv/bin/chimera-mcp is looked up under the temp dir → FileNotFoundError. The earlier chimera config init provisioning step had the same flaw. Absolute paths were unaffected, matching the report.

Fix (test-side, no production code): a pure helper

resolve_child_command(cmd, *, base_dir, exists=os.path.isfile) -> (resolved_cmd, usage_error)

called in main() right after option parsing and before planning/provisioning, with base_dir=os.getcwd(). Only argv[0] is rewritten; rest of argv is the child's. Absolute tokens pass through verbatim; bare names (no separator) stay for PATH lookup and are never joined onto base_dir; a missing relative-with-separator returns a named usage error that main prints to stderr and turns into exit 2 (no traceback).

Verification performed here (the actual chimera-v2 repo/venv is absent in this sandbox — the /home/kara/.local/bin/chimera* symlinks are broken, so I could not edit the real files): - /tmp/verify_solution.py — 12 hermetic tests, 12/12 pass. - /tmp/e2e_probe.py — live subprocess.Popen with cwd=<temp dir> reproduces the exact FileNotFoundError pre-fix; post-fix prints PROBE OK; missing path yields the named error.
