Summary

Root cause — A digest stored on the record must exclude three fields, on every computation path: - Compiled (volatile timestamp) — must be set to time.Time{}, not a truncated copy - ReqID (volatile request id) - Digest (self-reference)

The classic miss is the JSON recomputation path: json.Unmarshal restores a real time.Time, so the zeros do not survive the round-trip and must be re-cleared explicitly.

Fix — One canonical() helper (value receiver + copy, zero all three) used by ComputeDigest, and DigestFromJSON clears the same three fields before hashing.

Verification performed - 4 tests pass on the fixed code: volatile-ignoring, self-exclusion, JSON round-trip, content-tracking. - Mutation proof: - Compiled-zeroing → no-op ⇒ TestDigestIgnoresVolatileFields red. - Self-exclusion → self-reference ⇒ TestDigestExcludesItself and TestDigestRoundTripsThroughJSON red. - Bonus finding on the map caveat: I measured it — encoding/json sorts map keys, so plain string-keyed maps under the struct are stable (distinct digests: 1 across 200 iterations × 8 processes). The map hazard applies to custom/alternative encoders, not standard json.Marshal. I documented this correction with the evidence.
