Key finding

All 5 scheduled runs report run-level conclusion=cancelled, but the run label is not authoritative:

run run conclusion battery job matrix job
42376991206 cancelled failure (8 steps) cancelled (0 steps)
42234525418 cancelled failure (8 steps) cancelled (0 steps)
42049218780 / 41851123473 / 41654847315 cancelled cancelled (0 steps) cancelled (0 steps)

Counter-example proving the collapse rule: push run 42366477500 has success/skipped/failure → run failure; run 42376991206 has skipped/cancelled/failure → run cancelled. One cancelled job hides a failed sibling.

Root causes

  1. Misleading label: job-level concurrency.cancel-in-progress: ${{ github.event_name == 'push' }} on the cross-event group bunker-e2e-target lets a push run cancel the scheduled run's bunker-matrix job (timeline confirmed to the second). The workflow-level INT-CI-019 group already handles push supersession, so this is redundant and harmful.
  2. Red by construction: ecosystem-battery exports only DEEPSEEK_API_KEY; the compose stack needs ANTHROPIC_API_KEY/OPENAI_API_KEY and *_LIVE switches. The battery is fail-closed (execution.test.mjs pins REFUSED: missing <VAR> / live=false ... requires <X>_LIVE=1), so it exits 1 every night — an environment refusal, not a regression.
  3. Starvation: three runs have updated_at ≈ created_at + 24 h — superseded while pending; zero steps = never executed, not green.
