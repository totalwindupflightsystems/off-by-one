Answer

Root cause (SL-GAP-013). The subprocess argv used a bare script name ("cli.mjs") with cwd = repo root. execFile/subprocess resolve bare names via PATH only, never relative to cwd. The script lives in scripts/, which is not on PATH, so the spawn fails with ENOENT. The wrapper then collapsed the error into a numeric status via Number(error.code) — and since error.code is the string 'ENOENT' on spawn failure, the test observed Number('ENOENT') === NaN instead of a real exit code.

Fix. Prefix the repo-relative scripts/ segment in the argv, and resolve external binaries (like gitleaks in ~/go/bin, which is not on the default PATH) via PATH-then-absolute lookup — never by bare name.

TypeScript (the actual bug):

// tests/subprocess-path.test.ts
const REPO_ROOT = path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..');

// BEFORE (bug): bare name -> PATH lookup -> ENOENT -> Number('ENOENT') === NaN
await execFileP('cli.mjs', [], { cwd: REPO_ROOT });

// AFTER (fix): repo-relative path -> resolved against cwd -> exits 0
await execFileP(path.join('scripts', 'cli.mjs'), [], { cwd: REPO_ROOT });

// Defensive guard: never let 'ENOENT' masquerade as a numeric status
function exitStatus(e: NodeJS.ErrnoException): number | 'MISSING_BINARY' {
  if (e.code === 'ENOENT') return 'MISSING_BINARY'; // explicit, never NaN
  return Number(e.code);
}

pytest equivalent:

# tests/test_subprocess_path.py
REPO_ROOT = Path(__file__).resolve().parent.parent

# AFTER: prefix scripts/ (repo-relative path)
subprocess.run(["node", "scripts/cli.mjs"], cwd=REPO_ROOT, check=True)

# gitleaks: PATH first, then ~/go/bin fallback (env quirk, not a code regression)
def resolve_gitleaks() -> Path | None:
    found = shutil.which("gitleaks")
    if found:
        return Path(found)
    candidate = Path.home() / "go" / "bin" / "gitleaks"
    return candidate if candidate.is_file() else None
# then pytest.skip("gitleaks not installed...") when None, never assert on NaN
