I diagnosed the problem and wrote the solution to /workspace/solution.md.

Summary

Environment note: the checkout at ~/Hermes-DAGger/&lt;project&gt; was not present in this sandbox — only the deployed artifact ~/.local/bin/dagger. I therefore reconstructed and confirmed the fix from the binary's DWARF/symbols/disassembly and verified the deploy-stamp gate directly.

Root cause (two layers)

  1. Code: (*QJSExecutor).execute built the eval context only from tierRuntimeOptions and never read the node's declared timeout, so the hard 120s tier ceiling always won. Fix: declaredNodeTimeout(declared string) time.Duration parses the declaration and execute appends WithTimeout(d) after the tier options, so the declared value overrides the ceiling; blank/invalid/non-positive declarations fall back to the tier value.
  2. Deploy-lag trap: the live wrapper runs DAGGER_BIN (repo-root ./dagger), and the artifact used for the "post-fix" run was built the day before the fix. Pre-fix binary ⇒ 120s death ⇒ fix looks broken. Any evidence against a binary older than the fix is invalid.

Plumb the declared timeout

  • src/sandbox/qjs/executor.go: declaredNodeTimeout + append-last override in execute.
  • src/mcp/adapter.go: ScopedExec.TimeoutSeconds int carried through ExecuteScopedSpec/executeScoped.
  • src/mcp/server.go: populate ScopedExec.TimeoutSeconds from the request's timeout_seconds.

Verification (actually confirmed in this environment)

  • dagger version → Hermes DAGger v0.1.0 (build 271c313) (= post-fix HEAD f7a524eb + tests 3a3418bb + lint 271c3138).
  • go version -m dagger | grep vcs → vcs.revision=271c3138ca36…, vcs.modified=false, time 2026-10-24.
  • Fix symbols present: qjs.declaredNodeTimeout, QJSExecutor.tierRuntimeOptions.WithTimeout.func1, engineAdapter.ExecuteScopedSpec.
  • Operator diagnostic embedded: raise this node's declared timeout (unset nodes default to 600s) or investigate host load.
  • Contrast: dagger.prev-31e6ca0 is 31e6ca0…/2026-09-23 and +dirty — the exact stale-binary class to reject.

Procedure in the doc

  • V0 negative control (git checkout f7a524eb^ -- <files> with tests present → watch them fail).
  • V1 build-stamp gate (vcs.revision ≥ fix, vcs.modified=false, clean rebuild).
  • V2 tests TestQJSExecutor_DeclaredNodeTimeoutOverridesTierCeiling, TestEngineAdapterExecuteScopedSpecCarriesDeclaredTimeoutToNode.
  • V3 run.jsonl duration_ms histogram: pre-fix 120000-class, post-fix natural duration.
  • Pitfall documented: golangci-lint sibling-worktree paths still point at a real finding in your tree — fix at HEAD regardless.

Bottom line: thread the declared timeout into the QJS eval context so it overrides the tier ceiling, and verify the deployed binary's build stamp is ≥ the fix before interpreting any live 120s failure as a fix failure.
