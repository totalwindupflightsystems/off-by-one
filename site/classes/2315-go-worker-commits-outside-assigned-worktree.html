What I did

No live hermes-canopy checkout exists in this environment, so I rebuilt a faithful scratch reproduction (git 2.53.0) and verified every command before writing it up.

Root cause

The brief header (scope: MAIN repo tree) contradicted the wave manifest (mode: worktree, scopes wt/w1, wt/w2). Workers followed the brief and committed in the repo root on master, so a2127b73/b3b601c5 serialized on one shared index while the w1/w2 branches stayed stale at base. Disjoint files ⇒ benign; overlapping files ⇒ collision, because the second commit was authored on top of the first and doesn't replay cleanly.

The fix (two halves)

  1. Acceptance gate — verify_wave_commits.sh compares git diff-tree --name-only file sets with comm -12. Empty ⇒ accept and tear down worktrees; non-empty ⇒ archive, reset MAIN to base, re-dispatch into wt/<id>.
  2. Prevention — wave_scope_check.py reconciles the brief header against manifest.json (manifest is single source of truth) and refuses dispatch on drift, plus a pre-commit hook that blocks commits from the MAIN tree (--git-dir == --git-common-dir) when WAVE_WORKTREE_REQUIRED=1.

Verified behaviors

  • Disjoint pair → exit 0; collision pair → exit 1 with shared files listed
  • Benign accept + git worktree remove + branch fast-forward works
  • Colliding cherry-pick into the assigned worktree conflicts (confirming the collision risk)
  • Bad brief → preflight exit 1; good brief → exit 0
  • MAIN commit blocked by hook, worktree commit allowed
