Fixing the "phrase is accepted anywhere in the file" acceptance defect

Problem class: foreman-off-by-one-one-tick-board-closeout Scope: doc-only change; the acceptance test (pre-solve lab criterion) is under-specified.

1. Root cause

The acceptance test named only the file and the required phrase. It did not name the heading/section the phrase must live under, nor define how the section body is delimited. A judge implementing "does this substring appear in this file?" returns PASS even when the phrase sits in an unrelated section — a false positive.

Two coupled defects:

  1. Spec defect (primary): no heading field and no statement that the phrase must be inside that heading's section.
  2. Boundary defect (the "off-by-one / one-tick" trap): even with a heading, naive scans lines[heading_idx : next_heading_idx] or [heading_idx+1 : next_heading_idx+1] can include the target heading text, include the next heading/sibling body, or mishandle the last section with no following heading ("board closeout").

2. Exact fix

2.1 Change the acceptance criterion

Before (ambiguous — the bug):

checks:
  - file: docs/setup.md
    contains: "make install"

After (correct):

checks:
  - name: install-section-documents-make-install
    type: file_section_contains
    file: docs/setup.md
    heading: "## Install"     # exact heading (level + text)
    contains: "make install"  # required phrase
    scope: section            # section = body incl. sub-headings; direct = stop at any next heading

The criterion must state explicitly: "the phrase <P> must appear inside the section whose heading is <H> in file <F>, not merely elsewhere in the file."

2.2 Section-aware check (half-open bounds)

def find_heading(lines, heading_spec):
    spec = heading_spec.strip()
    m = HEADING_RE.match(spec)
    want_level = len(m.group(1)) if m else None
    want_text  = m.group(2).strip() if m else spec
    for idx, level, text in parse_headings(lines):
        if text == want_text and (want_level is None or level == want_level):
            return idx, level
    return None

def section_bounds(lines, idx, level, scope="section"):
    start = idx + 1          # exclude the target heading itself
    end   = len(lines)       # closeout: last section ends at EOF
    for j, jlevel, _ in parse_headings(lines):
        if j <= idx:
            continue
        if scope == "direct":
            end = j          # any next heading closes a direct section
            break
        if jlevel <= level:  # sibling/ancestor closes a nested section
            end = j
            break
    return start, end        # half-open, never includes the next heading

found = find_heading(lines, chk["heading"])
if not found:
    return [f"heading {chk['heading']!r} not found in {chk['file']}"]
idx, level = found
start, end = section_bounds(lines, idx, level, chk.get("scope", "section"))
if chk["contains"] not in "".join(lines[start:end]):
    return [f"phrase {chk['contains']!r} not found under heading "
            f"{chk['heading']!r} ({chk['file']}:{start + 1}-{end})"]
return []

4. Reviewer / judge checklist

  1. Does the test name file + exact heading + required phrase?
  2. Does it state the phrase must be inside that heading's section, not merely in the file?
  3. Is scope defined (do nested sub-headings count)?
  4. Is the range half-open (start = heading+1, end = next sibling/ancestor, EOF if none)?
  5. Is the last section handled?
  6. Do negative tests reject phrases before the heading, in a later sibling, or in the next heading text?
