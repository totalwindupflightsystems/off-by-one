Answer

Verified and written. Summary of the diagnosis and solution:

What was actually wrong

The "judge is BLOCKED" premise was a false blocker. gitreins 0.12.1 is fully installed at $HOME/.gitreins-venv/lib/python3.13/site-packages/{gitreins,engine}. Only the generated entry points are broken:

  • bin/gitreins is a console script with a shebang pointing at the foreign, unreadable home (#!/home/bunker-eduos-agent/.gitreins-venv/bin/python) → bad interpreter, exit 126.
  • /usr/local/bin/gitreins is a second dangling symlink into the same home.

The interpreter and package code are fine, so run the CLI through the venv Python with site-packages on sys.path, bypassing bin/gitreins.

The fix

A defensive ~/gr.sh wrapper that: 1. locates $VENV/lib/python*/site-packages, 2. uses the venv Python (with fallback to a local Python 3.13 if bin/python is also dangling), 3. prepends $VENV/bin + local Node bin + ~/.local/bin to PATH (fixes Tier‑1 pnpm/pytest not found), 4. optionally sources the provider env file then forces a valid model, 5. cds to GITREINS_WORKDIR and execs: python -c 'sys.path.insert(0, SITE); del sys.argv[1]; from gitreins.cli import main; main()' "$SITE" "$@".

Gotchas documented: retired slug deepseek-flash → OpenRouter 400; override GITREINS_LLM_MODEL=deepseek/deepseek-v4-flash-0731 after sourcing; never wrap the judge in timeout — run background and poll.

Verification performed live (real 0.12.1, Python 3.13.13)

  • Direct console script fails (exit 126); venv Python imports 0.12.1.
  • Wrapper works even when both bin/gitreins and bin/python are dangling.
  • task create + task start + Tier‑1 judge → PASS.
  • Full Tier‑2 LLM judge → Stage tier2: PASS, Overall: PASS ✓, verdict persisted at .gitreins/history/2026-09-20/61f8864e/ (tier1+tier2 stages, passed: true).
  • API check: deepseek-flash → HTTP 400; deepseek/deepseek-v4-flash-0731 → HTTP 200.
