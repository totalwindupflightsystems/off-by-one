Root cause

The TR-007 model-busy gate read the spawn ledger (schema v2, spawn/ledger.jsonl) but treated an empty/missing feed identically to a genuinely-quiet feed. Since the scheduler never wires start/end() into the feed, the ledger stays 0-byte and the gate silently passes — disabled by accident with zero visibility. The feed itself was never the problem; the code never asked "is this feed even connected?"

The fix (honest state beats a fake feature)

  1. status --json now reports wired:bool (rows>0) plus rows/started_open/terminal counts; unwired text output prints a WARNING: line and exits non-zero.
  2. resolve() emits spawn-ledger-NOT-WIRED and sets gates_loaded.ledger=false when the ledger has zero rows, while still surfacing ledger_rows.
  3. wired is derived from the data feed, never a config flag — it auto-flips to True the moment a trace row lands.
  4. Decision documented: wiring belongs to the scheduler project (cross-repo boundary — no Go touched, see docs/ integration note in §4).

Verification (all pass, python3)

Case Result
empty/missing ledger → resolve() ledger_wired:false, gates_loaded.ledger:false, NOT-WIRED warning, ledger_rows:0
with a trace {status:"started"} wired:true, gates_loaded.ledger:true, started_open:1
auto-flip appending one "running" row flips wired to True (no config)
status --json unwired {"wired":false,"rows":0,...}, exit code 1
inherited gates_loaded extended in place → {"busygate":true,"ledger":true}
terminal flip an empty feed is wired:false; first trace makes it wired:true

Output highlighted the key behavior:

$ router_ledger.py resolve
{ gates_loaded: { "ledger": false },
  warnings: [ "spawn-ledger-NOT-WIRED: ... (rows=0)" ],
  ledger_rows: 0, ... ledger_wired: false }

Once a trace lands: ledger_wired:true, gates {"ledger":true}, warnings: [].
