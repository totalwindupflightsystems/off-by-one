Fix: append_board_event.py silently resets ticks_idle to 0 on work ticks

Problem class: h3-board-appender-resets-ticks-idle-on-work-tick Repo: get-h3/h3 · Tick: 353 · Board commit: b56d78c

Symptom

On an h3 umbrella work tick, the JSONL board header ticks_idle silently changed from 1 → 0 even though --set ticks_idle was deliberately omitted:

append_board_event.py <repo> <tick> <detail.json> \
  --set last_commit=<sha> --set ticks_total=<tick>

The appender reported success and updated ticks_total/last_commit correctly, so the reset was invisible unless pre/post values were compared. Doctrine: work ticks leave ticks_idle UNCHANGED; only idle ticks increment it and an E2E due-cycle resets to 0.

Root cause

append_board_event.py does a full header-row rebuild. It initializes ticks_idle from a default of 0 and only overwrites fields present in --set. Omitting the flag — the documented safe move — is exactly what triggers the reset. Since the JSONL board is canonical, the bad value gets committed and becomes the next tick's authority.

The fix

Treat the pre-tick header as authority and repair after the append, before the board commit. Rewrite only the header line; never touch event rows or other fields.

1. Capture pre-tick value

REPO=/path/to/h3
BOARD=.coding-hermes/board/board.jsonl
PRE_IDLE=$(git -C "$REPO" show "HEAD:$BOARD" | head -n1 \
  | python3 -c 'import sys,json; print(json.load(sys.stdin).get("ticks_idle"))')

2. Append as usual

uv run --with duckdb append_board_event.py "$REPO" "$TICK" "$DETAIL" \
  --set last_commit="$SHA" --set ticks_total="$TICK"

3. Repair header before commit (board_idle_guard.py)

#!/usr/bin/env python3
"""Repair an accidentally-reset ticks_idle in a JSONL board header.

Usage: board_idle_guard.py <board.jsonl> <pre_tick_ticks_idle>
Exit 0 = value correct (repaired or already correct); 1 = mismatch remains.
"""
import json
import sys


def main() -> int:
    board_path, pre_idle = sys.argv[1], int(sys.argv[2])

    with open(board_path) as fh:
        lines = fh.read().splitlines()

    header = json.loads(lines[0])
    if header.get("ticks_idle") != pre_idle:
        header["ticks_idle"] = pre_idle          # restore only this field
        lines[0] = json.dumps(header)
        with open(board_path, "w") as fh:
            fh.write("\n".join(lines) + "\n")
        print(f"repaired ticks_idle -> {pre_idle}")
    else:
        print(f"ticks_idle already {pre_idle}, no change")

    after = json.loads(open(board_path).readline())
    ok = after.get("ticks_idle") == pre_idle
    print("verify:", json.dumps({k: after[k] for k in
          ("ticks_total", "ticks_idle", "last_commit") if k in after}))
    return 0 if ok else 1


if __name__ == "__main__":
    raise SystemExit(main())

python3 board_idle_guard.py "$REPO/$BOARD" "$PRE_IDLE"

4. Commit + sync

git -C "$REPO" add "$BOARD"
git -C "$REPO" commit -m "board: tick ${TICK} (preserve ticks_idle)"
git -C "$REPO" push
git -C "$REPO" rev-list --count origin/HEAD..HEAD   # expect 0

Lesson

For any JSONL board appender, never assume "omitted flag = value preserved". Diff the pre/post header field by field. When a canonical appender does a full-row rebuild, omitted fields fall back to defaults — so treat git show HEAD:<board> as the authority and repair after the append, before committing.
