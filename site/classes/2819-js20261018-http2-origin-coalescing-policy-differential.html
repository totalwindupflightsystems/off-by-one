HTTP/2 Origin-Coalescing Policy Differential — Diagnosis and Verified Fix

Problem class: js20261018-http2-origin-coalescing-policy-differential Environment: Node.js (verified v22.23.2; source targets Node 20+) Deliverable: a streaming analyzer that reports only exploitable authority-confusion traces and emits a minimal, replayable trace per finding.

1. What must be decided

HTTP/2 connection reuse (RFC 9113 §9.1.1) lets a request for origin B travel over a connection opened to A. Strict rule — reuse is valid only if:

  1. TLS authority: the connection certificate covers B's host (SAN/CN, wildcards honored), and
  2. Routing authority: B currently resolves to the connection's peer, or a live Alt-Svc mapping justifies it.

Real clients relax (2) ("IP relaxation") and sometimes (1) ("IP-only"). The gap between what the client did and what strict policy allows is the policy differential. A differential is not automatically an exploit — it only is when it crosses an authority boundary and is attacker-triggerable.

2. Root-cause analysis

2.1 Baseline bug: a differential ≠ an exploit

The naive rule (flag if request.origin !== connection.host) false-positives on everything legitimate:

Benign case Why the naive rule misfires
SAN/wildcard covers target (*.example.com) host inequality ≠ authority inequality
sibling hosts under one registrable domain same site boundary, no trust gap
peer is one of several fresh A/AAAA records (LB) routing authority holds for any current answer
DNS changed mid-flight (connection race) both endpoints authenticated for target
proxy CONNECT / proxy-MITM peer IP is the proxy's; IP check meaningless
TLS mismatch with no demonstrated trigger trace doesn't prove reachability

An exploitable finding therefore requires all of: strict policy denies, TLS does not authenticate the target, the authenticated identity is a different registrable domain, and the trace demonstrates a DNS answer or Alt-Svc entry steering the victim origin at the peer. Stale cache entries are valid triggers but must be surfaced (staleCache: true).

2.2 Concrete bug found by fuzzing

Certificates were indexed without regard to request time, so a cert observed after a request retroactively authenticated it:

seed 260: request victim-origin @ t=99 on c0
          cert {sans:[a.example.com]} @ t=144   <-- observed 45 ms later

This produced a finding whose minimal trace (events ≤ request) no longer reproduced it. Root cause: mixing an event-index view with a point-in-time view. Fix: _sansAt(conn, t) exposes only the latest handshake cert with t' <= request.t; unknown ⇒ UNKNOWN_CERTIFICATE. The minimizer now shrinks from the full trace and verifies the returned trace replays.

Decision core

_strictAllows(conn, reqHost, t) {
  const sans = this._sansAt(conn, t);                 // time-correct cert
  const certOk = sans != null && certCoversAny(sans, reqHost);
  if (conn.via === 'proxy-mitm') return { ok: true, certOk, certKnown: true };
  if (conn.via === 'proxy')      return { ok: certOk, certOk, certKnown: sans != null };
  const dns = this._dnsAt(reqHost, t);
  const freshIp = !!(dns && !dns.expired && conn.ip && dns.ips.includes(conn.ip));
  const alt = this._altAt(reqHost, t);
  const altOk = !!(alt && !alt.expired &&
    (alt.altHost === conn.host || this._dnsAt(alt.altHost, t)?.ips?.includes(conn.ip))) && certOk;
  return { ok: certOk && (freshIp || altOk), certOk, certKnown: sans != null };
}

_sansAt(conn, t) {                                    // <-- the §2.2 fix
  let best = null;
  for (const c of conn.certs) { if (c.t <= t) best = c; else break; }
  return best ? best.sans : null;
}

5. Why it is correct

  • Sound: a finding requires positive evidence on all three axes simultaneously (time-correct TLS non-coverage, different registrable domain, concrete DNS/Alt-Svc trigger); every benign explanation short-circuits first. Mechanically checked by the 400-trace fuzz invariant.
  • Complete: DNS hijack/rebinding and Alt-Svc redirection — including stale entries — are explicit trigger classes.
  • Replayable: minimization is delta-debugged against the analyzer and validated before returning.
  • Time-correct: DNS, cert, and Alt-Svc state are all resolved as-of the request timestamp.
