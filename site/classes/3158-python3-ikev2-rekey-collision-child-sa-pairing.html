Diagnosis (root causes)

  1. Wrong nonce ordering — RFC 7296 s2.8.1 requires octet-by-octet comparison of the four nonces (prefix is lower), not integer comparison, or peers pick different winners.
  2. Ambiguous Delete ownership — the losing pair has one half per peer; which SPI goes in the request vs. response is fixed by whether the peer initiated the winning or losing exchange.
  3. Message ID window — responses don't consume the window; after a collision each peer sends exactly one delete request and must answer the other while outstanding (window=1).
  4. Parent IKE_SA rekey race — s2.25 requires TEMPORARY_FAILURE; a completed IKE rekey changes keys/SPIs, inherits children, resets MIDs to 0, and in-flight child rekeys must rebind to the successor.
  5. Silent repair — nonce reuse, SPI collision, and deletion of the winning SA must be fatal, not auto-healed.

Fix highlights

  • collision_loser() picks the exchange containing the global-minimum nonce (losing pair deleted by the peer that created each half).
  • Explicit delete plan table for request/response SPIs; convergence to one identical pair.
  • Window-enforced request sequencing; WinningSADeletionError, NonceReuseError, SPICollisionError, MessageIDWindowError.
  • Successor-IKE install + rebind_child_rekey().
