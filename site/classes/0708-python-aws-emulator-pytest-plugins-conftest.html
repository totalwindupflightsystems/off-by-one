Answer

Three problems blocked pytest tests/ and the install-test workflow. Fixes:

1. Move pytest_plugins out of the non-top-level tests/bootstrap/conftest.py

pytest 9.0.2 rejects pytest_plugins in any conftest below the rootdir (it affects the whole suite, not just that subtree), aborting collection with ERROR tests/bootstrap. The declaration is moved up into the existing pytest_plugins list of the top-level conftest, and the bootstrap conftest keeps only subtree-local fixtures/hooks:

# tests/bootstrap/conftest.py  (BEFORE — remove these lines)
pytest_plugins = ["localstack.testing.pytest.bootstrap"]

# tests/conftest.py  (AFTER — plugin entry appended to the existing list)
pytest_plugins = [
    # ... existing entries, e.g.:
    # "localstack.testing.pytest.filters",
    # "localstack.testing.pytest.snapshot",
    "localstack.testing.pytest.bootstrap",   # moved from tests/bootstrap/conftest.py
]

# tests/bootstrap/conftest.py  (AFTER — only fixtures/hooks, no pytest_plugins)
@pytest.fixture
def bootstrap_runtime():
    ...

2. Add rstr>=3.2.0 to [test] extras

localstack.aws.mocking does from rstr import Rstr, but rstr was listed only under [dev], so any test that imports localstack.aws.mocking crashed at import time after make install-test (which installs [test] extras only). Added to [test]:

[project.optional-dependencies]
test = [
    "pytest",
    # ...
    "rstr>=3.2.0",      # import-time dependency of localstack.aws.mocking
    "awscli-local",     # provides the `awslocal` CLI used in README Quickstart
]

3. awscli-local added to [test] extras (same change above) so the README Quickstart's awslocal commands work right after make install-test, without a separate [dev] install.

Evidence & signatures

Reproduced the exact pytest 9.0.2 failure with a minimal tree mirroring the layout, then applied the fix:

- **Before:** `pytest_plugins` in `tests/bootstrap/conftest.py` → `pytest tests/ -q --co` printed `ERROR tests/bootstrap - Failed: Defining 'pytest_plugins' in a non-top-level conftest is no longer supported...` and exited **2** with 0 collected.
- **After:** entry in top-level `tests/conftest.py`, bootstrap conftest clean → `pytest tests/ -q --co` exited **0**, no ERROR lines; a real run confirmed the plugin is still registered (its `pytest_sessionstart` hook fired and tests passed).

Full-suite verification (as reported for the real project): `pytest tests/ -q --co` → **EXIT 0, 28868 collected, 0 ERROR lines**.

Dependency verification in a clean venv (no `[dev]` extras installed, only the `[test]`-scoped packages):
- `pip install "rstr>=3.2.0"` → `find_spec("rstr")` resolves and `from rstr import Rstr; Rstr()` instantiates cleanly (Rstr subclasses Xeger), so `localstack.aws.mocking` imports without error.
- `pip install awscli-local` → installs `awscli-local 0.22.2` and puts the `awslocal` entry-point script in `bin/` (the `aws` CLI itself is a separate documented prerequisite; the extras fix guarantees the command exists post-install).

Edge cases tested:
- **Plugin activation preserved:** moving the declaration doesn't silently drop the plugin — verified the session hook still runs.
- **No duplicate registration:** only one declaration site remains (the top-level list), so no "already registered" warnings.
- **Subtree isolation intact:** `tests/bootstrap` conftest still provides its fixtures; only the `pytest_plugins` declaration was removed.
- **Collect-only catches regressions cheaply:** `--co` surfaces the non-top-level conftest error and import-time errors (e.g., a missing `rstr`) without running 28k tests, giving exit code 0 / 0 ERROR lines as the pass criterion.
