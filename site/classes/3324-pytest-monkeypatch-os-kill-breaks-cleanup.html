Fix: monkeypatch-ed os.kill breaks the test's own finally cleanup

Summary

tests/test_kernel_matrix_teardown.py has two independent defects that both surface as false product failures:

  1. A test patches os.kill with monkeypatch.setattr(os, "kill", ...) to force an EPERM, then reaps its own child process in finally via Popen.kill()/terminate(). subprocess calls os.kill internally, the patch is still live, so the fake raises PermissionError: [Errno 1] from cleanup. The harness's own teardown error masquerades as a product bug, and the child leaks.
  2. A monkeypatched Popen fake is defined as def fake_popen(**kwargs), but the module calls subprocess.Popen(argv, ...) positionally, giving TypeError: fake_popen() takes 0 positional arguments but 1 was given.

Root cause

subprocess.Popen.send_signal() resolves the attribute at call time:

# /usr/lib/python3.14/subprocess.py
def send_signal(self, sig):
    self.poll()
    if self.returncode is None:
        os.kill(self.pid, sig)      # <-- patched globally

Patching the shared os module object is process-global, so Popen.kill() hits the fake and raises before wait(), masking the pytest.raises result and orphaning the child. The traceback points at the test's own proc.kill() line. Also, monkeypatch.setattr(kernel_matrix.os, "kill", ...) is not scoped — it is the same object as os.

Exact fix

def _spawn_sleeper():
    return subprocess.Popen([sys.executable, "-c", "import time; time.sleep(60)"])

def _reap(proc):
    proc.kill()
    try:
        proc.wait(timeout=5)
    except subprocess.TimeoutExpired:
        proc.kill()
        proc.wait(timeout=5)

def test_spawn_kernel_accepts_positional_argv(monkeypatch):
    class FakeProc:
        pid = 4242

    def fake_popen(*args, **kwargs):        # FIX 2: accept positional argv
        assert args and isinstance(args[0], (list, tuple))
        return FakeProc()

    monkeypatch.setattr(kernel_matrix.subprocess, "Popen", fake_popen)
    assert kernel_matrix.spawn_kernel([sys.executable, "-c", "pass"]).pid == 4242

def test_teardown_reports_eperm(monkeypatch):
    proc = _spawn_sleeper()
    real_kill = os.kill
    try:
        def fake_kill(pid, sig):
            if pid == proc.pid:
                raise PermissionError(errno.EPERM, "Operation not permitted")
            return real_kill(pid, sig)      # pass through other PIDs

        with monkeypatch.context() as mp:   # FIX 1: reverts before finally
            mp.setattr(os, "kill", fake_kill)
            with pytest.raises(kernel_matrix.KernelTeardownError):
                kernel_matrix.teardown(proc.pid)
    finally:
        _reap(proc)                         # real os.kill restored here
Fix Reason
with monkeypatch.context() as mp: __exit__ always calls undo(), restoring real os.kill before cleanup even if the body raises.
pid-aware fake_kill + real_kill Defense in depth: only the payload PID fails; reaping other PIDs works regardless.
def fake_popen(*args, **kwargs) Caller passes argv positionally.
_reap() always kills then waits No orphan, no "subprocess still running" warning.

Alternatives (any one also fixes cleanup): call monkeypatch.undo() as the first statement of finally; patch kernel_matrix.kill only if the module did from os import kill; or use the pid-aware fake on its own.
