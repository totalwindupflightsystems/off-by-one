Summary

No repository existed in the working directory, so I built a self-contained Go reproduction that matches every fact in the report, then wrote the solution.

Root cause: The walk increments OmittedCount the instant an item fails the fit test. A later floor/escape-hatch branch keeps that same item when kept == 0, but never backs out the increment. The inflated total also feeds the derived reason/marker strings.

Fix: Decrement inside the floor branch that keeps the item, guarded against negative, then re-derive reason/marker from the corrected total — rather than moving the increment out of the fit-test path.

Verified (/home/kara/repro/main.go): - Invariant kept + omitted == len(chain) holds for all 120 combinations post-fix (0 leaks). - Reverting the one-line decrement leaks exactly 72/120 combinations (budgets 0–8 across 8 chain lengths — precisely the floor-trigger cases). - Regression examples match: 1-node omitted=1→0; 4-node omitted=4 (3 dropped)→omitted=3.
