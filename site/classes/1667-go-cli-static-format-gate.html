What I did

The working directory had no repo, so I reconstructed the failure mode in a scratch module, then implemented and empirically verified the fix.

Root cause: "gofmt-clean" has no executable definition in a typical Go repo. go build, go vet, and go test are all indifferent to formatting, so rot accumulates behind green checks.

Fix: one in-repo package internal/fmtcheck is the single check-only definition; three surfaces invoke it with the byte-identical command: - TestGofmt (no testing.Short() skip) → caught by plain go test ./... - Makefile target → go test -count=1 -run TestGofmt ./internal/fmtcheck - CI step → same exact string, verified identical with diff

Verified against Go 1.26.0
