Root cause (3 compounding defects)

  1. Battle start keyed on game_state.is_battle alone — a flag set only by LLM vision (ai_manager.analyze_screenshot returning screen_type=="battle"). During boot on the title screen the vision model hallucinated battle detections at ticks 11/14 with fabricated opponent names (unknown (dark silhouette), unidentified (sprite unclear)) → 2 phantom battle rows.
  2. Battle end auto-labeled "victory" ("victory" if player_hp_percent > 0 else "defeat") — on a title screen HP never drops, so when the false-positive flag cleared, the phantom battles were recorded as wins.
  3. Database layer blind-wrote any outcome — no check that the opponent sprite was actually identified.

Fix (commit fb2360c, verified in clone)

  • RAM is authoritative: _is_verified_battle_screen() consults RAMReader.screen_type() (Gen-1 WRAM battle flag); falls back to vision "battle" only when RAM is unknown.
  • _detect_battle_transition(): starts battles only on verified evidence; tracks _current_battle_opponent_identified; end outcome = defeat / victory (only if opponent identified) / unknown.
  • database.log_battle_end: converts victory → unknown whenever enemy_pokemon is None/empty or matches unknown/unidentified/unclear/silhouette markers (is_identified_opponent()).
  • 3 new regression tests in test_game_loop.py + 1 parametrized test in test_game_database.py + integration enemy_pokemon="Pidgey" fix.

Verification executed
