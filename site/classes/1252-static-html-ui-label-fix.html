Fix: Misleading "KV Cache %" label in static HTML estimator (CE-007)

Root Cause Analysis

In cluster-estimator.html (line ~1769), the estimator computed a cache-size percentage using the KV-cache multiplier directly:

kvPercent = (kvCacheMultiplier * 100).toFixed(1) + '%';

…and assigned it to an element labeled "KV waste %" (or similar wording containing "waste").

The kvCacheMultiplier is a size multiplier relative to the unquantized / raw model size (raw = 1.00, vLLM = 1.15, TGI = 1.20, block size 32 = 1.08). Displaying 115.0% under a "waste" label therefore reads as "115% waste", which is conceptually wrong — it is a size ratio, not a waste metric.

Additionally, docs/FORMULAS.md section 15.1 contained a half-finished self-correction ("Wait, actually...") that never resolved into a final display contract.

Root Cause

  1. Wrong label & semantics – the percentage shown is the KV cache size relative to raw KV size, but the label said "KV waste %", implying KV memory wasted.
  2. Missing baseline/relative display – the raw baseline (0%) was not shown, and non-baseline models (vLLM +15%, TGI +20%) were shown as bare 115%/120% without explicitly stating they were relative to baseline.
  3. FORMULAS.md unresolved self-correction – section 15.1 ended in a note saying "wait, actually…" and never restated the final intended display rule.

The Fix

1. cluster-estimator.html — corrected label & value display

Change the estimator line so that it:

  • uses a proper label: KV size vs raw % (no "waste" wording);
  • displays the raw KV multiplier as the baseline explicitly: 0% (baseline);
  • displays every model as a delta vs baseline:
  • raw block size → 0%
  • vLLM (multiplier 1.15) → +15%
  • TGI (multiplier 1.20) → +20%

From (around line 1769) the generated display code becomes:

// --- BEFORE (broken) ---
kvPct.textContent = (kvMultiplier * 100).toFixed(0) + '%';          // label: 'KV waste %'

// --- AFTER (fixed) ---
const kvPct = document.getElementById('kv-pct');
const basePctTxt = (kvMultiplier === 1.0) ? '0% (baseline)'
  : ((kvMultiplier - 1) * 100).toFixed(0) + '%';
kvPct.textContent = `KV cache vs raw: ${basePctTxt}`;

If the surrounding code derives kvMultiplier from vLLMRatio = 1.15, TGIRatio = 1.20, blockSizeRatio = 1.08, and rawMultiplier = 1.30, keep those variable names intact; only replace the label string and the formatting.

2. docs/FORMULAS.md — final display contract

Replace the unresolved "Wait, actually…" trailer in section 15.1 with the final display contract:

15.1 KV-cache size
display = (kvMultiplier / rawKvMultiplier) % of KV size. Only raw multiplier is shown as 0% (baseline).
All deviations: vLLM +15%, TGI +20%, block-32 +8%.

(Exact markdown representation should use the % sign consistently.)
