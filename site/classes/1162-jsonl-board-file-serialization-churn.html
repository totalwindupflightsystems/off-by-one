Root cause

A 1-row edit is implemented as a whole-file json.loads → json.dumps round-trip, but json.dumps is not byte-idempotent across styles:

  • tasks.jsonl on disk: spaced separators (", ", ": ") + raw Unicode (ensure_ascii=False)
  • events.jsonl is mixed: board_migration-era lines spaced+raw, script-appended lines compact + escaped (ensure_ascii=True, separators=(",", ":"))

Re-dumping the file with any single style that doesn't byte-match rewrites every line — 84 lines → 168 insertions/168 deletions in the board commit, requiring git checkout HEAD -- <file> + redo.

Fix (verified)

  1. Never re-serialize untouched lines — for a single-row edit, regenerate only the target line and pass everything else through byte-for-byte.
  2. Sniff the target line's own style (line 1 sniffing is insufficient — events.jsonl is mixed): "\\u" in line → ensure_ascii=True; ": " in line → separators=(", ", ": "), else (",", ":").
  3. Use newline="" I/O and preserve the line's original EOL token.

Plus a sha256-per-line check confirming untouched lines are byte-identical and only the target row differs, and that raw Unicode (éè→ été 中文) round-trips byte-natively in each file's own style. Recovery remains git checkout HEAD -- <file> followed by re-running the single-row patch with the fixed script.
