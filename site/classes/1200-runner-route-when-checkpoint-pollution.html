GAP-068: when() predicate pollutes the route node's own checkpoint slot

  • Environment: hermes-dagger Go DAG engine, QJS sandbox, SQLite checkpoints, HTTP API, TS-DSL surface (dag.node / dag.route)
  • Affected files: src/runner/runner.go, src/runner/tsrun.go, src/runner/gap068_test.go
  • Fix commit: a35b36b

Symptom

A TS-DSL dag.route node with a when() predicate routes its boolean verdict ('true'/'false') to the winning branch target instead of the routing node's payload. Error seen at the branch target: prev='true'; the stored route checkpoint contains verdict='true'. Expected (matching .d5s): the winner receives the routing node's payload (pass-through of the dep payload).

Root-cause analysis

  1. evalWhenJS evaluates the predicate under the route node's own wire id — in src/runner/runner.go:

go verdict, err := executeMCP(ctx, js, node.ID) // BUG: wire id = node.ID

executeMCP is a server-side QJS execution bound to a wire id; every run persists a checkpoint (SQLite) keyed by that id, with output = stringified JS result — for when() that is "true"/"false". So the verdict lands in the checkpoint slot belonging to the route node itself.

  1. NodesToPipeline gives the route node a pass-through body — in src/runner/tsrun.go, opts["js"] = "prev". The step executor consults checkpointOutput(...) first (GAP-048/GAP-067 replay logic): if a run already exists for this wire id, the stored output is replayed and the body is never executed.

  2. The collision: evalWhenJS writes verdict='true' under node.ID → the route step's own checkpoint consult hits → replays 'true' instead of running prev against the dep payload → branch targets receive the boolean; route checkpoint stores verdict='true'.

Step Wire id What lands in node.ID slot
evalWhenJS node.ID verdict='true' ← pollutes the route's own slot
route body (prev) consult node.ID hit → replays 'true'; body never runs

The fix

Run the when() evaluation under a distinct wire id — node.ID + "#when" — so it can never collide with the route's own slot; the route node then executes its pass-through against the dep payload.

--- a/src/runner/runner.go
+++ b/src/runner/runner.go
@@ -evalWhenJS
-   verdict, err := executeMCP(ctx, js, node.ID)
+   // Distinct wire id (GAP-068): the sandbox persists a checkpoint for this
+   // id, which would otherwise be replayed by the route node's own consult.
+   verdict, err := executeMCP(ctx, js, node.ID+"#when")

#when is an attribute-style id no pipeline step addresses, so no checkpointOutput(...) consult sees the verdict as its own output; any collision-free suffix works. NodesToPipeline and routing-decision logic are unchanged.

Regression test — src/runner/gap068_test.go

Asserts (1) winner receives the payload object, (2) when-eval runs under route#when exactly once, (3) route executes exactly once under its own id. Full test code is in the doc (/tmp/gap68-solution.md) — builds the dep→route(when) DAG, runs the pipeline, checks the branch output parses as the payload and the two run counters equal 1. It fails with the fix reverted (route output 'true'; counters 0/0 since the body never runs).
