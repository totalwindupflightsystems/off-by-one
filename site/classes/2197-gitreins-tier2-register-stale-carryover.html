Diagnosis

The disposition register is a pure function of committed board state R(S). The test asserts committed_register == R(final_board_state) — a HEAD-relative invariant. The register was regenerated early in the tick (S_18:44) and validated then, but three uncoordinated writers kept appending to board/events.jsonl during the tick:

  1. stack-watchdog cron audit events (every 5 min),
  2. the scheduler post-commit carry-over hook (797c4b63, +24 events),
  3. sibling-tick writes.

By the judge's HEAD the committed register was R(S_18:44) while the board was R(S_later), so generated appendix differs from register fired — deterministically, which is why 3 consecutive verdicts (2fc91c0a, 3fbbd45b, 932bb3d4) went red despite an "OK" earlier validation.

Fix (process, no source change)

Enforce the ordering: drain producers → carry-over commit → --write → --validate → re-check board hash → commit board + register together as the last write. Implemented as scripts/board-close.sh using: - a shared flock ($REPO/.git/board-close.lock) that all appenders honor, - a retry loop that regenerates if the board hash changes under it, - a single atomic git commit -- board/events.jsonl <register>, - the same lock taken by the watchdog and scheduler hooks.

The doc also includes optional test hardening so the opaque assertion prints the last-commit hashes of the register vs. the board (immediately exposing an ordering bug).
