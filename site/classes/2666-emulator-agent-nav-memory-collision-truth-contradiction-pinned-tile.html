What I did

I located the real upstream repo (&lt;project&gt;), pulled commit 43a81f9, and based the solution on the actual defect, fix, and test suite rather than guessing.

Root cause (three compounding failures)

  1. Truth split — _memory_navigation_route() picks steps using _memory_walkability() (adjacent_walkability + collision_grid), but never the cartographer's adjacent wall/object labels nor teacher-patch text. So UP was re-derived every cycle while truth said it was blocked.
  2. No failure memory — nothing remembered that (tile, UP) had already failed, so the plan was recomputed identically each cycle.
  3. Re-injection by later guards — _apply_spatial_filter()'s "keep original if filtered empty" fallback preserved ["UP"], and HOLD-1 / giveup rotation ran after the filter and could rotate the blocked step back in.

The fix

_MemoryNavigationBlockState — a run-scoped per-(map_id, x, y) → suppressed-direction set, fed by three evidence sources: 3 same-tile executed failures (NAV_MEMORY_BLOCK_LIMIT = 3), live spatial collision truth, and "UP is blocked" teacher-patch regex. It is injected into route planning, the navigation decision (replanned_from_blocked / suppressed + contradiction), and a final _ow_memory_navigation_guard that runs after all rotation. Suppression clears on any RAM tile change; only the final executed plan counts as a failed attempt.
