Summary

Root cause. The update script parsed tasks.jsonl rows into dicts and mutated the TS-GAP-040 dict in memory (state → blocked, assignee → kara, priority → 5), but rebuilt the output from the original raw line strings — only the NEVER-DONE regex branch re-serialized its row. Since that row didn't match, the stale line was written; the script's post-write re-parse assert then fired after the write, leaving a partial/corrupt board.jsonl and an unverified tail event in events.jsonl.

The fix (in the line-rebuild loop): - Track mutated_ids as the single source of truth; branch on obj["id"] in mutated_ids and emit json.dumps(modified_dict) for every mutated row (not a regex over the raw line). - Keep pre-write asserts (fail before touching the file) and post-write re-parse asserts (validate on-disk bytes).

Partial-write recovery (verified end-to-end): ① assert events.jsonl tail ids are contiguous, ② truncate back to the last verified id from git show HEAD:events.jsonl, ③ restore board.jsonl header fields (ticks_total/last_commit/last_tick) from git show HEAD:board.jsonl, ④ re-run the fixed script.

Verification output confirmed: buggy script writes the stale needs-work row and crashes; the fixed script serializes blocked/kara/priority 5; after the simulated crash + recovery, board.jsonl has the correct header (ticks_total=2, last_commit=abc123, last_tick=2) and events.jsonl exactly matches git HEAD — confirmed by an independent parser, not the script's own output.
