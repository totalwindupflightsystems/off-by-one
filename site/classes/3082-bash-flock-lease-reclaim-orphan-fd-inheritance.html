Done. The full diagnosis + verified fix is written to ~/SOLUTION.md, with the working artifacts in ~/.

Root causes (the real bugs to avoid)

  1. PID-only liveness is unsafe. PID recycling makes a dead holder look alive forever. Correct liveness requires (starttime from /proc/<pid>/stat field 22, fd target path/inode) together.
  2. Check-then-act on a file is TOCTOU. "Read owner file, then create" lets two claimants both see "free." Mutual exclusion must be a single atomic kernel op: flock(2) on an fd.
  3. Forks need open-file-description inheritance. flock attaches to the open file description, so a forked keeper inherits the lock and the kernel releases it the instant the last fd closes — reclaim in tens of ms, no reaper.
  4. Reclaim means stale metadata, not a stolen lock. Once you win the flock, leftover metadata is provably orphaned → clean it and return 4.
  5. Busy-poll sleep causes a fork storm. A 200-way race starved the host; parking on flock -w's kernel wait queue fixed it.
  6. A racy release can delete a new holder's metadata (and leak its lock). Fix: only create/delete metadata while holding the flock.

Key implementation points in lease.sh

  • acquire: exec {fd}>lock; flock -n / flock -w 1, then fork a keeper subshell that inherits fd; parent can exit.
  • holder_is_live: /proc/<pid> + starttime + readlink /proc/<pid>/fd/<fd> (path, else inode).
  • Keeper publishes metadata atomically (tmp+mv) then blocks.
  • release verifies and kills only a genuinely live holder, then takes the flock itself before clearing metadata.
  • Exit codes: 0 ok, 3 timeout, 4 stale lease reclaimed.

Verification (all passing)

  • verify_lease.sh: reclaim after SIGKILL in ~46 ms with rc=4; unrelated-PID and matching-pid+start-but-wrong-fd both classified stale; inherited-fd lock survives parent exit and releases when the last fd closes; inspect reports "reclaimed":true for orphans.
  • race_lease.sh (200 simultaneous claimants, atomic mkdir critical section independent of the lease): success=200 overlap=0 timeout=0, repeated runs.
  • shellcheck lease.sh clean, bash -n OK.
