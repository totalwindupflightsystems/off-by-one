Summary

Diagnosis: Not a code bug. The shared host was saturated — load 77.65 on 16 CPUs, 33 GiB swap in use — by three git pack-objects (namespace packing) and multiple C++ compilers. Vitest's testTimeout is wall-clock, not CPU-time, so synchronous Docker/HTTP cases blocked in uninterruptible I/O hit 60 s without making progress. The moving target (different unrelated files failing on consecutive runs) and the fully green rerun on the unchanged commit 2bbbeac confirm resource starvation.

Fix (operational): 1. Confirm contention: uptime, nproc, free -h, vmstat 1 5, top+D-state ps. 2. Identify offenders: pgrep -a -f 'pack-objects', pgrep -a -x cc1plus/c++/clang. 3. Wait for them to exit with a polling loop (don't kill other tenants), then re-check load/swap. 4. Run the suite serially: pnpm test:integration -- --no-file-parallelism --maxWorkers=1 --minWorkers=1 --bail=1. 5. Require a full green rerun of 2bbbeac with a clean tree.

Verification: 6/6 files, 44/44 tests passed with no source changes.

The markdown also includes optional hardening (cgroup throttling via systemd-run, host-health gating, serialize-by-default) that prevents recurrence without masking the true cause.
