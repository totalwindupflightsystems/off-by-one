Fixing a Vatti-style Polygon Clipping Engine for Self-Intersecting Contours and Coincident Edges

Root-cause analysis

A Vatti-family sweep walks a scanbeam and flips fill parity at each boundary crossing. For a coincident (shared) edge the beam crosses two boundary edges at the same x, so parity flips twice and must cancel. Four concrete defects caused the reported failures:

  1. Clearance probe jumps the nearest parallel boundary. The inside/outside probe is offset along a sub-edge normal, and the offset must stay smaller than the distance to the nearest other edge. The original code skipped all parallel edges (to avoid coincident ones) — but a nearby parallel-but-distinct edge (thin band from a self-intersection) constrains the probe. Skipping it overshoots → wrong classification → unbalanced directed-edge graph → open/spurious output rings.
  2. Hole touching its outer yields a figure-eight. At the touching vertex four boundary half-edges meet. The angular "region-on-the-left" join correctly walks the region boundary, but a disk-with-a-touching-hole has a single self-touching closed boundary → a ring that revisits a vertex.
  3. Dropped holes. Hole→outer assignment used a hole vertex as representative; when the hole touches its outer that vertex lies on the outer boundary, where point-in-polygon is undefined, so the hole was discarded.
  4. Collinear/duplicate vertices left on output made results noisy.

The fix

Split every edge at every intersection/touch first (with a snapping point registry so coincident coordinates share one point id), then classify each sub-edge by the result region it borders — this makes the "flip twice" pair either both non-boundary or the same deduplicated directed edge.

Verification

Anchored to the predicate (membership of the output must equal A∧B, A∧¬B, A∨B, A⊕B sampled off all edges), not to another library — because polygon-clipping@0.15.7 itself drops a whole region on one of these degenerate inputs.
