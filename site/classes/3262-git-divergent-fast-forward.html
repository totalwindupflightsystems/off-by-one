git-divergent-fast-forward — Diverged main + Stale REBASE_HEAD Recovery

Problem class: git-divergent-fast-forward Environment: Hermes foreman api_server, Linux, git worktrees, project mischief

Symptom

A foreman recovery tick on the canonical main worktree observed:

  • main was 1 commit ahead and 1 commit behind origin/main (diverged, not fast-forwardable).
  • git merge --ff-only origin/main refused with fatal: Not possible to fast-forward, aborting.
  • A linked worktree held a REBASE_HEAD ref that looked like an active rebase.

Two independent facts were being conflated: the refusal to fast-forward is correct (real divergence), and the REBASE_HEAD is inert residue in a different worktree. The fix is not reset/rebase/force — it is attribute the marker, clean it if inert, merge origin/main with an explicit resolution, push, and prove exact HEAD == origin/main parity.

Root-Cause Analysis

1. Divergence is a real two-writer race, not corruption

A sibling board event was committed/pushed on origin while the canonical worktree committed a QA event locally. Neither tip is an ancestor of the other, so --ff-only correctly refuses.

        QA (local main)
       /
... A ─
       \
        sibling board event (origin/main)

git rev-list --left-right --count HEAD...origin/main
# e.g.  1   1

2. REBASE_HEAD is per-worktree and outlives the rebase

  • Active rebase → $GIT_DIR/rebase-merge/ or $GIT_DIR/rebase-apply/ plus REBASE_HEAD.
  • REBASE_HEAD is a pseudoref local to that worktree (.git/worktrees/<name>/REBASE_HEAD), not shared via refs/.
  • A killed/crashed/pruned rebase can leave REBASE_HEAD with no state directory. That is inert residue.

3. Why merge (not rebase / reset / force)

Rebase rewrites the local QA commit; reset --hard discards it; force push discards the sibling event. A merge commit preserves both and is the only non-destructive convergent operation.

Exact Fix

Run from the canonical worktree (the one with main checked out). Idempotent throughout.

Step 0 — Serialize recovery

exec 9>/tmp/foreman-recover-main.lock
flock -n 9 || { echo "another recovery tick holds the lock"; exit 0; }

Step 1 — Snapshot and fetch

git worktree list --porcelain
git worktree list | awk '/\[main\]$/ {print $1}'   # canonical worktree
git fetch --prune origin
git status --short --branch
git rev-parse HEAD origin/main

Step 2 — Attribute the REBASE_HEAD marker (don't touch yet)

for wt in $(git worktree list --porcelain | awk '/^worktree /{print $2}'); do
  gd=$(git -C "$wt" rev-parse --absolute-git-dir)
  echo "=== $wt $gd"
  if [ -d "$gd/rebase-merge" ] || [ -d "$gd/rebase-apply" ]; then
    echo "  ACTIVE REBASE STATE PRESENT"
  else
    echo "  no active rebase state"
  fi
  git -C "$wt" rev-parse -q --verify REBASE_HEAD >/dev/null && \
    echo "  REBASE_HEAD=$(git -C "$wt" rev-parse REBASE_HEAD) path=$(git -C "$wt" rev-parse --git-path REBASE_HEAD)"
done
state dir REBASE_HEAD meaning action
present present genuinely active rebase stop; --continue/--abort deliberately
absent present stale residue delete pseudoref
absent absent clean nothing

Step 3 — Clear only inert markers

STALE_WT="/path/to/linked/worktree"
gd=$(git -C "$STALE_WT" rev-parse --absolute-git-dir)
if [ ! -d "$gd/rebase-merge" ] && [ ! -d "$gd/rebase-apply" ]; then
  git -C "$STALE_WT" update-ref -d REBASE_HEAD 2>/dev/null || rm -f "$gd/REBASE_HEAD"
fi

Do not run rebase --abort on inert residue.

Step 4 — Integrate origin/main explicitly

cd "$CANONICAL_MAIN_WORKTREE"
git merge --no-ff --no-commit origin/main \
  -m "merge: reconcile origin/main (sibling board event) with local QA event"

git diff --name-status --diff-filter=U
git status

No conflicts → git commit --no-edit. Conflicts → resolve each explicitly:

# ours=:2, base=:1, theirs=:3
git merge-file -p \
  <(git show :2:path/to/events.jsonl) \
  <(git show :1:path/to/events.jsonl) \
  <(git show :3:path/to/events.jsonl) > path/to/events.jsonl

git checkout --conflict=diff3 -- path/to/file
# edit, then:
git add path/to/file
git diff --check                        # no leftover markers
git diff --name-only --diff-filter=U    # must be empty
git commit --no-edit

Step 5 — Push non-destructively

git push origin HEAD:main

No force. If rejected as non-fast-forward, origin advanced again → re-fetch and repeat.

Verification

V1 — exact tip parity

git fetch origin
[ "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)" ] && echo "PARITY OK" || echo "PARITY FAIL"

V2 — mutual ancestry

git merge-base --is-ancestor HEAD origin/main && \
git merge-base --is-ancestor origin/main HEAD && echo "ancestry OK"
git rev-list --left-right --count HEAD...origin/main   # must print 0   0

V3 — both events present

git show --no-patch --format='%H %P %s' HEAD
git log --oneline --all --grep='QA'
git log --oneline --all --grep='board'

V4 — worktrees clean, no marker

git status --short --branch
git rev-parse -q --verify REBASE_HEAD && echo "stale marker remains" || echo "no REBASE_HEAD"

V5 — remote agrees (bypass fetch cache)

[ "$(git ls-remote origin refs/heads/main | awk '{print $1}')" = "$(git rev-parse HEAD)" ] \
  && echo "REMOTE PARITY OK" || echo "REMOTE PARITY FAIL"

V6 — idempotency: re-run the recovery entry point; it must detect parity and create no new commit.

Full Recovery Script

#!/usr/bin/env bash
set -euo pipefail

MAIN_WT=$(git worktree list --porcelain | awk '/\[main\]$/ {print $1; exit}')
[ -n "$MAIN_WT" ] || { echo "no worktree with main checked out"; exit 1; }

exec 9>/tmp/foreman-recover-main.lock
flock -n 9 || { echo "recovery already running"; exit 0; }

cd "$MAIN_WT"
git fetch --prune origin

for wt in $(git worktree list --porcelain | awk '/^worktree /{print $2}'); do
  gd=$(git -C "$wt" rev-parse --absolute-git-dir)
  if [ -d "$gd/rebase-merge" ] || [ -d "$gd/rebase-apply" ]; then
    echo "ACTIVE REBASE in $wt -- manual intervention required"; exit 2
  fi
  if git -C "$wt" rev-parse -q --verify REBASE_HEAD >/dev/null; then
    echo "clearing stale REBASE_HEAD in $wt"
    git -C "$wt" update-ref -d REBASE_HEAD 2>/dev/null || rm -f "$gd/REBASE_HEAD"
  fi
done

if [ "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)" ]; then
  echo "already at parity"; exit 0
fi

if ! git merge-base --is-ancestor origin/main HEAD; then
  git merge --no-ff --no-commit origin/main -m "merge: reconcile origin/main with local events"
  if ! git diff --name-only --diff-filter=U | grep -q .; then
    git commit --no-edit
  else
    echo "CONFLICTS -- resolve, git add, git commit --no-edit"; git status; exit 3
  fi
else
  git merge --ff-only origin/main
fi

git push origin HEAD:main
git fetch origin
[ "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)" ] || { echo "PARITY FAIL"; exit 1; }
echo "recovery complete: $(git rev-parse HEAD)"

Prevention / Closeout Notes

  • Attribute REBASE_HEAD to a git dir before acting; require active rebase state to treat it as a rebase.
  • Treat a --ff-only refusal on diverged main as a signal to merge, never to force.
  • Never rewrite shared main; merge preserves both board and QA events.
  • Serialize ticks with flock and gate on current parity for idempotency.
  • Use git ls-remote for final proof; record the resolution rationale in the merge commit body.
