go-ci-windows-cross-platform

Answer

1. Makefile: CGO_ENABLED := 1 clobbers the environment

:= makes CGO_ENABLED unconditionally override the env var, so GOOS=linux GOARCH=arm64 go build tries to assemble runtime/cgo with the host x86 gcc and fails. The built commands are pure Go (sqlite lives only in pkg/repository, which no built cmd/ imports), so CGO can be off.

# before
CGO_ENABLED:=1

# after — only set a default when the caller didn't
CGO_ENABLED ?= 1

And pin it off in the workflow so no step re-enables it:

# .github/workflows/ci.yml
jobs:
  build:
    runs-on: ubuntu-latest
    env:
      CGO_ENABLED: "0"   # binaries are pure Go; prevents cross-gcc requirement
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version-file: go.mod }
      - run: make build
      - run: GOOS=linux GOARCH=arm64 make build     # cross-arch now works
      - run: GOOS=windows GOARCH=amd64 make build

2. Windows keychain: restore the real Credential Manager impl, tag the stub

The purge-regression restore deleted keychain_windows.go, leaving only a build-tag-less stub that compiled on all platforms and returned ErrSecretServiceNotAvailable everywhere. Restore from history, constrain the stub, and guard empty blobs.

# locate the deletion and restore the real impl from the commit before it
git log --diff-filter=D --oneline -- pkg/keyring/keychain_windows.go
git checkout <deleting-commit>^ -- pkg/keyring/keychain_windows.go

Stub — now Windows-only builds the real impl, every other OS gets the stub:

//go:build !windows
// +build !windows

package keyring

import "errors"

// ErrSecretServiceNotAvailable is returned on platforms without a secret service.
var ErrSecretServiceNotAvailable = errors.New("keychain: secret service not available")

// Get returns ErrSecretServiceNotAvailable on non-Windows platforms.
func Get(name string) ([]byte, error) { return nil, ErrSecretServiceNotAvailable }

Restored Windows impl with the empty-blob nil guard (a zero-length stored blob must return (nil, nil) — a successful empty read — not be conflated with not-found):

//go:build windows
// +build windows

package keyring

import "unsafe"

// Get reads a generic credential from the Windows Credential Manager.
// An empty credential blob is a valid stored value, distinct from
// "credential not found" (which surfaces as a read error).
func Get(name string) ([]byte, error) {
    cred, err := credRead(name)
    if err != nil {
        return nil, err
    }
    defer credFree(cred)

    // Empty-blob nil guard: size==0 is a successful empty read, not an error.
    if cred.CredentialBlobSize == 0 {
        return nil, nil
    }
    return unsafe.Slice((*byte)(cred.CredentialBlob), cred.CredentialBlobSize), nil
}

3. isProcessRunning: os.FindProcess + Signal(0) never works on Windows

Signal(0) returns ErrProcessDone/os: process already finished semantics that are unreliable on Windows. Split per platform; Windows uses OpenProcess + WaitForSingleObject so a racing process exit is disambiguated from "never existed".

// proc/process_unix.go
//go:build !windows

package proc

import (
    "os"
    "syscall"
)

// isProcessRunning reports whether the PID exists (Unix: signal 0 probe).
func isProcessRunning(pid int) bool {
    p, err := os.FindProcess(pid)
    if err != nil {
        return false
    }
    return p.Signal(syscall.Signal(0)) == nil
}

// proc/process_windows.go
//go:build windows

package proc

import "syscall"

var (
    kernel32            = syscall.NewLazyDLL("kernel32.dll")
    openProcess         = kernel32.NewProc("OpenProcess")
    closeHandle         = kernel32.NewProc("CloseHandle")
    waitForSingleObject = kernel32.NewProc("WaitForSingleObject")
)

const (
    processQueryLimitedInformation = 0x1000
    processSync                    = 0x00100000 // allow wait on the handle
    waitTimeout                    = 0x00000102 // WAIT_TIMEOUT
)

// isProcessRunning reports whether the PID names a live process.
// OpenProcess with SYNCHRONIZE lets WaitForSingleObject tell "still running"
// (WAIT_TIMEOUT) apart from "exited since we opened it" (WAIT_OBJECT_0).
func isProcessRunning(pid int) bool {
    if pid <= 0 {
        return false
    }
    h, _, _ := openProcess.Call(uintptr(processQueryLimitedInformation|processSync), 0, uintptr(pid))
    if h == 0 {
        return false // ERROR_INVALID_PARAMETER => no such process
    }
    defer closeHandle.Call(h)
    rc, _, _ := waitForSingleObject.Call(h, 0)
    return rc == waitTimeout
}

4. Coarse Windows clock (~15.6 ms tick): zero lockout + boundary equality

time.Since() can be exactly 0 after a real pause, and two consecutive time.Now() calls can be equal — so "elapsed > duration" tests and strict After() comparisons misbehave. Fix: treat duration <= 0 as "never locked", and compare the boundary with >= semantics.

type Lockout struct {
    duration   time.Duration
    lockedUntil time.Time
}

// locked reports whether a lockout is currently active.
func (l *Lockout) locked(now time.Time) bool {
    // Zero/negative duration short-circuits: no lockout. This also avoids the
    // coarse-clock artifact where time.Since(lastFailure)==0 at small deltas.
    if l.duration <= 0 {
        return false
    }
    if l.lockedUntil.IsZero() {
        return false
    }
    // Coarse clock can make now == lockedUntil exactly at the boundary;
    // !Before means ">= " so the boundary tick still counts as locked.
    return !l.lockedUntil.Before(now)
}

5. Connection-refused text differs on Windows

Unix reports dial tcp ...: connection refused; Windows reports connectex: No connection could be made because the target machine actively refused it. Normalize with a dual-path matcher used by both code and tests.

func isConnectionRefused(err error) bool {
    if err == nil {
        return false
    }
    msg := strings.ToLower(err.Error())
    return strings.Contains(msg, "connection refused") || strings.Contains(msg, "actively refused")
}

6. upload-sarif needs actions: read

github/codeql-action/upload-sarif@v3 calls the workflow-runs API; without actions: read it 403s on private repos.

permissions:
  contents: read
  actions: read         # required by upload-sarif workflow-runs API
  security-events: write

Pattern fix: verify the run ON the claiming commit, surface masked steps

The 5 "CI-fix" commits stayed red because (a) the run was checked on the branch tip or a stale SHA rather than the commit that claimed the fix, and (b) step summaries masked later failing steps. Enforce:

# check the run for the *exact* commit that claims the fix
gh run list --commit <FIX_SHA> --json databaseId,status,conclusion
gh run view <id> --log-failed            # never trust only the job summary

and gate merges on conclusion == success for the run at the merge commit — a green summary with a masked red step no longer passes. Set ACTIONS_STEP_DEBUG: true on the failing workflow to un-mask step logs while iterating.
