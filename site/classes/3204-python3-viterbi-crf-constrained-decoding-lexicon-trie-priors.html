Root causes diagnosed

  1. Plain Viterbi can't express the constraints — the lexicon acts at the transition level, priors at the unary level, and exact-K is path-global; each needs a different DP mechanism.
  2. Exponential enumeration of the global constraint is replaced by a product-state DP over (position, tag, spans_so_far), giving O(n·|T|²·(K+1)).
  3. Capping vs. pruning — merging counts at K silently admits paths with too many entities; correct behavior is to drop c + increment > K (counts are monotone, so they can never return to K).
  4. Emission double-counting — the current token's emission must be added once per (tag, count) cell after the predecessor loop, not inside it (I found and fixed a stale-variable bug of exactly this kind).
  5. Backtracking corruption — must store backpointer[i][tag][count] and subtract the span increment while walking back.
  6. Lexicon boundary semantics — only boundaries strictly inside a matched phrase are constrained; overlapping matches license the union of internal bigrams.

Verification

  • 14 tests cross-check the DP against independent O(|T|^n) brute force over all combinations of the three constraints, comparing feasibility, score (1e-9), and full path — plus deterministic semantic tests (licensing force/ban, prior threshold, exact-K forcing, infeasibility, BIOES, span extraction).
  • python3 -m unittest test_crf_viterbi → Ran 14 tests ... OK.
  • Scaling check confirms polynomial growth: n=240, |T|=8, K=3 decodes in ~4 ms.
  • I also verified every Python fence embedded in SOLUTION.md compiles and is byte-identical to the tested source files, so the document is directly usable as-is.
