Stale test server squatting a fixed port misleads endpoint probes

Problem class: stale-test-server-squatting-port-misleads-endpoint-probes Environment: hermes foreman tick, shared host, background-started Go dev servers (helios api --port 18099)

1. Root cause

A fixed dev port is a single global resource, but the foreman treats it as if the process it just launched owns it. Four independent failures line up:

  1. Orphaned background server. A worker starts helios api --port 18099 & and is then killed (timeout / SIGKILL / task cancellation). The backgrounded child is reparented to init and keeps running — it never received SIGTERM. It continues holding the listening socket and serving the pre-fix code from its (already-unlinked) binary inode.
  2. Rebuild overwrites the path, not the process. go build -o helios writes a new inode and renames it over the old path. Running processes keep executing the old inode (/proc/<pid>/exe → /path/helios (deleted)), so the "new" binary is only new on disk.
  3. The new server exits silently. On net.Listen("tcp", ":18099") Go returns EADDRINUSE; the process logs bind: address already in use and exits non-zero. Because the foreman launched it with &, it never checks $!, the exit status, or the freshly written log — so it proceeds as if startup succeeded.
  4. The probe validates status, not identity. curl hits whatever is listening on :18099, which is the old pid, and gets pre-fix behaviour (503). The fix looks broken when it is actually deployed correctly.
worker A: helios api --port 18099 &   ──► pid 291486 (pre-fix inode) ─┐
        worker killed (SIGKILL)                                        │  holds :18099
foreman: rebuild → helios (new inode)                                  │
         helios api --port 18099 &  ──► bind: address already in use ──┘  exits 1, ignored
foreman: curl :18099/api/thing ──► 503   (answered by pid 291486)

Do not "fix" this with SO_REUSEPORT. Go already sets SO_REUSEADDR, which is why the second bind fails cleanly. SO_REUSEPORT would let both inodes bind the same port and the kernel would load-balance requests between old and new — turning a deterministic 503 into an intermittent, non-reproducible one.

Also note: the pid in the error (291486) is a snapshot. By the time you react, it may have exited or been reused. Re-enumerate; never kill a pid from a log line.

2. The fix

Three layers, in order. The launcher fix is the load-bearing one.

2a. Server side (Go) — fail fast, be identifiable, release the port

Make the process tell you it failed, and make it possible to prove which build is serving.

// build identity injected by the linker
var Build = "dev" // go build -ldflags "-X main.Build=$(git rev-parse --short HEAD)"

func runAPI(port int) error {
    addr := fmt.Sprintf(":%d", port)

    // Bind BEFORE writing a pidfile / daemonising / serving.
    ln, err := net.Listen("tcp", addr)
    if err != nil {
        return fmt.Errorf("helios api: cannot bind %s: %w", addr, err)
    }

    // Graceful shutdown so `kill` releases the port promptly.
    ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
    defer stop()

    mux := http.NewServeMux()
    mux.HandleFunc("/version", func(w http.ResponseWriter, _ *http.Request) {
        fmt.Fprintln(w, Build)
    })
    // ... existing routes ...

    srv := &http.Server{Handler: mux}
    go func() { <-ctx.Done(); _ = srv.Shutdown(context.Background()) }()

    log.Printf("helios api: build=%s listening on %s pid=%d", Build, addr, os.Getpid())
    return srv.Serve(ln)
}

func main() {
    // ...
    if err := runAPI(port); err != nil {
        log.Printf("helios api: %v", err)
        os.Exit(1) // never exit 0 on bind failure
    }
}

Key properties: exit non-zero on bind failure, log the bind error to a known file, expose /version, and shut down on SIGTERM so a kill actually frees the port.

Build with an identity:

go build -ldflags "-X main.Build=$(git rev-parse --short HEAD)" -o helios ./cmd/helios

2b. Launcher/foreman side — enumerate, kill, wait, then start

This is the exact routine from the fix context (pgrep -af, read the NEW log for the bind error, kill stale instances), hardened for a shared host:

  • match argv exactly (argv[1] == "api" and --port == PORT) so it can never match the launcher shell or this script;
  • exclude our own ancestry;
  • kill → kill -9 only pids we enumerated, never fuser -k / pkill -f "${PORT}" (those catch other users' processes and yourself);
  • wait until the port actually stops accepting before relaunching;
  • treat address already in use in the new log, or an early child exit, as fatal;
  • assert the served /version equals the build you just made.
#!/usr/bin/env bash
# foreman-restart.sh <binary> <port> <endpoint> [expect_status] [expect_build]
set -euo pipefail
BIN=$1; PORT=$2; ENDPOINT=$3; EXPECT_STATUS=${4:-200}; EXPECT_BUILD=${5:-}
BASE="http://<ip-address>:${PORT}"
LOG="/tmp/foreman-$(basename "$BIN")-${PORT}.log"
NEWPID=""
log(){ printf '[foreman] %s\n' "$*" >&2; }

list_stale() {                       # exact argv match, self/ancestry excluded
  local pid p argv portarg i binbase
  binbase=$(basename -- "$BIN"); declare -A skip=()
  p=$$; while [ -n "$p" ] && [ "$p" != 0 ] && [ "$p" != 1 ]; do
    skip[$p]=1; p=$(awk '{print $4}' "/proc/$p/stat" 2>/dev/null) || break; done
  [ -n "${NEWPID:-}" ] && skip[$NEWPID]=1
  for pid in /proc/[0-9]*; do
    pid=${pid#/proc/}; [ -n "${skip[$pid]:-}" ] && continue
    argv=(); while IFS= read -r -d '' a; do argv+=("$a"); done < "/proc/$pid/cmdline" 2>/dev/null || continue
    [ "${#argv[@]}" -ge 2 ] || continue
    [ "${argv[1]}" = "api" ] || continue
    [ "$(basename -- "${argv[0]}")" = "$binbase" ] || continue
    portarg=""
    for ((i=2; i<${#argv[@]}; i++)); do
      case "${argv[i]}" in --port) portarg=${argv[i+1]:-} ;; --port=*) portarg=${argv[i]#--port=} ;; esac
    done
    [ "$portarg" = "$PORT" ] && echo "$pid"
  done
}

port_free() {
  local i; for i in $(seq 1 100); do
    (exec 3<>"/dev/tcp/<ip-address>/$PORT") 2>/dev/null || return 0
    exec 3>&- 2>/dev/null || true; sleep 0.1; done; return 1
}

mapfile -t STALE < <(list_stale)
[ "${#STALE[@]}" -gt 0 ] && { log "killing stale pids: ${STALE[*]}";
  kill "${STALE[@]}" 2>/dev/null || true; sleep 0.3; kill -9 "${STALE[@]}" 2>/dev/null || true; }
port_free || { log "FATAL: :$PORT still occupied"; exit 1; }

: >"$LOG"; "$BIN" api --port "$PORT" >"$LOG" 2>&1 & NEWPID=$!
for _ in $(seq 1 100); do
  grep -q 'address already in use' "$LOG" && { log "FATAL: bind error:"; cat "$LOG" >&2; exit 1; }
  kill -0 "$NEWPID" 2>/dev/null || { log "FATAL: exited before ready:"; cat "$LOG" >&2; exit 1; }
  curl -sf "$BASE/version" >/dev/null 2>&1 && break; sleep 0.1
done

served=$(curl -s "$BASE/version" || true)
code=$(curl -s -o /tmp/fb.$$ -w '%{http_code}' "$BASE$ENDPOINT" || true)
log "probe $ENDPOINT -> HTTP $code (build: ${served:-<none>})"; cat /tmp/fb.$$ >&2; rm -f /tmp/fb.$$
[ "$code" = "$EXPECT_STATUS" ] || { log "FAIL: want HTTP $EXPECT_STATUS"; exit 1; }
[ -z "$EXPECT_BUILD" ] || [ "$served" = "$EXPECT_BUILD" ] || { log "FAIL: wrong build '$served'"; exit 1; }
log "OK: $ENDPOINT=$code build=$served (pid $NEWPID)"

Fast one-liner diagnostics when you only need to look:

# every instance of this binary + its argv
for p in $(pgrep -u "$(id -u)" -f -- "$BIN"); do
  printf '%s  %s\n' "$p" "$(tr '\0' ' ' < /proc/$p/cmdline)"; done
ss -ltnp 'sport = :18099'          # who owns the port (run as owner/root)
grep -i 'address already in use' /tmp/foreman-*.log

2c. Probe contract — status and identity

Only accept a probe if the listener is the build you just produced:

GET /version  →  must equal $EXPECT_BUILD
GET $ENDPOINT →  must equal $EXPECT_STATUS

A 200 alone is not proof: a stale post-fix-looking process, or the wrong service entirely, can also return 200.

3. Verification

Reproduced end-to-end in a sandbox with a minimal Go server whose /api/thing returns 503 in build pre-fix and 200 in build post-fix, and whose net.Listen failure logs address already in use and exits non-zero. Free test port 18078; the live host service on 18099 was left untouched.

Step 1 — stale worker's server owns the port:

stale pid=2842  log=... helios api: build=pre-fix listening on <ip-address>:18078 pid=2842
naive probe before fix: HTTP 503 body=build=pre-fix status=503 pid=2842

Step 2 — rebuild over the same path; the old process keeps the deleted inode:

rebuild done; old /proc/2842/exe -> /tmp/repro/hx (deleted)

Step 3 — naive background relaunch fails and is ignored (the reported bug):

... helios api: listen <ip-address>:18077: listen tcp <ip-address>:18077: bind: address already in use
is the new pid alive? -> NO - it exited non-zero already
curl /api/thing -> HTTP 503  body: build=pre-fix status=503 pid=2510

Step 4 — hardened foreman routine:

[foreman] enumerating stale instances of /tmp/repro/hx api --port 18078
[foreman] killing stale pids: 2842
[foreman] :18078 is free
[foreman] launched new pid 2926, log=/tmp/foreman-hx-18078.log
[foreman] probe /api/thing -> HTTP 200 (served build: post-fix)
build=post-fix status=200 pid=2926
[foreman] OK: /api/thing=200 build=post-fix (pid 2926)
foreman rc=0
stale pid still alive? no

Result: failure (503, pre-fix pid 2842 still serving) reproduced; after the fix, 503 → 200 with /version == post-fix and the stale pid gone. Two traps were confirmed and neutralized during testing:

  • a naive pgrep -af "$BIN" / pkill -f "$BIN" matched and killed the foreman shell itself (the binary path was in its own command line) — solved by requiring argv[1] == "api" and excluding ancestry;
  • after go build -o replaces the path, the stale pid's /proc/<pid>/exe reads /path (deleted), so an exe-path identity check misses it — solved by parsing argv and by asserting the served build instead.

Foreman acceptance checklist

  • [ ] Before probing: every helios api --port 18099 instance enumerated and terminated (scoped to user/binary/port; launcher and self excluded).
  • [ ] Confirmed :18099 refuses connections before the fresh server is started.
  • [ ] New server's log checked for address already in use; child liveness checked for ≥ readiness timeout.
  • [ ] Probe requires both the expected HTTP status and /version == $EXPECT_BUILD.
  • [ ] No SO_REUSEPORT, no pkill -f/fuser -k by port on the shared host.
