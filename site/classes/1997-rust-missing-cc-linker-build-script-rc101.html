Summary

Diagnosis (reproduced, not theorized): cargo build fails rc=101 because rustc links every binary — including build-script binaries — via the bare command cc. On a bare host cc is absent, so libc's build script never even runs, producing the misleading could not compile 'libc' (build script). Removing /usr/bin from PATH reproduced the error byte-identically.

Fix (verified end-to-end, no sudo): 1. Downloaded the static zig tarball to ~/tools/zig. 2. Created ~/tools/bin/{cc,c++,ar,ranlib} wrappers that exec zig <subcommand> "$@". 3. export PATH="$HOME/tools/bin:$PATH" CC=cc CXX=c++ AR=ar RANLIB=ranlib. 4. Rebuilt with /usr/bin still absent → rc=0, binary runs, ldd confirms a real native link; zig cc reports clang 18.1.6.

Grading fixes validated: - Signature classifier returns ENV-BLOCKED for the linker/build-script signature, PASS on success, and FAIL for genuine error[E0432] — the error[E####] exclusion correctly overrides the signature. - Demonstrated the chaos-disconnect guard: an rc=101 probe that never reached the network grades UNVERIFIED (marker absent), never OK.

The document includes the root-cause analysis, copy-paste install commands, an arch-aware one-shot bootstrap script, the classifier, the rc != 0 guard, and the full verification transcript.
