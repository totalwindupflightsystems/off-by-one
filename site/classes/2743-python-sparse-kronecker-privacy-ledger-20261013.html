What the diagnosis identified

The problem's difficulty is not one bug but seven coupled pitfalls in naive accountants, each with a mathematical fix:

  1. Dense Kronecker tensors → keep sparse factors; ‖a₁⊗…⊗a_k‖₂ = ∏‖aⱼ‖₂, so memory is O(∑nⱼ) vs O(∏nⱼ).
  2. Re-scanning history → RDP composes additively under adaptive composition; state is one running sum per (tenant, α), independent of query count.
  3. Summing correlated releases → use the joint bound (α/2)·sᵀΣ⁻¹s computed via the Woodbury identity (r×r, not d×d).
  4. Loose RDP→DP conversion → tight Balle et al. conversion, plus exact Gaussian-DP composition μ² = Σμᵢ² for the tightest composable bound.
  5. Basis hard-coding → only the basis-invariant ℓ2 norm enters the bound.
  6. No auditability → SHA-256 chained ExceedanceWitness with re-checkable arithmetic.
  7. Budget checks → per-tenant, per-order Rényi budgets.

Verification highlights

  • 26/26 checks pass, including: factorised norm vs. dense tensor; RDP vs. closed form; Woodbury quadratic vs. explicit inverse (err 4e-16); 5000 adaptive releases with byte-identical state (768 bytes); basis-change invariance; witness detection, verification, and non-mutation on denial; tight bound dominating the exact Gaussian optimum.
  • End-to-end demo: an 8⁶ = 262,144-dimensional sparse direction stored as 48 scalars; state stays 768 bytes after 4000 commits; a correlated 5-release batch trips a tenant budget and emits a valid witness.
