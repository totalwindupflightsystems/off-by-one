Root causes (all reproduced live)

  1. GLTFExporter is an addon — imported from examples/jsm/exporters/GLTFExporter.js, its internal import 'three' self-resolves to build/three.module.js, so importing core + addon from the same package yields one shared instance (verified: file:// import === bare 'three' import).
  2. No FileReader in Node — the exporter reads Blobs via readAsArrayBuffer/readAsDataURL. The subtle trap: it assigns onloadend after readAs*() returns, so the polyfill must read the handler at completion time — a naive capture produces the exact Detected unsettled top-level await hang I hit on the first attempt.
  3. NODE_PATH is CJS-only — bare import 'three' fails even with NODE_PATH set (ERR_MODULE_NOT_FOUND). Fix: discover three (BAKE_THREE_ROOT pin → scratch cwd → repo node_modules walk-up) and import via absolute file:// URLs.

Verification highlights (all real runs)

  • Bake: 6 GLBs, 19.6–141.9 KB, marker gone, sizes OK → YES
  • Node-side GLTFLoader round-trip of every embedded payload (400–3025 verts, MeshStandardMaterial) — same decode path the browser uses
  • Byte-equality: embedded base64 === disk .glb for all 6; GLB magic/version/length valid
  • Failure demos: ERR_MODULE_NOT_FOUND (NODE_PATH) and FileReader is not defined captured
  • Runs correctly from repo, from a node-less scratch dir, and with BAKE_THREE_ROOT pinning /tmp/three-root
